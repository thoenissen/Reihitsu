## Mechanism and candidates

Mechanism: `PipelineTraceCommand` keeps its own list of the checks that come before the pipeline. That list was not extended when FMT-PIPE-033 added a third check to whole-document formatting. So every input that one of the formatter's whole-document checks leaves alone, but that the trace's list lacks, is traced instead of skipped.

Dispatch: the checks in front of `FormattingPipeline.Execute` in `ReihitsuFormatter.FormatDocumentAsync`/`FormatSyntaxTree`:

| Check | Defining member | Trace today |
|---|---|---|
| Syntax error (FMT-PIPE-005) | `ReihitsuFormatterHelpers.HasSyntaxErrors` | skipped |
| Generated source (FMT-PIPE-006) | `ReihitsuFormatterHelpers.IsAutoGeneratedSource`, plus the file-name check `GeneratedFileUtilities.IsGeneratedFile` in the trace and the CLI | skipped |
| Hiding carrier (FMT-PIPE-033) | `ReihitsuFormatterHelpers.HoldsHidingCarrier` / `ReihitsuFormatter.HoldsHidingCarrier` | **traced: the defect** |
| Unsupported shape (FMT-UNSUP-001) | `PrecheckPhase` inside the pipeline | reported on stderr, exit `0`. Correct, because the trace runs the precheck itself |

No other member is missing. The carrier kinds (verbatim, raw, interpolated verbatim and raw, `/* */`, `/** */`) and the directive words (`elif`, `else`, `endif`) are axes of the shared predicate. The formatter's tests cover them. The trace needs no matrix of its own as long as it calls that predicate and keeps no copy.

## Breaking inputs

The reason text `code hidden in another build configuration` will then be written in both `FormatCommandHandler` and the trace, as `syntax errors` and `generated` already are. - **FC-003** (boundary tested on one side only): test both sides. Seed 3 from the spec author covers it: the same string without an enclosing `#if` is traced, and a `# Title` line instead of `#else` is traced.
- **FC-017** (assertion weaker than the guarantee): for the skip, assert stdout contains `Skipped (code hidden in another build configuration): <full path>`, stdout has no `Pass 1` line, stderr is empty, the exit code is `0`, and the input bytes are unchanged, as in `ExecuteAsyncInvalidOrGeneratedSourceIsSkipped`. A `Contains` check on the skip line alone would also pass if the trace printed the skip and then traced anyway.

## Refuse option

- **Leave the trace as it is** and state in `scripts/README.md` that the trace does not apply FMT-PIPE-033. Cost: no production lines. But the trace would keep naming the wrong reason (the precheck's refusal) for `carrier_unsup.cs` and would keep showing diffs that no caller makes. The requested change costs about five production lines and no new type or mechanism: one `if` that reuses `WriteInvalidPassMessage`. Refusing saves nothing worth having. The input class is rare (FMT-PIPE-033 says so), but that matters to the formatter's guards, not to a diagnostic tool that only has to name the skip.
- **Declare the shape unsupported**: not applicable. FMT-PIPE-033's `Why` already decided against it ("the shape costs no special case in any phase, so declaring it would remove nothing"), and the trace change touches no phase. The span would be the carrier token or trivia, from its opening delimiter through its closing one, only when it starts inside a conditional group and holds an `#elif`/`#else`/`#endif` line. It would delete no special case. It would refuse no common code beyond what FMT-PIPE-033 already leaves alone, but it would add an unsupported report the CLI does not give today. Nothing to escalate.
- **A `--force` option**: rejected by the change doc. I agree: no one needs it, and the other skips have no such option.
