## Refuse option

The issue is itself the refuse option for the class, decided by the maintainer. The alternative refusal is to do nothing and keep today's continuation indent, which the maintainer rejected.

- **Cost:** two cheap precheck checks with two reasons, minus one 4-line guard. No new mechanism, and no type beyond the precheck's existing pattern.
- **What it refuses that people write:** the one-line forms `x = /* ms */ 500;` and `new R { A = /* c */ 3 }`, which `main` formats without any special handling, and own-line comments behind `=`/`=>`. The most common neighbouring form, `var x = /* c */ 1;` in a declaration, is already refused by FMT-UNSUP-004, so the one-line assignment case does not widen what users already meet. I count it as covered by the answer's literal text and by that precedent, and I raise no question for it.
- **Unsupported-shape options outside the issue:**
  - (a) the compound operators, the spec author's output question 1;
  - (b) a directive behind a declarator's `=`, or a comment, directive, or disabled text behind an enum member's or a parameter default's `=`. The span is the gap from the `=` through the first token of the value. Declaring it, together with (a), would delete the refusals in `NormalizeEqualsValuePlacement` and `NormalizeCollectionExpressionEqualsValue`. It would refuse `enum E { A = // c⏎1 }`, which `main` formats. This is the spec author's follow-up candidate, already in `00-lead.md` for escalation 10; I agree with it.
- **Simpler options:** _None._
