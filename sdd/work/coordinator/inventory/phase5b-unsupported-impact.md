## 1. What the merged PRs establish
- **#1663** (AGENTS.md *Special cases do not grow the source*, change doc `special-cases-do-not-grow-source.md`). A guard is a cheap syntactic check only. When safety needs `#if` evaluation, another-build reconstruction, prediction of another component or phase, parser-like text rules, or a new type, the fix is withheld for that rare class and the formatter leaves the construct as written. Input that already violates another rule (e.g. a comment in an argument list, RH5038; `#region` in a member, RH7303) is rare by definition. Escalation 9: >~100 production lines or a new type. Issues and follow-ups that only serve a rare class are argued against or dropped. Refusal "classes" are generic, not a list: withhold the fix, or leave the construct as written; the lead decides them, they are not output questions, and the PR names each refused class.
- **#1662** (same day) adds **SHARED-FIX-009 "A fix does not work out another build configuration"**: no condition evaluation; a position check on where directives sit, and withholding otherwise. Also SHARED-ORDER-008 for the member-moving fixes.
- **#1671** (closes #1670; spec `formatter/unsupported-syntax.md`). Adds `PrecheckPhase` as the first phase. **One declared shape: FMT-UNSUP-004**, a comment (any kind, every doc mode) in the span of a variable declaration (field, event field, local, `using` decl, `for` init, `using`/`fixed` statement). Exceptions: the first token's leading trivia, the trivia behind the `;` or `)`, and the inside of an initializer value (its boundary trivia is not excepted). Nested declarations are checked on their own. Consequences:
  - Entry points: every `ReihitsuFormatter.Format*` returns `FormattingResult<T>` (`Output`, `Unsupported` = reason + span of the first shape). The input is returned unchanged; there is no partial formatting. The check runs on what the phases receive (for WithContext, the context) and is local to that input (FMT-UNSUP-003). Phase-level refusals (FMT-UNSUP-006) are allowed, but none exists yet. `FindUnsupportedSyntax` is the query (FMT-UNSUP-007).
  - CLI: the file stays unchanged; `error: path(line,col)` goes to stderr and the exit code is 2 (CLI-019). `--suppress-unsupported` turns it into a warning with no exit-code change (CLI-020).
  - Code fixes: **yes, no longer offered.** SHARED-FIX-010: every formatting fix (~41 providers) asks `FindUnsupportedSyntax` at registration about exactly the node or context it formats (or the node it builds, e.g. RH2001). The diagnostic stays.
  - Deleted special cases: the comment carry-over of the field split. Kept: `CarriesDirective`, `IsDocumented`, `LineBreakAssignmentRewriter` guards, the RH5111/RH5113/RH2001 fix comment checks.
  - Syntax errors (FMT-PIPE-005) and generated code are **not** "unsupported".
- **#1674** (change doc `unsupported-shape-as-refusal.md`). Declaring a shape unsupported is a third refusal, but always a visible output change. It is **escalation 10**: raised wherever a shape costs a special case or a refusal, also outside the run's issues, and never filtered by any role. It is batched with the output questions, or asked before publishing if raised at or after the auditor. The run refuses locally meanwhile. Declaring is recommended when guards hit several phases or findings recur. Adds FC-038..043.
