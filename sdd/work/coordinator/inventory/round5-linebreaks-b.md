The #956 comment instance (RH5102 `M(1, 2⏎ );` / `M(1⏎ , 2, 3);`) has the same cause and belongs in that issue, not only in #956. The P7 part only says "withhold or converge"; whether these inputs should be reported at all is the needs-maintainer item M2.

## Needs maintainer

- **M1 — syntax-form gap (candidate principle P9):** #1118 Q1, #1119 Q1, #1120 Q2, #1124 Q1 (plus #1116 Q1/Q3 from part a). A rule skips forms of its own construct (primary ctor, lambda, extension block, record struct, nested assignment, lines without a leading keyword) that sibling rules and the formatter handle. Proposed P9: a layout rule covers every syntax form of its construct that the formatter lays out under the requirement it `Uses`; gaps are behavior changes (new diagnostics, change doc), batched per rule family. Narrower than P4, which stays "no principle". RH5204 goes after #951.
- **M2 — line-leading block comment (candidate principle P10):** #1119 Q2, #1123 Q1 shape 2, #1125 Q1. The rule measures the token behind a `/* */` that starts the line. The formatter keeps the line, so the rule reports formatted code and its fix cannot help. Proposed P10: a rule that checks where a line starts judges the line's first element, the comment included, as RH5204-005 already does for comments. So these are not reported (bug, matches formatter). Alternative: keep reporting, fix withheld (P7 alone).
- **M3 — FMT-BLANK-011 inside a construct:** #1119 Q2, #1123 Q1 shape 2. The formatter inserts a blank line before a line-leading comment inside a declaration header or an argument list, because FMT-BLANK-011 applies to every token's leading trivia. Suggested behavior change: only between statements and members. Check RH5020, which mirrors FMT-BLANK-011, for the same scope.
- **M4 — fix format scope:** #1120 Q3 = #1121 Q1. Decide with #1113 Q1 (reading A clarification / B bug). No separate question.
- **M5 — enum members in FMT-BREAK-016:** #1120 Q1, formatter part. Behavior change so that the RH5111 fix converges by delegation. Otherwise the fix is withheld for enum members under P7.
- **M6 — RH5204 location:** #1124 Q2. Bug against RH5204-005 (diagnostic from `///`). Quick confirm only.

- **Duplicate:** #1120 Q3 = #1121 Q1 (same doc-comment layout by a delegating fix), both part of #1113 Q1.
- **Same shape:** #1119 Q2, #1123 Q1 shape 2, #1125 Q1. A `/* */` starts the line in front of the checked token; the analyzer reports it, the fix does not converge, and the formatter keeps the line (M2). Two of them also hit M3.
