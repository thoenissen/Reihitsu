## Groups by shared cause

1. **Comparer/message "look-through" in constant-style evaluation** (new recurring pattern: "wrappers and dead branches are transparent when judging a value"): #1247 Q4, Q5, Q6; #1248 Q1; #1250 Q1. Parentheses, `!`, `throw` arms, `string.Empty`, `default(T)`. One decision shape: how far the analyzers see through an argument. A single principle would settle Q4/Q5 and #1248 Q1 together.
2. **Analyzer sees the outer shape or one syntax form only** (rule scope gaps): #1247 Q1, Q2, Q3; #1248 Q2, Q3; #1249 Q1, Q2; #1251 Q4, Q5; #1256 Q4. Mostly behavior changes; per P4/P11 each is judged on its own rule.
3. **Partial declarations read per part**: #1252 Q2, #1254 Q4 (fix), #1254 Q5, #1255 Q1. Candidate principle: a partial type or member is one declaration; the analyzer decides on the symbol (static, async, accessibility) and reports once, and a fix never edits one part only.
4. **P1 unsafe fix instances**: #1251 Q1, Q2, Q3, Q6; #1254 Q3, Q4 (plus #1254 Q1 adjacent). Bugs against SHARED-FIX-003.
5. **Explicit interface implementations**: #1252 Q1 (should be reported), #1254 Q2 (should be exempt for accessibility), #1254 Q3 (fix). Pattern is rule-specific; no common principle.
6. **Text-scanning rule (regex over raw file text)**: #1256 Q1, Q2, Q3. P5 settles Q1; Q2/Q3 are the same cause (lex Razor, or document the limitation).
7. **Semantic vs syntactic name match**: #1253 Q1 (alias).

## New principle candidates

- **P14 (proposed): partial declarations are one declaration** — groups 3 above (#1252 Q2, #1254 Q5, #1255 Q1, #1254 Q4). Would decide all four.
- **P15 (proposed): a value judgement sees through parentheses, `!`, and `throw` branches/arms** — #1247 Q4/Q5, #1248 Q1 (Q6 and #1250 Q1 separate). Maintainer-level, since the issues present "intended" readings.
- **P3 extension (proposed)**: alias names resolve like spellings (`using NIE = …`) — would decide #1253 Q1 as a bug; today SHARED-DIAG-002 states alias is "a different name".
- **P5 extension (proposed)**: Razor `@* *@` and HTML `<!-- -->` comment text counts as comment content, and escaped `@@` / email-like `@` is not a directive — would decide #1256 Q2 (and arguably Q3).
