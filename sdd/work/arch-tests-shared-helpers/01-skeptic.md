## Mechanism and candidates

_N/A_ as a bug: this is a deduplication. There is one pre-existing defect inside the code being unified.

**Mechanism.** `SelfReferentialTrackerReferenceTests.IsExcludedFromScan` splits the file's **absolute** path. A `bin` or `obj` segment anywhere above the scanned root, in any casing, therefore excludes every file. The scan then passes vacuously. This applies both to the repository-wide comment scan, for a checkout under such a directory, and to its fixture self-tests, for a temp directory under such a directory. None of the other six sites has this defect: each compares a path relative to the root it walks.

Reproduced with the existing test. The fixture is a scratch directory outside the repository, deleted afterwards.

## Internal choices

1. **Dot-directory rule: unify it or keep it per scan.** The comment proposes picking one rule. Doing so changes which files two scans read:
   - "Skip every dot directory" everywhere would stop `SquadNoteReferenceTests.RepositoryFilesReferenceNoSquadNote` from reading the 32 tracked `.md`/`.yml`/`.json` files under `.claude/` (19) and `.github/` (13). That is a silent coverage loss.
   - "Skip none" everywhere would make `RoslynVersionOwnership` (pattern `*`) enumerate all of `.git/`. It would also break `BuildOutputAndDotDirectoriesAreSkipped` and `PackageDirectivesInBuildOutputAndDotDirectoriesAreSkipped`.
   - "Skip `.git` only" everywhere would break those same two Roslyn tests.

   **Recommendation:** the shared check decides bin/obj only. The dot-directory policies (every dot directory for the Roslyn scan, `.git` for the squad-note scan) stay at their scans on top of it. The issue body asks only for the bin/obj skip, and this keeps "no test behavior changes" true.
2. **Path basis of the shared check.** Recommendation: segments of the path relative to the root the scan walks. That is what six sites do today. For the tracker scan, it removes the absolute-path defect under *Mechanism*. This is the one deliberate behavior change, visible only in an environment whose checkout or temp path holds a `bin`/`obj` segment. It is a small adjacent fix in a component the run already changes (`README.md`, *Scope*), and it needs a test: a scanned root under an `obj` directory still yields its finding. The alternative, keeping the absolute basis at that one site, preserves a vacuous-pass defect inside the shared owner.
3. **Case rule.** Either rule reads the same files on today's tree. Recommendation: OrdinalIgnoreCase, the wider skip, which three sites use already and which a case-insensitive file system (macOS) needs to treat `Bin` as `bin`. Ordinal is equally defensible. Pin whichever is chosen once, at the shared check (FC-003).
4. **Segments compared: directories only, or including the file name.** The two read the same files under every site's extension filter. Recommendation: directories only, which states "build output directory" exactly.
5. **Pruning vs filtering.** `SquadNoteReferenceTests` prunes during its walk. The others filter after `SearchOption.AllDirectories`. Both read the same files. Recommendation: the shared check is a predicate that both shapes can call. Keep the squad-note walk's pruning, because it also prunes `.git`.
6. **Fixture type shape.**
   - The types differ in the property name (`Root` vs `Path`), the writer name (`Write` vs `WriteFile`), the writer's return value (void vs full path), and the root style. No test depends on any of these.
   - Recommendation: one type with a neutral name. Its writer accepts `/`-separated relative paths, since `RoslynVersionFixtureDirectory.Write` replaces `/` with the platform separator, and returns the full path. The domain helpers stay with their consumers.
   - Converting `SquadNoteReferenceTests`' seven inline temp roots is optional scope growth of the same decision. Recommendation: include it, since it is the same lifecycle, and record it.
