## Internal choices

- **Which symbols are enumerated.** I chose the symbols that the directives in the moved span and the crossed span name, and every other symbol keeps the document's definition. This is the one reading under which decisions 27 and 28 hold together, with far9 keeping its fix while its type names ten symbols. The alternative is to enumerate every symbol of the type declaration and apply the limit only to the touched ones. I rejected it because it leaves the untouched symbols without a defined value once the type names more than eight. Known residual of the chosen reading: a group that lies wholly outside both spans and names only symbols the spans do not name is read with the document's definition. An example is `#if X struct N { #endif` in front of the target, closed by `#if X } #endif` behind the moved member, both outside both spans. In the `X` build the whole move lies inside `N`, and that build is not read. I found no realistic input where this changes an outcome. The members are the same in both builds and are reordered the same way. Only a type kind or layout that differs per build could matter, and that is the follow-up candidate below. I did not write a sentence that blesses the case.
- **The cap is counted per move**, over the union of both spans (decision 28), not per region (auditor #12's suggestion). Consequence: cap2 becomes no-fix (see above). Alternative: per run of groups, which would keep cap2's fix but brings back regions, the structure decision 27 removes.
- **Membership condition.** I stated it as two conditions: compiled code in a span belongs to a member of the type, and no member of the type reaches across a boundary of the move. The alternative was "every moved or crossed position is a member of the type" (decision 27's wording). I rejected it because, read literally, it passes nt2: `N`, which holds `_d` and `_c`, is itself a member of `C`.
- An assignment whose parse does not compile (for example a `DEBUG` group that opens a type and a `TRACE` group that closes it, with `DEBUG` defined and `TRACE` not) is judged like any other. The spec says nothing special about it. The membership condition refuses such a move whenever the broken braces reach the spans.
- No change to RH7102, RH7103, RH7109, or RH7309 specs; they reference SHARED-ORDER-007. No rule page changed: these are withheld fixes in corner cases. `sdd/specs/README.md` is unchanged, because the code owners are unchanged.
