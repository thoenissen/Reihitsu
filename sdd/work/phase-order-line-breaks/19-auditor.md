## Architecture findings

- **Two owners answer SHARED-COMMENT-012's line-start question for a token behind a multi-line comment's last line, and they disagree when the comment starts its own line.**
  - **The owners.** `TokenGapNormalizer.EnsureTokenStartsLine` (through `TriviaListUtilities.FindFirstContentIndexOnLine`) treats the token as starting its line because the comment does. It decides statement pairs with a blank-line rule (new in this repair), sections, labels, and first statements. `ChainLineBreakRewriter.IsBehindMultiLineCommentTail`, a private predicate, counts the same comment as a tail and breaks.
  - **The input that shows it.** `items.Where(…)⏎/* c⏎ */ .Select(…)` gets a line break in front of `.Select`. `a++;⏎/* x⏎ */ return a;` and `case 1:⏎/* y⏎ */ break;` keep the token behind `*/`.
  - **Repeat.** It repeats #1's class (same decision, line-break phase against SHARED-COMMENT-012, a member not enumerated), so `README.md`, *Architecture findings* applies.
  - **Output.** The structural fix changes visible output, so it carries the output question of decision 28's follow-up. Finding #4 carries the defect.
