## Architecture findings

- **Two phases own whether a statement behind a multi-line comment's closing line starts its line.** The line-break phase (`LineBreakBlockRewriter.EnsureStatementsStartOnSeparateLines`, `TokenGapAnalysis.HasLineBreak`) and the blank-line phase (`BlankLineEditor.InsertBlankLineBeforeToken`, `TokenGapAnalysis.HasTerminalLineBreak`) both decide it. The decision they share is SHARED-COMMENT-012's line start for a statement in a list. Input: `a++; /* x⏎ */ return a;`. The line-break phase leaves it, and the blank-line phase writes the line break. This is a member of the issue's own structural defect (the blank-line phase splitting statements), and it is in components the run changes. Finding #1 carries the defect and its options.
