## Failure classes dismissed

- FC-004, FC-019, FC-020, FC-021: the join only runs on gaps the guard has proven to hold nothing but whitespace and line breaks. Comments in front of `[` and behind `;`, and directives between `this` and `[`, stay where they are (observed: probe U1, the two offered tests, `VerifyFixIsOfferedForACommentBehindTheSemicolon`). The exposure if the guard drifts is in #2.
- FC-005: `WouldJoinAcrossUnjoinableTrivia` covers comments, directives, and disabled text alike (`ContainsUnjoinableTrivia`).
- FC-006, FC-022, FC-024, FC-025, FC-026, FC-027: the fix rewrites only trivia and changes no token. Observed with `apply-fix.sh`, LF and CRLF, each converging in one application: an explicit interface implementation in a doubly nested type, a generic `Dictionary<int,⏎ string>` parameter type, a tuple type, an attributed parameter with `params`, a string default value holding `", // b"`, `throw`, a conditional expression, a cast, a leading comma `[uint a = 1⏎, uint b = 2]`, tabs in the gaps, a line break directly behind `[`, and a comment behind `;`. A block lambda and a collection initializer (`new List<int> { a, b }`, which the formatter expands, observed with `format.sh`) stay on several lines and are withheld as RH5419-004 states.

- FC-009, FC-043: the fix is offered only when the formatted text differs from a reported shape. The unsupported-shape answer is the same for the original and the joined node (*Guard scope*).
- FC-010, FC-011, FC-012: the formatter is unchanged.
- FC-013, FC-014: the formatter joins every arrow case. A wrapped parameter list is the documented SHARED-DIAG-010 exception (maintainer answer D), and the formatter join is a recorded follow-up candidate.
- FC-016: no sibling private copies of the moved attribute guards remain (*Policy ownership*).
- FC-017: see *Assertion adequacy*.
