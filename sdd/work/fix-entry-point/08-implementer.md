## Disputed tests or scope

1. **`ReihitsuFormatterFieldSplitTests.TargetBetweenTheBracesOfItsTypeKeepsItsLine`** (FMT-PIPE-029) and **`ReihitsuFormatterUsingDirectivesTests.ScopeThatDoesNotStartItsLineIsReadWhereItStandsInTheDocument`** (FMT-PIPE-030) pass under LF and fail under CRLF.
   - **The problem:** each input has no line break (`class C { private int _x, _y; }`, `namespace A { namespace B { using System.Linq; using System; class C { } } }`). `NormalizeLineEndings` therefore gives the same text in both runs, but the expected output differs (`\n` vs `\r\n`).
   - **What the spec says:** FMT-PIPE-007 says the formatter falls back to `Environment.NewLine` when the input holds no line break.
   - **Result:** no implementation can pass both runs on one platform. On Linux the CRLF run fails; on Windows the LF run would. Both tests' visible outputs agree with the spec under the platform's newline.
   - **Remedy:** a test-implementer change, either one run per test or an input that holds a line break. Nothing visible is in question.
2. **`ReihitsuFormatterTests.FormatNodeInDocumentAsyncWithAutoGeneratedMarkerReturnsOriginalDocument`** (existing, untagged, `src/Reihitsu.Formatter.Test/Unit/ReihitsuFormatterTests.cs:1226`).
   - **What it asserts:** `FormatNodeInDocumentAsync` with the root as target leaves a `// <auto-generated />` document unchanged.
   - **What the spec says:** FMT-PIPE-006 as changed says the node-level entry points MUST NOT check the marker. 06 flipped the other `…ReturnsGeneratedDocumentUnchanged…` tests but not this one.
   - **Result:** it fails now, which is the intended change.
   - **Remedy:** the test implementer reverses or removes it. Document-level formatting's refusal is still covered by the `FormatDocumentAsync` tests.
3. **Scope: RH7101 Fix All is now a custom document-based provider.**
   - **Why:** `FixAllSplitsTwoDeclarationsOnOneLine` failed under `WellKnownFixAllProviders.BatchFixer`. The two single fixes of `private int _a, _b; private int _c, _d;` both write the line break in the gap between the declarations, as FMT-PIPE-029 requires of each fix alone.
   - **What the batch merge did:** the text differ gives fix `_a` the change `[28,33) ", _b;" → ";\n    private int _b;\n   "`, which keeps the original space as the last indentation character. It gives fix `_c` the change `[33,49) " private int _c," → "\n    private int _c;\n    private int"`. The two changes are adjacent, so the merge applies both and writes a whitespace-only line.
   - **Why it cannot be avoided otherwise:** both single-fix outputs are specified, so any implementation meets this under the batch merge.
   - **What I did:** `ApplyFixAllAsync` tracks the reported declarations and applies the fix to each in turn. This follows the existing RH3002 precedent (`FixAllProvider.Create`). `BatchCodeFixTestsBase` only requires a Fix All provider.
4. **Scope: size.** The production paths are the ones the handovers name (`ReihitsuFormatter`, the split transform, the RH7101 fix and analyzer, the using utility), plus the one-line remark in `UsingDirectiveOrderingPhase`. No new dependency. The public members added are the two that FMT-PIPE-009/030/031 specify.

## Architecture findings

- **`FormatSplitFieldInContext` repeats the context setup of the non-split path** in `FormatNodeInDocumentWithContextAsync`: the `rootFirstTokenColumn` computation, the `FormattingContext` arguments, and the annotated pipeline run on the context. The two paths share one decision, how the context is formatted and what facts the phases get, so a change to one can miss the other. I kept the narrow change and left the structure alone. A shared private helper that builds the context and runs the pipeline would leave one owner.
- **The member column in a shared-line gap is read from the phases' output**, as the column of the second split field in the formatted context. It is not predicted. With a member in front, the target-position fact is not passed, so no column has to be predicted there either. No prediction or copy of another component's behavior was needed.
