## Maintainer clarifications (summarized)

- The node-level formatting methods of `ReihitsuFormatter` are not a public API. A change to them only has to cover the cases the code fixes actually pass (the RH7101 and RH7201–RH7207 code fixes here, and the existing callers); inputs that only a direct call would produce need no handling, no requirement, and no test (`AGENTS.md`, *Supported inputs*).

## Maintainer answers

Asked after the skeptic (batch before the test implementer); the maintainer took every recommendation.

- **RH7101 1a–1f** (comment/doc comment in front of a later declarator, first declarator on a later line, spacing, attribute lists, one fix splits only the reported declaration): **A** — the fix result follows the formatter's layout (change doc cases 1–5, 8). The issue's goal "the fix output stays as today" is dropped.
- **RH7101 2** (initializers and attributes of the split field): **A** — the whole field is formatted, initializers included (structural rewrites such as control-flow braces and trailing-comma removal, and re-layout of initializers). The change doc must list this.
- **RH7101 3a/3b** (declaration off the member column, with spaces or a tab): **A** — the first field keeps its column (a tab counts as one column), later fields stand at the type's member column.
- **RH7101 4a** (syntax error anywhere in the document): **A** — the RH7101 analyzer does not report while the document contains a syntax error; the diagnostic and its fix come back once the error is fixed. (Replaces the spec author's RH7101-006 "fix withheld".)
- **RH7101 4b** (header `<auto-generated>` in a file the analyzers still analyze, e.g. `generated_code = false`): **A** — the node-level entry points (`FormatNodeInDocumentAsync`, `FormatNodeInDocumentWithContextAsync`, the ones only code fixes call) no longer apply the generated-header check; the analyzer's (Roslyn's) generated-code decision governs. Document-level formatting and the CLI keep the check.
- **Principle stated by the maintainer**: when an analyzer reports, a code fix is offered. Applied in this run to the cases where the formatter refuses the file (4a, 4b). The existing RH7101-005 withholding (a directive inside the declaration, SHARED-FIX-003) stays unchanged.
- **Using fixes RH7201–RH7207**: **1A** — reinstated into the run. A new `ReihitsuFormatter` entry point organizes the using directives of one scope in a document; internally it runs only the using-directive phase. The seven rules' outputs stay unchanged; `GetScopeIndentation` stays as that entry point's specified layout (FMT-USING-003, SHARED-USING-010). Supersedes decision 2's "the fixes keep running the phase".
- **Architecture rule**: code-fix code runs no formatter phase or transform except through `ReihitsuFormatter`; an architecture test enforces it. Formatter helper methods (`ReihitsuFormatterHelpers.DetectEndOfLine`, `RegionDirectiveUtilities`, …) used by code fixes stay as they are — self-contained helpers are fine; no follow-up for them. A static applicability predicate such as `CarriesDirective` that the RH7101 fix needs is reached through `ReihitsuFormatter` as well.
- Asked for maintainability: RH7101 2A and usings 1A were recommended as the options with the fewest layout owners; the maintainer agreed.
