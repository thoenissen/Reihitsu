### FMT-SWITCH-003 (one qualifier, both sides)

Joined side, new. Verified with `scripts/format.sh`. Input:

```csharp
class C
{
    void M(int x)
    {
        switch (x)

            case 2:
                B();
                break;
        }
    }
}
```

Output (no section braced):

```csharp
class C
{
    void M(int x)
    {
        switch (x)
        {
            case 1:
                A(out var v);
                break;

            case 2:
                B();
                break;
        }
    }
}
```

Kept side: the same input with `A(1,⏎  2);` in place of `A(out⏎  var v);` braces both sections, as in the spec's first FMT-SWITCH-003 example. Verified with `scripts/format.sh`. `SwitchCaseBraceRequirementTests.SingleStatementSpanningTwoLinesMakesTheSectionMultiLine` already covers it.

The "later line" part of the qualifier is verified but has no spec example. This input:

```csharp
class C
{
    int M(int x)
    {
        switch (x)
        {
            case 1:
                A(); return 1;
            case 2:
                return 2;
        }

        return 0;
    }
}
```

gives `case 1: { A();⏎⏎ return 1; }` and `case 2: { return 2; }`, each block on its own lines. The switch is braced because FMT-BREAK puts `return 1;` on a later line first.

### FMT-PIPE-008 (per entry-point family)

Every case uses `class Empty⏎{⏎}`. It stays braced under C# 11 and becomes `class Empty;` under C# 12:

- `FormatSyntaxTree`: the tree's parse options.
- `FormatDocumentAsync`: the project's parse options, which are the tree's.
- `FormatNode`: a tree parsed with C# 11 or C# 12 options. A detached node (`SyntaxFactory.ParseCompilationUnit`) gets the C# 12 result.
- `FormatNodeInDocumentAsync`: target = the class; the project's language version decides.
- `FormatNodeInDocumentWithContextAsync`: target = the class, context = the compilation unit; the project's language version decides.

The spec's C# 5 / C# 6 property example applies to the document and tree entry points only. `src/Reihitsu.Formatter.Test/Unit/ReihitsuFormatterLanguageVersionTests.cs` already holds tests for most of these cases. Some of them carry no `FMT-PIPE-008` tag (`FormatNodeInDocumentAsyncConvertsNestedEmptyClassInCSharp12Project`, `FormatNodeInDocumentWithContextAsyncConvertsEmptyClassInCSharp12Project`, `FormatNodeKeepsEmptyClassBracedForCSharp11Tree`).
