## Architecture findings

1. **The merged-list decision is taken twice and the two disagree (finding 1).** Per list, `AttributeTargetFormattingShared.ResolveListShapeMode` decides that a `param:`/`typevar:` list has the merged shape on any owner; the split guard (`CanSplit`) and RH5524's scope follow it. Per owner, `AttributeListMergeTransform` (visits only parameters and type parameters) and `AttributeTargetFormattingRewriter.ShapeAccessorAttributeLists` (merges only in one-line accessor lists) decide where a merge runs at all. Input: `int P { get => _v; [param: A] [param: B] set => _v = value; }` — the split guard leaves the lists alone because they are `MergedList`, and no merge runs on them. On `main` one predicate (`ResolveListShapeMode(list, keepAccessorListsSingleLine)`) drove both steps for every owner.
