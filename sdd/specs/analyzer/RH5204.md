# Analyzer — RH5204 Indentation must use 4 spaces per scope level

| | |
|---|---|
| ID prefix | RH5204 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5204IndentationMustUseFourSpacesPerScopeLevelAnalyzer`, `RH5204IndentationMustUseFourSpacesPerScopeLevelCodeFixProvider` |
| Uses | FMT-INDENT-001, FMT-INDENT-002, FMT-INDENT-003, FMT-INDENT-004, FMT-INDENT-006, FMT-INDENT-010, FMT-INDENT-011, FMT-INDENT-028, SHARED-BLANK-008, SHARED-COMMENT-011 |

RH5204 reports a line whose indentation does not match the depth of the scope it is in, at four spaces per level, and offers a code fix that re-indents it the way the formatter does.

In the examples, `→` marks a tab character.

## Non-goals

- Tab characters — RH5601.
- The column of a continuation line inside an expression or a declaration, such as a wrapped argument or a chain link — the alignment rules (RH5201, RH5203, RH5205, RH5206) and the formatter (FMT-INDENT).
- The column of a lambda's block body — RH5205.

## Requirements

### RH5204-001 — A misindented declaration, statement, or brace is reported

The analyzer MUST report a line whose first token (SHARED-BLANK-008) is a keyword or a modifier that starts a namespace, a type, a member, a statement, an accessor, an `else`, `catch`, or `finally` clause, or a switch label, the name of an enum member, the label of a labeled statement, or a brace of a namespace, a type, a block, an accessor list, or a switch statement, when the line's indentation is not four spaces per scope level as FMT-INDENT-002, FMT-INDENT-003, and FMT-INDENT-004 count them. A line that starts with a comment is judged as SHARED-COMMENT-011 specifies.

Why: Each scope level adds four spaces, so the indentation of a line shows which scope it belongs to (FMT-INDENT-001, FMT-INDENT-002). When declarations, statements, or braces drift from their level, the visual structure of the file no longer matches the code.

Example:

```csharp
class C
{
  {|RH5204:private|} int _a;

    void M(int x)
    {
         {|RH5204:if|} (x > 0)
        {
          {|RH5204:return|};
        }
        switch (x)
        {
              {|RH5204:case|} 1:
                break;
        }
          {|RH5204:L|}: return;
      {|RH5204:}|}
}

enum E
{
      {|RH5204:A|},
}
```

### RH5204-002 — A misindented comment line is reported

The analyzer MUST report a comment that starts its own line in front of a line that RH5204-001 checks when the comment's indentation differs from that line's expected indentation, or, in front of a closing brace, from one level deeper than the brace (FMT-INDENT-006).

Why: A comment on its own line describes the code below it and belongs to that code's level; a comment at the end of a scope describes the scope's contents.

Example:

```csharp
class C
{
      {|RH5204:/* M */|}
    public void M()
    {
          {|RH5204:// first|}
        return;
    {|RH5204:// end|}
    }
}
```

### RH5204-003 — A misindented region directive is reported

The analyzer MUST report an active `#region` or `#endregion` directive whose indentation differs from the block indentation of its position (FMT-INDENT-010). A region directive in disabled text MUST NOT be reported.

Why: A region groups members or statements, so it takes the column of what it groups. Disabled text is left as written (FMT-INDENT-011).

Example:

```csharp
class C
{
{|RH5204:#region Fields|}
    private int _a;
        {|RH5204:#endregion|}

#if NEVER
#region Inactive
#endregion
#endif
}
```

### RH5204-004 — Literal lines and tab indentation are not reported

The analyzer MUST NOT report a line that starts inside a multi-line string literal, a line whose indentation contains a tab character, a blank line, or a line inside the block body of a lambda or an anonymous method.

Why: The lines of a literal are part of its value. A tab is RH5601's diagnostic, and its width cannot be compared with a count of spaces. A lambda's body aligns to the lambda rather than to the scope depth (FMT-INDENT-028), which RH5205 checks.

Example:

```csharp
using System;

class C
{
    void M()
    {
        var s = """
  raw
  """;
→       return;
    }

    Action A()
    {
        return () =>
        {
                    return;
        };
    }
}
```

is not reported.

### RH5204-005 — The diagnostic is on the line's first token, comment, or directive

The analyzer MUST report one diagnostic per misindented line, located on the line's first token, on the comment, or on the region directive.

Why: That element is what starts the line and what the indentation is measured for.

Example: see RH5204-001 to RH5204-003.

### RH5204-006 — The fix re-indents the scope around the line

For a reported token or comment, the code fix MUST format the smallest node around it that starts on an earlier line — for a comment, on another line than the comment — as the formatter formats it in place, which gives the reported line its expected indentation. For a reported region directive, the code fix MUST replace only that line's indentation with the expected number of spaces.

Why: The indentation of a line depends on the scope it is in, so the fix formats that scope and reuses the formatter's indentation policy. A directive is not part of a node, so it is re-indented on its own.

Example:

```csharp
class C
{
  {|RH5204:private|} int _a;

    public void M()
    {
          {|RH5204:// first|}
        return;
    }
}
```

```csharp
class C
{
    private int _a;

    public void M()
    {
        // first
        return;
    }
}
```

A region directive:

```csharp
class C
{
{|RH5204:#region Fields|}
    private int _a;
    #endregion
}
```

```csharp
class C
{
    #region Fields
    private int _a;
    #endregion
}
```
