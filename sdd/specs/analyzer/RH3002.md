# Analyzer — RH3002 Statement must not use unnecessary parentheses

| | |
|---|---|
| ID prefix | RH3002 |
| Status | Active |
| Category | Clarity |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH3002StatementMustNotUseUnnecessaryParenthesesAnalyzer`, `RH3002StatementMustNotUseUnnecessaryParenthesesCodeFixProvider` |
| Uses | — |

RH3002 reports a parenthesized expression whose parentheses change neither the meaning nor the parsing of the code, in a set of positions where an expression needs no grouping, and offers a code fix that removes the parentheses.

## Non-goals

- Parentheses that declare the precedence of mixed `&&` and `||` — RH3006 asks for them.
- The parentheses that a statement, a cast, an argument list, or a parameter list requires; they are not a parenthesized expression.
- Patterns: a parenthesized pattern is not a parenthesized expression.

## Requirements

### RH3002-001 — Parentheses around a whole expression are reported

The analyzer MUST report a parenthesized expression that is the whole expression of a `return` statement, a `throw` statement, the value after `=` in a variable, member, or parameter declaration, the expression body (`=>`) of a member, an accessor, or a local function, an argument of an invocation, an object creation, or an element access, an element of a tuple, or either side of an assignment, and a parenthesized expression directly inside another parenthesized expression, unless RH3002-003, RH3002-004, or RH3002-005 applies. As the operand of a throw expression, it MUST be reported only when its content is not a conditional expression, an assignment, or a query expression.

Why: In these positions the expression stands alone, so the parentheses group nothing and only add noise. The operand of a throw expression is parsed only down to the null-coalescing level: without the parentheses, a conditional, an assignment, or a query would take the throw expression into itself.

Example:

```csharp
using System;
using System.Threading.Tasks;

class C
{
    int _f;

    int P => {|RH3002:(_f)|};

    int Q { get => {|RH3002:(_f)|}; }

    int M(int a, string s, int d = {|RH3002:(1)|})
    {
        int b = {|RH3002:(a)|};
        b = {|RH3002:(a + 1)|};
        Console.WriteLine({|RH3002:(a)|});
        var t = ({|RH3002:(a)|}, 1);
        var u = {|RH3002:(s ?? throw {|RH3002:(new InvalidOperationException())|})|};
        return {|RH3002:({|RH3002:(b)|})|};
    }

    void Fail()
    {
        throw {|RH3002:(new InvalidOperationException())|};
    }
}
```

The operand of a throw expression that is a conditional expression keeps its parentheses:

```csharp
using System;

class C
{
    int Fail(bool c) => throw (c ? new Exception() : new InvalidOperationException());
}
```

is not reported.

### RH3002-002 — Parentheses around a receiver are reported only around a primary expression

The analyzer MUST report a parenthesized expression that is the receiver of a member access, an invocation, or an element access, or the operand of `await`, when its content, after the pairs inside it that are reported themselves, is a name, a generic name, a literal, `this`, `base`, an invocation, a member access, an element access, an object creation, or a pair of parentheses that is not reported itself. Around a binary, conditional, cast, or `switch` expression, the parentheses MUST NOT be reported.

Why: A primary expression, and a pair that stays, binds as tightly as the access that follows it, so the parentheses around it change nothing. Around a binary, conditional, cast, or `switch` expression, the access or the `await` would bind to part of it once the parentheses are gone.

Example:

```csharp
using System.Threading.Tasks;

class C
{
    async Task<int> M(string s, Task<int> t)
    {
        var n = {|RH3002:(s)|}.Length;
        var c = {|RH3002:(((object)s))|}.ToString();
        return await {|RH3002:(t)|};
    }
}
```

Around other content, the parentheses stay:

```csharp
class C
{
    string M(int a, int b, object o, bool c)
    {
        var y = (a + b).ToString();
        var z = ((int)o).ToString();
        var w = (a switch { 1 => "a", _ => "b" }).Length;
        return (c ? "a" : "b").ToString();
    }
}
```

is not reported.

### RH3002-003 — Parentheses around a cast, a lambda, an anonymous method, or a `switch` expression are not reported

The analyzer MUST NOT report a parenthesized expression whose content is a cast, a lambda, an anonymous method, or a `switch` expression, in any position.

Why: Each of these extends as far to the right as it can or starts with a token the parser reads differently in front of other code, so the parentheses are what marks where it ends.

Example:

```csharp
using System;

class C
{
    void M(int a, object o)
    {
        Func<int> f = (() => a);
        var x = ((int)o);
        var y = (a switch { 1 => "a", _ => "b" });
    }
}
```

is not reported.

### RH3002-004 — Parentheses the parser needs are not reported

The analyzer MUST NOT report a parenthesized expression whose removal would let the parser read the code around it differently: as a cast, as a local declaration, as a member initializer, or as a generic name. When this decides between two pairs, the pair that keeps the parser's reading MUST stay unreported and the other pair MUST be reported.

Why: The parser decides between these readings from the tokens before and after the parentheses, not from the parent node alone. `(d)()` is a cast of `()`, and `(G < A), (B > (7))` turns into the generic invocation `G<A, B>(7)` once both pairs are gone; removing such a pair would change the program or break the build.

Example — the inner pair would leave `(_d)()`, which is read as a cast:

```csharp
class C
{
    System.Func<int> _d;

    int M()
    {
        return ((_d))();
    }
}
```

is not reported. Of two arguments that would join into a generic name, the first pair is reported and the second stays:

```csharp
class C
{
    int G;
    int A;
    int B;

    void M(bool x, bool y)
    {
    }

    void Run()
    {
        M({|RH3002:(G < A)|}, (B > (7)));
    }
}
```

```csharp
class C
{
    int G;
    int A;
    int B;

    void M(bool x, bool y)
    {
    }

    void Run()
    {
        M(G < A, (B > (7)));
    }
}
```

### RH3002-005 — Parentheses in front of an assignment operator that it would join are not reported

The analyzer MUST NOT report a parenthesized expression that directly precedes an assignment operator when its content ends, along its rightmost operand, in a conditional expression, an assignment, a query expression, or a conditional access. Other content in front of an assignment operator MUST be reported under RH3002-001.

Why: Without the parentheses, the assignment operator would be parsed into the end of the content — into the false branch of the conditional, for example — instead of assigning to the whole of it.

Example:

```csharp
class C
{
    int _a;
    int _b;

    void M(bool c)
    {
        (c ? ref _a : ref _b) = 5;
        {|RH3002:(_a)|} = 6;
    }
}
```

```csharp
class C
{
    int _a;
    int _b;

    void M(bool c)
    {
        (c ? ref _a : ref _b) = 5;
        _a = 6;
    }
}
```

### RH3002-006 — Of nested pairs, one stays

When nested pairs surround content, the analyzer MUST report every pair but one in these two cases:

- when the content is a cast, a lambda, an anonymous method, or a `switch` expression (RH3002-003) and the outermost pair stands in a position of RH3002-001 or is the receiver of RH3002-002, every pair but the innermost is reported;
- when the content is any other expression that needs a pair where the outermost pair stands — as the receiver of RH3002-002, the target in front of an assignment operator of RH3002-005, or the operand of a throw expression — every pair but the outermost is reported.

Why: One pair keeps the meaning; the others are redundant. Around a cast, a lambda, an anonymous method, or a `switch` expression the pair directly around it is the one that marks where it ends; where the position needs the pair, keeping the outermost one leaves the grouping where the reader expects it. Either way the fixes converge without ever removing the last pair.

Example:

```csharp
using System;

class C
{
    string M(int a, int b, object o)
    {
        var x = {|RH3002:({|RH3002:(((int)o))|})|};
        Func<int> f = {|RH3002:((() => a))|};
        var s = {|RH3002:(((int)o))|}.ToString();
        return ({|RH3002:(a + b)|}).ToString();
    }
}
```

```csharp
using System;

class C
{
    string M(int a, int b, object o)
    {
        var x = ((int)o);
        Func<int> f = (() => a);
        var s = ((int)o).ToString();
        return (a + b).ToString();
    }
}
```

### RH3002-007 — The diagnostic covers the parentheses

The analyzer MUST report one diagnostic per parenthesized expression, from its `(` to its `)`.

Why: The pair is what the fix removes, together with the expression it encloses.

Example: see RH3002-001.

### RH3002-008 — The fix removes the parentheses and keeps the code around them

The code fix MUST replace the parenthesized expression with its content, keep the trivia in front of `(` and after `)` around the content, and insert one space on a side where nothing separates the content from the neighboring token and the two would otherwise be read as one token.

Why: Only the pair goes; the comments around it belong to the code next to it. `return(a)` would become the identifier `returna` without the space.

Example:

```csharp
class C
{
    int M(int a)
    {
        return{|RH3002:(a)|};
    }

    int N(int a)
    {
        return /* x */ {|RH3002:(a)|} /* y */;
    }
}
```

```csharp
class C
{
    int M(int a)
    {
        return a;
    }

    int N(int a)
    {
        return /* x */ a /* y */;
    }
}
```

### RH3002-009 — A comment or a directive inside the parentheses withholds the fix

The code fix MUST NOT be offered when a comment or a preprocessor directive stands between `(` and `)`. The diagnostic is still reported. A comment in front of `(` or after `)` MUST NOT withhold the fix (RH3002-008).

Why: A comment directly inside a parenthesis has no unambiguous place once the parenthesis is gone, and a directive there would have to move across the code it guards.

Example:

```csharp
class C
{
    int M(int a)
    {
        return {|RH3002:(/* x */ a)|};
    }
}
```

is reported, and no code fix is offered.
