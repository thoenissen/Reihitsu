# Analyzer — RH7308 Standard regions should contain only their matching member kind

| | |
|---|---|
| ID prefix | RH7308 |
| Status | Active |
| Category | Organization |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH7308StandardRegionsShouldContainOnlyMatchingMemberKindAnalyzer` |
| Uses | SHARED-REGDESC-001, SHARED-TYPEREGION-006 |

RH7308 reports a member that sits in a top-level region whose label names member kinds, when the member is of none of those kinds. It has no code fix: which region the member belongs in, and whether that region exists, is the user's decision.

## Non-goals

- Whether a type has regions at all — RH7305, RH7305A — and the order of its regions — RH7309.
- Nested types and delegates. They are never reported, whatever region they are in.
- Labels named after a type, such as an interface — RH7309 orders such regions; RH7308 does not check them.

## Requirements

### RH7308-001 — A member of a kind the label does not name is reported

For every class, struct, interface, record, and record struct declaration, nested ones included, the analyzer MUST report each member that lies in a top-level region of that declaration (SHARED-TYPEREGION-006), outside any region nested in it, when the region's label is recognized (RH7308-002) and the member's kind is not one the label names. The kinds are: field, `const` included; property; method; constructor; finalizer; event, in both forms; indexer; and operator, conversion operators included.

Why: Readers expect a `Fields` region to hold fields and a `Methods` region to hold methods; a property inside `Fields` hides it where nobody looks for it. A nested type is checked against its own top-level regions.

Example:

```csharp
class C
{
    #region Fields

    private int _value;

    public int {|RH7308:Value|} => _value;

    #endregion

    #region Constructors / Finalizer

    public C()
    {
    }

    ~C()
    {
    }

    public void {|RH7308:Run|}()
    {
    }

    #endregion

    #region Operators

    public static C operator +(C left, C right) => left;

    public static implicit operator int(C value) => 0;

    public int {|RH7308:this|}[int index] => index;

    #endregion

    class D
    {
        #region Methods

        private int {|RH7308:_b|};

        #endregion
    }
}
```

and nested types and delegates are not reported:

```csharp
class C
{
    #region Events

    public event System.EventHandler A;

    public event System.EventHandler B
    {
        add { }
        remove { }
    }

    public delegate void D();

    class E
    {
    }

    #endregion
}
```

is not reported.

### RH7308-002 — Which labels are recognized

The analyzer MUST split a region's description (SHARED-REGDESC-001) into words at spaces, tabs, `/`, `&`, `,`, and `-`, and MUST recognize the label exactly when it contains at least one member-kind noun and every other word is one of the qualifiers below, all compared case-insensitively. A region whose label is not recognized MUST NOT be checked.

- Member-kind nouns: `field`, `fields`, `const`, `constant`, `constants` (fields); `property`, `properties`; `method`, `methods`; `constructor`, `constructors`, `ctor`, `ctors` (constructors); `finalizer`, `finalizers`, `destructor`, `destructors` (finalizers); `event`, `events`; `indexer`, `indexers`; `operator`, `operators`.
- Qualifiers: `public`, `private`, `protected`, `internal`, `static`, `instance`, `abstract`, `virtual`, `override`, `sealed`, `readonly`, `partial`, `extern`, `async`, `unsafe`, `new`, `explicit`, `implicit`, `generic`, `and`, `or`.

A recognized label names every kind whose noun it contains.

Why: A label made of member-kind nouns and modifiers states which members the region holds, and the separators let one region name several kinds. Any other word — `Helper methods`, `IDisposable` — means the label is about something else, so the rule stays silent instead of guessing what the author meant.

Example:

```csharp
class C
{
    #region private methods

    public int {|RH7308:P|} => 1;

    #endregion

    #region Ctors - Finalizer

    public C()
    {
    }

    public void {|RH7308:M|}()
    {
    }

    #endregion

    #region Const

    public int {|RH7308:Q|} => 1;

    #endregion
}
```

while a label with any other word is not checked:

```csharp
class C
{
    #region Helper methods

    public int P => 1;

    #endregion

    #region IDisposable

    public int Q => 1;

    #endregion
}
```

is not reported.

### RH7308-003 — The diagnostic is on the member's name

The analyzer MUST report one diagnostic per reported member, located on its identifier — for a field or event field the first declarator's identifier, for an indexer the `this` keyword, for an operator the operator token, and for a conversion operator the `operator` keyword.

Why: The name is what a reader scans for, and one diagnostic per member lets the user move members one at a time.

Example:

```csharp
class C
{
    #region Methods

    private int {|RH7308:_a|}, _b;

    public event System.EventHandler {|RH7308:Changed|};

    public static C operator {|RH7308:+|}(C left, C right) => left;

    public static implicit {|RH7308:operator|} int(C value) => 0;

    #endregion
}
```
