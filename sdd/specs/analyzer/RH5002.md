# Analyzer — RH5002 If statements should be preceded by a blank line

| | |
|---|---|
| ID prefix | RH5002 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5002IfStatementsShouldBePrecededByABlankLineAnalyzer`, `RH5002IfStatementsShouldBePrecededByABlankLineCodeFixProvider` |
| Uses | SHARED-STMT-001, SHARED-STMT-002, SHARED-STMT-003, SHARED-STMT-004 |

RH5002 reports an `if` statement that follows another statement of the same block or switch section without a blank line between them, and offers a code fix that inserts one as SHARED-STMT-004 specifies.

## Non-goals

- Blank lines before other statement kinds — RH5001, RH5003–RH5010, RH5012–RH5019.
- A blank line after a statement that ends with a closing brace — RH5030 (SHARED-BLANK-003).
- More than one blank line in a row — RH5023.
- Whether a comment above the `if` needs a blank line of its own — RH5020.
- A block comment in front of the `if` on the same line (`/* note */ if (…)`). The fix currently inserts two blank lines there; whether that is a defect is an open question.

## Requirements

### RH5002-001 — An `if` that follows a statement needs a blank line

The analyzer MUST report an `if` statement as SHARED-STMT-001, SHARED-STMT-002, and SHARED-STMT-003 specify.

Why: An `if` starts a new decision in the control flow; the blank line makes that step visible.

Example:

```csharp
class C
{
    void M(int a)
    {
        a++;
        {|RH5002:if|} (a > 1)
        {
        }

        if (a > 2)
        {
        }
    }
}
```

The second `if` follows a blank line and is not reported.

### RH5002-002 — An `if` that is not a statement of a list is not checked

Status: Retired — moved to SHARED-STMT-002, which states it for every rule of this kind.

The analyzer MUST NOT report an `if` statement whose parent is not a block or a switch section: the `if` of an `else if`, and an `if` that is the embedded body of another statement, such as an unbraced `if`, `while`, or `for` body.

Why: An `else if` continues the chain of the `if` above it, and an embedded statement is bound to its header; a blank line in either place would tear a single statement apart.

Example:

```csharp
class C
{
    void M(int a)
    {
        if (a > 1)
        {
        }
        else if (a > 2)
        {
        }

        while (a > 3)
            if (a > 4)
                a--;
    }
}
```

is not reported.

### RH5002-003 — A directive directly above the `if` is a separator

Status: Retired — moved to SHARED-STMT-003, which states it for every rule of this kind.

The analyzer MUST NOT report an `if` statement when the last trivia in front of its `if` keyword, apart from whitespace and line breaks, is a preprocessor directive.

Why: A directive line already sets the `if` apart from the code above it, and inserting a blank line between a directive and the code it governs would separate them instead. The formatter makes the same decision.

Example:

```csharp
class C
{
    void M(int a)
    {
        a++;
#if DEBUG
        a--;
#endif
        if (a > 6)
        {
        }
    }
}
```

is not reported.

### RH5002-004 — The diagnostic is on the `if` keyword

The analyzer MUST report the diagnostic on the `if` keyword.

Why: The keyword is where the missing separator becomes visible, and the location stays stable when the condition changes.

Example: see RH5002-001.

### RH5002-005 — The fix inserts one blank line above the statement and its comments

Status: Retired — moved to SHARED-STMT-004, which states it for every rule of this kind.

The code fix MUST make exactly one blank line appear in front of the `if` statement. When comments sit directly above the `if` on their own lines, the blank line MUST go above the first of them. When the `if` shares its line with the statement before it, the fix MUST move the `if` to a new line, indented like the statement it follows. Inserted line breaks MUST use the line ending the document already uses.

Why: A comment directly above the `if` describes it, so it stays with the `if`; putting the blank line between them would leave the comment describing the code above. The fix changes only the gap in front of the statement.

Example:

```csharp
class C
{
    void M(int a)
    {
        a++;
        {|RH5002:if|} (a > 1)
        {
        }

        a++;
        // note
        {|RH5002:if|} (a > 3)
        {
        }

        a++; {|RH5002:if|} (a > 5) { }
    }
}
```

```csharp
class C
{
    void M(int a)
    {
        a++;

        if (a > 1)
        {
        }

        a++;

        // note
        if (a > 3)
        {
        }

        a++;

        if (a > 5) { }
    }
}
```

### RH5002-006 — Fix All inserts every blank line in one pass

Status: Retired — `shared/code-fixes.md` specifies Fix All for every rule whose header says `Fix All`.

The code fix MUST provide a batch Fix All. The fixes of one document MUST NOT overlap, because each changes only the trivia in front of its own `if` keyword.

Why: Every diagnostic owns a separate gap, so applying all fixes together gives the same result as applying them one by one.

Example: the two blocks under RH5002-005 are the Fix All input and result.
