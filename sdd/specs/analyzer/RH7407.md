# Analyzer — RH7407 Non-override events should not be placed in override regions

| | |
|---|---|
| ID prefix | RH7407 |
| Status | Active |
| Category | Organization |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH7407NonOverrideEventsShouldNotBePlacedInOverrideRegionsAnalyzer` |
| Uses | SHARED-REGGROUP-001, SHARED-REGGROUP-002, SHARED-REGGROUP-006, SHARED-REGGROUP-007 |

RH7407 reports an event that overrides nothing when it lies in a top-level region named after the type that one of the type's override events comes from. It has no code fix.

## Non-goals

- Where an override event belongs — RH7403.
- Methods, properties, and indexers that override nothing — RH7405, RH7406, RH7408.

## Requirements

### RH7407-001 — An event that overrides nothing in an override region is reported

In every type declaration it checks (SHARED-REGGROUP-001), the analyzer MUST report each event declaration that overrides no event — a field-like event and an event with `add` and `remove` accessors alike — when it lies (SHARED-REGGROUP-002) in a top-level region that is an override region of events (SHARED-REGGROUP-007). An override event of either form makes a region an override region. The diagnostic MUST be placed as SHARED-REGGROUP-006 specifies.

Why: A region named after a base type groups the members that override that type's members. An event of the type's own placed among them blurs the inheritance boundary. Both forms declare the same kind of member.

Example:

```csharp
using System;

class B
{
    public virtual event EventHandler Changed;
}

class C : B
{
    #region B

    public override event EventHandler Changed;

    public event EventHandler {|RH7407:Saved|};

    public event EventHandler {|RH7407:Closed|}
    {
        add
        {
        }

        remove
        {
        }
    }

    #endregion
}
```

### RH7407-002 — Other members and other regions are not reported

The analyzer MUST NOT report an event that lies in a region that is not an override region, an override event, or a member that is not an event declaration.

Why: Outside an override region an event that overrides nothing is where it belongs, an override in an override region is where RH7403 asks it to be, and the other member kinds have rules of their own.

Example:

```csharp
using System;

class B
{
    public virtual event EventHandler Changed;
}

class C : B
{
    #region B

    public override event EventHandler Changed;

    #endregion

    #region Events

    public event EventHandler Saved;

    #endregion
}
```

is not reported.
