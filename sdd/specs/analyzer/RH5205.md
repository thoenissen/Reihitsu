# Analyzer — RH5205 Statement lambda opening braces should be aligned

| | |
|---|---|
| ID prefix | RH5205 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5205StatementLambdaOpeningBraceShouldBeAlignedAnalyzer`, `RH5205StatementLambdaOpeningBraceShouldBeAlignedCodeFixProvider` |
| Uses | FMT-INDENT-028 |

RH5205 reports the opening brace of a lambda's block body that starts a line in another column than the lambda's anchor, and offers a code fix that lays the lambda out the way the formatter does.

## Non-goals

- Whether the opening brace starts a line at all — the formatter (FMT-BREAK-002).
- The block body of an anonymous method (`delegate (…) { … }`).
- The indentation of the statements inside the body relative to its braces.

## Requirements

### RH5205-001 — A misaligned lambda block brace is reported

The analyzer MUST report the opening brace of the block body of a simple or a parenthesized lambda when the brace starts a line below the token in front of it and is not in the column of the lambda's anchor: the `async` keyword of an async lambda, otherwise the opening parenthesis of a parenthesized lambda or the parameter of a simple lambda. A brace on the line of the arrow MUST NOT be reported.

Why: A lambda can start anywhere on its line; aligning its body with the lambda's own start keeps the body visually attached to the lambda rather than to the statement around it (FMT-INDENT-028).

Example:

```csharp
using System;
using System.Threading.Tasks;

class C
{
    void M()
    {
        Func<int, int> a = x =>
                             {|RH5205:{|}
                                 return x;
                             };
        Func<int, int> b = (x) =>
        {|RH5205:{|}
            return x;
        };
        Func<int, Task<int>> c = async x =>
                                       {|RH5205:{|}
                                           return await Task.FromResult(x);
                                       };
        Func<int, int> d = x =>
                           {
                               return x;
                           };
        Func<int, int> e = x => {
            return x;
        };
    }
}
```

### RH5205-002 — The diagnostic is on the opening brace

The analyzer MUST report one diagnostic per lambda, located on the opening brace of its block body.

Why: The brace is the token that is aligned, and the body follows it.

Example: see RH5205-001.

### RH5205-003 — The fix lays out the lambda

The code fix MUST format the lambda as the formatter formats it in place, which moves the opening brace into the anchor's column and shifts the body with it (FMT-INDENT-028).

Why: The formatter owns the alignment of lambda bodies; delegating to it applies that alignment instead of a second one.

Example:

```csharp
using System;

class C
{
    void M()
    {
        Func<int, int> a = x =>
                             {|RH5205:{|}
                                 return x;
                             };
        Func<int, int> b = (x) =>
        {|RH5205:{|}
            return x;
        };
    }
}
```

```csharp
using System;

class C
{
    void M()
    {
        Func<int, int> a = x =>
                           {
                               return x;
                           };
        Func<int, int> b = (x) =>
                           {
                               return x;
                           };
    }
}
```
