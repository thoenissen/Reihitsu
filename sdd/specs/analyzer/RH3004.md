# Analyzer — RH3004 Use lambda syntax

| | |
|---|---|
| ID prefix | RH3004 |
| Status | Active |
| Category | Clarity |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH3004UseLambdaSyntaxAnalyzer`, `RH3004UseLambdaSyntaxCodeFixProvider` |
| Uses | — |

RH3004 reports an anonymous method written with `delegate` and a parameter list and offers a code fix that rewrites it as a lambda expression.

## Non-goals

- An anonymous method without a parameter list, `delegate { }`, which no lambda expresses: a lambda always states its parameters.
- An empty parameter list `delegate () { }` as such — RH3106 reports the parentheses; RH3004 reports the anonymous method.

## Requirements

### RH3004-001 — An anonymous method with a parameter list is reported

The analyzer MUST report an anonymous method that has a parameter list, empty or not. An anonymous method without a parameter list MUST NOT be reported.

Why: A lambda is the normal C# form for an inline function and says the same with less syntax. Without a parameter list, the anonymous method converts to a delegate of any parameter list, which no lambda can express.

Example:

```csharp
using System;

class C
{
    void M()
    {
        Func<int, int> a = {|RH3004:delegate|} (int x) { return x + 1; };
        Func<int> b = {|RH3004:delegate|} () { return 1; };
        Action c = delegate { };
    }
}
```

### RH3004-002 — The diagnostic is on `delegate`

The analyzer MUST report one diagnostic per anonymous method, on its `delegate` keyword.

Why: The keyword is what marks the old syntax; the parameters and the body stay.

Example: see RH3004-001.

### RH3004-003 — The fix writes a lambda

For an anonymous method that is neither the operand of a cast nor an operand of a binary operator, the code fix MUST replace it with a lambda that has the same parameter list, `async` when the anonymous method was `async`, and as its body:

- the expression of the only statement, when the block holds exactly one `return` statement with an expression and no comment or directive;
- the block, unchanged, otherwise.

Why: The parameter list and the statements carry the meaning and are kept as written. A block that only returns a value reads best as an expression body; any other block, or one with comments, keeps its statements.

Example:

```csharp
using System;
using System.Threading.Tasks;

class C
{
    void M()
    {
        Func<int, int> a = {|RH3004:delegate|} (int x) { return x + 1; };
        Action<int> b = {|RH3004:delegate|} (int x) { Console.WriteLine(x); };
        Func<Task> c = async {|RH3004:delegate|} () { await Task.Delay(1); };
        Func<int, int> d = {|RH3004:delegate|} (int x) { return x; /* c */ };
    }
}
```

```csharp
using System;
using System.Threading.Tasks;

class C
{
    void M()
    {
        Func<int, int> a = (int x) => x + 1;
        Action<int> b = (int x) => { Console.WriteLine(x); };
        Func<Task> c = async () => { await Task.Delay(1); };
        Func<int, int> d = (int x) => { return x; /* c */ };
    }
}
```

### RH3004-004 — A comment or a directive outside the parameter list and the body withholds the fix

The code fix MUST NOT be offered when a comment or a preprocessor directive stands between the start of the anonymous method and its parameter list, or between the parameter list and the body. The diagnostic is still reported.

Why: The lambda is built from the parameter list and the body; a comment or directive between them belongs to neither and would be lost.

Example:

```csharp
using System;

class C
{
    void M()
    {
        Func<int, int> a = {|RH3004:delegate|} (int x) /* c */ { return x; };
    }
}
```

is reported, and no code fix is offered.
