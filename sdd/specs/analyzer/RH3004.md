# Analyzer — RH3004 Use lambda syntax

| | |
|---|---|
| ID prefix | RH3004 |
| Status | Active |
| Category | Clarity |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH3004UseLambdaSyntaxAnalyzer`, `RH3004UseLambdaSyntaxCodeFixProvider` |
| Uses | FMT-BREAK-002, FMT-INDENT-028, FMT-RAW-001, FMT-RAW-002, SHARED-FIX-003, SHARED-FIX-007 |

RH3004 reports an anonymous method written with `delegate` and a parameter list and offers a code fix that rewrites it as a lambda expression.

## Non-goals

- An anonymous method without a parameter list, `delegate { }`, which no lambda expresses: a lambda always states its parameters.
- An empty parameter list `delegate () { }` as such — RH3106 reports the parentheses; RH3004 reports the anonymous method.

## Requirements

### RH3004-001 — An anonymous method with a parameter list is reported

The analyzer MUST report an anonymous method that has a parameter list, empty or not. An anonymous method without a parameter list MUST NOT be reported.

Why: A lambda is the normal C# form for an inline function and says the same with less syntax. Without a parameter list, the anonymous method converts to a delegate of any parameter list, which no lambda can express.

Example:

```csharp
using System;

class C
{
    void M()
    {
        Func<int, int> a = {|RH3004:delegate|} (int x) { return x + 1; };
        Func<int> b = {|RH3004:delegate|} () { return 1; };
        Action c = delegate { };
    }
}
```

### RH3004-002 — The diagnostic is on `delegate`

The analyzer MUST report one diagnostic per anonymous method, on its `delegate` keyword.

Why: The keyword is what marks the old syntax; the parameters and the body stay.

Example: see RH3004-001.

### RH3004-003 — The fix writes a lambda

For an anonymous method whose fix RH3004-004, RH3004-005, RH3004-008, and RH3004-009 do not withhold, the code fix MUST replace it with a lambda that has the same parameter list, `async` when the anonymous method was `async`, and as its body:

- the expression of the only statement, when the block holds exactly one `return` statement with an expression and no comment or directive;
- the block's statements, unchanged, otherwise, laid out as RH3004-006 states.

Why: The parameter list and the statements carry the meaning and are kept as written. A block that only returns a value reads best as an expression body; any other block, or one with comments, keeps its statements.

Example:

```csharp
using System;
using System.Threading.Tasks;

class C
{
    void M()
    {
        Func<int, int> a = {|RH3004:delegate|} (int x) { return x + 1; };
        Action<int> b = {|RH3004:delegate|} (int x) { Console.WriteLine(x); };
        Func<Task> c = async {|RH3004:delegate|} () { await Task.Delay(1); };
        Func<int, int> d = {|RH3004:delegate|} (int x) { return x; /* c */ };
    }
}
```

```csharp
using System;
using System.Threading.Tasks;

class C
{
    void M()
    {
        Func<int, int> a = (int x) => x + 1;
        Action<int> b = (int x) =>
                        {
                            Console.WriteLine(x);
                        };
        Func<Task> c = async () =>
                       {
                           await Task.Delay(1);
                       };
        Func<int, int> d = (int x) =>
                           {
                               return x; /* c */
                           };
    }
}
```

### RH3004-004 — A comment or a directive outside the parameter list and the body withholds the fix

The code fix MUST NOT be offered when a comment or a preprocessor directive stands between the start of the anonymous method and its parameter list, or between the parameter list and the body. The diagnostic is still reported.

Why: The lambda is built from the parameter list and the body; a comment or directive between them belongs to neither and would be lost.

Example:

```csharp
using System;

class C
{
    void M()
    {
        Func<int, int> a = {|RH3004:delegate|} (int x) /* c */ { return x; };
    }
}
```

is reported, and no code fix is offered.

### RH3004-005 — An operand of a cast or a binary operator withholds the fix

The code fix MUST NOT be offered for an anonymous method that is directly the operand of a cast or an operand of a binary operator. The diagnostic is still reported. An anonymous method inside parentheses that are the operand, and one that is the value of an assignment, including a compound assignment such as `+=`, is rewritten as RH3004-003 states.

Why: A lambda is not a valid operand of a cast or a binary operator without parentheses: in front of an operator, the lambda's body takes in the rest of the expression, so `delegate () { return 1; } + h` would become `() => 1 + h`, and a block body in front of an operator draws warning CS8848, as `() => { } + g` does; behind a cast or an operator, the lambda does not parse as the operand (SHARED-FIX-003). The fix does not write the parentheses that would keep the meaning.

Example:

```csharp
using System;

class C
{
    void M(Func<int> h, Action g)
    {
        var a = (Func<int, int>){|RH3004:delegate|} (int x) { return x + 1; };
        var b = {|RH3004:delegate|} () { return 1; } + h;
        var c = g + {|RH3004:delegate|} () { };
    }
}
```

is reported, and no code fix is offered. Inside parentheses and as the value of a compound assignment, the fix rewrites the anonymous method:

```csharp
using System;

class C
{
    void M(Func<int> g)
    {
        var a = (Func<int, int>)({|RH3004:delegate|} (int x) { return x + 1; });
        g += {|RH3004:delegate|} () { return 1; };
    }
}
```

```csharp
using System;

class C
{
    void M(Func<int> g)
    {
        var a = (Func<int, int>)((int x) => x + 1);
        g += () => 1;
    }
}
```

### RH3004-006 — The lambda is laid out as the formatter lays it out

The code fix MUST lay out the lambda it writes as the formatter lays it out (SHARED-FIX-007): the braces of a block body each start their own line (FMT-BREAK-002), and both start in the column of the lambda's anchor — `async`, or the opening parenthesis of the parameter list (FMT-INDENT-028). This holds whether the anonymous method's block stood on one line, as in RH3004-003, or on lines of its own, also with its opening brace on the line after the parameter list. An expression body stays on the line of `=>`.

The lambda's parameter list, `=>`, and braces are the code the fix lays out. The block's statements, with the comments and blank lines between them, are code the fix moves (SHARED-FIX-007, moved code): they MUST keep their own layout — the spacing between their tokens, their line breaks, their braces, and the blank lines inside the block — also where formatting the result would change it. Only the indentation of their lines MUST follow the braces. A block the fix keeps as a block body holds no preprocessor directive and no disabled text (RH3004-009), and no string literal and no delimited comment that spans lines (RH3004-008), so each of its lines that is not blank starts with a token or a comment that begins on that line. One rule gives every such line exactly one of two outcomes:

- A line **stays**, keeping its columns, when it holds no code, only comments and whitespace, and its first comment starts in column 0, such as a line of code commented out by an editor's comment toggle. Each line of a documentation comment written with `///` is decided on its own marker.
- Every other line **moves**: every line that holds code, also where a comment in front of the code starts in column 0, and a line that holds no code and whose first comment starts in another column.

Every moving line moves by the same number of columns, the shift, except where one of the two paragraphs below moves the moving lines by another number. A line that stays never moves, and no part of this requirement measures on it or counts it. The shift puts the block's first statement line one indentation level inside the braces, and the other moving lines keep their indentation relative to it. The first statement line is the first line of the block, in source order, on which a statement starts. That line holds code, so it always moves. The shift is measured on the first statement line from its first character, also where that character starts a comment in front of the statement, not on the block's first line: a comment line in front of the first statement does not decide it. In a block in which no line holds a statement, the shift is measured on the block's first moving line, and a block without a moving line has nothing to move. Statements that stood on the block's one line move together onto one line of their own between the braces.

When the block's first statement starts on the line of its opening brace and moving lines stand after that line, those lines keep their indentation relative to the first statement only when none of them starts left of the first statement in the source. Otherwise, they move together by the number of columns that puts the leftmost of them one indentation level inside the braces, in the column of the first statement, and keep their indentation relative to each other, so that no moving line stands left of the statements. Only moving lines count for the leftmost line.

When the first statement starts on a line of its own and moving every moving line by the shift would put one of them left of column 0, every moving line instead moves by the number of columns that puts the leftmost moving line one indentation level inside the braces, in the column of the statements, and the moving lines keep their indentation relative to each other. Every moving line counts for the leftmost line, also a comment line in front of the first statement; only moving lines count. Where no moving line would stand left of column 0, the shift applies, also where it puts a line in the column of the braces or left of them, such as a comment or a label the author wrote left of the statements. No moving line is ever cut off at column 0.

Why: A fix whose result the formatter changes again hands the user a second diff for the same correction (SHARED-FIX-007), and a block body on one line is reported by RH5417, which offers no fix for a lambda. The statements inside the block are the author's code that only changes its position, so reformatting them would hide the rewrite in layout changes nobody asked for; the formatter and the layout rules still correct them on their own. Giving every line exactly one outcome keeps the rule closed: a line that holds code is part of a statement and moves with it, whatever stands in front of it on the line, and the line that sets the shift is a moving line, so it always moves by the shift it sets. A comment alone in column 0 belongs to no nesting depth; such a comment is most often code commented out by an editor, which writes the comment marker in column 0, so it stays where it was written and does not push the statements to the right. A statement written behind the opening brace moves to the left onto its own line, while the lines after it were indented for the block, not for that statement: keeping their offset to it would put them left of the braces, or cut off at column 0. Measured on their own leftmost line, they keep the layout the author gave them relative to each other. In a block whose first statement starts its own line, the author placed every line, so the shift keeps all of them as written relative to each other, also a line written left of the statements; only a line that would cross column 0 forces another shift, because cutting it off there would lose its indentation relative to the others, so the whole block moves as far right as its leftmost line needs. The lines that a string or a comment over several lines, a directive, or disabled text would add to this rule are not decided here: the fix is withheld for them (RH3004-008, RH3004-009).

### RH3004-007 — A multi-line raw string literal withholds an expression body only by a `#` line

Where the fix writes an expression body — the block holds exactly one `return` statement with an expression and no comment or directive (RH3004-003, first item) — a multi-line raw string literal in that expression, also an interpolated or a UTF-8 one, MUST NOT withhold the fix on its own: the formatter lays out the expression body, and moves the literal's content lines and closing quotes together so the closing quotes start under the opening quotes (FMT-RAW-001, FMT-RAW-002), and the literal keeps its value. Such a literal withholds the fix there only when it has a `#` line, as every string or delimited comment over several lines with one does (RH3004-008). Where the fix would keep the anonymous method's block as the lambda's block body (RH3004-003, second item), a multi-line raw string literal in that block withholds the fix by RH3004-008, as every string literal over several lines does, whatever its lines start with; the diagnostic is still reported. A raw string literal on one line does not withhold the fix on either path.

Why: For a block body, the fix itself moves the lines of the block to new columns (RH3004-006). The value of a multi-line raw string literal depends on the column of each of its lines relative to its closing quotes, also of a line that holds only whitespace, so moving those lines risks changing the literal's value, which SHARED-FIX-003 forbids. An expression body moves no line by the fix's own rule: the formatter lays it out, raw string literals included, and moving the literal's lines together keeps its value, so a guard on every multi-line raw string literal there would refuse inputs the fix rewrites safely. The expression body is not free of every hazard, though: the fix still deletes and writes text behind the literal, and a later line of the literal that starts with `#` can be a directive in another build, where that text can be the inside of another string. That hazard is the same for every string and every delimited comment, raw or not, and RH3004-008 decides it.

Example:

```csharp
using System;

class C
{
    void M()
    {
        Action<int> b = {|RH3004:delegate|} (int x)
        {
            Console.WriteLine("""
                a
                """);
        };
    }
}
```

is reported, and no code fix is offered (RH3004-008). On the other side, a block that is a single `return` of a multi-line raw string literal, none of whose lines starts with `#`, becomes an expression body, and the fix is offered. The literal's lines move under the opening quotes, and its value, `a`, a line break, and `  b`, stays:

```csharp
using System;

class C
{
    void M()
    {
        Func<string> f = {|RH3004:delegate|} ()
        {
            return """
                a
                  b
                """;
        };
    }
}
```

```csharp
using System;

class C
{
    void M()
    {
        Func<string> f = () => """
                               a
                                 b
                               """;
    }
}
```

A raw string literal on one line does not withhold the fix:

```csharp

    {
        Action<int> b = {|RH3004:delegate|} (int x) { Console.WriteLine("""a"""); };
    }
```

### RH3004-008 — A string or a comment that spans lines withholds the fix

A *spanning carrier* is either of these, where it starts on one line and ends on a later one:

- a string literal or an interpolated string of any kind — regular, verbatim, interpolated, raw, or UTF-8 — measured from its first character (`@`, `$`, or the opening quote) through its closing quote and a `u8` suffix, holes included;
- a delimited comment, `/* */` or `/** */`.

A *`#` line* of a spanning carrier is one of the later lines it covers whose first character that is not whitespace, as the C# lexer counts whitespace — space, tab, vertical tab, form feed, and every other character the lexer skips as whitespace — is `#`. A `#` behind other text on its line does not make a `#` line.

The code fix MUST NOT be offered:

1. on either path of RH3004-003, when the anonymous method, from its first token, `async` or `delegate`, through the block's closing brace — its parameter list included — holds a spanning carrier with a `#` line;
2. when the fix would keep the anonymous method's block as the lambda's block body (RH3004-003, second item) and the anonymous method, over the same span, holds any spanning carrier, whatever its lines start with.

The diagnostic is still reported. Each condition has two sides:

- **Path.** Where the fix writes an expression body (RH3004-003, first item), a spanning carrier without a `#` line does not withhold the fix: a verbatim, interpolated, or raw string over several lines that the block returns is rewritten (RH3004-007). Where the fix keeps a block body, every spanning carrier withholds it.
- **Place.** A spanning carrier in the parameter list counts as one in the block. A comment between the anonymous method's first token and its parameter list, or between the parameter list and the block, already withholds the fix by RH3004-004. This requirement decides only on the strings and comments that stand inside that span; a string or a comment that starts before the anonymous method's first token is not decided by it.
- **Line start.** A later line whose first character other than whitespace is `#`, also behind spaces, tabs, or a form feed, is a `#` line; a line holding `#` behind other text, such as `b #c`, is not. On the block-body path, a carrier without a `#` line still withholds the fix by the second condition.
- **One line.** A string or a delimited comment on one line never withholds the fix, and neither do comments written with `//` or `///`, each of which ends on its own line; a block's lines are then decided as RH3004-006 states.

The withheld fix is a deliberate gap in the fix's coverage: such an anonymous method is rewritten by hand. Rewriting such an anonymous method so that every string keeps its value in every build is left open.

Why: In the build the fix sees, the anonymous method holds no directive (RH3004-009), so a line that is a directive in another build lies, in this one, inside a string or a delimited comment. Where a conditional chain, also one standing wholly outside the anonymous method, turns off the line that opens the string or the comment, a `#` line of it is a directive in that build, and the lines after it are code or the inside of another string there. Every edit the fix makes behind such a line — deleting `return` and the braces and writing `=>` on the expression-body path, also writing `=>` behind the parameter list and moving the block's lines on the block-body path — can then change a string's value in that build, which SHARED-FIX-003 forbids. The expression body is therefore not free of the hazard: the fix moves no line there, but it still deletes and writes text, and the parameter list is the same text on both paths. A spanning carrier without a `#` line hides no directive line from any build, so on the expression-body path, where the formatter lays out the result (RH3004-007), it does not withhold the fix. On the block-body path the fix moves the block's lines itself, and no reading of the text alone tells which lines of a carrier are safe to move for every set of symbols, so every spanning carrier withholds the fix there, without deciding on `#` or on whitespace; the parameter list belongs to the same span, so that no carrier of the anonymous method lies outside the guard. Deciding on every string and delimited comment of the anonymous method ends that class for every line the anonymous method holds, without knowledge of the directives around it. It does not see a line hidden in a string or a comment that starts before the anonymous method.

### RH3004-009 — A directive or disabled text in the anonymous method withholds the fix

The code fix MUST NOT be offered, on either path of RH3004-003, when the anonymous method, from its first token, `async` or `delegate`, through the block's closing brace, holds any preprocessor directive — a conditional directive, `#region`, `#endregion`, `#pragma`, `#nullable`, `#define`, `#undef`, `#line`, `#error`, `#warning`, or any other — or any disabled text: in its parameter list, between the parameter list and the block (RH3004-004 already withholds there), or inside the block. The diagnostic is still reported. A directive that stands wholly outside the anonymous method, before its first token or after its closing brace, does not withhold the fix, also where it opens or closes a conditional chain around the anonymous method. The withheld fix is a deliberate gap in the fix's coverage: such an anonymous method is rewritten by hand. Building the lambda so that the anonymous method's directives keep their structure and layout is left open.

Why: The fix rebuilds the lambda from the text of the parameter list and of the body, joined by `=>`, and reparses that text without the document's preprocessor symbols. A directive in that text whose chain partner lies outside it, or a directive chain the seam at `=>` splits, reaches that reparse unbalanced, and the result loses code and directives or does not compile; a `#region` whose `#endregion` lies outside the text leaves the braces out of the formatter's layout (SHARED-FIX-007). On the block path, the fix also moves the block's lines, and which of them are code or a directive depends on symbols the fix does not see, so the result could differ by build (SHARED-FIX-003). Deciding on any directive or disabled text in the anonymous method ends both classes without reading the document's directive structure. The departure this makes from laying out a block with a conditional chain in column 0 is deliberate: such a block is rewritten by hand.

Example:

```csharp
using System;

class C
{
    void M()
    {
        Action<int> b = {|RH3004:delegate|} (int x)
        {
#if DEBUG
            Console.WriteLine(x);
#else
            Console.WriteLine(-x);
#endif
        };
    }
}
```

is reported, and no code fix is offered, with and without `DEBUG`: the chain lies wholly inside the block, but it is a directive in the anonymous method. The same holds where a chain crosses the parameter list and the block, with `A` defined:

```csharp
#define A
using System;

class C
{
    void M()
    {
        Action<int> a = {|RH3004:delegate|} (
#if A
            int x)
        {
            Console.WriteLine(x);
#else
            int x) { Console.WriteLine(-x);
#endif
        };
    }
}
```

and on the expression-body path, where the block only returns a value and the directives stand in the parameter list:

```csharp
using System;

class C
{
    void M()
    {
        Func<int, int> f = {|RH3004:delegate|} (
#if A
            int x
#else
            int x
#endif
            ) { return x + 1; };
    }
}
```

and, with `A` defined, where a chain crosses `delegate`, and where a `#region` before `delegate` ends in the block:

```csharp

class C
{
    void M()
    {
        Action a =
#if A
            {|RH3004:delegate|} ()
            {
                Console.WriteLine(1);
#else
            () =>
            {
                Console.WriteLine(2);
#endif
                Console.WriteLine(3);
            };

#region Init
            {|RH3004:delegate|} ()
            {
                Console.WriteLine(1);
#endregion
            };
    }
}
```

Each of these is reported, and no code fix is offered. `#pragma` and `#region` inside the block withhold the fix in the same way:

```csharp
        };

```

is reported, and no code fix is offered.

On the other side, a chain wholly outside the anonymous method does not withhold the fix:
