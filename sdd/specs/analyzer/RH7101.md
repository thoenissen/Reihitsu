# Analyzer — RH7101 Do not combine fields

| | |
|---|---|
| ID prefix | RH7101 |
| Status | Active |
| Category | Organization |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH7101DoNotCombineFieldsAnalyzer`, `RH7101DoNotCombineFieldsCodeFixProvider` |
| Uses | FMT-STRUCT-021, FMT-STRUCT-022, FMT-STRUCT-023, SHARED-DOC-004, SHARED-FIX-003 |

RH7101 reports a field declaration that declares more than one field, and offers a code fix that splits it into one declaration per field.

## Non-goals

- Event field declarations and local variable declarations with several declarators.
- The order of the fields after the split — RH7102, RH7103, RH7109, RH7110.

## Requirements

### RH7101-001 — A field declaration with several declarators is reported

The analyzer MUST report a field declaration with more than one declarator in a class, struct, interface, record, or record struct, whatever its modifiers — `const`, `static`, `readonly`, and fixed-size buffers included — when no `#if`, `#elif`, `#else`, or `#endif` directive stands between its declarators.

Why: Each field deserves its own line for its documentation, attributes, and diff history; a combined declaration also hides a second field behind the first one's type and modifiers.

Example:

```csharp
interface I
{
    static int A, {|RH7101:B|};
}

struct S
{
    public int X, {|RH7101:Y|};
}

record R
{
    public const int A = 1, {|RH7101:B|} = 2;
}

unsafe struct U
{
    public fixed int A[2], {|RH7101:B|}[3];
}
```

### RH7101-002 — Event fields and locals are not reported

The analyzer MUST NOT report an event field declaration or a local variable declaration with several declarators.

Why: The rule is about the fields of a type. An event field declaration is not a field declaration, and locals are not part of a type's state.

Example:

```csharp
using System;

class C
{
    public event Action E1, E2;

    void M()
    {
        int a, b;
    }
}
```

is not reported.

### RH7101-003 — One diagnostic per declaration, on the second declarator

The analyzer MUST report one diagnostic per field declaration, located on the identifier of its second declarator.

Why: The second declarator is the first field that should have a declaration of its own; one diagnostic per declaration matches the fix, which splits the whole declaration at once.

Example:

```csharp
class C
{
    private int _a, {|RH7101:_b|} = 1, _c;
}
```

### RH7101-004 — The fix splits the declaration

Unless RH7101-005 or RH7101-006 withholds it, the code fix MUST split the reported field declaration into one declaration per declarator as specified in FMT-STRUCT-021, and MUST keep its comments as specified in FMT-STRUCT-022.

Why: The fix makes exactly the change the formatter makes, so applying the fix and formatting the file give the same fields.

Example:

```csharp
using System;

class C
{
    [NonSerialized]
    private static readonly string _a = "a", {|RH7101:_b|} = "b";
}
```

```csharp
using System;

class C
{
    [NonSerialized]
    private static readonly string _a = "a";
    [NonSerialized]
    private static readonly string _b = "b";
}
```

A comment that trailed a separating comma trails the field that comma now ends:

```csharp
class C
{
    private int _first, // first
                {|RH7101:_second|}; // second
}
```

```csharp
class C
{
    private int _first; // first
    private int _second; // second
}
```

### RH7101-005 — The fix is withheld for a declaration with a directive

The code fix MUST NOT be offered for a field declaration that the formatter does not split under FMT-STRUCT-023. When the declaration contains no `#if`, `#elif`, `#else`, or `#endif` directive, the diagnostic is still reported.

Why: The split cannot carry a directive or disabled text over to the generated fields, so a fix would drop the directive or move it to a different field. A reported diagnostic without a fix is a supported end state.

Example:

```csharp
class C
{
    #region Fields
    private int _a, {|RH7101:_b|};
    #endregion
}
```

is reported, and no code fix is offered.

### RH7101-006 — The fix is withheld for a documented declaration

When the documentation mode of the syntax tree is `Parse` or `Diagnose`, the code fix MUST NOT be offered for a field declaration that has a documentation comment (SHARED-DOC-004), a `///` comment or a `/** */` comment. The diagnostic is still reported. In the documentation mode `None`, such a comment is an ordinary comment, and the fix splits the declaration as RH7101-004 states.

Why: The documentation comment of a declaration with several declarators documents each of its fields, and the split keeps it on the first field only (FMT-STRUCT-022), so every other field would lose its documentation (SHARED-FIX-003). Whether the comment fits each field or each field needs its own is the author's decision. When documentation comments are not parsed, the comment documents no field and nothing is lost.

Example:

```csharp
class C
{
    /// <summary>The coordinates</summary>
    public int X, {|RH7101:Y|};

    /** <summary>The sizes</summary> */
    public int Width, {|RH7101:Height|};
}
```

is reported, and no code fix is offered. In the documentation mode `None`, the fix splits both declarations:

```csharp
class C
{
    /// <summary>The coordinates</summary>
    public int X;
    public int Y;

    /** <summary>The sizes</summary> */
    public int Width;
    public int Height;
}
```

An ordinary comment does not withhold the fix:

```csharp
class C
{
    // The coordinates
    public int X, {|RH7101:Y|};
}
```

```csharp
class C
{
    // The coordinates
    public int X;
    public int Y;
}
```
