# Analyzer — RH5023 Code must not contain multiple blank lines in a row

| | |
|---|---|
| ID prefix | RH5023 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5023CodeMustNotContainMultipleBlankLinesInARowAnalyzer`, `RH5023CodeMustNotContainMultipleBlankLinesInARowCodeFixProvider` |
| Uses | SHARED-WS-001 |

RH5023 reports every blank line that directly follows another blank line, and offers a code fix that deletes it as SHARED-WS-001 specifies, so each run of blank lines shrinks to one.

In the examples, a reported blank line is marked from its start to the end of its line break, so the markup encloses the line break itself.

## Non-goals

- A single blank line next to a brace or a chained keyword — RH5022 and RH5024 to RH5027, which report the first blank line of a run there, while this rule reports the rest.
- A single blank line at the start of the file — RH5028.

## Requirements

### RH5023-001 — Each blank line after the first of a run is reported

The analyzer MUST report a blank line that ends with a line break and directly follows another blank line. A line holding nothing but whitespace counts as blank, so a run of two or more blank lines is reported once for each line after its first.

Why: One blank line is enough to separate two pieces of code; every further line only spreads the code out.

Example:

```csharp
class C
{
    void M()
    {
        var a = 1;

{|RH5023:
|}{|RH5023:
|}        a++;
    }
}
```

### RH5023-002 — Lines of literals, multi-line comments, and disabled code are not considered

The analyzer MUST NOT report a line that holds part of a string literal (including verbatim, raw, and interpolated strings), of a multi-line comment (`/* */`, `/** */`), or of disabled text inside an `#if` branch that is not taken, and MUST NOT count such a line as blank when it decides whether the line below it follows a blank line.

Why: Those lines are part of the string's value, the comment's text, or code the current build does not compile; deleting one would change the program or the author's text rather than its layout.

Example — only the second blank line below the block comment is reported:

```csharp
class C
{
    void M()
    {
        var a = 1;
        /* one


           two */

{|RH5023:
|}        a++;
#if NEVER
        a++;


#endif
        var s = @"x


y";
    }
}
```

### RH5023-003 — One diagnostic per surplus line

The analyzer MUST report one diagnostic per reported line, located from the line's start to the end of its line break.

Why: Each surplus line is deleted on its own, and Fix All deletes all of them in one application.

Example: see RH5023-001.

### RH5023-004 — The fix deletes the blank line

The code fix MUST delete the reported line as SHARED-WS-001 specifies. It is offered for every reported line.

Why: The reported span holds nothing but whitespace and its line break, so deleting it can never touch a comment, a directive, or a token.

Example:

```csharp
class C
{
    void M()
    {
        var a = 1;

{|RH5023:
|}{|RH5023:
|}        a++;
    }
}
```

```csharp
class C
{
    void M()
    {
        var a = 1;

        a++;
    }
}
```
