# Analyzer — RH4009 Namespace not allowed

| | |
|---|---|
| ID prefix | RH4009 |
| Status | Active |
| Category | Naming |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH4009NamespaceNotAllowedAnalyzer` |
| Uses | — |

RH4009 reports a namespace declaration whose name is not on the allow-list `naming.allowedNamespaceDeclarations` of the `reihitsu.json` configuration file.

## Non-goals

- Validating the configuration file and the shape of the `naming` section — RH0001 (RH0001-005).
- The casing of namespace names — RH4007 and RH4008.
- Whether a namespace matches the folder of its file.

## Requirements

### RH4009-001 — The rule is active only with a non-empty allow-list

The analyzer MUST NOT report anything when the project has no `reihitsu.json`, when the file is not valid JSON, or when `naming.allowedNamespaceDeclarations` is missing or has no entry that is a string. Entries that are not strings MUST be ignored; the strings of the list stay in effect.

Why: Which namespaces a project may declare is the project's own decision; without a list there is nothing to check against.

Example:

```csharp
namespace Company.Product
{
}
```

is not reported without a configuration file, with `{ "naming": { } }`, with `{ "naming": { "allowedNamespaceDeclarations": [] } }`, with `{ "naming": { "allowedNamespaceDeclarations": [ 1 ] } }`, and with a file whose JSON is malformed. With `{ "naming": { "allowedNamespaceDeclarations": [ "A", 1 ] } }`, the same declaration is reported, because `"A"` stays in effect.

### RH4009-002 — A namespace that is not on the list is reported

The analyzer MUST report a block-scoped or file-scoped namespace declaration of a file, declared at file level and with a name written as identifiers joined by dots, without `@`, whitespace, or comments, when that name is not exactly one of the entries of the list. The comparison MUST be case-sensitive, and an entry MUST NOT allow its child namespaces. The diagnostic MUST be located on the whole namespace name.

Why: The list pins the namespaces of the project, so a namespace that is not on it usually comes from a file in the wrong place or copied from elsewhere. Each namespace that is allowed is listed on its own, so a child namespace is a decision of its own.

Example — with `{ "naming": { "allowedNamespaceDeclarations": [ "MyCompany.Project" ] } }`:

```csharp
namespace MyCompany.Project
{
}

namespace {|RH4009:MyCompany.Project.Data|}
{
}

namespace {|RH4009:mycompany.project|}
{
}
```

In another file of the same project,

```csharp
namespace {|RH4009:MyCompany.Internal|};
```

is reported as well.
