# Analyzer — RH3007 Do not use query syntax

| | |
|---|---|
| ID prefix | RH3007 |
| Status | Active |
| Category | Clarity |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH3007DoNotUseQuerySyntaxAnalyzer` |
| Uses | — |

RH3007 reports a LINQ query expression. It offers no code fix.

## Non-goals

- Calls of the query operators in method syntax, such as `Where` or `Select`, which are the form the rule asks for.

## Requirements

### RH3007-001 — Every query expression is reported

The analyzer MUST report every query expression, whatever its clauses, including a query nested inside another query. A query continued with `into` is one query expression and MUST be reported once.

Why: Method syntax is the form the rest of the code uses for LINQ; it composes with every extension method and keeps the style uniform. A nested query is a query expression of its own.

Example:

```csharp
using System.Linq;

class C
{
    void M(int[] xs, int[] ys)
    {
        var a = {|RH3007:from|} x in xs where x > 0 select x;
        var b = {|RH3007:from|} x in xs
                group x by x % 2 into g
                select g.Key;
        var c = {|RH3007:from|} x in xs
                from y in ({|RH3007:from|} z in ys select z)
                select x + y;
        var d = xs.Where(x => x > 0);
    }
}
```

### RH3007-002 — The diagnostic is on the first `from`

The analyzer MUST report one diagnostic per query expression, on the `from` keyword of its first clause.

Why: The keyword marks where the query starts without covering the whole, often multi-line, expression.

Example: see RH3007-001. The second `from` of the query assigned to `c` starts a clause of the same query and is not reported; the nested query after `in` is reported on its own `from`.
