# Analyzer — RH3106 Unnecessary delegate parentheses should be removed

| | |
|---|---|
| ID prefix | RH3106 |
| Status | Active |
| Category | Clarity |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH3106UnnecessaryDelegateParenthesesShouldBeRemovedAnalyzer`, `RH3106UnnecessaryDelegateParenthesesShouldBeRemovedCodeFixProvider` |
| Uses | SHARED-PARENS-001, SHARED-PARENS-002, SHARED-PARENS-003, SHARED-DIAG-011, SHARED-FIX-002, SHARED-FIX-003 |

RH3106 reports the empty parameter list of an anonymous method, `delegate () { }`, and offers a code fix that removes it. Where the diagnostic is and what the fix produces are SHARED-PARENS-001 and SHARED-PARENS-002. A comment inside the list withholds the fix (SHARED-PARENS-003).

## Non-goals

- Rewriting the anonymous method as a lambda — RH3004 reports every anonymous method with a parameter list, the empty one included.
- Empty parameter lists of methods, local functions, and lambdas, which the language requires.

## Requirements

### RH3106-001 — An empty parameter list of an anonymous method is reported

The analyzer MUST report the empty parameter list of an anonymous method wherever it stands, unless RH3106-003 applies: as the initializer of a variable whose type is a delegate type, as an argument (RH3106-002), as a value assigned or returned, and in any other expression. An anonymous method without a parameter list or with parameters MUST NOT be reported.

Why: `delegate () { }` says nothing that `delegate { }` does not; the parentheses describe parameters that do not exist.

Example:

```csharp
using System;
using System.Threading.Tasks;

class C
{
    void M()
    {
        Action a = delegate{|RH3106:()|} { };
        Func<Task> b = async delegate {|RH3106:()|} { await Task.Yield(); };
        Action c = delegate { };
        Action<int> d = delegate (int x) { };
    }
}
```

### RH3106-002 — The fix is withheld where removing the list changes what the code binds to

The code fix MUST NOT be offered for a reported empty parameter list when, without it, the code around the anonymous method would bind differently or would have a compile error it did not have: when the anonymous method would convert to another delegate type, or when a member chosen for it — a method, constructor, or indexer that overload resolution picks, a user-defined operator, an `Add` method of a collection initializer, or a type argument inferred from it — would be another one, would be ambiguous, or could no longer be found, as when the type arguments of a generic method can no longer be inferred (CS0411). The condition is the outcome on the code without the list, wherever the anonymous method stands, not a list of positions. Among the places where it can hold are an argument of an invocation, of an object creation, also a target-typed `new(…)`, of a constructor initializer (`base(…)` or `this(…)`), or of an element access; an operand of a binary operator; the value of a compound assignment such as `+=`, whether a `static` user-defined operator or a C# 14 instance compound assignment operator `operator +=` binds it; and an element of a collection initializer. Where the code binds as before and gains no error, this requirement does not withhold the fix. The empty parameter list stays reported in every such place (RH3106-001), unless RH3106-003 applies. The condition is decided on the code the fix is applied to, and under Fix All on the code the fixes of the diagnostics in front of it in the document produce (SHARED-FIX-002): two removals that each keep the binding alone, but not together, remove the first list and leave the second reported.

Why: Without a parameter list, an anonymous method converts to a delegate of any parameter list and has no natural type, so an overload, a user-defined operator, or an `Add` method that `delegate () { }` did not match can become applicable, and a type parameter that its natural type inferred has nothing to infer from (SHARED-FIX-003). The compile error comes from the other overloads, operators, or `Add` methods or from the generic signature, not from the position of the anonymous method, so the report stays (SHARED-DIAG-011). Deciding on the outcome rather than on the position covers every place where the language chooses among candidates, also the ones a list of positions would miss. Two anonymous methods of one call can each pin the overload alone, so removing both lists can make the call ambiguous where removing either does not.

Example:

```csharp
using System;

class C
{
    void Run(Action a)
    {
    }

    void Run(Action<int> a)
    {
    }

    void M()
    {
        Run(delegate {|RH3106:()|} { });
    }
}
```

is reported, and no code fix is offered. Neither is one offered for a constructor initializer with two applicable constructors, nor where a type argument is inferred from the anonymous method:

```csharp
using System;

class B
{
    public B(Action a)
    {
    }

    public B(Action<int> a)
    {
    }
}

class D : B
{
    public D()
        : base(delegate {|RH3106:()|} { })
    {
    }

    static T Run<T>(T t) => t;

    void M()
    {
        Run(delegate {|RH3106:()|} { });
    }
}
```

is reported, and no code fix is offered. Nor is one offered for an operand of a binary operator with two user-defined operators that the anonymous method converts to without its parameter list:

```csharp
using System;

class C
{
    public static C operator +(C c, Action a) => c;

    public static C operator +(C c, Action<int> a) => c;

    void M(C c)
    {
        _ = c + delegate {|RH3106:()|} { };
    }
}
```

is reported, and no code fix is offered: `c + delegate { }` would be ambiguous between the two operators. The same holds for a compound assignment, with `static` operators and with C# 14 instance compound assignment operators, and for an element of a collection initializer with two `Add` methods:

```csharp
using System;
using System.Collections;

class C
{
    public static C operator +(C c, Action a) => c;

    public static C operator +(C c, Action<int> a) => c;
}

class D
{
    public void operator +=(Action a)
    {
    }

    public void operator +=(Action<int> a)
    {
    }
}

class Coll : IEnumerable
{
    public void Add(Action a)
    {
    }

    public void Add(Action<int> a)
    {
    }

    public IEnumerator GetEnumerator() => throw new NotSupportedException();
}

class E
{
    void M(C c, D d)
    {
        c += delegate {|RH3106:()|} { };
        d += delegate {|RH3106:()|} { };
        var e = new Coll { delegate {|RH3106:()|} { } };
    }
}
```

is reported, and no code fix is offered: without the lists, `c += delegate { };` is ambiguous between the two operators (CS9342), and `d += delegate { };` and the collection initializer between the two methods (CS0121). With one applicable overload or one applicable operator, the fix removes the list:

```csharp
using System;

class C
{
    public static C operator +(C c, Action a) => c;

    void Run(Action a)
    {
    }

    void M(C c)
    {
        Run(delegate {|RH3106:()|} { });
        _ = c + delegate {|RH3106:()|} { };
    }
}
```

```csharp
using System;

class C
{
    public static C operator +(C c, Action a) => c;

    void Run(Action a)
    {
    }

    void M(C c)
    {
        Run(delegate { });
        _ = c + delegate { };
    }
}
```

Fix All, on two arguments that each pin the overload alone:

```csharp
using System;

class C
{
    void Run(Action a, Action b)
    {
    }

    void Run(Action<int> a, Action<int> b)
    {
    }

    void M()
    {
        Run(delegate {|RH3106:()|} { }, delegate {|RH3106:()|} { });
    }
}
```

```csharp
using System;

class C
{
    void Run(Action a, Action b)
    {
    }

    void Run(Action<int> a, Action<int> b)
    {
    }

    void M()
    {
        Run(delegate { }, delegate {|RH3106:()|} { });
    }
}
```

The second list stays reported without a fix: once the first is removed, removing it too would make the call ambiguous (CS0121).

### RH3106-003 — An anonymous method that takes its natural type is not reported

The analyzer MUST NOT report the empty parameter list of an anonymous method that takes its natural type: no delegate type is its target, so the code converts it to the delegate type its own parameter list gives it, or to a type that is not a delegate type, and no overload, user-defined operator, `Add` method of a collection initializer, or type inference of a generic method chooses among candidates for it. Without the parameter list, `delegate { }` has no natural type and cannot take the type the parameter list gave it. The condition is that outcome, wherever the anonymous method stands, not a list of positions. Among the places where an anonymous method takes its natural type are:

- the initializer of an implicitly typed local (`var`);
- an element of an implicitly typed array creation, `new[] { … }`;
- the expression a lambda or another anonymous method returns, as a lambda's expression body or in a `return` statement, when the enclosing function has no delegate type as its target and its return type is inferred from that expression, as in `var f = () => delegate () { };` and `var n = delegate () { return delegate () { }; };`;
- a variable, an assignment, a return value, a cast, or an element of a collection expression whose type is not a delegate type, such as `object`, `System.Delegate`, or the `object` elements of a collection expression over a type that implements only the non-generic `IEnumerable`, whatever `Add` methods the type declares;
- an argument whose parameter type is not a delegate type when no other overload is a candidate for the call and no type argument is inferred from the argument, such as the argument of `Run(object o)` as the only `Run`.

An anonymous method inside parentheses, in a branch of a conditional expression, or in an arm of a switch expression stands in the position of that parenthesized, conditional, or switch expression. A conditional or a switch expression whose branches are all anonymous methods has no natural type, so under `var` it does not compile (CS0173, CS8506); its anonymous methods reach this requirement through a target that is not a delegate type, such as `object`. An anonymous method whose target is a delegate type, also through parentheses or a conditional expression, MUST be reported as RH3106-001 states: also an element of an array creation that names its element type, and the expression a lambda returns whose delegate type is its target, such as `Func<Action>`, or whose return type the lambda declares, so `var f = Action () => delegate () { };` is reported. A delegate type also becomes the target through the expressions around the anonymous method: a conditional expression with another branch, a switch expression with another arm, and an implicitly typed array creation with another element that is not an anonymous function and whose type is a delegate type take that delegate type, and the anonymous method converts to it. Its empty parameter list MUST then be reported, also where the conditional, the switch expression, or the array creation is the initializer of an implicitly typed local, so `var x = b ? delegate () { } : someAction;` is reported. An argument, an operand, or an element whose binding competing overloads, user-defined operators, `Add` methods, or type inference decide MUST be reported as RH3106-002 states.

Why: An anonymous method has a natural type, from C# 10, only with a parameter list; `delegate { }` has none, so `var a = delegate { };` does not compile (CS8917), nor does its conversion to `object` or `System.Delegate`, also as the argument of a parameter of such a type or as an element of a collection expression of such elements. An implicitly typed array takes its element type, and a lambda or an anonymous method without a target its return type, from the natural type of the expression, so `new[] { delegate { } }` (CS0826), `var f = () => delegate { };`, and `var n = delegate () { return delegate { }; };` (CS8917) do not compile either. A lambda that declares its return type gives the anonymous method that type as its target, so the list can go. Parentheses, a conditional, or a switch expression pass the position on to the anonymous method. Where the anonymous method takes its natural type, its position rules the change out (SHARED-DIAG-011); deciding on that outcome rather than on a list of positions covers every place where it happens.

Example:

```csharp
using System;

class C
{
    static void Run(object o)
    {
    }

    object M(bool b)
    {
        var a = delegate () { };
        var e = (delegate () { });
        var h = new[] { delegate () { } };
        var f = () => delegate () { };
        var k = () =>
        {
            return delegate () { };
        };
        Delegate d = delegate () { };
        object o = delegate () { };
        Run(delegate () { });
        return delegate () { };
    }
}
```

is not reported. The uses of the local outside the declaration do not decide it, also where they stand in the same statement, such as the condition and the incrementor of a `for` statement whose initializer declares it:

```csharp
using System;

class C
{
    void M()
    {
        for (var a = delegate () { }; a != null; a()) { }
        Action f = () =>
        {
            for (var b = delegate () { }; b != null; b()) { }
        };
        for (var arr = new[] { delegate () { } }; arr.Length > 0; arr[0]()) { }
    }
}
```

is not reported either. Neither is a conditional branch or a switch-expression arm whose target is `object`:

```csharp
class C
{
    object M(bool b, int i)
    {
        object g = b ? delegate () { } : delegate () { };

        return i switch
               {
                   1 => delegate () { },
                   _ => (delegate () { })
               };
    }
}
```

Neither is an anonymous method that another anonymous method under `var` returns, nor an element of a collection expression whose elements are `object`:

```csharp
using System;
using System.Collections;

class Coll : IEnumerable
{
    public void Add(Action a)
    {
    }

    public void Add(Action<int> a)
    {
    }

    public IEnumerator GetEnumerator() => throw new NotSupportedException();
}

class C
{
    void M()
    {
        var n = delegate () { return delegate () { }; };
        Coll e = [delegate () { }];
    }
}
```

Where the target is a delegate type, the list is reported, also where a lambda declares the return type:

```csharp
using System;

class C
{
    void M(bool b)
    {
        Action a = b ? delegate {|RH3106:()|} { } : null;
        Action e = (delegate {|RH3106:()|} { });
        Action[] h = new Action[] { delegate {|RH3106:()|} { } };
        Func<Action> f = () => delegate {|RH3106:()|} { };
        var g = Action () => delegate {|RH3106:()|} { };
        var k = Action () =>
        {
            return delegate {|RH3106:()|} { };
        };
    }
}
```

The same holds where another branch, arm, or element gives the expression a delegate type, also under `var`:

```csharp
using System;

class C
{
    void M(bool b, int i, Action someAction)
    {
        var x = b ? delegate {|RH3106:()|} { } : someAction;
        var y = i switch
                {
                    1 => delegate {|RH3106:()|} { },
                    _ => someAction
                };
        var z = new[] { delegate {|RH3106:()|} { }, someAction };
    }
}
```

As a deliberate gap in this requirement, an anonymous method that is an element of an implicitly typed array creation, `new[] { … }`, none of whose other elements gives the array a delegate type, is decided by outcome in only two ways:

- it MUST NOT be reported where the array creation, or a value taken from it, stands in one of these shapes: the array creation is the initializer of an implicitly typed local (`var`), also in the initializer of a `for` statement and also where a later statement or a later part of the same statement invokes an element; another element of the array creation has a type that is not a delegate type, such as `new object()`, under `var`; or the array creation or an element taken from it by an element access is the receiver of `.Length`, of `.Method`, or of `.DynamicInvoke()`, the left operand of `is Action`, or the initializer of a local of type `object` or `System.Delegate`;
- everywhere else, its empty parameter list MAY be reported, and where it is reported, no code fix is offered. Among the positions where it is reported are an element taken from the array and invoked, directly, through `Invoke`, or through `BeginInvoke`; and the array or an element of it converted to a delegate type, to an array of delegates, or to a collection of delegates, as the initializer of a typed local, as the value of an assignment, or as an argument.

The requirement's outcome would leave every such anonymous method not reported, since nothing chooses a type for it there, but the analyzer does not tell an expression that only consumes the array's value apart from one that chooses a type for it. Reporting it with no fix changes no code. Telling such a consuming expression apart, so that none of these anonymous methods is reported, is left open.

```csharp
using System;
using System.Collections.Generic;

class C
{
    static void Run(Action a)
    {
    }

    void M()
    {
        var r = new[] { delegate {|RH3106:()|} { return 1; } }[0]();
        new[] { delegate {|RH3106:()|} { } }[0]();
        new[] { delegate {|RH3106:()|} { } }[0].Invoke();
        new[] { delegate {|RH3106:()|} { } }[0].BeginInvoke(null, null);
        Action x = new[] { delegate {|RH3106:()|} { } }[0];
        Func<int> g = new[] { delegate {|RH3106:()|} { return 1; } }[0];
        Action y;
        y = new[] { delegate {|RH3106:()|} { } }[0];
        Run(new[] { delegate {|RH3106:()|} { } }[0]);
        Action[] arr = new[] { delegate {|RH3106:()|} { } };
        IEnumerable<Action> e = new[] { delegate {|RH3106:()|} { } };
    }
}
```

is reported, and no code fix is offered. On the other side, the shapes of the first item are not reported, as the `var` and `for` examples above show, and as these do:

```csharp
using System;

class C
{
    void M()
    {
        var n = new[] { delegate () { } }.Length;
        var m = new[] { delegate () { } }[0].Method;
        var t = new[] { delegate () { } }[0] is Action;
        var v = new[] { delegate () { } }[0].DynamicInvoke();
        object o = new[] { delegate () { } }[0];
        Delegate d = new[] { delegate () { } }[0];
        var z = new[] { delegate () { }, new object() };
    }
}
```

is not reported.
