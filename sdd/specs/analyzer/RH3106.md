# Analyzer — RH3106 Unnecessary delegate parentheses should be removed

| | |
|---|---|
| ID prefix | RH3106 |
| Status | Active |
| Category | Clarity |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH3106UnnecessaryDelegateParenthesesShouldBeRemovedAnalyzer`, `RH3106UnnecessaryDelegateParenthesesShouldBeRemovedCodeFixProvider` |
| Uses | SHARED-PARENS-001, SHARED-PARENS-002, SHARED-PARENS-003, SHARED-DIAG-011, SHARED-FIX-002, SHARED-FIX-003 |

RH3106 reports the empty parameter list of an anonymous method, `delegate () { }`, and offers a code fix that removes it. Where the diagnostic is and what the fix produces are SHARED-PARENS-001 and SHARED-PARENS-002. A comment inside the list withholds the fix (SHARED-PARENS-003).

## Non-goals

- Rewriting the anonymous method as a lambda — RH3004 reports every anonymous method with a parameter list, the empty one included.
- Empty parameter lists of methods, local functions, and lambdas, which the language requires.

## Requirements

### RH3106-001 — An empty parameter list of an anonymous method is reported

The analyzer MUST report the empty parameter list of an anonymous method wherever it stands, unless RH3106-003 applies: as the initializer of a variable whose type is a delegate type, as an argument (RH3106-002), as a value assigned or returned, and in any other expression. An anonymous method without a parameter list or with parameters MUST NOT be reported.

Why: `delegate () { }` says nothing that `delegate { }` does not; the parentheses describe parameters that do not exist.

Example:

```csharp
using System;
using System.Threading.Tasks;

class C
{
    void M()
    {
        Action a = delegate{|RH3106:()|} { };
        Func<Task> b = async delegate {|RH3106:()|} { await Task.Yield(); };
        Action c = delegate { };
        Action<int> d = delegate (int x) { };
    }
}
```

### RH3106-002 — An argument or operand whose binding depends on the parameter list keeps its parentheses

The analyzer MUST report the empty parameter list of an anonymous method whose target is chosen by overload resolution or type inference, unless RH3106-003 applies: an argument of an invocation, of an object creation, also a target-typed `new(…)`, of a constructor initializer (`base(…)` or `this(…)`), or of an element access, and an operand of a binary operator for which overload resolution chooses among user-defined operators. The code fix MUST NOT be offered when, without the parameter list, the call or the operator would not bind to the same method, constructor, indexer, or operator: when it would bind to another one, would be ambiguous (CS0121 for a call), or would fail, as when the type arguments of a generic method can no longer be inferred (CS0411). Where it binds to the same one, this requirement does not withhold the fix. The condition is decided on the code the fix is applied to, and under Fix All on the code the fixes of the diagnostics in front of it in the document produce (SHARED-FIX-002): two removals that each keep the binding alone, but not together, remove the first list and leave the second reported.

Why: Without a parameter list, an anonymous method converts to a delegate of any parameter list and has no natural type, so an overload or a user-defined operator that `delegate () { }` did not match can become applicable, and a type parameter that its natural type inferred has nothing to infer from (SHARED-FIX-003). The compile error comes from the other overloads or operators or from the generic signature, not from the position of the anonymous method, so the report stays (SHARED-DIAG-011). Two anonymous methods of one call can each pin the overload alone, so removing both lists can make the call ambiguous where removing either does not.

Example:

```csharp
using System;

class C
{
    void Run(Action a)
    {
    }

    void Run(Action<int> a)
    {
    }

    void M()
    {
        Run(delegate {|RH3106:()|} { });
    }
}
```

is reported, and no code fix is offered. Neither is one offered for a constructor initializer with two applicable constructors, nor where a type argument is inferred from the anonymous method:

```csharp
using System;

class B
{
    public B(Action a)
    {
    }

    public B(Action<int> a)
    {
    }
}

class D : B
{
    public D()
        : base(delegate {|RH3106:()|} { })
    {
    }

    static T Run<T>(T t) => t;

    void M()
    {
        Run(delegate {|RH3106:()|} { });
    }
}
```

is reported, and no code fix is offered. Nor is one offered for an operand of a binary operator with two user-defined operators that the anonymous method converts to without its parameter list:

```csharp
using System;

class C
{
    public static C operator +(C c, Action a) => c;

    public static C operator +(C c, Action<int> a) => c;

    void M(C c)
    {
        _ = c + delegate {|RH3106:()|} { };
    }
}
```

is reported, and no code fix is offered: `c + delegate { }` would be ambiguous between the two operators. With one applicable overload or one applicable operator, the fix removes the list:

```csharp
using System;

class C
{
    public static C operator +(C c, Action a) => c;

    void Run(Action a)
    {
    }

    void M(C c)
    {
        Run(delegate {|RH3106:()|} { });
        _ = c + delegate {|RH3106:()|} { };
    }
}
```

```csharp
using System;

class C
{
    public static C operator +(C c, Action a) => c;

    void Run(Action a)
    {
    }

    void M(C c)
    {
        Run(delegate { });
        _ = c + delegate { };
    }
}
```

Fix All, on two arguments that each pin the overload alone:

```csharp
using System;

class C
{
    void Run(Action a, Action b)
    {
    }

    void Run(Action<int> a, Action<int> b)
    {
    }

    void M()
    {
        Run(delegate {|RH3106:()|} { }, delegate {|RH3106:()|} { });
    }
}
```

```csharp
using System;

class C
{
    void Run(Action a, Action b)
    {
    }

    void Run(Action<int> a, Action<int> b)
    {
    }

    void M()
    {
        Run(delegate { }, delegate {|RH3106:()|} { });
    }
}
```

The second list stays reported without a fix: once the first is removed, removing it too would make the call ambiguous (CS0121).

### RH3106-003 — An anonymous method that takes its natural type is not reported

The analyzer MUST NOT report the empty parameter list of an anonymous method that takes its natural type, because no delegate type is its target and no overload resolution or type inference chooses one. It takes its natural type in these positions:

- the initializer of an implicitly typed local (`var`);
- an element of an implicitly typed array creation, `new[] { … }`;
- the expression a lambda returns, as its expression body or in a `return` statement, when the lambda has no delegate type as its target and its return type is inferred from that expression, as in `var f = () => delegate () { };`;
- a variable, an assignment, a return value, or a cast whose type is not a delegate type, such as `object` or `System.Delegate`;
- an argument whose parameter type is not a delegate type when no other overload is a candidate for the call and no type argument is inferred from the argument, such as the argument of `Run(object o)` as the only `Run`.

An anonymous method inside parentheses, in a branch of a conditional expression, or in an arm of a switch expression stands in the position of that parenthesized, conditional, or switch expression. A conditional or a switch expression whose branches are all anonymous methods has no natural type, so under `var` it does not compile (CS0173, CS8506); its anonymous methods reach this requirement through a target that is not a delegate type, such as `object`. An anonymous method whose target is a delegate type, also through parentheses or a conditional expression, MUST be reported as RH3106-001 states: also an element of an array creation that names its element type, and the expression a lambda returns whose delegate type is its target, such as `Func<Action>`. An argument or an operand whose binding competing overloads, user-defined operators, or type inference decide MUST be reported as RH3106-002 states.

Why: An anonymous method has a natural type, from C# 10, only with a parameter list; `delegate { }` has none, so `var a = delegate { };` does not compile (CS8917), nor does its conversion to `object` or `System.Delegate`, also as the argument of a parameter of such a type. An implicitly typed array takes its element type, and a lambda without a target its return type, from the natural type of the expression, so `new[] { delegate { } }` (CS0826) and `var f = () => delegate { };` (CS8917) do not compile either. Parentheses, a conditional, or a switch expression pass the position on to the anonymous method. The position rules the change out (SHARED-DIAG-011).

Example:

```csharp
using System;

class C
{
    static void Run(object o)
    {
    }

    object M(bool b)
    {
        var a = delegate () { };
        var e = (delegate () { });
        var h = new[] { delegate () { } };
        var f = () => delegate () { };
        var k = () =>
        {
            return delegate () { };
        };
        Delegate d = delegate () { };
        object o = delegate () { };
        Run(delegate () { });
        return delegate () { };
    }
}
```

is not reported. Neither is a conditional branch or a switch-expression arm whose target is `object`:

```csharp
class C
{
    object M(bool b, int i)
    {
        object g = b ? delegate () { } : delegate () { };

        return i switch
               {
                   1 => delegate () { },
                   _ => (delegate () { })
               };
    }
}
```

Where the target is a delegate type, the list is reported:

```csharp
using System;

class C
{
    void M(bool b)
    {
        Action a = b ? delegate {|RH3106:()|} { } : null;
        Action e = (delegate {|RH3106:()|} { });
        Action[] h = new Action[] { delegate {|RH3106:()|} { } };
        Func<Action> f = () => delegate {|RH3106:()|} { };
    }
}
```
