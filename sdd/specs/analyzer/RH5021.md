# Analyzer — RH5021 Local declarations should be followed by a blank line

| | |
|---|---|
| ID prefix | RH5021 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5021LocalDeclarationsShouldBeFollowedByABlankLineAnalyzer`, `RH5021LocalDeclarationsShouldBeFollowedByABlankLineCodeFixProvider` |
| Uses | SHARED-STMT-001, SHARED-STMT-002, SHARED-STMT-003, SHARED-STMT-004 |

RH5021 reports an expression statement that directly follows a local declaration of the same block or switch section without a blank line between them, unless the expression statement is an assignment, and offers a code fix that inserts one as SHARED-STMT-004 specifies.

## Non-goals

- Other statements after a local declaration, such as `if` or `return` — the rules for their own statement kind.
- A local declaration after another statement — RH5029.

## Requirements

### RH5021-001 — An expression statement that follows a local declaration needs a blank line

The analyzer MUST report an expression statement whose directly preceding statement in the same block or switch section is a local declaration, a `using` declaration included, as SHARED-STMT-001, SHARED-STMT-002, and SHARED-STMT-003 specify, unless RH5021-002 exempts it. It MUST NOT report an expression statement whose directly preceding statement is not a local declaration.

Why: A run of local declarations reads as the setup for the code that follows; the blank line separates that setup from the first action.

Example:

```csharp
class C
{
    void M(int a, System.IDisposable resource)
    {
        var b = a;
        {|RH5021:M|}(b, resource);
        M(a, resource);

        using var other = resource;
        {|RH5021:other|}.Dispose();
    }
}
```

`M(a, resource);` follows an expression statement and is not reported.

### RH5021-002 — An assignment after a local declaration is exempt

The analyzer MUST NOT report an expression statement whose expression is an assignment, simple or compound, such as `b = 2;` or `c += 3;`. Any other expression statement, such as an increment or a method call, is reported as RH5021-001 specifies.

Why: An assignment directly after a declaration usually continues the setup the declaration started, so it stays in the same group.

Example:

```csharp
class C
{
    void M(int a)
    {
        var b = a;
        b = 2;

        var c = a;
        c += 3;

        var d = a;
        {|RH5021:d|}++;
    }
}
```

`b = 2;` and `c += 3;` are assignments and are exempt; `d++;` is reported.

### RH5021-003 — The diagnostic is on the first token of the expression statement

The analyzer MUST report the diagnostic on the first token of the expression statement.

Why: The statement's first token is where the missing separator becomes visible, whatever expression the statement starts with.

Example: see RH5021-001.
