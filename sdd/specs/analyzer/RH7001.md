# Analyzer — RH7001 File may only contain a single namespace

| | |
|---|---|
| ID prefix | RH7001 |
| Status | Active |
| Category | Organization |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH7001FileMayOnlyContainASingleNamespaceAnalyzer` |
| Uses | — |

RH7001 reports every top-level namespace declaration of a file after the first one. It has no code fix.

## Non-goals

- How many types a file declares — RH7002.
- Whether the namespace is block-scoped or file-scoped — RH7003.

## Requirements

### RH7001-001 — Every top-level namespace after the first is reported

The analyzer MUST report every namespace declaration directly in the compilation unit that follows another namespace declaration directly in the compilation unit, whatever the names of the two declarations — also when both declare the same namespace.

Why: One file is one unit of organization. A second top-level namespace splits it into two units that a reader has to find inside one file; the file name and the folder can only describe one of them.

Example:

```csharp
namespace A
{
}

namespace {|RH7001:B|}
{
}

namespace {|RH7001:A|}
{
}
```

### RH7001-002 — Nested namespaces are not counted

The analyzer MUST NOT count a namespace declaration that is nested in another namespace declaration. A file with one top-level namespace is not reported, however many namespaces are nested in it.

Why: A nested namespace is part of the one unit the file declares; the file still has a single top-level namespace to name it after.

Example:

```csharp
namespace A
{
    namespace B
    {
    }

    namespace C
    {
    }
}
```

is not reported.

### RH7001-003 — The diagnostic is on the namespace name

The analyzer MUST report one diagnostic per reported namespace declaration, located on its whole name, a qualified name included.

Why: The name is what tells the reader which unit to move to its own file.

Example:

```csharp
namespace A.B
{
}

namespace {|RH7001:A.C|}
{
}
```
