# Analyzer — RH1001 Types used as dictionary keys or in hash sets must implement equality members

| | |
|---|---|
| ID prefix | RH1001 |
| Status | Active |
| Category | Performance |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH1001TypesUsedAsKeysMustImplementEqualityMembersAnalyzer` |
| Uses | SHARED-EQUAL-001, SHARED-EQUAL-002 |

RH1001 reports every use of a hash-based dictionary or set type whose key is a struct without its own equality members.

## Non-goals

- Equality-based LINQ and collection operations, such as `ToDictionary` or `Distinct` — RH1002.
- Collections that do not hash their keys, such as `SortedDictionary<TKey, TValue>` or `List<T>`.
- Uses of a type derived from one of the collection types, such as `new Map()` for `class Map : Dictionary<S, int>`, and a variable whose collection type is inferred with `var` from a call.

## Requirements

### RH1001-001 — Hash-based collections keyed by a struct without equality members

The analyzer MUST report a use of one of the types `Dictionary<TKey, TValue>`, `HashSet<T>`, `ConcurrentDictionary<TKey, TValue>`, `ImmutableDictionary<TKey, TValue>`, `ImmutableHashSet<T>`, `FrozenDictionary<TKey, TValue>`, and `FrozenSet<T>` when its first type argument, the key or the element, lacks equality members as SHARED-EQUAL-001 defines it. The value type of a dictionary MUST NOT be checked.

Why: These collections hash and compare their keys on every lookup and insertion. A struct key without its own equality members is boxed and inspected by `ValueType`'s members each time. A value is stored, never hashed.

Example:

```csharp
using System.Collections.Concurrent;
using System.Collections.Frozen;
using System.Collections.Generic;
using System.Collections.Immutable;

struct S
{
}

class C
{
    Dictionary<{|RH1001:S|}, int> a;
    HashSet<{|RH1001:S|}> b;
    ConcurrentDictionary<{|RH1001:S|}, int> c;
    ImmutableDictionary<{|RH1001:S|}, int> d;
    ImmutableHashSet<{|RH1001:S|}> e;
    FrozenDictionary<{|RH1001:S|}, int> f;
    FrozenSet<{|RH1001:S|}> g;
    Dictionary<int, S> h;
    SortedDictionary<S, int> i;
    List<S> j;
}
```

### RH1001-002 — Every use of the collection type is reported

The analyzer MUST report each place that names such a collection type — the type of a field, property, parameter, return value, or local variable, a type argument of another type, and `typeof` — and each object creation of it. A target-typed `new()` that creates it MUST be reported when it is not the initial value of a variable or property declared with that type, whose declared type is reported instead.

Why: Each use is a place where the collection hashes the struct, and the rule cannot see whether a collection that is passed in or returned was created with a comparer. A creation that initializes a declaration of the same type is the declaration's own collection, so one diagnostic on the declared type covers both.

Example:

```csharp
using System.Collections.Generic;

struct S
{
}

class C
{
    Dictionary<{|RH1001:S|}, int> _field;

    Dictionary<{|RH1001:S|}, int> M(Dictionary<{|RH1001:S|}, int> values, List<HashSet<{|RH1001:S|}>> sets)
    {
        var created = new Dictionary<{|RH1001:S|}, int>();
        Dictionary<{|RH1001:S|}, int> declared = new();
        var type = typeof(HashSet<{|RH1001:S|}>);
        Take({|RH1001:new|}());

        return created;
    }

    void Take(HashSet<{|RH1001:S|}> set)
    {
    }
}
```

### RH1001-003 — A creation with a custom comparer is not reported

The analyzer MUST NOT report an object creation, explicit or target-typed, that passes a custom comparer as SHARED-EQUAL-002 defines it. It MUST NOT report the declared type of a variable or property, or the type of a cast, when every creation its initial value can produce is a creation of that type with a custom comparer. The initial value MAY be wrapped in parentheses, the null-forgiving operator `!`, or a cast that is not a user-defined conversion, and MAY choose between creations in the branches of a conditional expression or in the arms of a `switch` expression; a conditional expression with a constant condition counts only its chosen branch. When one of the creations passes no custom comparer, the declared type MUST be reported.

Why: A collection created with its own comparer hashes and compares through that comparer, so the key's members are never called. A declaration is free of that cost only when every collection it can hold was created that way.

Example:

```csharp
using System.Collections.Generic;

struct S
{
}

class C
{
    IEqualityComparer<S> _comparer;
    bool _flag;
    int _mode;

    void M()
    {
        var a = new Dictionary<S, int>(_comparer);
        Dictionary<S, int> b = new(_comparer);
        Dictionary<S, int> c = _flag ? new(_comparer) : new Dictionary<S, int>(_comparer);
        Dictionary<S, int> d = _mode switch
        {
            0 => new(_comparer),
            _ => new(_comparer),
        };
        Dictionary<{|RH1001:S|}, int> e = _flag ? new(_comparer) : new();
        Dictionary<S, int> f = true ? new(_comparer) : new();
        Dictionary<S, int> h = (new(_comparer))!;
        object i = (Dictionary<S, int>)new Dictionary<S, int>(_comparer);
        object j = (Dictionary<{|RH1001:S|}, int>)new Dictionary<{|RH1001:S|}, int>();
        var k = new Dictionary<{|RH1001:S|}, int>(EqualityComparer<S>.Default);
    }
}
```

### RH1001-004 — A use through an alias is reported on the alias

The analyzer MUST NOT report a `using` alias directive, and MUST report each use of an alias whose target is such a collection type or contains one as a type argument or as the element type of an array.

Why: The alias directive only gives the type a name; the places that use the name are where the collection hashes the struct.

Example:

```csharp
using Map = System.Collections.Generic.Dictionary<S, int>;
using Maps = System.Collections.Generic.List<System.Collections.Generic.Dictionary<S, int>>;
using Table = System.Collections.Generic.Dictionary<S, int>[];
using Names = System.Collections.Generic.Dictionary<string, S>;

struct S
{
}

class C
{
    {|RH1001:Map|} _map;

    {|RH1001:Maps|} _maps;

    {|RH1001:Table|} _table;

    Names _names;

    object Create() => new {|RH1001:Map|}();
}
```

### RH1001-005 — Where the diagnostic is

The analyzer MUST report one diagnostic per reported use, located on the first type argument of the collection type where it is named with its type arguments, on the alias name where it is named through an alias, and on the `new` keyword of a target-typed creation.

Why: The key type is what the user changes, either by adding equality members to it or by choosing a comparer for it. An alias and a target-typed creation do not show the type argument, so the name or the keyword stands for it.

Example: see RH1001-002 and RH1001-004.
