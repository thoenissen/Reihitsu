# Analyzer — RH8306 Property summary must use a noun phrase instead of a sentence

| | |
|---|---|
| ID prefix | RH8306 |
| Status | Active |
| Category | Documentation |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH8306PropertySummaryMustUseNounPhraseInsteadOfSentenceAnalyzer` |
| Uses | SHARED-DOC-004, SHARED-DOC-008 |

RH8306 reports the `<summary>` of a property that reads as a sentence — one that ends with a sentence terminator or starts with a verb such as `Gets` — instead of as a noun phrase.

## Non-goals

- Whether the property has a summary, and whether the summary has text — RH8022 to RH8025 and RH8030.
- The summaries of other declarations, and the wording of other documentation elements.
- The layout of the summary — RH8305 and RH8307.

## Requirements

### RH8306-001 — The summary of a property is checked

The analyzer MUST check the `<summary>` element at the top level of the documentation comment of a property declaration, as SHARED-DOC-004 defines it, whatever the property's accessibility, and also when the property explicitly implements an interface member. The text of the summary is its content with every nested element counted as one space, so `Value <see cref="C"/>.` reads as `Value  .`. A property without documentation, with only `<inheritdoc/>`, with an empty `<summary/>`, or with a summary that has no text MUST NOT be reported. Nothing is reported when SHARED-DOC-008 applies.

This requirement covers a property declaration whose leading trivia has one documentation comment with at most one `<summary>` element at its top level, written in lower case, without a namespace prefix, and in no XML namespace, whose content is text without character references and empty elements such as `<see cref="…"/>`. Indexers are not covered.

Why: A property describes a value, so its summary names that value. The rule judges the words the reader sees in the tooltip, and an inline reference such as `<see cref="…"/>` stands for a word of that text.

Example:

```csharp
interface I
{
    int Total { get; }
}

class C : I
{
    /// {|RH8306:<summary>
    /// Gets or sets the size.
    /// </summary>|}
    public int Size { get; set; }

    /// {|RH8306:<summary>Value <see cref="C"/>.</summary>|}
    private int Value { get; }

    /// <summary>
    /// Current size
    /// </summary>
    public int Length { get; set; }

    /// <inheritdoc/>
    public int Count { get; }

    /// <summary></summary>
    public int Width { get; }

    /// {|RH8306:<summary>Gets the total</summary>|}
    int I.Total => 0;

    /// <summary>
    /// Gets the name.
    /// </summary>
    public string Name;
}
```

### RH8306-002 — A summary that ends like a sentence is reported

The analyzer MUST report the summary when its text, without leading and trailing white space, ends with `.`, `!`, or `?`. A summary that ends with `?` MUST NOT be reported for this reason when the property's type is `bool` or `bool?`.

Why: A trailing terminator turns the label into a sentence and carries no meaning for a value. A Boolean property may be described by the question it answers, such as `Is the connection open?`.

Example:

```csharp
class C
{
    /// {|RH8306:<summary>Current size.</summary>|}
    public int Size { get; set; }

    /// {|RH8306:<summary>Current size!</summary>|}
    public int Length { get; set; }

    /// {|RH8306:<summary>Is it open?</summary>|}
    public int Count { get; set; }

    /// <summary>Is it open?</summary>
    public bool IsOpen { get; set; }

    /// <summary>Is it closed?</summary>
    public bool? IsClosed { get; set; }
}
```

### RH8306-003 — A summary that starts with a narrating verb is reported

The analyzer MUST report the summary when the first word of its text — the characters up to the first white space, after leading white space — is one of `Gets`, `Sets`, `Returns`, `Represents`, `Indicates`, `Specifies`, `Determines`, `Holds`, or `Stores`, compared case-insensitively, whatever the property's type. A word further along the text, and a first word that only starts with such a verb, MUST NOT be reported.

Why: These verbs narrate what an accessor does (`Gets or sets …`) instead of naming the value, and they are the boilerplate a noun phrase leaves out. Only the first word decides, because the same verbs are ordinary words later in a phrase such as `Name that represents the user`.

Example:

```csharp
class C
{
    /// {|RH8306:<summary>Gets or sets the size</summary>|}
    public int Size { get; set; }

    /// {|RH8306:<summary>returns the length</summary>|}
    public int Length { get; set; }

    /// {|RH8306:<summary>Indicates whether it is open?</summary>|}
    public bool IsOpen { get; set; }

    /// <summary>Name that represents the user</summary>
    public string Name { get; set; }

    /// <summary>Getset value</summary>
    public int Value { get; set; }
}
```

### RH8306-004 — The diagnostic covers the summary

The analyzer MUST report one diagnostic per property, covering the whole `<summary>` element from its start tag through its end tag.

Why: The wording of the summary is what has to change.

Example: see RH8306-001.
