# Analyzer — RH5604 Code must not contain mixed line endings

| | |
|---|---|
| ID prefix | RH5604 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5604CodeMustNotContainMixedLineEndingsAnalyzer`, `RH5604CodeMustNotContainMixedLineEndingsCodeFixProvider` |
| Uses | FMT-PIPE-007, FMT-EOL-001, FMT-EOL-002, FMT-EOL-003, FMT-EOL-004 |

RH5604 reports every line whose line ending differs from the file's predominant line ending, and offers a code fix that converts the line endings of the whole file to the predominant one.

In the examples, `␍` marks a carriage return: a line that ends in `␍` ends with `\r\n`, every other line except the last line of a block ends with `\n`, and the last line of a block has no line break.

## Non-goals

- Whether the file ends with a line break — RH5603.
- Which line ending a project should use; the rule only makes a file consistent with itself.
- Line breaks inside block comments and disabled text.

## Requirements

### RH5604-001 — Lines that differ from the predominant line ending are reported

When the line breaks of a file are `\r\n` and `\n` and both occur, the analyzer MUST report every line whose line ending differs from the predominant line ending as FMT-PIPE-007 detects it: `\r\n` when it occurs at least as often as `\n`, counting the line breaks between tokens, the line breaks that end directives, and the line breaks inside documentation comments.

Why: Mixed line endings are invisible and produce whole-file diffs the next time a tool normalizes the file. The majority is what the file's author most likely uses, and the tie rule makes the decision deterministic; the formatter decides the same way, so formatted code raises no RH5604.

Example — two `\r\n` against one `\n`, and a tie between one of each:

```csharp
class C␍
{|RH5604:{
|}    int x;␍
}
```

```csharp
class C␍
{|RH5604:{
|}}
```

A directive's line break and a documentation comment's line break count and are reported like any other:

```csharp
class C␍
{␍
{|RH5604:#pragma warning disable CS0168
|}    int x;␍
#pragma warning restore CS0168␍
{|RH5604:    /// <summary>
|}    /// Gets the value.␍
    /// </summary>␍
    int A;␍
}
```

### RH5604-002 — A file with one kind of line ending is not reported

The analyzer MUST NOT report a file whose line breaks between tokens, at the end of directives, and inside documentation comments are all `\r\n` or all `\n`.

Why: The rule asks for consistency within the file, not for a particular line ending.

Example:

```csharp
class C␍
{␍
    /// <summary>␍
    /// Gets the value.␍
    /// </summary>␍
    int A;␍
}
```

is not reported.

### RH5604-003 — Line breaks inside string literals do not count

The analyzer MUST NOT report a line break in the text of a string literal — the content of a verbatim or raw literal, or a text part of an interpolated verbatim literal — and MUST NOT count it when it decides whether a file mixes line endings.

Why: A line break inside a literal is part of the string's value; converting it would change what the program prints, compares, or hashes. The formatter keeps it as well (FMT-EOL-004).

Example:

```csharp
class C
{
    string s = @"a␍
b";
    string t = """␍
        c␍
        """;
    string u = $@"d␍
{1}";
}
```

is not reported.

### RH5604-004 — One diagnostic per line

The analyzer MUST report one diagnostic per differing line ending, located on the whole line from its first character through its line break.

Why: The line ending is invisible on its own; covering the whole line shows the reader which line it ends.

Example: see RH5604-001.

### RH5604-005 — The fix converts every line ending of the file

In a file whose line breaks are `\r\n` and `\n`, the code fix MUST rewrite every line break of the file whose text differs from the predominant line ending to that line ending — between tokens, at the end of directives, and inside documentation comments, as FMT-EOL-001, FMT-EOL-002, and FMT-EOL-003 specify for the formatter — whichever of the file's diagnostics it is applied to. Line breaks in the text of string literals MUST NOT be changed.

Why: One application makes the whole file consistent, so the result does not depend on which diagnostic the user picked.

Example:

```csharp
class C
{|RH5604:{␍
|}    int x;
{|RH5604:    /// <summary>␍
|}    /// Gets the value.
    /// </summary>
    int A;
}
```

```csharp
class C
{
    int x;
    /// <summary>
    /// Gets the value.
    /// </summary>
    int A;
}
```
