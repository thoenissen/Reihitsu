# Analyzer — RH4120 Record primary constructor parameter casing

| | |
|---|---|
| ID prefix | RH4120 |
| Status | Active |
| Category | Naming |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH4120RecordPrimaryConstructorParameterCasingAnalyzer`, `RH4120RecordPrimaryConstructorParameterCasingCodeFixProvider` |
| Uses | SHARED-CASING-001, SHARED-CASING-006, SHARED-CASING-007, SHARED-CASING-008, SHARED-CASING-009, SHARED-CASING-010, SHARED-CASING-012, SHARED-FIX-003 |

RH4120 reports a parameter of a record's primary constructor whose name is not in PascalCase and offers a code fix that renames the parameter, the property it declares, and every reference to them.

## Non-goals

- Parameters of the primary constructor of a class or struct, and of every other member — RH4105.
- Properties declared in the body of a record — RH4111 to RH4114.

## Requirements

### RH4120-001 — Record primary constructor parameter names are in PascalCase

The analyzer MUST report every parameter of the primary constructor of a record — `record`, `record class`, `record struct`, or `readonly record struct` — whose name is not in PascalCase as SHARED-CASING-001 defines it. The analyzer MUST report one diagnostic per parameter, located on its identifier.

This requirement covers a parameter that the compiler turns into a property, which it does when no member of the same name is declared in the record or inherited from its base type.

Why: The compiler turns each of these parameters into a public property unless a member of that name already exists, and the name is what every consumer sees in a member access, in a `with` expression, and in the generated `ToString`. A camelCase parameter therefore produces a camelCase public property.

Example:

```csharp
public record R(int {|RH4120:firstName|}, int LastName);

public record class C(int {|RH4120:last_name|});

public record struct S(int {|RH4120:count|});

public readonly record struct T(int {|RH4120:size|});
```

### RH4120-002 — Discards and other parameters are not checked

The analyzer MUST NOT report a record primary constructor parameter named `_`, and MUST NOT report a parameter of any other constructor or member, including the primary constructor of a class or struct and an explicit constructor of a record.

Why: `_` is the conventional name of a parameter whose value is not used. Every other parameter declares no property, so it is named like a parameter in camelCase; RH4105 checks it.

Example:

```csharp
public record R(int _, int Id)
{
    public R(string text)
        : this(0, text.Length)
    {
    }

    public void M(int input)
    {
    }
}

public class C(int value);

public struct S(int value);
```

is not reported.

### RH4120-003 — The fix renames the parameter and its property to PascalCase

The code fix MUST rename the parameter, the property it declares, and every reference to them (SHARED-CASING-007) to the PascalCase name that SHARED-CASING-006 derives from its old name. It is withheld as SHARED-CASING-008, SHARED-CASING-009, and SHARED-CASING-012 specify, and its Fix All skips colliding names as SHARED-CASING-010 specifies. This requirement covers the renames that SHARED-CASING-007 covers, for the parameters that RH4120-001 covers. It does not cover a rename after which a positional parameter of the record, or of a record derived from it, has a member of the same name that it did not have before: the compiler then declares no property for that parameter, so a public property disappears, and SHARED-FIX-003 withholds the fix. A parameter whose rename could change which parameter a `CallerArgumentExpression` attribute names, or whether it names one, is left to manual correction as SHARED-CASING-012 specifies.

Why: The parameter and its property share one name; renaming only the parameter would leave every consumer of the property pointing at a name that no longer exists.

Example:

```csharp
public record R(int {|RH4120:firstName|})
{
    public int Twice => firstName * 2;
}

public class U
{
    public int M(R r) => r.firstName;
}
```

```csharp
public record R(int FirstName)
{
    public int Twice => FirstName * 2;
}

public class U
{
    public int M(R r) => r.FirstName;
}
```

Example — a rename that would match an inherited property:

```csharp
public record B(int Count);

public record D(int {|RH4120:count|}) : B(count);
```

is reported, and no code fix is offered: `D` declares a public property `count` today, and after the rename to `Count`, the parameter would match the property `Count` that `D` inherits from `B`, so `D.count` would disappear. The same holds the other way round, for `public record B(int {|RH4120:count|});` with `public record D(int Count) : B(Count);`: renaming the parameter of `B` gives `D` an inherited `Count`, so the property that `D` declares for its own parameter disappears.
