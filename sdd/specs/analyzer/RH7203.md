# Analyzer — RH7203 Using directives must be ordered alphabetically by namespace

| | |
|---|---|
| ID prefix | RH7203 |
| Status | Active |
| Category | Organization |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH7203UsingDirectivesMustBeOrderedAlphabeticallyByNamespaceAnalyzer`, `RH7203UsingDirectivesMustBeOrderedAlphabeticallyByNamespaceCodeFixProvider` |
| Uses | SHARED-USING-004, SHARED-USING-007, SHARED-USING-009, FMT-USING-001, FMT-USING-002, FMT-USING-003, FMT-USING-005, FMT-USING-006, FMT-USING-007, FMT-USING-008, FMT-USING-009 |

RH7203 reports a regular namespace directive that is sorted before the directive of its group directly above it, and offers a code fix that organizes the whole using block.

## Non-goals

- The order of the groups — RH7201, RH7207.
- The canonical order and grouping of using directives — SHARED-USING — and how the formatter lays out a reordered block — FMT-USING.

## Requirements

### RH7203-001 — A regular directive sorted before its neighbor is reported

The analyzer MUST report every regular namespace directive that directly follows a regular namespace directive of the same group (SHARED-USING-004) and whose sort key is smaller than that directive's, compared as SHARED-USING-007 specifies, when SHARED-USING-009 allows the block to be reordered.

Why: Alphabetical order within a group makes an import easy to find and keeps file headers consistent. Comparing ignoring case gives the order a reader expects.

Example:

```csharp
using System.Linq;
using {|RH7203:System|};
using Microsoft.CodeAnalysis.CSharp;
using {|RH7203:Microsoft.CodeAnalysis|};

class C
{
}
```

and case does not decide the order:

```csharp
using System.Xml;
using {|RH7203:System.collections|};

class C
{
}
```

and a block with a preprocessor directive is not reported (SHARED-USING-009):

```csharp
using System.Linq;
#if DEBUG
using System.Diagnostics;
#endif
using System;

class C
{
}
```

### RH7203-002 — Equal keys, other groups, and other kinds are not reported

The analyzer MUST NOT report a directive whose sort key equals that of the directive of its group directly above it (SHARED-USING-007), MUST NOT report a directive because of a directive of another group (SHARED-USING-004), and MUST NOT report a `using static` or alias directive.

Why: Equal keys keep their source order, so the analyzer and the fix agree and never swap two directives back and forth. Roots that differ only in case are different namespaces and different groups, whose order is RH7207's decision; static and alias directives are ordered by RH7206 and RH7204.

Example:

```csharp
using System.collections;
using System.Collections;

using Microsoft.B;
using microsoft.A;

using static System.Math;
using static System.Console;

using B = System.Text;
using A = System.IO;

class C
{
}
```

is not reported by RH7203.

### RH7203-003 — The diagnostic is on the directive's name

The analyzer MUST report one diagnostic per reported directive, located on the namespace name it imports.

Why: The name is the sort key the reader compares, and one diagnostic per directive shows each one that is out of order.

Example: see RH7203-001.

### RH7203-004 — The fix organizes the whole block

The code fix MUST rewrite the whole using block that contains the reported directive as the formatter's using-directive phase does: into the canonical order (FMT-USING-001), with exactly one blank line between two groups and none inside a group (FMT-USING-002), with one directive per line (FMT-USING-003), and with comments placed as FMT-USING-005, FMT-USING-006, FMT-USING-007, FMT-USING-008, and FMT-USING-009 specify. It MUST NOT change anything outside the block.

Why: A block has one organized form, shared by the formatter and the seven using-ordering rules RH7201–RH7207. Producing it in one step corrects every diagnostic those rules report in the block at once, so their fixes never undo each other. The code after the block is not the finding.

Example:

```csharp
using System.Linq;
using {|RH7203:System|};
using Microsoft.CodeAnalysis.CSharp;
using {|RH7203:Microsoft.CodeAnalysis|};

class C
{
}
```

```csharp
using System;
using System.Linq;

using Microsoft.CodeAnalysis;
using Microsoft.CodeAnalysis.CSharp;

class C
{
}
```
