# Analyzer — RH8111 Generic type parameter documentation must have text

| | |
|---|---|
| ID prefix | RH8111 |
| Status | Active |
| Category | Documentation |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH8111GenericTypeParameterDocumentationMustHaveTextAnalyzer` |
| Uses | SHARED-DOC-004, SHARED-DOC-008, SHARED-DOC-014 |

RH8111 reports a `<typeparam>` element that has no text.

## Non-goals

- A type parameter without a `<typeparam>` element — RH8108; whether the element's name matches a type parameter or is present — RH8109 and RH8110.
- `<param>` and `<returns>` elements — RH8104 and RH8106; the summary — RH8030.

## Requirements

### RH8111-001 — A `<typeparam>` element without text is reported

The analyzer MUST report each `<typeparam>` element at the top level of a declaration's documentation comment, as SHARED-DOC-004 defines it, that has no text as SHARED-DOC-014 specifies, whether or not the element names a type parameter of the declaration. The declarations checked are class, struct, interface, record, record struct, delegate, and method declarations, whether or not they are generic; a method that explicitly implements an interface member is checked as well, and the declaration's accessibility does not matter. A `<typeparam>` element nested inside another element MUST NOT be reported. Nothing is reported when SHARED-DOC-008 applies.

This requirement covers a declaration whose leading trivia has one documentation comment, placed as SHARED-DOC-004 covers and well-formed XML, with the tag name `typeparam` written in lower case, without a namespace prefix, and in no XML namespace.

Why: An empty description looks like finished documentation while it tells the reader nothing about the type argument; the tooltip shows the same nothing as without the element.

Example:

```csharp
/// <summary>
/// Container
/// </summary>
/// {|RH8111:<typeparam name="T"></typeparam>|}
/// <typeparam name="U">Key</typeparam>
/// <remarks>
/// <typeparam name="V"></typeparam>
/// </remarks>
public class C<T, U>
{
    /// <summary>
    /// Creates
    /// </summary>
    /// {|RH8111:<typeparam name="TResult">
    /// </typeparam>|}
    /// <returns>Result</returns>
    public TResult Create<TResult>() => default;
}

/// <summary>
/// Contract
/// </summary>
/// {|RH8111:<typeparam name="T"/>|}
public interface I<T>
{
}
```

### RH8111-002 — The diagnostic is on the element

The analyzer MUST report one diagnostic per reported `<typeparam>` element, located on the whole element: the empty element, or everything from the start tag through the end tag.

Why: The element is where the description has to be written.

Example: see RH8111-001.
