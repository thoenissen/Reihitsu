# Analyzer — RH5020 Comments should be preceded by a blank line

| | |
|---|---|
| ID prefix | RH5020 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5020CommentsShouldBePrecededByABlankLineAnalyzer`, `RH5020CommentsShouldBePrecededByABlankLineCodeFixProvider` |
| Uses | SHARED-BLANK-001, SHARED-BLANK-002 |

RH5020 reports an ordinary comment on its own line whose line above is not blank, and offers a code fix that inserts a blank line above it.

## Non-goals

- Documentation comments (`///`, `/** */`) — RH8303.
- The blank line between a documentation comment and the code it documents — RH8302.
- The blank line before a statement that a comment precedes — the rules that use `shared/statement-blank-lines.md`.

## Requirements

### RH5020-001 — A comment on its own line needs a blank line above it

The analyzer MUST report a single-line comment (`//`, including `////`) or a delimited comment (`/* */`) that starts its line as SHARED-BLANK-002 specifies, when the line directly above it is not blank as SHARED-BLANK-001 defines it. A comment behind code on the same line MUST NOT be reported.

Why: A comment introduces the code below it; the blank line groups it with that code instead of with the code above. A comment behind code annotates that code and is not a new paragraph.

Example:

```csharp
class C
{
    int _a;
    {|RH5020:// line comment|}
    int _b;
    {|RH5020:/* block comment */|}
    int _c;
    {|RH5020://// four slashes|}
    int _d; // trailing
    {|RH5020:// after a trailing comment|}
    int _e;

    void M(int a)
    {
        var x = 1; /* a
        b */ // behind code
        a++;
        {|RH5020:// before the closing brace|}
    }
}
```

### RH5020-002 — The first comment of a block, a switch section, or a file is not reported

The analyzer MUST NOT report a comment whose preceding token is an opening brace `{` or the colon of a `case` or `default` label, or that has no preceding content in the file.

Why: An opening brace or a case label already marks the start of the content below it, and the start of a file needs no separator; a blank line there would only pad the block.

Example:

```csharp
// first in file
class C
{
    // first in type
    int _a;

    void M(int a)
    {
        // first in block
        a++;
        switch (a)
        {
            case 1:
                // first in section
                break;
            default:
                // first in default
                break;
        }
    }
}
```

is not reported.

### RH5020-003 — A comment that follows a comment or a directive is not reported

The analyzer MUST NOT report a comment when the content directly in front of it, apart from whitespace and line breaks, is another comment that starts its own line or a preprocessor directive.

Why: Consecutive comment lines form one paragraph and stay together; only the first line of the paragraph needs the blank line. After a directive the comment belongs to the directive's group, and a blank line between them would separate the directive from the code it governs.

Example:

```csharp
class C
{
    int _a;

    // first line
    // second line
    /* third line */
    int _b;
#pragma warning disable CS0169
    // after directive
    int _c;
}
```

is not reported.

### RH5020-004 — The diagnostic is on the comment

The analyzer MUST report one diagnostic per comment, located on the comment's text.

Why: The comment is what needs the separator.

Example: see RH5020-001.

### RH5020-005 — The fix inserts one empty line above the comment

The code fix MUST insert one empty line — a line break in the line ending the document already uses, with no indentation — directly above the line of the reported comment, and change nothing else.

Why: The empty line is exactly the separator the rule asks for; the comment and the code around it stay as written.

Example:

```csharp
class C
{
    int _a;
    {|RH5020:// line comment|}
    int _b;
    {|RH5020:/* block comment */|}
    int _c; // trailing
    {|RH5020:// after a trailing comment|}
    int _d;
}
```

```csharp
class C
{
    int _a;

    // line comment
    int _b;

    /* block comment */
    int _c; // trailing

    // after a trailing comment
    int _d;
}
```
