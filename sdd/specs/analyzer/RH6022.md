# Analyzer — RH6022 No space after new for implicitly typed arrays

| | |
|---|---|
| ID prefix | RH6022 |
| Status | Active |
| Category | Spacing |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH6022NoSpaceAfterNewForImplicitlyTypedArraysAnalyzer`, `RH6022NoSpaceAfterNewForImplicitlyTypedArraysCodeFixProvider` |
| Uses | FMT-CLEAN-001, FMT-SPACE-012, SHARED-WS-001, SHARED-WS-002 |

RH6022 reports whitespace between `new` and the `[` of an implicitly typed array creation, and offers a code fix that deletes it as SHARED-WS-001 and SHARED-WS-002 specify.

In the examples, `→` marks a tab and `·` a space at the end of a line.

## Non-goals

- The whitespace inside the brackets, such as `new[ ]` — RH6007 and RH6008.
- The space before the initializer brace — RH6009.

## Requirements

### RH6022-001 — Whitespace after `new` of an implicitly typed array is reported

The analyzer MUST report the run of spaces and tabs directly after the `new` keyword of an implicitly typed array creation, one- or multi-dimensional, when the run is followed by a token or by the end of the line. A `new` directly followed by `[` or by a line break MUST NOT be reported, and neither MUST the `new` of any other creation expression.

Why: `new[]` is one construct, and a space in it makes `new` look like the start of an object creation with a missing type. The formatter removes the same whitespace — before the `[` on the same line (FMT-SPACE-012), at the end of the line (FMT-CLEAN-001) — so formatted code raises no RH6022 in these places.

Example:

```csharp
class C
{
    string M()
    {
        var a = new{|RH6022: |}[] { 1 };
        var b = new{|RH6022:→|}[] { 1 };
        var c = new{|RH6022:  |}[,] { { 1 } };
        var d = new{|RH6022:·|}
            [] { 1 };
        var e = new
            [] { 1 };
        var f = new int [] { 1 };

        return $"{new{|RH6022: |}[] { 1 }.Length}";
    }
}
```

### RH6022-002 — One diagnostic per creation

The analyzer MUST report one diagnostic per implicitly typed array creation, located on the whitespace run after `new`.

Why: The run is the text that is wrong and the text the fix deletes.

Example: see RH6022-001.

### RH6022-003 — The fix deletes the whitespace unless a comment is in the gap

The code fix MUST delete the reported whitespace as SHARED-WS-001 specifies, and MUST NOT be offered when a comment or directive sits between `new` and the `[`, as SHARED-WS-002 specifies.

Why: A comment or directive in the gap is the author's placement; the fix does not decide whether the deletion affects it.

Example:

```csharp
class C
{
    void M()
    {
        var a = new{|RH6022: |}[] { 1 };
        var c = new{|RH6022:→|}[,] { { 1 } };
        var d = new{|RH6022:·|}
            [] { 1 };
    }
}
```

```csharp
class C
{
    void M()
    {
        var a = new[] { 1 };
        var c = new[,] { { 1 } };
        var d = new
            [] { 1 };
    }
}
```

A directive on the next line of the gap withholds the fix:

```csharp
class C
{
    void M()
    {
        var a = new{|RH6022:·|}
#if DEBUG
            [] { 1 };
#else
            [] { 2 };
#endif
    }
}
```

is reported, and no code fix is offered.
