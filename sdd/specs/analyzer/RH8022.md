# Analyzer — RH8022 Non-private properties must be documented

| | |
|---|---|
| ID prefix | RH8022 |
| Status | Active |
| Category | Documentation |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH8022NonPrivatePropertiesMustBeDocumentedAnalyzer` |
| Uses | SHARED-DOC-001, SHARED-DOC-002, SHARED-DOC-004, SHARED-DOC-005, SHARED-DOC-006, SHARED-DOC-007, SHARED-DOC-008, SHARED-DOC-009 |

RH8022 reports a property in the non-private group that has no `<summary>` or `<inheritdoc>` documentation.

## Non-goals

- Properties in the private group — RH8023.
- Indexers — RH8024 and RH8025.
- The properties a record generates from its primary constructor parameters, which are documented with the record — RH8007 to RH8010 and RH8101.
- Whether the summary has text — RH8030; the wording of a property summary — RH8306.

## Requirements

### RH8022-001 — Undocumented non-private properties are reported

The analyzer MUST report every property declaration in the non-private group of SHARED-DOC-002 that is not documented, checked as SHARED-DOC-001 specifies, except an explicit interface implementation, which SHARED-DOC-009 exempts. A property declaration is a property declared in the body of a class, struct, interface, record, record struct, or extension block — auto-implemented, expression-bodied, abstract, override, and static properties included; an indexer is not one. The group is decided by the modifiers of the property, not by those of its accessors. Whether it is documented MUST be decided as SHARED-DOC-004, SHARED-DOC-005, SHARED-DOC-006, and SHARED-DOC-007 specify, and nothing is reported when SHARED-DOC-008 applies.

Why: A property that other code can read or set is part of the contract that code builds on. Without a summary, the generated documentation and the editor's tooltip show nothing, and readers have to infer what the value stands for from its implementation. An accessor that is more restricted than its property does not hide the property from other code.

Example:

```csharp
/// <summary>
/// Settings
/// </summary>
public class Settings
{
    public string {|RH8022:Name|} { get; set; }

    /// <remarks>
    /// No summary
    /// </remarks>
    internal int {|RH8022:Count|} => 0;

    public int {|RH8022:Version|} { get; private set; }

    protected static bool {|RH8022:Enabled|} { get; }

    /// <summary>
    /// Gets the profile
    /// </summary>
    public string Profile { get; }

    private int Hidden { get; }

    public int this[int index] => index;
}

/// <summary>
/// Contract
/// </summary>
public interface IContract
{
    int {|RH8022:Value|} { get; }
}

/// <summary>
/// Extensions
/// </summary>
public static class Extensions
{
    /// <summary>
    /// Text values
    /// </summary>
    /// <param name="value">Value</param>
    extension(string value)
    {
        public int {|RH8022:Words|} => 0;

        int Hidden => 0;
    }
}
```

### RH8022-002 — The diagnostic is on the property name

The analyzer MUST report one diagnostic per undocumented property declaration, located on its identifier.

Why: The name is what the documentation describes; marking it identifies the declaration without marking its accessors.

Example: see RH8022-001.
