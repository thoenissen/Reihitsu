# Analyzer — RH6004 Preprocessor keywords must not be preceded by space

| | |
|---|---|
| ID prefix | RH6004 |
| Status | Active |
| Category | Spacing |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH6004PreprocessorKeywordsMustNotBePrecededBySpaceAnalyzer`, `RH6004PreprocessorKeywordsMustNotBePrecededBySpaceCodeFixProvider` |
| Uses | FMT-INDENT-009, FMT-INDENT-010, SHARED-WS-001 |

RH6004 reports the indentation in front of an active preprocessor directive other than `#region` and `#endregion`, and offers a code fix that deletes it as SHARED-WS-001 specifies.

In the examples, `→` marks a tab.

## Non-goals

- The indentation of `#region` and `#endregion` — the formatter (FMT-INDENT-010); no analyzer rule checks it.
- The whitespace between the tokens of a directive and at the end of a directive line — RH5601 for tabs, RH5602.
- Lines inside disabled text, which the compiler does not parse as code.

## Requirements

### RH6004-001 — An indented directive is reported

The analyzer MUST report the whitespace in front of the `#` of an active preprocessor directive that starts its line — `#if`, `#elif`, `#else`, `#endif`, `#define`, `#undef`, `#pragma`, `#nullable`, `#line`, `#error`, `#warning` — whether the whitespace is spaces or tabs.

Why: A directive is not scoped by braces; it takes effect from the point in the file where it appears, and an indented directive looks as if it belonged to the block it sits in. The formatter puts these directives in column 0 (FMT-INDENT-009).

Example:

```csharp
{|RH6004:  |}#define FEATURE
class C
{
    void M(int x)
    {
{|RH6004:        |}#if FEATURE
        x++;
{|RH6004:        |}#else
        x--;
{|RH6004:        |}#endif
{|RH6004:→|}#pragma warning disable CS0168
#pragma warning restore CS0168
    }
}
```

### RH6004-002 — Regions, inactive directives, and directive-like text are not reported

The analyzer MUST NOT report the indentation of a `#region` or `#endregion` directive written without whitespace between the `#` and the keyword, of a directive that is inactive because it sits inside a branch the compiler skips, or of a line that only looks like a directive because it lies inside a multi-line comment or a string literal.

Why: A region groups members or statements and is indented with them (FMT-INDENT-010). An inactive directive and text inside a comment or literal are not active code; rewriting them would edit content the compiler ignores or the program's value.

Example:

```csharp
class C
{
    #region Fields
    int x;
    #endregion

    /*
        #if FEATURE
    */
    string s = @"
        #if FEATURE";

#if NEVER
    #if NESTED
    #endif
#endif
}
```

is not reported.

### RH6004-003 — One diagnostic per directive line

The analyzer MUST report one diagnostic per directive, located on the whole whitespace in front of its `#`.

Why: The indentation is removed as one piece.

Example: see RH6004-001.

### RH6004-004 — The fix deletes the indentation

The code fix MUST delete the reported whitespace as SHARED-WS-001 specifies. It is offered for every reported directive.

Why: The directive is the only thing on its line, so deleting the whitespace in front of it can never glue it to a comment or a token; the fix needs no guard beyond the one the diagnostic already applies.

Example:

```csharp
class C
{
    void M(int x)
    {
{|RH6004:        |}#if FEATURE
        x++;
{|RH6004:        |}#endif
{|RH6004:→|}#pragma warning disable CS0168
    }
}
```

```csharp
class C
{
    void M(int x)
    {
#if FEATURE
        x++;
#endif
#pragma warning disable CS0168
    }
}
```
