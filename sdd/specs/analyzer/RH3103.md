# Analyzer — RH3103 Use shorthand for nullable types

| | |
|---|---|
| ID prefix | RH3103 |
| Status | Active |
| Category | Clarity |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH3103UseShorthandForNullableTypesAnalyzer`, `RH3103UseShorthandForNullableTypesCodeFixProvider` |
| Uses | — |

RH3103 reports a type written as `Nullable<T>` and offers a code fix that writes it as `T?`.

## Non-goals

- Nullable reference type annotations, which are written `T?` already.
- References to `Nullable<T>` inside documentation comments, such as `<see cref="Nullable{T}"/>`.

## Requirements

### RH3103-001 — `Nullable<T>` with a type argument is reported

The analyzer MUST report a generic name that binds to `System.Nullable<T>` and has one written type argument, written unqualified, qualified with dots (`System.Nullable<int>`, also behind `global::` as in `global::System.Nullable<int>`), or qualified by an alias alone (`S::Nullable<int>` with `using S = System;`), where it stands as the type of a field, a property, a parameter, a local variable, or a method's return value, inside `typeof` or `default`, as an array element type, or as a type argument — also a type argument inside `nameof`.

Why: `T?` is the standard C# notation for a nullable value type; it is shorter and reads the same everywhere.

Example:

```csharp
using System;
using System.Collections.Generic;

class C
{
    {|RH3103:Nullable<int>|} _a;
    {|RH3103:System.Nullable<DateTime>|} _b;
    {|RH3103:global::System.Nullable<long>|} _c;
    {|RH3103:Nullable<int>|} P { get; }

    {|RH3103:Nullable<int>|} M({|RH3103:Nullable<int>|} p)
    {
        var t = typeof({|RH3103:Nullable<int>|});
        var d = default({|RH3103:Nullable<int>|});
        {|RH3103:Nullable<int>|}[] arr = null;
        var n = nameof(List<{|RH3103:Nullable<int>|}>);
        return p;
    }
}
```

### RH3103-002 — An unqualified argument of `nameof` is not reported

The analyzer MUST NOT report `Nullable<T>` when it is, written unqualified, the argument of `nameof`.

Why: `nameof(int?)` does not compile; the generic name is the only way to write that argument.

Example:

```csharp
using System;

class C
{
    string M() => nameof(Nullable<int>);
}
```

is not reported.

### RH3103-003 — The diagnostic covers the whole type name

The analyzer MUST report one diagnostic per type in a position of RH3103-001, on the generic name, or on the whole qualified name when the generic name is the part after the last `.` of a dotted qualified name, such as `System.Nullable<int>` or `global::System.Nullable<int>`.

Why: The whole name, qualifier included, is what the fix replaces.

Example: see RH3103-001.

### RH3103-004 — The fix writes `T?`

Where the reported name has one written type argument and stands as the type of a field, a property, a parameter, a local variable, or a method's return value, inside `typeof` or `default`, as an array element type, or as a type argument, the code fix MUST replace it, together with any qualifier in front of it — `System.`, `global::System.`, or an alias such as `S::` — with a nullable type of its type argument and keep a block comment that stands inside the angle brackets on the same line, in front of or after the type argument.

Why: `T?` is the same type, so the program does not change. A comment inside the angle brackets was written about the type argument and stays next to it.

Example:

```csharp
using System;

class C
{
    {|RH3103:Nullable<int>|} _a;
    {|RH3103:System.Nullable<DateTime>|} _b;
    {|RH3103:Nullable</* a */ int /* b */>|} _c;
}
```

```csharp
using System;

class C
{
    int? _a;
    DateTime? _b;
    /* a */ int /* b */? _c;
}
```

### RH3103-005 — A comment the fix cannot place withholds the fix

The code fix MUST NOT be offered when the reported name contains a preprocessor directive, a comment outside the angle brackets, a single-line comment, or a block comment on a line of its own. The diagnostic is still reported.

Why: The fix only knows where a block comment next to the type argument belongs. A comment between the parts of the qualified name, a `//` comment that would swallow the `?`, or a comment on its own line has no place in `T?`, and a directive cannot move.

Example:

```csharp
class C
{
    {|RH3103:System./* a */Nullable<int>|} _a;
}
```

is reported, and no code fix is offered. Neither is one offered for a block comment on a line of its own:

```csharp
using System;

class C
{
    {|RH3103:Nullable<
        /* a */
        int>|} _a;
}
```

### RH3103-006 — A dotted name whose generic name is the right side of a member access withholds the fix

The code fix MUST NOT be offered when the reported generic name is the `Name` of a `MemberAccessExpressionSyntax`, such as a dotted `Nullable<T>` written as the argument of `nameof`. The diagnostic is still reported.

Why: Inside `nameof`, a dotted name is parsed as a member access, so the generic name sits where only a simple name belongs. Replacing it with `T?`, a nullable type, does not fit that position, so the fix would break the code (see `shared/code-fixes.md`).

Example:

```csharp
using System;

class C
{
    string M() => nameof(System.{|RH3103:Nullable<int>|});
}
```

is reported, and no code fix is offered.
