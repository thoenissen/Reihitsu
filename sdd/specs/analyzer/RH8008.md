# Analyzer — RH8008 Private records must be documented

| | |
|---|---|
| ID prefix | RH8008 |
| Status | Active |
| Category | Documentation |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH8008PrivateRecordsMustBeDocumentedAnalyzer` |
| Uses | SHARED-DOC-001, SHARED-DOC-002, SHARED-DOC-004, SHARED-DOC-005, SHARED-DOC-006, SHARED-DOC-007, SHARED-DOC-008 |

RH8008 reports a record in the private group that has no `<summary>` or `<inheritdoc>` documentation.

## Non-goals

- Records in the non-private group — RH8007.
- Record structs — RH8010; classes declared with `class` — RH8002.
- Whether the summary has text — RH8030; the documentation of type parameters and positional parameters — RH8108 and RH8101.

## Requirements

### RH8008-001 — Undocumented private records are reported

The analyzer MUST report every record declaration in the private group of SHARED-DOC-002 that is not documented, checked as SHARED-DOC-001 specifies. A record declaration is one written with `record` or `record class`, positional or not, including generic records; a `record struct` declaration is not one, and neither is a `class` declaration. Whether it is documented MUST be decided as SHARED-DOC-004, SHARED-DOC-005, SHARED-DOC-006, and SHARED-DOC-007 specify, and nothing is reported when SHARED-DOC-008 applies.

Why: A private record is an implementation detail of its type, but the next maintainer still has to know what it is for. It has a rule of its own, so a project can require documentation for what other code uses without requiring it here.

Example:

```csharp
/// <summary>
/// Outer
/// </summary>
public class Outer
{
    private record {|RH8008:Hidden|}(int Value);

    /// <remarks>
    /// No summary
    /// </remarks>
    record class {|RH8008:Helper|}<T>
    {
    }

    /// <summary>
    /// Documented
    /// </summary>
    private record Documented;

    internal record Visible;

    private class Plain
    {
    }

    private record struct Entry;
}
```

### RH8008-002 — The diagnostic is on the record name

The analyzer MUST report one diagnostic per undocumented record declaration, located on its identifier, without its type parameter list and its parameter list.

Why: The name is what the documentation describes; marking it identifies the declaration without marking its whole body.

Example: see RH8008-001.
