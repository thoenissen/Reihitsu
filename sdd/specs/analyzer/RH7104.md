# Analyzer — RH7104 Partial elements must declare access modifier

| | |
|---|---|
| ID prefix | RH7104 |
| Status | Active |
| Category | Organization |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH7104PartialElementsMustDeclareAccessModifierAnalyzer`, `RH7104PartialElementsMustDeclareAccessModifierCodeFixProvider` |
| Uses | — |

RH7104 reports a `partial` type declaration that does not state its accessibility, and offers a code fix that adds it.

## Non-goals

- Declarations that are not `partial` — RH2004.
- Partial members such as partial methods and partial properties.
- Which accessibility the type should have. The fix states the accessibility the type has; narrowing or widening it is the author's decision.
- The order of the modifiers after the fix — RH7105.

## Requirements

### RH7104-001 — A partial type without accessibility modifier is reported

The analyzer MUST report a class, struct, interface, record, or record struct declaration that carries the `partial` modifier and none of the modifiers `public`, `protected`, `internal`, `private`, and `file`, at the top level and nested in another type, when the declaration is the type's only declaration.

Why: A `partial` declaration tells the reader that the type may be declared elsewhere too. Without an accessibility modifier the reader has to know the default or look for other declarations to learn it; stating it removes the guess.

Example:

```csharp
partial class {|RH7104:C|}
{
    partial struct {|RH7104:S|}
    {
        int _value;
    }
}

partial interface {|RH7104:I|}
{
    void M();
}

partial record {|RH7104:R|}(int X);

partial record struct {|RH7104:P|}(int X);
```

### RH7104-002 — A partial type with an accessibility modifier is not reported

The analyzer MUST NOT report a `partial` type declaration that carries one of the modifiers `public`, `protected`, `internal`, `private`, or `file`.

Why: The declaration already states its accessibility.

Example:

```csharp
internal partial class C
{
    private protected partial class N
    {
        int _value;
    }
}

file partial class F
{
    int _value;
}
```

is not reported.

### RH7104-003 — The diagnostic is on the type name

The analyzer MUST report one diagnostic per reported declaration (RH7104-001), located on its identifier.

Why: The name identifies the part, and one diagnostic per declaration keeps Fix All one action per declaration.

Example: see RH7104-001.

### RH7104-004 — The fix adds the type's default accessibility

For a type that has only the reported declaration (RH7104-001), the code fix MUST insert the accessibility the type has by default in front of the declaration's first modifier: `internal` for a top-level type, `private` for a type nested in a class, struct, record, or record struct, and `public` for a type nested in an interface. The trivia in front of the first modifier — a documentation comment, the indentation — MUST stay in front of the inserted keyword, and the attribute lists MUST stay in front of it.

Why: Stating the default changes nothing about the type; it makes visible what the compiler already assumes. Keeping the documentation comment in front of the declaration keeps it attached to the type.

Example:

```csharp
/// <summary>
/// Doc
/// </summary>
[System.Obsolete]
static partial class {|RH7104:C|}
{
    static void M()
    {
    }
}
```

```csharp
/// <summary>
/// Doc
/// </summary>
[System.Obsolete]
internal static partial class C
{
    static void M()
    {
    }
}
```

A nested type gets the default of its container:

```csharp
internal interface I
{
    partial class {|RH7104:N|}
    {
        int _value;
    }
}

internal struct S
{
    partial class {|RH7104:M|}
    {
        int _value;
    }
}
```

```csharp
internal interface I
{
    public partial class N
    {
        int _value;
    }
}

internal struct S
{
    private partial class M
    {
        int _value;
    }
}
```
