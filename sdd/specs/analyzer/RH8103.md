# Analyzer — RH8103 Element parameter documentation must declare parameter name

| | |
|---|---|
| ID prefix | RH8103 |
| Status | Active |
| Category | Documentation |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH8103ElementParameterDocumentationMustDeclareParameterNameAnalyzer` |
| Uses | SHARED-DOC-008, SHARED-DOC-016 |

RH8103 reports a `<param>` element that does not name its parameter.

## Non-goals

- Whether the name matches a parameter — RH8102; whether the description has text — RH8104.
- `<typeparam>` elements — RH8110.

## Requirements

### RH8103-001 — A `<param>` element without a name is reported

The analyzer MUST report each `<param>` element that SHARED-DOC-016 requires to name a parameter, in the documentation comment of a method, constructor, delegate, indexer, operator, or conversion operator declaration, or of a class, struct, record, or record struct declaration, whether or not the declaration has parameters or a primary constructor. A declaration that explicitly implements an interface member MUST be checked as well, and the declaration's accessibility does not matter. Nothing is reported when SHARED-DOC-008 applies.

This requirement covers what SHARED-DOC-016 covers. The documentation comments of other declarations, such as interfaces, properties, and fields, are not covered.

Why: A `<param>` element without a name describes no parameter: the tooltip of every parameter stays empty, and the reader has to guess which one the text means.

Example:

```csharp
/// <summary>
/// Service
/// </summary>
/// {|RH8103:<param>Unused</param>|}
public class C
{
    /// <summary>
    /// Runs
    /// </summary>
    /// {|RH8103:<param>Value</param>|}
    public void M(int value)
    {
    }

    /// <summary>
    /// Runs
    /// </summary>
    /// {|RH8103:<param/>|}
    public void N()
    {
    }

}
```

### RH8103-002 — The diagnostic is on the element

The analyzer MUST report one diagnostic per reported `<param>` element, located on the whole element: the empty element, or everything from the start tag through the end tag.

Why: The element is what needs the `name` attribute, and each element is corrected on its own.

Example: see RH8103-001.
