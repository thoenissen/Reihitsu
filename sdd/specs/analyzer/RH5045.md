# Analyzer — RH5045 Comments must not be placed inside a conditional expression

| | |
|---|---|
| ID prefix | RH5045 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH5045CommentsMustNotBePlacedInsideConditionalExpressionAnalyzer` |
| Uses | SHARED-COMMENT-001, SHARED-COMMENT-002, SHARED-COMMENT-003 |

RH5045 reports a comment placed directly before or directly after the `?` or the `:` of a conditional expression.

## Non-goals

- How a conditional expression is wrapped — the line-break rules.
- A comment inside one of the operands — the rules for the construct the comment is in.

## Requirements

### RH5045-001 — A comment next to a conditional operator is reported

The analyzer MUST report every ordinary comment (SHARED-COMMENT-001, SHARED-COMMENT-002) directly before or directly after the `?` or the `:` of a conditional expression, as SHARED-COMMENT-003 specifies. A comment inside an operand that is not next to one of these operators, and a comment next to a `?` or `:` that belongs to another construct, such as a conditional access or a named argument, MUST NOT be reported.

Why: A conditional expression reads as one unit. A comment next to one of its operators splits it across lines and leaves it unclear which branch it describes.

Example:

```csharp
class C
{
    int Compute(int value) => value;

    void M(bool a, object o)
    {
        var text = a
            {|RH5045:// valid case|}
            ? "ok"
            {|RH5045:// fallback|}
            : "error";
        var other = a ? {|RH5045:/* valid case */|} "ok" : {|RH5045:/* fallback */|} "error";
        var value = a ? (1
            // offset
            + 2) : 3;
        var name = o
            // text
            ?.ToString();
        var result = Compute(value:
            // the value
            1);
        _ = text + other + name + value + result;
    }
}
```

The comments `// offset`, `// text`, and `// the value` are not reported.
