# Analyzer — RH5306 List patterns should be formatted correctly

| | |
|---|---|
| ID prefix | RH5306 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5306ListPatternsShouldBeFormattedCorrectlyAnalyzer`, `RH5306ListPatternsShouldBeFormattedCorrectlyCodeFixProvider` |
| Uses | FMT-BREAK-022, FMT-INDENT-025 |

RH5306 reports a list pattern (`[…]`) that spans several lines without its brackets in one column or without each inner pattern on a line of its own, and offers a code fix that lays it out the way the formatter does.

## Non-goals

- Collection expressions — RH5305.
- Property patterns, positional patterns, and parenthesized patterns.
- The layout of an inner pattern after its first token.

## Requirements

### RH5306-001 — Wrapped brackets out of column are reported

The analyzer MUST report a list pattern that spans several lines when its closing bracket does not start at the column of its opening bracket, provided that no comment and no preprocessor directive sits inside the list pattern, in front of its opening bracket on the line before it, or behind its closing bracket, and that each of its inner patterns is on one line. A list pattern on one line MUST NOT be reported.

Why: Once a list pattern is wrapped, it is a block that hangs from its opening bracket; the closing bracket in the same column shows where the block ends (FMT-INDENT-025). On one line it reads as one pattern (FMT-BREAK-022).

Example:

```csharp
class C
{
    bool M(int[] v)
    {
        var a = v is [1, 2];
        var b = v is {|RH5306:[
                         1
               ]|};

        return a;
    }
}
```

### RH5306-002 — Wrapped inner patterns that share a line are reported

Under the same provisions as RH5306-001, the analyzer MUST report a list pattern that spans several lines when one of its inner patterns does not start on a line of its own between the brackets: on the line of the opening bracket, on the line of the closing bracket, or on the line of the inner pattern before it. A wrapped list pattern whose brackets are in one column and whose inner patterns each start on their own line between them MUST NOT be reported.

Why: A wrapped list pattern gets one inner pattern per line, so each element of the match is visible on its own (FMT-BREAK-022).

Example:

```csharp
class C
{
    bool M(int[] v)
    {
        var a = v is {|RH5306:[1,
                      2]|};
        var b = v is {|RH5306:[
                         1, .. var rest
                     ]|};
        var c = v is [
                         1,
                         2
                     ];

        return a;
    }
}
```

### RH5306-003 — The diagnostic is on the list pattern

The analyzer MUST report one diagnostic per list pattern, located on the whole list pattern, even when both its brackets and its inner patterns are out of place.

Why: Brackets and inner patterns are laid out together, so the diagnostic covers the construct the fix lays out.

Example: see RH5306-001 and RH5306-002.

### RH5306-004 — The fix lays out the list pattern

The code fix MUST lay out the reported list pattern as the formatter lays it out: every inner pattern starts its own line one level deeper than the opening bracket, and the closing bracket starts its own line at the column of the opening bracket (FMT-BREAK-022, FMT-INDENT-025).

Why: The formatter owns the layout of list patterns; delegating to it applies that layout instead of a second one.

Example:

```csharp
class C
{
    bool M(int[] v)
    {
        var a = v is {|RH5306:[1, .. var rest
                     ]|};

        return a;
    }
}
```

```csharp
class C
{
    bool M(int[] v)
    {
        var a = v is [
                         1,
                         .. var rest
                     ];

        return a;
    }
}
```
