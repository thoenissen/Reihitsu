# Analyzer — RH7207 Using directives should be organized into groups

| | |
|---|---|
| ID prefix | RH7207 |
| Status | Active |
| Category | Organization |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH7207UsingDirectivesShouldBeOrganizedIntoGroupsAnalyzer`, `RH7207UsingDirectivesShouldBeOrganizedIntoGroupsCodeFixProvider` |
| Uses | SHARED-USING-001, SHARED-USING-002, SHARED-USING-003, SHARED-USING-004, SHARED-USING-005, SHARED-USING-006, SHARED-USING-007, SHARED-USING-008, SHARED-USING-009, FMT-USING-001, FMT-USING-002, FMT-USING-003, FMT-USING-005, FMT-USING-006, FMT-USING-007, FMT-USING-008, FMT-USING-009 |

RH7207 reports a using block whose directives are not in the canonical order or whose blank lines do not match its groups, and offers a code fix that organizes the block.

## Non-goals

- The canonical order and grouping of using directives — SHARED-USING — and how the formatter lays out a reordered block — FMT-USING.

## Requirements

### RH7207-001 — A block that is not organized is reported

The analyzer MUST report every using block of at least two directives that SHARED-USING-009 allows to be reordered and that is not organized: its directives differ from the canonical order of SHARED-USING-001, SHARED-USING-002, SHARED-USING-003, SHARED-USING-004, SHARED-USING-005, SHARED-USING-006, and SHARED-USING-007, or a directive that starts a new group has no blank line before it, or a directive that continues its group has one (SHARED-USING-008). Each block is checked on its own.

Why: The rule checks the whole layout of a block — section, kind, and root-namespace groups with a blank line at each boundary — so the reader sees at a glance what a file depends on. The other using rules each check one aspect; RH7207 reports a block that any of them, or a misplaced blank line, leaves unorganized.

Example — the order:

```csharp
using {|RH7207:System.Linq|};
using System;
using Microsoft.CodeAnalysis;

class C
{
}
```

a missing blank line between groups, also between two directives on one line:

```csharp
using {|RH7207:System|};
using Microsoft.CodeAnalysis;

class C
{
}
```

```csharp
using {|RH7207:System|}; using Microsoft.CodeAnalysis;

class C
{
}
```

a blank line inside a group:

```csharp
using {|RH7207:System|};

using System.Linq;

class C
{
}
```

and only the block that is not organized:

```csharp
using System;

using Microsoft.CodeAnalysis;

namespace N
{
    using {|RH7207:System.Linq|};
    using System;

    class C
    {
    }
}
```

and a block with a preprocessor directive is not reported (SHARED-USING-009):

```csharp
using System.Linq;
#if DEBUG
using System.Diagnostics;
#endif
using System;

class C
{
}
```

### RH7207-002 — An organized block is not reported

The analyzer MUST NOT report a block that is organized, a block with fewer than two directives, or a group boundary with more than one blank line before it.

Why: The rule asks for a blank line at each group boundary; how many blank lines a run may have is decided for the whole file by the blank-line rules, such as RH5023.

Example:

```csharp
using System;


using Microsoft.CodeAnalysis;

using static System.Math;

using A = System.Text;

class C
{
}
```

is not reported, and neither is:

```csharp
using static System.Math;

class C
{
}
```

### RH7207-003 — The diagnostic is on the block's first directive

The analyzer MUST report one diagnostic per block, located on the name of the block's first directive — the namespace or type it imports, also for an alias directive.

Why: The finding is about the block as a whole; one diagnostic at its start leads the user to the block without listing every directive in it.

Example:

```csharp
using A = {|RH7207:System.Text|};
using System;

class C
{
}
```

### RH7207-004 — The fix organizes the whole block

The code fix MUST rewrite the whole using block that contains the reported directive as the formatter's using-directive phase does: into the canonical order (FMT-USING-001), with exactly one blank line between two groups and none inside a group (FMT-USING-002), with one directive per line (FMT-USING-003), and with comments placed as FMT-USING-005, FMT-USING-006, FMT-USING-007, FMT-USING-008, and FMT-USING-009 specify. It MUST NOT change anything outside the block.

Why: A block has one organized form, shared by the formatter and the seven using-ordering rules RH7201–RH7207. Producing it in one step corrects every diagnostic those rules report in the block at once, so their fixes never undo each other. The code after the block is not the finding.

Example:

```csharp
using {|RH7207:System.Linq|};
using System;
using Microsoft.CodeAnalysis;

class C
{
}
```

```csharp
using System;
using System.Linq;

using Microsoft.CodeAnalysis;

class C
{
}
```
