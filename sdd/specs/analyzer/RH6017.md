# Analyzer — RH6017 Increment/decrement symbols must be spaced correctly

| | |
|---|---|
| ID prefix | RH6017 |
| Status | Active |
| Category | Spacing |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH6017IncrementAndDecrementSymbolsMustBeSpacedCorrectlyAnalyzer`, `RH6017IncrementAndDecrementSymbolsMustBeSpacedCorrectlyCodeFixProvider` |
| Uses | FMT-SPACE-007, FMT-SPACE-013, SHARED-WS-001, SHARED-WS-002 |

RH6017 reports whitespace between an operand and its postfix `++` or `--` on the same line, and offers a code fix that deletes it as SHARED-WS-001 and SHARED-WS-002 specify.

In the examples, `→` marks a tab.

## Non-goals

- Whether a postfix operator starts its own line — the formatter.

## Requirements

### RH6017-001 — Whitespace before a postfix `++` or `--` on the same line is reported

The analyzer MUST report the run of spaces and tabs directly in front of the operator of a postfix increment or decrement when the last token of its operand ends on the operator's line, also when a comment sits between that token and the run. A postfix operator that starts its line, after a line break, MUST NOT be reported.

Why: The operator belongs to the operand it changes; a space in between makes the two look like separate expressions. An operator on its own line is a layout choice, and its indentation is not a gap. The formatter removes the same whitespace (FMT-SPACE-007), also between a comment and the operator (FMT-SPACE-013), so formatted code raises no RH6017.

Example:

```csharp
class C
{
    int _f;

    void M(int a, int[] v)
    {
        a{|RH6017: |}++;
        a{|RH6017:→|}--;
        v[0]{|RH6017: |}++;
        this._f{|RH6017: |}++;
        a /* note */{|RH6017: |}++;

        for (int i = 0; i < a; i{|RH6017: |}++)
        {
        }

        a = a{|RH6017: |}++ + 1;
        a
            ++;
        a // note
            ++;
    }
}
```

### RH6017-002 — Prefix operators and operator declarations are not reported

The analyzer MUST NOT report the whitespace after a prefix `++` or `--`, and MUST NOT report the `++` or `--` of an operator declaration.

Why: A prefix operator stands in front of its operand, so the rule's "space before the operator" does not describe it, and no analyzer rule checks the space after it; the formatter removes that space (FMT-SPACE-007). An operator declaration names the operator and is not an increment or decrement.

Example:

```csharp
class C
{
    void M(int a)
    {
        ++ a;
        -- a;
    }

    public static C operator ++ (C c) => c;
}
```

is not reported.

### RH6017-003 — One diagnostic per operator

The analyzer MUST report one diagnostic per postfix operator, located on the whitespace run in front of it.

Why: The run is the text that is wrong and the text the fix deletes.

Example: see RH6017-001.

### RH6017-004 — The fix deletes the whitespace unless a comment is in the gap

The code fix MUST delete the reported whitespace as SHARED-WS-001 specifies, and MUST NOT be offered when a comment or directive sits between the operator and the token before it, as SHARED-WS-002 specifies.

Why: Deleting the whitespace between a comment and the operator would glue the comment to it; the author decides whether the comment stays there.

Example:

```csharp
class C
{
    void M(int a, int[] v)
    {
        a{|RH6017: |}++;
        v[0]{|RH6017:→|}--;

        for (int i = 0; i < a; i{|RH6017: |}++)
        {
        }
    }
}
```

```csharp
class C
{
    void M(int a, int[] v)
    {
        a++;
        v[0]--;

        for (int i = 0; i < a; i++)
        {
        }
    }
}
```

The comment before the operator withholds the fix:

```csharp
class C
{
    void M(int a)
    {
        a /* note */{|RH6017: |}++;
    }
}
```

is reported, and no code fix is offered.
