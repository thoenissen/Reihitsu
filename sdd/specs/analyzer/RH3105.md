# Analyzer — RH3105 Do not prefix local members with this

| | |
|---|---|
| ID prefix | RH3105 |
| Status | Active |
| Category | Clarity |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH3105DoNotPrefixLocalMembersWithThisAnalyzer`, `RH3105DoNotPrefixLocalMembersWithThisCodeFixProvider` |
| Uses | SHARED-FIX-003 |

RH3105 reports a `this.` member access that binds to the same member without `this`, and offers a code fix that removes the qualifier.

## Non-goals

- The `base.` qualifier — RH3101.
- `this` used on its own, as an argument, as a receiver of an indexer (`this[…]`), or in a constructor initializer.

## Requirements

### RH3105-001 — A `this.` access that binds the same without `this` is reported

The analyzer MUST report a member access `this.X` when `X` alone binds to the same symbol in the same place, also inside a lambda.

Why: The qualifier adds noise and makes a plain member access look special. It is only worth writing where it changes what the name binds to.

Example:

```csharp
class C
{
    int _a;
    int P { get; set; }

    int M()
    {
        {|RH3105:this|}._a = {|RH3105:this|}.P;
        System.Func<int> f = () => {|RH3105:this|}._a;
        return {|RH3105:this|}.M2({|RH3105:this|}._a).GetHashCode();
    }

    int M2(int x) => x;
}
```

### RH3105-002 — A `this.` access the code needs is not reported

The analyzer MUST NOT report `this.X` when `X` alone binds to something else, such as a parameter or a local with the same name, or binds to nothing.

Why: Here the qualifier is what selects the member; without it the code would mean something else or not compile.

Example:

```csharp
class C
{
    int a;

    void M(int a)
    {
        this.a = a;
    }
}
```

is not reported.

### RH3105-003 — The diagnostic is on `this`

The analyzer MUST report one diagnostic per access, on the `this` keyword.

Why: The qualifier is what the fix removes; the member stays.

Example: see RH3105-001.

### RH3105-004 — The fix removes the qualifier

Where the largest expression that contains the access does not hold both a `<` operator and a `>` operator, and neither RH3105-005 nor RH3105-006 withholds the fix, the code fix MUST replace `this.X` with `X` and keep the trivia in front of `this` and after `X`.

Why: `X` binds to the same member, so the program does not change.

Example:

```csharp
class C
{
    int _a;
    int P { get; set; }

    int M()
    {
        {|RH3105:this|}._a = {|RH3105:this|}.P;
        return {|RH3105:this|}.M2({|RH3105:this|}._a).GetHashCode();
    }

    int M2(int x) => x;
}
```

```csharp
class C
{
    int _a;
    int P { get; set; }

    int M()
    {
        _a = P;
        return M2(_a).GetHashCode();
    }

    int M2(int x) => x;
}
```

### RH3105-005 — A fix that would parse as a generic name or a cast is withheld

The code fix MUST NOT be offered when the code it writes would parse as a generic name or as a cast: when, without the `this.` qualifier, a `<` in front of the member name and a later `>` would read as a type argument list, as they do when the `>` is followed by `(`; or when the member name, alone in parentheses, would read as the type of a cast, as `(A)` does when `(`, `!`, or `with` follows it. The diagnostic is still reported. Where the code the fix writes parses with the same operators and operands as the code it replaces, this requirement does not withhold the fix.

Why: `A < this.B` is a comparison only because `this.B` is not a simple name; `A < B, D > (7)` reads as the call of a generic method `A<B, D>`. Likewise `(this.A)(5)` invokes a delegate, while `(A)(5)` reads as a cast of `5` to a type `A`, and `(S)!.Length` does not parse. None of them compiles (SHARED-FIX-003).

Example:

```csharp
class C
{
    int A;
    int B;
    int D;

    void M(bool x, bool y)
    {
    }

    void Run()
    {
        M(A < {|RH3105:this|}.B, D > (7));
    }
}
```

is reported, and no code fix is offered. Neither is one offered where the member name in parentheses would read as a cast:

```csharp
using System;

class C
{
    Action<int> A;
    string S;

    int Run()
    {
        ({|RH3105:this|}.A)(5);
        return ({|RH3105:this|}.S)!.Length;
    }
}
```

is reported, and no code fix is offered. Where the parentheses still read as a parenthesized expression, the fix removes the qualifier:

```csharp
class C
{
    int N;

    int Run()
    {
        return ({|RH3105:this|}.N) - 1;
    }
}
```

```csharp
class C
{
    int N;

    int Run()
    {
        return (N) - 1;
    }
}
```

### RH3105-006 — A comment between `this` and the member name withholds the fix

The code fix MUST NOT be offered when a comment or a preprocessor directive stands between `this` and the member name. The diagnostic is still reported. The trivia in front of `this` and after the member name is kept as RH3105-004 states.

Why: The fix keeps only the member name; a comment around the `.` it removes would be deleted (SHARED-FIX-003).

Example:

```csharp
class C
{
    int _a;

    int M()
    {
        return {|RH3105:this|} /* a */ . /* b */ _a;
    }
}
```

is reported, and no code fix is offered.
