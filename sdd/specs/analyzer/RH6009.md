# Analyzer — RH6009 Opening braces must be spaced correctly

| | |
|---|---|
| ID prefix | RH6009 |
| Status | Active |
| Category | Spacing |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH6009OpeningBracesMustBeSpacedCorrectlyAnalyzer`, `RH6009OpeningBracesMustBeSpacedCorrectlyCodeFixProvider` |
| Uses | FMT-SPACE-009 |

RH6009 reports an opening brace outside interpolated strings that directly follows another character on its line, and offers a code fix that inserts a space in front of it.

## Non-goals

- The whitespace after an opening brace, such as `{1, 2 }` — no analyzer rule checks it.
- Closing braces — RH6010.
- Whether a brace starts its own line — the brace layout rules, such as RH5402 and RH5417.

## Requirements

### RH6009-001 — An opening brace glued to the character before it is reported

The analyzer MUST report an opening brace token outside interpolated strings whose preceding character is not whitespace — the last character of a token or of a `/* */` comment. An opening brace preceded by whitespace of any width, or that starts its line, MUST NOT be reported.

Why: A brace written directly against the preceding token merges with it, so the start of the block is harder to spot on a line that carries other code. The formatter writes one space in front of these braces (FMT-SPACE-009), so formatted code raises no RH6009.

Example:

```csharp
class C
{
    int P{|RH6009:{|} get; set; }
    int Q  { get; set; }
    int R/* note */{|RH6009:{|} get; set; }

    void M(object o, int a){|RH6009:{|}
        var x = new int[]{|RH6009:{|}1 };
        var b = o is C{|RH6009:{|} };
        var c = a switch{|RH6009:{|} _ => 1 };
    }
}
```

### RH6009-002 — The braces of an interpolation are not reported

The analyzer MUST NOT report the opening brace of an interpolation in an interpolated string, such as the brace in `$"{a}"`.

Why: An interpolation brace is part of the string's text layout; a space in front of it would become part of the string's value.

Example:

```csharp
class C
{
    string M(int a)
    {
        return $"value:{a}";
    }
}
```

is not reported.

### RH6009-003 — The diagnostic is on the brace

The analyzer MUST report one diagnostic per brace, located on the opening brace token.

Why: The brace is the token whose spacing is wrong.

Example: see RH6009-001.

### RH6009-004 — The fix inserts a space in front of the brace

The code fix MUST insert one space directly in front of the reported brace, after a comment that precedes it, and MUST NOT change anything else.

Why: The fix answers exactly what the diagnostic reports; inserting the space next to the brace never touches the comment.

Example:

```csharp
class C
{
    int P{|RH6009:{|} get; set; }
    int R/* note */{|RH6009:{|} get; set; }

    void M(object o){|RH6009:{|}
        var x = new int[]{|RH6009:{|}1 };
    }
}
```

```csharp
class C
{
    int P { get; set; }
    int R/* note */ { get; set; }

    void M(object o) {
        var x = new int[] {1 };
    }
}
```
