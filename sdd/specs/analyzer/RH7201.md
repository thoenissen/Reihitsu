# Analyzer — RH7201 System using directives must be placed before other using directives

| | |
|---|---|
| ID prefix | RH7201 |
| Status | Active |
| Category | Organization |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH7201SystemUsingDirectivesMustBePlacedBeforeOtherUsingDirectivesAnalyzer`, `RH7201SystemUsingDirectivesMustBePlacedBeforeOtherUsingDirectivesCodeFixProvider` |
| Uses | SHARED-USING-001, SHARED-USING-002, SHARED-USING-005, SHARED-USING-009, FMT-USING-001, FMT-USING-002, FMT-USING-003, FMT-USING-005, FMT-USING-006, FMT-USING-007, FMT-USING-008, FMT-USING-009 |

RH7201 reports a `System` namespace directive that follows a regular directive of another root namespace, and offers a code fix that organizes the whole using block.

## Non-goals

- The order within the `System` group — RH7203 — and blank lines between groups — RH7207.
- The canonical order and grouping of using directives — SHARED-USING — and how the formatter lays out a reordered block — FMT-USING.

## Requirements

### RH7201-001 — A `System` directive after another root is reported

The analyzer MUST report every regular namespace directive of the `System` group (SHARED-USING-005) that follows a regular namespace directive of another root namespace in the same block (SHARED-USING-001) and the same section, global or not (SHARED-USING-002), when SHARED-USING-009 allows the block to be reordered. `using static` and alias directives between the two do not matter. A `global::` qualifier does not change the root.

Why: The base class library is imported by almost every file, and listing it first is the long-standing .NET convention. Every `System` directive below another root is out of place, not only the first one, so each is reported. Directives of another block or section are ordered on their own, so they are never compared.

Example:

```csharp
using Microsoft.CodeAnalysis;
using {|RH7201:System.Linq|};
using static System.Math;
using {|RH7201:global::System.Text|};

class C
{
}
```

and the global section is checked on its own:

```csharp
global using Microsoft.CodeAnalysis;
global using {|RH7201:System|};

class C
{
}
```

while directives of different sections or blocks are not compared:

```csharp
global using Microsoft.CodeAnalysis;
using System;

class C
{
}
```

```csharp
using Microsoft.CodeAnalysis;

namespace N
{
    using System;

    class C
    {
    }
}
```

and a block with a preprocessor directive is not reported (SHARED-USING-009):

```csharp
using Microsoft.CodeAnalysis;
#if DEBUG
using System.Diagnostics;
#endif
using System;

class C
{
}
```

### RH7201-002 — Static, alias, and look-alike directives are not reported

The analyzer MUST NOT report a `using static` or an alias directive, also when it refers into `System`, and MUST NOT report a directive whose root only resembles `System`, such as `SYSTEM` or `Systematic` (SHARED-USING-005).

Why: The position of static and alias directives is RH7205's and RH7202's decision. A root that differs from `System` in case or length is a different namespace and an ordinary group.

Example:

```csharp
using Microsoft.CodeAnalysis;
using SYSTEM.Text;
using Systematic;
using static System.Math;
using A = System.Text;

class C
{
}
```

is not reported.

### RH7201-003 — The diagnostic is on the directive's name

The analyzer MUST report one diagnostic per reported directive, located on the namespace name it imports, a `global::` qualifier included.

Why: The name is what the reader scans for, and one diagnostic per directive shows each one that is out of place.

Example: see RH7201-001.

### RH7201-004 — The fix organizes the whole block

The code fix MUST rewrite the whole using block that contains the reported directive as the formatter's using-directive phase does: into the canonical order (FMT-USING-001), with exactly one blank line between two groups and none inside a group (FMT-USING-002), with one directive per line (FMT-USING-003), and with comments placed as FMT-USING-005, FMT-USING-006, FMT-USING-007, FMT-USING-008, and FMT-USING-009 specify. It MUST NOT change anything outside the block.

Why: A block has one organized form, shared by the formatter and the seven using-ordering rules RH7201–RH7207. Producing it in one step corrects every diagnostic those rules report in the block at once, so their fixes never undo each other. The code after the block is not the finding.

Example:

```csharp
using Microsoft.CodeAnalysis;
using {|RH7201:System.Linq|};
using {|RH7201:System|};

class C
{
}
```

```csharp
using System;
using System.Linq;

using Microsoft.CodeAnalysis;

class C
{
}
```
