# Analyzer — RH5029 Local declarations should be preceded by a blank line

| | |
|---|---|
| ID prefix | RH5029 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5029LocalDeclarationsShouldBePrecededByABlankLineAnalyzer`, `RH5029LocalDeclarationsShouldBePrecededByABlankLineCodeFixProvider` |
| Uses | SHARED-STMT-001, SHARED-STMT-002, SHARED-STMT-003, SHARED-STMT-004 |

RH5029 reports a local declaration that follows a statement other than a local declaration of the same block or switch section without a blank line between them, and offers a code fix that inserts one as SHARED-STMT-004 specifies.

## Non-goals

- An expression statement after a local declaration — RH5021.
- Blank lines before other statement kinds — the other rules that use `shared/statement-blank-lines.md`.

## Requirements

### RH5029-001 — A local declaration that follows another kind of statement needs a blank line

The analyzer MUST report a local declaration, a `const` or `using` declaration included, whose directly preceding statement in the same block or switch section is not a local declaration, as SHARED-STMT-001, SHARED-STMT-002, and SHARED-STMT-003 specify. It MUST NOT report a local declaration whose directly preceding statement is a local declaration, so a run of declarations needs a blank line only above its first declaration.

Why: A local declaration starts a new group of local state; the blank line separates it from the action above it. A run of declarations reads as one unit, so its declarations stay together.

Example:

```csharp
class C
{
    void M(int a, System.IDisposable resource)
    {
        var b = a;
        var c = b;
        a++;
        {|RH5029:var|} d = c;
        const int e = 1;

        M(d + e, resource);
        {|RH5029:const|} int f = 2;

        M(f, resource);
        {|RH5029:using|} var other = resource;
    }
}
```

`var b` is the first statement of its block, and `var c` and `const int e` follow a declaration; none of them is reported.

### RH5029-002 — The diagnostic is on the first token of the declaration

The analyzer MUST report the diagnostic on the first token of the local declaration statement, such as `var`, `const`, `using`, or the declared type.

Why: The first token is where the missing separator becomes visible, whatever modifier the declaration starts with.

Example: see RH5029-001.
