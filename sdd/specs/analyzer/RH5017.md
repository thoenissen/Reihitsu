# Analyzer — RH5017 fixed-Statement should be preceded by a blank line

| | |
|---|---|
| ID prefix | RH5017 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5017FixedStatementsShouldBePrecededByABlankLineAnalyzer`, `RH5017FixedStatementsShouldBePrecededByABlankLineCodeFixProvider` |
| Uses | SHARED-STMT-001, SHARED-STMT-002, SHARED-STMT-003, SHARED-STMT-004 |

RH5017 reports a `fixed` statement that follows another statement of the same block or switch section without a blank line between them, and offers a code fix that inserts one as SHARED-STMT-004 specifies.

## Non-goals

- Blank lines before other statement kinds — the other rules that use `shared/statement-blank-lines.md`.

## Requirements

### RH5017-001 — A `fixed` statement that follows a statement needs a blank line

The analyzer MUST report a `fixed` statement as SHARED-STMT-001, SHARED-STMT-002, and SHARED-STMT-003 specify.

Why: A `fixed` statement pins memory for the block it guards; the blank line marks where the pinned region begins.

Example:

```csharp
class C
{
    unsafe void M(int[] values)
    {
        var length = values.Length;
        {|RH5017:fixed|} (int* pointer = values)
        {
            pointer[0] = length;
        }

        fixed (int* pointer = values)
        {
            pointer[0] = 0;
        }
    }
}
```

The second `fixed` follows a blank line and is not reported.

### RH5017-002 — The diagnostic is on the `fixed` keyword

The analyzer MUST report the diagnostic on the `fixed` keyword.

Why: The keyword is where the missing separator becomes visible, and the location stays stable when the pinned declaration changes.

Example: see RH5017-001.
