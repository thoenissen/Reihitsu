# Analyzer — RH8106 Element return value documentation must have text

| | |
|---|---|
| ID prefix | RH8106 |
| Status | Active |
| Category | Documentation |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH8106ElementReturnValueDocumentationMustHaveTextAnalyzer` |
| Uses | SHARED-DOC-004, SHARED-DOC-008, SHARED-DOC-014 |

RH8106 reports a `<returns>` element that has no text.

## Non-goals

- A missing `<returns>` element — RH8105; a `<returns>` element on a member that returns `void` — RH8107.
- `<param>` and `<typeparam>` elements — RH8104 and RH8111; the summary — RH8030.

## Requirements

### RH8106-001 — A `<returns>` element without text is reported

The analyzer MUST report the `<returns>` element at the top level of the documentation comment, as SHARED-DOC-004 defines it, of a method, delegate, operator, or conversion operator declaration when that element has no text as SHARED-DOC-014 specifies. A declaration that explicitly implements an interface member MUST be checked as well, and the declaration's accessibility does not matter. A `<returns>` element nested inside another element MUST NOT be reported. Nothing is reported when SHARED-DOC-008 applies.

This requirement covers a declaration whose return type is not the `void` keyword and whose leading trivia has one documentation comment with at most one `<returns>` element at its top level, placed as SHARED-DOC-004 covers and well-formed XML, with the tag name `returns` written in lower case, without a namespace prefix, and in no XML namespace.

Why: An empty `<returns>` element looks like finished documentation while it leaves the return value as unexplained as a missing one. An explicit implementation needs no documentation of its own, but a `<returns>` element that it does carry is shown to the reader, so it has to say something.

Example:

```csharp
using System.Threading.Tasks;

/// <summary>
/// Factory
/// </summary>
/// {|RH8106:<returns></returns>|}
public delegate int Factory();

/// <summary>
/// Contract
/// </summary>
public interface I
{
    /// <summary>
    /// Gets
    /// </summary>
    /// <returns>Value</returns>
    int Get();
}

/// <summary>
/// Service
/// </summary>
public class C : I
{
    /// <summary>
    /// Counts
    /// </summary>
    /// {|RH8106:<returns/>|}
    public int Count() => 0;

    /// <summary>
    /// Loads
    /// </summary>
    /// {|RH8106:<returns>
    /// </returns>|}
    public Task LoadAsync() => Task.CompletedTask;

    /// <summary>
    /// Gets
    /// </summary>
    /// {|RH8106:<returns>&#32;</returns>|}
    int I.Get() => 0;

    /// <summary>
    /// Finds
    /// </summary>
    /// <returns>Value</returns>
    /// <remarks>
    /// <returns></returns>
    /// </remarks>
    public int Find() => 0;

    /// <summary>
    /// Adds
    /// </summary>
    /// <param name="left">Left</param>
    /// <param name="right">Right</param>
    /// {|RH8106:<returns></returns>|}
    public static C operator +(C left, C right) => left;
}
```

### RH8106-002 — The diagnostic is on the element

The analyzer MUST report one diagnostic per declaration, located on the whole `<returns>` element: the empty element, or everything from the start tag through the end tag.

Why: The element is where the description has to be written.

Example: see RH8106-001.
