# Analyzer — RH4001 Type name matches the file name

| | |
|---|---|
| ID prefix | RH4001 |
| Status | Active |
| Category | Naming |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Without Fix All |
| Code owners | `RH4001TypeNameShouldMatchFileNameAnalyzer`, `RH4001TypeNameShouldMatchFileNameCodeFixProvider`, `RH4001TypeNameShouldMatchFileNameHelper` |
| Uses | — |

RH4001 reports the first type of a file when its name does not match the file name, and offers a code fix that renames the file.

## Non-goals

- Whether a file should declare more than one type — no rule checks it.
- The casing of the type name — RH4002 to RH4006, RH4010, and RH4011.
- Renaming the type instead of the file.

## Requirements

### RH4001-001 — The first type of a file is checked

The analyzer MUST compare the name of the first type declaration of a file with the file name: the first class, struct, interface, enum, record, or delegate declaration in document order that is declared at file level or inside namespace declarations. Nested types and every type after the first MUST NOT be compared, and a file that declares no type MUST NOT be reported.

Why: A reader finds a type by its file name, so the file is named after the type it is about, which is the one declared first. Nested types and later types are companions of that type and are found through it.

Example — in a file `Outer.cs`:

```csharp
public class Outer
{
    public class Inner
    {
    }
}

public class Second
{
}
```

is not reported. In a file `Mismatched.cs`:

```csharp
namespace EmptyNamespace
{
}

namespace PopulatedNamespace
{
    internal class {|RH4001:LaterType|}
    {
    }
}
```

is reported, because `LaterType` is the first type of the file. In a file `Test0.cs`:

```csharp
public delegate void {|RH4001:Handler|}();

public class Test0
{
}
```

is reported, because the delegate comes first. A file `Test0.cs` that contains only `namespace N { }` is not reported.

### RH4001-002 — The type name is compared with the file name up to its first dot

The analyzer MUST compare the type name with the file name up to its first dot, without the extension. When that part starts with 14 digits followed by `_`, the digits and the `_` MUST be removed before the comparison. The comparison MUST be exact and case-sensitive.

Why: A suffix after the first dot marks the file's role — `View.xaml.cs`, `Component.razor.cs`, `Type.Part1.cs` — and is not part of the type name. Entity Framework Core prefixes its migration files with a timestamp of 14 digits and an underscore.

Example — `public class Test0 { }` is not reported in the files `Test0.cs`, `Test0.razor.cs`, `Test0.xaml.cs`, and `Test0.Part1.cs`. `public class InitialCreate { }` is not reported in `20210501083748_InitialCreate.cs`, and `public class A2345678901234_Something { }` is not reported in `A2345678901234_Something.cs`, whose prefix is not all digits. In a file `testclass.cs`:

```csharp
public class {|RH4001:TestClass|}
{
}
```

is reported, and so is `public class SomeMigration { }` in `20210501083748_InitialCreate.cs`.

### RH4001-003 — A generic type is expected with its type parameters in braces

For a generic type, the analyzer MUST expect its name followed by `{`, the names of its type parameters separated by `,` without spaces, and `}`.

Why: A file name cannot contain `<` and `>`, and a generic type and a non-generic type of the same name are different types that need different files.

Example — `public class Cache<TKey, TValue> { }` is not reported in `Cache{TKey,TValue}.cs`. In a file `Cache.cs`:

```csharp
public class {|RH4001:Cache|}<TKey, TValue>
{
}
```

is reported.

### RH4001-004 — The diagnostic is on the type name

The analyzer MUST report one diagnostic per file, located on the identifier of the first type declaration.

Why: The type name is what has to match; marking it shows which type the file is expected to be named after.

Example: see RH4001-001.

### RH4001-005 — The fix renames the file

For a file name that does not start with the 14-digit prefix of RH4001-002, the code fix MUST rename the document to the expected name of RH4001-001 and RH4001-003, followed by the part of the old file name from its first dot and the extension. The document MUST stay in its folder, and its content MUST NOT change; the type is not renamed.

Why: The file name is the half of the mismatch that nothing else refers to, so renaming it changes no code. Keeping the part from the first dot keeps a code-behind or a partial file in its role.

Example — in a file `Test0.cs`:

```csharp
public class {|RH4001:TestClass|}
{
}
```

the fix renames the file to `TestClass.cs`. It renames `Test0.razor.cs` that declares `TestComponent` to `TestComponent.razor.cs`, `Test0.Part1.cs` that declares `partial class TestComponent` to `TestComponent.Part1.cs`, and `Test0.cs` that declares `TestClass<T>` to `TestClass{T}.cs`.

### RH4001-006 — The fix is withheld when the new file name is taken

The code fix MUST NOT be offered when another document of the project in the same folder already has the new file name, compared case-insensitively. The diagnostic is still reported.

Why: Renaming the file would replace that document when the project is saved.

Example — a project with `Mismatched.cs`, which declares `class TestClass`, and `TestClass.cs` in the same folder, which declares another `class TestClass` in another namespace: `Mismatched.cs` is reported, and no code fix is offered.
