# Analyzer — RH4001 Type name matches the file name

| | |
|---|---|
| ID prefix | RH4001 |
| Status | Active |
| Category | Naming |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Without Fix All |
| Code owners | `RH4001TypeNameShouldMatchFileNameAnalyzer`, `RH4001TypeNameShouldMatchFileNameCodeFixProvider`, `RH4001TypeNameShouldMatchFileNameHelper` |
| Uses | — |

RH4001 reports the first type of a file when its name does not match the file name, and offers a code fix that renames the file.

## Non-goals

- Whether a file should declare more than one type — no rule checks it.
- The casing of the type name — RH4002 to RH4006, RH4010, and RH4011.
- Renaming the type instead of the file.

## Requirements

### RH4001-001 — The first type of a file is checked

The analyzer MUST compare the name of the first type declaration of a file with the file name: the first class, struct, interface, enum, record, or delegate declaration in document order that is declared at file level or inside namespace declarations. Nested types and every type after the first MUST NOT be compared, and a file that declares no type MUST NOT be reported.

This requirement covers a file without top-level statements.

Why: A reader finds a type by its file name, so the file is named after the type it is about, which is the one declared first. Nested types and later types are companions of that type and are found through it.

Example — in a file `Outer.cs`:

```csharp
public class Outer
{
    public class Inner
    {
    }
}

public class Customer
{
}
```

is not reported. In a file `Invoice.cs`:

```csharp
namespace Billing
{
}

namespace Sales
{
    internal class {|RH4001:Order|}
    {
    }
}
```

is reported, because `Order` is the first type of the file. In a file `Order.cs`:

```csharp
public delegate void {|RH4001:Handler|}();

public class Order
{
}
```

is reported, because the delegate comes first. A file `Order.cs` that contains only `namespace Sales { }` is not reported.

### RH4001-002 — The type name is compared with the file name up to its first dot

The analyzer MUST compare the type name, by its value (SHARED-DIAG-002) and with every Unicode escape sequence in it replaced by the character it stands for, with the file name up to its first dot, without the extension. When that part starts with 14 digits followed by `_`, the digits and the `_` MUST be removed before the comparison. The comparison MUST be exact and case-sensitive.

Why: A suffix after the first dot marks the file's role — `View.xaml.cs`, `Component.razor.cs`, `Type.Part1.cs` — and is not part of the type name. Entity Framework Core prefixes its migration files with a timestamp of 14 digits and an underscore.

Example — `public class Order { }` is not reported in the files `Order.cs`, `Order.razor.cs`, `Order.xaml.cs`, and `Order.Part1.cs`. `public class InitialCreate { }` is not reported in `20210501083748_InitialCreate.cs`, and `public class V2021050108374_Order { }` is not reported in `V2021050108374_Order.cs`, whose prefix is not all digits. In a file `order.cs`:

```csharp
public class {|RH4001:Order|}
{
}
```

is reported, and so is `public class SomeMigration { }` in `20210501083748_InitialCreate.cs`.

Example — the verbatim prefix is not part of the name: `public class @class { }` is not reported in `class.cs`, and `public class @Order { }` is not reported in `Order.cs`. In a file `@class.cs`:

```csharp
public class {|RH4001:@class|}
{
}
```

is reported, because the type is named `class`.

Example — a Unicode escape is not part of the name either: `public class \u0041bc { }` declares the type `Abc` and is not reported in `Abc.cs`. In a file `Invoice.cs`,

```csharp
public class {|RH4001:\u0041bc|}
{
}
```

is reported.

### RH4001-003 — A generic type is expected with its type parameters in braces

For a generic type, the analyzer MUST expect its name followed by `{`, the names of its type parameters separated by `,` without spaces, and `}`. The type name and the type-parameter names are compared as RH4001-002 compares the type name: by their values, with Unicode escape sequences replaced.

Why: A file name cannot contain `<` and `>`, and a generic type and a non-generic type of the same name are different types that need different files.

Example — `public class Cache<TKey, TValue> { }` is not reported in `Cache{TKey,TValue}.cs`. In a file `Cache.cs`:

```csharp
public class {|RH4001:Cache|}<TKey, TValue>
{
}
```

is reported. `public class Cache<@TKey> { }` is not reported in `Cache{TKey}.cs`, and

```csharp
public class {|RH4001:Cache|}<@TKey>
{
}
```

is reported in `Cache{@TKey}.cs`.

### RH4001-004 — The diagnostic is on the type name

The analyzer MUST report one diagnostic per file, located on the identifier of the first type declaration.

Why: The type name is what has to match; marking it shows which type the file is expected to be named after.

Example: see RH4001-001.

### RH4001-005 — The fix renames the file

For a file name that does not start with the 14-digit prefix of RH4001-002, the code fix MUST rename the document to the expected name of RH4001-001 and RH4001-003, followed by the part of the old file name from its first dot and the extension. The document MUST stay in its folder, and its content MUST NOT change; the type is not renamed.

Why: The file name is the half of the mismatch that nothing else refers to, so renaming it changes no code. Keeping the part from the first dot keeps a code-behind or a partial file in its role.

Example — in a file `Invoice.cs`:

```csharp
public class {|RH4001:Order|}
{
}
```

the fix renames the file to `Order.cs`. It renames `Invoice.razor.cs` that declares `OrderView` to `OrderView.razor.cs`, `Invoice.Part1.cs` that declares `partial class Order` to `Order.Part1.cs`, and `Invoice.cs` that declares `Order<T>` to `Order{T}.cs`. The new name is derived from the values of the names (SHARED-DIAG-002): the fix renames `Invoice.cs` that declares `class @Order` to `Order.cs`, `Invoice.cs` that declares `Cache<@TKey>` to `Cache{TKey}.cs`, and `@class.cs` that declares `class @class` to `class.cs`. A Unicode escape is replaced the same way: the fix renames `Invoice.cs` that declares `class \u0041bc` to `Abc.cs`.

### RH4001-006 — The fix is withheld when the new file name is taken

The code fix MUST NOT be offered when another document of the project in the same folder already has the new file name, compared case-insensitively. The diagnostic is still reported.

Why: Renaming the file would replace that document when the project is saved.

Example — a project with `Invoice.cs`, which declares `class Order`, and `Order.cs` in the same folder, which declares another `class Order` in another namespace: `Invoice.cs` is reported, and no code fix is offered. The same holds when the other document is named `order.cs`. When `Order.cs` is in another folder of the project, such as `Archive`, the fix is offered and renames `Invoice.cs` to `Order.cs` in its own folder. The new file name is the one RH4001-005 derives, so when `Invoice.cs` declares `class @Order` and `Order.cs` is in the same folder, no code fix is offered either.
