# Analyzer — RH5201 Method chains should be aligned

| | |
|---|---|
| ID prefix | RH5201 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5201MethodChainsShouldBeAlignedAnalyzer`, `RH5201MethodChainsShouldBeAlignedCodeFixProvider` |
| Uses | SHARED-CHAIN-002, SHARED-CHAIN-004, SHARED-CHAIN-005, SHARED-CHAIN-006, SHARED-CHAIN-007, SHARED-CHAIN-008, SHARED-CHAIN-009 |

RH5201 reports a link of a wrapped member-access chain that does not start its own line where it must, is not aligned to the chain's anchor, or has its operator split by a line break, and offers a code fix that lays the chain out the way the formatter does.

## Non-goals

- A first link that starts a line below the root — RH5112.
- Chains written on one line (SHARED-CHAIN-002).
- Comments between the links of a chain — RH5048 for the one in front of the first link.

## Requirements

### RH5201-001 — A later call that shares a line is reported

In a wrapped chain (SHARED-CHAIN-002), the analyzer MUST report every link after the first invoked link that does not start a line, as SHARED-CHAIN-005 requires. A link of the prefix in front of the first invoked link, and every link of a chain without an invoked link, MUST NOT be reported for not starting a line.

Why: Once a chain is wrapped, one step per line keeps it scannable; a property prefix is not a step and may stay together (SHARED-CHAIN-005).

Example:

```csharp
using System.Linq;

class C
{
    C Next { get; set; }
    C Self() => this;

    void M(int[] items, C c)
    {
        var a = items.Where(x => x > 0)
                     .Select(x => x){|RH5201:.|}ToList();
        var b = c.Next
                 .Next.Next;
        var d = c.Next.Next
                 .Self();
    }
}
```

### RH5201-002 — A misaligned wrapped link is reported

In a wrapped chain, the analyzer MUST report every link that starts a line whose first character that is not whitespace is not in the column of the chain's anchor, as SHARED-CHAIN-007 defines it; when a comment or a directive keeps the first link on its own line (SHARED-CHAIN-004), the anchor is the start of the root. A block comment in front of a link on the link's line MUST be aligned together with the link. The first link MUST NOT be reported for its column when nothing keeps it on its own line.

Why: Aligned operators make the chain read as a column of steps under the first one (SHARED-CHAIN-007). A comment that starts the link's line is part of that line, so the line, not the operator, is what aligns. A first link that starts a line is RH5112's concern, and the links after it align to it.

Example:

```csharp
using System.Linq;

class C
{
    void M(int[] items)
    {
        var a = items.Where(x => x > 0)
            {|RH5201:.|}Select(x => x);
        var b = items // root
            {|RH5201:.|}Where(x => x > 0);
        var c = items.Where(x => x > 0)
                     /* all */ .ToList();
        var d = items
            .Where(x => x > 0)
            .ToList();
    }
}
```

### RH5201-003 — A split link operator is reported

The analyzer MUST report a link whose operator holds a line break between its own tokens (SHARED-CHAIN-006). A line break that a comment, a preprocessor directive, or disabled text keeps between the operator's tokens MUST NOT count as splitting it; such a link is checked by RH5201-001 and RH5201-002 by the line its first token is on.

Why: `?.` and `!.` read as one operator; a `?` or `!` at the end of a line reads as a conditional or a negation. A line break that a comment holds cannot be removed without moving the comment, but the operator can still start its own line in front of the comment.

Example:

```csharp
#nullable enable
using System.Linq;

class C
{
    C? Next { get; set; }

    void M(int[]? items, C d)
    {
        var a = items?.Where(x => x > 0){|RH5201:?|}
                     .ToList();
        var b = d{|RH5201:!|}
            .ToString();
        var e = d.Next{|RH5201:?|}
                 .Next;
        var f = d.Next? // why
                 .Next;
        var g = items?.Where(x => x > 0){|RH5201:?|} // why
                     .ToList();
    }
}
```

The `?` in front of `// why` in `f` is not reported: the comment keeps the line break, and a link of a chain without a call need not start a line. The `?` in front of `// why` in `g` is reported because, as a later link of a chain with a call, it does not start a line (RH5201-001).

### RH5201-004 — The diagnostic is on the link's operator

The analyzer MUST report one diagnostic per misplaced link, located on the first token of its operator: the `.`, the `?` of `?.`, or the `!` of `!.` and `!?.`. A link that is misplaced in more than one way is reported once.

Why: The operator's first token is where the line break goes and what is aligned; one diagnostic per link keeps the count of diagnostics equal to the number of links that move.

Example: see RH5201-001 to RH5201-003.

### RH5201-005 — The fix lays out the chain

The code fix MUST lay out the chain as SHARED-CHAIN-008 and SHARED-CHAIN-009 specify.

Why: The links of a chain align to one anchor, so moving one link can move the others; the formatted layout of the whole chain clears every diagnostic of the chain at once.

Example:

```csharp
using System.Linq;

class C
{
    void M(int[] items)
    {
        var a = items.Where(x => x > 0)
        {|RH5201:.|}Select(x => x){|RH5201:.|}ToList();
    }
}
```

```csharp
using System.Linq;

class C
{
    void M(int[] items)
    {
        var a = items.Where(x => x > 0)
                     .Select(x => x)
                     .ToList();
    }
}
```
