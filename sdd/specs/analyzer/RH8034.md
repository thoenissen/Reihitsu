# Analyzer — RH8034 Operators must be documented

| | |
|---|---|
| ID prefix | RH8034 |
| Status | Active |
| Category | Documentation |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH8034OperatorsMustBeDocumentedAnalyzer` |
| Uses | SHARED-DOC-001, SHARED-DOC-004, SHARED-DOC-005, SHARED-DOC-006, SHARED-DOC-007, SHARED-DOC-008, SHARED-DOC-009 |

RH8034 reports an operator or conversion operator that has no `<summary>` or `<inheritdoc>` documentation.

## Non-goals

- Methods — RH8020 and RH8021.
- Whether the summary has text — RH8030; the documentation of parameters and return values — RH8101 and RH8105.

## Requirements

### RH8034-001 — Undocumented operators are reported

The analyzer MUST report every operator declaration and conversion operator declaration that is not documented, checked as SHARED-DOC-001 specifies, whatever its modifiers, except an explicit interface implementation, which SHARED-DOC-009 exempts. An operator declaration is a user-defined unary, binary, checked, or compound assignment operator, checked in the body of a class, struct, interface, record, record struct, or extension block; a conversion operator declaration is an `implicit` or `explicit` conversion, checked in the body of a class, struct, interface, record, or record struct. Whether it is documented MUST be decided as SHARED-DOC-004, SHARED-DOC-005, SHARED-DOC-006, and SHARED-DOC-007 specify, and nothing is reported when SHARED-DOC-008 applies.

Why: An operator changes the meaning of ordinary expression syntax for a type; without documentation, a reader cannot know what `a + b` does for that type without reading the implementation. C# requires every operator that is not an explicit interface implementation to be public, so there is no private group to split into a rule of its own.

Example:

```csharp
/// <summary>
/// Money
/// </summary>
public readonly struct Money
{
    public static Money operator {|RH8034:+|}(Money left, Money right) => left;

    public static Money operator checked {|RH8034:-|}(Money left, Money right) => left;

    public static Money operator {|RH8034:-|}(Money left, Money right) => left;

    /// <remarks>
    /// No summary
    /// </remarks>
    public static implicit {|RH8034:operator|} int(Money value) => 0;

    /// <summary>
    /// Negates an amount
    /// </summary>
    /// <param name="value">Amount</param>
    /// <returns>The negated amount</returns>
    public static Money operator -(Money value) => value;
}

/// <summary>
/// Counter
/// </summary>
public class Counter
{
    public void operator {|RH8034:+=|}(int value)
    {
    }
}

/// <summary>
/// Addable values
/// </summary>
/// <typeparam name="T">Value</typeparam>
public interface IAddable<T> where T : IAddable<T>
{
    static abstract T operator {|RH8034:+|}(T left, T right);
}

/// <summary>
/// Number
/// </summary>
public readonly struct Number : IAddable<Number>
{
    static Number IAddable<Number>.operator +(Number left, Number right) => left;
}
```

### RH8034-002 — Where the diagnostic is

The analyzer MUST report one diagnostic per undocumented declaration, located on the operator token of an operator declaration — the `+` of `operator +`, the `-` of `operator checked -`, the `+=` of `operator +=` — and on the `operator` keyword of a conversion operator declaration.

Why: The operator token names an operator the way an identifier names a method. A conversion operator has no operator token, and `operator` is the keyword that names it.

Example: see RH8034-001.
