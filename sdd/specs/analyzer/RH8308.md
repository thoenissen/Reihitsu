# Analyzer — RH8308 No content should appear after closing XML tags

| | |
|---|---|
| ID prefix | RH8308 |
| Status | Active |
| Category | Documentation |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH8308NoContentShouldAppearAfterClosingXmlTagsAnalyzer`, `RH8308NoContentShouldAppearAfterClosingXmlTagsCodeFixProvider` |
| Uses | SHARED-DOC-004, SHARED-DOC-008 |

RH8308 reports text that follows a top-level XML element of a `///` documentation comment on the line where the element ends, and offers a code fix that removes the text.

## Non-goals

- A second element after an end tag on the same line — RH8304.
- The layout of the lines inside an element — RH8305 and RH8307.

## Requirements

### RH8308-001 — Text after a top-level element on its line is reported

The analyzer MUST report text at the top level of a `///` documentation comment that directly follows a top-level element — closed by an end tag or empty, such as `<inheritdoc/>` — when the text's first character that is not white space is on the line on which the element ends. An element such as `<c>` that follows the text on the same line is itself a top-level element, so in `</summary> a <c>x</c> b` both `a` and `b` are reported. Nothing is reported when SHARED-DOC-008 applies.

This requirement covers the `///` documentation comments of a declaration, as SHARED-DOC-004 defines them, and text without character references, such as `&amp;`. A `///` comment that is not a documentation comment of a declaration, such as one inside a method body, and text that an XML comment separates from the element are not covered.

Why: Text after a finished element is outside every element, so documentation tools show it nowhere or attach it to nothing, and the reader cannot tell which part of the documentation it belongs to.

Example:

```csharp
class C
{
    /// <summary>
    /// Runs
    /// </summary> {|RH8308:Additional text|}
    void M()
    {
    }

    /// <summary>Stops</summary>   {|RH8308:now|}
    void N()
    {
    }

    /// <inheritdoc/> {|RH8308:inherited|}
    int A;
}
```

### RH8308-002 — Text on a later line or inside an element is not reported

The analyzer MUST NOT report text whose first character that is not white space is on a line after the one on which the preceding element ends, text inside an element, or text in a `/** */` documentation comment.

Why: Text on a line of its own after an element is how documentation continues prose between elements, and text after an inline element such as `<c>` is part of the content of the element around it. A delimited comment has no `///` lines to lay out.

Example:

```csharp
class C
{
    /// <summary>Runs</summary>
    /// Text on the next line
    void M()
    {
    }

    /// <summary>
    /// Stops <c>now</c> quickly
    /// </summary>
    void N()
    {
    }

    /** <summary>Value</summary> text */
    int A;
}
```

is not reported.

### RH8308-003 — The diagnostic covers the text up to the end of the line

The analyzer MUST report one diagnostic per reported text, from its first character that is not white space to the end of that text: the end of the line, or the start of the next XML node on the line.

Why: That text is what the fix removes; the white space in front of it is not reported, because it is not content.

Example: see RH8308-001.

### RH8308-004 — The fix removes the text

The code fix MUST remove the reported text together with the spaces and tabs directly in front of it, and change nothing else.

Why: The text is not part of any element, so the fix cannot move it into one; a user who wants to keep it moves it first. The white space in front of it would otherwise be left behind at the end of the line.

Example:

```csharp
class C
{
    /// <summary>
    /// Runs
    /// </summary> {|RH8308:Additional text|}
    void M()
    {
    }

    /// <summary>Stops</summary> {|RH8308:a |}<c>x</c> {|RH8308:b|}
    void N()
    {
    }
}
```

```csharp
class C
{
    /// <summary>
    /// Runs
    /// </summary>
    void M()
    {
    }

    /// <summary>Stops</summary><c>x</c>
    void N()
    {
    }
}
```
