# Analyzer — RH1002 Types used for equality comparison must implement equality members

| | |
|---|---|
| ID prefix | RH1002 |
| Status | Active |
| Category | Performance |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH1002TypesUsedForEqualityComparisonMustImplementEqualityMembersAnalyzer` |
| Uses | SHARED-EQUAL-001, SHARED-EQUAL-002 |

RH1002 reports a call of an equality-based LINQ or collection-conversion method that compares a struct without its own equality members.

## Non-goals

- Hash-based collection types used directly, such as `Dictionary<TKey, TValue>` or `HashSet<T>` — RH1001.
- Ordering operations, such as `OrderBy`, which compare by order and not by equality.
- Predicates and comparisons the user writes, such as `Any(x => x.Equals(y))` or `==`.

## Requirements

### RH1002-001 — Equality-based operations on a struct without equality members are reported

The analyzer MUST report a call of one of the methods `Distinct`, `DistinctBy`, `Union`, `UnionBy`, `Intersect`, `IntersectBy`, `Except`, `ExceptBy`, `ToHashSet`, `ToLookup`, `ToDictionary`, `GroupBy`, `Join`, `GroupJoin`, `Contains`, `SequenceEqual`, `ToImmutableHashSet`, `ToImmutableDictionary`, `ToFrozenSet`, and `ToFrozenDictionary` that binds to a method declared on `System.Linq.Enumerable`, `System.Collections.Immutable.ImmutableDictionary`, `System.Collections.Immutable.ImmutableHashSet`, `System.Collections.Frozen.FrozenDictionary`, or `System.Collections.Frozen.FrozenSet`, when the type it compares, as RH1002-002 determines it, lacks equality members as SHARED-EQUAL-001 defines it and the call passes no custom comparer as SHARED-EQUAL-002 defines it. `Contains` and `SequenceEqual` MUST be reported only when they bind to `System.Linq.Enumerable`.

Why: These operations hash or compare the type many times, once per element and often once per pair of elements. A struct without its own equality members is boxed and inspected by `ValueType`'s members on each of those calls.

Example:

```csharp
using System.Collections.Frozen;
using System.Collections.Generic;
using System.Collections.Immutable;
using System.Linq;

struct S
{
}

class C
{
    void M(IEnumerable<S> items, S item)
    {
        items.{|RH1002:Distinct|}();
        items.{|RH1002:DistinctBy|}(x => x);
        items.{|RH1002:Union|}(items);
        items.{|RH1002:UnionBy|}(items, x => x);
        items.{|RH1002:Intersect|}(items);
        items.{|RH1002:IntersectBy|}(items, x => x);
        items.{|RH1002:Except|}(items);
        items.{|RH1002:ExceptBy|}(items, x => x);
        items.{|RH1002:ToHashSet|}();
        items.{|RH1002:ToLookup|}(x => x);
        items.{|RH1002:ToDictionary|}(x => x);
        items.{|RH1002:GroupBy|}(x => x);
        items.{|RH1002:Join|}(items, x => x, x => x, (a, b) => a);
        items.{|RH1002:GroupJoin|}(items, x => x, x => x, (a, b) => a);
        items.{|RH1002:Contains|}(item);
        items.{|RH1002:SequenceEqual|}(items);
        items.{|RH1002:ToImmutableHashSet|}();
        items.{|RH1002:ToImmutableDictionary|}(x => x, x => 0);
        items.{|RH1002:ToFrozenSet|}();
        items.{|RH1002:ToFrozenDictionary|}(x => x);
    }
}
```

### RH1002-002 — The compared type is the key

The analyzer MUST check the type the bound overload compares: the type its key selector returns, when the overload has a key selector, and otherwise its first type argument. For the overloads of `ToDictionary`, `ToImmutableDictionary`, and `ToFrozenDictionary` that take a sequence of `KeyValuePair<TKey, TValue>`, the first type argument is the key type.

Why: An overload with a key selector compares the keys it selects, not the elements; a struct element whose selected key is an `int` is never compared. A dictionary built from key/value pairs compares only their keys.

Example:

```csharp
using System.Collections.Generic;
using System.Linq;

struct S
{
    public int Value;
}

class C
{
    void M(IEnumerable<S> items, IEnumerable<int> numbers, IEnumerable<KeyValuePair<S, int>> byKey, IEnumerable<KeyValuePair<int, S>> byValue)
    {
        items.GroupBy(x => x.Value);
        items.ToDictionary(x => x.Value);
        items.DistinctBy(x => x.Value);
        numbers.{|RH1002:GroupBy|}(x => new S());
        byKey.{|RH1002:ToDictionary|}();
        byValue.ToDictionary();
    }
}
```

### RH1002-003 — Methods of other types are not reported

The analyzer MUST NOT report a call that binds to a method of a type the rule does not name, even when the method has one of the names, such as `List<T>.Contains` or the `Queryable` methods. It MUST NOT report `ImmutableDictionary.Contains`, which binds to `ImmutableDictionary` and not to `Enumerable`.

Why: These methods compare through their own logic: a list scans with the type's members at the caller's choice, a query is translated elsewhere, and `ImmutableDictionary.Contains(map, key, value)` looks the key up through the map's own comparer.

Example:

```csharp
using System.Collections.Generic;
using System.Collections.Immutable;
using System.Linq;

struct S
{
}

class C
{
    void M(List<S> list, IQueryable<S> query, ImmutableDictionary<S, int> map, S item)
    {
        list.Contains(item);
        query.Distinct();
        map.Contains(item, 0);
    }
}
```

is not reported.

### RH1002-004 — `Contains` on a dictionary is not reported

The analyzer MUST NOT report a call of `Enumerable.Contains` without a comparer whose searched value is a `KeyValuePair<TKey, TValue>` and whose source has a static type that is a dictionary of that pair: a type that converts to `IDictionary<TKey, TValue>`, or an interface that converts to `IReadOnlyDictionary<TKey, TValue>`, also as the interface constraint of a type parameter. A class that implements only `IReadOnlyDictionary<TKey, TValue>`, used directly or as the class constraint of a type parameter, a source typed only as a sequence of pairs, a `Contains` call with a comparer argument that is not custom, and `SequenceEqual` MUST still be reported.

Why: `Enumerable.Contains` without a comparer hands the search to the source's own `ICollection<T>.Contains`, which a dictionary answers with a key lookup, so the pair's equality members are never called. A read-only dictionary interface is implemented by dictionaries that do the same. A class that only implements the read-only interface is not such a collection and is scanned with the pair's members, and so is a plain sequence, a call with a comparer, and `SequenceEqual`.

Example:

```csharp
using System.Collections;
using System.Collections.Generic;
using System.Linq;

struct S
{
}

abstract class ReadOnlyMap : IReadOnlyDictionary<S, int>
{
    public abstract int this[S key] { get; }
    public abstract IEnumerable<S> Keys { get; }
    public abstract IEnumerable<int> Values { get; }
    public abstract int Count { get; }
    public abstract bool ContainsKey(S key);
    public abstract bool TryGetValue(S key, out int value);
    public abstract IEnumerator<KeyValuePair<S, int>> GetEnumerator();
    IEnumerator IEnumerable.GetEnumerator() => GetEnumerator();
}

class C
{
    void M(Dictionary<S, int> dictionary, IReadOnlyDictionary<S, int> readOnly, ReadOnlyMap map, IEnumerable<KeyValuePair<S, int>> pairs, KeyValuePair<S, int> pair)
    {
        dictionary.Contains(pair);
        readOnly.Contains(pair);
        map.{|RH1002:Contains|}(pair);
        pairs.{|RH1002:Contains|}(pair);
        dictionary.{|RH1002:Contains|}(pair, null);
        dictionary.{|RH1002:SequenceEqual|}(pairs);
    }

    bool N<T>(T source, KeyValuePair<S, int> pair)
        where T : IReadOnlyDictionary<S, int>
    {
        return source.Contains(pair);
    }
}
```

### RH1002-005 — Where the diagnostic is

The analyzer MUST report one diagnostic per reported call, located on the method name, with its type argument list when it has one, when the method is called through a member access, and on the whole call from its `.` on when it is called through a null-conditional access.

Why: The method name says which operation compares the struct; a null-conditional call has no member-access name of its own, so the call stands for it.

Example:

```csharp
using System.Collections.Generic;
using System.Linq;

struct S
{
}

class C
{
    void M(IEnumerable<S> items)
    {
        items.{|RH1002:Distinct<S>|}();
        Enumerable.{|RH1002:Distinct|}(items);
        items?{|RH1002:.Distinct()|};
    }
}
```
