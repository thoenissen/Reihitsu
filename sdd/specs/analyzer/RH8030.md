# Analyzer — RH8030 Element documentation must have summary text

| | |
|---|---|
| ID prefix | RH8030 |
| Status | Active |
| Category | Documentation |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH8030ElementDocumentationMustHaveSummaryTextAnalyzer` |
| Uses | SHARED-DOC-004, SHARED-DOC-008, SHARED-DOC-010 |

RH8030 reports a `<summary>` element in the documentation of a declaration that has no text.

## Non-goals

- Whether a declaration has a summary at all — RH8001 to RH8029 and RH8034.
- Extension declarations — RH8031.
- Whether the descriptions of parameters, type parameters, and return values have text — RH8104, RH8106, and RH8111.

## Requirements

### RH8030-001 — A summary without text is reported

The analyzer MUST report the `<summary>` element at the top level of a declaration's documentation comment, as SHARED-DOC-004 defines it, when that element has no text as SHARED-DOC-010 specifies. The declarations checked are class, struct, interface, record, record struct, enum, enum member, delegate, constructor, destructor, method, property, indexer, field, event, operator, and conversion operator declarations, whatever their accessibility and wherever they are declared; an extension declaration is not one. A `<summary>` nested in another element MUST NOT be reported, and an `<inheritdoc>` element next to the summary MUST NOT prevent the report. Nothing is reported when SHARED-DOC-008 applies.

This requirement covers a declaration whose leading trivia has one documentation comment with at most one `<summary>` element at its top level, where the comment is well-formed XML and writes the tag name `summary` in lower case, without a namespace prefix, and in no XML namespace. A declaration that explicitly implements an interface member, a declaration with more than one documentation comment, a part of a partial element declared in several parts, and a summary in a file that an `<include>` element brings in are not covered.

Why: The rules that require a declaration to be documented are satisfied as soon as a `<summary>` is present. An empty summary added only to silence them leaves the tooltip and the generated documentation as empty as before, so this rule asks the summary to say something. A `<summary>` inside `<remarks>` or another element is not the element's summary.

Example:

```csharp
/// {|RH8030:<summary></summary>|}
public class Service
{
    /// {|RH8030:<summary>
    /// </summary>|}
    private int _count;

    /// <summary>
    /// Runs the service
    /// </summary>
    public void Run()
    {
    }

    /// {|RH8030:<summary/>|}
    ~Service()
    {
    }
}

/// <summary>
/// Status
/// </summary>
public enum Status
{
    /// {|RH8030:<summary></summary>|}
    Active,
}

/// <inheritdoc/>
/// {|RH8030:<summary></summary>|}
public class Derived : Service
{
}

/// <remarks>
/// <summary></summary>
/// </remarks>
public class Nested
{
}

/// <summary>
/// Money
/// </summary>
public readonly struct Money
{
    /// {|RH8030:<summary></summary>|}
    public static Money operator +(Money left, Money right) => left;
}
```

### RH8030-002 — The diagnostic is on the summary element

The analyzer MUST report one diagnostic per declaration, located on the whole `<summary>` element: the empty element `<summary/>`, or everything from the start tag through the end tag.

Why: The summary is what has to change, and a declaration of several fields or events still has a single summary.

Example: see RH8030-001.
