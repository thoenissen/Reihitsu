# Analyzer — RH2110 Nested unions should not be used

| | |
|---|---|
| ID prefix | RH2110 |
| Status | Active |
| Category | Design |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH2110NestedUnionsShouldNotBeUsedAnalyzer` |
| Uses | SHARED-NESTED-001, SHARED-NESTED-002 |

RH2110 reports a union declared inside another type.

## Non-goals

- Nested classes, structs, interfaces, records, enums, and delegates — RH2101, RH2104, RH2105, RH2106, RH2107, and RH2108.
- A type declared inside a union — the rule of that type's own kind, since a union body is a type body (SHARED-NESTED-001).

## Requirements

### RH2110-001 — A nested union is reported

The analyzer MUST report a union declaration that is nested as SHARED-NESTED-001 defines it, in the body of a class, struct, interface, record, record struct, or union, located as SHARED-NESTED-002 specifies. A union declared in a namespace or at file level MUST NOT be reported. A nested struct or record struct MUST NOT be reported by this rule, although the compiler emits a union as a struct.

Why: A union inside another type is harder to discover and to reuse, and it hides a declaration inside a type that is about something else. A union is declared with its own keyword, and every kind of declaration has its own nested-type rule, so a project can configure it on its own; nested structs and record structs are RH2104's and RH2106's.

Example:

```csharp
union Top(int, string)
{
    union {|RH2110:Inner|}(long, string);
}

class Outer
{
    union {|RH2110:Choice|}(int, string);

    public union {|RH2110:Result|}(int, string)
    {
        public int Get() => 1;
    }

    struct Entry
    {
    }
}

interface I
{
    union {|RH2110:Value|}(int, string);
}

namespace N
{
    union Free(int, string);
}
```

`Top` and `Free` are not nested. `Entry` is RH2104's and is not reported by this rule.
