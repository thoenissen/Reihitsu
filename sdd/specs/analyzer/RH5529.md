# Analyzer — RH5529 Generic parameter attributes must use merged attribute lists

| | |
|---|---|
| ID prefix | RH5529 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5529GenericParameterAttributeListsMustFollowShapeRulesAnalyzer`, `RH5529GenericParameterAttributeListsMustFollowShapeRulesCodeFixProvider` |
| Uses | SHARED-ATTR-002, SHARED-ATTR-003, SHARED-ATTR-015, SHARED-ATTR-016, SHARED-ATTR-018, SHARED-ATTR-020 |

RH5529 reports an attribute list of a type parameter that follows another list of the same type parameter naming the same target, and offers a code fix that merges those lists into the first. The rule uses `shared/attribute-targets.md`.

## Non-goals

- Attribute lists of parameters — RH5524.

## Requirements

### RH5529-001 — The lists of one type parameter and one target are merged

The analyzer MUST check every attribute list attached to a type parameter (SHARED-ATTR-003): the lists of a type parameter of a class, struct, interface, record, delegate, method, or local function, without a specifier, with `typevar:`, or with a specifier of SHARED-ATTR-002. It MUST report such a list that follows another list of the same type parameter naming the same target, as SHARED-ATTR-015 specifies.

Why: Attributes of a type parameter sit inside the angle brackets on the line of the declaration, so separate lists buy no vertical space; they only repeat the brackets and the `typevar:` specifier.

Example:

```csharp
class C<[A] {|RH5529:[B]|} T, [typevar: A] {|RH5529:[B]|} U, [A] [property: B] V, [A, B] W>
{
    void M<[A] {|RH5529:[B]|} T>()
    {
    }
}

delegate void D<[A] {|RH5529:[B]|} T>();
```

### RH5529-002 — The diagnostic is on the attribute list

The analyzer MUST report the diagnostic on the attribute list, as SHARED-ATTR-016 specifies.

Why: Each list after the first of a target is one that the fix removes; the first list is the one the others merge into.

Example: see RH5529-001.

### RH5529-003 — The fix merges the lists of the target into the first

The code fix MUST merge every list of the reported list's target on the type parameter into the first of them, as SHARED-ATTR-018 specifies.

Why: The fix makes only the change the diagnostic asks for, for all lists of the target at once, so one application leaves no list of that target behind.

Example:

```csharp
interface I<[A]
            {|RH5529:[B]|} out T>
{
}
```

```csharp
interface I<[A, B] out T>
{
}
```

### RH5529-004 — The fix is withheld for comments and directives around the lists

The code fix MUST NOT be offered when SHARED-ATTR-020 withholds it. The diagnostic is still reported.

Why: The merge rewrites the stretch from the first to the last list, where a comment would be dropped or moved and a directive would end up off its own line.

Example:

```csharp
class C<[typevar: A /* c */] {|RH5529:[typevar: B]|} T>
{
}
```

is reported, and no code fix is offered.
