# Analyzer — RH3206 Expression style conversion operators should not be used

| | |
|---|---|
| ID prefix | RH3206 |
| Status | Active |
| Category | Clarity |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH3206ExpressionStyleConversionOperatorsShouldNotBeUsedAnalyzer`, `RH3206ExpressionStyleConversionOperatorsShouldNotBeUsedCodeFixProvider` |
| Uses | SHARED-BODY-001, SHARED-BODY-002, SHARED-BODY-003, FMT-STRUCT-005 |

RH3206 reports an expression-bodied conversion operator and offers a code fix that converts it to a block body, as the formatter does under FMT-STRUCT-005. Which conversion operators are left alone, where the diagnostic is, and what the fix produces are SHARED-BODY-001, SHARED-BODY-002, and SHARED-BODY-003.

## Non-goals

- Other operators — RH3205.
- Expression-bodied methods (RH3202), constructors (RH3203), finalizers (RH3207), and local functions (RH3208).

## Requirements

### RH3206-001 — Every expression-bodied conversion operator is reported

The analyzer MUST report every conversion operator declaration that has an expression body — `implicit`, `explicit`, and `explicit checked` — unless SHARED-BODY-001 applies. A conversion operator with a block body MUST NOT be reported.

Why: The house style uses block bodies for conversion operators, as for methods; the other function kinds have rules of their own, so each kind can be configured separately.

Example:

```csharp
using System;

class C
{
    private int _value;

    public static implicit operator int(C c) {|RH3206:=> c._value|};

    public static explicit operator C(int v) {|RH3206:=> throw new NotSupportedException()|};

    public static explicit operator checked byte(C c) {|RH3206:=> checked((byte)c._value)|};

    public static explicit operator byte(C c)
    {
        return (byte)c._value;
    }
}
```
