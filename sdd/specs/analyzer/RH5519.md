# Analyzer — RH5519 Event attributes must be on their own line

| | |
|---|---|
| ID prefix | RH5519 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5519EventAttributesMustFollowPlacementRulesAnalyzer`, `RH5519EventAttributesMustFollowPlacementRulesCodeFixProvider` |
| Uses | SHARED-ATTR-001, SHARED-ATTR-002, SHARED-ATTR-004, SHARED-ATTR-005, SHARED-ATTR-006, SHARED-ATTR-007, SHARED-ATTR-008, SHARED-ATTR-009, SHARED-ATTR-011, SHARED-ATTR-012 |

RH5519 reports an attribute list of an event that shares its line with the token after it, and offers a code fix that moves that token onto the next line. The rule uses `shared/attribute-targets.md`.

## Non-goals

- Attributes of an event's `add` and `remove` accessors — RH5530.

## Requirements

### RH5519-001 — Event attribute lists are on their own line

The analyzer MUST check every attribute list that resolves to the event target (SHARED-ATTR-001, SHARED-ATTR-002): the lists of an event field or an event with accessors without a specifier, and every list with the `event:` specifier, and MUST report such a list whose closing bracket shares its line with the first token after it, as SHARED-ATTR-004, SHARED-ATTR-005, and SHARED-ATTR-006 specify for a list that must be on its own line.

Why: Events are read with the other members of a type, one declaration per line; an attribute in front of an event pushes it to the right of its neighbors.

Example:

```csharp
class C
{
    {|RH5519:[A]|} event System.Action E;

    {|RH5519:[A]|} event System.Action F
    {
        add
        {
        }
        remove
        {
        }
    }

    [A]
    event System.Action G;
}
```

### RH5519-002 — The diagnostic is on the attribute list

The analyzer MUST report the diagnostic on the attribute list, as SHARED-ATTR-007 specifies.

Why: The list is what is misplaced; each list of a declaration is reported and fixed on its own.

Example: see RH5519-001.

### RH5519-003 — The fix moves what follows onto the next line

The code fix MUST put the first token after the list on a new line, as SHARED-ATTR-008 and SHARED-ATTR-009 specify.

Why: The fix makes only the change the diagnostic asks for: the declaration starts on its own line, and the list stays where it is.

Example:

```csharp
class C
{
    {|RH5519:[A]|} event System.Action E;
}
```

```csharp
class C
{
    [A]
    event System.Action E;
}
```

### RH5519-004 — The fix is withheld for comments, directives, and missing braces

The code fix MUST NOT be offered when SHARED-ATTR-011 or SHARED-ATTR-012 withholds it. The diagnostic is still reported.

Why: A comment inside the list belongs to the attribute next to it, and an unclosed scope leaves no indentation to compute; both are left to the author.

Example:

```csharp
class C
{
    {|RH5519:[A /* c */]|} event System.Action E;
}
```

is reported, and no code fix is offered.
