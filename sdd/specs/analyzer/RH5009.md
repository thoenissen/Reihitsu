# Analyzer — RH5009 goto-Statement should be preceded by a blank line

| | |
|---|---|
| ID prefix | RH5009 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5009GotoStatementsShouldBePrecededByABlankLineAnalyzer`, `RH5009GotoStatementsShouldBePrecededByABlankLineCodeFixProvider` |
| Uses | SHARED-STMT-001, SHARED-STMT-002, SHARED-STMT-003, SHARED-STMT-004 |

RH5009 reports a `goto` statement that follows another statement of the same block or switch section without a blank line between them, and offers a code fix that inserts one as SHARED-STMT-004 specifies.

## Non-goals

- Blank lines before other statement kinds — the other rules that use `shared/statement-blank-lines.md`.

## Requirements

### RH5009-001 — A `goto` statement that follows a statement needs a blank line

The analyzer MUST report a `goto` statement as SHARED-STMT-001, SHARED-STMT-002, and SHARED-STMT-003 specify. This covers a `goto` to a label, `goto case`, and `goto default`. A `goto` that ends a switch section is reported like any other.

Why: A `goto` statement jumps unconditionally; the blank line draws attention to the change in control flow.

Example:

```csharp
class C
{
    void M(int a)
    {
        switch (a)
        {
            case 1:
                a++;
                {|RH5009:goto|} case 2;
            case 2:
                a++;
                {|RH5009:goto|} default;
            default:
                a++;
                {|RH5009:goto|} End;
        }

        End:
        a--;
    }
}
```

Each `goto` ends its switch section and is reported.

### RH5009-002 — The diagnostic is on the `goto` keyword

The analyzer MUST report the diagnostic on the `goto` keyword.

Why: The keyword is where the missing separator becomes visible, whichever target follows it.

Example: see RH5009-001.
