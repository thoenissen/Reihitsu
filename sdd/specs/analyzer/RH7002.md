# Analyzer — RH7002 File may only contain a single top-level type

| | |
|---|---|
| ID prefix | RH7002 |
| Status | Active |
| Category | Organization |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH7002FileMayOnlyContainASingleTopLevelTypeAnalyzer` |
| Uses | SHARED-DIAG-004 |

RH7002 reports every top-level type declaration of a file after the first one. It has no code fix.

## Non-goals

- How many namespaces a file declares — RH7001.
- Whether a type may be nested — RH2101 and RH2104 to RH2108.

## Requirements

### RH7002-001 — Every top-level type after the first is reported

The analyzer MUST report every class, struct, interface, enum, record, and record struct declaration, with or without the `partial` modifier, that is declared directly in the compilation unit or in a namespace — at any depth of nested namespaces — and follows another such declaration in the same file, unless it is a further part of a type declared earlier in the file (RH7002-004). The declarations of all namespaces of the file are counted together.

Why: A file named after one type should contain that type. Further top-level types are hard to find from the file name, and moving them to files of their own keeps every type at a predictable place.

Example:

```csharp
namespace N;

public class A
{
}

internal record {|RH7002:B|}(string Name);

internal struct {|RH7002:S|}
{
}

internal interface {|RH7002:I|}
{
}

internal enum {|RH7002:E|}
{
    One,
}
```

and a type after a `partial` declaration:

```csharp
partial class A
{
}

class {|RH7002:B|}
{
}
```

and the types of two namespaces of one file:

```csharp
namespace N1
{
    class A
    {
    }
}

namespace N2
{
    namespace Inner
    {
        class {|RH7002:B|}
        {
        }
    }
}
```

### RH7002-002 — Nested types and delegates are not counted

The analyzer MUST NOT count a type declared inside another type, and MUST NOT count a delegate declaration.

Why: A nested type is part of the type that declares it and lives in its file. A delegate is a one-line signature that usually belongs next to the type that uses it, so it does not compete with that type for the file.

Example:

```csharp
delegate void Handler();

class C
{
    private record Nested(string Name);

    private enum Kind
    {
        One,
    }
}
```

is not reported.

### RH7002-003 — The diagnostic is on the type name

The analyzer MUST report one diagnostic per reported type declaration, located on its identifier.

Why: The name is what tells the reader which type to move to its own file.

Example: see RH7002-001.

### RH7002-004 — Further parts of one partial type are not reported

The analyzer MUST NOT report a top-level declaration with the `partial` modifier when an earlier top-level declaration of the same file declares the same type: a type of the same name, with the same number of type parameters, in the same namespace. Both declarations are parts of one type (SHARED-DIAG-004).

A `partial` declaration of a type that no earlier declaration of the file declares is not such a part; when another top-level declaration comes before it, RH7002-001 reports it.

Why: The compiler builds one type from all its parts, so a file that holds two parts of one type still holds one type. The rule asks for one type per file, not for one declaration.

Example:

```csharp
partial class C
{
}

partial class C
{
}
```

is not reported.

Example — the same name in another namespace, and the same name with a type parameter, are other types, so their first parts are reported, and the further part of `C<T>` is not:

```csharp
namespace N1
{
    partial class C
    {
    }
}

namespace N2
{
    partial class {|RH7002:C|}
    {
    }

    partial class {|RH7002:C|}<T>
    {
    }

    partial class C<T>
    {
    }
}
```
