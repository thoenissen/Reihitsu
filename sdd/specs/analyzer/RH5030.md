# Analyzer — RH5030 Blank line after closing brace

| | |
|---|---|
| ID prefix | RH5030 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5030BlankLineAfterClosingBraceAnalyzer`, `RH5030BlankLineAfterClosingBraceCodeFixProvider` |
| Uses | SHARED-BLANK-003, SHARED-BLANK-004, FMT-BLANK-005 |

RH5030 reports a statement that ends with a closing brace and is followed by another statement of the same block or switch section without a blank line between them, and offers a code fix that inserts one in front of the following statement.

## Non-goals

- The blank line before a statement of a particular kind, such as `if` or `return` — the rules that use `shared/statement-blank-lines.md`.
- The blank line after a `break` statement — RH5011.

## Requirements

### RH5030-001 — A statement after a closing brace needs a blank line

The analyzer MUST report a statement whose last token is `}` and that is followed by another statement in the same block or switch section, as SHARED-BLANK-003 and SHARED-BLANK-004 specify.

Why: A closing brace ends a visual block; without a blank line the next statement reads as part of it.

Example:

```csharp
class C
{
    void M(int a)
    {
        if (a > 0)
        {
            a++;
        {|RH5030:}|}
        a++;
        if (a > 0)
        {
            a++;
        {|RH5030:}|} // note
        // next
        a++;
        if (a > 0)
        {
        {|RH5030:}|}
#pragma warning disable CS0168
        a++;
        if (a > 0) { } a++;
        switch (a)
        {
            case 1:
                {
                    a++;
                }
                break;
            case 2:
                {
                    a++;
                {|RH5030:}|}
                a++;
                break;
        }
    }
}
```

The pair on one line and the terminal `break` of `case 1:` are not reported.

### RH5030-002 — The diagnostic is on the closing brace

The analyzer MUST report the diagnostic on the closing brace that ends the statement.

Why: The brace is the end of the block that needs the separator behind it.

Example: see RH5030-001.

### RH5030-003 — The fix inserts the blank line directly before the next statement

The code fix MUST insert one line break, in the line ending the document already uses, at the start of the next statement's leading trivia, or directly after the last preprocessor directive in that trivia when there is one. A comment between the brace and the statement therefore stays directly above the statement, below the new blank line, and a directive stays directly below the brace.

Why: The comment describes the statement that follows it, so it stays with that statement. A blank line in front of a directive would land inside the region the directive opens or closes; behind the directive it separates the statement without moving the directive (FMT-BLANK-005 makes the same choice).

Example:

```csharp
class C
{
    void M(int a)
    {
        if (a > 0)
        {
            a++;
        {|RH5030:}|}
        a++;
        if (a > 0)
        {
            a++;
        {|RH5030:}|} // note
        // next
        a++;
        if (a > 0)
        {
        {|RH5030:}|}
#pragma warning disable CS0168
        a++;
    }
}
```

```csharp
class C
{
    void M(int a)
    {
        if (a > 0)
        {
            a++;
        }

        a++;
        if (a > 0)
        {
            a++;
        } // note

        // next
        a++;
        if (a > 0)
        {
        }
#pragma warning disable CS0168

        a++;
    }
}
```
