# Analyzer — RH8026 Non-private fields must be documented

| | |
|---|---|
| ID prefix | RH8026 |
| Status | Active |
| Category | Documentation |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH8026NonPrivateFieldsMustBeDocumentedAnalyzer` |
| Uses | SHARED-DOC-001, SHARED-DOC-002, SHARED-DOC-004, SHARED-DOC-005, SHARED-DOC-006, SHARED-DOC-007, SHARED-DOC-008 |

RH8026 reports a field declaration in the non-private group that has no `<summary>` or `<inheritdoc>` documentation.

## Non-goals

- Fields in the private group — RH8027.
- Field-like events — RH8028 and RH8029; enum members — RH8013 and RH8014.
- Whether the summary has text — RH8030.

## Requirements

### RH8026-001 — Undocumented non-private fields are reported

The analyzer MUST report every field declaration in the non-private group of SHARED-DOC-002 that is not documented, checked as SHARED-DOC-001 specifies. A field declaration is a declaration of one or more fields in the body of a class, struct, interface, record, or record struct — constant, static, and read-only fields included; a field-like event and an enum member are not ones. A declaration of several fields is one declaration, documented by the documentation comments before it. Whether it is documented MUST be decided as SHARED-DOC-004, SHARED-DOC-005, SHARED-DOC-006, and SHARED-DOC-007 specify, and nothing is reported when SHARED-DOC-008 applies.

Why: A field that other code can read or write is part of the contract that code builds on, and its type and name rarely say what is stored or when the value is valid. Without a summary, the generated documentation and the editor's tooltip show nothing. The compiler gives every field of one declaration the documentation written before that declaration.

Example:

```csharp
/// <summary>
/// Counters
/// </summary>
public class Counters
{
    public int {|RH8026:Current|};

    /// <remarks>
    /// No summary
    /// </remarks>
    internal static readonly int {|RH8026:Maximum|} = 10;

    public const int {|RH8026:Limit|} = 5;

    protected int {|RH8026:First|}, Second;

    /// <summary>
    /// The total count
    /// </summary>
    public int Total;

    private int _hidden;

    public event System.Action Changed;
}

/// <summary>
/// Contract
/// </summary>
public interface IContract
{
    static int {|RH8026:Shared|};
}
```

### RH8026-002 — The diagnostic is on the name of the first field

The analyzer MUST report one diagnostic per undocumented field declaration, located on the identifier of the first field it declares.

Why: The documentation comment covers the whole declaration, so one diagnostic is enough, and the first name identifies the declaration without marking its initializers.

Example: see RH8026-001.
