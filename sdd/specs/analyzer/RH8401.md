# Analyzer — RH8401 Single-line comments must not use documentation style slashes

| | |
|---|---|
| ID prefix | RH8401 |
| Status | Active |
| Category | Documentation |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH8401SingleLineCommentsMustNotUseDocumentationStyleSlashesAnalyzer`, `RH8401SingleLineCommentsMustNotUseDocumentationStyleSlashesCodeFixProvider` |
| Uses | SHARED-DOC-004, SHARED-DOC-008 |

RH8401 reports a `///` comment that holds plain text and no XML, and offers a code fix that turns it into a `//` comment.

## Non-goals

- `/** */` comments, and comments that start with four or more slashes.
- Whether a declaration is documented — RH8001 to RH8029.

## Requirements

### RH8401-001 — A `///` comment without XML is reported

The analyzer MUST report a `///` comment whose content holds no XML node other than text — no element, no empty element, no XML comment, no CDATA section, and no processing instruction — so that it holds only text, character references, and white space, or nothing at all. It MUST report such a comment wherever it stands: in front of a declaration, inside a method body, or behind code on its line.

This requirement covers a syntax tree whose documentation mode is `Parse` or `Diagnose`. The rule's subject is an ordinary comment, so SHARED-DOC-008 requires it to check syntax trees in every documentation mode; what it reports in mode `None` is not covered here.

Why: Three slashes mark XML documentation. A comment without any XML is an ordinary remark; written with `///`, it looks like documentation, editors and the compiler treat it as such, and the declaration it precedes looks documented when it is not.

Example:

```csharp
class C
{
    {|RH8401:///|} Temporary workaround
    {|RH8401:///|} for the old service
    int A;

    void M()
    {
        {|RH8401:///|} Call it again
        M();
        int b = 0; {|RH8401:///|} Behind code
    }

    {|RH8401:///|} Tom &amp; Jerry
    int D;

    {|RH8401:///|}
    int E;
}
```

### RH8401-002 — A `///` comment with XML is not reported

The analyzer MUST NOT report a `///` comment that holds at least one XML node other than text, such as an element, an empty element, or an XML comment, nor a `/** */` comment or a comment that starts with four or more slashes.

This requirement covers the `///` documentation comments of a declaration as SHARED-DOC-004 defines them. A `///` comment that is not a documentation comment of a declaration, such as one inside a method body, is not covered.

Why: A comment with XML is documentation, even when its form is imperfect; whether it is complete and well laid out is for the documentation rules to decide. Other comment forms do not use the documentation slashes.

Example:

```csharp
class C
{
    /// <summary>Runs</summary>
    void M()
    {
    }

    /// Stops <c>now</c>
    void N()
    {
    }

    /// <!-- Note -->
    int A;

    /** Plain text */
    int B;

    //// Four slashes
    int D;
}
```

is not reported.

### RH8401-003 — Each line of the comment is reported on its `///`

The analyzer MUST report one diagnostic per line of a reported comment, located on the three slashes of that line's `///`.

Why: Every line carries the documentation slashes that have to change, so each one is marked.

Example: see RH8401-001.

### RH8401-004 — The fix turns the whole comment into a `//` comment

The code fix MUST replace the `///` of every line of the reported comment with `//`, whichever line's diagnostic it is applied to, and keep everything else: the indentation, the text after the slashes, and a `///` further along a line, which belongs to the text. The line breaks between the lines stay as they are, whichever of the C# line terminators they are.

This requirement covers a comment each of whose lines has nothing but white space in front of its `///`.

Why: Converting every line at once never leaves a comment that is half `//` and half `///`, and only the slashes are wrong; the text is the author's.

Example:

```csharp
class C
{
    void M()
    {
        {|RH8401:///|} Temporary workaround
        {|RH8401:///|} see http://example.com///path
        M();
    }
}
```

```csharp
class C
{
    void M()
    {
        // Temporary workaround
        // see http://example.com///path
        M();
    }
}
```
