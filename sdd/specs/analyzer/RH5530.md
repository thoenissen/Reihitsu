# Analyzer — RH5530 Accessor attributes must follow placement rules

| | |
|---|---|
| ID prefix | RH5530 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5530AccessorAttributesMustFollowPlacementRulesAnalyzer`, `RH5530AccessorAttributesMustFollowPlacementRulesCodeFixProvider` |
| Uses | SHARED-ATTR-001, SHARED-ATTR-002, SHARED-ATTR-004, SHARED-ATTR-005, SHARED-ATTR-006, SHARED-ATTR-007, SHARED-ATTR-008, SHARED-ATTR-009, SHARED-ATTR-011, SHARED-ATTR-012 |

RH5530 reports an attribute list of a `get`, `set`, `init`, `add`, or `remove` accessor that shares its line with the accessor keyword, and offers a code fix that moves the keyword onto the next line. The rule uses `shared/attribute-targets.md`.

## Non-goals

- The `return:` attributes of an accessor — RH5527.
- Attributes of the property, indexer, or event that owns the accessor — RH5515 and RH5519.

## Requirements

### RH5530-001 — Accessor attribute lists are on their own line

The analyzer MUST check every attribute list attached to an accessor that resolves to the method target (SHARED-ATTR-001, SHARED-ATTR-002): the lists of a `get`, `set`, `init`, `add`, or `remove` accessor without a specifier, with `type:`, or with `method:`, and MUST report such a list whose closing bracket shares its line with the first token after it, as SHARED-ATTR-004, SHARED-ATTR-005, and SHARED-ATTR-006 specify for a list that must be on its own line.

Why: In a multi-line accessor list, the accessor keywords are the structure a reader looks for down the left edge; an attribute in front of one of them pushes that keyword to the right, so the accessor that carries metadata is the harder one to find.

Example:

```csharp
class C
{
    int P
    {
        {|RH5530:[A]|} get;
        {|RH5530:[method: A]|} init;
    }

    event System.Action E
    {
        {|RH5530:[A]|} add
        {
        }
        remove
        {
        }
    }

    int Q
    {
        [A]
        get;
        set;
    }

    int R { [A] get; set; }

    [B]
    int S { [A] get; set; }
}
```

### RH5530-002 — Method attributes of other declarations are not checked

The analyzer MUST NOT report an attribute list that resolves to the method target but is not attached to an accessor.

Why: Methods, operators, local functions, and lambdas have no accessor list around them; RH5513 checks their lists.

Example:

```csharp
class C
{
    [A] void M()
    {
    }
}
```

is not reported by RH5530; RH5513 reports it.

### RH5530-003 — The diagnostic is on the attribute list

The analyzer MUST report the diagnostic on the attribute list, as SHARED-ATTR-007 specifies.

Why: The list is what is misplaced; each list of a declaration is reported and fixed on its own.

Example: see RH5530-001.

### RH5530-004 — The fix moves what follows onto the next line

The code fix MUST put the first token after the list on a new line, as SHARED-ATTR-008 and SHARED-ATTR-009 specify.

Why: The fix makes only the change the diagnostic asks for: the declaration starts on its own line, and the list stays where it is.

Example:

```csharp
class C
{
    int P
    {
        {|RH5530:[A]|} get;
        set;
    }
}
```

```csharp
class C
{
    int P
    {
        [A]
        get;
        set;
    }
}
```

### RH5530-005 — The fix is withheld for comments, directives, and missing braces

The code fix MUST NOT be offered when SHARED-ATTR-011 or SHARED-ATTR-012 withholds it. The diagnostic is still reported.

Why: A comment inside the list belongs to the attribute next to it, and an unclosed scope leaves no indentation to compute; both are left to the author.

Example:

```csharp
class C
{
    int P
    {
        {|RH5530:[A /* c */]|} get;
        set;
    }
}
```

is reported, and no code fix is offered.
