# Analyzer — RH7102 Constants must appear before fields

| | |
|---|---|
| ID prefix | RH7102 |
| Status | Active |
| Category | Organization |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH7102ConstantsMustAppearBeforeFieldsAnalyzer`, `RH7102ConstantsMustAppearBeforeFieldsCodeFixProvider` |
| Uses | SHARED-ORDER-001, SHARED-ORDER-002, SHARED-ORDER-003, SHARED-ORDER-004, SHARED-ORDER-005, SHARED-ORDER-006, SHARED-TYPEREGION-006 |

RH7102 reports a `const` field that follows a non-constant field of the same accessibility, and offers a code fix that moves it in front of the first such field.

## Non-goals

- The order of static and instance fields — RH7103 — and of readonly and non-readonly fields — RH7109.
- The order of accessibility levels — RH7110.
- Ordering across the parts of a `partial` type and between a type and its nested types. Each type declaration is checked on its own.
- Members other than fields. Properties, event fields, and other members do not take part in the comparison.

## Requirements

### RH7102-001 — A constant after a field of the same accessibility is reported

The analyzer MUST report every `const` field declaration that contains no `#if`, `#elif`, `#else`, or `#endif` directive and follows, in the same class, struct, interface, record, or record struct declaration, a field declaration without `const` whose accessibility modifiers form the same group: `public`, `protected internal`, `private protected`, `internal`, `protected`, or `private`, with `protected internal` and `private protected` each one group regardless of modifier order. The analyzer compares the two fields when both lie outside every region, or both lie in the same top-level region (RH7102-003).

Why: A constant is a fixed value of the type, not part of its state. Listing the constants first keeps them apart from the fields a reader has to follow through the type's lifetime. Comparing only within one accessibility leaves the order of accessibility levels to RH7110.

Example:

```csharp
class C
{
    private int _value;
    private static readonly int _shared = 1;
    private const int {|RH7102:Max|} = 1;
    internal protected int Count;
    protected internal const int {|RH7102:Min|} = 0;
}
```

### RH7102-002 — Fields of another accessibility are not compared

The analyzer MUST NOT report a `const` field that follows only fields of other accessibility groups.

Why: Accessibility order is RH7110's decision; a private constant after a public field is in a different group, not misplaced inside it.

Example:

```csharp
class C
{
    public int Value;
    private const int Max = 1;
}
```

is not reported.

### RH7102-003 — Fields in one top-level region are compared

The analyzer MUST compare a `const` field with the earlier fields of its group that lie in the same top-level region of the type (SHARED-TYPEREGION-006), also when one of them lies in a region nested in it, as SHARED-ORDER-004 states.

Why: A region holds members the author keeps together, and inside it the fields are read in order as in a type without regions.

Example:

```csharp
class C
{
    #region Fields

    private int _value;

    #region Limits

    private const int {|RH7102:Max|} = 1;

    #endregion

    #endregion
}
```

The diagnostic has no code fix here (RH7102-006): the `#region Fields` line belongs to the leading trivia of `_value`, so it lies in the crossed span without its partner (SHARED-ORDER-004).

### RH7102-004 — The diagnostic is on the first name

The analyzer MUST report one diagnostic per misplaced `const` field declaration, located on the identifier of its first declarator.

Why: The order belongs to the declaration, and the fix moves the whole declaration at once.

Example:

```csharp
class C
{
    private int _value;
    private const int {|RH7102:Min|} = 0, Max = 1;
}
```

### RH7102-005 — The fix moves the constant in front of the first field of its group

The code fix MUST move the reported field declaration in front of the first earlier field declaration without `const` of the same accessibility group (RH7102-001), and MUST perform the move as specified in SHARED-ORDER-001 and SHARED-ORDER-002.

Why: The first such field is the earliest position at which the constant satisfies the rule, so one move corrects the diagnostic without moving any other member.

Example:

```csharp
class C
{
    private int _a;
    public int B;
    private int _c;
    private const int {|RH7102:D|} = 1;
}
```

```csharp
class C
{
    private const int D = 1;
    private int _a;
    public int B;
    private int _c;
}
```

The documentation comment travels with the constant, and the blank line stays where it was:

```csharp
class C
{
    private int _value;

    /// <summary>
    /// The largest value
    /// </summary>
    private const int {|RH7102:Max|} = 1;
}
```

```csharp
class C
{
    /// <summary>
    /// The largest value
    /// </summary>
    private const int Max = 1;

    private int _value;
}
```

### RH7102-006 — The fix is withheld when the move is unsafe

The code fix MUST NOT be offered when the move is refused by SHARED-ORDER-003, SHARED-ORDER-004, or SHARED-ORDER-005. When no `#if`, `#elif`, `#else`, or `#endif` directive takes part in the refusal, the diagnostic is still reported. A balanced directive pair alone does not withhold it (SHARED-ORDER-006).

Why: These moves would change which code a directive governs. A reported diagnostic without a fix is a supported end state; the user decides where the directive belongs.

Example:

```csharp
class C
{
    private int _value;
#pragma warning disable CS0414
    private int _unused = 1;
#pragma warning restore CS0414
    private const int {|RH7102:Max|} = 1;
}
```

is reported, and no code fix is offered.
