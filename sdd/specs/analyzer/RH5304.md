# Analyzer — RH5304 Nested collection initializer assignments should be formatted correctly

| | |
|---|---|
| ID prefix | RH5304 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5304NestedCollectionInitializerAssignmentsShouldBeFormattedCorrectlyAnalyzer`, `RH5304NestedCollectionInitializerAssignmentsShouldBeFormattedCorrectlyCodeFixProvider` |
| Uses | SHARED-INIT-001, SHARED-INIT-002, FMT-BREAK-021, FMT-INDENT-023, SHARED-COMMENT-011, FMT-PIPE-017 |

RH5304 reports a member assignment inside an object initializer whose value is a collection initializer (`Items = { … }`) when the target, the `=`, and the opening brace are not on one line, or when a wrapped collection initializer is not laid out as a block under its opening brace, and offers a code fix that lays it out the way the formatter does.

## Non-goals

- The braces and members of the object initializer itself — RH5301; collection initializers of an object creation — RH5303.
- A member whose value is not a collection initializer, such as an object creation or a nested object initializer (`Inner = { X = 1 }`).
- Whether the `=` and the value of an assignment are on the line of its target in general — RH5111.

## Requirements

### RH5304-001 — A split assignment is reported

The analyzer MUST report a member assignment of the object initializer of an object creation (`new T { … }` or `new() { … }`) whose value is a collection initializer when its `=` is not on the line its target starts on, or when the opening brace of the collection initializer is not on the line of the `=`.

Why: The collection initializer adds to the member it is assigned to, so target, `=`, and opening brace read as one unit; the formatter keeps the opening brace on the `=` line (FMT-BREAK-021).

Example:

```csharp
using System.Collections.Generic;

class C
{
    List<int> L { get; } = new List<int>();

    void M()
    {
        var a = new C
                {
                    {|RH5304:L
                        = { 1 }|}
                };
        var b = new C
                {
                    {|RH5304:L =
                    {
                        1
                    }|}
                };
    }
}
```

### RH5304-002 — A wrapped collection initializer that is not a block is reported

When target, `=`, and opening brace are on one line and the collection initializer spans several lines, the analyzer MUST report the assignment when:

- the closing brace does not start at the column of the opening brace;
- an element starts on the line of the opening brace, on the line of the closing brace, or on a line on which an earlier element starts;
- an element does not start four columns to the right of the opening brace; or
- an element is a complex element initializer that SHARED-INIT-002 treats as misaligned, with four columns to the right of the opening brace as its expected column.

The columns of the closing brace and of the elements follow SHARED-INIT-001. A wrapped collection initializer that meets all four conditions MUST NOT be reported. A line that starts with a comment is judged as SHARED-COMMENT-011 specifies.

Why: A wrapped collection initializer is a block that hangs from its opening brace on the `=` line: the brace is its anchor, so the closing brace aligns with it and the elements sit one level inside (FMT-INDENT-023).

Example:

```csharp
using System.Collections.Generic;

class C
{
    List<int> A { get; } = new List<int>();
    List<int> B { get; } = new List<int>();
    List<int> E { get; } = new List<int>();
    List<int> L { get; } = new List<int>();
    Dictionary<int, int> D { get; } = new Dictionary<int, int>();

    void M()
    {
        var a = new C
                {
                    {|RH5304:A = {
                            1
                      }|},
                    {|RH5304:B = {
                            1, 2
                        }|},
                    {|RH5304:E = {
                          1
                        }|},
                    {|RH5304:D = {
                            {
                                1,
                              2
                            }
                        }|},
                    L = {
                            1,
                            2
                        }
                };
    }
}
```

A comment that leads the line of a complex element's opening brace does not move the element's expressions and closing brace to the comment's column; they are measured from the brace (SHARED-INIT-002), so

```csharp
using System.Collections.Generic;

class C
{
    Dictionary<int, int> D { get; } = new Dictionary<int, int>();

    void M()
    {
        var a = new C
                {
                    D = {
                            /* e */ {
                                        1,
                                        2
                                    }
                        }
                };
    }
}
```

is not reported, while

```csharp
using System.Collections.Generic;

class C
{
    Dictionary<int, int> D { get; } = new Dictionary<int, int>();

    void M()
    {
        var a = new C
                {
                    {|RH5304:D = {
                            /* e */ {
                                1,
                                2
                            }
                        }|}
                };
    }
}
```

is reported.

### RH5304-003 — The diagnostic is on the assignment

The analyzer MUST report one diagnostic per assignment, located on the whole member assignment, however many of its parts are out of place.

Why: Target, `=`, and collection initializer are laid out together, so the diagnostic covers the construct the fix lays out.

Example: see RH5304-001 and RH5304-002.

### RH5304-004 — The fix lays out the assignment

The code fix MUST lay out the reported assignment as the formatter lays it out: the opening brace on the line of the `=` (FMT-BREAK-021), every element on its own line one level deeper than the opening brace, and the closing brace at the column of the opening brace (FMT-INDENT-023).

Why: The formatter owns the layout of nested collection initializers; delegating to it applies that layout instead of a second one.

Example:

```csharp
using System.Collections.Generic;

class C
{
    List<int> L { get; } = new List<int>();

    void M()
    {
        var a = new C
                {
                    {|RH5304:L =
                    {
                        1,
                        2
                    }|}
                };
    }
}
```

```csharp
using System.Collections.Generic;

class C
{
    List<int> L { get; } = new List<int>();

    void M()
    {
        var a = new C
                {
                    L = {
                            1,
                            2
                        }
                };
    }
}
```

Example — a complex element whose brace stands behind the last line of a multi-line comment is laid out from the brace, as everywhere else:

```csharp
using System.Collections.Generic;

class C
{
    Dictionary<int, int> D { get; } = new Dictionary<int, int>();

    void M()
    {
        var a = new C
                {
                    {|RH5304:D = {
                            /* a
                               b */ {
                                1,
                                2
                            }
                        }|}
                };
    }
}
```

```csharp
using System.Collections.Generic;

class C
{
    Dictionary<int, int> D { get; } = new Dictionary<int, int>();

    void M()
    {
        var a = new C
                {
                    D = {
                            /* a
                               b */ {
                                        1,
                                        2
                                    }
                        }
                };
    }
}
```

### RH5304-005 — The fix is withheld for a complex element behind the last line of a multi-line comment

Status: Retired — the node-level entry points now lay out every line of the code they format from that code's own column, with no move after the formatting (FMT-PIPE-017), so the line behind a multi-line comment's last line is no longer left behind; the fix is offered for such a complex element and lays it out as RH5304-004 states.
