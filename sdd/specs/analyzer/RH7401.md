# Analyzer — RH7401 Override methods should be grouped by base type regions

| | |
|---|---|
| ID prefix | RH7401 |
| Status | Active |
| Category | Organization |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH7401OverrideMethodsShouldBeGroupedByBaseTypeRegionsAnalyzer` |
| Uses | SHARED-DIAG-004, SHARED-DIAG-012, SHARED-REGGROUP-001, SHARED-REGGROUP-002, SHARED-REGGROUP-003, SHARED-REGGROUP-005, SHARED-TYPEREGION-006 |

RH7401 reports an override method that does not lie in a top-level region named after the type that introduced the method. It has no code fix.

## Non-goals

- Override properties, events, and indexers — RH7402, RH7403, RH7404.
- A method that overrides nothing but lies in a region named after a base type — RH7405.
- An interface implementation that is not an override — RH7409.

## Requirements

### RH7401-001 — An override method outside its base type's region is reported

In every type declaration it checks (SHARED-REGGROUP-001), the analyzer MUST report each method declaration that overrides a method and lies in no region nested in a top-level region (SHARED-TYPEREGION-006), when the method does not lie in a top-level region whose name matches (SHARED-REGGROUP-002) the type it comes from (SHARED-REGGROUP-003) — whether it lies in a region of another name or in no region. This holds also for an override that implements an interface method. The diagnostic MUST be placed as SHARED-REGGROUP-005 specifies.

A `partial` method is one method (SHARED-DIAG-004): it is reported at most once, on the part SHARED-DIAG-012 selects. This requirement covers a `partial` method only when each of its parts, judged on its own, would be reported; whether a `partial` method is reported when only some of its parts would be is not covered.

Why: Overrides are easier to scan when they are grouped by the type that introduced them; a generic region name such as `Methods` hides that relationship, and a region inside the method's body groups statements, not the method. An override that also implements an interface method is still an override of its base type, so it is grouped there.

Example:

```csharp
interface IRunnable
{
    void Run();
}

abstract class B
{
    public abstract void Run();

    public virtual void Stop()
    {
    }

    public virtual void Wait()
    {
    }
}

class C : B, IRunnable
{
    #region IRunnable

    public override void {|RH7401:Run|}()
    {
    }

    #endregion

    #region Methods

    public override void {|RH7401:Stop|}()
    {
    }

    #endregion

    public override void {|RH7401:Wait|}()
    {
        #region B
        System.Console.WriteLine();
        #endregion
    }
}
```

while an override in the region named after its base type:

```csharp
class B
{
    public virtual void M()
    {
    }
}

class C : B
{
    #region B

    public override void M()
    {
    }

    #endregion
}
```

is not reported.

Example — a `partial` method whose parts both lie outside a matching region is reported once, on its defining part:

```csharp
abstract class B
{
    public abstract void M();
}

partial class C : B
{
    #region Methods

    public override partial void {|RH7401:M|}();

    #endregion

    #region Other

    public override partial void M()
    {
    }

    #endregion
}
```

### RH7401-002 — Other members are not reported

The analyzer MUST NOT report a method that overrides nothing, and MUST NOT report an override property, indexer, or event.

Why: A method that overrides nothing has no base type to be grouped by, and the other override kinds have rules of their own.

Example:

```csharp
class B
{
    public virtual int P => 0;
}

class C : B
{
    public override int P => 1;

    public void M()
    {
    }
}
```

is not reported.
