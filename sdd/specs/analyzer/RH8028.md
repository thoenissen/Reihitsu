# Analyzer — RH8028 Non-private events must be documented

| | |
|---|---|
| ID prefix | RH8028 |
| Status | Active |
| Category | Documentation |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH8028NonPrivateEventsMustBeDocumentedAnalyzer` |
| Uses | SHARED-DOC-001, SHARED-DOC-002, SHARED-DOC-004, SHARED-DOC-005, SHARED-DOC-006, SHARED-DOC-007, SHARED-DOC-008, SHARED-DOC-009 |

RH8028 reports an event declaration in the non-private group that has no `<summary>` or `<inheritdoc>` documentation.

## Non-goals

- Events in the private group — RH8029.
- Fields and delegates — RH8026, RH8027, RH8015, and RH8016.
- Whether the summary has text — RH8030.

## Requirements

### RH8028-001 — Undocumented non-private events are reported

The analyzer MUST report every event declaration in the non-private group of SHARED-DOC-002 that is not documented, checked as SHARED-DOC-001 specifies, except an explicit interface implementation, which SHARED-DOC-009 exempts. An event declaration is a field-like event (`event Action Changed;`) or an event with `add` and `remove` accessors, declared in the body of a class, struct, interface, record, or record struct. A field-like declaration of several events is one declaration, documented by the documentation comments before it. Whether it is documented MUST be decided as SHARED-DOC-004, SHARED-DOC-005, SHARED-DOC-006, and SHARED-DOC-007 specify, and nothing is reported when SHARED-DOC-008 applies.

Why: An event that other code can subscribe to is part of the contract that code builds on, and its name and delegate type say nothing about when it is raised. Without a summary, the generated documentation and the editor's tooltip show nothing.

Example:

```csharp
using System;

/// <summary>
/// Publisher
/// </summary>
public class Publisher
{
    public event Action {|RH8028:Changed|};

    /// <remarks>
    /// No summary
    /// </remarks>
    internal event Action {|RH8028:Closed|}
    {
        add
        {
        }
        remove
        {
        }
    }

    protected event Action {|RH8028:Opened|}, Moved;

    /// <summary>
    /// Raised after saving
    /// </summary>
    public event Action Saved;

    private event Action Hidden;
}

/// <summary>
/// Contract
/// </summary>
public interface IContract
{
    event Action {|RH8028:Raised|};
}
```

### RH8028-002 — The diagnostic is on the event name

The analyzer MUST report one diagnostic per undocumented event declaration, located on the identifier of the event, or on the identifier of the first event a field-like declaration declares.

Why: The documentation comment covers the whole declaration, so one diagnostic is enough, and the name identifies the declaration without marking its accessors.

Example: see RH8028-001.
