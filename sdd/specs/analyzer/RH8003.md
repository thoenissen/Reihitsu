# Analyzer — RH8003 Non-private structs must be documented

| | |
|---|---|
| ID prefix | RH8003 |
| Status | Active |
| Category | Documentation |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH8003NonPrivateStructsMustBeDocumentedAnalyzer` |
| Uses | SHARED-DOC-001, SHARED-DOC-002, SHARED-DOC-004, SHARED-DOC-005, SHARED-DOC-006, SHARED-DOC-007, SHARED-DOC-008 |

RH8003 reports a struct in the non-private group that has no `<summary>` or `<inheritdoc>` documentation.

## Non-goals

- Structs in the private group — RH8004.
- Record structs — RH8009.
- Whether the summary has text — RH8030; the documentation of type parameters and primary constructor parameters — RH8108 and RH8101.

## Requirements

### RH8003-001 — Undocumented non-private structs are reported

The analyzer MUST report every struct declaration in the non-private group of SHARED-DOC-002 that is not documented, checked as SHARED-DOC-001 specifies. A struct declaration is one written with the `struct` keyword, including `readonly`, `ref`, and generic structs; a `record struct` declaration is not one. Whether it is documented MUST be decided as SHARED-DOC-004, SHARED-DOC-005, SHARED-DOC-006, and SHARED-DOC-007 specify, and nothing is reported when SHARED-DOC-008 applies.

Why: A struct that other code can use is part of the contract that code builds on. Without a summary, the generated documentation and the editor's tooltip show nothing, and readers have to infer what the struct is for from its implementation.

Example:

```csharp
public struct {|RH8003:Point|}
{
}

/// <remarks>
/// No summary
/// </remarks>
internal readonly struct {|RH8003:Size|}
{
}

public ref struct {|RH8003:Buffer|}<T>
{
}

/// <summary>
/// Documented
/// </summary>
public struct Documented
{
    private struct Hidden
    {
    }
}

public record struct Entry;
```

### RH8003-002 — The diagnostic is on the struct name

The analyzer MUST report one diagnostic per undocumented struct declaration, located on its identifier, without its type parameter list.

Why: The name is what the documentation describes; marking it identifies the declaration without marking its whole body.

Example: see RH8003-001.
