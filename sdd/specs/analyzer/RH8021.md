# Analyzer — RH8021 Private methods must be documented

| | |
|---|---|
| ID prefix | RH8021 |
| Status | Active |
| Category | Documentation |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH8021PrivateMethodsMustBeDocumentedAnalyzer` |
| Uses | SHARED-DOC-001, SHARED-DOC-002, SHARED-DOC-004, SHARED-DOC-005, SHARED-DOC-006, SHARED-DOC-007, SHARED-DOC-008, SHARED-DOC-009 |

RH8021 reports a method in the private group that has no `<summary>` or `<inheritdoc>` documentation.

## Non-goals

- Methods in the non-private group — RH8020.
- Operators and conversion operators — RH8034; constructors and destructors — RH8017 to RH8019.
- Whether the summary has text — RH8030; the documentation of parameters, type parameters, and return values — RH8101, RH8105, and RH8108.

## Requirements

### RH8021-001 — Undocumented private methods are reported

The analyzer MUST report every method declaration in the private group of SHARED-DOC-002 that is not documented, checked as SHARED-DOC-001 specifies, except an explicit interface implementation, which SHARED-DOC-009 exempts although it has no access modifier. A method declaration is a method declared in the body of a class, struct, interface, record, record struct, or extension block; a local function is not one. Whether it is documented MUST be decided as SHARED-DOC-004, SHARED-DOC-005, SHARED-DOC-006, and SHARED-DOC-007 specify, and nothing is reported when SHARED-DOC-008 applies.

Why: A private method can only be called from inside its type, so nothing outside the type explains what it is for. The summary records why it exists, and the editor shows it at every call site, so the next maintainer does not have to reconstruct the intent from the body. It has a rule of its own, so a project can require documentation for what other code uses without requiring it here.

Example:

```csharp
using System;

/// <summary>
/// Service
/// </summary>
public class Service : IDisposable
{
    private void {|RH8021:Run|}()
    {
    }

    /// <remarks>
    /// No summary
    /// </remarks>
    static int {|RH8021:Compute|}() => 0;

    /// <summary>
    /// Stops the service
    /// </summary>
    private void Stop()
    {
        void Local()
        {
        }

        Local();
    }

    private protected void Shared()
    {
    }

    void IDisposable.Dispose()
    {
    }
}

/// <summary>
/// Contract
/// </summary>
public interface IContract
{
    private void {|RH8021:Helper|}()
    {
    }

    void Execute();
}
```

### RH8021-002 — The diagnostic is on the method name

The analyzer MUST report one diagnostic per undocumented method declaration, located on its identifier, without its type parameter list.

Why: The name is what the documentation describes; marking it identifies the declaration without marking its whole body.

Example: see RH8021-001.
