# Analyzer — RH7305A Types with multiple member kinds should be organized with regions

| | |
|---|---|
| ID prefix | RH7305A |
| Status | Active |
| Category | Organization |
| Severity | Warning |
| Enabled by default | No |
| Code fix | None |
| Code owners | `RH7305ATypesShouldBeOrganizedWithRegionsForMultipleKindsAnalyzer` |
| Uses | SHARED-TYPEREGION-001, SHARED-TYPEREGION-002, SHARED-TYPEREGION-003, SHARED-TYPEREGION-004 |

RH7305A reports a top-level type that declares members of more than one kind but is not organized with regions. It is the alternative to RH7305 for users who want single-purpose types left alone, is off by default, and has no code fix.

## Non-goals

- Types whose members are all of one kind — RH7305 reports them.
- Which types are checked, which members count, and when a member is inside a region — SHARED-TYPEREGION-001 to SHARED-TYPEREGION-003.

## Requirements

### RH7305A-001 — A type mixing member kinds outside regions is reported

The analyzer MUST report every type declaration it checks (SHARED-TYPEREGION-001) whose counted members (SHARED-TYPEREGION-002) are of at least two kinds and which is not organized with regions (SHARED-TYPEREGION-003). The kinds are: nested types and delegates together; fields; constructors; finalizers; properties; indexers; events in both forms together; methods; and operators and conversion operators together. The diagnostic MUST be placed as SHARED-TYPEREGION-004 specifies.

Why: A type that mixes fields, constructors, properties, and methods is read by jumping between those groups, and without regions there is nothing to jump to. The kinds are the groups a reader looks for, so two declarations of the same group — an event field and an event with accessors — do not make a mix.

Example:

```csharp
class {|RH7305A:C|}
{
    private int _a;

    public void M()
    {
    }
}
```

and a nested type counts as a kind of its own:

```csharp
class {|RH7305A:C|}
{
    #region Methods

    void M()
    {
    }

    #endregion

    class D
    {
    }
}
```

### RH7305A-002 — A type with one member kind is not reported

The analyzer MUST NOT report a type declaration whose counted members are all of one kind (RH7305A-001), however many members it has and whether or not any of them is inside a region.

Why: A type with only one kind of member already reads as one group; regions would add ceremony without adding orientation, which is the reason to choose this rule over RH7305.

Example — an event field and an event with accessors are one kind:

```csharp
class C
{
    public event System.EventHandler A;

    public event System.EventHandler B
    {
        add { }
        remove { }
    }
}
```

is not reported, and neither is a type of operators and conversion operators:

```csharp
class C
{
    public static C operator +(C left, C right) => left;

    public static implicit operator int(C value) => 0;
}
```

while a type that adds one member of another kind is reported:

```csharp
class {|RH7305A:C|}
{
    public event System.EventHandler A;

    public static C operator +(C left, C right) => left;
}
```

### RH7305A-003 — An organized type is not reported

The analyzer MUST NOT report a type declaration in which every counted member lies inside a region (SHARED-TYPEREGION-003), whatever kinds of member it declares.

Why: Such a type already has the outline the rule asks for.

Example:

```csharp
class C
{
    #region Fields

    private int _a;

    #endregion // Fields

    #region Methods

    public void M()
    {
    }

    #endregion // Methods
}
```

is not reported.
