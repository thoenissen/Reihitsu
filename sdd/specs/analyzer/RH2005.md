# Analyzer — RH2005 Fields must be private

| | |
|---|---|
| ID prefix | RH2005 |
| Status | Active |
| Category | Design |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH2005FieldsMustBePrivateAnalyzer`, `RH2005FieldsMustBePrivateCodeFixProvider`, `DeclarationModifierUtilities` |
| Uses | — |

RH2005 reports a `public` field of a class or record class that can be reassigned, and offers a code fix that makes it `private`.

## Non-goals

- Fields with any accessibility other than `public` — `protected`, `internal`, `protected internal`, `private protected`, and implicit private fields are not reported.
- Fields of structs, record structs, and interfaces.
- The name of the field after the fix — RH4106 reports it once the field is private.
- Replacing the field with a property. The user documentation recommends it where the value belongs to the public surface; the fix does not do it.
- Fields whose `public` modifier is not the first modifier (`static public int X;`). The fix currently loses the declaration's indentation there; whether that is a defect is an open question.
- References to the field from outside the type. The fix is currently offered even when such references exist and stop compiling once the field is private; whether it should be withheld then is an open question.

## Requirements

### RH2005-001 — Writable public fields of reference types are reported

The analyzer MUST report a field declaration that carries the `public` modifier and is declared directly in a class or a record class, including nested classes. `const` fields and fields that are both `static` and `readonly` MUST NOT be reported. Instance `readonly`, `static`, and `volatile` fields are reported.

Why: A public field hands every caller a slot of the object's state; it cannot be validated or reimplemented later without breaking callers. A constant or a static readonly field cannot be reassigned, so exposing it hands out no writable slot; an instance readonly field is still part of the object's layout and is reported.

Example:

```csharp
public class C
{
    public string {|RH2005:publicField|};

    protected int protectedField;

    internal bool internalField;

    protected internal int protectedInternalField;

    private protected int privateProtectedField;

    private string privateField;

    string implicitPrivateField;

    public static readonly string Shared = string.Empty;

    public const int Constant = 1;
}

public struct S
{
    public int PublicField;
}

public record R
{
    public int {|RH2005:recordField|};
}

public record struct RS
{
    public int PublicField;
}
```

### RH2005-002 — One diagnostic per declaration, on the first name

The analyzer MUST report one diagnostic per field declaration, located on the identifier of its first declarator.

Why: The accessibility belongs to the declaration, not to a single declarator; the fix changes it for all of them at once.

Example:

```csharp
public class C
{
    public readonly int {|RH2005:A|}, B;
    public volatile int {|RH2005:Flag|};
}
```

```csharp
public class C
{
    private readonly int A, B;
    private volatile int Flag;
}
```

### RH2005-003 — The fix replaces `public` with `private`

The code fix MUST remove the declaration's accessibility modifiers and put `private` first in the modifier list, keeping the other modifiers in their order and keeping the declaration's attributes, documentation comment, and name.

Why: The fix makes exactly the change the diagnostic asks for. The name stays, so references inside the type keep working; renaming to `_camelCase` is RH4106's separate step.

Example:

```csharp
public class C
{
    /// <summary>Doc</summary>
    [System.Obsolete]
    public static int {|RH2005:Counter|};
}
```

```csharp
public class C
{
    /// <summary>Doc</summary>
    [System.Obsolete]
    private static int Counter;
}
```

### RH2005-004 — Fix All changes every declaration in one pass

Status: Retired — `shared/code-fixes.md` specifies Fix All for every rule whose header says `Fix All`.

The code fix MUST provide a batch Fix All. The fixes of one document never overlap, because each replaces the modifiers of its own declaration.

Why: Every diagnostic owns a different declaration, so applying all fixes together gives the same result as applying them one by one.

Example:

```csharp
public class C
{
    public string {|RH2005:first|};

    public int {|RH2005:second|};
}
```

```csharp
public class C
{
    private string first;

    private int second;
}
```
