# Analyzer — RH5509 Enum attributes must be on their own line

| | |
|---|---|
| ID prefix | RH5509 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5509EnumAttributesMustFollowPlacementRulesAnalyzer`, `RH5509EnumAttributesMustFollowPlacementRulesCodeFixProvider` |
| Uses | SHARED-ATTR-001, SHARED-ATTR-004, SHARED-ATTR-005, SHARED-ATTR-007, SHARED-ATTR-008, SHARED-ATTR-009, SHARED-ATTR-011, SHARED-ATTR-012 |

RH5509 reports an attribute list of an enum that shares its line with the token after it, and offers a code fix that moves that token onto the next line. The rule uses `shared/attribute-targets.md`.

## Non-goals

- Attributes of enum members — RH5517.

## Requirements

### RH5509-001 — Enum attribute lists are on their own line

The analyzer MUST check every attribute list that resolves to the enum target: the lists of an `enum` declaration without a specifier or with `type:` (SHARED-ATTR-001), and MUST report such a list whose closing bracket shares its line with the first token after it, as SHARED-ATTR-004 and SHARED-ATTR-005 specify for a list that must be on its own line.

Why: A reader scanning a file for its types looks down a column of modifiers and type names; an attribute in front of the declaration pushes that line to the right by however long the attribute is.

Example:

```csharp
{|RH5509:[A]|} enum E
{
    V
}

[A]
enum F
{
    V
}
```

### RH5509-002 — The diagnostic is on the attribute list

The analyzer MUST report the diagnostic on the attribute list, as SHARED-ATTR-007 specifies.

Why: The list is what is misplaced; each list of a declaration is reported and fixed on its own.

Example: see RH5509-001.

### RH5509-003 — The fix moves what follows onto the next line

The code fix MUST put the first token after the list on a new line, as SHARED-ATTR-008 and SHARED-ATTR-009 specify.

Why: The fix makes only the change the diagnostic asks for: the declaration starts on its own line, and the list stays where it is.

Example:

```csharp
{|RH5509:[A]|} enum E
{
    V
}
```

```csharp
[A]
enum E
{
    V
}
```

### RH5509-004 — The fix is withheld for comments, directives, and missing braces

The code fix MUST NOT be offered when SHARED-ATTR-011 or SHARED-ATTR-012 withholds it. The diagnostic is still reported.

Why: A comment inside the list belongs to the attribute next to it, and an unclosed scope leaves no indentation to compute; both are left to the author.

Example:

```csharp
{|RH5509:[A /* c */]|} enum E
{
    V
}
```

is reported, and no code fix is offered.
