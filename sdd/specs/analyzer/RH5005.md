# Analyzer — RH5005 using-Statement should be preceded by a blank line

| | |
|---|---|
| ID prefix | RH5005 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5005UsingStatementsShouldBePrecededByABlankLineAnalyzer`, `RH5005UsingStatementsShouldBePrecededByABlankLineCodeFixProvider` |
| Uses | SHARED-STMT-001, SHARED-STMT-002, SHARED-STMT-003, SHARED-STMT-004 |

RH5005 reports a `using` statement that follows another statement of the same block or switch section without a blank line between them, and offers a code fix that inserts one as SHARED-STMT-004 specifies.

## Non-goals

- Blank lines before other statement kinds — the other rules that use `shared/statement-blank-lines.md`.

## Requirements

### RH5005-001 — A `using` statement that follows a statement needs a blank line

The analyzer MUST report a `using` statement as SHARED-STMT-001, SHARED-STMT-002, and SHARED-STMT-003 specify. It MUST NOT report a `using` declaration (`using var x = …;`), which is a local declaration, not a `using` statement.

Why: A `using` statement opens a scope that owns a resource; the blank line marks where that scope begins. A `using` declaration has no scope of its own and is grouped with the other local declarations.

Example:

```csharp
class C
{
    void M(System.IDisposable resource)
    {
        var a = 1;
        {|RH5005:using|} (resource)
        {
            a++;
        }

        a++;
        using var other = resource;
    }
}
```

`using var other = resource;` is a `using` declaration and is not reported.

### RH5005-002 — The diagnostic is on the `using` keyword

The analyzer MUST report the diagnostic on the `using` keyword.

Why: The keyword is where the missing separator becomes visible, and the location stays stable when the resource expression changes.

Example: see RH5005-001.
