# Analyzer — RH2003 NotImplementedException should not be used

| | |
|---|---|
| ID prefix | RH2003 |
| Status | Active |
| Category | Design |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH2003NotImplementedExceptionShouldNotBeUsedAnalyzer` |
| Uses | — |

RH2003 reports every creation of `System.NotImplementedException`.

## Non-goals

- A mention of the type that creates no instance: a `catch` clause, `typeof`, a declaration, or a `throw` of an existing instance.
- An instance created through reflection, such as `Activator.CreateInstance<NotImplementedException>()`.
- A code fix. Only the author can write the missing implementation, or choose the exception that says the operation is not supported.

## Requirements

### RH2003-001 — An explicit creation is reported

The analyzer MUST report an object creation expression whose created type is `System.NotImplementedException`, with or without arguments, with or without an object initializer, and however its type name is written: qualified or not, and through a `using` alias of the type or of its namespace (SHARED-DIAG-002).

Why: `NotImplementedException` is a placeholder for code that was never written. Shipped, it fails at run time on a path the author meant to finish. An intentionally unsupported operation is better expressed with `NotSupportedException`.

Example:

```csharp
using System;

class C
{
    void A() => throw new {|RH2003:NotImplementedException|}();

    void B() => throw new {|RH2003:NotImplementedException|}("Later");

    void D() => throw new {|RH2003:global::System.NotImplementedException|}();

    Exception E() => new {|RH2003:NotImplementedException|} { Source = "C" };

    int P
    {
        get
        {
            throw new {|RH2003:NotImplementedException|}();
        }
    }
}
```

Example — through a `using` alias:

```csharp
using NIE = System.NotImplementedException;
using S = System;

class C
{
    void A() => throw new {|RH2003:NIE|}();

    void B() => throw new {|RH2003:S.NotImplementedException|}();

    void D() => throw new {|RH2003:S::NotImplementedException|}();
}
```

### RH2003-002 — A target-typed creation is reported

The analyzer MUST report a target-typed `new()` expression whose created type is `System.NotImplementedException`.

Why: The created type is the same; only its name is left to the target.

Example:

```csharp
using System;

class C
{
    NotImplementedException _exception = {|RH2003:new|}();
}
```

### RH2003-003 — Other exception types are not reported

The analyzer MUST NOT report the creation of any other type, including a type derived from `System.NotImplementedException`, a type named `NotImplementedException` in another namespace, and another type written through a `using` alias named `NotImplementedException`.

Why: The rule is about the framework's placeholder exception. A derived or a user-defined type is the author's own exception with its own meaning.

Example:

```csharp
using System;

class MyException : NotImplementedException
{
}

class C
{
    void A() => throw new NotSupportedException();

    void B() => throw new MyException();

    InvalidOperationException _exception = new();
}

namespace Other
{
    class NotImplementedException : System.Exception
    {
    }

    class D
    {
        void M() => throw new NotImplementedException();
    }
}
```

is not reported, and neither is

```csharp
using NotImplementedException = System.NotSupportedException;

class C
{
    void M() => throw new NotImplementedException();
}
```

### RH2003-004 — The diagnostic is on the created type, or on `new`

The analyzer MUST report one diagnostic per creation, located on the type of an explicit creation, qualification included, and on the `new` keyword of a target-typed creation.

Why: The type is what the user replaces; a target-typed creation has no type of its own, so its `new` stands for it.

Example: see RH2003-001 and RH2003-002.
