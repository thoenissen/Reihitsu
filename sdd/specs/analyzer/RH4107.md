# Analyzer — RH4107 Protected field casing

| | |
|---|---|
| ID prefix | RH4107 |
| Status | Active |
| Category | Naming |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH4107ProtectedFieldCasingAnalyzer`, `RH4107ProtectedFieldCasingCodeFixProvider` |
| Uses | SHARED-CASING-003, SHARED-CASING-004, SHARED-CASING-006, SHARED-CASING-007, SHARED-CASING-008, SHARED-CASING-009, SHARED-CASING-010 |

RH4107 reports a protected field whose name is not in `_camelCase` and offers a code fix that renames the field and every reference to it.

## Non-goals

- `const` fields of any accessibility — RH4110.
- Fields of the private, internal, and public groups — RH4106, RH4108, and RH4109.
- Whether a field should be protected at all — RH2005.

## Requirements

### RH4107-001 — Protected field names are in `_camelCase`

The analyzer MUST report every variable declarator of a field declaration that is not `const`, belongs to the protected group of SHARED-CASING-004, and whose name is not in `_camelCase` as SHARED-CASING-003 defines it. Static and readonly fields MUST be checked too. The analyzer MUST report one diagnostic per declarator, located on its identifier.

Why: A protected field is state of the object that only derived types see. It is named like a private field, so that a derived type's code tells it apart from locals and parameters in the same way.

Example:

```csharp
public class C
{
    protected int _cacheCount;
    protected int {|RH4107:CacheCount|}, {|RH4107:retryOffset|};
    private protected int {|RH4107:CacheLimit|};
    protected static readonly int {|RH4107:MaxSize|} = 1;
    protected internal int RetryLimit;
    protected const int Limit = 2;
    int cacheValue;
}
```

### RH4107-002 — The fix renames the field to `_camelCase`

The code fix MUST rename the field and every reference to it (SHARED-CASING-007) to the `_camelCase` name that SHARED-CASING-006 derives from its old name. It is withheld as SHARED-CASING-008 and SHARED-CASING-009 specify, and its Fix All skips colliding names as SHARED-CASING-010 specifies. This requirement covers the renames that SHARED-CASING-007 covers.

Why: The fix makes exactly the change the diagnostic asks for, and a field is referenced throughout its type and the types derived from it.

Example:

```csharp
public class BaseService
{
    protected int {|RH4107:CacheCount|}, {|RH4107:RetryOffset|};

    public int Sum => CacheCount + RetryOffset;
}
```

```csharp
public class BaseService
{
    protected int _cacheCount, _retryOffset;

    public int Sum => _cacheCount + _retryOffset;
}
```
