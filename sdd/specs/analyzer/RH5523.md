# Analyzer — RH5523 Parameter attributes must stay inline

| | |
|---|---|
| ID prefix | RH5523 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5523ParameterAttributesMustFollowPlacementRulesAnalyzer`, `RH5523ParameterAttributesMustFollowPlacementRulesCodeFixProvider` |
| Uses | SHARED-ATTR-001, SHARED-ATTR-002, SHARED-ATTR-003, SHARED-ATTR-004, SHARED-ATTR-005, SHARED-ATTR-007, SHARED-ATTR-010, SHARED-ATTR-011 |

RH5523 reports an attribute list of a parameter whose closing bracket is not on the line of the token after it, and offers a code fix that joins that token onto the list's line. The rule uses `shared/attribute-targets.md`.

## Non-goals

- Attribute lists that resolve to the type-parameter target — no placement rule checks them.
- How many attributes the lists of one parameter hold — RH5524.
- Whether the parameters of a list are on one line or one per line — RH5109.

## Requirements

### RH5523-001 — Parameter attribute lists stay on the parameter's line

The analyzer MUST check every attribute list that resolves to the parameter target (SHARED-ATTR-001, SHARED-ATTR-003): the lists of a parameter of a method, constructor, primary constructor, positional record, local function, lambda, delegate, operator, or indexer, without a specifier, with `param:`, or with a specifier of SHARED-ATTR-002. It MUST report such a list whose closing bracket is on an earlier line than the first token after it, as SHARED-ATTR-004 and SHARED-ATTR-005 specify for a list that must be on the line of what follows.

Why: A parameter is read as one unit of attributes, type, and name. A line break after the attribute splits that unit, and in a parameter list with one parameter per line the orphaned attribute looks like a parameter of its own. Parameter attributes are short markers, so they cost little on the parameter's line.

Example:

```csharp
class C({|RH5523:[A]|}
        int x)
{
    void M({|RH5523:[A]|}
           int a, [A] int b)
    {
        System.Func<int, int> f = ({|RH5523:[A]|}
                                   int c) => c;
    }
}

record R({|RH5523:[property: A]|}
         int Id, [property: A] int Code);
```

### RH5523-002 — The diagnostic is on the attribute list

The analyzer MUST report the diagnostic on the attribute list, as SHARED-ATTR-007 specifies.

Why: The list is what is misplaced; each list of a parameter is reported and fixed on its own.

Example: see RH5523-001.

### RH5523-003 — The fix joins the parameter onto the list's line

The code fix MUST join the first token after the list onto the list's line, as SHARED-ATTR-010 specifies.

Why: The fix makes only the change the diagnostic asks for and leaves the layout of the rest of the parameter list to the author.

Example:

```csharp
class C
{
    void M({|RH5523:[A]|}
           int value)
    {
    }
}
```

```csharp
class C
{
    void M([A] int value)
    {
    }
}
```

### RH5523-004 — The fix is withheld for a comment or directive inside the list

The code fix MUST NOT be offered when SHARED-ATTR-011 withholds it. The diagnostic is still reported.

Why: A comment inside the list belongs to the attribute next to it; only the author can tell whether the joined line still reads right.

Example:

```csharp
class C
{
    void M({|RH5523:[A /* c */]|}
           int value)
    {
    }
}
```

is reported, and no code fix is offered.
