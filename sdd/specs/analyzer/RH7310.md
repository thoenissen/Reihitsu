# Analyzer — RH7310 Empty regions should be removed

| | |
|---|---|
| ID prefix | RH7310 |
| Status | Active |
| Category | Organization |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH7310EmptyRegionsShouldBeRemovedAnalyzer`, `RH7310EmptyRegionsShouldBeRemovedCodeFixProvider` |
| Uses | SHARED-TYPEREGION-005 |

RH7310 reports a region that encloses nothing but whitespace and line breaks, and offers a code fix that removes the region.

## Non-goals

- Regions inside executable code — RH7303.

## Requirements

### RH7310-001 — A region with nothing inside is reported

The analyzer MUST report every `#region` between declarations (SHARED-TYPEREGION-005) whose text up to its matching `#endregion` contains only whitespace and line breaks: no token, no comment, no nested `#region`, no other directive, and no code excluded by `#if`.

Why: An empty region implies a structure that does not exist; it is usually left behind when its members were moved or deleted. A comment, a directive, or excluded code is content the author wrote on purpose, so a region holding any of them is not empty.

Example:

```csharp
{|RH7310:#region Types|}

#endregion

class C
{
    int _a;

    {|RH7310:#region Methods|}

    #endregion // Methods

    {|RH7310:#region Events|}
    #endregion

    int _b;
}
```

### RH7310-002 — A region with content is not reported

The analyzer MUST NOT report a region that contains a token, a comment, a nested `#region`, another directive, or code excluded by `#if`, and MUST NOT report a region inside executable code (SHARED-TYPEREGION-005).

Why: Each of these is content the region groups or documents; removing the region would leave it without the heading the author gave it. A region that holds a nested region holds content, even when the nested one is empty.

Example:

```csharp
class C
{
    #region Properties

    // Added later

    #endregion // Properties

    #region Outer

    {|RH7310:#region Inner|}

    #endregion // Inner

    #endregion // Outer

    #region Fields

#pragma warning disable CS0169

    #endregion // Fields

    #region Legacy

#if false
    void Old()
    {
    }
#endif

    #endregion // Legacy

    void M()
    {
        #region Body
        #endregion
    }
}
```

`Inner` is reported; `Properties`, `Outer`, `Fields`, `Legacy`, and `Body` are not.

### RH7310-003 — The diagnostic is on the `#region`

The analyzer MUST report one diagnostic per empty region, located on its `#region` directive from the `#` to the end of its line. The `#endregion` is not reported.

Why: One region is one finding, and the `#region` line carries its name.

Example: see RH7310-001.

### RH7310-004 — The fix removes the region and the blank lines after it

For a region between two declarations — the nearest line above its `#region` and the nearest line below its `#endregion` that hold more than whitespace each belong to a declaration — the code fix MUST remove everything from the start of the `#region` line to the end of the `#endregion` line, its line break included, and the lines directly after it that hold only whitespace. It MUST leave every other line unchanged.

Why: The region is the whole finding. The blank lines after it were its separation from the code that follows; the blank lines before it now separate that code from what precedes the region, so the layout keeps one separator instead of two.

Example:

```csharp
class C
{
    int _a;

    {|RH7310:#region Methods|}

    #endregion // Methods

    int _b;
}
```

```csharp
class C
{
    int _a;

    int _b;
}
```
