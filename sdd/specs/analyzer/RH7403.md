# Analyzer — RH7403 Override events should be grouped by base type regions

| | |
|---|---|
| ID prefix | RH7403 |
| Status | Active |
| Category | Organization |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH7403OverrideEventsShouldBeGroupedByBaseTypeRegionsAnalyzer` |
| Uses | SHARED-REGGROUP-001, SHARED-REGGROUP-002, SHARED-REGGROUP-003, SHARED-REGGROUP-005, SHARED-TYPEREGION-006 |

RH7403 reports an override event that does not lie in a top-level region named after the type that introduced the event. It has no code fix.

## Non-goals

- Override methods, properties, and indexers — RH7401, RH7402, RH7404.
- An event that overrides nothing but lies in a region named after a base type — RH7407.
- An interface implementation that is not an override — RH7411.

## Requirements

### RH7403-001 — An override event outside its base type's region is reported

In every type declaration it checks (SHARED-REGGROUP-001), the analyzer MUST report each event declaration — a field-like event with one declarator and an event with `add` and `remove` accessors alike — that overrides an event, is not `partial`, and lies in no region nested in a top-level region (SHARED-TYPEREGION-006), when the event does not lie in a top-level region whose name matches (SHARED-REGGROUP-002) the type it comes from (SHARED-REGGROUP-003) — whether it lies in a region of another name or in no region. This holds also for an override that implements an interface event. The diagnostic MUST be placed as SHARED-REGGROUP-005 specifies.

Why: Overrides are easier to scan when they are grouped by the type that introduced them; a generic region name such as `Events` hides that relationship. Both forms declare the same kind of member, and an override that also implements an interface event is still an override of its base type, so it is grouped there.

Example:

```csharp
using System;

interface INotifier
{
    event EventHandler Changed;
}

abstract class B
{
    public abstract event EventHandler Changed;

    public virtual event EventHandler Saved;

    public virtual event EventHandler Closed;
}

class C : B, INotifier
{
    #region INotifier

    public override event EventHandler {|RH7403:Changed|};

    #endregion

    #region Events

    public override event EventHandler {|RH7403:Saved|}
    {
        add
        {
        }

        remove
        {
        }
    }

    #endregion

    public override event EventHandler {|RH7403:Closed|};
}
```

while an override in the region named after its base type:

```csharp
using System;

class B
{
    public virtual event EventHandler Changed;
}

class C : B
{
    #region B

    public override event EventHandler Changed;

    #endregion
}
```

is not reported.

### RH7403-002 — Other members are not reported

The analyzer MUST NOT report an event that overrides nothing, and MUST NOT report an override method, property, or indexer.

Why: An event that overrides nothing has no base type to be grouped by, and the other override kinds have rules of their own.

Example:

```csharp
using System;

class B
{
    public virtual void M()
    {
    }
}

class C : B
{
    public override void M()
    {
    }

    public event EventHandler Changed;
}
```

is not reported.
