# Analyzer — RH2009 Methods should not exceed the complexity limit

| | |
|---|---|
| ID prefix | RH2009 |
| Status | Active |
| Category | Design |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH2009MethodsShouldNotExceedTheComplexityLimitAnalyzer` |
| Uses | RH0001-001, RH0001-003, RH0001-007, SHARED-DIAG-007, SHARED-DIAG-008, SHARED-DIAG-012 |

RH2009 reports a method, or another member with a body of statements or an expression, whose body has a cognitive complexity above its limit — 15, unless the `design` section of the `reihitsu.json` configuration file sets another limit — and whose body nests at least one structure inside another.

## Non-goals

- Loading and validating the configuration file and the `design` section — RH0001 (RH0001-007).
- The length of a member — RH2008 — and of a type — RH2111.
- Cyclomatic complexity or any other count of the paths through a member.
- Lambda expressions and anonymous methods judged on their own, also a lambda in a field or property initializer; their structures count toward the member that holds them (RH2009-005).
- Top-level statements, which declare no method in the source.
- A field, property, or event initializer, a constructor initializer (`: base(…)`, `: this(…)`), parameter default values, and attribute arguments, which are not part of a body.
- Recursion: a member that calls itself scores nothing for the call.
- A code fix: making a member less complex is a design decision — extracting a method, inverting a condition, replacing a branch with a lookup — that no fix can make.

## Requirements

### RH2009-001 — The limit is `design.maximumMethodComplexity`

The analyzer MUST take the limit of every judged member, in production code and in test code alike, from the setting `design.maximumMethodComplexity` of the configuration that RH0001-001 loads, valid as RH0001-007 specifies, with the default 15. The default MUST apply whenever the setting has no valid value: when there is no configuration file, when the file holds no `design` section or the section does not hold the setting, when RH0001 reports a problem with the setting's value (RH0001-007), when the file is empty or cannot be parsed (RH0001-003), and when it cannot be read. A problem RH0001 reports elsewhere in the configuration file MUST NOT keep a valid setting from taking effect. A member MUST be reported when its cognitive complexity (RH2009-003) is greater than the limit and the member passes RH2009-004, and MUST NOT be reported when its complexity equals the limit or is lower.

Why: The limit is the highest complexity the project accepts, so a member of exactly that complexity is accepted. The default makes the rule work without setup; a member above 15 has usually gathered more decisions than a reader follows at once. Unlike their length, the complexity of test methods is not higher by nature — a test arranges, acts, and asserts without branching — so one limit serves both kinds of code. A setting without a valid value has nothing the rule could trust, so the rule keeps to the documented default rather than going silent, and RH0001 reports the setting or the file.

Example — without a `reihitsu.json`, `Score` has a cognitive complexity of 16 — `foreach` 1, the outer `if` 2, the inner `if` 3, `for` 4, the innermost `if` 5, `else if` 1 — and is reported, "This member has a cognitive complexity of 16, which exceeds the limit of 15.":

```csharp
class C
{
    public int {|RH2009:Score|}(int[] values)
    {
        int total = 0;

        foreach (var value in values)
        {
            if (value > 0)
            {
                if (value % 2 == 0)
                {
                    for (int i = 0; i < value; i++)
                    {
                        if (i % 3 == 0)
                        {
                            total += i;
                        }
                        else if (i % 5 == 0)
                        {
                            total -= i;
                        }
                    }
                }
            }
        }

        return total;
    }
}
```

With `{ "design": { "maximumMethodComplexity": 16 } }` it is not reported; with `{ "design": { "maximumMethodComplexity": 10 } }` it is reported, "This member has a cognitive complexity of 16, which exceeds the limit of 10.", in a production project and in a test project alike. With `{ "design": { "maximumMethodComplexity": 0 } }` or `{ "design": { "maximumMethodComplexity": "10" } }`, which RH0001 reports, the default of 15 applies and it is reported against 15. With `{ "design": { "maximumMethodComplexity": 10 }, "formatting": 1 }`, it is reported against 10, although RH0001 reports the unknown section `formatting`.

### RH2009-002 — The members judged

The analyzer MUST judge every method, constructor, finalizer, operator, conversion operator, local function, and accessor (`get`, `set`, `init`, `add`, `remove`) that has a block body or an expression body, and every property and indexer that has an expression body instead of an accessor list, by the cognitive complexity of that body. It MUST NOT judge a member that has neither: an abstract or `extern` member, an interface member without a default implementation, the defining part of a partial method or partial property, and an accessor without a body. A property or indexer with an accessor list is not judged itself; each of its accessors is judged on its own. A partial member is judged by the part that holds its body, and its one diagnostic stands on that part (SHARED-DIAG-012).

Why: The members judged are the ones RH2008 judges for their length: an accessor, an operator, and a constructor are methods under another syntax, and a property or indexer with an expression body is a `get` accessor written without the keyword. The accessors of a property are separate bodies, each read on its own, so their complexities are not summed.

Example — with `{ "design": { "maximumMethodComplexity": 2 } }`; `get` of `Value`, `Sign`, and `+` each have a cognitive complexity of 3, and `Flat` of 2:

```csharp
class C
{
    private int _value;

    public int Value
    {
        {|RH2009:get|}
        {
            if (_value > 0)
            {
                if (_value > 1)
                {
                    return 2;
                }
            }

            return 0;
        }
    }

    public int {|RH2009:Sign|} => _value > 0 ? (_value > 1 ? 2 : 1) : 0;

    public static C operator {|RH2009:+|}(C left, C right)
    {
        foreach (var digit in right._value.ToString())
        {
            if (digit == '1')
            {
                left._value++;
            }
        }

        return left;
    }

    public int Flat()
    {
        while (_value > 10)
        {
            _value--;
        }

        return _value > 5 ? 1 : 0;
    }
}
```

Example — with `{ "design": { "maximumMethodComplexity": 1 } }`:

```csharp
abstract partial class C
{
    public abstract void A(int value);

    public int P { get; set; }

    public partial void M(int value);

    public partial void {|RH2009:M|}(int value)
    {
        if (value > 0)
        {
            if (value > 1)
            {
                A(value);
            }
        }
    }
}
```

### RH2009-003 — Cognitive complexity of a body

The cognitive complexity of a judged body MUST be the sum of the following increments, starting from 0. The *nesting level* of a structure is the number of nesting constructs of the judged body whose nested part (below) contains it: 0 for a structure that no nesting construct contains, 1 for a structure inside one, 2 inside two, and so on. A structure of item 1 MUST cost more the deeper it is nested: its increment is 1 plus its nesting level, so the same `if` statement scores 1 at nesting level 0, 2 at level 1, and 3 at level 2.

1. **Structure, with a nesting increment** — 1 plus the structure's nesting level, for each:
   - `if` statement that is not the statement of an `else` clause;
   - conditional expression `?:`;
   - `switch` statement and `switch` expression — once for the whole switch, not per section, label, or arm;
   - `for`, `foreach` (also `await foreach`), `while`, and `do` statement;
   - `catch` clause.
2. **Structure, without a nesting increment** — 1 for each `else` clause: 1 for `else if`, whose `if` scores nothing further under 1, and 1 for a final `else`.
3. **Fundamental** — 1, whatever the nesting level, for each:
   - sequence of logical operators: in a tree of `&&` and `||` expressions joined directly or through parentheses, the first operator in source order and each operator that differs from the operator before it; a `!` or any other expression between two of them starts a new tree. The `and` and `or` pattern combinators, joined directly or through parenthesized patterns, are counted in the same way;
   - `goto` statement, in each of its forms (`goto label`, `goto case`, `goto default`).

The nesting constructs, and the nested part of each, are: an `if` statement with its `else` clauses — one construct for a chain written `if … else if … else`, whose nested part is every branch of the chain and not its conditions; a conditional expression, whose nested part is its two branches; a `switch` statement and a `switch` expression, whose nested part is their sections or arms; a loop, whose nested part is its body; a `catch` clause, whose nested part is its block; and a lambda expression, an anonymous method, and a local function, whose nested part is their body (RH2009-005).

Nothing else adds to the complexity or nests: not `try` and `finally` blocks, `using`, `lock`, `fixed`, `checked`, `unchecked`, and `unsafe` statements, plain blocks, labeled statements, `return`, `throw`, `yield`, `break`, and `continue`, the case labels, `when` clauses, and `default` section of a switch, the `??`, `??=`, `?.`, and `?[]` operators, the `&` and `|` operators, a pattern without `and` or `or`, and a call of the member itself.

Why: Cognitive complexity measures how hard a body is to follow, not how many paths it has. Every break in the linear flow costs the reader once, and it costs more the deeper it sits, because the reader has to keep each enclosing condition in mind while following it: three nested `if` statements are harder to follow than three in a row, and score 6 instead of 3; a switch is read as one decision, however many cases it has, and an `else` continues the decision its `if` began instead of opening a new one. A run of the same logical operator reads as one condition; switching between `&&` and `||` makes the reader regroup. A `goto` breaks the flow wherever it stands. The null-handling operators, `try`, `using`, and `lock` do not make the reader track a decision, so they score nothing; neither do the steps of a `switch` that are part of the switch the reader already counts.

Example — deeper nesting costs more; with `{ "design": { "maximumMethodComplexity": 5 } }`, `M` nests three `if` statements and has a cognitive complexity of 6, while `N` holds the same three `if` statements one after another and has 3:

```csharp
class C
{
    void {|RH2009:M|}(int a)
    {
        if (a > 0)              // 1 (nesting 0)
        {
            if (a > 1)          // 2 (nesting 1)
            {
                if (a > 2)      // 3 (nesting 2)
                {
                    a--;
                }
            }
        }
    }

    void N(int a)
    {
        if (a > 0)              // 1
        {
            a--;
        }

        if (a > 1)              // 1
        {
            a--;
        }

        if (a > 2)              // 1
        {
            a--;
        }
    }
}
```

With `{ "design": { "maximumMethodComplexity": 2 } }`, `M` is still reported, and `N` is not: it holds no nesting increment (RH2009-004).

Example — with `{ "design": { "maximumMethodComplexity": 10 } }`; the comments give the increments, 11 in all:

```csharp
using System;

class C
{
    int {|RH2009:M|}(int[] values, string text)
    {
        var total = 0;

        foreach (var value in values)                // 1
        {
            if (value > 0 && value < 10)             // 2 (nesting 1), 1 for &&
            {
                total += value;
            }
            else if (value is 10 or 20)              // 1, 1 for or
            {
                total -= value;
            }
            else                                     // 1
            {
                total += value > 100 ? 1 : 2;        // 3 (nesting 2)
            }
        }

        try
        {
            total = checked(total * 2);
        }
        catch (OverflowException)                    // 1
        {
            total = text?.Length ?? 0;
        }

        return total;
    }
}
```

With `{ "design": { "maximumMethodComplexity": 11 } }` it is not reported.

Example — the sequences of logical operators; each method holds one `if` (1) with a `while` inside it (2), so the complexity is 3 plus the sequences of its condition:

```csharp
class C
{
    bool _a, _b, _c;

    void A() { if (_a) { while (_a && _b && _c) { } } }                    // 1 sequence: 4
    void {|RH2009:B|}() { if (_a) { while (_a && _b || _c) { } } }                    // 2 sequences: 5
    void {|RH2009:D|}() { if (_a) { while (_a && (_b || _c)) { } } }                  // 2 sequences: 5
    void {|RH2009:E|}() { if (_a) { while (!(_a && _b) && _c) { } } }                 // 2 sequences: 5
    void F(int x) { if (_a) { while (x is 1 or 2 or 3) { } } }             // 1 sequence: 4
    void {|RH2009:G|}(int x) { if (_a) { while (x is (1 or 2) and not 3) { } } }      // 2 sequences: 5
}
```

The block is analyzed with `{ "design": { "maximumMethodComplexity": 4 } }`.

Example — a switch scores once, and its nested part nests; with `{ "design": { "maximumMethodComplexity": 3 } }`, `M` has a cognitive complexity of 4 — `switch` 1, the `switch` expression 2 (nesting 1), `goto case` 1:

```csharp
class C
{
    int {|RH2009:M|}(int value, string text)
    {
        switch (value)
        {
            case 1:
            case 2:
                return text switch
                {
                    "a" => 1,
                    _ => 2,
                };

            default:
                goto case 1;
        }
    }
}
```

Example — `lock`, `using`, `try`, `finally`, a type pattern, `throw`, and `??` score nothing and do not nest; `M` has a cognitive complexity of 3 — the outer `if` 1, the inner `if` 2 (nesting 1) — and with `{ "design": { "maximumMethodComplexity": 3 } }`

```csharp
using System;

class C
{
    private readonly object _gate = new object();

    void M(IDisposable resource, object value)
    {
        if (value != null)
        {
            lock (_gate)
            {
                using (resource)
                {
                    try
                    {
                        if (value is int number)
                        {
                            throw new InvalidOperationException(number.ToString() ?? string.Empty);
                        }
                    }
                    finally
                    {
                        resource.Dispose();
                    }
                }
            }
        }
    }
}
```

is not reported.

### RH2009-004 — A body without a nesting increment is not reported

The analyzer MUST NOT report a member whose cognitive complexity holds no nesting increment: no structure of RH2009-003, item 1, in its body has a nesting level above 0. This holds whatever the complexity. A structure has a nesting level above 0 when it lies in the nested part of a nesting construct (RH2009-003), and only then:

- an `if` statement inside the block of an `else` clause (`else { if … }`) lies in the nested part of the chain and has a nesting increment; an `if` statement that is itself the statement of the `else` clause (`else if …`) continues the chain and has none;
- an `if` statement inside the block of a `catch` clause has a nesting increment; one inside the block of the `try` or of the `finally` has none;
- a structure inside a lambda, an anonymous method, or a local function has a nesting increment (RH2009-005);
- a structure in a condition — the condition of an `if`, a loop, or a conditional expression, or the governing expression of a switch — is not in that construct's nested part.

A logical operator, a pattern combinator, a `goto`, and an `else` clause never carry a nesting increment, also inside a nested part.

This requirement only decides whether a member is compared with its limit; it does not change the complexity. A body without a nesting increment scores 1 for each of its structures and is never reported, however many it holds. A body with at least one nesting increment is compared with the limit by its whole complexity (RH2009-003): its nesting increments, which grow with the depth, and the increments of its structures at nesting level 0 together.

Why: A body whose decisions stand one after another can be read one decision at a time, however many there are; the reader never has to hold one condition in mind while following another. Such a body is long rather than complex, which RH2008 judges. Once one decision sits inside another, the reader has to keep the outer one in mind, and from then on every decision of the body adds to what the reader has to follow, so the whole complexity is compared with the limit.

Example — with `{ "design": { "maximumMethodComplexity": 1 } }`; `M` has a cognitive complexity of 9 — the `if` chain 3, `&&` 1, `for` 1, the conditional expression 1, `||` 1, `switch` 1, and the second `if` 1 — and no nesting increment:

```csharp
class C
{
    int M(int value)
    {
        if (value == 1)
        {
            return 10;
        }
        else if (value == 2 && value > 0)
        {
            return 20;
        }
        else
        {
            value++;
        }

        for (var i = 0; i < value; i++)
        {
            value--;
        }

        value = value > 5 || value < 0 ? 0 : 1;

        if (value > 4)
        {
            value--;
        }

        switch (value)
        {
            case 3:
                return 30;

            default:
                return value;
        }
    }
}
```

is not reported. Moved into the block of the second `if`, the conditional expression would lie in that `if`'s nested part and score 2 (nesting 1), and `M` would be reported with a cognitive complexity of 10.

Example — with `{ "design": { "maximumMethodComplexity": 1 } }`; an `if` statement in the block of an `else` clause nests, 2 (nesting 1), and `M` has a cognitive complexity of 4 — the chain 2 and the nested `if` 2:

```csharp
class C
{
    int {|RH2009:M|}(int value)
    {
        if (value == 1)
        {
            return 10;
        }
        else
        {
            if (value > 5)
            {
                value++;
            }
        }

        return value;
    }
}
```

while the same `if` written as `else if (value > 5)` gives a chain without a nesting increment, which is not reported.

Example — with `{ "design": { "maximumMethodComplexity": 1 } }`; an `if` in a `try` block does not nest, an `if` in a `catch` block does:

```csharp
class C
{
    void M(int value)
    {
        try
        {
            if (value > 0)
            {
                M(value - 1);
            }
        }
        finally
        {
            M(0);
        }
    }

    void {|RH2009:N|}(int value)
    {
        try
        {
            M(value);
        }
        catch (System.InvalidOperationException)
        {
            if (value > 0)
            {
                M(0);
            }
        }
    }
}
```

`M` has a cognitive complexity of 1 and no nesting increment; `N` has 3 — `catch` 1, `if` 2 (nesting 1).

### RH2009-005 — Nested functions count toward the member that holds them

The structures of a lambda expression, an anonymous method, or a local function inside a judged body MUST count toward that body, each one nesting level deeper than the place where the function is written, and the function itself MUST NOT add an increment. A local function MUST in addition be judged on its own by its own body, whose nesting starts at 0 there. A lambda expression and an anonymous method MUST NOT be judged on their own.

Why: A reader of the member reads the functions declared inside it, and a lambda's body runs in a context the reader has to keep in mind, as a branch does; moving a branch into a local function or a lambda keeps the member as hard to follow as it was. A local function is still a method with a name of its own, so its own complexity is judged too, as RH2008 judges its length.

Example — with `{ "design": { "maximumMethodComplexity": 1 } }`; the `if` in the lambda scores 2 (nesting 1) for `M`:

```csharp
using System.Linq;

class C
{
    int {|RH2009:M|}(int[] values) => values.Count(value =>
    {
        if (value > 0)
        {
            return true;
        }

        return false;
    });
}
```

Example — with `{ "design": { "maximumMethodComplexity": 3 } }`; `M` has a cognitive complexity of 6 — its `if` 1, the `foreach` of `Local` 2 (nesting 1), the `if` of `Local` 3 (nesting 2) — and `Local` has 3 — `foreach` 1, `if` 2 (nesting 1):

```csharp
class C
{
    int {|RH2009:M|}(int value)
    {
        if (value > 0)
        {
            return Local(value);
        }

        return 0;

        int Local(int input)
        {
            foreach (var digit in input.ToString())
            {
                if (digit == '0')
                {
                    return 0;
                }
            }

            return input;
        }
    }
}
```

With `{ "design": { "maximumMethodComplexity": 2 } }`, `Local` is reported as well, as `int {|RH2009:Local|}(int input)`.

Example — a lambda outside every judged body, such as in a field initializer, is not judged; with `{ "design": { "maximumMethodComplexity": 1 } }`

```csharp
using System;

class C
{
    private static readonly Func<int, int> Compute = value =>
    {
        if (value > 0)
        {
            if (value > 1)
            {
                return 2;
            }
        }

        return 0;
    };
}
```

is not reported.

### RH2009-006 — One diagnostic per member, located on its name

The analyzer MUST report one diagnostic for each judged member that RH2009-001 reports, located on the member's identifier for a method, constructor, finalizer, local function, and property; on the `this` keyword for an indexer; on the operator token for an operator, such as `+` or `==`; on the `operator` keyword for a conversion operator; and on the keyword of an accessor. A member that holds a reported local function and is itself over the limit is reported as well, on its own identifier. Code that a conditional directive excludes counts as absent (SHARED-DIAG-008).

Why: The name is where a reader looks for the member and where a suppression is placed; a member without an identifier is marked by the token that names it in its declaration (SHARED-DIAG-007). The tokens are the ones RH2008 reports on, so the two rules about one member stand at one place.

Example — with `{ "design": { "maximumMethodComplexity": 1 } }`:

```csharp
class C
{
    private int _value;

    public int {|RH2009:this|}[int index] => index > 0 ? (index > 1 ? 2 : 1) : 0;

    public static explicit {|RH2009:operator|} int(C value)
    {
        if (value._value > 0)
        {
#if FEATURE
            if (value._value > 1)
            {
                return 2;
            }
#endif
            return 1;
        }

        return 0;
    }

    ~{|RH2009:C|}()
    {
        while (_value > 0)
        {
            if (_value > 1)
            {
                _value--;
            }

            _value--;
        }
    }
}
```

The block is analyzed in a build that defines `FEATURE`, where the conversion operator has a cognitive complexity of 3. In a build that does not define it, the conversion operator has a cognitive complexity of 1, holds no nesting increment, and is not reported; the indexer and the finalizer, 3 each, are reported in both builds.
