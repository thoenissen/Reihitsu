# Analyzer — RH2009 Methods should not exceed the complexity limit

| | |
|---|---|
| ID prefix | RH2009 |
| Status | Active |
| Category | Design |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH2009MethodsShouldNotExceedTheComplexityLimitAnalyzer`, `CognitiveComplexityWalker` |
| Uses | RH0001-007, RH2008-002, RH2008-004, RH2008-005, SHARED-DIAG-008, SHARED-LIMIT-001, SHARED-LIMIT-002 |

RH2009 reports a method, or another member with a body of statements or an expression, whose body has a cognitive complexity above its limit — 15, unless the `design` section of the `reihitsu.json` configuration file sets another limit — and whose body nests at least one structure inside another. RH2009-003 defines the cognitive complexity; the user-facing scoring guide is `documentation/cognitive-complexity.md`.

## Non-goals

- Loading and validating the configuration file and the `design` section — RH0001 (RH0001-007).
- The length of a member — RH2008 — and of a type — RH2111.
- Cyclomatic complexity or any other count of the paths through a member.
- A lambda expression or an anonymous method judged on its own, also one in a field, property, or event initializer (RH2009-005).
- Top-level statements, which declare no method in the source.
- A field, property, or event initializer, a constructor initializer (`: base(…)`, `: this(…)`), parameter default values, and attribute arguments, which are not part of a body.
- Recursion through more than one member (`A` calls `B`, `B` calls `A`): only a member that calls itself scores for recursion (RH2009-003).
- A total of the complexity of a type, a file, or a project.
- A code fix: making a member less complex is a design decision — extracting a method, inverting a condition, replacing a branch with a lookup — that no fix can make.

## Requirements

### RH2009-001 — The limit is `design.maximumMethodComplexity`

The analyzer MUST take the limit of every judged member, in production code and in test code alike, from the setting `design.maximumMethodComplexity` (RH0001-007), with the default 15, as SHARED-LIMIT-001 specifies, and MUST compare the member's cognitive complexity (RH2009-003) with it as SHARED-LIMIT-002 specifies. A member that RH2009-004 leaves unreported is not reported, whatever its complexity.

Why: The default makes the rule work without setup; a member above 15 has usually gathered more decisions than a reader follows at once. Unlike their length, the complexity of test methods is not higher by nature — a test arranges, acts, and asserts without branching — so one limit serves both kinds of code.

Example — without a `reihitsu.json`, `Score` has a cognitive complexity of 16 — `foreach` 1, the outer `if` 2, the inner `if` 3, `for` 4, the innermost `if` 5, `else if` 1 — and is reported, "This member has a cognitive complexity of 16, which exceeds the limit of 15.":

```csharp
class C
{
    public int {|RH2009:Score|}(int[] values)
    {
        int total = 0;

        foreach (var value in values)
        {
            if (value > 0)
            {
                if (value % 2 == 0)
                {
                    for (int i = 0; i < value; i++)
                    {
                        if (i % 3 == 0)
                        {
                            total += i;
                        }
                        else if (i % 5 == 0)
                        {
                            total -= i;
                        }
                    }
                }
            }
        }

        return total;
    }
}
```

With `{ "design": { "maximumMethodComplexity": 16 } }` it is not reported; with `{ "design": { "maximumMethodComplexity": 10 } }` it is reported, "This member has a cognitive complexity of 16, which exceeds the limit of 10.", in a production project and in a test project alike. With `{ "design": { "maximumMethodComplexity": 0 } }` or `{ "design": { "maximumMethodComplexity": "10" } }`, which RH0001 reports, the default of 15 applies and it is reported against 15. With `{ "design": { "maximumMethodComplexity": 10 }, "formatting": 1 }`, it is reported against 10, although RH0001 reports the unknown section `formatting`. With `{ "design": { "maximumMethodLines": 10 } }` the complexity limit stays 15.

### RH2009-002 — The members judged

The analyzer MUST judge the members that RH2008-002 judges, and MUST NOT judge those that RH2008-004 leaves out, each by the cognitive complexity of the body that RH2008-002 names: its block body, or the expression of its expression body. A constructor initializer is not part of the body. A property or indexer with an accessor list is not judged itself; each of its accessors is judged on its own, and their complexities are not summed.

Why: An accessor, an operator, and a constructor are methods under another syntax, and a property or indexer with an expression body is a `get` accessor written without the keyword; the members judged for their complexity are the ones judged for their length, so both rules about one member judge the same body.

Example — with `{ "design": { "maximumMethodComplexity": 2 } }`; `get` of `Value`, `Sign`, and `+` each have a cognitive complexity of 3, and `Flat` of 2:

```csharp
class C
{
    private int _value;

    public int Value
    {
        {|RH2009:get|}
        {
            if (_value > 0)
            {
                if (_value > 1)
                {
                    return 2;
                }
            }

            return 0;
        }
    }

    public int {|RH2009:Sign|} => _value > 0 ? (_value > 1 ? 2 : 1) : 0;

    public static C operator {|RH2009:+|}(C left, C right)
    {
        foreach (var digit in right._value.ToString())
        {
            if (digit == '1')
            {
                left._value++;
            }
        }

        return left;
    }

    public int Flat()
    {
        while (_value > 10)
        {
            _value--;
        }

        return _value > 5 ? 1 : 0;
    }
}
```

Example — with `{ "design": { "maximumMethodComplexity": 1 } }`:

```csharp
abstract partial class C
{
    public abstract void A(int value);

    public int P { get; set; }

    public partial void M(int value);

    public partial void {|RH2009:M|}(int value)
    {
        if (value > 0)
        {
            if (value > 1)
            {
                A(value);
            }
        }
    }
}
```

### RH2009-003 — Cognitive complexity of a body

The cognitive complexity of a judged body MUST be the sum of the following increments over its *scored part*, starting from 0. The scored part is the body without the local functions declared in it, at any depth (RH2009-005); the bodies of lambda expressions and anonymous methods in it belong to it. The *nesting level* of a structure is the number of nesting constructs (below) whose nested part contains it: 0 for a structure that no nesting construct contains, 1 for a structure inside one, 2 inside two, and so on. A structure of item 1 MUST cost more the deeper it is nested: its increment is 1 plus its nesting level, so the same `if` statement scores 1 at nesting level 0, 2 at level 1, and 3 at level 2.

1. **Structure, with a nesting increment** — 1 plus the structure's nesting level, for each:
   - `if` statement that is not the statement of an `else` clause;
   - conditional expression `?:` that does not continue a chain (below);
   - `switch` statement and `switch` expression — once for the whole switch, not per section, label, or arm;
   - `for`, `foreach` (also `await foreach` and `foreach` with a deconstruction), `while`, and `do` statement;
   - `catch` clause.
2. **Structure, without a nesting increment** — 1, whatever the nesting level, for each:
   - `else` clause: 1 for `else if`, whose `if` scores nothing further under item 1, and 1 for a final `else`;
   - conditional expression that continues a chain: a conditional expression that is the false branch of another conditional expression, directly or inside one or more pairs of parentheses, continues the chain of that one, as `else if` continues an `if`.
3. **Fundamental** — 1, whatever the nesting level, for each:
   - sequence of binary logical operators. The binary logical operators are `&&` and `||`, and `&`, `|`, and `^` when the operator is the logical operator of `bool` or `bool?` operands. In each tree of binary logical operators joined directly or through parentheses, the first operator in source order and each operator that differs from the operator before it in source order are a sequence. A `!` or any other expression between two of them — a call, a comparison, a conditional expression, a `??`, an `is` expression — starts a new tree. A compound assignment (`&=`, `|=`, `^=`) is not a binary logical operator;
   - sequence of pattern combinators: the `and` and `or` combinators of the pattern of an `is` expression are counted in the same way, in each tree joined directly or through parenthesized patterns; a `not` pattern or any other pattern between two of them starts a new tree. The combinators of the pattern of a case label or of a switch expression arm score nothing; an `is` expression in its `when` clause is counted;
   - `goto` statement, in each of its forms (`goto label`, `goto case`, `goto default`);
   - recursion: 1, once, when the scored part holds an invocation of the judged method or local function itself — an invocation expression whose target is the member's own symbol, written as `M(…)`, `this.M(…)`, or `C.M(…)`, with or without type arguments — however many such invocations it holds. Only an invocation counts: a constructor that creates an instance of its own type with `new`, an accessor that uses its own property or indexer, and an operator whose body applies the same operator are not invocations of the member and score nothing.

The nesting constructs, and the nested part of each, are:

- an `if` statement with its `else` clauses — one construct for a chain written `if … else if … else`, whose nested part is every branch of the chain and none of its conditions;
- a conditional expression with the conditional expressions that continue its chain — one construct, whose nested part is every true branch of the chain and its last false branch, and none of its conditions;
- a `switch` statement and a `switch` expression, whose nested part is their sections or arms, with their case labels, patterns, and `when` clauses, and not the governing expression;
- a loop, whose nested part is its body, and not its condition, its `for` initializers and incrementors, or the collection of a `foreach`;
- a `catch` clause, whose nested part is its block, and not its exception filter (`when`);
- a lambda expression and an anonymous method, whose nested part is their body (RH2009-005).

Nothing else adds to the complexity or nests: not `try` and `finally` blocks, `using`, `lock`, `fixed`, `checked`, `unchecked`, and `unsafe` statements, plain blocks, labeled statements, `return`, `throw`, `yield`, `break`, and `continue`; the case labels, `when` clauses, and `default` section of a switch, and an exception filter, which score nothing themselves while the operators and structures in them count; the `??`, `??=`, `?.`, and `?[]` operators; `&`, `|`, and `^` on integers, enums, and other operands that are not `bool` or `bool?`; a pattern without `and` or `or`, and a `not` pattern; the clauses of a query expression (`from`, `where`, `orderby`, `select`, …), whose expressions count at the nesting level where the query stands; a lambda expression or an anonymous method itself; a call of another overload of the member, a reference to the member as a method group, a call that reaches the member only through another member, and a use of the member that is not an invocation — `new` of its own type in a constructor, its own property or indexer in an accessor, its own operator in an operator; a compound assignment `&=`, `|=`, or `^=`, also on `bool`; and a conditional directive, while code it excludes counts as absent (SHARED-DIAG-008).

Why: Cognitive complexity measures how hard a body is to follow, not how many paths it has. Every break in the linear flow costs the reader once, and it costs more the deeper it sits, because the reader has to keep each enclosing condition in mind while following it: three nested `if` statements are harder to follow than three in a row, and score 6 instead of 3. A switch is read as one decision, however many cases it has, so neither its sections nor the alternatives listed in one case add to it; an `else` and a chained conditional continue the decision their `if` or conditional began instead of opening a new one. A run of the same logical operator reads as one condition, whether it short-circuits or not; switching between operators makes the reader regroup. A `goto` breaks the flow wherever it stands, and a member that calls itself has to be read with the whole member in mind once more. The null-handling operators, `try`, `using`, and `lock` do not make the reader track a decision, so they score nothing.

Example — deeper nesting costs more; with `{ "design": { "maximumMethodComplexity": 5 } }`, `M` nests three `if` statements and has a cognitive complexity of 6, while `N` holds the same three `if` statements one after another and has 3:

```csharp
class C
{
    void {|RH2009:M|}(int a)
    {
        if (a > 0)              // 1 (nesting 0)
        {
            if (a > 1)          // 2 (nesting 1)
            {
                if (a > 2)      // 3 (nesting 2)
                {
                    a--;
                }
            }
        }
    }

    void N(int a)
    {
        if (a > 0)              // 1
        {
            a--;
        }

        if (a > 1)              // 1
        {
            a--;
        }

        if (a > 2)              // 1
        {
            a--;
        }
    }
}
```

With `{ "design": { "maximumMethodComplexity": 2 } }`, `M` is still reported, and `N` is not: it holds no nesting increment (RH2009-004).

Example — with `{ "design": { "maximumMethodComplexity": 10 } }`; the comments give the increments, 11 in all:

```csharp
using System;

class C
{
    int {|RH2009:M|}(int[] values, string text)
    {
        var total = 0;

        foreach (var value in values)                // 1
        {
            if (value > 0 && value < 10)             // 2 (nesting 1), 1 for &&
            {
                total += value;
            }
            else if (value is 10 or 20)              // 1, 1 for or
            {
                total -= value;
            }
            else                                     // 1
            {
                total += value > 100 ? 1 : 2;        // 3 (nesting 2)
            }
        }

        try
        {
            total = checked(total * 2);
        }
        catch (OverflowException)                    // 1
        {
            total = text?.Length ?? 0;
        }

        return total;
    }
}
```

With `{ "design": { "maximumMethodComplexity": 11 } }` it is not reported.

Example — the sequences of logical operators and pattern combinators; each method holds one `if` (1) with a `while` inside it (2), so the complexity is 3 plus the sequences of its condition; the block is analyzed with `{ "design": { "maximumMethodComplexity": 4 } }`:

```csharp
class C
{
    bool _a, _b, _c;

    void A() { if (_a) { while (_a && _b && _c) { } } }                         // 1 sequence: 4
    void {|RH2009:B|}() { if (_a) { while (_a && _b || _c) { } } }                         // 2 sequences: 5
    void {|RH2009:D|}() { if (_a) { while (_a && (_b || _c)) { } } }                       // 2 sequences: 5
    void {|RH2009:E|}() { if (_a) { while (!(_a && _b) && _c) { } } }                      // 2 sequences: 5
    void F(int x) { if (_a) { while (x is 1 or 2 or 3) { } } }                  // 1 sequence: 4
    void {|RH2009:G|}(int x) { if (_a) { while (x is (1 or 2) and not 3) { } } }           // 2 sequences: 5
    void {|RH2009:H|}() { if (_a) { while (_a & _b | _c) { } } }                           // 2 sequences: 5
    void I(int x) { if (_a) { while ((x & 4) != 0 && _b) { } } }                // 1 sequence: 4
    void {|RH2009:J|}(int x) { if (_a) { while (_a && x is 1 or 2) { } } }                 // 2 sequences: 5
    void K(bool? x) { if (_a) { while ((x & _b) == true) { } } }                // 1 sequence: 4
}
```

`I`'s `&` combines integers and scores nothing; `J`'s `or` belongs to the pattern of the `is` expression, a tree of its own.

Example — a chained conditional expression scores like an `else if` chain; with `{ "design": { "maximumMethodComplexity": 3 } }`, `Name` has a cognitive complexity of 3 and no nesting increment, and `Pick` has 4 — the chain 1 and 1, and the conditional expression in its first true branch 2 (nesting 1):


### RH2009-004 — A body without a nesting increment is not reported

The analyzer MUST NOT report a member none of whose structures of RH2009-003, item 1, lies in the nested part of a nesting construct other than a lambda expression or an anonymous method. This holds whatever the complexity. A structure lies in a nested part as RH2009-003 defines it, and only then:

- an `if` statement inside the block of an `else` clause (`else { if … }`) lies in the nested part of the chain; an `if` statement that is itself the statement of the `else` clause (`else if …`) continues the chain and does not;
- a conditional expression in a true branch of another lies in its nested part; one that continues a chain does not;
- an `if` statement inside the block of a `catch` clause lies in its nested part; one inside the block of the `try` or of the `finally` does not;
- a structure in a condition — the condition of an `if`, a loop, or a conditional expression, the governing expression of a switch, or an exception filter — is not in that construct's nested part;
- a structure inside a lambda expression or an anonymous method has a nesting increment for the complexity (RH2009-003), but the lambda or anonymous method does not count for this requirement: a structure whose only enclosing nesting constructs are lambda expressions and anonymous methods does not make the member reportable.

A logical operator, a pattern combinator, a `goto`, recursion, an `else` clause, and a conditional expression that continues a chain never carry a nesting increment, also inside a nested part.

This requirement only decides whether a member is compared with its limit; it does not change the complexity. A member that it lets through is compared with the limit by its whole complexity (RH2009-003): its nesting increments, which grow with the depth — those that lambdas add included — and the increments of its structures at nesting level 0 together.

Why: A body whose decisions stand one after another can be read one decision at a time, however many there are; the reader never has to hold one condition in mind while following another. Such a body is long rather than complex, which RH2008 judges. Once one decision sits inside another, the reader has to keep the outer one in mind, and from then on every decision of the body adds to what the reader has to follow, so the whole complexity is compared with the limit. A lambda is not a decision: a projection or a predicate written as a lambda in an otherwise flat method does not make the reader hold a condition while reading another, so it alone does not make the member reportable.

Example — with `{ "design": { "maximumMethodComplexity": 1 } }`; `M` has a cognitive complexity of 9 — the `if` chain 3, `&&` 1, `for` 1, the conditional expression 1, `||` 1, `switch` 1, and the second `if` 1 — and no nesting increment:

```csharp
        {
            value++;
        }

        {
            value--;
        }

        value = value > 5 || value < 0 ? 0 : 1;

        {
            value--;
        }

        switch (value)
        {
            case 3:
                return 30;

            default:
                return value;
        }
    }
```

### RH2009-005 — Lambdas count toward the member that holds them, local functions do not

The body of a lambda expression or an anonymous method inside a judged body MUST count toward that body, its structures one nesting level deeper than the place where the lambda or anonymous method is written, and the lambda or anonymous method itself MUST NOT add an increment. A lambda expression and an anonymous method MUST NOT be judged on their own, also when no judged body holds them, as in a field, property, or event initializer or a constructor initializer. A local function MUST NOT count toward the body that holds it — neither its structures nor its recursion — and MUST be judged on its own by its own body (RH2009-002), whose nesting starts at 0, also when it is declared inside a lambda or inside another local function.

Why: A lambda's body is read as part of the member, in the context of the call that receives it, as a branch is read in the context of its condition, so its decisions count toward the member one level deeper. A local function has a name and a signature of its own and is read as a method of its own; it is judged by itself and does not add to the member that declares it, so extracting a nested block into a local function makes the member simpler, as extracting it into a method does.

Example — with `{ "design": { "maximumMethodComplexity": 3 } }`; the `if` in the lambda lies in the nested part of the `if` that holds the call and of the lambda, and scores 3 (nesting 2), so `M` has a cognitive complexity of 4:

```csharp
using System;
using System.Collections.Generic;

class C
{
    void {|RH2009:M|}(List<int> values, bool enabled)
    {
        if (enabled)
        {
            values.ForEach(value =>
            {
                if (value > 0)
                {
                    Console.WriteLine(value);
                }
            });
        }
    }
}
```

The same body with the lambda written as an anonymous method, `values.ForEach(delegate (int value) { … })`, has the same complexity and is reported in the same way.

With `{ "design": { "maximumMethodComplexity": 3 } }` neither is reported.

### RH2009-006 — One diagnostic per member, located on its name

The analyzer MUST report one diagnostic for each member that RH2009-001 reports, located where RH2008-005 locates the diagnostic of RH2008 on the same member, with the message "This member has a cognitive complexity of {0}, which exceeds the limit of {1}." Code that a conditional directive excludes counts as absent (SHARED-DIAG-008).

Why: Both rules about one member stand at one place, where a reader looks for the member and where a suppression is placed.

Example — with `{ "design": { "maximumMethodComplexity": 1 } }`:

```csharp
class C
{
    private int _value;

    public int {|RH2009:this|}[int index] => index > 0 ? (index > 1 ? 2 : 1) : 0;

    public static explicit {|RH2009:operator|} int(C value)
    {
        if (value._value > 0)
        {
#if FEATURE
            if (value._value > 1)
            {
                return 2;
            }
#endif
            return 1;
        }

        return 0;
    }

    ~{|RH2009:C|}()
    {
        while (_value > 0)
        {
            if (_value > 1)
            {
                _value--;
            }

            _value--;
        }
    }
}
```

The block is analyzed in a build that defines `FEATURE`, where the conversion operator has a cognitive complexity of 3. In a build that does not define it, the conversion operator has a cognitive complexity of 1, holds no nesting increment, and is not reported; the indexer and the finalizer, 3 each, are reported in both builds.
