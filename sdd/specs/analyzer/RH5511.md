# Analyzer — RH5511 Constructor attributes must be on their own line

| | |
|---|---|
| ID prefix | RH5511 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5511ConstructorAttributesMustFollowPlacementRulesAnalyzer`, `RH5511ConstructorAttributesMustFollowPlacementRulesCodeFixProvider` |
| Uses | SHARED-ATTR-001, SHARED-ATTR-004, SHARED-ATTR-005, SHARED-ATTR-007, SHARED-ATTR-008, SHARED-ATTR-011, SHARED-ATTR-012 |

RH5511 reports an attribute list of a constructor that shares its line with the token after it, and offers a code fix that moves that token onto the next line. The rule uses `shared/attribute-targets.md`.

## Non-goals

- Attributes of a primary constructor's parameters — RH5523.
- Attributes of methods and destructors — RH5513.

## Requirements

### RH5511-001 — Constructor attribute lists are on their own line

The analyzer MUST check every attribute list that resolves to the constructor target: the lists of a constructor declaration, instance or static, without a specifier or with `type:` (SHARED-ATTR-001), and MUST report such a list whose closing bracket shares its line with the first token after it, as SHARED-ATTR-004 and SHARED-ATTR-005 specify for a list that must be on its own line.

Why: A reader scanning a type for its members looks down a column of modifiers and names; an attribute in front of the constructor pushes that line to the right, so a constructor with attributes no longer lines up with the members without.

Example:

```csharp
class C
{
    {|RH5511:[A]|} C()
    {
    }

    [A]
    static C()
    {
    }
}
```

### RH5511-002 — The diagnostic is on the attribute list

The analyzer MUST report the diagnostic on the attribute list, as SHARED-ATTR-007 specifies.

Why: The list is what is misplaced; each list of a declaration is reported and fixed on its own.

Example: see RH5511-001.

### RH5511-003 — The fix moves what follows onto the next line

The code fix MUST put the first token after the list on a new line, as SHARED-ATTR-008 specifies.

Why: The fix makes only the change the diagnostic asks for: what follows the list starts on its own line.

Example:

```csharp
class C
{
    {|RH5511:[A]|} C()
    {
    }
}
```

```csharp
class C
{
    [A]
    C()
    {
    }
}
```

### RH5511-004 — The fix is withheld for comments, directives, and missing braces

The code fix MUST NOT be offered when SHARED-ATTR-011 or SHARED-ATTR-012 withholds it. The diagnostic is still reported.

Why: A comment inside the list belongs to the attribute next to it, and an unclosed scope leaves no indentation to compute; both are left to the author.

Example:

```csharp
class C
{
    {|RH5511:[A /* c */]|} C()
    {
    }
}
```

is reported, and no code fix is offered.
