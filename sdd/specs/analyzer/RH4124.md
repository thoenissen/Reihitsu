# Analyzer — RH4124 Single-letter lambda and anonymous method parameter names

| | |
|---|---|
| ID prefix | RH4124 |
| Status | Active |
| Category | Naming |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH4124SingleLetterLambdaAndAnonymousMethodParameterNamesAnalyzer` |
| Uses | SHARED-SINGLE-001 |

RH4124 reports a parameter of a lambda or an anonymous method, and a range variable of a query expression, whose name is a single letter.

## Non-goals

- Parameters of methods and other members — RH4122; of local functions — RH4123.
- Local variables — RH4125; `foreach` iteration variables — RH4126.
- The casing of parameter names — RH4105.

## Requirements

### RH4124-001 — Single-letter lambda and anonymous method parameter names are reported

The analyzer MUST report every parameter of a simple lambda, a parenthesized lambda, or an anonymous method whose name is a single-letter name (SHARED-SINGLE-001). The analyzer MUST report one diagnostic per parameter, located on its identifier.

Why: A descriptive parameter name lets a reader understand a transformation or a predicate without tracing the parameter's type and the collection it comes from.

Example:

```csharp
using System;

class C
{
    void M()
    {
        Func<int, int> f = {|RH4124:x|} => x;
        Func<int, int, int> g = ({|RH4124:a|}, {|RH4124:B|}) => a + B;
        Action<int> h = delegate (int {|RH4124:v|}) { };
        Func<int, int, int> i = (_, _) => 0;
        Func<int, int> j = value => value;
    }
}
```

### RH4124-002 — Parameters of other members are not checked

The analyzer MUST NOT report a parameter of a method, constructor, or other member, nor a parameter of a local function.

Why: Those parameters have rules of their own (RH4122 and RH4123), so each kind can be configured separately.

Example:

```csharp
class C
{
    void M(int a)
    {
        int Local(int b) => b;
    }
}
```

is not reported.

### RH4124-003 — Single-letter query range variable names are reported

The analyzer MUST report every range variable of a query expression whose name is a single-letter name (SHARED-SINGLE-001). A range variable is the variable that a query clause declares with an identifier of its own: the `from` clause, also the first one of a query and one with an explicit type such as `from int x in …`, the `let` clause, the `join` clause, and the `into` of a `join` clause or of a query continuation behind `select` or `group`. The analyzer MUST report one diagnostic per declared range variable, located on the identifier of the clause that declares it. A use of a range variable in a later clause declares nothing and MUST NOT be reported.

Why: A range variable plays the role of a lambda parameter: the compiler translates the query into method calls whose lambdas take it as their parameter, so `from x in values select x` and `values.Select(x => x)` name the same value and are checked alike (RH4124-001).

Example:

```csharp
using System.Linq;

class C
{
    void M(int[] values, int[] others)
    {
        var doubled = from {|RH4124:x|} in values
                      let {|RH4124:y|} = x * 2
                      select y;

        var joined = from int value in values
                     join {|RH4124:o|} in others on value equals o
                     select value + o;

        var grouped = from value in values
                      join other in others on value equals other into {|RH4124:g|}
                      select g.Count();

        var continued = from value in values
                        group value by value % 2 into {|RH4124:p|}
                        select p.Key into {|RH4124:k|}
                        select k;

        var nested = from {|RH4124:@a|} in values
                     from _ in others
                     select @a;
    }
}
```

Example — range variables with longer names:

```csharp
using System.Linq;

class C
{
    void M(int[] values)
    {
        var names = from value in values
                    let doubledValue = value * 2
                    select doubledValue;
    }
}
```

is not reported.
