# Analyzer — RH5024 Closing brace must not be preceded by blank line

| | |
|---|---|
| ID prefix | RH5024 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5024ClosingBraceMustNotBePrecededByBlankLineAnalyzer`, `RH5024ClosingBraceMustNotBePrecededByBlankLineCodeFixProvider` |
| Uses | SHARED-BLANK-006, SHARED-FIX-001, SHARED-WS-001 |

RH5024 reports a blank line directly above a line that begins with a closing brace, and offers a code fix that deletes it, together with the rest of its run of blank lines, as SHARED-WS-001 specifies for that run.

In the examples, a reported blank line is marked from its start to the end of its line break, so the markup encloses the line break itself.

## Non-goals

- A blank line directly below an opening brace that does not precede a closing brace directly — RH5022. In an empty body the same line is directly below `{` and directly above `}`, and both rules report it.
- The blank line in front of a `while` keyword that follows the brace — RH5027 reports it as well.

## Requirements

### RH5024-001 — A blank line above a closing brace is reported

The analyzer MUST report the blank line directly above a line that begins with a closing brace `}` — only whitespace stands in front of the brace on its line — when the nearest line above it that is not blank — the line above the run of blank lines that ends at the brace — holds code, a comment, or a directive other than `#region`. A run directly below an active `#region` directive is not reported: SHARED-BLANK-006 requires its first line, and RH5023 reports any line after it. What follows the brace on its line does not matter: `;`, a comment, `else`, or `while`. A line holding nothing but whitespace counts as blank.

Why: The brace already delimits the content above it; a blank line next to it pads the block without separating anything.

Example:

```csharp
class C
{
    int[] _a = new[]
    {
        1,
{|RH5024:
|}    };

    void M()
    {
        _a[0]++;
{|RH5024:
|}    } // note

    #region R

    void N()
    {
    }
    #endregion // R
{|RH5024:
|}}
```

Example — the blank lines below `#region R` are not reported by RH5024; in the second method, RH5023 reports the second of them:

```csharp
class C
{
    void M()
    {
        #region R

    }
    #endregion // R

    void N()
    {
        #region S


    }
    #endregion // S
}
```

### RH5024-002 — Only the line directly above the brace counts

The analyzer MUST NOT report a blank line that is separated from the closing brace by a line holding a comment or a directive.

Why: Such a blank line separates the comment or the directive from the code above it; it is not next to the brace.

Example:

```csharp
class C
{
    void M()
    {
        _ = 1;

        #region R

        _ = 2;
        #endregion // R
    }

    void N()
    {
        _ = 1;

        // trailing
    }
}
```

is not reported.

### RH5024-003 — A brace inside a comment, a string, or disabled code is not considered

The analyzer MUST NOT report a blank line above a `}` that is not a closing-brace token: a `}` in the text of a comment, in the content of a string literal, or in code that an `#if` branch excludes.

Why: Such a brace closes nothing; the line above it is part of the comment's text, the string's value, or code the compiler does not see.

Example:

```csharp
class C
{
    string _s = """

        }
        """;

    /*

    } */
#if NEVER
    void M()
    {

    }
#endif
}
```

is not reported.

### RH5024-004 — One diagnostic per brace, on the line directly above it

The analyzer MUST report one diagnostic per closing brace, located on the line directly above it, from the line's start to the end of its line break.

Why: The diagnostic covers exactly the line the brace touches, which the fix deletes together with the rest of its run.

Example: see RH5024-001.

### RH5024-005 — The fix deletes the run of blank lines

The code fix MUST delete the reported line together with every blank line of the run it belongs to — the blank lines that directly precede it, up to the previous line that is not blank — and MUST NOT change any other text, as SHARED-WS-001 specifies for the span of that run. It is offered for every reported line.

Why: The run holds nothing but whitespace and line breaks, so deleting it can never touch a comment, a directive, or a token. One application removes the whole run (SHARED-FIX-001); deleting only the reported line would leave a blank line that the rule reports again.

Example:

```csharp
class C
{
    void M(int a)
    {
        do
        {
            a++;
{|RH5024:
|}        } while (a < 3);
{|RH5024:
|}    }
}
```

```csharp
class C
{
    void M(int a)
    {
        do
        {
            a++;
        } while (a < 3);
    }
}
```

Example — a run of two blank lines; RH5023 reports the line directly above the brace as well:

```csharp
class C
{
    void M()
    {
        M();

{|RH5024:
|}    }
}
```

```csharp
class C
{
    void M()
    {
        M();
    }
}
```
