# Analyzer — RH5206 Switch expression braces should be anchored

| | |
|---|---|
| ID prefix | RH5206 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5206SwitchExpressionBracesShouldBeAnchoredAnalyzer`, `RH5206SwitchExpressionBracesShouldBeAnchoredCodeFixProvider` |
| Uses | FMT-BREAK-008, FMT-INDENT-027, FMT-PIPE-017, SHARED-COMMENT-011, SHARED-FIX-006 |

RH5206 reports a switch expression whose braces are not in the column of its governing expression or whose arms that start a line are not one level deeper, and offers a code fix that lays it out the way the formatter does.

## Non-goals

- Whether the arms of a switch expression share a line.
- The layout inside an arm, such as a wrapped pattern or a multi-line result.

## Requirements

### RH5206-001 — A switch expression off its anchor is reported

The analyzer MUST report a switch expression when its opening brace or its closing brace does not start in the column of the first token of its governing expression, or when an arm that starts a line with only whitespace in front of it does not start four spaces right of that column. A switch expression written on one line MUST be reported as well, because its braces are not in that column. An arm that shares a line with the arm before it MUST NOT be checked for its column. A line that starts with a comment is judged as SHARED-COMMENT-011 specifies.

Why: The braces of a switch expression go on lines of their own (FMT-BREAK-008), under the start of the expression that is switched on, and the arms one level deeper (FMT-INDENT-027), so the reader sees where the expression starts and ends. The rule never asks for arms to be split, so an arm behind another one has no column to check.

Example:

```csharp
class C
{
    string M(int status)
    {
        var a = {|RH5206:status switch { 0 => "Idle", _ => "Other" }|};
        var b = {|RH5206:status switch
            {
              0 => "Idle",
                _ => "Unknown"
            }|};
        var c = status switch
                {
                    0 => "Idle", 1 => "Running",
                    _ => "Unknown"
                };

        return c;
    }
}
```

### RH5206-002 — The diagnostic is on the switch expression

The analyzer MUST report one diagnostic per switch expression, located on the whole switch expression from its governing expression to its closing brace, however many of its braces and arms are misplaced.

Why: The braces and the arms are laid out together, so one diagnostic per expression matches the one fix that lays it out.

Example: see RH5206-001.

### RH5206-003 — The fix lays out the switch expression

The code fix MUST lay out the switch expression as the formatter lays it out in place, which puts each brace on a line of its own in the column of the governing expression and indents the arms that start a line one level deeper (FMT-BREAK-008, FMT-INDENT-027). The fix MUST change only the switch expression: its first token keeps its line and its column in the document, and its other lines are laid out from that column (FMT-PIPE-017). The statement, initializer, or expression body that contains the switch expression MUST stay as written apart from it (SHARED-FIX-006) — the code in front of the switch expression on its line, the code behind it, and, for a switch expression in the condition of an `if` or a loop, the body — also where formatting the document would change it.

Why: The formatter owns the layout of switch expressions, and delegating to it applies that layout instead of a second one. The braces align to the governing expression, which is the switch expression's first token, so laying it out from the column that token has in the document places them as the formatter places them there; the code around the switch expression is the author's layout, which the formatter and the layout rules correct on their own.

Example:

```csharp
class C
{
    string M(int status)
    {
        var a = {|RH5206:status switch
        {
            0 => "Idle",
            _ => "Other"
        }|};
        var b = {|RH5206:status switch
            {
              0 => "Idle",
                _ => "Unknown"
            }|};

        return a + b;
    }
}
```

```csharp
class C
{
    string M(int status)
    {
        var a = status switch
                {
                    0 => "Idle",
                    _ => "Other"
                };
        var b = status switch
                {
                    0 => "Idle",
                    _ => "Unknown"
                };

        return a + b;
    }
}
```

Example — no blank line is inserted in front of the statement that holds the switch expression (SHARED-FIX-006):

```csharp
class C
{
    string M(int status)
    {
        status++;
        return {|RH5206:status switch
            {
              0 => "Idle",
                _ => "Other"
            }|};
    }
}
```

```csharp
class C
{
    string M(int status)
    {
        status++;
        return status switch
               {
                   0 => "Idle",
                   _ => "Other"
               };
    }
}
```

Formatting the document would also insert a blank line between `status++;` and `return`.

Example — a switch expression in the condition of an `if` statement; the body stays as written:

```csharp
class C
{
    bool Check(string s) => true;

    void M(int status)
    {
        if (Check({|RH5206:status switch
            {
              0 => "Idle",
                _ => "Other"
            }|}))
        {
            int  y = 1;
        }
    }
}
```

```csharp
class C
{
    bool Check(string s) => true;

    void M(int status)
    {
        if (Check(status switch
                  {
                      0 => "Idle",
                      _ => "Other"
                  }))
        {
            int  y = 1;
        }
    }
}
```

Formatting the document would also write `int y = 1;`.
