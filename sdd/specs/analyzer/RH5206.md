# Analyzer — RH5206 Switch expression braces should be anchored

| | |
|---|---|
| ID prefix | RH5206 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5206SwitchExpressionBracesShouldBeAnchoredAnalyzer`, `RH5206SwitchExpressionBracesShouldBeAnchoredCodeFixProvider` |
| Uses | FMT-BREAK-008, FMT-INDENT-027, SHARED-COMMENT-011 |

RH5206 reports a switch expression whose braces are not in the column of its governing expression or whose arms that start a line are not one level deeper, and offers a code fix that lays it out the way the formatter does.

## Non-goals

- Whether the arms of a switch expression share a line.
- The layout inside an arm, such as a wrapped pattern or a multi-line result.

## Requirements

### RH5206-001 — A switch expression off its anchor is reported

The analyzer MUST report a switch expression when its opening brace or its closing brace does not start in the column of the first token of its governing expression, or when an arm that starts a line with only whitespace in front of it does not start four spaces right of that column. A switch expression written on one line MUST be reported as well, because its braces are not in that column. An arm that shares a line with the arm before it MUST NOT be checked for its column, and an arm or a brace behind a comment that starts its line MUST NOT be reported for its column (SHARED-COMMENT-011).

Why: The braces of a switch expression go on lines of their own (FMT-BREAK-008), under the start of the expression that is switched on, and the arms one level deeper (FMT-INDENT-027), so the reader sees where the expression starts and ends. The rule never asks for arms to be split, so an arm behind another one has no column to check.

Example:

```csharp
class C
{
    string M(int status)
    {
        var a = {|RH5206:status switch { 0 => "Idle", _ => "Other" }|};
        var b = {|RH5206:status switch
            {
              0 => "Idle",
                _ => "Unknown"
            }|};
        var c = status switch
                {
                    0 => "Idle", 1 => "Running",
                    _ => "Unknown"
                };

        return c;
    }
}
```

### RH5206-002 — The diagnostic is on the switch expression

The analyzer MUST report one diagnostic per switch expression, located on the whole switch expression from its governing expression to its closing brace, however many of its braces and arms are misplaced.

Why: The braces and the arms are laid out together, so one diagnostic per expression matches the one fix that lays it out.

Example: see RH5206-001.

### RH5206-003 — The fix lays out the switch expression

The code fix MUST format the switch expression as the formatter formats it in place, which puts each brace on a line of its own in the column of the governing expression and indents the arms that start a line one level deeper (FMT-BREAK-008, FMT-INDENT-027). When the switch expression is part of a statement, an initializer, or an expression body, the code fix MUST format the innermost of these that contains it, so that the switch expression gets the columns the code in front of it gives it.

Why: The formatter owns the layout of switch expressions, and delegating to it applies that layout instead of a second one; the anchor column depends on the code in front of the governing expression on its line, which formatting the surrounding construct settles.

Example:

```csharp
class C
{
    string M(int status)
    {
        var a = {|RH5206:status switch
        {
            0 => "Idle",
            _ => "Other"
        }|};
        var b = {|RH5206:status switch
            {
              0 => "Idle",
                _ => "Unknown"
            }|};

        return a + b;
    }
}
```

```csharp
class C
{
    string M(int status)
    {
        var a = status switch
                {
                    0 => "Idle",
                    _ => "Other"
                };
        var b = status switch
                {
                    0 => "Idle",
                    _ => "Unknown"
                };

        return a + b;
    }
}
```
