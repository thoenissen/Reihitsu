# Analyzer — RH3003 Use string.Empty for empty strings

| | |
|---|---|
| ID prefix | RH3003 |
| Status | Active |
| Category | Clarity |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH3003UseStringEmptyForEmptyStringsAnalyzer`, `RH3003UseStringEmptyForEmptyStringsCodeFixProvider` |
| Uses | — |

RH3003 reports an empty string literal where the code does not need a constant and offers a code fix that replaces it with `string.Empty`.

## Non-goals

- An interpolated string without content, such as `$""` — RH3204 reports the `$`.
- A UTF-8 string literal such as `""u8`, which is not a `string`.

## Requirements

### RH3003-001 — An empty string literal is reported

The analyzer MUST report a regular or verbatim string literal whose value is empty, unless RH3003-002 applies.

Why: `""` is easy to miss or to misread as a space when scanning code; `string.Empty` states the intent.

Example:

```csharp
class C
{
    string _f = {|RH3003:""|};

    string M(string s)
    {
        s = {|RH3003:@""|};
        M({|RH3003:""|});
        return {|RH3003:""|} + s;
    }
}
```

### RH3003-002 — A literal where a constant is required is not reported

The analyzer MUST NOT report an empty string literal inside the initializer of a `const` field or local, a parameter's default value, an attribute argument, a `case` label, a `goto case` statement, or a constant pattern.

Why: These positions need a compile-time constant. `string.Empty` is a static field, not a constant, so the replacement would not compile.

Example:

```csharp
using System.ComponentModel;

class C
{
    const string F = "";

    [DefaultValue("")]
    void M(string s = "")
    {
        const string L = "";
        switch (s)
        {
            case "":
                goto case "x";
            case "x":
                break;
        }

        if (s is "")
        {
        }

        var b = s switch { "" => 1, _ => 2 };
    }
}
```

is not reported.

### RH3003-003 — The diagnostic is on the literal

The analyzer MUST report one diagnostic per literal, on the literal.

Why: The literal is what the fix replaces.

Example: see RH3003-001.

### RH3003-004 — The fix writes `string.Empty`

The code fix MUST replace the literal with `string.Empty` and keep the trivia in front of and after the literal.

Why: `string.Empty` has the same value as `""`, so the program does not change, and the comments around the literal belong to the code next to it.

Example:

```csharp
class C
{
    string M(string s)
    {
        var a = {|RH3003:""|};
        return /* a */ {|RH3003:""|} /* b */ + s;
    }
}
```

```csharp
class C
{
    string M(string s)
    {
        var a = string.Empty;
        return /* a */ string.Empty /* b */ + s;
    }
}
```
