# Analyzer — RH7303 Do not place regions within elements

| | |
|---|---|
| ID prefix | RH7303 |
| Status | Active |
| Category | Organization |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH7303DoNotPlaceRegionsWithinElementsAnalyzer`, `RH7303DoNotPlaceRegionsWithinElementsCodeFixProvider` |
| Uses | FMT-REGION-003, FMT-REGION-005, SHARED-BLANK-003, SHARED-FIX-007, SHARED-TYPEREGION-005 |

RH7303 reports a `#region` or `#endregion` directive inside executable code, and offers a code fix that removes the region's two directive lines and keeps the code they enclosed.

## Non-goals

- Regions that group members, types, or namespaces, and their indentation — RH7304.
- The names of regions inside executable code — the naming rules check them like any other region.
- Extracting the enclosed statements into a method. The fix only removes the directives.

## Requirements

### RH7303-001 — A region directive inside executable code is reported

The analyzer MUST report every `#region` and every `#endregion` directive inside executable code (SHARED-TYPEREGION-005), each directive on its own. A directive inside a branch that `#if` excludes is reported too.

Why: A region inside a body collapses part of an algorithm out of sight, so the reader has to expand it before the control flow can be followed. A body that needs regions to stay readable usually wants to be split into smaller methods.

Example:

```csharp
class C
{
    int P
    {
        {|RH7303:#region Accessors|}
        get { return 1; }
        {|RH7303:#endregion|}
    }

    System.Func<int> F = () =>
    {
        {|RH7303:#region Body|}
        return 1;
        {|RH7303:#endregion|}
    };

    void M()
    {
#if false
        {|RH7303:#region Inactive|}
        {|RH7303:#endregion|}
#endif
    }
}
```

### RH7303-002 — Region directives between declarations are not reported

The analyzer MUST NOT report a region directive between declarations (SHARED-TYPEREGION-005).

Why: Grouping members, types, and namespaces is what regions are for.

Example:

```csharp
#region Types
namespace N
{
    #region Classes
    class C
    {
        #region Fields
        int _a;
        #endregion
    }
    #endregion

    enum E
    {
        #region Values
        A,
        #endregion
    }
}
#endregion
```

is not reported.

### RH7303-003 — The diagnostic is on the directive

The analyzer MUST report one diagnostic per reported directive, located on the directive from its `#` to the end of its line.

Why: The `#region` and the `#endregion` are each misplaced, and each is where the user looks when the outline shows a region inside a method.

Example: see RH7303-001.

### RH7303-004 — The fix removes the region's two directive lines

For a region whose `#region` and `#endregion` are both reported, the code fix MUST remove the whole line of the reported directive and the whole line of the directive it pairs with, each with its line break, and MUST leave the code between them and every other line unchanged, apart from the blank lines that the removal leaves at the start of a body, at the end of a body, or doubled between two lines, which it removes as SHARED-FIX-007 states for a removed directive line. It MUST NOT insert a blank line, also where a statement that ends with a closing brace is followed directly by the next statement after the removal, where SHARED-BLANK-003 asks for one.

Why: The enclosed statements are the code; the region is only a heading, so removing its two directives keeps the program and drops the heading. A `#region` or `#endregion` removed on its own would leave the other unpaired, so the pair goes together. The lines around the removed directives keep the layout they had, except for a blank line the removal leaves where none belongs. A blank line the formatter would want after a closing brace is not left by the removal, so the fix does not insert it; RH5030 reports it on its own. Removing a misplaced region is the analyzer's decision to offer, never the formatter's (FMT-REGION-005).

Example:

```csharp
class C
{
    void M()
    {
        var x = 1;
        {|RH7303:#region Work|}
        x++;
        {|RH7303:#endregion // Work|}
        x--;
    }
}
```

```csharp
class C
{
    void M()
    {
        var x = 1;
        x++;
        x--;
    }
}
```

Blank lines the removal leaves doubled, or at the start and the end of a body, go:

```csharp
class C
{
    void M()
    {
        var x = 1;

        {|RH7303:#region Work|}

        x++;
        {|RH7303:#endregion // Work|}
        x--;
    }

    void N()
    {

        {|RH7303:#region Work|}
        var y = 1;
        {|RH7303:#endregion // Work|}

    }
}
```

```csharp
class C
{
    void M()
    {
        var x = 1;

        x++;
        x--;
    }

    void N()
    {
        var y = 1;
    }
}
```

The start and the end of a body are the lines behind an opening and in front of a closing brace of any construct, also of an initializer, an accessor list, or a switch statement (SHARED-FIX-007):

```csharp
class C
{
    int[] M()
    {
        return new[]
               {

                   {|RH7303:#region Values|}
                   1,
                   2
                   {|RH7303:#endregion|}

               };
    }
}
```

```csharp
class C
{
    int[] M()
    {
        return new[]
               {
                   1,
                   2
               };
    }
}
```

No blank line is inserted behind a statement that ends with a closing brace:

```csharp
class C
{
    void M(bool a)
    {
        if (a)
        {
        }
        {|RH7303:#region Work|}
        a = !a;
        {|RH7303:#endregion // Work|}
    }
}
```

```csharp
class C
{
    void M(bool a)
    {
        if (a)
        {
        }
        a = !a;
    }
}
```

### RH7303-005 — The fix is withheld for a region that reaches between declarations

The code fix MUST NOT be offered for a reported directive whose partner (FMT-REGION-003) lies between declarations (SHARED-TYPEREGION-005). The diagnostic is still reported.

Why: The partner between declarations is placed where regions belong, and the rule does not report it, so removing it would drop a directive the diagnostic is not about. Whether the region should end in the body, start at the type level, or go away is the user's decision.

Example:

```csharp
class C
{
    #region Members

    void M()
    {
        {|RH7303:#endregion|}
    }

    void N()
    {
        {|RH7303:#region Work|}
        N();
    }

    #endregion
}
```

is reported, and no code fix is offered for either directive.
