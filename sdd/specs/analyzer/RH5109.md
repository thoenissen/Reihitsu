# Analyzer — RH5109 Parameters must be on same line or separate lines

| | |
|---|---|
| ID prefix | RH5109 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5109ParametersMustBeOnSameLineOrSeparateLinesAnalyzer`, `RH5109ParametersMustBeOnSameLineOrSeparateLinesCodeFixProvider` |
| Uses | FMT-BREAK-012 |

RH5109 reports a multi-line parameter list in which two parameters start on the same line, and offers a code fix that puts every parameter on its own line.

## Non-goals

- Whether the first parameter starts on the line of the opening parenthesis — RH5108.
- The bracketed parameter list of an indexer.
- Argument lists — RH5102.

## Requirements

### RH5109-001 — Parameters sharing a line in a multi-line list are reported

The analyzer MUST report a parenthesized parameter list — of a declaration, a primary constructor, an anonymous method, or a parenthesized lambda — with at least two parameters whose opening and closing parentheses are on different lines when two of its parameters start on the same line. A parameter list on one line, and a multi-line parameter list in which every parameter starts its own line, MUST NOT be reported.

Why: A partly wrapped list hides parameters at the end of a line, so the reader cannot see at a glance how many there are; a list is either compact or one parameter per line (FMT-BREAK-012). A list counts as multi-line when anything in it wraps, a parameter's type included.

Example:

```csharp
using System.Collections.Generic;

class C
{
    void M{|RH5109:(|}int a, int b,
           int c)
    {
    }

    void N{|RH5109:(|}int a, Dictionary<int,
           int> b)
    {
    }

    void O(int a, int b)
    {
    }

    void P(int a,
           int b)
    {
    }
}
```

### RH5109-002 — The diagnostic is on the opening parenthesis

The analyzer MUST report one diagnostic per parameter list, located on its opening parenthesis, however many parameters share a line.

Why: The layout of the whole list is wrong, not one parameter; the opening parenthesis marks the list and is the anchor its parameters align to.

Example: see RH5109-001.

### RH5109-003 — The fix puts every parameter on its own line

The code fix MUST rewrite the parameter list from its opening to its closing parenthesis with the first parameter directly behind the opening parenthesis, every further parameter on a line of its own behind the comma of the previous one, aligned one column right of the opening parenthesis, and the closing parenthesis directly behind the last parameter. The text of each parameter MUST be kept as written.

Why: One parameter per line, aligned under the first one, is the layout of a wrapped parameter list (FMT-BREAK-012). Rebuilding only the list leaves the rest of the declaration as it is.

Example:

```csharp
class C
{
    void M{|RH5109:(|}int a, int b,
           int c)
    {
    }

    void N{|RH5109:(|}
        int a, int b)
    {
    }
}
```

```csharp
class C
{
    void M(int a,
           int b,
           int c)
    {
    }

    void N(int a,
           int b)
    {
    }
}
```

### RH5109-004 — A comment or directive in the parameter list withholds the fix

The code fix MUST NOT be offered when a comment or a preprocessor directive sits in front of the opening parenthesis or anywhere inside the parameter list, a documentation comment included. A comment behind the closing parenthesis MUST NOT withhold the fix. The diagnostic is still reported.

Why: The fix rebuilds the list from the text of its parameters, so a comment between them would be lost. A comment behind the closing parenthesis is outside the rebuilt text and stays where it is.

Example:

```csharp
class C
{
    void M{|RH5109:(|}int a, // first
           int b, int c)
    {
    }
}
```

is reported, and no code fix is offered. In

```csharp
class C
{
    void M{|RH5109:(|}int a, int b,
           int c) // note
    {
    }
}
```

the comment follows the closing parenthesis, and the fix is offered.
