# Analyzer — RH5010 break-Statement should be preceded by a blank line

| | |
|---|---|
| ID prefix | RH5010 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5010BreakStatementsShouldBePrecededByABlankLineAnalyzer`, `RH5010BreakStatementsShouldBePrecededByABlankLineCodeFixProvider` |
| Uses | SHARED-STMT-001, SHARED-STMT-002, SHARED-STMT-003, SHARED-STMT-004, SHARED-BLANK-004 |

RH5010 reports a `break` statement that follows another statement of the same block or switch section without a blank line between them, and offers a code fix that inserts one as SHARED-STMT-004 specifies.

## Non-goals

- Blank lines before other statement kinds — the other rules that use `shared/statement-blank-lines.md`.

## Requirements

### RH5010-001 — A `break` statement that follows a statement needs a blank line

The analyzer MUST report a `break` statement as SHARED-STMT-001, SHARED-STMT-002, and SHARED-STMT-003 specify.

Why: A `break` statement leaves a loop or a section early; the blank line makes the exit visible instead of letting it read as one more step of the body.

Example:

```csharp
class C
{
    void M()
    {
        while (true)
        {
            var shouldStop = true;
            {|RH5010:break|};
        }
    }
}
```

### RH5010-002 — The terminal `break` of a switch section is exempt

The analyzer MUST NOT report a `break` statement that SHARED-BLANK-004 exempts: the last statement owned directly by a switch section. A `break` that is not the section's last statement, or that sits inside a block the section owns, is reported as RH5010-001 specifies.

Why: The terminal `break` closes its section; a blank line in front of it would separate the section's body from its own end.

Example:

```csharp
class C
{
    void M(int choice)
    {
        switch (choice)
        {
            case 1:
                var value = choice;
                break;
            case 2:
            {
                var other = choice;
                {|RH5010:break|};
            }
        }
    }
}
```

The `break` of `case 1` is exempt; the one inside the block of `case 2` is reported.

### RH5010-003 — The diagnostic is on the `break` keyword

The analyzer MUST report the diagnostic on the `break` keyword.

Why: The keyword is where the missing separator becomes visible.

Example: see RH5010-001.
