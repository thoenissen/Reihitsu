# Analyzer — RH5046 Comments must not be placed inside a type parameter, type argument or tuple list

| | |

| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH5046CommentsMustNotBePlacedInsideTypeParameterTypeArgumentOrTupleListAnalyzer` |
| Uses | SHARED-COMMENT-001, SHARED-COMMENT-002, SHARED-COMMENT-003, SHARED-COMMENT-004, SHARED-COMMENT-005, SHARED-COMMENT-006, SHARED-COMMENT-008, SHARED-COMMENT-009 |

RH5046 reports a comment placed inside a type parameter list, a type argument list, or a tuple type.

## Non-goals

- A comment inside a function pointer type's parameter list — RH5035.
- A comment between a type parameter list and its constraint clauses.

## Requirements

### RH5046-001 — A comment inside a type parameter, type argument, or tuple type list is reported

The analyzer MUST report every ordinary comment (SHARED-COMMENT-001, SHARED-COMMENT-002) inside a type parameter list or a type argument list, from `<` to `>`, and inside a tuple type, from `(` to `)`, as SHARED-COMMENT-003, SHARED-COMMENT-004, SHARED-COMMENT-005, SHARED-COMMENT-006, SHARED-COMMENT-008, and SHARED-COMMENT-009 specify for a region. A tuple expression is not a tuple type and MUST NOT be checked.

Why: A comment inside one of these lists leaves it unclear which type it describes, and it splits the list across lines. A comment above the declaration or the statement describes it as a whole.

Example:

```csharp
using System;
using System.Collections.Generic;

class C<
    {|RH5046:// key type|}
    TKey,
    TValue>
{
    public (int First, {|RH5046:/* second */|} int Second) M()
    {
        var map = new Dictionary<
            {|RH5046:// key|}
            string,
            int>();
        _ = Array.Empty
            // element
            <int>();
        _ = map;

        return (
            // first
            1, 2);
    }
}
```

The comments `// element` and `// first` are not reported.
