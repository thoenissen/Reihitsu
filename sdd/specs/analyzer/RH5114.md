# Analyzer — RH5114 Using directives must be placed on separate lines

| | |
|---|---|
| ID prefix | RH5114 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5114UsingDirectivesMustBePlacedOnSeparateLinesAnalyzer`, `RH5114UsingDirectivesMustBePlacedOnSeparateLinesCodeFixProvider` |
| Uses | FMT-USING-003, FMT-USING-005, SHARED-USING-010 |

RH5114 reports a using directive that starts on the line on which the using directive before it ends, and offers a code fix that moves it onto a line of its own.

## Non-goals

- The order and the grouping of using directives — the ordering rules (SHARED-USING) and the formatter (FMT-USING).
- Blank lines between using directives.

## Requirements

### RH5114-001 — A using directive on the line of its predecessor is reported

The analyzer MUST report a using directive of a file, a namespace, or a file-scoped namespace — a plain, `static`, alias, or `global` directive — when its first token is on the line of the semicolon of the directive before it in the same list. A directive separated from its predecessor by a line break MUST NOT be reported, also when the line break is inside a block comment between them (FMT-USING-005).

Why: Directives that share a line are easy to overlook, and a change to one of them becomes a change to its neighbors in reviews and merges; the formatter puts each on its own line (FMT-USING-003).

Example:

```csharp
using System; {|RH5114:using System.Linq;|}
using System.Text; /* text */ {|RH5114:using System.IO;|}
using L = System.Collections.Generic.List<int>; {|RH5114:using static System.Math;|}
using System.Threading; /* a
 */ using System.Threading.Tasks;

namespace N
{
    using System.Net; {|RH5114:using System.Xml;|}

    class C
    {
    }
}
```

### RH5114-002 — The diagnostic is on the directive

The analyzer MUST report one diagnostic per directive that shares the line, located on the whole directive. On a line with three directives, the second and the third are reported.

Why: Each directive after the first has to move to a line of its own.

Example:

```csharp
using System; {|RH5114:using System.Linq;|} {|RH5114:using System.Text;|}

class C
{
}
```

### RH5114-003 — The fix moves the directive onto its own line

The code fix MUST replace the whitespace between the two directives with a line break followed by the indentation of SHARED-USING-010, keep a comment that trails the previous directive on that directive's line, and drop the whitespace in front of the moved directive. It MUST NOT reorder directives or insert a blank line.

Why: The comment behind the first directive describes it, so it stays with it. Ordering and grouping are other rules' concern, so splitting the line changes nothing else.

Example:

```csharp
using System; {|RH5114:using System.Linq;|}
using System.Text; /* text */ {|RH5114:using System.IO;|}

namespace N
{
    using System.Net; {|RH5114:using System.Xml;|}

    class C
    {
    }
}
```

```csharp
using System;
using System.Linq;
using System.Text; /* text */
using System.IO;

namespace N
{
    using System.Net;
    using System.Xml;

    class C
    {
    }
}
```
