# Analyzer — RH5517 Field attributes must be on their own line

| | |
|---|---|
| ID prefix | RH5517 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5517FieldAttributesMustFollowPlacementRulesAnalyzer`, `RH5517FieldAttributesMustFollowPlacementRulesCodeFixProvider` |
| Uses | SHARED-ATTR-001, SHARED-ATTR-002, SHARED-ATTR-003, SHARED-ATTR-004, SHARED-ATTR-005, SHARED-ATTR-006, SHARED-ATTR-007, SHARED-ATTR-008, SHARED-ATTR-009, SHARED-ATTR-011, SHARED-ATTR-012 |

RH5517 reports an attribute list of a field or enum member that shares its line with the token after it, and offers a code fix that moves that token onto the next line. The rule uses `shared/attribute-targets.md`.

## Non-goals

- Attributes of the enum itself — RH5509.
- A `field:` list on a positional record parameter — RH5523.

## Requirements

### RH5517-001 — Field attribute lists are on their own line

The analyzer MUST check every attribute list that resolves to the field target (SHARED-ATTR-001, SHARED-ATTR-002, SHARED-ATTR-003): the lists of a field declaration or an enum member without a specifier or with `type:`, and every list with the `field:` specifier that is not attached to a parameter or type parameter, and MUST report such a list whose closing bracket shares its line with the first token after it, as SHARED-ATTR-004, SHARED-ATTR-005, and SHARED-ATTR-006 specify for a list that must be on its own line.

Why: Fields are read as a block of declarations, one type-and-name pair per line; an attribute in front of one field pushes it to the right of its neighbors.

Example:

```csharp
class C
{
    {|RH5517:[A]|} int _a, _b;

    {|RH5517:[field: A]|} int P { get; set; }

    [A]
    int _c;
}

enum E
{
    {|RH5517:[A]|} V,
    W
}

record R([field: A] int Id);
```

### RH5517-002 — The diagnostic is on the attribute list

The analyzer MUST report the diagnostic on the attribute list, as SHARED-ATTR-007 specifies.

Why: The list is what is misplaced; each list of a declaration is reported and fixed on its own.

Example: see RH5517-001.

### RH5517-003 — The fix moves what follows onto the next line

The code fix MUST put the first token after the list on a new line, as SHARED-ATTR-008 and SHARED-ATTR-009 specify.

Why: The fix makes only the change the diagnostic asks for: what follows the list starts on its own line.

Example:

```csharp
class C
{
    {|RH5517:[A]|} int _a;
}
```

```csharp
class C
{
    [A]
    int _a;
}
```

### RH5517-004 — The fix is withheld for comments, directives, and missing braces

The code fix MUST NOT be offered when SHARED-ATTR-011 or SHARED-ATTR-012 withholds it. The diagnostic is still reported.

Why: A comment inside the list belongs to the attribute next to it, and an unclosed scope leaves no indentation to compute; both are left to the author.

Example:

```csharp
class C
{
    {|RH5517:[A /* c */]|} int _a;
}
```

is reported, and no code fix is offered.
