# Analyzer — RH5512 Constructor attribute lists must use one attribute per list

| | |
|---|---|
| ID prefix | RH5512 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5512ConstructorAttributeListsMustFollowShapeRulesAnalyzer`, `RH5512ConstructorAttributeListsMustFollowShapeRulesCodeFixProvider` |
| Uses | SHARED-ATTR-001, SHARED-ATTR-013, SHARED-ATTR-016, SHARED-ATTR-017, SHARED-ATTR-019 |

RH5512 reports an attribute list of a constructor that holds more than one attribute, and offers a code fix that gives each attribute a list of its own. The rule uses `shared/attribute-targets.md`.

## Non-goals

- Attributes of methods and destructors — RH5514.
- Where a constructor attribute list is placed — RH5511.

## Requirements

### RH5512-001 — Constructor attribute lists hold one attribute

The analyzer MUST check every attribute list that resolves to the constructor target: the lists of a constructor declaration, instance or static, without a specifier or with `type:` (SHARED-ATTR-001), and MUST report such a list that holds more than one attribute, as SHARED-ATTR-013 specifies.

Why: Attributes on a constructor are independent decisions — a dependency-injection marker, an obsolescence notice — and a diff that changes one of them should not restate the others.

Example:

```csharp
class C
{
    {|RH5512:[A, B]|}
    C()
    {
    }

    {|RH5512:[A, B]|}
    static C()
    {
    }
}
```

### RH5512-002 — The diagnostic is on the attribute list

The analyzer MUST report the diagnostic on the attribute list, as SHARED-ATTR-016 specifies.

Why: The list is what has the wrong shape; each list of a declaration is reported and fixed on its own.

Example: see RH5512-001.

### RH5512-003 — The fix gives each attribute a list of its own

The code fix MUST replace the list with one list per attribute, each on its own line, as SHARED-ATTR-017 specifies.

Why: The fix makes only the change the diagnostic asks for: the attributes keep their order and their specifier, and each gets a line of its own.

Example:

```csharp
class C
{
    {|RH5512:[A, B]|}
    C()
    {
    }
}
```

```csharp
class C
{
    [A]
    [B]
    C()
    {
    }
}
```

### RH5512-004 — The fix is withheld for a comment or directive inside the list

The code fix MUST NOT be offered when SHARED-ATTR-019 withholds it. The diagnostic is still reported.

Why: A comment inside the list belongs to the attribute next to it, and only the author can tell which of the new lists it belongs to.

Example:

```csharp
class C
{
    {|RH5512:[A, /* c */ B]|}
    C()
    {
    }
}
```

is reported, and no code fix is offered.
