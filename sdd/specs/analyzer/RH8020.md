# Analyzer — RH8020 Non-private methods must be documented

| | |
|---|---|
| ID prefix | RH8020 |
| Status | Active |
| Category | Documentation |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH8020NonPrivateMethodsMustBeDocumentedAnalyzer` |
| Uses | SHARED-DOC-001, SHARED-DOC-002, SHARED-DOC-004, SHARED-DOC-005, SHARED-DOC-006, SHARED-DOC-007, SHARED-DOC-008, SHARED-DOC-009 |

RH8020 reports a method in the non-private group that has no `<summary>` or `<inheritdoc>` documentation.

## Non-goals

- Methods in the private group — RH8021.
- Operators and conversion operators — RH8034; constructors and destructors — RH8017 to RH8019.
- Whether the summary has text — RH8030; the documentation of parameters, type parameters, and return values — RH8101, RH8105, and RH8108.

## Requirements

### RH8020-001 — Undocumented non-private methods are reported

The analyzer MUST report every method declaration in the non-private group of SHARED-DOC-002 that is not documented, checked as SHARED-DOC-001 specifies, except an explicit interface implementation, which SHARED-DOC-009 exempts. A method declaration is a method declared in the body of a class, struct, interface, record, record struct, or extension block — abstract, virtual, override, static, and generic methods included; a local function is not one. Whether it is documented MUST be decided as SHARED-DOC-004, SHARED-DOC-005, SHARED-DOC-006, and SHARED-DOC-007 specify, and nothing is reported when SHARED-DOC-008 applies.

Why: A method that other code can call is part of the contract that code builds on. Without a summary, the generated documentation and the editor's tooltip show nothing, and readers have to infer what the method does from its implementation. An override is reported like any other method; `<inheritdoc/>` documents it without repeating the base description.

Example:

```csharp
/// <summary>
/// Service
/// </summary>
public class Service
{
    public void {|RH8020:Run|}()
    {
    }

    /// <remarks>
    /// No summary
    /// </remarks>
    protected virtual int {|RH8020:Compute|}<T>(T value) => 0;

    internal static void {|RH8020:Reset|}()
    {
    }

    public override string {|RH8020:ToString|}() => "";

    /// <inheritdoc/>
    public override int GetHashCode() => 0;

    /// <summary>
    /// Stops the service
    /// </summary>
    public void Stop()
    {
        void Local()
        {
        }

        Local();
    }

    private void Hidden()
    {
    }
}

/// <summary>
/// Contract
/// </summary>
public interface IContract
{
    void {|RH8020:Execute|}();
}

/// <summary>
/// Extensions
/// </summary>
public static class Extensions
{
    /// <summary>
    /// Text values
    /// </summary>
    /// <param name="value">Value</param>
    extension(string value)
    {
        public int {|RH8020:WordCount|}() => 0;

        int Hidden() => 0;
    }
}
```

### RH8020-002 — The diagnostic is on the method name

The analyzer MUST report one diagnostic per undocumented method declaration, located on its identifier, without its type parameter list.

Why: The name is what the documentation describes; marking it identifies the declaration without marking its whole body.

Example: see RH8020-001.
