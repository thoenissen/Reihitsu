# Analyzer — RH5302 Logical expressions should be formatted correctly

| | |
|---|---|
| ID prefix | RH5302 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5302LogicalExpressionsShouldBeFormattedCorrectlyAnalyzer`, `RH5302LogicalExpressionsShouldBeFormattedCorrectlyCodeFixProvider` |
| Uses | FMT-BREAK-001, FMT-BREAK-017, FMT-INDENT-018 |

RH5302 reports a `&&` or `||` operator that ends a line or that starts a line outside the column of its left operand, and offers a code fix that lays out the chain of logical operators the way the formatter does.

## Non-goals

- Other binary operators, such as `&`, `|`, `+`, and `??`, and the pattern combinators `and` and `or`.
- The layout of an operand that spans several lines.

## Requirements

### RH5302-001 — An operator at the end of a line is reported

The analyzer MUST report a `&&` or `||` operator that is on the line its left operand ends on while its right operand starts on a later line. A logical expression on one line MUST NOT be reported.

Why: An operator at the end of a line is easy to miss; at the start of the continuation line it shows at a glance how the line continues the condition (FMT-BREAK-017).

Example:

```csharp
class C
{
    bool M(bool a, bool b, bool c)
    {
        var x = a {|RH5302:&&|}
                b;
        var y = a && b || c;

        return x;
    }
}
```

### RH5302-002 — An operator that starts a line outside its column is reported

The analyzer MUST report a `&&` or `||` operator that starts a line below the end of its left operand when it does not start at the column of the first token of that left operand. Each operator is measured against its own left operand: in `a || b && c`, the left operand of `&&` is `b`. A `&&` or `||` operator that starts a line at that column, followed by its right operand on the same line, MUST NOT be reported.

Why: Operators at the column of the first operand line up under it, so the structure of a long condition reads from the left edge (FMT-INDENT-018). An operator that binds tighter belongs to its own left operand and aligns with it.

Example:

```csharp
class C
{
    bool M(bool a, bool b, bool c)
    {
        var x = a
            {|RH5302:|||} b;
        var y = a
                && b
                && c;
        var z = a
                || b
                   && c;

        return x;
    }
}
```

### RH5302-003 — The diagnostic is on the operator

The analyzer MUST report one diagnostic per misplaced operator, located on the operator token.

Why: The operator is what has to move; each operator of a chain is placed on its own.

Example: see RH5302-001 and RH5302-002.

### RH5302-004 — The fix lays out the whole chain

The code fix MUST format the outermost chain of `&&` and `||` operators that contains the reported operator as the formatter formats it in place: every operator of the chain starts its continuation line at the column of its left operand (FMT-BREAK-017, FMT-INDENT-018). One application therefore corrects every operator of the chain.

Why: The operators of one chain are laid out together; fixing one of them at a time would leave the chain half-converted and need one application per operator.

Example:

```csharp
class C
{
    void M(bool a, bool b, bool c)
    {
        if (a {|RH5302:&&|}
            b {|RH5302:|||}
            c)
        {
        }
    }
}
```

```csharp
class C
{
    void M(bool a, bool b, bool c)
    {
        if (a
            && b
            || c)
        {
        }
    }
}
```

### RH5302-005 — A comment behind an operator at the end of a line withholds the fix

The code fix MUST NOT be offered for an operator reported under RH5302-001 when a comment or a preprocessor directive sits between the operator and its right operand, in the operator's trailing trivia or in the right operand's leading trivia. A comment in front of the operator MUST NOT withhold the fix. The diagnostic is still reported.

Why: Moving the right operand up to the operator would move the comment or the directive with it, and the formatter refuses that join (FMT-BREAK-001). A comment in front of the operator stays where it is when the operator moves to the next line.

Example:

```csharp
class C
{
    bool M(bool a, bool b)
    {
        var x = a {|RH5302:&&|} // note
                b;

        return x;
    }
}
```

is reported, and no code fix is offered. In

```csharp
class C
{
    bool M(bool a, bool b)
    {
        var x = a /* note */ {|RH5302:&&|}
                b;

        return x;
    }
}
```

the comment is in front of the operator, and the fix is offered:

```csharp
class C
{
    bool M(bool a, bool b)
    {
        var x = a /* note */
                && b;

        return x;
    }
}
```
