# Analyzer — RH5302 Logical expressions should be formatted correctly

| | |
|---|---|
| ID prefix | RH5302 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5302LogicalExpressionsShouldBeFormattedCorrectlyAnalyzer`, `RH5302LogicalExpressionsShouldBeFormattedCorrectlyCodeFixProvider` |
| Uses | FMT-BREAK-017, FMT-INDENT-018, FMT-UNSUP-007, FMT-UNSUP-011, SHARED-COMMENT-011, SHARED-FIX-010 |

RH5302 reports a `&&` or `||` operator that ends a line or that starts a line outside the column of its left operand, and offers a code fix that lays out the chain of logical operators the way the formatter does.

## Non-goals

- Other binary operators, such as `&`, `|`, `+`, and `??`, and the pattern combinators `and` and `or`.
- The layout of an operand that spans several lines.

## Requirements

### RH5302-001 — An operator at the end of a line is reported

The analyzer MUST report a `&&` or `||` operator that is on the line its left operand ends on while its right operand starts on a later line. A logical expression on one line MUST NOT be reported.

Why: An operator at the end of a line is easy to miss; at the start of the continuation line it shows at a glance how the line continues the condition (FMT-BREAK-017).

Example:

```csharp
class C
{
    bool M(bool a, bool b, bool c)
    {
        var x = a {|RH5302:&&|}
                b;
        var y = a && b || c;

        return x;
    }
}
```

### RH5302-002 — An operator that starts a line outside its column is reported

The analyzer MUST report a `&&` or `||` operator that starts a line below the end of its left operand when it does not start at the column of the first token of that left operand. Each operator is measured against its own left operand: in `a || b && c`, the left operand of `&&` is `b`. A `&&` or `||` operator that starts a line at that column, followed by its right operand on the same line, MUST NOT be reported. A line that starts with a comment is judged as SHARED-COMMENT-011 specifies.

Why: Operators at the column of the first operand line up under it, so the structure of a long condition reads from the left edge (FMT-INDENT-018). An operator that binds tighter belongs to its own left operand and aligns with it.

Example:

```csharp
class C
{
    bool M(bool a, bool b, bool c)
    {
        var x = a
            {|RH5302:|||} b;
        var y = a
                && b
                && c;
        var z = a
                || b
                   && c;

        return x;
    }
}
```

### RH5302-003 — The diagnostic is on the operator

The analyzer MUST report one diagnostic per misplaced operator, located on the operator token.

Why: The operator is what has to move; each operator of a chain is placed on its own.

Example: see RH5302-001 and RH5302-002.

### RH5302-004 — The fix lays out the whole chain

The code fix MUST format the outermost chain of `&&` and `||` operators that contains the reported operator as the formatter formats it in place: every operator of the chain starts its continuation line at the column of its left operand (FMT-BREAK-017, FMT-INDENT-018). One application therefore corrects every operator of the chain.

Why: The operators of one chain are laid out together; fixing one of them at a time would leave the chain half-converted and need one application per operator.

Example:

```csharp
class C
{
    void M(bool a, bool b, bool c)
    {
        if (a {|RH5302:&&|}
            b {|RH5302:|||}
            c)
        {
        }
    }
}
```

```csharp
class C
{
    void M(bool a, bool b, bool c)
    {
        if (a
            && b
            || c)
        {
        }
    }
}
```

### RH5302-005 — The fix is withheld for a comment or directive behind an operator

The code fix MUST NOT be offered when the chain it formats (RH5302-004) holds a binary expression with a comment, a directive, or disabled text between its operator and its right operand: the formatter refuses the chain (FMT-UNSUP-011), and the fix asks it before it is offered (FMT-UNSUP-007, SHARED-FIX-010). This holds for the reported operator, for every other operator of the chain, and for every binary operator inside an operand of the chain, whether the operator ends its line or starts it. The diagnostic is still reported. A comment in front of an operator, behind its left operand or on the line above the operator's line, does not withhold the fix, and neither does a comment behind an operator outside the chain.

Why: The comment keeps the right operand off the operator's line, so the layout the rule asks for cannot be written without moving the comment, and where it belongs is the author's decision. The formatter declares the shape unsupported, so the fix needs no guard of its own for it. A comment in front of the operator stays where it is when the operator moves to the start of the next line.

Example — each operator is reported, and no code fix is offered for any of them:

```csharp
class C
{
    bool M(bool a, bool b, bool c, int n)
    {
        var x = a {|RH5302:&&|} // note
                b;
        var y = a
            {|RH5302:&&|} /* note */ b;

        if (a {|RH5302:&&|}
            b {|RH5302:&&|} // note
            c)
        {
        }

        if (n + /* note */ 1 > 2 {|RH5302:&&|}
            b)
        {
        }

        return x && y;
    }
}
```

In front of the operator, the comment does not withhold the fix:

```csharp
class C
{
    bool M(bool a, bool b)
    {
        var x = a /* note */ {|RH5302:&&|}
                b;

        return x;
    }
}
```

```csharp
class C
{
    bool M(bool a, bool b)
    {
        var x = a /* note */
                && b;

        return x;
    }
}
```

Outside the chain, a comment behind an operator does not withhold the fix either:

```csharp
class C
{
    void M(bool a, bool b, int n)
    {
        N(a {|RH5302:&&|}
          b, n + /* note */ 1);
    }

    void N(bool v, int w)
    {
    }
}
```

```csharp
class C
{
    void M(bool a, bool b, int n)
    {
        N(a
          && b, n + /* note */ 1);
    }

    void N(bool v, int w)
    {
    }
}
```
