# Analyzer — RH5103 Code must not contain multiple statements on one line

| | |
|---|---|
| ID prefix | RH5103 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5103CodeMustNotContainMultipleStatementsOnOneLineAnalyzer`, `RH5103CodeMustNotContainMultipleStatementsOnOneLineCodeFixProvider` |
| Uses | FMT-BREAK-006, FMT-INDENT-003 |

RH5103 reports a statement that starts on the same line as the statement before it in the same block or switch section, and offers a code fix that moves it onto a line of its own.

## Non-goals

- A comment behind a statement — RH5104.
- The embedded statement of `if`, `while`, `for`, `foreach`, `using`, `lock`, `fixed`, and `do`, which is not part of a block's statement list.
- Declarations other than statements, such as two members on one line.

## Requirements

### RH5103-001 — A statement that starts on the line of its predecessor is reported

The analyzer MUST report a statement of a block or of a switch section that starts on the line on which the closest preceding statement of the same list starts, where an empty statement (`;`) is skipped both as the reported statement and as its predecessor. The first statement of a switch section MUST NOT be reported for sharing the line of its `case` label.

Why: One statement per line keeps every statement visible at the left margin and gives each its own line in diffs and stack traces; the formatter writes the same layout (FMT-BREAK-006). The label introduces the section's statements and is not one of them.

Example:

```csharp
class C
{
    void N(int x)
    {
        M(); {|RH5103:M();|}
        M(); ; {|RH5103:M();|}
        ; M();
        switch (x)
        {
            case 1: M(); {|RH5103:break;|}
        }
    }

    void M()
    {
    }
}
```

### RH5103-002 — The diagnostic is on the later statement

The analyzer MUST report one diagnostic for each reported statement, located on the whole statement. On a line with three statements, the second and the third are reported.

Why: Each statement after the first has to move to a line of its own, so each gets its own diagnostic and its own fix.

Example:

```csharp
class C
{
    void N()
    {
        M(); {|RH5103:M();|} {|RH5103:M();|}
    }

    void M()
    {
    }
}
```

### RH5103-003 — The fix moves the statement onto its own line

The code fix MUST replace the whitespace in front of the reported statement with a line break and an indentation, and MUST NOT change anything else. When the preceding statement starts its line, the indentation MUST be that of the preceding statement's line. In a switch section, when the preceding statement does not start its line and the line on which it starts is indented as its scope depth requires, the moved statement MUST be indented to the section's statement column, one level deeper than the section's labels (FMT-INDENT-003) — also when that line starts with a comment, with the label of another section, or with a statement of another section. This requirement does not cover a label that spans several lines, a label on the line of the switch statement's opening brace, and a line that is not indented as its scope depth requires.

Why: The moved statement belongs to the same list as its predecessor, so it takes its predecessor's column. When the predecessor shares its line with something else, the line's indentation may belong to a label or to another section, not to the statements of this section, so the section's statement column is used.

Example:

```csharp
class C
{
    void N(int x)
    {
        M(); {|RH5103:M();|}
        switch (x)
        {
            case 1: M(); {|RH5103:break;|}
            case 2:
                M(); {|RH5103:break;|}
            /* three */ case 3: M(); {|RH5103:break;|}
            case 4: break; case 5: M(); {|RH5103:break;|}
            case 6:
                break; case 7: M(); {|RH5103:break;|}
        }
    }

    void M()
    {
    }
}
```

```csharp
class C
{
    void N(int x)
    {
        M();
        M();
        switch (x)
        {
            case 1: M();
                break;
            case 2:
                M();
                break;
            /* three */ case 3: M();
                break;
            case 4: break; case 5: M();
                break;
            case 6:
                break; case 7: M();
                break;
        }
    }

    void M()
    {
    }
}
```

### RH5103-004 — Anything but whitespace in front of the statement withholds the fix

The code fix MUST NOT be offered when the gap between the preceding statement and the reported one holds anything but spaces and tabs — a comment, a preprocessor directive, disabled text, or an empty statement. The diagnostic is still reported.

Why: Splitting the line would have to decide whether the comment belongs to the statement before or after it, or where a stray `;` goes; only the author can decide that.

Example:

```csharp
class C
{
    void N()
    {
        M(); /* next */ {|RH5103:M();|}
        M(); ; {|RH5103:M();|}
    }

    void M()
    {
    }
}
```

is reported, and no code fix is offered.
