# Analyzer — RH5307 Indexer bracketed arguments should be single lined

| | |
|---|---|
| ID prefix | RH5307 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5307IndexerBracketedArgumentsShouldBeSingleLinedAnalyzer`, `RH5307IndexerBracketedArgumentsShouldBeSingleLinedCodeFixProvider` |
| Uses | FMT-BREAK-001, FMT-BREAK-014, SHARED-FIX-006 |

RH5307 reports the argument list of an element access (`m[1, 2]`) whose brackets are on different lines, and offers a code fix that joins it onto one line the way the formatter does.

## Non-goals

- Bracketed lists that are not the arguments of an element access, such as attribute lists, array rank specifiers, collection expressions, and list patterns.
- Parenthesized argument lists — RH5101 and RH5102.

## Requirements

### RH5307-001 — A wrapped element access is reported

The analyzer MUST report the bracketed argument list of an element access (`m[…]`) and of an implicit element access inside an object initializer (`[…] = value`) when its opening and its closing bracket are on different lines, provided that no comment and no preprocessor directive sits between the two brackets and that every argument is on one line. An argument list on one line MUST NOT be reported, and a comment behind the closing bracket MUST NOT keep the argument list from being reported. The argument list of a null-conditional element access (`c?[…]`) MUST NOT be reported: in the syntax tree it belongs to an element binding expression, not to an element access, and it is not part of the rule.

Why: An index is short by nature and reads as part of the access expression; wrapping it breaks up the expression without making it clearer (FMT-BREAK-014).

Example:

```csharp
using System.Collections.Generic;

class C
{
    void M(int[,] m)
    {
        var a = {|RH5307:m[1,
                  2]|};
        var b = {|RH5307:m[1,
                  2]|}; // note
        var c = m[1, 2];
        var d = new Dictionary<int, int>
                {
                    {|RH5307:[1
                    ]|} = 2
                };
    }
}
```

Example — a null-conditional element access:

```csharp
class C
{
    void M(int[,] c)
    {
        var a = c?[1,
                   2];
    }
}
```

is not reported.

### RH5307-002 — A wrapped element access the formatter cannot join is not reported

The analyzer MUST NOT report a bracketed argument list when a comment or a preprocessor directive sits between its two brackets, or when one of its arguments spans several lines.

Why: Joining the list would move the comment or the directive into the middle of a line, and the formatter refuses that join (FMT-BREAK-001); an argument that spans several lines cannot be on one line with the brackets, and the formatter leaves such a list as it is (FMT-BREAK-014).

Example:

```csharp
class C
{
    void M(int[,] m)
    {
        var a = m[1, // note
                  2];
        var b = m[N(1,
                    2), 3];
    }

    int N(int a, int b) => a;
}
```

is not reported.

### RH5307-003 — Where the diagnostic is

The analyzer MUST report one diagnostic per argument list, located on the whole element access expression, or, for an implicit element access inside an initializer, on the bracketed argument list.

Why: The access expression is the unit the reader sees; an implicit element access has nothing in front of its brackets.

Example: see RH5307-001.

### RH5307-004 — The fix joins the reported argument list

The code fix MUST join the argument list the diagnostic reports — the one the diagnostic is located on (RH5307-003) — onto one line as the formatter joins it: the brackets and the arguments on the line of the opening bracket, separated by a comma and a space (FMT-BREAK-014). Which list that is MUST NOT depend on the receiver of the element access or on what contains it: the receiver may itself be an element access (`j[0][…]`), an element binding (`c?[0][…]`), a member access that starts with one (`a[0].P[0][…]`), or `this` (`this[0][…]`), and the element access may stand inside the argument list of another element access, element binding, or implicit element access (`x[m[…]]`, `c?[m[…]]`, `[m[…]] = 1`), inside a parenthesized argument list, or as an element of a collection expression. An argument list in the receiver, or one that contains the element access, is not the reported list: the fix MUST NOT join it, also where it is wrapped, and a comment in it or an argument of it that spans several lines MUST NOT keep the fix from being offered. Where that list is reported as well, its own diagnostic gets its own fix, and fixing all diagnostics joins both lists. A comment behind the closing bracket stays behind it. The fix MUST change only the argument list: the element access, and the statement, initializer, expression body, or argument that contains it, MUST stay as written apart from it (SHARED-FIX-006) — the receiver, the code in front of the element access on its line, and the code behind the closing bracket — also where formatting the document would change it.

Why: The formatter owns the layout of bracketed argument lists; delegating to it applies that layout instead of a second one. The fix corrects the finding it is offered for, so it judges and joins the list that finding names; a list around it or in front of it is a finding of its own or none at all. A fix that joined another list would leave its own diagnostic in place.

Example:

```csharp
class C
{
    void M(int[,] m)
    {
        var a = {|RH5307:m[
            1, 2]|};
        var b = {|RH5307:m[1,
                  2]|}; // note
    }
}
```

```csharp
class C
{
    void M(int[,] m)
    {
        var a = m[1, 2];
        var b = m[1, 2]; // note
    }
}
```

Example — the reported list inside another argument list, and behind a receiver that is an element access:

```csharp
class C
{
    void M(int[] x, int[,] m, int[][,] j)
    {
        var a = x[{|RH5307:m[1,
                    2]|}];
        var b = {|RH5307:j[0][1,
                     2]|};
        var c = {|RH5307:j[0 /* c */][1,
                             2]|};
        var d = {|RH5307:j[N(1,
                    2)][1,
                        2]|};
        var p = x[/* c */ {|RH5307:m[1,
                            2]|}];
    }

    int N(int a, int b) => a;
}
```

```csharp
class C
{
    void M(int[] x, int[,] m, int[][,] j)
    {
        var a = x[m[1, 2]];
        var b = j[0][1, 2];
        var c = j[0 /* c */][1, 2];
        var d = j[N(1,
                    2)][1, 2];
        var p = x[/* c */ m[1, 2]];
    }

    int N(int a, int b) => a;
}
```

In `d`, the receiver's list, whose argument spans two lines, is not reported (RH5307-002) and stays as written; in `c` and `p`, the comment in the other list does not keep the reported list from being joined, and in `p` the space behind it stays (SHARED-FIX-006).

Example — the reported list behind an element binding, a member access, or `this`, and inside an element binding or an implicit element access:

```csharp
using System.Collections.Generic;

class D
{
    public int[][,] P;
}

class C
{
    int[,] this[int i] => null;

    void M(int[][,] c, int[] n, int[,] m, D[] a)
    {
        var e = c?{|RH5307:[0][1,
                      2]|};
        var h = n?[{|RH5307:m[1,
                     2]|}];
        var i = {|RH5307:a[0].P[0][1,
                          2]|};
        var j = {|RH5307:this[0][1,
                        2]|};
        var d = new Dictionary<int, int>
                {
                    [{|RH5307:m[1,
                       2]|}] = 1,
                };
    }
}
```

```csharp
using System.Collections.Generic;

class D
{
    public int[][,] P;
}

class C
{
    int[,] this[int i] => null;

    void M(int[][,] c, int[] n, int[,] m, D[] a)
    {
        var e = c?[0][1, 2];
        var h = n?[m[1, 2]];
        var i = a[0].P[0][1, 2];
        var j = this[0][1, 2];
        var d = new Dictionary<int, int>
                {
                    [m[1, 2]] = 1,
                };
    }
}
```

In `e`, the element access `[0][1,⏎2]` belongs to the element binding `c?[0]`, so its list is reported although the list of `?[0]` is not (RH5307-001).

Example — the reported list and the list of its receiver are both reported:

```csharp
class C
{
    void M(int[,][,] j)
    {
        var n = {|RH5307:{|RH5307:j[0,
                  1]|}[1,
                     2]|};
    }
}
```

```csharp
class C
{
    void M(int[,][,] j)
    {
        var n = j[0, 1][1, 2];
    }
}
```

Each diagnostic's fix joins its own list; applying one fix after the other, or fixing all diagnostics at once, gives the output above.

Example — the reported list as the argument of an invocation, as an element of a collection expression, and behind a parenthesized or member-binding receiver:

```csharp
class E
{
    public int[,] P;
}

class C
{
    void M(int[,] m, int[][,] j, E c)
    {
        N({|RH5307:m[1,
            2]|});
        int[] l = [{|RH5307:m[1,
                     2]|}];
        var o = {|RH5307:(j[0])[1,
                       2]|};
        var g = c?{|RH5307:.P[1,
                     2]|};
    }

    void N(int a)
    {
    }
}
```

```csharp
class E
{
    public int[,] P;
}

class C
{
    void M(int[,] m, int[][,] j, E c)
    {
        N(m[1, 2]);
        int[] l = [m[1, 2]];
        var o = (j[0])[1, 2];
        var g = c?.P[1, 2];
    }

    void N(int a)
    {
    }
}
```

The collection expression stays as written, also where formatting the document would break it over several lines (SHARED-FIX-006).
