# Analyzer — RH5044 Comments must not be placed inside an attribute list

| | |
|---|---|
| ID prefix | RH5044 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH5044CommentsMustNotBePlacedInsideAttributeListAnalyzer` |
| Uses | SHARED-COMMENT-001, SHARED-COMMENT-002, SHARED-COMMENT-003, SHARED-COMMENT-004, SHARED-COMMENT-005, SHARED-COMMENT-006, SHARED-COMMENT-008, SHARED-COMMENT-009 |

RH5044 reports a comment placed inside an attribute list, between its brackets.

## Non-goals

- A comment between an attribute list and its declaration — RH5033.
- How many attributes one list holds — the attribute rules of the RH55xx range.

## Requirements

### RH5044-001 — A comment inside an attribute list is reported

The analyzer MUST report every ordinary comment (SHARED-COMMENT-001, SHARED-COMMENT-002) inside an attribute list, including its target specifier and the arguments of its attributes, as SHARED-COMMENT-003, SHARED-COMMENT-004, SHARED-COMMENT-005, SHARED-COMMENT-006, SHARED-COMMENT-008, and SHARED-COMMENT-009 specify for a region. The region runs from the opening to the closing bracket, for the attribute lists of declarations and for file-level `assembly:` and `module:` attribute lists alike.

Why: A comment inside an attribute list leaves it unclear which attribute it describes, and it splits the list across lines. A comment above the list describes the attributes as a whole.

Example:

```csharp
using System;

[assembly: {|RH5044:/* compliance */|} CLSCompliant(false)]

// serialization
[
    {|RH5044:// serialization|}
    Serializable,
    Obsolete {|RH5044:/* obsolete */|}]
class C
{
    [Obsolete("Use "
        // version
        + "N")]
    void M()
    {
    }
}
```

The comments `// serialization` before the list and `// version` are not reported.
