# Analyzer — RH5401 Expression style get-only properties should be single lined

| | |
|---|---|
| ID prefix | RH5401 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5401ExpressionStyleGetOnlyPropertiesShouldBeSingleLinedAnalyzer`, `RH5401ExpressionStyleGetOnlyPropertiesShouldBeSingleLinedCodeFixProvider` |
| Uses | FMT-BREAK-026 |

RH5401 reports an expression-bodied property whose `=>` or the start of whose expression is not on the line of the property's name, and offers a code fix that puts the property on one line the way the formatter does when it fits there.

## Non-goals

- Properties with an accessor list, also when an accessor has an expression body (`get => 1;`).
- Expression-bodied indexers, methods, operators, and other members.
- The layout of the expression after its first token.

## Requirements

### RH5401-001 — An arrow or expression below the name is reported

The analyzer MUST report a property with an expression body when its `=>` is not on the line of the property's name, or when the first token of its expression is not on that line. A property whose `=>` and first expression token are on the line of its name MUST NOT be reported, also when the expression continues on later lines.

Why: An expression-bodied property is a one-line declaration by intent; a wrapped arrow makes the reader look at the next line to see what the property returns (FMT-BREAK-026). An expression that starts on the name's line already says what the property computes, so its continuation may wrap.

Example:

```csharp
class C
{
    {|RH5401:int A
        => 1;|}

    {|RH5401:int B =>
        1;|}

    int D => 1
             + 2;
}
```

### RH5401-002 — The diagnostic is on the property

The analyzer MUST report one diagnostic per property, located on the whole property declaration, its attribute lists and modifiers included.

Why: The declaration is laid out as a whole, so the diagnostic covers the construct the fix lays out.

Example:

```csharp
using System;

class C
{
    {|RH5401:[Obsolete]
    int A
        => 1;|}
}
```

### RH5401-003 — The fix puts the property on one line

For a property without attribute lists, the code fix MUST format the property as the formatter formats it in place, which puts the `=>` and the expression on the line of the property's name (FMT-BREAK-026).

Why: The formatter owns the layout of expression-bodied properties; delegating to it applies that layout instead of a second one.

Example:

```csharp
class C
{
    {|RH5401:int A
        => 1;|}

    {|RH5401:int B =>
        1;|}
}
```

```csharp
class C
{
    int A => 1;

    int B => 1;
}
```

### RH5401-004 — The fix is withheld when the property stays on several lines

For a property without attribute lists, the code fix MUST NOT be offered when the property, laid out by the formatter, would still span several lines: when its expression stays wrapped, or when a comment or a preprocessor directive keeps the `=>` or the expression on a later line. The diagnostic is still reported.

Why: The fix promises a one-line property. Where the formatter keeps the property on several lines, applying it would leave the expression in a shape the author did not choose without clearing the diagnostic; the author moves the arrow and the first token by hand.

Example:

```csharp
class C
{
    {|RH5401:int A =>
        1
        + 2;|}

    {|RH5401:int B // note
        => 1;|}
}
```

is reported, and no code fix is offered.
