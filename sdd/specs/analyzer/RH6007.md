# Analyzer — RH6007 Opening square brackets must be spaced correctly

| | |
|---|---|
| ID prefix | RH6007 |
| Status | Active |
| Category | Spacing |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH6007OpeningSquareBracketsMustBeSpacedCorrectlyAnalyzer`, `RH6007OpeningSquareBracketsMustBeSpacedCorrectlyCodeFixProvider` |
| Uses | FMT-CLEAN-001, FMT-SPACE-004, SHARED-WS-001, SHARED-WS-002 |

RH6007 reports whitespace directly after an opening square bracket that does not open an attribute list, and offers a code fix that deletes it as SHARED-WS-001 and SHARED-WS-002 specify.

In the examples, `→` marks a tab and `·` a space at the end of a line.

## Non-goals

- The opening bracket of an attribute list — RH6013.
- The whitespace before a closing square bracket — RH6008.
- The whitespace before an opening square bracket, such as `arr [0]`.

## Requirements

### RH6007-001 — Whitespace after an opening square bracket is reported

The analyzer MUST report the run of spaces and tabs directly after an opening square bracket that does not open an attribute list — for example of an element access, an array type or rank specifier, an array creation, a collection expression, or a list pattern — when the run is followed by a token or by the end of the line. An opening square bracket directly followed by a token or by a line break MUST NOT be reported, and neither MUST the opening bracket of an attribute list.

Why: The bracket belongs to the index, rank, or elements it opens; a space after it makes indexers and collection expressions harder to scan. The formatter removes the same whitespace — before a token on the same line (FMT-SPACE-004), at the end of the line (FMT-CLEAN-001) — so formatted code raises no RH6007 in these places.

Example:

```csharp
using System;

class C
{
    [ Obsolete]
    void M(int[] arr)
    {
        var x = arr[{|RH6007: |}0];
        int[{|RH6007: |}] e = [{|RH6007: |}1, 2];
        int[{|RH6007: |},] g = null;
        var y = new int[{|RH6007:→|}2];
        var p = arr is [{|RH6007: |}1, ..];
        var v = arr[{|RH6007:··|}
            0];
        var u = arr[
            0];
    }
}
```

### RH6007-002 — One diagnostic per bracket

The analyzer MUST report one diagnostic per opening square bracket, located on the whitespace run after it.

Why: The run is the text that is wrong and the text the fix deletes.

Example: see RH6007-001.

### RH6007-003 — The fix deletes the whitespace unless a comment is in the gap

The code fix MUST delete the reported whitespace as SHARED-WS-001 specifies, and MUST NOT be offered when a comment or directive sits between the bracket and the next token, as SHARED-WS-002 specifies.

Why: A comment in the gap is the author's placement; the fix does not decide whether the deletion affects it.

Example:

```csharp
class C
{
    void M(int[] arr)
    {
        var x = arr[{|RH6007: |}0];
        int[{|RH6007: |},] g = null;
        int[] e = [{|RH6007:→|}1, 2];
    }
}
```

```csharp
class C
{
    void M(int[] arr)
    {
        var x = arr[0];
        int[,] g = null;
        int[] e = [1, 2];
    }
}
```

A comment on the next line of the gap withholds the fix:

```csharp
class C
{
    void M(int[] arr)
    {
        var v = arr[{|RH6007:··|}
            // first index
            0];
    }
}
```

is reported, and no code fix is offered.
