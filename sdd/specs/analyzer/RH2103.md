# Analyzer — RH2103 Structs should not use parameterized primary constructors

| | |
|---|---|
| ID prefix | RH2103 |
| Status | Active |
| Category | Design |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH2103StructsShouldNotUseParameterizedPrimaryConstructorsAnalyzer` |
| Uses | — |

RH2103 reports a struct declaration whose primary constructor has parameters.

## Non-goals

- Classes — RH2102.
- Record structs. Their positional parameter list declares their members.
- A code fix. Moving the parameters into an explicit constructor needs fields or properties whose names and kinds only the author can decide.

## Requirements

### RH2103-001 — A struct with primary-constructor parameters is reported

The analyzer MUST report a struct declaration whose primary constructor has at least one parameter, including a `readonly` or `partial` struct. A struct whose primary constructor has no parameters, `struct S()`, and a struct without a primary constructor MUST NOT be reported. A record struct MUST NOT be reported.

Why: The parameters of a primary constructor are captured wherever the struct body uses them, so the type header hides how the value is initialized and which fields it holds. For a value type, whose fields define its size and copy cost, an explicit constructor that assigns declared fields shows both. An empty parameter list captures nothing.

Example:

```csharp
struct {|RH2103:Size|}(int width, int height)
{
    public int Area => width * height;
}

readonly struct {|RH2103:Id|}(int value)
{
    public int Value => value;
}

struct Empty()
{
}

struct Plain
{
}

record struct Point(int X);
```

### RH2103-002 — The diagnostic is on the struct name

The analyzer MUST report one diagnostic per reported struct declaration, located on its identifier.

Why: The name identifies the type whose header carries the parameters; the parameter list itself may span several lines.

Example: see RH2103-001.
