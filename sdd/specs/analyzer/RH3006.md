# Analyzer — RH3006 Conditional expressions must declare precedence

| | |
|---|---|
| ID prefix | RH3006 |
| Status | Active |
| Category | Clarity |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH3006ConditionalExpressionsMustDeclarePrecedenceAnalyzer`, `RH3006ConditionalExpressionsMustDeclarePrecedenceCodeFixProvider` |
| Uses | — |

RH3006 reports an `&&` expression that is a direct operand of `||`, and an `and` pattern that is a direct operand of `or`, and offers a code fix that puts the reported operand in parentheses.

## Non-goals

- Mixing other operators, such as arithmetic or bitwise operators, or `??`.
- Removing parentheses that declare this precedence — RH3002 never reports them in a binary operand.

## Requirements

### RH3006-001 — `&&` directly inside `||` is reported

The analyzer MUST report each operand of a `||` expression that is itself an `&&` expression without parentheses, and each operand of an `or` pattern that is itself an `and` pattern without parentheses. An operand in parentheses, and an expression or pattern that uses only one of the two operators, MUST NOT be reported.

Why: C# binds `&&` more tightly than `||`, and `and` more tightly than `or`, but a reader should not have to remember that to understand a condition. Parentheses make the grouping visible.

Example:

```csharp
class C
{
    bool M(bool a, bool b, bool c, bool d, int x)
    {
        var p = a || {|RH3006:b && c|};
        var q = {|RH3006:a && b|} || {|RH3006:c && d|};
        var r = x is {|RH3006:> 0 and < 10|} or 20;
        var s = a || (b && c);
        var t = a && b && c;
        return a || b || c;
    }
}
```

### RH3006-002 — The diagnostic covers the operand

The analyzer MUST report one diagnostic per reported operand, covering the whole `&&` expression or `and` pattern.

Why: The operand is what the fix puts in parentheses.

Example: see RH3006-001.

### RH3006-003 — The fix puts the operand in parentheses

The code fix MUST wrap the reported operand in parentheses and keep the trivia in front of and after it outside the parentheses.

Why: The parentheses declare the precedence the compiler already applies, so the program does not change. The comments around the operand belong to the code next to it.

Example:

```csharp
class C
{
    bool M(bool a, bool b, bool c, bool d, int x)
    {
        var p = a || /* x */ {|RH3006:b && c|};
        var q = {|RH3006:a && b|} || {|RH3006:c && d|};
        return x is {|RH3006:> 0 and < 10|} or 20;
    }
}
```

```csharp
class C
{
    bool M(bool a, bool b, bool c, bool d, int x)
    {
        var p = a || /* x */ (b && c);
        var q = (a && b) || (c && d);
        return x is (> 0 and < 10) or 20;
    }
}
```
