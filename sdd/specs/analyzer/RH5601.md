# Analyzer — RH5601 Tab characters must not be used

| | |
|---|---|
| ID prefix | RH5601 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5601UseTabsCorrectlyAnalyzer`, `RH5601UseTabsCorrectlyCodeFixProvider` |
| Uses | FMT-TAB-001, FMT-TAB-002, FMT-TAB-003, SHARED-DIAG-003 |

RH5601 reports tab characters in the whitespace of the code, and offers a code fix that replaces each tab with four spaces.

In the examples, `→` marks a tab character.

## Non-goals

- Indentation width and alignment — RH5204 and the formatter (FMT-INDENT).
- Whitespace at the end of a line — RH5602.

## Requirements

### RH5601-001 — Every tab in the code is reported

The analyzer MUST report every tab character that is part of the code's whitespace — in indentation, between two tokens, in front of a trailing comment, between the tokens of a preprocessor directive, and in front of or behind a literal or a comment — unless the tab indents the second or a later line of a `///` documentation comment. Whether a string or character literal or a `/** */` documentation comment stands next to the tab on its line does not matter: the whitespace before and after a literal is code (SHARED-DIAG-003), and so is the whitespace inside an interpolation hole outside its format clause. Only a tab inside the text of a literal, a comment, or disabled text is content (RH5601-002).

Why: A tab renders at a width that depends on the reader's editor, so code laid out with tabs looks different for every reader. The formatter writes no tab in these places (FMT-TAB-001, and FMT-TAB-002 between the tokens of a directive), so formatted code raises no RH5601.

Example:

```csharp
#define{|RH5601:→|}FEATURE
class C
{
{|RH5601:→|}int{|RH5601:→|}x;{|RH5601:→|}// note
    string u = $"""
        {1
{|RH5601:→|}+ 2}
        """;
#pragma{|RH5601:→|}warning disable CS0168
#pragma warning restore CS0168
    string a ={|RH5601:→|}"abc";{|RH5601:→|}// note
    string b =
{|RH5601:→|}"abc";
    string c = /** c */{|RH5601:→|}"abc";
    char d ={|RH5601:→|}'d';
    string e = $"{{|RH5601:→|}1{|RH5601:→|}}";
}
```

The tab in front of `"abc"` on the line after `string b =` is reported although nothing but the literal follows it on its line, and the tab behind `/** c */` although a documentation comment stands between it and the `=`.

### RH5601-002 — Tabs in literals, comments, and disabled text are not reported

The analyzer MUST NOT report a tab inside the text of a string literal (regular, verbatim, raw, or UTF-8) or of an interpolated string, a character literal, a comment (`//`, `/* */`, `///`, or `/** */`) that is not on a directive line, or disabled text. The whitespace after the opening quotes of a multi-line raw string literal and the indentation of its content lines and of its closing line, interpolated or not, are how the literal spells its value (SHARED-DIAG-003) and are part of its text.

Why: A tab inside a literal is part of the program's value, and a tab inside a comment or disabled text may be deliberate alignment. Both are user-authored content the formatter keeps as well (FMT-TAB-003). The indentation in front of a raw string's closing quotes decides how much the compiler strips from every content line; replacing a tab there, and not on the content lines, breaks the literal.

Example:

```csharp
class C
{
    string s = "a→b";
    char t = '→';
    string u = $"{1}→";
    string v = """
        a→b
        """;
    string w = """
→→a
→→""";
    string x = $"""
→→a
→→""";
    string y = """→
        a
        """;
    string z = $"""→
        a
        """;
    // a→b
    /* a→b */
    /// a→b
    void M()
    {
    }
#if NEVER
→int y;
#endif
}
```

is not reported.

### RH5601-003 — One diagnostic per tab

The analyzer MUST report one diagnostic per tab character, located on that character. Consecutive tabs are reported one by one.

Why: Each tab is replaced independently; reporting each one keeps one fix per diagnostic.

Example:

```csharp
class C
{
{|RH5601:→|}{|RH5601:→|}int x;
}
```

### RH5601-004 — The fix replaces the tab with four spaces

The code fix MUST replace the reported tab with four spaces, whatever column the tab starts in, and MUST NOT change anything else.

Why: Four spaces is the formatter's indentation unit, and a fixed width keeps the result independent of tab-stop settings — the same replacement FMT-TAB-001 makes. Realigning the line is the job of the indentation rules.

Example:

```csharp
class C
{
{|RH5601:→|}int{|RH5601:→|}x;{|RH5601:→|}// note
{|RH5601:→|}{|RH5601:→|}int y;
}
```

```csharp
class C
{
    int    x;    // note
        int y;
}
```
