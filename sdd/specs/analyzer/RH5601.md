# Analyzer — RH5601 Tab characters must not be used

| | |
|---|---|
| ID prefix | RH5601 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5601UseTabsCorrectlyAnalyzer`, `RH5601UseTabsCorrectlyCodeFixProvider` |
| Uses | FMT-CLEAN-002, FMT-CLEAN-003, FMT-CLEAN-004, SHARED-DIAG-003 |

RH5601 reports tab characters in the whitespace of the code, and offers a code fix that replaces each tab with four spaces.

In the examples, `→` marks a tab character.

## Non-goals

- Indentation width and alignment — RH5204 and the formatter (FMT-INDENT).
- Whitespace at the end of a line — RH5602.

## Requirements

### RH5601-001 — Every tab in the code is reported

The analyzer MUST report a tab character that is part of the code's whitespace — in indentation, between two tokens, in front of a trailing comment, or between the tokens of a preprocessor directive — when the tab does not indent the second or a later line of a `///` documentation comment and one of these conditions holds, where a code token is a token outside directives and documentation comments:

- a code token precedes the tab on its line, the last code token before it on that line is not a string or character literal, and no `/** */` documentation comment stands between that token and the tab;
- no code token precedes the tab on its line, and the next code token after it is not a string or character literal.

Why: A tab renders at a width that depends on the reader's editor, so code laid out with tabs looks different for every reader. The formatter writes no tab in these places (FMT-CLEAN-002, and FMT-CLEAN-003 between the tokens of a directive), so formatted code raises no RH5601.

Example:

```csharp
#define{|RH5601:→|}FEATURE
class C
{
{|RH5601:→|}int{|RH5601:→|}x;{|RH5601:→|}// note
    string u = $"""
        {1
{|RH5601:→|}+ 2}
        """;
#pragma{|RH5601:→|}warning disable CS0168
#pragma warning restore CS0168
}
```

### RH5601-002 — Tabs in literals, comments, and disabled text are not reported

The analyzer MUST NOT report a tab inside the text of a string literal (regular, verbatim, raw, or UTF-8) or of an interpolated string, a character literal, a comment (`//`, `/* */`, `///`, or `/** */`) that is not on a directive line, or disabled text. The indentation of the content lines and of the closing line of a multi-line raw string literal, interpolated or not, is how the literal spells its value (SHARED-DIAG-003) and is part of its text.

Why: A tab inside a literal is part of the program's value, and a tab inside a comment or disabled text may be deliberate alignment. Both are user-authored content the formatter keeps as well (FMT-CLEAN-004). The indentation in front of a raw string's closing quotes decides how much the compiler strips from every content line; replacing a tab there, and not on the content lines, breaks the literal.

Example:

```csharp
class C
{
    string s = "a→b";
    char t = '→';
    string u = $"{1}→";
    string v = """
        a→b
        """;
    string w = """
→→a
→→""";
    string x = $"""
→→a
→→""";
    // a→b
    /* a→b */
    /// a→b
    void M()
    {
    }
#if NEVER
→int y;
#endif
}
```

is not reported.

### RH5601-003 — One diagnostic per tab

The analyzer MUST report one diagnostic per tab character, located on that character. Consecutive tabs are reported one by one.

Why: Each tab is replaced independently; reporting each one keeps one fix per diagnostic.

Example:

```csharp
class C
{
{|RH5601:→|}{|RH5601:→|}int x;
}
```

### RH5601-004 — The fix replaces the tab with four spaces

The code fix MUST replace the reported tab with four spaces, whatever column the tab starts in, and MUST NOT change anything else.

Why: Four spaces is the formatter's indentation unit, and a fixed width keeps the result independent of tab-stop settings — the same replacement FMT-CLEAN-002 makes. Realigning the line is the job of the indentation rules.

Example:

```csharp
class C
{
{|RH5601:→|}int{|RH5601:→|}x;{|RH5601:→|}// note
{|RH5601:→|}{|RH5601:→|}int y;
}
```

```csharp
class C
{
    int    x;    // note
        int y;
}
```
