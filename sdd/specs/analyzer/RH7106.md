# Analyzer — RH7106 Protected must come before internal

| | |
|---|---|
| ID prefix | RH7106 |
| Status | Active |
| Category | Organization |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH7106ProtectedMustComeBeforeInternalAnalyzer`, `RH7106ProtectedMustComeBeforeInternalCodeFixProvider` |
| Uses | SHARED-DIAG-004, SHARED-MODORDER-001, SHARED-MODORDER-002, SHARED-MODORDER-003 |

RH7106 reports a compound accessibility written as `internal protected` or `protected private`, and offers a code fix that swaps the two keywords.

## Non-goals

- The position of the accessibility keywords relative to the other modifiers — RH7105.
- Whether a compound accessibility is the right one for the declaration.

## Requirements

### RH7106-001 — A compound accessibility in the other order is reported

The analyzer MUST report a checked declaration (SHARED-MODORDER-001) whose modifiers contain `internal` before `protected`, or `protected` before `private`, also when other modifiers stand between the two keywords, when no `#if`, `#elif`, `#else`, or `#endif` directive stands between its modifiers. Each part of a `partial` type or member is judged by the modifiers that part carries, also when another part writes the same accessibility in the canonical order (SHARED-DIAG-004).

Why: `protected internal` and `private protected` are the spellings the C# documentation uses; writing each compound accessibility one way makes it recognizable at a glance.

Example:

```csharp
class C
{
    internal {|RH7106:protected|} int A;
    protected {|RH7106:private|} int B;
    internal static {|RH7106:protected|} int D;
}
```

### RH7106-002 — The canonical spellings are not reported

The analyzer MUST NOT report `protected internal` or `private protected`.

Why: These are the spellings the rule asks for.

Example:

```csharp
class C
{
    protected internal int A;
    private protected int B;
}
```

is not reported.

### RH7106-003 — The diagnostic is on the second keyword

The analyzer MUST report one diagnostic per declaration, located on `protected` when it follows `internal`, and on `private` when it follows `protected`.

Why: The second keyword is the one written out of place, and one diagnostic per declaration matches the fix.

Example: see RH7106-001.

### RH7106-004 — The fix swaps the two keywords in place

The code fix MUST swap the positions of the two keywords and leave every other modifier at its position, and MUST rewrite the modifier list as specified in SHARED-MODORDER-002. It MUST NOT be offered when SHARED-MODORDER-003 withholds it.

Why: The rule decides only the order of the two accessibility keywords; where the accessibility stands among the other modifiers is RH7105's decision and its fix.

Example:

```csharp
class C
{
    internal {|RH7106:protected|} void M()
    {
    }

    internal static {|RH7106:protected|} int D;
}
```

```csharp
class C
{
    protected internal void M()
    {
    }

    protected static internal int D;
}
```
