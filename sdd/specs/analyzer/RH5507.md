# Analyzer — RH5507 Struct attributes must be on their own line

| | |
|---|---|
| ID prefix | RH5507 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5507StructAttributesMustFollowPlacementRulesAnalyzer`, `RH5507StructAttributesMustFollowPlacementRulesCodeFixProvider` |
| Uses | SHARED-ATTR-001, SHARED-ATTR-004, SHARED-ATTR-005, SHARED-ATTR-007, SHARED-ATTR-008, SHARED-ATTR-009, SHARED-ATTR-011, SHARED-ATTR-012 |

RH5507 reports an attribute list of a struct or record struct that shares its line with the token after it, and offers a code fix that moves that token onto the next line. The rule uses `shared/attribute-targets.md`.

## Non-goals

- Class and record class attributes — RH5505.

## Requirements

### RH5507-001 — Struct attribute lists are on their own line

The analyzer MUST check every attribute list that resolves to the struct target: the lists of a `struct` or `record struct` declaration without a specifier or with `type:` (SHARED-ATTR-001), and MUST report such a list whose closing bracket shares its line with the first token after it, as SHARED-ATTR-004 and SHARED-ATTR-005 specify for a list that must be on its own line.

Why: A reader scanning a file for its types looks down a column of modifiers and type names; an attribute in front of the declaration pushes that line to the right by however long the attribute is.

Example:

```csharp
{|RH5507:[A]|} struct S
{
}

{|RH5507:[A]|} record struct R;

[A]
struct T
{
}
```

### RH5507-002 — The diagnostic is on the attribute list

The analyzer MUST report the diagnostic on the attribute list, as SHARED-ATTR-007 specifies.

Why: The list is what is misplaced; each list of a declaration is reported and fixed on its own.

Example: see RH5507-001.

### RH5507-003 — The fix moves what follows onto the next line

The code fix MUST put the first token after the list on a new line, as SHARED-ATTR-008 and SHARED-ATTR-009 specify.

Why: The fix makes only the change the diagnostic asks for: the declaration starts on its own line, and the list stays where it is.

Example:

```csharp
{|RH5507:[A]|} struct S
{
}
```

```csharp
[A]
struct S
{
}
```

### RH5507-004 — The fix is withheld for comments, directives, and missing braces

The code fix MUST NOT be offered when SHARED-ATTR-011 or SHARED-ATTR-012 withholds it. The diagnostic is still reported.

Why: A comment inside the list belongs to the attribute next to it, and an unclosed scope leaves no indentation to compute; both are left to the author.

Example:

```csharp
{|RH5507:[A /* c */]|} struct S
{
}
```

is reported, and no code fix is offered.
