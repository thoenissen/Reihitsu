# Analyzer — RH8019 Destructors must be documented

| | |
|---|---|
| ID prefix | RH8019 |
| Status | Active |
| Category | Documentation |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH8019DestructorsMustBeDocumentedAnalyzer` |
| Uses | SHARED-DOC-001, SHARED-DOC-004, SHARED-DOC-005, SHARED-DOC-006, SHARED-DOC-007, SHARED-DOC-008 |

RH8019 reports a destructor that has no `<summary>` or `<inheritdoc>` documentation.

## Non-goals

- Constructors — RH8017 and RH8018.
- Whether the summary has text — RH8030.

## Requirements

### RH8019-001 — Undocumented destructors are reported

The analyzer MUST report every destructor declaration that is not documented, checked as SHARED-DOC-001 specifies, whatever the accessibility of the type that declares it. Whether it is documented MUST be decided as SHARED-DOC-004, SHARED-DOC-005, SHARED-DOC-006, and SHARED-DOC-007 specify, and nothing is reported when SHARED-DOC-008 applies.

Why: A destructor runs on the garbage collector's thread at a time nobody controls, so the cleanup it does is easy to miss and hard to debug. It takes no access modifier, so it is not split into a private and a non-private rule.

Example:

```csharp
/// <summary>
/// Resource
/// </summary>
public class Resource
{
    ~{|RH8019:Resource|}()
    {
    }
}

/// <summary>
/// Outer
/// </summary>
public class Outer
{
    private class Hidden
    {
        /// <remarks>
        /// No summary
        /// </remarks>
        ~{|RH8019:Hidden|}()
        {
        }
    }

    /// <summary>
    /// Releases the outer resources
    /// </summary>
    ~Outer()
    {
    }
}
```

### RH8019-002 — The diagnostic is on the destructor name

The analyzer MUST report one diagnostic per undocumented destructor, located on its identifier, without the `~`.

Why: The name is what the documentation describes; marking it identifies the destructor without marking its whole body.

Example: see RH8019-001.
