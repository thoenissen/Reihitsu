# Analyzer — RH8001 Non-private classes must be documented

| | |
|---|---|
| ID prefix | RH8001 |
| Status | Active |
| Category | Documentation |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH8001NonPrivateClassesMustBeDocumentedAnalyzer` |
| Uses | SHARED-DOC-001, SHARED-DOC-002, SHARED-DOC-004, SHARED-DOC-005, SHARED-DOC-006, SHARED-DOC-007, SHARED-DOC-008 |

RH8001 reports a class in the non-private group that has no `<summary>` or `<inheritdoc>` documentation.

## Non-goals

- Classes in the private group — RH8002.
- Records declared with `record` or `record class` — RH8007.
- Whether the summary has text — RH8030; the documentation of type parameters and primary constructor parameters — RH8108 and RH8101.

## Requirements

### RH8001-001 — Undocumented non-private classes are reported

The analyzer MUST report every class declaration in the non-private group of SHARED-DOC-002 that is not documented, checked as SHARED-DOC-001 specifies. A class declaration is one written with the `class` keyword, including static, abstract, sealed, and generic classes; a `record` or `record class` declaration is not one. Whether it is documented MUST be decided as SHARED-DOC-004, SHARED-DOC-005, SHARED-DOC-006, and SHARED-DOC-007 specify, and nothing is reported when SHARED-DOC-008 applies.

Why: A class that other code can use is part of the contract that code builds on. Without a summary, the generated documentation and the editor's tooltip show nothing, and readers have to infer what the class is for from its implementation.

Example:

```csharp
public class {|RH8001:Service|}
{
}

/// <remarks>
/// No summary
/// </remarks>
internal static class {|RH8001:Helper|}
{
}

internal class {|RH8001:Repository|}<T>
{
}

/// <summary>
/// Documented
/// </summary>
public class Documented
{
    private class Hidden
    {
    }
}

public record Entity;
```

### RH8001-002 — The diagnostic is on the class name

The analyzer MUST report one diagnostic per undocumented class declaration, located on its identifier, without its type parameter list.

Why: The name is what the documentation describes; marking it identifies the declaration without marking its whole body.

Example: see RH8001-001.
