# Analyzer — RH6015 Nullable type symbols must not be preceded by space

| | |
|---|---|
| ID prefix | RH6015 |
| Status | Active |
| Category | Spacing |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH6015NullableTypeSymbolsMustNotBePrecededBySpaceAnalyzer`, `RH6015NullableTypeSymbolsMustNotBePrecededBySpaceCodeFixProvider` |
| Uses | FMT-SPACE-005, SHARED-WS-001 |

RH6015 reports whitespace in front of the `?` of a nullable type on the line of the type before it, and offers a code fix that deletes it as SHARED-WS-001 specifies.

In the examples, `→` marks a tab.

## Non-goals

- The whitespace after the `?` of a nullable type, such as `int?  a` — no analyzer rule checks it.
- The `?` that opens a conditional access — RH6016.
- Whether a `?` starts its own line — the formatter.

## Requirements

### RH6015-001 — Whitespace before a nullable `?` on the same line is reported

The analyzer MUST report the run of spaces and tabs directly in front of the `?` of a nullable type — of a value type or of an annotated reference type, wherever a type is written — when the `?` is on the line on which the token before it ends and the run directly follows that token. A `?` that starts its line, after a line break, MUST NOT be reported.

Why: `int?` is one type name; a space in front of the `?` makes it read like the start of a conditional expression. A `?` on its own line is a layout choice, and its indentation is not a gap. The formatter removes the same whitespace (FMT-SPACE-005), so formatted code raises no RH6015.

Example:

```csharp
#nullable enable

using System.Collections.Generic;

class C
{
    int{|RH6015: |}? _a;
    string{|RH6015:→|}? _b;
    int{|RH6015: |}?[] _c;
    int
        ? _e;

    void M(int{|RH6015: |}? a, object o)
    {
        var t = typeof(int{|RH6015: |}?);
        var x = (int{|RH6015: |}?)o;
        List<int{|RH6015: |}?> l = new();
        var y = o as int{|RH6015: |}? ?? 0;
    }
}
```

### RH6015-002 — A `?` that is not a nullable type, and documentation references, are not reported

The analyzer MUST NOT report the whitespace in front of a `?` that is not the `?` of a nullable type, such as the `?` of a conditional expression, and MUST NOT report a nullable type inside a documentation comment reference such as `cref="M(int ?)"`.

Why: A conditional `?` is an operator between two operands, not part of a type name. A `cref` is part of a documentation comment, not code whose layout the rule checks.

Example:

```csharp
class C
{
    /// <see cref="M(int ?)"/>
    int M(int? a, object o)
    {
        var x = o is int ? 1 : 2;

        return a == null ? x : 0;
    }
}
```

is not reported.

### RH6015-003 — One diagnostic per `?`

The analyzer MUST report one diagnostic per nullable `?`, located on the whitespace run in front of it.

Why: The run is the text that is wrong and the text the fix deletes.

Example: see RH6015-001.

### RH6015-004 — The fix deletes the whitespace

The code fix MUST delete the reported whitespace as SHARED-WS-001 specifies.

Why: The run is the whole of what the diagnostic names as wrong, and deleting it is the whole correction.

Example:

```csharp
#nullable enable

class C
{
    int{|RH6015: |}? _a;
    string{|RH6015:→|}? _b;

    void M(int{|RH6015: |}? a, object o)
    {
        var x = (int{|RH6015: |}?)o;
    }
}
```

```csharp
#nullable enable

class C
{
    int? _a;
    string? _b;

    void M(int? a, object o)
    {
        var x = (int?)o;
    }
}
```
