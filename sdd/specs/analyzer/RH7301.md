# Analyzer — RH7301 #region and #endregion descriptions should match

| | |
|---|---|
| ID prefix | RH7301 |
| Status | Active |
| Category | Organization |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH7301RegionsShouldMatchAnalyzer`, `RH7301RegionsShouldMatchCodeFixProvider` |
| Uses | SHARED-REGDESC-001, FMT-REGION-003 |

RH7301 reports an `#endregion` whose description differs from the description of the `#region` it closes, and offers a code fix that rewrites the `#endregion` to repeat the region's description.

## Non-goals

- What the description of a region directive is — SHARED-REGDESC-001.
- The capitalization of the description — RH7302 — and the words it may contain — RH7306, RH7307.
- How the formatter writes the `#endregion` comment (FMT-REGION). The formatter derives it from the capitalized `#region` description; this rule's fix copies the description as written.

## Requirements

### RH7301-001 — An `#endregion` that does not repeat its region's description is reported

The analyzer MUST report every `#endregion` whose description (SHARED-REGDESC-001) differs from the description of the `#region` it closes, compared ordinally, so a difference in case counts. The `#endregion` and the `#region` it closes are paired as FMT-REGION-003 specifies. Every pair is checked: between members, inside an element body, and inside a branch that `#if` excludes.

Why: A closing directive that names its region lets the reader see which block ends without scrolling up. A stale or differently spelled name points at the wrong block, which is worse than no name; region names are headings, so their case is part of the name.

Example:

```csharp
class C
{
    #region Fields
    int _a;
    {|RH7301:#endregion // fields|}

    #region Methods
    void M()
    {
        #region Local
        var a = 1;
        {|RH7301:#endregion // Other|}
    }
    {|RH7301:#endregion|}
}
```

and nested regions pair innermost first:

```csharp
class C
{
    #region Outer

    #region Inner
    int _a;
    {|RH7301:#endregion // Outer|}

    {|RH7301:#endregion // Inner|}
}
```

and a pair in an excluded branch is checked too:

```csharp
class C
{
#if false
    #region Fields

    {|RH7301:#endregion // Members|}
#endif
}
```

### RH7301-002 — Matching descriptions are not reported

The analyzer MUST NOT report an `#endregion` whose description equals the description of its `#region`, including when both are empty.

Why: The pair already agrees; the form of the `#endregion` text — with or without `//`, and the whitespace around it — is presentation (SHARED-REGDESC-001).

Example:

```csharp
class C
{
    #region Fields
    int _a;
    #endregion Fields

    #region Methods
    void M() { }
    #endregion //Methods

    #region
    int _b;
    #endregion
}
```

is not reported.

### RH7301-003 — The diagnostic is on the `#endregion`

The analyzer MUST report one diagnostic per mismatched pair, located on its `#endregion` directive from the `#` to the end of its line. The `#region` is not reported.

Why: The `#region` is the source of the name; the `#endregion` is the copy that is out of date and the one the fix changes.

Example: see RH7301-001.

### RH7301-004 — The fix repeats the region's description

The code fix MUST rewrite the reported `#endregion` directive as `#endregion // <description>`, where `<description>` is the description of its `#region` as written (SHARED-REGDESC-001), and MUST keep the directive's indentation and the line break after it.

Why: Copying the description from the `#region` is the only correction that cannot be wrong, and the `// ` form is the one the formatter writes, so the result needs no further layout.

Example:

```csharp
class C
{
    #region Fields
    int _a;
    {|RH7301:#endregion /* Fields */|}

    #region Methods
    void M() { }
    {|RH7301:#endregion|}
}
```

```csharp
class C
{
    #region Fields
    int _a;
    #endregion // Fields

    #region Methods
    void M() { }
    #endregion // Methods
}
```

### RH7301-005 — The fix is withheld when the region has no description

The code fix MUST NOT be offered when the `#region` that the reported `#endregion` closes has an empty description. The diagnostic is still reported.

Why: There is no name to copy. Whether the region deserves the name written on its `#endregion` — then it belongs on the `#region` — or the stray text should go is the user's decision.

Example:

```csharp
class C
{
    #region
    int _a;
    {|RH7301:#endregion // Stale|}
}
```

is reported, and no code fix is offered.
