# Analyzer — RH5012 continue-Statement should be preceded by a blank line

| | |
|---|---|
| ID prefix | RH5012 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5012ContinueStatementsShouldBePrecededByABlankLineAnalyzer`, `RH5012ContinueStatementsShouldBePrecededByABlankLineCodeFixProvider` |
| Uses | SHARED-STMT-001, SHARED-STMT-002, SHARED-STMT-003, SHARED-STMT-004 |

RH5012 reports a `continue` statement that follows another statement of the same block or switch section without a blank line between them, and offers a code fix that inserts one as SHARED-STMT-004 specifies.

## Non-goals

- Blank lines before other statement kinds — the other rules that use `shared/statement-blank-lines.md`.

## Requirements

### RH5012-001 — A `continue` statement that follows a statement needs a blank line

The analyzer MUST report a `continue` statement as SHARED-STMT-001, SHARED-STMT-002, and SHARED-STMT-003 specify.

Why: A `continue` statement skips the rest of the loop body; the blank line makes the jump visible instead of letting it read as one more step of the body.

Example:

```csharp
class C
{
    void M(int[] items)
    {
        foreach (var item in items)
        {
            if (item > 0)
            {
                continue;
            }

            M(items);
            {|RH5012:continue|};
        }
    }
}
```

The `continue` inside the `if` block is the first statement of its block and is not reported.

### RH5012-002 — The diagnostic is on the `continue` keyword

The analyzer MUST report the diagnostic on the `continue` keyword.

Why: The keyword is where the missing separator becomes visible.

Example: see RH5012-001.
