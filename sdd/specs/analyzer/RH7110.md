# Analyzer — RH7110 Members must be ordered by accessibility

| | |
|---|---|
| ID prefix | RH7110 |
| Status | Active |
| Category | Organization |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH7110MembersMustBeOrderedByAccessibilityAnalyzer` |
| Uses | SHARED-TYPEREGION-006 |

RH7110 reports a member whose accessibility comes earlier in the accessibility order than that of the member of the same kind before it. It has no code fix.

## Non-goals

- The order of member kinds — the region rules, such as RH7305 and RH7309.
- The order of static and instance members, constants and fields, and readonly and non-readonly fields within one accessibility — RH7103, RH7102, RH7109.
- Ordering across the parts of a `partial` type and between a type and its nested types. Each type declaration is checked on its own.

## Requirements

### RH7110-001 — A member after a member later in the accessibility order is reported

The analyzer MUST report every member of a class, struct, interface, record, or record struct declaration whose accessibility modifiers state an accessibility that comes earlier in the accessibility order than the accessibility stated by the modifiers of the previous member of the same group in the same declaration that carries accessibility modifiers. The accessibility order is `public`, `internal`, `protected internal`, `protected`, `private protected`, `private`, with `protected internal` and `private protected` each one position regardless of modifier order. A group is the combination of member kind (RH7110-002) and containing top-level region (RH7110-003).

Why: The most visible surface of a type belongs at the top, so readers see what a type exposes before its implementation details. Comparing only within one kind keeps the rule from fighting the kind order the region rules impose.

Example:

```csharp
class C
{
    private int _a;
    public int {|RH7110:B|};

    protected void M()
    {
    }

    protected private void N()
    {
    }

    internal protected void {|RH7110:O|}()
    {
    }
}
```

`B` follows the private field `_a`, and `O` follows the `private protected` method `N`. `N`, written `protected private`, comes after `M`'s `protected` in the order and is not reported.

### RH7110-002 — Only members of the same kind are compared

The analyzer MUST compare a member only with earlier members of the same kind: nested type, delegate, field, constructor, destructor, property, indexer, event, event field, method, operator, or conversion operator.

Why: The kind order of a type is a separate decision. A public property after a private field is in the property group, not misplaced among the fields.

Example:

```csharp
using System;

class C
{
    private int _value;
    public int Value { get; set; }

    private event Action _changed;
    public event Action Changed
    {
        add
        {
        }

        remove
        {
        }
    }

    private C()
    {
    }

    public {|RH7110:C|}(int value)
    {
    }

    private delegate void Handler();
    public delegate void {|RH7110:Callback|}();

    private int this[int index] => index;
    public int {|RH7110:this|}[string key] => 0;
}
```

Only the constructor, the delegate, and the indexer are reported: the property follows only a field, and the event with accessors follows only an event field.

### RH7110-003 — Each top-level region is checked on its own

The analyzer MUST compare a member only with members that lie in the same top-level region of the type (SHARED-TYPEREGION-006), or with members outside every top-level region when the member lies outside every top-level region too.

Why: A type organized in regions has chosen its order by region; comparing across them would ask a member to leave its region.

Example:

```csharp
class C
{
    private void A()
    {
    }

    #region Api

    public void B()
    {
    }

    #endregion
}
```

is not reported.

```csharp
class C
{
    #region Members

    private void A()
    {
    }

    #region Inner

    public void {|RH7110:B|}()
    {
    }

    #endregion

    #endregion

    public void D()
    {
    }
}
```

### RH7110-004 — The diagnostic is on the member's name

The analyzer MUST report one diagnostic per reported member, located on its identifier — for a field or event field the first declarator's identifier, for an indexer the `this` keyword, for an operator the operator token, and for a conversion operator the `operator` keyword.

Why: The name is what a reader scans for, and one diagnostic per member names each member that has to move. C# requires every user-defined operator and conversion operator to be `public` (CS0558), so these two locations occur only while a declaration carries another accessibility modifier, for example in the editor before the code compiles; the analyzer still runs on such code.

Example:

```csharp
using System;

class C
{
    private event Action _changed;
    public event Action {|RH7110:Changed|}, Updated;

    private int this[int index] => index;
    public int {|RH7110:this|}[string key] => 0;
}
```

and the two operator forms, in code that does not compile:

```csharp
class C
{
    private static C operator +(C a, C b) => a;
    public static C operator {|RH7110:-|}(C a, C b) => a;

    private static explicit operator long(C c) => 0;
    public static implicit {|RH7110:operator|} int(C c) => 0;
}
```
