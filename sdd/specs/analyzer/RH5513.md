# Analyzer — RH5513 Method attributes must be on their own line

| | |
|---|---|
| ID prefix | RH5513 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5513MethodAttributesMustFollowPlacementRulesAnalyzer`, `RH5513MethodAttributesMustFollowPlacementRulesCodeFixProvider` |
| Uses | SHARED-ATTR-001, SHARED-ATTR-002, SHARED-ATTR-004, SHARED-ATTR-005, SHARED-ATTR-007, SHARED-ATTR-008, SHARED-ATTR-009, SHARED-ATTR-011, SHARED-ATTR-012 |

RH5513 reports an attribute list of a method, operator, conversion operator, destructor, local function, or lambda that shares its line with the token after it, and offers a code fix that moves that token onto the next line. The rule uses `shared/attribute-targets.md`.

## Non-goals

- Attributes of constructors — RH5511.
- The `return:` attributes of a method — RH5527.

## Requirements

### RH5513-001 — Method attribute lists are on their own line

The analyzer MUST check every attribute list that resolves to the method target (SHARED-ATTR-001, SHARED-ATTR-002) and is not attached to an accessor: the lists of a method, operator, conversion operator, destructor, local function, or lambda without a specifier or with `type:`, and every list with the `method:` specifier, and MUST report such a list whose closing bracket shares its line with the first token after it, as SHARED-ATTR-004 and SHARED-ATTR-005 specify for a list that must be on its own line.

Why: A reader scanning a type for a method looks down a column of modifiers, return types, and names; an attribute in front of the method pushes that line to the right, so methods with attributes no longer line up with methods without.

Example:

```csharp
class C
{
    {|RH5513:[A]|} void M()
    {
        {|RH5513:[A]|} void L()
        {
        }

        System.Func<int> f = {|RH5513:[A]|} () => 1;
    }

    {|RH5513:[A]|} public static C operator +(C a, C b) => a;

    {|RH5513:[A]|} public static implicit operator int(C c) => 0;

    {|RH5513:[A]|} ~C()
    {
    }

    {|RH5513:[method: A]|} int P { get; set; }

    [A]
    void N()
    {
    }
}
```

### RH5513-002 — Accessor attributes are not checked

The analyzer MUST NOT report an attribute list attached to an accessor, even though it resolves to the method target.

Why: An accessor is laid out inside its property's accessor list, where a one-line property keeps its accessor attributes inline; RH5530 checks those lists with that exception.

Example:

```csharp
class C
{
    int P
    {
        [A] get;
        set;
    }
}
```

is not reported by RH5513; RH5530 reports it.

### RH5513-003 — The diagnostic is on the attribute list

The analyzer MUST report the diagnostic on the attribute list, as SHARED-ATTR-007 specifies.

Why: The list is what is misplaced; each list of a declaration is reported and fixed on its own.

Example: see RH5513-001.

### RH5513-004 — The fix moves what follows onto the next line

The code fix MUST put the first token after the list on a new line, as SHARED-ATTR-008 and SHARED-ATTR-009 specify.

Why: The fix makes only the change the diagnostic asks for: the declaration starts on its own line, and the list stays where it is.

Example:

```csharp
class C
{
    {|RH5513:[A]|} void M()
    {
    }
}
```

```csharp
class C
{
    [A]
    void M()
    {
    }
}
```

### RH5513-005 — The fix is withheld for comments, directives, and missing braces

The code fix MUST NOT be offered when SHARED-ATTR-011 or SHARED-ATTR-012 withholds it. The diagnostic is still reported.

Why: A comment inside the list belongs to the attribute next to it, and an unclosed scope leaves no indentation to compute; both are left to the author.

Example:

```csharp
class C
{
    {|RH5513:[A /* c */]|} void M()
    {
    }
}
```

is reported, and no code fix is offered.
