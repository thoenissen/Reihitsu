# Analyzer — RH7302 #region description should start with an uppercase letter

| | |
|---|---|
| ID prefix | RH7302 |
| Status | Active |
| Category | Organization |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH7302RegionsShouldStartWithAUpperCaseLetterAnalyzer`, `RH7302RegionsShouldStartWithAUpperCaseLetterCodeFixProvider` |
| Uses | FMT-REGION-001, FMT-REGION-006 |

RH7302 reports a `#region` whose description starts with a lower-case letter, and offers a code fix that capitalizes that letter, together with the `#endregion` comment that repeats the name.

## Non-goals

- The rest of the description. Only its first character is checked; title case is not required.
- The spacing of the `#region` line. The fix keeps it as written; the formatter normalizes it (FMT-REGION).
- Whether the `#endregion` repeats the description — RH7301.

## Requirements

### RH7302-001 — A description starting with a lower-case letter is reported

The analyzer MUST report every `#region` directive whose description's first character that is not whitespace changes under invariant upper-casing — a lower-case letter such as `m`, `ä`, or `ǆ`. Every `#region` is checked: between members, inside an element body, and inside a branch that `#if` excludes.

Why: Region names are headings in the code and in the editor's outline, and a consistent capital letter makes them read as such. The check is the one the formatter applies (FMT-REGION-001), so the analyzer and the formatter agree on which names need a capital. Region directives in an excluded branch are parsed and named by the formatter as well (FMT-REGION-006).

Example:

```csharp
class C
{
    {|RH7302:#region äpfel und birnen|}

    int _a;

    #endregion // äpfel und birnen

    {|RH7302:#region   members|}

    int _b;

    #endregion // members

    void M()
    {
        {|RH7302:#region local|}
        var a = 1;
        #endregion
    }

#if false
    {|RH7302:#region test|}

    #endregion
#endif
}
```

### RH7302-002 — Other first characters are not reported

The analyzer MUST NOT report a `#region` whose description starts with an upper-case letter or with a character that has no upper-case form, such as a digit or `_`, and MUST NOT report a `#region` without a description. An `#endregion` is never reported.

Why: Only a lower-case letter can be capitalized; reporting a digit or a symbol would raise a diagnostic the fix cannot correct. The `#endregion` text is a copy of the name, which RH7301 checks.

Example:

```csharp
class C
{
    #region   Fields

    int _a;

    #endregion // fields

    #region 1st fields

    int _b;

    #endregion // 1st fields

    #region _private

    int _c;

    #endregion // _private

    #region

    int _d;

    #endregion
}
```

is not reported.

### RH7302-003 — The diagnostic is on the `#region`

The analyzer MUST report one diagnostic per reported `#region`, located on the directive from its `#` to the end of its line.

Why: The `#region` holds the name the user has to change.

Example: see RH7302-001.

### RH7302-004 — The fix capitalizes the first letter

The code fix MUST replace the first character of the description that is not whitespace with its invariant upper-case form and MUST leave every other character of the `#region` line unchanged, the whitespace in front of the description included.

Why: The first letter is the whole finding; the rest of the description is the author's wording, and the spacing of the line is layout the formatter owns.

Example:

```csharp
class C
{
    {|RH7302:#region   äpfel und birnen|}

    int _a;

    #endregion
}
```

```csharp
class C
{
    #region   Äpfel und birnen

    int _a;

    #endregion
}
```

### RH7302-005 — The fix renames the `#endregion` that repeats the name

When the `#region` line ends with its description and the text after the matching `#endregion` — after an optional `//` and the whitespace around it — is exactly that description, the code fix MUST rewrite the `#endregion` text with the new description. An `#endregion` whose text does not contain the old description MUST stay unchanged.

Why: An `#endregion` that repeats the region's name is part of the name, so renaming the region renames it too; otherwise RH7301 would report the pair right after the fix. An `#endregion` that names something else is text the user wrote for another purpose, and the fix does not touch it.

Example:

```csharp
class C
{
    {|RH7302:#region members|}
    #endregion // members

    {|RH7302:#region values|}
    #endregion values

    {|RH7302:#region helpers|}
    #endregion // other
}
```

```csharp
class C
{
    #region Members
    #endregion // Members

    #region Values
    #endregion Values

    #region Helpers
    #endregion // other
}
```
