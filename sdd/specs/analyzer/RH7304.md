# Analyzer — RH7304 Region directives must use consistent indentation with containing code

| | |
|---|---|
| ID prefix | RH7304 |
| Status | Active |
| Category | Organization |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH7304RegionDirectivesMustUseConsistentIndentationAnalyzer`, `RH7304RegionDirectivesMustUseConsistentIndentationCodeFixProvider` |
| Uses | SHARED-TYPEREGION-005, FMT-REGION-003, SHARED-COMMENT-011, SHARED-INIT-001 |

RH7304 reports a `#region` or `#endregion` directive that is not indented like the first code of its region, and offers a code fix that indents both directives of the region like that code.

## Non-goals

- Region directives inside executable code — RH7303.
- The indentation of the code inside the region. The rule takes it as written; the indentation rules and the formatter (FMT-INDENT-010) decide whether it is right.
- Blank lines around region directives — RH5031, RH5032.

## Requirements

### RH7304-001 — A directive indented unlike its region's first code is reported

For every `#region` and the `#endregion` that closes it (FMT-REGION-003), when both directives and every region directive between them lie between declarations (SHARED-TYPEREGION-005), the analyzer MUST compare the indentation of each of the two directives — the whitespace from the start of its line to its `#` — with the indentation of the region's first element, and MUST report each directive whose indentation differs. The region's first element is:

- the first token after the `#region`, when it starts its line; a comment that ends on an earlier line, such as a `//` comment on a line of its own above the token, does not change that;
- otherwise — one or more comments stand in front of that token on its line — the comment that starts the line (SHARED-COMMENT-011): the comment that starts the token's line, or, when the token's line begins with the end of a comment that started on an earlier line, the comment that starts that earlier line. Its indentation is the whitespace from the start of the line on which it starts to the comment. Neither a further comment behind it nor the column of the token behind the comments counts.

Why: A region marker that lines up with the code it groups shows the nesting level at a glance; a marker at another column suggests a different level. The first token inside the region is the best evidence of the level the region belongs to, also when that code itself is indented wrongly — the indentation of the code is another rule's finding. A comment that leads the token's line is that line's first element, and it stands at the line's level as the token would; whether the comment may stand there is for the rules that report comments. A comment that spans lines and ends in front of the token starts the code of the region, so its start shows the level, as SHARED-INIT-001 takes it for an initializer.

Example:

```csharp
namespace N
{
{|RH7304:#region Types|}
    class C
    {
    {|RH7304:#region Fields|}

          private int _a;

    {|RH7304:#endregion // Fields|}
    }
{|RH7304:#endregion|}
}
```

and only the misaligned directive of a pair is reported:

```csharp
class C
{
    #region Fields

    private int _a;

  {|RH7304:#endregion // Fields|}
}
```

Example — a comment leads the first line of code in the region:

```csharp
class C
{
    #region Fields

    /* c */ int _a;

    #endregion // Fields

  {|RH7304:#region Values|}

    /* d */ int _b;

  {|RH7304:#endregion // Values|}

    {|RH7304:#region Names|}

      /* e */ int _c;

    {|RH7304:#endregion // Names|}

            {|RH7304:#region Others|}

    /* f */ int _d;

            {|RH7304:#endregion // Others|}

    #region Lines

    /* g
     */ int _e;

    #endregion // Lines
}
```

The `Fields` region is not reported, because its directives stand in the column of the comment `/* c */`, and neither is the `Lines` region, whose directives stand in the column where the comment `/* g` starts. The directives of `Values` stand left of the comment `/* d */`, and those of `Names` left of the comment `/* e */`. Those of `Others` stand in the column of the token `int` behind the comment `/* f */`, which does not count. All three pairs are reported.

### RH7304-002 — A region without code is not reported

The analyzer MUST NOT report the directives of a region that contains no token before its `#endregion`, whatever their indentation.

Why: Without code inside, there is no level to align the directives with. An empty region is RH7310's finding.

Example:

```csharp
class C
{
#region Empty
    #endregion
}
```

is not reported.

### RH7304-003 — The diagnostic is on the directive

The analyzer MUST report one diagnostic per misaligned directive, located on the directive from its `#` to the end of its line.

Why: Each directive can be misaligned on its own, and the fix of one diagnostic is visible on its own line.

Example: see RH7304-001.

### RH7304-004 — The fix indents both directives of the region

The code fix MUST replace the indentation of the reported directive and of the directive it pairs with by the indentation of the region's first element (RH7304-001) — its first token, or the comment that leads the first line of its code — and MUST change nothing else.

Why: Both directives belong to the same level, so fixing them together corrects the pair in one application; the directive that was already aligned keeps its indentation.

Example:

```csharp
class C
{
{|RH7304:#region Fields|}

    private int _a;

  {|RH7304:#endregion // Fields|}
}
```

```csharp
class C
{
    #region Fields

    private int _a;

    #endregion // Fields
}
```

Example — a comment leads the first line of the region's code, on one line or across two:

```csharp
class C
{
  {|RH7304:#region Fields|}

    /* c */ int _a;

  {|RH7304:#endregion // Fields|}

  {|RH7304:#region Lines|}

    /* g
     */ int _e;

  {|RH7304:#endregion // Lines|}
}
```

```csharp
class C
{
    #region Fields

    /* c */ int _a;

    #endregion // Fields

    #region Lines

    /* g
     */ int _e;

    #endregion // Lines
}
```

### RH7304-005 — A region with a directive inside executable code is not reported

The analyzer MUST NOT report either directive of a `#region` and the `#endregion` that closes it (FMT-REGION-003) when one of the two, or a region directive between them, lies inside executable code (SHARED-TYPEREGION-005), whatever their indentation.

Why: The directives are paired as the compiler pairs them, so a region that reaches into a body, or holds a region of a body, is not a region between declarations, and its first code does not show the level both directives belong to. The directive inside executable code is RH7303's finding.

Example:

```csharp
class C
{
#region Outer
    void M()
    {
        #region Inner
        M();
        #endregion
    }
#endregion

#region Members
    void N()
    {
        #endregion
    }
}
```

is not reported: the `Outer` region holds a region inside the body of `M`, and the `#endregion` that closes `Members` lies inside the body of `N`.
