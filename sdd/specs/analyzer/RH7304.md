# Analyzer — RH7304 Region directives must use consistent indentation with containing code

| | |
|---|---|
| ID prefix | RH7304 |
| Status | Active |
| Category | Organization |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH7304RegionDirectivesMustUseConsistentIndentationAnalyzer`, `RH7304RegionDirectivesMustUseConsistentIndentationCodeFixProvider` |
| Uses | SHARED-TYPEREGION-005, FMT-REGION-003 |

RH7304 reports a `#region` or `#endregion` directive that is not indented like the first code of its region, and offers a code fix that indents both directives of the region like that code.

## Non-goals

- Region directives inside executable code — RH7303.
- The indentation of the code inside the region. The rule takes it as written; the indentation rules and the formatter (FMT-INDENT-010) decide whether it is right.
- Blank lines around region directives — RH5031, RH5032.

## Requirements

### RH7304-001 — A directive indented unlike its region's first code is reported

For every `#region` and the `#endregion` that closes it (FMT-REGION-003), when both directives and every region directive between them lie between declarations (SHARED-TYPEREGION-005) and the first token after the `#region` starts its line, the analyzer MUST compare the indentation of each of the two directives — the whitespace from the start of its line to its `#` — with the indentation of that token, and MUST report each directive whose indentation differs.

Why: A region marker that lines up with the code it groups shows the nesting level at a glance; a marker at another column suggests a different level. The first token inside the region is the best evidence of the level the region belongs to, also when that code itself is indented wrongly — the indentation of the code is another rule's finding.

Example:

```csharp
namespace N
{
{|RH7304:#region Types|}
    class C
    {
    {|RH7304:#region Fields|}

          private int _a;

    {|RH7304:#endregion // Fields|}
    }
{|RH7304:#endregion|}
}
```

and only the misaligned directive of a pair is reported:

```csharp
class C
{
    #region Fields

    private int _a;

  {|RH7304:#endregion // Fields|}
}
```

### RH7304-002 — A region without code is not reported

The analyzer MUST NOT report the directives of a region that contains no token before its `#endregion`, whatever their indentation.

Why: Without code inside, there is no level to align the directives with. An empty region is RH7310's finding.

Example:

```csharp
class C
{
#region Empty
    #endregion
}
```

is not reported.

### RH7304-003 — The diagnostic is on the directive

The analyzer MUST report one diagnostic per misaligned directive, located on the directive from its `#` to the end of its line.

Why: Each directive can be misaligned on its own, and the fix of one diagnostic is visible on its own line.

Example: see RH7304-001.

### RH7304-004 — The fix indents both directives of the region

The code fix MUST replace the indentation of the reported directive and of the directive it pairs with by the indentation of the region's first token (RH7304-001), and MUST change nothing else.

Why: Both directives belong to the same level, so fixing them together corrects the pair in one application; the directive that was already aligned keeps its indentation.

Example:

```csharp
class C
{
{|RH7304:#region Fields|}

    private int _a;

  {|RH7304:#endregion // Fields|}
}
```

```csharp
class C
{
    #region Fields

    private int _a;

    #endregion // Fields
}
```
