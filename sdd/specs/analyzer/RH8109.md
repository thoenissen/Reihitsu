# Analyzer — RH8109 Generic type parameter documentation must match type parameters

| | |
|---|---|
| ID prefix | RH8109 |
| Status | Active |
| Category | Documentation |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH8109GenericTypeParameterDocumentationMustMatchTypeParametersAnalyzer` |
| Uses | SHARED-DOC-008, SHARED-DOC-015 |

RH8109 reports a `<typeparam>` element whose name does not match the type parameter in its position.

## Non-goals

- A type parameter without a `<typeparam>` element — RH8108.
- A `<typeparam>` element without a name, and one without text — RH8110 and RH8111.
- `<param>` elements — RH8102.

## Requirements

### RH8109-001 — A `<typeparam>` element that does not follow the type parameters is reported

The analyzer MUST report each `<typeparam>` element that does not match the declaration's type parameters as SHARED-DOC-015 specifies, in the documentation comment of a class, struct, interface, record, record struct, delegate, or method declaration. A method that explicitly implements an interface member MUST be checked as well, and the declaration's accessibility does not matter. Nothing is reported when SHARED-DOC-008 applies.

This requirement covers what SHARED-DOC-015 covers.

Why: A description that names the wrong type parameter, or one the declaration does not have, makes the reader attach the text to the wrong type argument, and one in a different order than the declaration has to be matched up by hand.

Example:

```csharp
/// <summary>
/// Pair
/// </summary>
/// {|RH8109:<typeparam name="TSecond">Second</typeparam>|}
/// {|RH8109:<typeparam name="TFirst">First</typeparam>|}
public class Pair<TFirst, TSecond>
{
}

/// <summary>
/// Factory
/// </summary>
/// <typeparam name="T">Result</typeparam>
/// {|RH8109:<typeparam name="U">Extra</typeparam>|}
public delegate T Factory<T>();

/// <summary>
/// Contract
/// </summary>
public interface I
{
    /// <summary>
    /// Maps
    /// </summary>
    /// <typeparam name="TSource">Source</typeparam>
    /// <typeparam name="TTarget">Target</typeparam>
    void Map<TSource, TTarget>();
}
```

### RH8109-002 — The diagnostic is on the element

The analyzer MUST report one diagnostic per reported `<typeparam>` element, located on the whole element: the empty element, or everything from the start tag through the end tag.

Why: The element is what has to be renamed or moved, and each misplaced element is corrected on its own.

Example: see RH8109-001.
