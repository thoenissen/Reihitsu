# Analyzer — RH3208 Expression style local functions should not be used

| | |
|---|---|
| ID prefix | RH3208 |
| Status | Active |
| Category | Clarity |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH3208ExpressionStyleLocalFunctionsShouldNotBeUsedAnalyzer`, `RH3208ExpressionStyleLocalFunctionsShouldNotBeUsedCodeFixProvider` |
| Uses | SHARED-BODY-001, SHARED-BODY-002, SHARED-BODY-003, FMT-STRUCT-004, SHARED-BLANK-003, SHARED-BLANK-004 |

RH3208 reports an expression-bodied local function and offers a code fix that converts it to a block body, as the formatter does under FMT-STRUCT-004. Which local functions are left alone, where the diagnostic is, and how the body is converted are SHARED-BODY-001, SHARED-BODY-002, and SHARED-BODY-003; this spec adds the blank line the fix inserts after the new block and the column the block is laid out from.

## Non-goals

- Expression-bodied methods (RH3202), constructors (RH3203), operators (RH3205), conversion operators (RH3206), and finalizers (RH3207).
- Lambdas, which stay expression-bodied (FMT-STRUCT-008).

## Requirements

### RH3208-001 — Every expression-bodied local function is reported

The analyzer MUST report every local function that has an expression body — in a method, a lambda, another local function, or top-level statements, `async` or not — unless SHARED-BODY-001 applies. A local function with a block body or without a body MUST NOT be reported.

Why: The house style uses block bodies for local functions, as for methods; the other function kinds have rules of their own, so each kind can be configured separately.

Example:

```csharp
using System;
using System.Threading.Tasks;

class C
{
    void M()
    {
        Func<int> f = () =>
        {
            int One() {|RH3208:=> 1|};

            return One();
        };

        async Task RunAsync() {|RH3208:=> await Task.Delay(1)|};

        int Fail()
        {
            throw new InvalidOperationException();
        }

        static extern int Native();
    }
}
```

### RH3208-002 — The fix separates the new block from the next statement

When the converted local function, or the labeled statement it is the statement of, is followed by another statement of the same block or switch section and SHARED-BLANK-003 requires a blank line between them, the code fix MUST insert that blank line in the same step. The blank line MUST go in front of a comment that leads the next statement and after a preprocessor directive that leads it. No blank line MUST be inserted when one is already there, when the next statement is the terminal `break` of SHARED-BLANK-004, or when the local function is the last statement.

Why: Formatting the local function alone does not decide the gap below it, yet the new closing brace would otherwise leave code that RH5030 reports. A comment describes the statement below it and stays with it; a blank line in front of a directive would land on the other side of the code the directive guards.

Example:

```csharp
class C
{
    int M()
    {
        int Twice(int x) {|RH3208:=> x * 2|};
        // Use it.
        return Twice(1);
    }

    int N()
    {
        int Twice(int x) {|RH3208:=> x * 2|};
#pragma warning disable CS0168
        return Twice(1);
    }

    void O(int a)
    {
        switch (a)
        {
            case 1:
                int Twice(int x) {|RH3208:=> x * 2|};
                break;
        }
    }

    int P()
    {
        L: int Local() {|RH3208:=> 1|};
        return Local();
    }
}
```

```csharp
class C
{
    int M()
    {
        int Twice(int x)
        {
            return x * 2;
        }

        // Use it.
        return Twice(1);
    }

    int N()
    {
        int Twice(int x)
        {
            return x * 2;
        }
#pragma warning disable CS0168

        return Twice(1);
    }

    void O(int a)
    {
        switch (a)
        {
            case 1:
                int Twice(int x)
                {
                    return x * 2;
                }
                break;
        }
    }

    int P()
    {
        L: int Local()
        {
            return 1;
        }

        return Local();
    }
}
```

### RH3208-003 — The block of a labeled local function is laid out from the start of its line

When a label stands in front of the local function on the same line, the code fix MUST lay out the block from the column at which that line starts. When the local function starts its own line, the code fix MUST lay out the block from the column of the local function, also below a label on a line of its own.

Why: The block's braces line up with the start of the line the declaration begins on, as for any statement; a label on the same line belongs to that line, while a label on its own line does not move the statement below it.

Example:

```csharp
class C
{
    void M()
    {
        goto L;
        L: int Local() {|RH3208:=> 1|};
    }

    int N()
    {
        goto L;
    L:
        int Local() {|RH3208:=> 1|};
        return Local();
    }
}
```

```csharp
class C
{
    void M()
    {
        goto L;
        L: int Local()
        {
            return 1;
        }
    }

    int N()
    {
        goto L;
    L:
        int Local()
        {
            return 1;
        }

        return Local();
    }
}
```
