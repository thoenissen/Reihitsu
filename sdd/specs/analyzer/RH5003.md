# Analyzer — RH5003 while-Statement should be preceded by a blank line

| | |
|---|---|
| ID prefix | RH5003 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5003WhileStatementsShouldBePrecededByABlankLineAnalyzer`, `RH5003WhileStatementsShouldBePrecededByABlankLineCodeFixProvider` |
| Uses | SHARED-STMT-001, SHARED-STMT-002, SHARED-STMT-003, SHARED-STMT-004 |

RH5003 reports a `while` statement that follows another statement of the same block or switch section without a blank line between them, and offers a code fix that inserts one as SHARED-STMT-004 specifies.

## Non-goals

- Blank lines before other statement kinds — the other rules that use `shared/statement-blank-lines.md`.

## Requirements

### RH5003-001 — A `while` statement that follows a statement needs a blank line

The analyzer MUST report a `while` statement as SHARED-STMT-001, SHARED-STMT-002, and SHARED-STMT-003 specify.

Why: A `while` statement starts a loop; the blank line marks where the repeated part begins.

Example:

```csharp
class C
{
    void M(bool keepRunning)
    {
        var count = 0;
        {|RH5003:while|} (keepRunning)
        {
            count++;
        }

        while (count > 0)
        {
            count--;
        }
    }
}
```

The second `while` follows a blank line and is not reported.

### RH5003-002 — The diagnostic is on the `while` keyword

The analyzer MUST report the diagnostic on the `while` keyword.

Why: The keyword is where the missing separator becomes visible, and the location stays stable when the condition changes.

Example: see RH5003-001.
