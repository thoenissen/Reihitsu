# Analyzer — RH2101 Nested classes should not be used

| | |
|---|---|
| ID prefix | RH2101 |
| Status | Active |
| Category | Design |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH2101NestedClassesShouldNotBeUsedAnalyzer` |
| Uses | SHARED-NESTED-001, SHARED-NESTED-002 |

RH2101 reports a class declared inside another type, unless the class is `static`.

## Non-goals

- Nested records, which are reported by RH2106, and nested structs, interfaces, enums, and delegates — RH2104, RH2105, RH2107, and RH2108.

## Requirements

### RH2101-001 — A nested class is reported

The analyzer MUST report a class declaration that is nested as SHARED-NESTED-001 defines it, located as SHARED-NESTED-002 specifies. A record class MUST NOT be reported.

Why: A class inside another type is harder to discover, to reuse, and to test on its own, and it hides a declaration inside a type that is about something else.

Example:

```csharp
class Outer
{
    class {|RH2101:Helper|}
    {
    }

    record Point(int X);
}
```

### RH2101-002 — A nested static class is not reported

The analyzer MUST NOT report a nested class that carries the `static` modifier. A class nested in a static class MUST be reported when it is not `static` itself.

Why: A static class holds no instance state; keeping a small group of helpers next to the type that uses them is accepted. What matters is the nested class itself, not the type that contains it.

Example:

```csharp
class Outer
{
    static class Helpers
    {
        class {|RH2101:State|}
        {
        }
    }
}
```
