# Analyzer — RH8203 Inheritdoc must be used with inheriting class

| | |
|---|---|
| ID prefix | RH8203 |
| Status | Active |
| Category | Documentation |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH8203InheritdocMustBeUsedWithInheritingClassAnalyzer` |
| Uses | SHARED-DOC-004, SHARED-DOC-008 |

RH8203 reports an `<inheritdoc>` element on a declaration that has no documentation to inherit.

## Non-goals

- A member that inherits documentation but does not use `<inheritdoc>` — RH8201.
- Whether `<inheritdoc>` documents a declaration — SHARED-DOC-005.
- Enum members and extension declarations.

## Requirements

### RH8203-001 — `<inheritdoc>` on a declaration that inherits nothing is reported

The analyzer MUST report an `<inheritdoc>` element without a `cref` attribute in the documentation of a class, struct, interface, record, record struct, enum, delegate, constructor, destructor, method, property, indexer, field, event, field-like event, operator, or conversion operator declaration that inherits no documentation. The element considered MUST be the `<inheritdoc>` element at the top level of the declaration's documentation, whether it is in the declaration's documentation comment, as SHARED-DOC-004 defines it, in a later documentation comment, or in the content that an `<include>` element brings in. An `<inheritdoc>` element nested inside another element MUST NOT be considered, and an `<inheritdoc>` element with a `cref` attribute MUST NOT be reported.

A declaration inherits documentation when it is:

- a class, struct, interface, record, or record struct declaration with a base list, whatever the list names;
- a constructor whose type's base type has a constructor with the same parameter types in the same order — for a class without a base list, the parameterless constructor of `object`, and for a struct, the parameterless constructor of `ValueType`;
- a method, property, indexer, event, field-like event, operator, or conversion operator declaration that is declared `override`, or that implements an interface member — explicitly, or implicitly for the type that declares it — `static abstract` operators and conversion operators included.

An enum, a delegate, a field, a destructor, and a static constructor MUST count as inheriting nothing. The declaration's accessibility does not matter, and nothing is reported when SHARED-DOC-008 applies.

This requirement covers documentation with at most one `<inheritdoc>` element at its top level, counting every documentation comment of the declaration and the content of every `<include>` element, placed as SHARED-DOC-004 covers and well-formed XML, with the tag name `inheritdoc` written in lower case, without a namespace prefix, and in no XML namespace; an included file is covered when it is well-formed XML and writes the tag name the same way. A part of a partial element declared in several parts and a field-like event that declares several events are not covered. A constructor is covered when the base type has no `private` constructor and no constructor whose parameters differ from the constructor's only in `ref`, `in`, `out`, or `params` modifiers or in nullable annotations.

Why: `<inheritdoc/>` on a declaration with nothing above it promises documentation that does not exist: the tooltip and the generated documentation show nothing, and a reader who sees the tag assumes the contract is described elsewhere. `<inheritdoc cref="…"/>` names the declaration to take the documentation from, so it works without any inheritance. A nested `<inheritdoc>` only fills in the element around it, and the declaration keeps its own description.

Example:

```csharp
using System;

/// <summary>
/// Base
/// </summary>
public class B
{
    /// <summary>
    /// Creates
    /// </summary>
    /// <param name="value">Value</param>
    public B(int value)
    {
    }

    /// <summary>
    /// Runs
    /// </summary>
    public virtual void Run()
    {
    }
}

/// <inheritdoc/>
public class D : B
{
    /// <inheritdoc/>
    public D(int value)
        : base(value)
    {
    }

    /// {|RH8203:<inheritdoc/>|}
    public D(string text)
        : base(0)
    {
    }

    /// <inheritdoc/>
    public override void Run()
    {
    }

    /// {|RH8203:<inheritdoc/>|}
    public void Stop()
    {
    }

    /// <inheritdoc cref="Run"/>
    public void Restart()
    {
    }

    /// <summary>
    /// Pauses
    /// </summary>
    /// <remarks>
    /// <inheritdoc/>
    /// </remarks>
    public void Pause()
    {
    }

    /// {|RH8203:<inheritdoc/>|}
    public int Count;
}

/// {|RH8203:<inheritdoc/>|}
public class Standalone
{
}

/// <inheritdoc/>
public class Resource : IDisposable
{
    /// <inheritdoc/>
    public void Dispose()
    {
    }
}

/// {|RH8203:<inheritdoc/>|}
public enum E
{
}

/// {|RH8203:<inheritdoc/>|}
public delegate void Handler();

/// <summary>
/// Addition
/// </summary>
/// <typeparam name="T">Operand</typeparam>
public interface IAdd<T>
    where T : IAdd<T>
{
    /// <summary>
    /// Adds
    /// </summary>
    /// <param name="left">Left</param>
    /// <param name="right">Right</param>
    /// <returns>Sum</returns>
    static abstract T operator +(T left, T right);
}

/// <summary>
/// Value
/// </summary>
public class V : IAdd<V>
{
    /// <inheritdoc/>
    static V IAdd<V>.operator +(V left, V right) => left;

    /// {|RH8203:<inheritdoc/>|}
    public static V operator -(V left, V right) => left;
}
```

### RH8203-002 — The diagnostic is on the element or on the declaration's name

The analyzer MUST report one diagnostic per declaration. It MUST be located on the reported `<inheritdoc>` element when that element is in the declaration's documentation comment, as SHARED-DOC-004 defines it, and on the declaration's name when the element comes from a later documentation comment or from an included file: the identifier, `this` for an indexer, the operator token of an operator, the `operator` keyword of a conversion operator, and the first variable of a field or a field-like event.

Why: The element is what has to be replaced, so the squiggle marks it where it is written. An element in an included file has no place in the source to mark, so the declaration it misdocuments is marked instead.

Example:

```csharp
/// <summary>
/// Service
/// </summary>
public class C
{
    /// <summary>
    /// Runs
    /// </summary>

    /// <inheritdoc/>
    public void {|RH8203:Run|}()
    {
    }
}
```

Example — with a file `docs.xml` next to the source:

```xml
<doc>
    <members>
        <member name="I">
            <inheritdoc/>
        </member>
    </members>
</doc>
```

```csharp
/// <summary>
/// Service
/// </summary>
public class C
{
    /// <include file='docs.xml' path='doc/members/member[@name="I"]/*'/>
    public int {|RH8203:this|}[int index] => 0;
}
```
