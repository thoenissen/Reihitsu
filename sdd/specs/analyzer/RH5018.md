# Analyzer — RH5018 lock-Statement should be preceded by a blank line

| | |
|---|---|
| ID prefix | RH5018 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5018LockStatementsShouldBePrecededByABlankLineAnalyzer`, `RH5018LockStatementsShouldBePrecededByABlankLineCodeFixProvider` |
| Uses | SHARED-STMT-001, SHARED-STMT-002, SHARED-STMT-003, SHARED-STMT-004 |

RH5018 reports a `lock` statement that follows another statement of the same block or switch section without a blank line between them, and offers a code fix that inserts one as SHARED-STMT-004 specifies.

## Non-goals

- Blank lines before other statement kinds — the other rules that use `shared/statement-blank-lines.md`.

## Requirements

### RH5018-001 — A `lock` statement that follows a statement needs a blank line

The analyzer MUST report a `lock` statement as SHARED-STMT-001, SHARED-STMT-002, and SHARED-STMT-003 specify.

Why: A `lock` statement opens a region that holds a lock; the blank line marks where the protected region begins.

Example:

```csharp
class C
{
    private readonly object _gate = new object();

    void M(int a)
    {
        a++;
        {|RH5018:lock|} (_gate)
        {
            a--;
        }

        lock (_gate)
        {
            a++;
        }
    }
}
```

The second `lock` follows a blank line and is not reported.

### RH5018-002 — The diagnostic is on the `lock` keyword

The analyzer MUST report the diagnostic on the `lock` keyword.

Why: The keyword is where the missing separator becomes visible, and the location stays stable when the lock expression changes.

Example: see RH5018-001.
