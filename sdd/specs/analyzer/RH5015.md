# Analyzer — RH5015 checked-Statement should be preceded by a blank line

| | |
|---|---|
| ID prefix | RH5015 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5015CheckedStatementsShouldBePrecededByABlankLineAnalyzer`, `RH5015CheckedStatementsShouldBePrecededByABlankLineCodeFixProvider` |
| Uses | SHARED-STMT-001, SHARED-STMT-002, SHARED-STMT-003, SHARED-STMT-004 |

RH5015 reports a `checked` statement that follows another statement of the same block or switch section without a blank line between them, and offers a code fix that inserts one as SHARED-STMT-004 specifies.

## Non-goals

- Blank lines before other statement kinds — the other rules that use `shared/statement-blank-lines.md`.

## Requirements

### RH5015-001 — A `checked` statement that follows a statement needs a blank line

The analyzer MUST report a `checked` statement as SHARED-STMT-001, SHARED-STMT-002, and SHARED-STMT-003 specify. It MUST NOT report an `unchecked` statement or a `checked` expression.

Why: A `checked` statement opens a block with overflow checking; the blank line marks where that context begins. A `checked` expression is part of the statement that contains it.

Example:

```csharp
class C
{
    void M(int a)
    {
        a++;
        {|RH5015:checked|}
        {
            a++;
        }

        a++;
        unchecked
        {
            a--;
        }

        a++;
        a = checked(a + 1);
    }
}
```

The `unchecked` statement belongs to RH5016, and `checked(a + 1)` is an expression; RH5015 reports neither.

### RH5015-002 — The diagnostic is on the `checked` keyword

The analyzer MUST report the diagnostic on the `checked` keyword.

Why: The keyword is where the missing separator becomes visible.

Example: see RH5015-001.
