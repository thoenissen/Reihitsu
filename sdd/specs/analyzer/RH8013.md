# Analyzer — RH8013 Enum members in non-private enums must be documented

| | |
|---|---|
| ID prefix | RH8013 |
| Status | Active |
| Category | Documentation |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH8013NonPrivateEnumMembersMustBeDocumentedAnalyzer` |
| Uses | SHARED-DOC-001, SHARED-DOC-002, SHARED-DOC-003, SHARED-DOC-004, SHARED-DOC-005, SHARED-DOC-006, SHARED-DOC-007, SHARED-DOC-008 |

RH8013 reports a member of an enum in the non-private group that has no `<summary>` or `<inheritdoc>` documentation.

## Non-goals

- Members of enums in the private group — RH8014.
- The enum itself — RH8011 and RH8012.
- Whether the summary has text — RH8030.

## Requirements

### RH8013-001 — Undocumented members of non-private enums are reported

The analyzer MUST report every enum member that belongs to the non-private group, as SHARED-DOC-003 derives it from its enum with SHARED-DOC-002, and that is not documented, checked as SHARED-DOC-001 specifies: whether the enum itself is documented does not matter. Whether a member is documented MUST be decided as SHARED-DOC-004, SHARED-DOC-005, SHARED-DOC-006, and SHARED-DOC-007 specify, and nothing is reported when SHARED-DOC-008 applies.

Why: Each member of an enum that other code can use is a value that code passes and compares; the enum's summary rarely says what each value means, and the editor's tooltip on a member shows only the member's own documentation.

Example:

```csharp
/// <summary>
/// Color
/// </summary>
public enum Color
{
    {|RH8013:Red|},

    /// <remarks>
    /// No summary
    /// </remarks>
    {|RH8013:Green|} = 2,

    /// <summary>
    /// Blue
    /// </summary>
    Blue,
}

internal enum State
{
    {|RH8013:Open|},
    {|RH8013:Closed|},
}

/// <summary>
/// Outer
/// </summary>
public class Outer
{
    private enum Hidden
    {
        Value,
    }
}
```

### RH8013-002 — The diagnostic is on the member name

The analyzer MUST report one diagnostic per undocumented enum member, located on its identifier, without its value.

Why: Each member needs its own documentation, and the name identifies the member that lacks it.

Example: see RH8013-001.
