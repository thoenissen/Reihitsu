# Analyzer — RH4106 Private field casing

| | |
|---|---|
| ID prefix | RH4106 |
| Status | Active |
| Category | Naming |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH4106PrivateFieldCasingAnalyzer`, `RH4106PrivateFieldCasingCodeFixProvider` |
| Uses | SHARED-CASING-003, SHARED-CASING-004, SHARED-CASING-006, SHARED-CASING-007, SHARED-CASING-008, SHARED-CASING-009, SHARED-CASING-010 |

RH4106 reports a private field whose name is not in `_camelCase` and offers a code fix that renames the field and every reference to it.

## Non-goals

- `const` fields of any accessibility — RH4110.
- Fields of the protected, internal, and public groups — RH4107, RH4108, and RH4109.
- Whether a field should be private at all — RH2005.
- Names of properties, locals, and parameters — the other RH41xx rules.

## Requirements

### RH4106-001 — Private fields that are not constants are checked

The analyzer MUST check every variable declarator of a field declaration that is not `const` and belongs to the private group of SHARED-CASING-004. Static, readonly, and static readonly fields MUST be checked too.

Why: The underscore prefix marks state of the object at the point of use. That matters for state that is invisible outside the type; the other groups and constants are named for their users and have their own conventions.

Example:

```csharp
public class C
{
    private int {|RH4106:MyField|};
    int {|RH4106:my_field2|};
    private static readonly int {|RH4106:MaxValue|} = 1;
    private const int Limit = 2;
    protected int Prot;
    private protected int PrivProt;

    public int Run() => MyField + my_field2 + MaxValue + Limit;
}
```

### RH4106-002 — Private field names are in `_camelCase`

The analyzer MUST report a checked field whose name is not in `_camelCase` as SHARED-CASING-003 defines it.

Why: The prefix keeps a field apart from a parameter or a local of the same meaning, so a constructor parameter `count` and the field `_count` it initializes can share their words without `this.`.

Example:

```csharp
public class C
{
    private int _total;
    private int {|RH4106:total2|};
    private int {|RH4106:Count|};
}
```

### RH4106-003 — The diagnostic is on the field name

The analyzer MUST report one diagnostic per non-conforming declarator, located on its identifier.

Why: Each declarator is its own field with its own name, and the fix renames one field at a time.

Example:

```csharp
public class C
{
    private int _ok, {|RH4106:Bad|}, {|RH4106:worse|};
}
```

### RH4106-004 — The fix renames the field to `_camelCase`

The code fix MUST rename the field to the `_camelCase` name that SHARED-CASING-006 derives from its old name. This requirement covers the renames that SHARED-CASING-007 covers.

Why: The fix makes exactly the change the diagnostic asks for, with the same derivation as every other casing fix.

Example:

```csharp
internal class C
{
    int {|RH4106:cacheCount|};
    private static readonly int {|RH4106:cacheLimit|} = 10;
}
```

```csharp
internal class C
{
    int _cacheCount;
    private static readonly int _cacheLimit = 10;
}
```

### RH4106-005 — The fix renames every use of the field

The code fix MUST rename the field together with every reference to it, as SHARED-CASING-007 specifies.

Why: A field is read and written throughout its type; a fix that renamed only the declaration would break every one of those uses.

Example:

```csharp
public class C
{
    private int {|RH4106:cacheCount|};

    public int GetCount()
    {
        return cacheCount;
    }
}
```

```csharp
public class C
{
    private int _cacheCount;

    public int GetCount()
    {
        return _cacheCount;
    }
}
```

### RH4106-006 — The fix is withheld when the new name is unusable or taken

The code fix MUST NOT be offered when SHARED-CASING-008 or SHARED-CASING-009 withholds it. The diagnostic is still reported.

Why: A field without letters has no words to build a name from, and a name that is already taken cannot be resolved without knowing which of the two fields the author meant.

Example:

```csharp
public class C
{
    private int {|RH4106:__|};
}
```

is reported, and no code fix is offered. The same holds for `Value` next to an existing `_value` (SHARED-CASING-009).

### RH4106-007 — Fix All skips fields that would collide with each other

The Fix All provider MUST skip fields whose new names would collide with each other, as SHARED-CASING-010 specifies, and rename every other reported field.

Why: Two fields that differ only in casing would receive the same name; which of them should keep it is the author's decision.

Example:

```csharp
public class C
{
    private int {|RH4106:Value|};

    private int {|RH4106:value|};

    private int {|RH4106:Count|};

    public int Sum => Value + value + Count;
}
```

```csharp
public class C
{
    private int {|RH4106:Value|};

    private int {|RH4106:value|};

    private int _count;

    public int Sum => Value + value + _count;
}
```
