# Analyzer — RH5013 throw-Statement should be preceded by a blank line

| | |
|---|---|
| ID prefix | RH5013 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5013ThrowStatementsShouldBePrecededByABlankLineAnalyzer`, `RH5013ThrowStatementsShouldBePrecededByABlankLineCodeFixProvider` |
| Uses | SHARED-STMT-001, SHARED-STMT-002, SHARED-STMT-003, SHARED-STMT-004 |

RH5013 reports a `throw` statement that follows another statement of the same block or switch section without a blank line between them, and offers a code fix that inserts one as SHARED-STMT-004 specifies.

## Non-goals

- Blank lines before other statement kinds — the other rules that use `shared/statement-blank-lines.md`.

## Requirements

### RH5013-001 — A `throw` statement that follows a statement needs a blank line

The analyzer MUST report a `throw` statement as SHARED-STMT-001, SHARED-STMT-002, and SHARED-STMT-003 specify. It MUST NOT report a `throw` expression, such as the right operand of `??`.

Why: A `throw` statement ends the current path with an exception; the blank line makes that exit visible. A `throw` expression is part of a larger expression, not a step of its own.

Example:

```csharp
class C
{
    void M(object value)
    {
        var text = value.ToString();
        {|RH5013:throw|} new System.InvalidOperationException(text);
    }

    string N(string value)
    {
        var text = value ?? throw new System.ArgumentNullException(nameof(value));

        return text;
    }
}
```

The `throw` expression in `N` is not a statement and is not reported.

### RH5013-002 — The diagnostic is on the `throw` keyword

The analyzer MUST report the diagnostic on the `throw` keyword.

Why: The keyword is where the missing separator becomes visible, and the location stays stable when the thrown expression changes.

Example: see RH5013-001.
