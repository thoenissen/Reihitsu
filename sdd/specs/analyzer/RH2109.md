# Analyzer — RH2109 Razor code blocks should not be used

| | |
|---|---|
| ID prefix | RH2109 |
| Status | Active |
| Category | Design |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH2109RazorCodeBlocksShouldNotBeUsedAnalyzer` |
| Uses | SHARED-DIAG-003 |

RH2109 reports every `@code` block in a Razor component file, so the component's logic moves to a code-behind file.

## Non-goals

- How a `.razor` file reaches the compiler. It is read only when it is an additional file of the project.
- Razor views and pages (`.cshtml`).
- The code that a `@code` block contains, and the C# that the Razor compiler generates from the component.
- A code fix. Moving a block into a `.razor.cs` partial class creates a file and needs the component's namespace and class name.

## Requirements

### RH2109-001 — A `@code` block in a `.razor` file is reported

The analyzer MUST report every `@code` directive that is followed by an opening brace `{`, with or without white space or line breaks between them, in an additional file whose path ends in `.razor`, compared case-insensitively. A `@code` is a directive only when it starts a line, after optional white space, and is not text. A `@code` behind other characters on its line, and a `@code` that SHARED-DIAG-003 makes text (its last example shows the cases for this rule), MUST NOT be reported; for a line inside a multi-line C# comment or literal, RH2109-004 decides instead.

Why: A `@code` block puts the component's behavior into its markup file. A code-behind partial class keeps rendering and behavior apart and gives the logic the full C# tooling of a `.cs` file.

Example — `Counter.razor`:

```razor
@page "/counter"
<h1>@CurrentCount</h1>
@code {
    private int CurrentCount;
}
@code
{
}
```

reports both `@code` directives.

Example — the Razor compiler accepts `@code` only at the start of a line, so in `Counter.razor`

```razor
<div>@code { int X; }</div>
<div>
    @code {
    }
</div>
```

only the `@code` on line 3 is reported.

### RH2109-002 — Other files are not reported

The analyzer MUST NOT report a file whose path does not end in `.razor`, such as a `.razor.cs` code-behind file or a `.cshtml` file, and MUST NOT report a `.razor` file without a `@code` block.

Why: The rule is about the code blocks of Razor components; a code-behind file is where their logic belongs.

Example — `Counter.razor.cs`:

```csharp
public partial class Counter
{
    private int CurrentCount;
}
```

is not reported, and neither is `Counter.razor` with the content

```razor
@page "/counter"
<h1>Counter</h1>
```

### RH2109-003 — The diagnostic covers `@code`

The analyzer MUST report one diagnostic per `@code` block, located in the `.razor` file on the five characters `@code`.

Why: The directive is what the user removes; the block it opens can be long.

Example: see RH2109-001.

### RH2109-004 — A line inside a multi-line C# comment or literal is read like markup

RH2109 reads a `.razor` file as Razor markup and does not lex its C#: it does not decide where the C# of a host block such as `@code { }`, `@functions { }`, `@{ }`, or a control-flow block starts and ends, nor where a C# comment or literal inside it does. A line inside a multi-line C# comment or literal — a `/* */` or `/** */` comment, a verbatim, raw, interpolated verbatim, or interpolated raw string — is therefore read like a line of markup, although SHARED-DIAG-003 makes it the text of a comment or a literal:

- a `@code` followed by `{` that starts such a line MUST be reported like a directive;
- an `@*` or `<!--` that starts such a line opens a Razor or HTML comment for this rule, so a `@code` from there up to the `*@` that closes an `@*`, or the `-->` that closes an `<!--`, is text and MUST NOT be reported, also when it is a real directive; when that closer does not follow, the comment runs to the end of the file, and a closer of the other kind does not end it.

A line inside a single-line C# comment or literal never starts with `@code`, because the comment's or literal's opener stands before it on the line, so RH2109-001's rule for a `@code` behind other characters on its line already decides it.

Why: Deciding whether a line lies inside a C# comment or literal needs both where Razor's C# ends — across the markup that C# in a Razor file can hold — and a lexer of C# comments and every literal form. That is a parser of text, which a rule does not grow for a rare input (`AGENTS.md`, *Special cases do not grow the source*). The input is rare: commented-out or quoted Razor source. A `@code` reported inside a `@code` host adds a diagnostic to a file this rule already reports.

Example — in `Counter.razor`

```razor
@code {
    /*
    @code {
    }
    */
    string s = """
@code {
""";
}
```

the `@code` on lines 1, 3, and 7 is reported.

Example — in `Counter.razor`

```razor
@code {
    /*
    @* not a Razor comment
    */
}
@code {
}
```

only the `@code` on line 1 is reported: the `@*` on line 3 starts its line, so the rest of the file is read as a Razor comment.

Example — an `@*` is closed only by `*@`, so in `Counter.razor`

```razor
@code {
    /*
    @* x
    */
}
<!-- -->
@code {
}
```

only the `@code` on line 1 is reported: the `-->` on line 6 does not close the `@*` on line 3.
