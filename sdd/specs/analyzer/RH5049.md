# Analyzer — RH5049 Comments must not be placed after a binary operator

| | |
|---|---|
| ID prefix | RH5049 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH5049CommentsMustNotBePlacedAfterBinaryOperatorAnalyzer` |
| Uses | SHARED-COMMENT-001, SHARED-COMMENT-002, SHARED-COMMENT-003, SHARED-COMMENT-007 |

RH5049 reports a comment placed directly after a binary operator, between the operator and its right operand.

## Non-goals

- Where a wrapped binary expression breaks — the line-break rules.
- A comment after an assignment operator — RH5042; after the `?` or `:` of a conditional expression — RH5045.

## Requirements

### RH5049-001 — A comment after a binary operator is reported

The analyzer MUST report every ordinary comment (SHARED-COMMENT-001, SHARED-COMMENT-002) directly after a binary operator, as SHARED-COMMENT-007 defines it, wherever the binary expression stands, as SHARED-COMMENT-003 specifies. A comment directly before a binary operator, and a comment after an operator inside a pattern, MUST NOT be reported.

Why: A wrapped binary expression breaks before the operator, so the operator starts the line of the operand it introduces. A comment after the operator separates the operator from its right operand.

Example:

```csharp
class C
{
    bool M(bool a, bool b, object o, int x)
    {
        var sum = 1 + {|RH5049:// second|}
                  2;
        var value = o ??
            {|RH5049:// fallback|}
            x;
        var text = o as {|RH5049:/* text */|} string;
        var isNumber = o is int or
            // wide
            long;
        _ = (sum, value, text, isNumber);

        return a
               // why b
               && b;
    }
}
```

The comments `// wide` and `// why b` are not reported.
