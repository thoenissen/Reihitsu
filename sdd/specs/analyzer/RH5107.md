# Analyzer — RH5107 Comma must be on same line as previous parameter

| | |
|---|---|
| ID prefix | RH5107 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5107CommaMustBeOnSameLineAsPreviousParameterAnalyzer`, `RH5107CommaMustBeOnSameLineAsPreviousParameterCodeFixProvider` |
| Uses | FMT-BREAK-011, FMT-BREAK-012, RH5035-001, SHARED-FIX-003, SHARED-JOIN-001 |

RH5107 reports a comma of a parameter list that starts a line below the end of the parameter in front of it, and offers a code fix that moves the comma behind that parameter.

## Non-goals

- The commas of an argument list.
- The bracketed parameter list of an indexer.
- The spaces around a comma — RH6002.
- Moving a comment that stands behind the comma together with the comma — RH5107-004 withholds the fix for it.

## Requirements

### RH5107-001 — A comma below its parameter is reported

The analyzer MUST report a comma between two parameters of a parenthesized parameter list — of a declaration, a primary constructor, an anonymous method, or a parenthesized lambda — when the comma starts on a later line than the parameter in front of it ends on, except where SHARED-JOIN-001 keeps the gap from being reported.

Why: A comma at the start of a line separates a parameter from its separator, which is easy to misread (FMT-BREAK-011); at the end of the line it shows that the list continues.

Example:

```csharp
using System;

class C
{
    void M(int a
           {|RH5107:,|} int b
           {|RH5107:,|}int c)
    {
        Func<int, int, int> f = (int x
            {|RH5107:,|} int y) => x;
        N(1
          , 2);
    }

    void N(params int[] values)
    {
    }
}
```

### RH5107-002 — The diagnostic is on the comma

The analyzer MUST report one diagnostic per misplaced comma, located on the comma.

Why: Each comma is moved on its own.

Example: see RH5107-001.

### RH5107-003 — The fix moves the comma behind the previous parameter

Where RH5107-004 does not withhold it, the code fix MUST insert the comma directly behind the parameter in front of it and remove it from its own line. When the comma's line holds more than whitespace after the comma, the indentation, the comma, and the whitespace after it MUST be replaced with spaces up to the column of the list's first parameter. When nothing but whitespace remains on the comma's line, that line MUST be removed, line break included.

Why: The parameter that followed the comma now starts its line, so it is aligned under the first parameter. A line that held only the comma would otherwise stay behind empty.

Example:

```csharp
class C
{
    void M(int a
           {|RH5107:,|} int b)
    {
    }

    void N(int a
           {|RH5107:,|}
           int b)
    {
    }
}
```

```csharp
class C
{
    void M(int a,
           int b)
    {
    }

    void N(int a,
           int b)
    {
    }
}
```

### RH5107-004 — No fix is offered when a comment stands behind the comma on its line

The code fix MUST NOT be offered when a comment stands behind the reported comma on the comma's line — a block comment followed by the next parameter (`, /* c */ int b`), a block comment that ends the line (`, /* c */`), a `//` comment (`, // c`), a documentation comment (`, /** c */ int b`, `, /** c */`, `, /// c`), several comments, or a multi-line comment that starts on the comma's line. The diagnostic is still reported (SHARED-FIX-003). A comment that starts a later line than the comma, in front of the parameter behind it, does not withhold the fix: the comma's line then holds only the comma, and RH5107-003 removes that line and leaves the comment and the parameter as they are.

The conditions, each with both sides:

- **Behind the comma on the comma's line.** A comment counts when its text starts behind the comma on the line the comma stands on: `int a⏎, /* c */ int b` and `int a⏎, /// c⏎int b` withhold the fix. A comment whose text starts on a later line does not: `int a⏎,⏎/* c */ int b` and `int a⏎,⏎/// c⏎int b` keep it.
- **Whichever token's trivia carries it.** Where the parser puts the comment does not decide. A comment behind the comma is the comma's trailing trivia when the parser lets it trail the comma — every `//` and `/* */` comment, and every comment in the documentation mode `None` — and the leading trivia of the parameter behind the comma when it does not — a `/** */` or `///` comment in the documentation modes `Parse` and `Diagnose`, where the parser puts no documentation comment into trailing trivia. Both withhold the fix: `int a⏎, /** c */ int b` withholds it in every documentation mode, as `int a⏎, /* c */ int b` does. A documentation comment in the parameter's leading trivia that starts a later line than the comma does not withhold it (first condition).

Why: A comment behind the comma is written with the comma. The fix moves only the comma, so it would leave a comment that ends the comma's line behind on a line of its own (`, // c` becomes `int a,` and `// c` below it), which moves a comment away from the code it stands with (SHARED-FIX-003); for a block comment between the comma and the next parameter it would keep the comment in front of the parameter, while the formatter keeps such a comment behind the moved comma (FMT-BREAK-011, FMT-BREAK-012), so a fixed file and a formatted file would keep two placements. Moving the comment with the comma would write the formatter's comment placement a second time into the fix's own text edit. A documentation comment behind the comma is written with the comma like any other comment; the parser attaching it to the parameter behind the comma changes nothing in the text, so it withholds the fix as well, and a `/// c` that ends the comma's line would otherwise be left on a line of its own above the parameter. Such a parameter list is rare: RH5035 reports every comment inside it (RH5035-001), so the comma is left to be moved by hand; a diagnostic without a fix is a supported end state.

Example:

```csharp
class C
{
    void P(int a
           {|RH5107:,|} /* c */ int b)
    {
    }

    void Q(int a
           {|RH5107:,|} // c
           int b)
    {
    }

    void R(int a
           {|RH5107:,|} /* c */
           int b)
    {
    }

    void S(int a
           {|RH5107:,|} /** c */ int b)
    {
    }

    void U(int a
           {|RH5107:,|} /// c
           int b)
    {
    }
}
```

is reported, and no code fix is offered, in every documentation mode.

Example — a comment that starts the line behind the comma's line keeps the fix:

```csharp
class C
{
    void T(int a
           {|RH5107:,|}
           /* c */ int b)
    {
    }

    void V(int a
           {|RH5107:,|}
           /** c */ int b)
    {
    }
}
```

```csharp
class C
{
    void T(int a,
           /* c */ int b)
    {
    }

    void V(int a,
           /** c */ int b)
    {
    }
}
```
