# Analyzer — RH3202 Expression style methods should not be used

| | |
|---|---|
| ID prefix | RH3202 |
| Status | Active |
| Category | Clarity |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH3202ExpressionStyleMethodsShouldNotBeUsedAnalyzer`, `RH3202ExpressionStyleMethodsShouldNotBeUsedCodeFixProvider` |
| Uses | FMT-STRUCT-004, FMT-STRUCT-006, FMT-STRUCT-007, FMT-PIPE-010 |

RH3202 reports an expression-bodied method and offers a code fix that converts it to a block body by formatting the method with the formatter. The rule and the formatter's FMT-STRUCT-004 are two views of one style decision and share the guard that decides which methods can be converted (RH3202-002).

## Non-goals

- Expression-bodied local functions (RH3208), constructors (RH3203), operators (RH3205), conversion operators (RH3206), and finalizers (RH3207).
- Expression-bodied properties, indexers, accessors, and lambdas, which stay expression-bodied (FMT-STRUCT-008).
- Which statement the converted body contains and how its trivia is carried over — FMT-STRUCT-004 and FMT-STRUCT-006 own that; this spec only references them.

## Requirements

### RH3202-001 — Every expression-bodied method is reported

The analyzer MUST report every method declaration that has an expression body — in a class, struct, record, or interface, static or instance, `async` or not — unless RH3202-002 applies. Local functions, operators, conversion operators, properties, and indexers MUST NOT be reported.

Why: The house style keeps expression bodies for properties, indexers, and accessors and uses block bodies for methods. The other function kinds have rules of their own, so each kind can be configured separately.

Example:

```csharp
using System;

class C
{
    void Run() {|RH3202:=> Console.WriteLine()|};

    void Outer()
    {
        int Local() => 1;
    }

    public static C operator +(C a, C b) => a;

    int P => 1;
}

interface I
{
    int M() {|RH3202:=> 1|};
}
```

### RH3202-002 — A method the formatter cannot convert is not reported

The analyzer MUST NOT report an expression-bodied method whose expression body the formatter keeps under FMT-STRUCT-007. Both decisions MUST come from `ExpressionBodyRewriteUtilities.BlocksRewrite`.

Why: A diagnostic whose fix the formatter then refuses would never converge: the fix would run and leave the code as it was. Sharing the one predicate keeps analyzer, code fix, and formatter in step.

Example:

```csharp
class C
{
    public int GetValue() =>
#pragma warning disable CS0618
        1;
#pragma warning restore CS0618
}
```

is not reported. A directive after the expression does not block the conversion:

```csharp
class C
{
    public int GetValue() {|RH3202:=> 1|}
#pragma warning disable CS0618
        ;
}
```

```csharp
class C
{
    public int GetValue()
    {
        return 1
#pragma warning disable CS0618
        ;
    }
}
```

### RH3202-003 — The diagnostic covers the expression body

The analyzer MUST report the diagnostic on the expression body, from the `=>` token to the end of the expression, excluding the semicolon.

Why: The arrow and the expression are what the fix replaces; the method name and signature stay.

Example:

```csharp
class C
{
    public int GetValue() {|RH3202:=>
        42|};
}
```

### RH3202-004 — The fix converts the method as the formatter does

The code fix MUST format the reported method with `ReihitsuFormatter.FormatNodeInDocumentAsync`, so the block body is exactly the one FMT-STRUCT-004 and FMT-STRUCT-006 produce, and only the method changes (FMT-PIPE-010). The rest of the method is laid out by the formatter in the same step.

Why: One owner for the conversion keeps the fix and the formatter from drifting apart; a fix that hand-built the block would have to reimplement the statement choice for `void`, `async`, and throw expressions and the trivia transfer.

Example:

```csharp
using System;
using System.Threading.Tasks;

class C
{
    void Run() {|RH3202:=> Console.WriteLine()|};

    async Task RunAsync() {|RH3202:=> await Task.Delay(1)|};

    Task Start() {|RH3202:=> Task.CompletedTask|};

    int Fail() {|RH3202:=> throw new InvalidOperationException()|};

    int  Get( int a ) {|RH3202:=> a+1|};
}
```

```csharp
using System;
using System.Threading.Tasks;

class C
{
    void Run()
    {
        Console.WriteLine();
    }

    async Task RunAsync()
    {
        await Task.Delay(1);
    }

    Task Start()
    {
        return Task.CompletedTask;
    }

    int Fail()
    {
        throw new InvalidOperationException();
    }

    int Get(int a)
    {
        return a + 1;
    }
}
```

### RH3202-005 — The fix keeps the separators around the method

The code fix MUST keep the blank lines above and below the converted method.

Why: The fix changes one member's body; the spacing between members is the author's and is not part of the diagnostic.

Example:

```csharp
class C
{
    private int _value;

    public int GetValue() {|RH3202:=> _value|};
}
```

```csharp
class C
{
    private int _value;

    public int GetValue()
    {
        return _value;
    }
}
```

### RH3202-006 — Fix All converts every method in one pass

Status: Retired — `shared/code-fixes.md` specifies Fix All for every rule whose header says `Fix All`.

The code fix MUST provide a batch Fix All that converts every reported method of a document in a single iteration.

Why: Each fix only touches its own method, so the fixes do not overlap and need no second pass.

Example:

```csharp
class C
{
    public int First() {|RH3202:=> 1|};

    public int Second() {|RH3202:=> 2|};
}
```

```csharp
class C
{
    public int First()
    {
        return 1;
    }

    public int Second()
    {
        return 2;
    }
}
```
