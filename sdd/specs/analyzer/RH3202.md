# Analyzer — RH3202 Expression style methods should not be used

| | |
|---|---|
| ID prefix | RH3202 |
| Status | Active |
| Category | Clarity |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH3202ExpressionStyleMethodsShouldNotBeUsedAnalyzer`, `RH3202ExpressionStyleMethodsShouldNotBeUsedCodeFixProvider` |
| Uses | FMT-STRUCT-004, FMT-STRUCT-006, FMT-STRUCT-007, FMT-PIPE-010, SHARED-BODY-001, SHARED-BODY-002, SHARED-BODY-003 |

RH3202 reports an expression-bodied method and offers a code fix that converts it to a block body by formatting the method with the formatter. The rule and the formatter's FMT-STRUCT-004 are two views of one style decision. Which methods are left alone, where the diagnostic is, and what the fix produces are SHARED-BODY-001, SHARED-BODY-002, and SHARED-BODY-003.

## Non-goals

- Expression-bodied local functions (RH3208), constructors (RH3203), operators (RH3205), conversion operators (RH3206), and finalizers (RH3207).
- Expression-bodied properties, indexers, accessors, and lambdas, which stay expression-bodied (FMT-STRUCT-008).
- Which statement the converted body contains and how its trivia is carried over — FMT-STRUCT-004 and FMT-STRUCT-006 own that; this spec only references them.

## Requirements

### RH3202-001 — Every expression-bodied method is reported

The analyzer MUST report every method declaration that has an expression body — in a class, struct, record, or interface, static or instance, `async` or not — unless SHARED-BODY-001 applies. Local functions, operators, conversion operators, properties, and indexers MUST NOT be reported.

Why: The house style keeps expression bodies for properties, indexers, and accessors and uses block bodies for methods. The other function kinds have rules of their own, so each kind can be configured separately.

Example:

```csharp
using System;

class C
{
    void Run() {|RH3202:=> Console.WriteLine()|};

    void Outer()
    {
        int Local() => 1;
    }

    public static C operator +(C a, C b) => a;

    int P => 1;
}

interface I
{
    int M() {|RH3202:=> 1|};
}
```

### RH3202-002 — The fix keeps the separators around the method

The code fix MUST keep the blank lines above and below the converted method.

Why: The fix changes one member's body; the spacing between members is the author's and is not part of the diagnostic.

Example:

```csharp
class C
{
    private int _value;

    public int GetValue() {|RH3202:=> _value|};
}
```

```csharp
class C
{
    private int _value;

    public int GetValue()
    {
        return _value;
    }
}
```
