# Analyzer — RH8304 XML documentation elements must be on separate lines

| | |
|---|---|
| ID prefix | RH8304 |
| Status | Active |
| Category | Documentation |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH8304XmlDocumentationElementsMustBeOnSeparateLinesAnalyzer`, `RH8304XmlDocumentationElementsMustBeOnSeparateLinesCodeFixProvider` |
| Uses | SHARED-DOC-004, SHARED-DOC-008 |

RH8304 reports a top-level XML element of a `///` documentation comment that starts on the line where the element before it ends, and offers a code fix that moves it onto a `///` line of its own.

## Non-goals

- Text after the end tag of an element on the same line — RH8308.
- How the lines inside one element are laid out — RH8305 and RH8307.
- The order of the elements — RH8309.

## Requirements

### RH8304-001 — An element on the line of the previous element is reported

The analyzer MUST report an XML element at the top level of a `///` documentation comment — with an end tag or empty, such as `<inheritdoc/>` — that starts on the line on which the previous top-level element ends, when nothing but white space stands between the two; a character reference that stands for white space, such as `&#32;`, counts as white space. Each element is judged against the one directly before it, so the second and the third of three elements on one line are both reported. Nothing is reported when SHARED-DOC-008 applies.

This requirement covers the `///` documentation comments of a declaration as SHARED-DOC-004 defines them. A `///` comment that is not a documentation comment of a declaration, such as one inside a method body, is not covered.

Why: Each element of the documentation is one part of it — the summary, a parameter, the remarks. On a line of its own, each part is easy to find, and adding or changing one touches only its own lines.

Example:

```csharp
class C
{
    /// <summary>Runs</summary>{|RH8304:<remarks>Remarks</remarks>|}
    void M()
    {
    }

    /// <summary>Stops</summary> {|RH8304:<remarks>Remarks</remarks>|} {|RH8304:<example>Example</example>|}
    void N()
    {
    }

    /// <summary>
    /// Value
    /// </summary>{|RH8304:<inheritdoc/>|}
    int A;

    /// <summary>Count</summary>&#32;{|RH8304:<remarks>Remarks</remarks>|}
    int B;
}
```

### RH8304-002 — Elements separated by content or nested in another element are not reported

The analyzer MUST NOT report an element when anything other than white space stands between it and the previous top-level element — text, a character reference that does not stand for white space, such as `&amp;`, an XML comment, or a CDATA section — nor an element nested inside another element. A `/** */` documentation comment MUST NOT be reported.

Why: Text between two elements belongs to the documentation's prose, and inline elements such as `<see/>` and `<c>` are part of the text of the element that contains them. A delimited comment has no `///` lines to put the elements on.

Example:

```csharp
class C
{
    /// <summary>Runs</summary> and <remarks>Remarks</remarks>
    void M()
    {
    }

    /// <summary>Stops <see cref="C"/> <c>now</c></summary>
    void N()
    {
    }

    /// <summary>Value</summary><!-- Note --><remarks>Remarks</remarks>
    int A;

    /** <summary>Count</summary><remarks>Remarks</remarks> */
    int B;
}
```

is not reported.

### RH8304-003 — The diagnostic covers the element

The analyzer MUST report one diagnostic per reported element, covering the whole element: from its start tag through its end tag, or the empty element.

Why: The element is what the fix moves.

Example: see RH8304-001.

### RH8304-004 — The fix moves the element onto a new `///` line

The code fix MUST remove the horizontal white space in front of the reported element and insert, at that place, the line break of the line the element starts on, the indentation of that line, and `/// `, so the element and everything after it on the line start a new documentation line.

This requirement covers a comment whose lines have nothing but white space in front of their `///`.

Why: The new line continues the same documentation comment at the same indentation, and the element keeps its content and its own layout.

Example:

```csharp
class C
{
    /// <summary>Stops</summary> {|RH8304:<remarks>Remarks</remarks>|} {|RH8304:<example>Example</example>|}
    void N()
    {
    }
}
```

```csharp
class C
{
    /// <summary>Stops</summary>
    /// <remarks>Remarks</remarks>
    /// <example>Example</example>
    void N()
    {
    }
}
```
