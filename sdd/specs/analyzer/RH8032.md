# Analyzer — RH8032 Extension declaration parameters must be documented

| | |
|---|---|
| ID prefix | RH8032 |
| Status | Active |
| Category | Documentation |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH8032ExtensionDeclarationParametersMustBeDocumentedAnalyzer` |
| Uses | SHARED-DIAG-007, SHARED-DOC-008, SHARED-DOC-011, SHARED-DOC-012, SHARED-DOC-013 |

RH8032 reports the parameter of a documented extension declaration that has no matching `<param>` documentation.

## Non-goals

- Whether the extension declaration has a summary — RH8031; its type parameters — RH8033.
- The parameters of methods, constructors, delegates, indexers, operators, and primary constructors, including the members of an extension block — RH8101.
- Whether the `<param>` description has text — RH8104.

## Requirements

### RH8032-001 — An undocumented parameter of an extension declaration is reported

The analyzer MUST report the parameter of an extension declaration — `extension(…)` or `extension<…>(…)` — that is not documented as SHARED-DOC-012 specifies, unless SHARED-DOC-011 exempts the declaration. Extension declarations that SHARED-DOC-013 merges are decided on the documentation they share. Nothing is reported when SHARED-DOC-008 applies.

A parameter without a name, such as the one of `extension(int)`, MUST NOT be reported.

This requirement covers what SHARED-DOC-011 and SHARED-DOC-012 cover, and a parameter without a name.

Why: The parameter of an extension declaration is the value that every member of the block extends, so it is the first thing a caller needs to understand. Its name and type alone do not say which values are meant, and the block offers no other place to look. A parameter without a name cannot be named by a `<param>` element, so there is nothing the rule could ask for, and it has no name for the diagnostic to stand on (SHARED-DIAG-007).

Example:

```csharp
/// <summary>
/// Extensions
/// </summary>
public static class Extensions
{
    /// <summary>
    /// Adds helpers to text values
    /// </summary>
    extension(string {|RH8032:value|})
    {
    }

    /// <summary>
    /// Adds helpers to integer values
    /// </summary>
    /// <param name="value">Value</param>
    extension(int value)
    {
    }

    /// <summary>
    /// Adds static helpers to long values
    /// </summary>
    extension(long)
    {
    }
}
```

### RH8032-002 — The diagnostic is on the parameter name

The analyzer MUST report one diagnostic per undocumented parameter, located on its identifier.

Why: The name is what the `<param>` element has to repeat, so marking it shows what is missing.

Example: see RH8032-001.
