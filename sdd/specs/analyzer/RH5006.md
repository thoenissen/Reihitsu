# Analyzer — RH5006 foreach-Statement should be preceded by a blank line

| | |
|---|---|
| ID prefix | RH5006 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5006ForeachStatementsShouldBePrecededByABlankLineAnalyzer`, `RH5006ForeachStatementsShouldBePrecededByABlankLineCodeFixProvider` |
| Uses | SHARED-STMT-001, SHARED-STMT-002, SHARED-STMT-003, SHARED-STMT-004 |

RH5006 reports a `foreach` statement that follows another statement of the same block or switch section without a blank line between them, and offers a code fix that inserts one as SHARED-STMT-004 specifies.

## Non-goals

- Blank lines before other statement kinds — the other rules that use `shared/statement-blank-lines.md`.

## Requirements

### RH5006-001 — A `foreach` statement that follows a statement needs a blank line

The analyzer MUST report a `foreach` statement as SHARED-STMT-001, SHARED-STMT-002, and SHARED-STMT-003 specify. A `foreach` statement that deconstructs its element (`foreach (var (x, y) in …)`) is reported the same way.

Why: A `foreach` statement starts an iteration; the blank line separates the loop from the code that prepares it.

Example:

```csharp
class C
{
    void M(int[] items, (int, int)[] pairs)
    {
        var sum = 0;
        {|RH5006:foreach|} (var item in items)
        {
            sum += item;
        }

        sum++;
        {|RH5006:foreach|} (var (left, right) in pairs)
        {
            sum += left + right;
        }
    }
}
```

Both `foreach` statements, the plain one and the deconstructing one, are reported.

### RH5006-002 — The diagnostic is on the `foreach` keyword that starts the statement

When the `foreach` statement starts with the `foreach` keyword, the analyzer MUST report the diagnostic on that keyword.

Why: The statement's first keyword is where the missing separator becomes visible, and the location stays stable when the iteration variable changes.

Example: see RH5006-001.
