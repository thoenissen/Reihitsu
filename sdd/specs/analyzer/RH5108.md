# Analyzer — RH5108 Parameter list must follow declaration

| | |
|---|---|
| ID prefix | RH5108 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5108ParameterListMustFollowDeclarationAnalyzer`, `RH5108ParameterListMustFollowDeclarationCodeFixProvider` |
| Uses | FMT-BREAK-001, FMT-BREAK-012, SHARED-WS-003 |

RH5108 reports the first parameter of a declaration's parameter list when it starts on a line below the opening parenthesis, and offers a code fix that moves it behind the parenthesis.

## Non-goals

- The opening parenthesis, the commas, and the closing parenthesis of a parameter list — RH5105, RH5107, and RH5106.
- Whether the remaining parameters share a line — RH5109.
- The first argument of an argument list — RH5101.

## Requirements

### RH5108-001 — A first parameter below the opening parenthesis is reported

The analyzer MUST report the first parameter of the parameter list of a method, a constructor, a local function, an operator, a conversion operator, a delegate, a record, and a record struct when the parameter starts on a later line than the opening parenthesis. The parameter lists of other declarations and expressions — the primary constructor of a class or a struct, an anonymous method, a lambda, an indexer — MUST NOT be reported.

Why: Starting the parameters on the next line separates the declaration from its parameters, and the remaining parameters can no longer align under the first one (FMT-BREAK-012).

Example:

```csharp
using System;

class C
{
    void M(
        {|RH5108:int|} a)
    {
        void L(
            {|RH5108:int|} b)
        {
        }

        Func<int, int> f = (
            int x) => x;
    }

    public static C operator +(
        {|RH5108:C|} c) => c;
}

class P(
    int a)
{
}

delegate void D(
    {|RH5108:int|} a);

record struct S(
    {|RH5108:int|} A);
```

### RH5108-002 — A comment or directive in front of the first parameter suppresses the diagnostic

The analyzer MUST NOT report the first parameter when a comment, a preprocessor directive, or disabled text sits between the opening parenthesis and the parameter.

Why: The parameter cannot join the opening line without moving the comment or the directive, which the formatter refuses as well (FMT-BREAK-001). A diagnostic that no layout can clear would stay for good.

Example:

```csharp
class C
{
    void M( // first
        int a)
    {
    }
}
```

is not reported.

### RH5108-003 — The diagnostic is on the first token of the first parameter

The analyzer MUST report one diagnostic per parameter list, located on the first token of its first parameter, which is the opening bracket of an attribute list when the parameter has one.

Why: The first token is what has to move; reporting it rather than the whole parameter keeps the diagnostic short.

Example:

```csharp
using System.Diagnostics.CodeAnalysis;

class C
{
    void M(
        {|RH5108:[|}NotNull] object a)
    {
    }
}
```

### RH5108-004 — The fix joins the first parameter to the opening parenthesis

The code fix MUST move the first parameter directly behind the opening parenthesis, as SHARED-WS-003 specifies.

Why: Deleting the line break and the indentation in front of the parameter is the whole correction.

Example:

```csharp
class C
{
    void M(
        {|RH5108:int|} a)
    {
    }
}
```

```csharp
class C
{
    void M(int a)
    {
    }
}
```
