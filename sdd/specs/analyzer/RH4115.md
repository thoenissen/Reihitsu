# Analyzer — RH4115 Local variable casing

| | |
|---|---|
| ID prefix | RH4115 |
| Status | Active |
| Category | Naming |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH4115LocalVariableCasingAnalyzer`, `RH4115LocalVariableCasingCodeFixProvider` |
| Uses | RH4117-001, RH4117-003, SHARED-CASING-002, SHARED-CASING-003, SHARED-CASING-006, SHARED-CASING-007, SHARED-CASING-008, SHARED-CASING-009, SHARED-CASING-010, SHARED-CASING-013, SHARED-CASING-015 |

RH4115 reports a local variable whose name is not in camelCase — apart from local constants and the variables a deconstruction declares — and offers a code fix that renames the variable and every reference to it.

## Non-goals

- Parameters, including those of lambdas and local functions, and the range variables of query expressions — RH4105.
- Local constants — RH4128.
- Variables that a deconstruction declares, in a declaration, a `foreach` statement, or a pattern — RH4117.
- Names of local functions — RH4104.
- Local variable names of a single letter — RH4125 to RH4127.

## Requirements

### RH4115-001 — Local variable names are in camelCase

The analyzer MUST report every local variable whose name is not in camelCase as SHARED-CASING-002 defines it, among the variables declared by:

- a local declaration statement that is not `const`, including a `using` declaration;
- the declaration in the initializer of a `for` statement;
- the declaration of a `using` statement or of a `fixed` statement;
- a `foreach` statement that declares a single iteration variable;
- a `catch` declaration that names its exception variable;
- the variable designation of an `out` argument, or of a declaration pattern, a `var` pattern that declares a single variable, a property or positional pattern, or a list pattern.

The analyzer MUST report one diagnostic per variable, located on its identifier. A variable that a deconstruction declares is excluded by RH4115-002, and a variable named `_` by RH4115-004.

Why: camelCase is the .NET style for locals; it tells a reader at every use that the name is a value of the current block, not a member of the type.

Example:

```csharp
using System;
using System.IO;

class C
{
    unsafe void M(object input, int[] values, (int, int) pair)
    {
        int {|RH4115:Count|} = 1, total = 2;
        using var {|RH4115:Stream|} = new MemoryStream();

        for (int {|RH4115:Index|} = 0; Index < 1; Index++)
        {
        }

        foreach (var {|RH4115:Item|} in values)
        {
        }

        using (var {|RH4115:Reader|} = new StringReader(""))
        {
        }

        fixed (int* {|RH4115:Pointer|} = values)
        {
        }

        int.TryParse("1", out var {|RH4115:Parsed|});

        if (input is int {|RH4115:Number|})
        {
        }

        if (input is string { Length: var {|RH4115:Size|} })
        {
        }

        if (input is string { Length: > 0 } {|RH4115:Text|})
        {
        }

        if (pair is (1, 2) {|RH4115:Both|})
        {
        }

        if (values is [_, _] {|RH4115:Items|})
        {
        }

        try
        {
        }
        catch (Exception {|RH4115:Error|})
        {
        }
        catch
        {
        }
    }
}
```

### RH4115-002 — Variables of a deconstruction are not checked

The analyzer MUST NOT report a variable that RH4117-001 or RH4117-003 names. Every other variable that a pattern declares is reported as RH4115-001 states.

Why: RH4117 checks every variable that a deconstruction declares, however the deconstruction is spelled, so that deconstruction can be configured apart from ordinary locals and no deconstruction variable is checked by two rules. RH4117 states which variables these are, so the boundary is stated once.

Example:

```csharp
using System.Collections.Generic;

class C
{
    void M((int, int) pair, (object, object) objects, List<(int, int)> pairs)
    {
        var (First, Second) = pair;
        (var Third, var Fourth) = pair;
        (int Fifth, var (Sixth, Seventh)) = (1, pair);

        foreach (var (Key, Value) in pairs)
        {
        }

        foreach ((var Name, var Count) in pairs)
        {
        }

        if (pair is var (Left, Right))
        {
        }

        if (objects is (var Item, int Number))
        {
        }

        if (objects is (int Positive and > 0, _))
        {
        }

        if (objects is (string { Length: > 0 } Text, { } Any))
        {
        }
    }
}
```

is not reported.

Example — pattern variables outside a deconstruction:

```csharp
class C
{
    void M(object input, (int, int) pair, (string, int) named)

        {
        }

        }
```

### RH4115-003 — The fix renames the variable to camelCase

The code fix MUST rename the variable and every reference to it (SHARED-CASING-007) to the camelCase name that SHARED-CASING-006 derives from its old name. It is withheld as SHARED-CASING-008, SHARED-CASING-009, and SHARED-CASING-013 specify, and its Fix All skips colliding names as SHARED-CASING-010 specifies. It keeps the name of an anonymous object member that a renamed reference names, as SHARED-CASING-015 specifies. This requirement covers the renames that SHARED-CASING-007 covers.

Why: The fix makes exactly the change the diagnostic asks for, and a local is referenced throughout its block.

Example:

```csharp
class C
{
    int M(int[] values)
    {
        var {|RH4115:Total|} = 0;

        foreach (var {|RH4115:Current_Value|} in values)
        {
            Total += Current_Value;
        }

        return Total;
    }
}
```

```csharp
class C
{
    int M(int[] values)
    {
        var total = 0;

        foreach (var currentValue in values)
        {
            total += currentValue;
        }

        return total;
    }
}
```

### RH4115-004 — A local named `_` is not reported

The analyzer MUST NOT report a local variable named `_`, whichever declaration RH4115-001 names declares it. A name that only starts or ends with `_`, such as `_count`, is reported as RH4115-001 states.

Why: `_` is the conventional name of a value that is not used, and every neighbouring casing rule accepts it: a parameter named `_` (RH4105) and a field named `_` (SHARED-CASING-003). Its fix could derive no name from it (SHARED-CASING-008), so the report could only be resolved by renaming a deliberately unused variable by hand.

Example:

```csharp
using System;

class C
{
    void M()
    {
        int _ = 42;
        int {|RH4115:_count|} = 0;
    }

    void N(int[] values)
    {
        foreach (var _ in values)
        {
        }

        try
        {
        }
        catch (Exception _)
        {
        }
    }

    void O()
    {
        using var _ = (IDisposable)null;
    }
}
```

### RH4115-005 — Local constants are not checked

The analyzer MUST NOT report a local constant, that is, a variable of a local declaration statement with the `const` modifier, whatever its name. A local declaration statement without `const` is reported as RH4115-001 states.

Why: RH4128 checks local constants, so that they can be configured apart from variables and each local name is checked by exactly one rule.

Example:

```csharp
class C
{
    int M()
    {
        const int MaxValue = 3, Max_Count = 4;
        int {|RH4115:Total|} = MaxValue + Max_Count;

        return Total;
    }
}
```
