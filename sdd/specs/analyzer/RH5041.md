# Analyzer — RH5041 Comments must not be placed inside a declarator list

| | |
|---|---|
| ID prefix | RH5041 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH5041CommentsMustNotBePlacedInsideDeclaratorListAnalyzer` |
| Uses | SHARED-COMMENT-001, SHARED-COMMENT-002, SHARED-COMMENT-003 |

RH5041 reports a comment placed next to the comma between two declarators of a variable declaration, or directly before the semicolon that ends a field, event, or local declaration.

## Non-goals

- Whether several variables may be declared in one declaration — RH7101.
- A comment around the `=` of a declarator's initializer — RH5042.

## Requirements

### RH5041-001 — A comment next to a declarator separator is reported

The analyzer MUST report every ordinary comment (SHARED-COMMENT-001, SHARED-COMMENT-002) directly before or directly after a comma that separates two declarators of a variable declaration — of a field, an event field, a local, a `using` declaration, the initializer of a `for` statement, or a `fixed` statement — as SHARED-COMMENT-003 specifies. A comment between the type and the first declarator, and a comment next to any other comma, such as one between enum members, MUST NOT be reported.

Why: A declaration with several declarators reads as one unit. A comment inside it describes only part of the declaration and splits it across lines.

Example:

```csharp
class C
{
    private int _first,
        {|RH5041:// second|}
        _second;

    private int _third {|RH5041:/* third */|}, _fourth;

    private int
        // value
        _value;

    void M()
    {
        for (int i = 0, {|RH5041:/* second */|} j = 0; i < j; i++)
        {
        }
    }
}

enum E
{
    First,
    // second
    Second
}
```

The comments `// value` and `// second` in the enum are not reported.

### RH5041-002 — A comment before the end of a declaration is reported

The analyzer MUST report a comment directly before the semicolon that ends a field, an event field, or a local declaration, whatever the number of its declarators. A comment directly before the semicolon of any other statement, and a comment after the semicolon, MUST NOT be reported.

Why: The semicolon closes the declaration as a whole; a comment in front of it is the last part of the declarator list and splits the declaration from its end.

Example:

```csharp
using System;

class C
{
    private int _value
        {|RH5041:// terminator|}
        ;

    public event Action Changed {|RH5041:/* terminator */|};

    int M()
    {
        const int limit = 1 {|RH5041:/* terminator */|};
        int other = 2; // after the declaration

        return limit + other
            // terminator
            ;
    }
}
```

The comments `// after the declaration` and the one before the semicolon of the `return` statement are not reported.
