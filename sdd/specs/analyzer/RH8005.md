# Analyzer — RH8005 Non-private interfaces must be documented

| | |
|---|---|
| ID prefix | RH8005 |
| Status | Active |
| Category | Documentation |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH8005NonPrivateInterfacesMustBeDocumentedAnalyzer` |
| Uses | SHARED-DOC-001, SHARED-DOC-002, SHARED-DOC-004, SHARED-DOC-005, SHARED-DOC-006, SHARED-DOC-007, SHARED-DOC-008 |

RH8005 reports an interface in the non-private group that has no `<summary>` or `<inheritdoc>` documentation.

## Non-goals

- Interfaces in the private group — RH8006.
- Whether the summary has text — RH8030; the documentation of type parameters — RH8108.

## Requirements

### RH8005-001 — Undocumented non-private interfaces are reported

The analyzer MUST report every interface declaration in the non-private group of SHARED-DOC-002 that is not documented, checked as SHARED-DOC-001 specifies. Generic interfaces and interfaces nested in other types are interface declarations too. Whether it is documented MUST be decided as SHARED-DOC-004, SHARED-DOC-005, SHARED-DOC-006, and SHARED-DOC-007 specify, and nothing is reported when SHARED-DOC-008 applies.

Why: An interface that other code can use is part of the contract that code builds on. Without a summary, the generated documentation and the editor's tooltip show nothing, and readers have to infer what the interface is for from its implementation.

Example:

```csharp
public interface {|RH8005:IService|}
{
}

/// <remarks>
/// No summary
/// </remarks>
internal interface {|RH8005:IHelper|}
{
}

interface {|RH8005:IRepository|}<T>
{
}

/// <summary>
/// Documented
/// </summary>
public interface IDocumented
{
    interface {|RH8005:INested|}
    {
    }
}

/// <summary>
/// Outer
/// </summary>
public class Outer
{
    private interface IHidden
    {
    }
}
```

### RH8005-002 — The diagnostic is on the interface name

The analyzer MUST report one diagnostic per undocumented interface declaration, located on its identifier, without its type parameter list.

Why: The name is what the documentation describes; marking it identifies the declaration without marking its whole body.

Example: see RH8005-001.
