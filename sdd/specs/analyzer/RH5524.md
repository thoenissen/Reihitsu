# Analyzer — RH5524 Parameter attributes must use merged attribute lists

| | |
|---|---|
| ID prefix | RH5524 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5524ParameterAttributeListsMustFollowShapeRulesAnalyzer`, `RH5524ParameterAttributeListsMustFollowShapeRulesCodeFixProvider` |
| Uses | SHARED-ATTR-002, SHARED-ATTR-003, SHARED-ATTR-015, SHARED-ATTR-016, SHARED-ATTR-018, SHARED-ATTR-020 |

RH5524 reports an attribute list of a parameter that follows another list of the same parameter naming the same target, and offers a code fix that merges those lists into the first. The rule uses `shared/attribute-targets.md`.

## Non-goals

- Attribute lists of type parameters — RH5529.
- Where a parameter attribute list is placed — RH5523.

## Requirements

### RH5524-001 — The lists of one parameter and one target are merged

The analyzer MUST check every attribute list attached to a parameter (SHARED-ATTR-003): the lists of a parameter of a method, constructor, primary constructor, positional record, local function, lambda, delegate, operator, or indexer, without a specifier, with `param:`, or with a specifier of SHARED-ATTR-002. It MUST report such a list that follows another list of the same parameter naming the same target, as SHARED-ATTR-015 specifies.

Why: Parameter attributes stay on the parameter's line, so separate lists buy no line per attribute the way they do on a declaration; they only repeat the brackets, and in a list of several parameters the brackets outnumber the parameters.

Example:

```csharp
class C
{
    void M([A] {|RH5524:[B]|} int a, [A, B] int b, [A] {|RH5524:[param: D]|} int c)
    {
    }

    System.Action<int> _a = ([A] {|RH5524:[B]|} int x) => { };
}

record R([property: A] {|RH5524:[property: B]|} int Id, [property: A] [B] int Name);
```

### RH5524-002 — The diagnostic is on the attribute list

The analyzer MUST report the diagnostic on the attribute list, as SHARED-ATTR-016 specifies.

Why: Each list after the first of a target is one that the fix removes; the first list is the one the others merge into.

Example: see RH5524-001.

### RH5524-003 — The fix merges the lists of the target into the first

The code fix MUST merge every list of the reported list's target on the parameter into the first of them, as SHARED-ATTR-018 specifies.

Why: The fix makes only the change the diagnostic asks for, for all lists of the target at once, so one application leaves no list of that target behind.

Example:

```csharp
class C
{
    void M([A] {|RH5524:[B]|} {|RH5524:[D]|} int a)
    {
    }
}
```

```csharp
class C
{
    void M([A, B, D] int a)
    {
    }
}
```

### RH5524-004 — The fix is withheld for comments and directives around the lists

The code fix MUST NOT be offered when SHARED-ATTR-020 withholds it. The diagnostic is still reported.

Why: The merge rewrites the stretch from the first to the last list, where a comment would be dropped or moved and a directive would end up off its own line.

Example:

```csharp
class C
{
    void M([A /* c */] {|RH5524:[B]|} int a)
    {
    }
}
```

is reported, and no code fix is offered.
