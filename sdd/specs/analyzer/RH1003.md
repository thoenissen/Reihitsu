# Analyzer — RH1003 Use string interpolation instead of string concatenation

| | |
|---|---|
| ID prefix | RH1003 |
| Status | Active |
| Category | Performance |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH1003UseStringInterpolationInsteadOfStringConcatenationAnalyzer` |
| Uses | — |

RH1003 reports a string concatenation chain of three or more parts that is not a compile-time constant.

## Non-goals

- Compound assignments (`s += a + b`), `string.Concat`, `string.Join`, `StringBuilder`, and `string.Format` calls.
- Interpolated strings that could be simplified — RH3204.
- A code fix. Rewriting a chain as an interpolated string has to decide on escaping of `{` and `}`, on format specifiers, and on how comments inside the chain survive; the rule leaves the rewrite to the author.

## Requirements

### RH1003-001 — A non-constant chain of three or more parts is reported

The analyzer MUST report an addition expression whose type is `string` when the chain it heads has at least three parts and at least one part is not a compile-time constant. The parts of a chain are the operands left after flattening nested additions and the parentheses around them.

Why: A long chain of `+` is harder to read than one interpolated string, and with runtime values it can allocate intermediate strings. Two-part concatenations are short enough to read and are left alone.

Example:

```csharp
class C
{
    void M(string name, int id, object o)
    {
        var a = {|RH1003:"User: " + name + ", Id: " + id|};
        var b = "User: " + name;
        var g = {|RH1003:name + o + name|};
        var j = {|RH1003:"a" + name + 'c'|};
    }
}
```

### RH1003-002 — A constant chain is not reported

The analyzer MUST NOT report a chain whose value is a compile-time constant, or whose parts are all compile-time constants, including `const` fields and locals.

Why: The compiler folds a constant chain into one literal, so it costs nothing at run time, and splitting a long constant across `+` is a common way to keep lines short.

Example:

```csharp
class C
{
    const string Prefix = "a";

    void M()
    {
        const string suffix = "Name";
        var c = Prefix + "b" + "c" + suffix;
    }
}
```

is not reported.

### RH1003-003 — Only the outermost chain is reported

The analyzer MUST report a chain once, on its outermost string addition, and MUST NOT report an addition nested in it, with or without parentheses.

Why: The nested additions are parts of the same chain; reporting each of them would put several diagnostics on one expression that one rewrite corrects.

Example:

```csharp
class C
{
    void M(string prefix, string name, string suffix)
    {
        var a = {|RH1003:(prefix + name) + suffix|};
        var h = {|RH1003:(name + "x") + (name + "y")|};
        var d = {|RH1003:"a" + (name + "b")|};
    }
}
```

### RH1003-004 — The diagnostic covers the whole chain

The analyzer MUST report the diagnostic on the span of the outermost addition expression.

Why: The whole chain is what an interpolated string replaces.

Example: see RH1003-001.
