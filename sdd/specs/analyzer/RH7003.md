# Analyzer — RH7003 File-scoped namespaces should be used

| | |
|---|---|
| ID prefix | RH7003 |
| Status | Active |
| Category | Organization |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH7003FileScopedNamespacesShouldBeUsedAnalyzer` |
| Uses | — |

RH7003 reports a block-scoped namespace declaration that could be written as a file-scoped namespace, because it is the only member of its file. It has no code fix.

## Non-goals

- Whether a file with several namespaces or with types outside the namespace should be split — RH7001 and RH7002.
- The indentation of the namespace's contents.

## Requirements

### RH7003-001 — A block-scoped namespace that is the file's only member is reported

The analyzer MUST report a block-scoped namespace declaration that is declared directly in the compilation unit and is the compilation unit's only member, when the file is compiled with C# 10 or later. Using directives, `extern alias` directives, and assembly or module attributes outside the namespace are not members. What the namespace contains — types, nested namespaces, using directives, comments — does not matter.

Why: A file-scoped namespace covers the whole file, so it can replace a block-scoped namespace exactly when nothing else is declared beside it. Writing it file-scoped removes one level of indentation from the whole file without changing what the file declares.

Example:

```csharp
using System;

[assembly: CLSCompliant(true)]

namespace {|RH7003:A.B|}
{
    namespace Inner
    {
        class C
        {
        }
    }
}
```

### RH7003-002 — A namespace with another member beside it is not reported

The analyzer MUST NOT report a block-scoped namespace declaration when the compilation unit has another member: a second namespace, a type declared outside the namespace, or a top-level statement. A namespace nested in another namespace MUST NOT be reported either.

Why: A file-scoped namespace would also cover the other member, so converting the namespace would change the namespace of that member or would not compile.

Example:

```csharp
namespace A
{
}

class C
{
}
```

is not reported, and neither is a file with two top-level namespaces.

### RH7003-003 — Language versions without file-scoped namespaces are not reported

The analyzer MUST NOT report a namespace declaration in a file compiled with a language version below C# 10.

Why: File-scoped namespaces exist from C# 10 on; below it the diagnostic would ask for code that does not compile.

For example, the namespace of RH7003-001 is not reported when the project sets `LangVersion` to `9`.

### RH7003-004 — The diagnostic is on the namespace name

The analyzer MUST report one diagnostic per reported namespace declaration, located on its whole name.

Why: The name is the part of the declaration that stays when the namespace becomes file-scoped.

Example: see RH7003-001.
