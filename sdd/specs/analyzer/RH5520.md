# Analyzer — RH5520 Event attribute lists must use one attribute per list

| | |
|---|---|
| ID prefix | RH5520 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5520EventAttributeListsMustFollowShapeRulesAnalyzer`, `RH5520EventAttributeListsMustFollowShapeRulesCodeFixProvider` |
| Uses | SHARED-ATTR-001, SHARED-ATTR-002, SHARED-ATTR-013, SHARED-ATTR-014, SHARED-ATTR-016, SHARED-ATTR-017, SHARED-ATTR-019 |

RH5520 reports an attribute list of an event that holds more than one attribute, and offers a code fix that gives each attribute a list of its own. The rule uses `shared/attribute-targets.md`.

## Non-goals

- Attributes of an event's `add` and `remove` accessors — RH5531.
- Where an event attribute list is placed — RH5519.

## Requirements

### RH5520-001 — Event attribute lists hold one attribute

The analyzer MUST check every attribute list that resolves to the event target (SHARED-ATTR-001, SHARED-ATTR-002): the lists of an event field or an event with accessors without a specifier or with `type:`, and every list with the `event:` specifier that is not attached to a parameter or type parameter, and MUST report such a list that holds more than one attribute, as SHARED-ATTR-013 and SHARED-ATTR-014 specify.

Why: Attributes on an event are independent decisions; one per line lets a diff that adds or removes one attribute leave the others alone.

Example:

```csharp
class C
{
    {|RH5520:[A, B]|}
    event System.Action E;

    {|RH5520:[A, B]|}
    event System.Action F
    {
        add
        {
        }
        remove
        {
        }
    }

    {|RH5520:[event: A, B]|}
    event System.Action G;
}
```

### RH5520-002 — The diagnostic is on the attribute list

The analyzer MUST report the diagnostic on the attribute list, as SHARED-ATTR-016 specifies.

Why: The list is what has the wrong shape; each list of a declaration is reported and fixed on its own.

Example: see RH5520-001.

### RH5520-003 — The fix gives each attribute a list of its own

The code fix MUST replace the list with one list per attribute, each on its own line, as SHARED-ATTR-017 specifies.

Why: The fix makes only the change the diagnostic asks for: the attributes keep their order and their specifier, and each gets a line of its own.

Example:

```csharp
class C
{
    {|RH5520:[A, B]|}
    event System.Action E;
}
```

```csharp
class C
{
    [A]
    [B]
    event System.Action E;
}
```

### RH5520-004 — The fix is withheld for a comment or directive inside the list

The code fix MUST NOT be offered when SHARED-ATTR-019 withholds it. The diagnostic is still reported.

Why: A comment inside the list belongs to the attribute next to it, and only the author can tell which of the new lists it belongs to.

Example:

```csharp
class C
{
    {|RH5520:[A, /* c */ B]|}
    event System.Action E;
}
```

is reported, and no code fix is offered.
