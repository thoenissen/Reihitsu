# Analyzer — RH8011 Non-private enums must be documented

| | |
|---|---|
| ID prefix | RH8011 |
| Status | Active |
| Category | Documentation |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH8011NonPrivateEnumsMustBeDocumentedAnalyzer` |
| Uses | SHARED-DOC-001, SHARED-DOC-002, SHARED-DOC-004, SHARED-DOC-005, SHARED-DOC-006, SHARED-DOC-007, SHARED-DOC-008 |

RH8011 reports an enum in the non-private group that has no `<summary>` or `<inheritdoc>` documentation.

## Non-goals

- Enums in the private group — RH8012.
- The members of an enum — RH8013 and RH8014.
- Whether the summary has text — RH8030.

## Requirements

### RH8011-001 — Undocumented non-private enums are reported

The analyzer MUST report every enum declaration in the non-private group of SHARED-DOC-002 that is not documented, checked as SHARED-DOC-001 specifies. Enums with an underlying type and enums nested in other types are enum declarations too. Whether it is documented MUST be decided as SHARED-DOC-004, SHARED-DOC-005, SHARED-DOC-006, and SHARED-DOC-007 specify, and nothing is reported when SHARED-DOC-008 applies.

Why: A enum that other code can use is part of the contract that code builds on. Without a summary, the generated documentation and the editor's tooltip show nothing, and readers have to infer what the enum is for from its implementation.

Example:

```csharp
public enum {|RH8011:Color|}
{
}

/// <remarks>
/// No summary
/// </remarks>
internal enum {|RH8011:State|} : byte
{
}

enum {|RH8011:Mode|}
{
}

/// <summary>
/// Outer
/// </summary>
public class Outer
{
    protected enum {|RH8011:Kind|}
    {
    }

    private enum Hidden
    {
    }
}
```

### RH8011-002 — The diagnostic is on the enum name

The analyzer MUST report one diagnostic per undocumented enum declaration, located on its identifier, without its underlying type.

Why: The name is what the documentation describes; marking it identifies the declaration without marking its whole body.

Example: see RH8011-001.
