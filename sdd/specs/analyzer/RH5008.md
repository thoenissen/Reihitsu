# Analyzer — RH5008 return-Statement should be preceded by a blank line

| | |
|---|---|
| ID prefix | RH5008 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5008ReturnStatementsShouldBePrecededByABlankLineAnalyzer`, `RH5008ReturnStatementsShouldBePrecededByABlankLineCodeFixProvider` |
| Uses | SHARED-STMT-001, SHARED-STMT-002, SHARED-STMT-003, SHARED-STMT-004 |

RH5008 reports a `return` statement that follows another statement of the same block or switch section without a blank line between them, and offers a code fix that inserts one as SHARED-STMT-004 specifies.

## Non-goals

- Blank lines before other statement kinds — the other rules that use `shared/statement-blank-lines.md`.

## Requirements

### RH5008-001 — A `return` statement that follows a statement needs a blank line

The analyzer MUST report a `return` statement as SHARED-STMT-001, SHARED-STMT-002, and SHARED-STMT-003 specify. A `return` that ends a switch section is reported like any other.

Why: A `return` statement leaves the method; the blank line makes the exit point visible instead of letting it read as one more step.

Example:

```csharp
class C
{
    int M(int a)
    {
        a++;
        {|RH5008:return|} a;
    }

    int N(int a)
    {
        switch (a)
        {
            case 1:
                return a;
            default:
                a++;
                {|RH5008:return|} 0;
        }
    }
}
```

The `return` of `case 1` is the first statement of its section and is not reported; the `return` that ends the `default` section is.

### RH5008-002 — The diagnostic is on the `return` keyword

The analyzer MUST report the diagnostic on the `return` keyword.

Why: The keyword is where the missing separator becomes visible, and the location stays stable when the returned expression changes.

Example: see RH5008-001.
