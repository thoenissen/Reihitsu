# Analyzer — RH4105 Parameter casing

| | |
|---|---|
| ID prefix | RH4105 |
| Status | Active |
| Category | Naming |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH4105MethodParameterCasingAnalyzer`, `RH4105MethodParameterCasingCodeFixProvider` |
| Uses | SHARED-CASING-002, SHARED-CASING-006, SHARED-CASING-007, SHARED-CASING-008, SHARED-CASING-009, SHARED-CASING-010 |

RH4105 reports a parameter whose name is not in camelCase and offers a code fix that renames the parameter and every reference to it.

## Non-goals

- Parameters of a record's primary constructor — RH4120.
- Type parameters — RH4121.
- Parameter names of a single letter — RH4122 to RH4124.

## Requirements

### RH4105-001 — Parameter names are in camelCase

The analyzer MUST report every parameter whose name is not in camelCase as SHARED-CASING-002 defines it: parameters of methods, constructors, the primary constructors of classes and structs, indexers, operators, delegates, local functions, and lambdas. The analyzer MUST report one diagnostic per parameter, located on its identifier.

Why: camelCase is the .NET style for parameters; it tells a reader at every use that the name is an input of the current member, not a member of the type.

Example:

```csharp
using System;

public delegate void D(int {|RH4105:Value|});

public class C(int {|RH4105:PrimaryValue|})
{
    public C(int {|RH4105:Count|}, int itemCount)
        : this(Count + itemCount)
    {
    }

    public int this[int {|RH4105:Index|}] => Index;

    public static C operator +(C {|RH4105:Left|}, C right) => Left;

    public void M()
    {
        void Local(int {|RH4105:Total|})
        {
        }

        Func<int, int> f = {|RH4105:Number|} => Number;
        Action<int> g = (int {|RH4105:Amount|}) => { };
    }
}

public struct S(int {|RH4105:ParameterName|});
```

### RH4105-002 — Discards and record parameters are not checked

The analyzer MUST NOT report a parameter named `_`, and MUST NOT report a parameter of the primary constructor of a record, whether `record`, `record class`, or `record struct`.

Why: `_` is the conventional name of a parameter whose value is not used. A record's primary constructor parameter also declares a public property, which is named in PascalCase; RH4120 checks it.

Example:

```csharp
using System;

public record class R(int ParameterName);

public record struct S(int ParameterName);

public class C
{
    public void M(object _, EventArgs e)
    {
        Func<int, int, int> f = (_, _) => 0;
    }
}
```

is not reported.

### RH4105-003 — The fix renames the parameter to camelCase

The code fix MUST rename the parameter and every reference to it (SHARED-CASING-007) to the camelCase name that SHARED-CASING-006 derives from its old name. It is withheld as SHARED-CASING-008 and SHARED-CASING-009 specify, and its Fix All skips colliding names as SHARED-CASING-010 specifies.

Why: The fix makes exactly the change the diagnostic asks for, and a parameter is referenced throughout its member's body.

Example:

```csharp
using System;

public class C
{
    public C(int {|RH4105:Count|})
    {
        Func<int, int> f = {|RH4105:Value|} => Value + Count;
    }
}
```

```csharp
using System;

public class C
{
    public C(int count)
    {
        Func<int, int> f = value => value + count;
    }
}
```
