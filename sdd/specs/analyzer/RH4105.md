# Analyzer — RH4105 Parameter and query range variable casing

| | |
|---|---|
| ID prefix | RH4105 |
| Status | Active |
| Category | Naming |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH4105MethodParameterCasingAnalyzer`, `RH4105MethodParameterCasingCodeFixProvider` |
| Uses | RH4124-003, SHARED-CASING-002, SHARED-CASING-006, SHARED-CASING-007, SHARED-CASING-008, SHARED-CASING-009, SHARED-CASING-010, SHARED-CASING-012, SHARED-CASING-013, SHARED-DIAG-007, SHARED-FIX-003 |

RH4105 reports a parameter or a range variable of a query expression whose name is not in camelCase, and offers a code fix that renames it and every reference to it.

## Non-goals

- Parameters of a record's primary constructor — RH4120.
- Type parameters — RH4121.
- Parameter and range variable names of a single letter — RH4122 to RH4124.
- Local variables — RH4115.

## Requirements

### RH4105-001 — Parameter names are in camelCase

The analyzer MUST report every parameter whose name is not in camelCase as SHARED-CASING-002 defines it: parameters of methods, constructors, the primary constructors of classes and structs, indexers, operators, delegates, local functions, lambdas, anonymous methods, and the receiver parameter of an extension block. The analyzer MUST report one diagnostic per parameter, located on its identifier.

Why: camelCase is the .NET style for parameters; it tells a reader at every use that the name is an input of the current member, not a member of the type.

Example:

```csharp
using System;

public delegate void D(int {|RH4105:Value|});

public class C(int {|RH4105:PrimaryValue|})
{
    public C(int {|RH4105:Count|}, int itemCount)
        : this(Count + itemCount)
    {
    }

    public int this[int {|RH4105:Index|}] => Index;

    public static C operator +(C {|RH4105:Left|}, C right) => Left;

    public void M()
    {
        void Local(int {|RH4105:Total|})
        {
        }

        Func<int, int> f = {|RH4105:Number|} => Number;
        Action<int> g = (int {|RH4105:Amount|}) => { };
        Action<int> h = delegate (int {|RH4105:Size|}) { };
    }
}

public struct S(int {|RH4105:ParameterName|});

public static class E
{
    extension(int {|RH4105:Value|})
    {
    }
}
```

### RH4105-002 — Discards and record parameters are not checked

The analyzer MUST NOT report a parameter or a range variable named `_`, and MUST NOT report a parameter of the primary constructor of a record, whether `record`, `record class`, or `record struct`.

Why: `_` is the conventional name of a parameter whose value is not used, and a range variable plays the role of a lambda parameter (RH4105-005). A record's primary constructor parameter also declares a public property, which is named in PascalCase; RH4120 checks it.

Example:

```csharp
using System;
using System.Linq;

public record class R(int ParameterName);

public record struct S(int ParameterName);

public class C
{
    public void M(object _, EventArgs e)
    {
        Func<int, int, int> f = (_, _) => 0;
    }

    public int N(int[] values)
    {
        return (from _ in values select 1).Count();
    }
}
```

is not reported.

### RH4105-003 — The fix renames the parameter to camelCase

The code fix MUST rename the parameter and every reference to it (SHARED-CASING-007) to the camelCase name that SHARED-CASING-006 derives from its old name. It is withheld as SHARED-CASING-008, SHARED-CASING-009, SHARED-CASING-012, and SHARED-CASING-013 specify, and its Fix All skips colliding names as SHARED-CASING-010 specifies. This requirement covers the renames that SHARED-CASING-007 covers. A parameter whose rename could change which parameter a `CallerArgumentExpression` attribute names, or whether it names one, is left to manual correction as SHARED-CASING-012 specifies.

Why: The fix makes exactly the change the diagnostic asks for, and a parameter is referenced throughout its member's body.

Example:

```csharp
using System;

public class C
{
    public C(int {|RH4105:Count|})
    {
        Func<int, int> f = {|RH4105:Value|} => Value + Count;
    }
}
```

```csharp
using System;

public class C
{
    public C(int count)
    {
        Func<int, int> f = value => value + count;
    }
}
```

### RH4105-004 — A parameter without a name is not reported

The analyzer MUST NOT report a parameter that has no name: the receiver parameter of an extension block that names only its type, such as `extension(long)` or `extension<T>(T[])`. A receiver parameter with a name is checked as RH4105-001 states.

Why: A parameter without a name has nothing to rename, and its diagnostic would have no name to be located on (SHARED-DIAG-007).

Example:

```csharp
public static class E
{
    extension(long)
    {
    }

    extension<T>(T[])
    {
    }

    extension(int)
    {
    }
}
```

is not reported.

### RH4105-005 — Query range variable names are in camelCase

The analyzer MUST report every range variable of a query expression whose name is not in camelCase as SHARED-CASING-002 defines it. A range variable is the variable that a query clause declares with an identifier of its own: the `from` clause, also the first one of a query and one with an explicit type such as `from int value in …`, the `let` clause, the `join` clause, also one with an explicit type or an `into`, and the `into` of a `join` clause or of a query continuation behind `select` or `group`. The analyzer MUST report one diagnostic per declared range variable, located on the identifier of the clause that declares it. A use of a range variable in a later clause declares nothing and MUST NOT be reported.

Why: A range variable plays the role of a lambda parameter: in method syntax the same value is named by a lambda parameter, as `from value in values select value` and `values.Select(value => value)` show, so the two forms are checked alike, as RH4124-003 checks them alike for single-letter names.

Example:

```csharp
using System.Linq;

class C
{
    void M(int[] values, int[] others)
    {
        var doubled = from {|RH4105:Value|} in values
                      let {|RH4105:Doubled_Value|} = Value * 2
                      select Doubled_Value;

        var joined = from int {|RH4105:Item|} in values
                     join {|RH4105:Other|} in others on Item equals Other
                     select Item + Other;

        var grouped = from value in values
                      join other in others on value equals other into {|RH4105:Matches|}
                      select Matches.Count();

        var continued = from value in values
                        group value by value % 2 into {|RH4105:Parity|}
                        select Parity.Key into {|RH4105:Key|}
                        select Key;
    }
}
```

Example — range variables in camelCase:

```csharp
using System.Linq;

class C
{
    void M(int[] values)
    {
        var names = from value in values
                    let doubledValue = value * 2
                    select doubledValue;
    }
}
```

is not reported.

### RH4105-006 — The fix renames the range variable to camelCase

The code fix MUST rename the range variable and every reference to it (SHARED-CASING-007) to the camelCase name that SHARED-CASING-006 derives from its old name. It is withheld as SHARED-CASING-008, SHARED-CASING-009, and SHARED-CASING-013 specify, and its Fix All skips colliding names as SHARED-CASING-010 specifies. This requirement covers the renames that SHARED-CASING-007 covers.

The code fix MUST NOT be offered when a reference to the range variable, anywhere in the query expression that declares it, is the whole expression of a member of an anonymous object creation that has no name of its own, such as `Value` in `new { Value }`. The diagnostic is still reported. A reference that stands in a member with a name of its own, such as `new { Item = Value }`, or that is only part of the member's expression, such as `new { Value.Length }` or `new { Total = Value + 1 }`, does not withhold the fix.

Why: The fix makes exactly the change the diagnostic asks for, and a range variable is referenced in every later clause of its query. The compiler names an anonymous object member that has no name of its own after the identifier of its expression, so renaming that reference renames the member too: the text `ToString()` returns and the names a serializer or reflection reads would change, which SHARED-FIX-003 forbids. A range variable cannot be referenced outside its query expression, so that expression holds every such member. Projecting range variables into an anonymous object is a common shape of query syntax, so the fix states it explicitly.

Example:

```csharp
using System.Linq;

class C
{
    int[] M(int[] values, int[] others)
    {
        return (from {|RH4105:Value|} in values
                let {|RH4105:Doubled|} = Value * 2
                join int {|RH4105:Other|} in others on Doubled equals Other into {|RH4105:Matches|}
                select new { Item = Value, Count = Matches.Count() } into {|RH4105:Projected|}
                select Projected.Item + Projected.Count).ToArray();
    }
}
```

```csharp
using System.Linq;

class C
{
    int[] M(int[] values, int[] others)
    {
        return (from value in values
                let doubled = value * 2
                join int other in others on doubled equals other into matches
                select new { Item = value, Count = matches.Count() } into projected
                select projected.Item + projected.Count).ToArray();
    }
}
```

Example — a range variable that names an anonymous object member:

```csharp
using System.Linq;

class C
{
    object M(int[] values)
    {
        return (from {|RH4105:Value|} in values
                select new { Value }).First();
    }
}
```

is reported, and no code fix is offered.
