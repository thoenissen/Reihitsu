# Analyzer — RH5007 for-Statement should be preceded by a blank line

| | |
|---|---|
| ID prefix | RH5007 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5007ForStatementsShouldBePrecededByABlankLineAnalyzer`, `RH5007ForStatementsShouldBePrecededByABlankLineCodeFixProvider` |
| Uses | SHARED-STMT-001, SHARED-STMT-002, SHARED-STMT-003, SHARED-STMT-004 |

RH5007 reports a `for` statement that follows another statement of the same block or switch section without a blank line between them, and offers a code fix that inserts one as SHARED-STMT-004 specifies.

## Non-goals

- Blank lines before other statement kinds — the other rules that use `shared/statement-blank-lines.md`.

## Requirements

### RH5007-001 — A `for` statement that follows a statement needs a blank line

The analyzer MUST report a `for` statement as SHARED-STMT-001, SHARED-STMT-002, and SHARED-STMT-003 specify.

Why: A `for` statement starts a loop; the blank line separates the loop from the setup code above it.

Example:

```csharp
class C
{
    void M(int count)
    {
        var sum = 0;
        {|RH5007:for|} (var i = 0; i < count; i++)
        {
            sum += i;
        }

        for (var i = 0; i < count; i++)
        {
            sum -= i;
        }
    }
}
```

The second `for` follows a blank line and is not reported.

### RH5007-002 — The diagnostic is on the `for` keyword

The analyzer MUST report the diagnostic on the `for` keyword.

Why: The keyword is where the missing separator becomes visible, and the location stays stable when the loop header changes.

Example: see RH5007-001.
