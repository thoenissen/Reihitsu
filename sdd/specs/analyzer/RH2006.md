# Analyzer — RH2006 Debug.Assert must provide message text

| | |
|---|---|
| ID prefix | RH2006 |
| Status | Active |
| Category | Design |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH2006DebugAssertMustProvideMessageTextAnalyzer` |
| Uses | SHARED-DEBUG-001 |

RH2006 reports a call of `System.Diagnostics.Debug.Assert` that passes no message, or a message without text.

## Non-goals

- `Debug.Fail` — RH2007.
- `Trace.Assert` and assertion methods of other types and test frameworks.
- The detail message of the overloads that take one. Only the `message` argument is checked.

## Requirements

### RH2006-001 — An assertion without message text is reported

The analyzer MUST report a call of `System.Diagnostics.Debug.Assert`, also when it is called through `using static`, that passes no argument for a parameter named `message`, or whose `message` argument has no text as SHARED-DEBUG-001 defines it. The `message` argument is the argument named `message`, or else the argument at the position of the `message` parameter.

Why: An assertion that fails without a message tells whoever hits it only that some condition was false, not which one or why it mattered.

Example:

```csharp
using System.Diagnostics;
using static System.Diagnostics.Debug;

class C
{
    void M(bool condition)
    {
        {|RH2006:Debug.Assert(condition)|};
        {|RH2006:Assert(condition)|};
        {|RH2006:Debug.Assert(condition, "")|};
        {|RH2006:Debug.Assert(message: "", condition: condition)|};
        Debug.Assert(condition, "Condition must hold.");
        Assert(condition, "Condition must hold.");
        Debug.Assert(message: "Condition must hold.", condition: condition);
    }
}
```

### RH2006-002 — Only the `message` argument is checked

The analyzer MUST NOT report a call whose `message` argument has text, whatever its detail message is, and MUST report a call whose `message` argument has no text even when its detail message has text.

Why: The message is the line a failed assertion shows first; the detail message only adds to it.

Example:

```csharp
using System.Diagnostics;

class C
{
    void M(bool condition)
    {
        Debug.Assert(condition, "Condition must hold.", "");
        {|RH2006:Debug.Assert(condition, "", "Detail")|};
        {|RH2006:Debug.Assert(condition, "", "Detail {0}", 1)|};
    }
}
```

### RH2006-003 — Only `System.Diagnostics.Debug.Assert` is checked

The analyzer MUST NOT report a call of a method named `Assert` that is not declared on `System.Diagnostics.Debug`, such as `Trace.Assert` or a method of the user's own type.

Why: The rule is about the framework's debug assertion; other assertion methods have their own conventions for messages.

Example:

```csharp
using System.Diagnostics;

class C
{
    void M(bool condition)
    {
        Trace.Assert(condition);
        Check.Assert(condition);
    }

    static class Check
    {
        public static void Assert(bool condition)
        {
        }
    }
}
```

is not reported.

### RH2006-004 — The diagnostic covers the whole call

The analyzer MUST report one diagnostic per reported call, covering the whole invocation expression.

Why: The missing or empty message belongs to the call as a whole; when no message is passed, there is no argument to point at.

Example: see RH2006-001.
