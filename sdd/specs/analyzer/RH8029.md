# Analyzer — RH8029 Private events must be documented

| | |
|---|---|
| ID prefix | RH8029 |
| Status | Active |
| Category | Documentation |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH8029PrivateEventsMustBeDocumentedAnalyzer` |
| Uses | SHARED-DOC-001, SHARED-DOC-002, SHARED-DOC-004, SHARED-DOC-005, SHARED-DOC-006, SHARED-DOC-007, SHARED-DOC-008, SHARED-DOC-009 |

RH8029 reports an event declaration in the private group that has no `<summary>` or `<inheritdoc>` documentation.

## Non-goals

- Events in the non-private group — RH8028.
- Fields and delegates — RH8026, RH8027, RH8015, and RH8016.
- Whether the summary has text — RH8030.

## Requirements

### RH8029-001 — Undocumented private events are reported

The analyzer MUST report every event declaration in the private group of SHARED-DOC-002 that is not documented, checked as SHARED-DOC-001 specifies, except an explicit interface implementation, which SHARED-DOC-009 exempts although it has no access modifier. An event declaration is a field-like event (`event Action Changed;`) or an event with `add` and `remove` accessors, declared in the body of a class, struct, interface, record, or record struct. A field-like declaration of several events is one declaration, documented by the documentation comments before it. Whether it is documented MUST be decided as SHARED-DOC-004, SHARED-DOC-005, SHARED-DOC-006, and SHARED-DOC-007 specify, and nothing is reported when SHARED-DOC-008 applies.

Why: A private event is raised only from inside its type, so nothing else says when it is raised. The summary records the triggering condition, and the editor shows it wherever the event is subscribed to or raised. It has a rule of its own, so a project can require documentation for what other code uses without requiring it here.

Example:

```csharp
using System;

/// <summary>
/// Notifier
/// </summary>
public interface INotifier
{
    /// <summary>
    /// Raised on notification
    /// </summary>
    event Action Notified;
}

/// <summary>
/// Publisher
/// </summary>
public class Publisher : INotifier
{
    private event Action {|RH8029:Changed|};

    /// <remarks>
    /// No summary
    /// </remarks>
    event Action {|RH8029:Closed|}
    {
        add
        {
        }
        remove
        {
        }
    }

    private event Action {|RH8029:Opened|}, Moved;

    /// <summary>
    /// Raised after saving
    /// </summary>
    private event Action Saved;

    public event Action Visible;

    event Action INotifier.Notified
    {
        add
        {
        }
        remove
        {
        }
    }
}
```

### RH8029-002 — The diagnostic is on the event name

The analyzer MUST report one diagnostic per undocumented event declaration, located on the identifier of the event, or on the identifier of the first event a field-like declaration declares.

Why: The documentation comment covers the whole declaration, so one diagnostic is enough, and the name identifies the declaration without marking its accessors.

Example: see RH8029-001.
