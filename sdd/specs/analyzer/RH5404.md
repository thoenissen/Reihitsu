# Analyzer — RH5404 Element must not be on a single line

| | |
|---|---|
| ID prefix | RH5404 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5404ElementMustNotBeOnSingleLineAnalyzer`, `RH5404ElementMustNotBeOnSingleLineCodeFixProvider` |
| Uses | FMT-BLANK-011, FMT-BREAK-002, FMT-BREAK-007, FMT-STRUCT-017, SHARED-DIAG-007, SHARED-FIX-001, SHARED-FIX-006 |

RH5404 reports a type declaration or an extension block whose body is written on one line, and offers a code fix that lays out a type declaration the way the formatter does.

## Non-goals

- The bodies of members, accessors, and statements — RH5403 for statement blocks.
- Whether an empty type uses a semicolon declaration — RH5412 to RH5416 and RH5418.
- A type body whose braces are on different lines while members share a line, and the layout the formatter gives the braces of an extension block — thoenissen/Reihitsu#1446.

## Requirements

### RH5404-001 — A type body on one line is reported

The analyzer MUST report a class, struct, interface, record, record struct, union, or enum declaration, or an extension block, whose opening and closing braces are on the same line, also when the body is empty. A declaration without a body (`class C;`, `record struct P(int X);`, `union U(int, string);`) and a declaration whose braces are on different lines MUST NOT be reported.

Why: A one-line type body hides where the type begins and ends, and the next member added to it rewrites the whole declaration line.

Example:

```csharp
class {|RH5404:A|} { int _x; }

struct {|RH5404:B|} { }

enum {|RH5404:E|} { One, Two }

union {|RH5404:U|}(int, string) { public int X => 1; }

class D;

record struct P(int X);

union V(int, string);

class F
{
}

static class X
{
    {|RH5404:extension|}(int value) { public int Doubled => value * 2; }

    extension(string text)
    {
        public int Length2 => text.Length * 2;
    }
}
```

### RH5404-002 — The diagnostic is on the type's name

The analyzer MUST report one diagnostic per declaration, located on the identifier of the type. An extension block has no name; its diagnostic is located on its `extension` keyword (SHARED-DIAG-007).

Why: The name identifies the declaration without covering its members, so the diagnostics of a nested type stay apart from those of its container. The `extension` keyword is the token a reader recognizes as the start of a block without a name.

Example:

```csharp
class {|RH5404:A|} { class {|RH5404:B|} { } }

static class {|RH5404:X|} { {|RH5404:extension|}(int value) { } }
```

### RH5404-003 — The fix lays out the declaration

The code fix MUST format the reported declaration as the formatter formats it in place: the braces on their own lines (FMT-BREAK-002) and, in a class, struct, interface, record, record struct, or union, every member on its own line between them (FMT-BREAK-007). The members of an enum move between the braces and keep their layout among themselves. An empty class, struct, interface, record, record struct, or union becomes a semicolon declaration (FMT-STRUCT-017); an empty enum keeps its braces.

No code fix is offered for an extension block. The diagnostic is still reported, and the fix of a type declaration that contains it is offered as usual.

Why: The formatter owns the layout of type declarations; delegating to it applies that layout instead of a second one, including the semicolon form the formatter gives an empty type. The formatter does not place the braces of an extension block on their own lines: formatting the block leaves an empty block on its one line, so the diagnostic stays (SHARED-FIX-001), and leaves the braces of any other block on the lines of its header and of its last member, a layout that is not the expanded body this rule asks for. The block is expanded by hand.

Example:

```csharp
class {|RH5404:A|} { int _x; }

struct {|RH5404:B|} { }

interface {|RH5404:I|} { void M(); }

enum {|RH5404:E|} { One, Two }

enum {|RH5404:F|} { }

union {|RH5404:U|}(int, string) { public int X => 1; }

union {|RH5404:V|}(int, string) { }
```

```csharp
class A
{
    int _x;
}

struct B;

interface I
{
    void M();
}

enum E
{
    One, Two
}

enum F
{
}

union U(int, string)
{
    public int X => 1;
}

union V(int, string);
```

Example — no blank line is inserted above a comment that leads the declaration (SHARED-FIX-006, *Leading trivia*):

```csharp
namespace N
{
    class A
    {
        int _y;
    }
    // c
    class {|RH5404:B|} { int _x; }
}
```

```csharp
namespace N
{
    class A
    {
        int _y;
    }
    // c
    class B
    {
        int _x;
    }
}
```

Formatting the document would also insert a blank line above `// c` (FMT-BLANK-011).

For an extension block:

```csharp
static class X
{
    {|RH5404:extension|}(int value) { public int Doubled => value * 2; }
}
```

no code fix is offered.
