# Analyzer — RH5404 Element must not be on a single line

| | |
|---|---|
| ID prefix | RH5404 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5404ElementMustNotBeOnSingleLineAnalyzer`, `RH5404ElementMustNotBeOnSingleLineCodeFixProvider` |
| Uses | FMT-BREAK-002, FMT-BREAK-007, FMT-STRUCT-017 |

RH5404 reports a type declaration whose body is written on one line, and offers a code fix that lays out the declaration the way the formatter does.

## Non-goals

- Union declarations.
- The bodies of members, accessors, and statements — RH5403 for statement blocks.
- Whether an empty type uses a semicolon declaration — RH5412 to RH5416.

## Requirements

### RH5404-001 — A type body on one line is reported

The analyzer MUST report a class, struct, interface, record, record struct, or enum declaration whose opening and closing braces are on the same line, also when the body is empty. A declaration without a body (`class C;`, `record struct P(int X);`) and a declaration whose braces are on different lines MUST NOT be reported.

Why: A one-line type body hides where the type begins and ends, and the next member added to it rewrites the whole declaration line.

Example:

```csharp
class {|RH5404:A|} { int _x; }

struct {|RH5404:B|} { }

enum {|RH5404:E|} { One, Two }

class D;

record struct P(int X);

class F
{
}
```

### RH5404-002 — The diagnostic is on the type's name

The analyzer MUST report one diagnostic per declaration, located on the identifier of the type.

Why: The name identifies the declaration without covering its members, so the diagnostics of a nested type stay apart from those of its container.

Example:

```csharp
class {|RH5404:A|} { class {|RH5404:B|} { } }
```

### RH5404-003 — The fix lays out the declaration

The code fix MUST format the reported declaration as the formatter formats it in place: the braces on their own lines (FMT-BREAK-002) and, in a class, struct, interface, record, or record struct, every member on its own line between them (FMT-BREAK-007). The members of an enum move between the braces and keep their layout among themselves. An empty class, struct, interface, record, or record struct becomes a semicolon declaration (FMT-STRUCT-017); an empty enum keeps its braces.

Why: The formatter owns the layout of type declarations; delegating to it applies that layout instead of a second one, including the semicolon form the formatter gives an empty type.

Example:

```csharp
class {|RH5404:A|} { int _x; }

struct {|RH5404:B|} { }

interface {|RH5404:I|} { void M(); }

enum {|RH5404:E|} { One, Two }

enum {|RH5404:F|} { }
```

```csharp
class A
{
    int _x;
}

struct B;

interface I
{
    void M();
}

enum E
{
    One, Two
}

enum F
{
}
```
