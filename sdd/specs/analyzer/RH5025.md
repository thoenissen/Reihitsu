# Analyzer — RH5025 Opening brace must not be preceded by blank line

| | |
|---|---|
| ID prefix | RH5025 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5025OpeningBraceMustNotBePrecededByBlankLineAnalyzer`, `RH5025OpeningBraceMustNotBePrecededByBlankLineCodeFixProvider` |
| Uses | SHARED-WS-001 |

RH5025 reports a blank line between a declaration, a statement header, or an initializer and the opening brace of its body on the next line, and offers a code fix that deletes it as SHARED-WS-001 specifies.

In the examples, a reported blank line is marked from its start to the end of its line break, so the markup encloses the line break itself.

## Non-goals

- The other blank lines of a run above the brace — RH5023.
- A blank line directly after an opening brace — RH5022.

## Requirements

### RH5025-001 — A blank line above the opening brace of a body is reported

The analyzer MUST report the blank line directly above a line that begins with an opening brace `{` — only whitespace stands in front of the brace on its line — when the brace opens the body of the type, member, or statement written above it, or the initializer of the expression above it. A line holding nothing but whitespace counts as blank.

Why: The brace belongs to the code above it; a blank line between them makes the body look detached from its header.

Example:

```csharp
class C
{|RH5025:
|}{
    void M()
{|RH5025:
|}    {
        int[] a = new[]
{|RH5025:
|}        {
            1,
        };
        if (a[0] > 0)
{|RH5025:
|}        {
        }
    }
}
```

### RH5025-002 — Only the line directly above the brace counts

The analyzer MUST NOT report a blank line that is separated from the opening brace by a line holding a comment or a directive, and MUST NOT report a `{` that is not an opening-brace token: a `{` in the text of a comment or in code that an `#if` branch excludes.

Why: A blank line above a comment separates the comment from the code above it, not the brace from its header. A brace in a comment or in excluded code opens nothing.

Example:

```csharp
class C
{
    void M()

    // note
    {
    }

    /*

    { */
#if NEVER
    void N()

    {
    }
#endif
}
```

is not reported.

### RH5025-003 — One diagnostic per brace, on the line directly above it

The analyzer MUST report one diagnostic per opening brace, located on the line directly above it, from the line's start to the end of its line break.

Why: The diagnostic covers exactly the line the brace touches; a run of blank lines is RH5023's concern.

Example: see RH5025-001.

### RH5025-004 — The fix deletes the blank line

The code fix MUST delete the reported line as SHARED-WS-001 specifies. It is offered for every reported line.

Why: The reported span holds nothing but whitespace and its line break, so deleting it can never touch a comment, a directive, or a token.

Example:

```csharp
class C
{|RH5025:
|}{
    void M()
{|RH5025:
|}    {
    }
}
```

```csharp
class C
{
    void M()
    {
    }
}
```
