# Analyzer — RH5025 Opening brace must not be preceded by blank line

| | |
|---|---|
| ID prefix | RH5025 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5025OpeningBraceMustNotBePrecededByBlankLineAnalyzer`, `RH5025OpeningBraceMustNotBePrecededByBlankLineCodeFixProvider` |
| Uses | SHARED-BLANK-006, SHARED-DIAG-003, SHARED-FIX-001, SHARED-FIX-004, SHARED-WS-001 |

RH5025 reports a blank line between the code above an opening brace and the brace that continues it on the next line, and offers a code fix that deletes it, together with the rest of its run of blank lines, as SHARED-WS-001 specifies for that run.

In the examples, a reported blank line is marked from its start to the end of its line break, so the markup encloses the line break itself.

## Non-goals

- A blank line directly after an opening brace — RH5022.

## Requirements

### RH5025-001 — A blank line above the opening brace of a body is reported

The analyzer MUST report the blank line directly above a line that begins with an opening brace `{` — only whitespace stands in front of the brace on its line — when the brace continues the code written above it: the body of a namespace, a type, a member, an accessor list, a lambda, or a statement such as `if` or `switch`; the body of a switch expression; the initializer or anonymous-object body after `new`; or a property pattern that continues an expression such as `s is`. A line holding nothing but whitespace counts as blank.

Why: The brace belongs to the code above it; a blank line between them makes the body look detached from its header.

Example:

```csharp
namespace N
{|RH5025:
|}{
    class C
{|RH5025:
|}    {
        int P
{|RH5025:
|}        {
            get;
        }

        void M(int a, string s)
{|RH5025:
|}        {
            int[] i = new[]
{|RH5025:
|}            {
                1,
            };
            if (a > 0)
{|RH5025:
|}            {
            }

            System.Action f = () =>
{|RH5025:
|}            {
            };
            var b = a switch
{|RH5025:
|}            {
                _ => 0,
            };
            var c = s is
{|RH5025:
|}                { Length: 0 };
            var d = new
{|RH5025:
|}            {
                X = 1,
            };
        }
    }
}
```

### RH5025-002 — Only the line directly above the brace counts

The analyzer MUST NOT report a blank line that is separated from the opening brace by a line holding a comment or a directive, and MUST NOT report a `{` that is not an opening-brace token: a `{` in the text of a comment or in code that an `#if` branch excludes.

Why: A blank line above a comment separates the comment from the code above it, not the brace from its header. A brace in a comment or in excluded code opens nothing.

Example:

```csharp
class C
{
    void M()

    // note
    {
    }

    /*

    { */
#if NEVER
    void N()

    {
    }
#endif
}
```

is not reported.

### RH5025-003 — One diagnostic per brace, on the line directly above it

The analyzer MUST report one diagnostic per opening brace, located on the line directly above it, from the line's start to the end of its line break.

Why: The diagnostic covers exactly the line the brace touches, which the fix deletes together with the rest of its run.

Example: see RH5025-001.

### RH5025-004 — The fix deletes the run of blank lines

The code fix MUST delete the reported line together with every blank line of the run it belongs to — the blank lines that directly precede it, up to the previous line that is not blank — and MUST NOT change any other text, as SHARED-WS-001 specifies for the span of that run. It is offered for every reported line.

Why: For the lines RH5025-001 names, the run lies between two tokens and holds nothing but whitespace and line breaks, so deleting it can never touch a comment, a directive, a literal, or a token. One application removes the whole run (SHARED-FIX-001); deleting only the reported line would leave a blank line that the rule reports again.

Example:

```csharp
class C
{|RH5025:
|}{
    void M()
{|RH5025:
|}    {
    }
}
```

```csharp
class C
{
    void M()
    {
    }
}
```

Example — a run of two blank lines; RH5023 reports the line directly above the brace as well:

```csharp
class C
{
    void M()

{|RH5025:
|}    {
    }
}
```

```csharp
class C
{
    void M()
    {
    }
}
```

### RH5025-005 — The opening brace of a block statement that follows a statement is not reported

The analyzer MUST NOT report the blank line above the opening brace of a block statement that follows another statement of the same block or switch section, whatever that statement is. A block statement is a block that stands in the statement list of a block or a switch section. The blank line above the opening brace of a block statement that is the first statement of its block or switch section stays reported.

Why: The brace of a block statement starts a statement; it continues no code above it. The blank line above it separates two statements, which the rules about blank lines between statements decide: RH5030 asks for it after a statement that ends with `}`.

Example:

```csharp
class C
{
    void M(int a)
    {
        if (a > 0)
        {
        }

        {
        }
        a++;

        {
        }
        switch (a)
        {
            case 1:
{|RH5025:
|}                {
                }
                break;
        }
    }
}
```

The blank lines above the block statements behind `}` and behind `a++;` are not reported.

### RH5025-006 — The brace of an interpolation hole is not reported

The analyzer MUST NOT report the line above a `{` that opens an interpolation hole of a verbatim or a raw interpolated string, with one `$` or several. That line, even when it is empty, is part of the literal's text (SHARED-DIAG-003); the brace starts a hole, not a body that continues the code above it (RH5025-001).

Why: An empty line in front of a hole is part of the string's value. Deleting it would change what the program does, and the blank line separates no code from a header. In a regular interpolated string a hole's `{` cannot start a line, because the string's text cannot hold a line break. A `{` inside the hole's code, such as the body of a lambda, is a brace like any other and is checked by RH5025-001.

Example:

```csharp
class C
{
    void M(int x)
    {
        var s = $"""
            a

            {x}
            """;
        var u = $$"""
            a

            {{x}}
            """;
        var t = $@"a

{x}";
    }
}
```

is not reported.

### RH5025-007 — A blank line below a region directive is not reported

The analyzer MUST NOT report a blank line above an opening brace when the nearest line above it that is not blank holds an active `#region` or `#endregion` directive. A run of two or more blank lines there is not reported by RH5025 either; RH5023 reports every line after the first.

Why: SHARED-BLANK-006 requires the line below a region directive to be blank — its exemption for `#endregion` applies only in front of `}` — and RH5032 inserts that line. Deleting it would undo RH5032's fix, and the two fixes would alternate forever (SHARED-FIX-004).

Example:

```csharp
class C
{
    System.Collections.Generic.Dictionary<string, int> _d = new()
    {
        { "a", 1 },
        #region A

        { "b", 2 },
        #endregion // A

        { "c", 3 },
    };
}
```

is not reported by RH5025. A blank line whose nearest line above that is not blank holds code or a comment stays reported as RH5025-001 states.
