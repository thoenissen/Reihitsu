# Analyzer — RH5419 Expression style get-only indexers should be single lined

| | |
|---|---|
| ID prefix | RH5419 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5419ExpressionStyleGetOnlyIndexersShouldBeSingleLinedAnalyzer`, `RH5419ExpressionStyleGetOnlyIndexersShouldBeSingleLinedCodeFixProvider` |
| Uses | FMT-BREAK-026, FMT-BREAK-027, FMT-UNSUP-012, FMT-UNSUP-013, RH5401-003, RH5401-004, SHARED-DIAG-010, SHARED-FIX-006, SHARED-FIX-010 |

RH5419 reports an expression-bodied indexer whose `=>` or the start of whose expression is not on the line of the `]` that closes its parameter list, and offers a code fix that moves them onto that line the way the formatter does.

## Non-goals

- Indexers with an accessor list, also when an accessor has an expression body (`get => 1;`) — RH3210 reports a get-only accessor list.
- Expression-bodied properties — RH5401; methods, operators, and other members.
- The layout of the indexer's parameter list, and of the expression after its first token.

## Requirements

### RH5419-001 — An arrow or expression below the closing bracket is reported

The analyzer MUST report an indexer with an expression body when its `=>` is not on the line of the `]` that closes its parameter list, or when the first token of its expression is not on that line. An indexer whose `=>` and first expression token are on the line of that `]` MUST NOT be reported, also when the expression continues on later lines and also when the parameter list spans several lines. The `]` is the token in front of the `=>`; the line of the indexer's `this` keyword or of its `[` does not count where the parameter list wraps.

Why: An expression-bodied indexer is a one-line declaration by intent, like an expression-bodied property (RH5401); a wrapped arrow makes the reader look at the next line to see what the indexer returns (FMT-BREAK-026). The signature of an indexer ends with its parameter list, which may wrap on its own, so the arrow belongs on the line where the signature ends. An expression that starts on that line already says what the indexer computes, so its continuation may wrap. Properties and indexers have separate rules so that each can be configured on its own.

Example:

```csharp
class C
{
    {|RH5419:int this[int i]
        => i;|}

    {|RH5419:int this[long i] =>
        1;|}

    {|RH5419:int this[short a,
             short b]
        => a;|}

    int this[byte a,
             byte b] => a;

    int this[char a, char b] => a
                                + b;
}
```

### RH5419-002 — The diagnostic is on the indexer

The analyzer MUST report one diagnostic per indexer, located on the whole indexer declaration, its attribute lists and modifiers included.

Why: The declaration is laid out as a whole, so the diagnostic covers the construct the fix lays out.

Example:

```csharp
using System;

class C
{
    {|RH5419:[Obsolete]
    public int this[int i]
        => i;|}
}
```

### RH5419-003 — The fix puts the arrow and the expression on the line of the closing bracket

The code fix MUST format the indexer as the formatter formats it in place, which puts the `=>` and the start of the expression on the line of the `]` that closes the parameter list (FMT-BREAK-026), lays out the parameter list as the formatter does, and places the attribute lists of the indexer as FMT-BREAK-027 places them. The attribute lists are laid out as RH5401-003 states for the attribute lists of a property, with the indexer in the property's place.

Why: The formatter owns the layout of expression-bodied indexers; delegating to it applies that layout instead of a second one. The fix formats the construct it reports (RH5419-002), so the parameter list and the attribute lists come out as the formatter writes them.

Example:

```csharp
class C
{
    {|RH5419:int this[int i]
        => i;|}

    {|RH5419:int this[long i] =>
        1;|}

    {|RH5419:int this[
        uint a,
        uint b]
        => 1;|}
}
```

```csharp
class C
{
    int this[int i] => i;

    int this[long i] => 1;

    int this[uint a,
             uint b] => 1;
}
```

Example — the documentation comment stays as written (SHARED-FIX-006, *Leading trivia*):

```csharp
class C
{
    /// <summary>A</summary>
    {|RH5419:int this[int i]
        => i;|}
}
```

```csharp
class C
{
    /// <summary>A</summary>
    int this[int i] => i;
}
```

Example — an indexer with attribute lists:

```csharp
using System;

class C
{
    {|RH5419:[Obsolete] int this[int i]
        => i;|}

    {|RH5419:[Obsolete, CLSCompliant(false)]
    int this[long i]
        => 1;|}
}
```

```csharp
using System;

class C
{
    [Obsolete]
    int this[int i] => i;

    [Obsolete]
    [CLSCompliant(false)]
    int this[long i] => 1;
}
```

### RH5419-004 — The fix is withheld when the expression stays on several lines

The code fix MUST NOT be offered when the indexer's code from its `=>` through its `;`, laid out by the formatter, would still span several lines because its expression stays wrapped. A parameter list that the formatter keeps on several lines does not count: an indexer whose expression the formatter puts on the line of the `]` gets the fix (RH5419-003). Nor MUST it be offered when a comment, a directive, or disabled text stands in front of the `=>`, between the `]` and the `=>`, or behind the `=>`, in front of the expression: the formatter refuses such an indexer as a whole (FMT-UNSUP-013, FMT-UNSUP-012), and the fix asks it before it is offered (SHARED-FIX-010). Nor MUST it be offered where RH5401-004 withholds the fix for the attribute lists of a property, with the indexer in the property's place: where the formatted indexer would hold, in the gap behind one of its attribute lists, a different number of blank lines than the indexer as written, and where one of its attribute lists holds, between its brackets, a blank line, a directive, disabled text, or a comment that starts its own line. The diagnostic is still reported in each case: a shape the formatter refuses is not one it keeps (SHARED-DIAG-010).

Why: The fix promises the arrow and the expression on the line of the `]`. Where the formatter keeps the expression on several lines, applying it would leave the expression in a shape the author did not choose; the author moves the arrow and the first token by hand. A wrapped parameter list is the author's layout of the signature, which the fix keeps as the formatter keeps it, and it is not what the diagnostic is about. Where the formatter refuses the indexer, it changes nothing, and the author moves the comment or the directive above the indexer, after which the fix applies. The attribute lists of an indexer are the attribute lists of a member like those of a property, and RH5401-004 gives the reasons for which the fix leaves their blank lines and the lists that hold a blank line, a directive, or a comment on its own line alone.

Example:

```csharp
using System;

class C
{
    {|RH5419:int this[int i] =>
        i
        + 1;|}

    {|RH5419:int this[long i] // note
        => 1;|}

    {|RH5419:int this[short i] => // note
        1;|}

    {|RH5419:[Obsolete]
    // note
    int this[byte i]
        => 1;|}

    {|RH5419:[Obsolete,

     CLSCompliant(false)]
    int this[char c]
        => 1;|}
}
```

is reported, and no code fix is offered.
