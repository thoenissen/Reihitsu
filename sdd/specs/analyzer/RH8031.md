# Analyzer — RH8031 Extension declarations must have summary text

| | |
|---|---|
| ID prefix | RH8031 |
| Status | Active |
| Category | Documentation |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH8031ExtensionDeclarationsMustHaveSummaryTextAnalyzer` |
| Uses | SHARED-DOC-004, SHARED-DOC-008, SHARED-DOC-010, SHARED-DOC-013 |

RH8031 reports an extension declaration whose documentation has no `<summary>` element, or one without text.

## Non-goals

- The members declared in an extension block — RH8020 to RH8023, RH8030, and RH8034.
- The documentation of the extension declaration's parameter and type parameters — RH8032 and RH8033.

## Requirements

### RH8031-001 — An extension declaration without a summary is reported

The analyzer MUST report every extension declaration — `extension(…)` or `extension<…>(…)` — that has no documentation comment, as SHARED-DOC-004 defines its documentation comments, or whose documentation comment has no `<summary>` element at its top level. A `<summary>` nested in another element MUST NOT count. Whether the static class that declares the extension block is documented, and which accessibility it has, MUST NOT change the report. Nothing is reported when SHARED-DOC-008 applies.

This requirement covers an extension declaration whose leading trivia has at most one documentation comment and that shares its documentation with no other extension declaration as SHARED-DOC-013 specifies, and documentation comments that are well-formed XML, write the tag name `summary` in lower case, without a namespace prefix, and in no XML namespace, and have neither an `<inheritdoc>` nor an `<include>` element at their top level.

Why: An extension block names the value it extends and nothing else. Without a summary, a reader who wants to know which values the block is meant for, and what it adds to them, has to open the block and work that out from its members.

Example:

```csharp
/// <summary>
/// Extensions
/// </summary>
public static class Extensions
{
    {|RH8031:extension|}(string value)
    {
    }

    /// <remarks>
    /// <summary>Nested</summary>
    /// </remarks>
    {|RH8031:extension|}(int value)
    {
    }

    /// <summary>
    /// Adds helpers to long values
    /// </summary>
    extension(long value)
    {
    }
}

internal static class Hidden
{
    {|RH8031:extension|}(byte value)
    {
    }
}
```

### RH8031-002 — An extension declaration whose summary has no text is reported

The analyzer MUST report an extension declaration whose `<summary>` element at the top level of its documentation comment has no text as SHARED-DOC-010 specifies.

This requirement covers what RH8031-001 covers.

Why: An empty summary leaves the reader as uninformed as a missing one, while it looks as if the block were documented.

Example:

```csharp
/// <summary>
/// Extensions
/// </summary>
public static class Extensions
{
    /// {|RH8031:<summary></summary>|}
    extension(string value)
    {
    }

    /// {|RH8031:<summary>
    /// </summary>|}
    extension(int value)
    {
    }
}
```

### RH8031-003 — Where the diagnostic is

The analyzer MUST report one diagnostic per extension declaration: on its `extension` keyword when it has no `<summary>` at the top level of its documentation comment, and on the whole `<summary>` element — the empty element `<summary/>`, or everything from the start tag through the end tag — when that element has no text.

Why: The keyword identifies the declaration when there is no summary to mark; when there is one, the summary is what has to change.

Example: see RH8031-001 and RH8031-002.
