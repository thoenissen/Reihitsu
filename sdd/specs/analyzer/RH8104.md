# Analyzer — RH8104 Element parameter documentation must have text

| | |
|---|---|
| ID prefix | RH8104 |
| Status | Active |
| Category | Documentation |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH8104ElementParameterDocumentationMustHaveTextAnalyzer` |
| Uses | SHARED-DOC-004, SHARED-DOC-008, SHARED-DOC-014 |

RH8104 reports a `<param>` element that has no text.

## Non-goals

- A parameter without a `<param>` element — RH8101; whether the element's name matches a parameter or is present — RH8102 and RH8103.
- `<typeparam>` and `<returns>` elements — RH8111 and RH8106; the summary — RH8030.

## Requirements

### RH8104-001 — A `<param>` element without text is reported

The analyzer MUST report each `<param>` element at the top level of a declaration's documentation comment, as SHARED-DOC-004 defines it, that has no text as SHARED-DOC-014 specifies, whether or not the element names a parameter of the declaration. The declarations checked are method, constructor, delegate, indexer, operator, and conversion operator declarations, and class, struct, record, and record struct declarations, whether or not they have parameters or a primary constructor; a declaration that explicitly implements an interface member is checked as well, and the declaration's accessibility does not matter. A `<param>` element nested inside another element MUST NOT be reported. Nothing is reported when SHARED-DOC-008 applies.

This requirement covers a declaration whose leading trivia has one documentation comment, placed as SHARED-DOC-004 covers and well-formed XML, with the tag name `param` written in lower case, without a namespace prefix, and in no XML namespace.

Why: An empty description looks like finished documentation while it tells the reader nothing about the argument; the tooltip shows the same nothing as without the element.

Example:

```csharp
/// <summary>
/// Service
/// </summary>
/// {|RH8104:<param name="size"></param>|}
public class C(int size)
{
    /// <summary>
    /// Runs
    /// </summary>
    /// {|RH8104:<param name="a"/>|}
    /// <param name="b">B</param>
    /// <remarks>
    /// <param name="c"></param>
    /// </remarks>
    public void M(int a, int b)
    {
    }

    /// <summary>
    /// Adds
    /// </summary>
    /// {|RH8104:<param name="left">
    /// </param>|}
    /// <param name="right">Right</param>
    /// <returns>Sum</returns>
    public static C operator +(C left, C right) => left;
}
```

### RH8104-002 — The diagnostic is on the element

The analyzer MUST report one diagnostic per reported `<param>` element, located on the whole element: the empty element, or everything from the start tag through the end tag.

Why: The element is where the description has to be written.

Example: see RH8104-001.
