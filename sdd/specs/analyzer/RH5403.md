# Analyzer — RH5403 Statement must not be on a single line

| | |
|---|---|
| ID prefix | RH5403 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5403StatementMustNotBeOnSingleLineAnalyzer`, `RH5403StatementMustNotBeOnSingleLineCodeFixProvider` |
| Uses | SHARED-BLOCK-001, FMT-BLANK-001, FMT-BLANK-011, FMT-BREAK-002, FMT-BREAK-006, SHARED-DIAG-011, SHARED-FIX-006 |

RH5403 reports a statement block that holds statements and is written on one line, and offers a code fix that lays out the statement it belongs to the way the formatter does.

## Non-goals

- A block whose opening brace shares the line of its statement while the block spans several lines — RH5402.
- Type bodies — RH5404; the bodies of members, accessors, and lambdas.
- Unbraced bodies — RH5405 and RH5406.

## Requirements

### RH5403-001 — A block with statements on one line is reported

The analyzer MUST report a block that SHARED-BLOCK-001 names when it contains at least one statement and its opening and closing braces are on the same line. An empty block on one line (`{ }`) MUST NOT be reported.

Why: A statement hidden between two braces on one line is hard to read and cannot get a breakpoint of its own. An empty block holds no statement that could be moved to a line of its own.

Example:

```csharp
class C
{
    void M(bool a)
    {
        if (a) {|RH5403:{|} M(a); }
        else {|RH5403:{|} M(a); M(a); }
        while (a) { }
        System.Action f = () => { M(a); };
    }
}
```

### RH5403-002 — The diagnostic is on the opening brace

The analyzer MUST report one diagnostic per block, located on its opening brace.

Why: The block starts at its opening brace, and the brace is the first thing that moves.

Example: see RH5403-001.

### RH5403-003 — The fix lays out the statement

The code fix MUST format the statement that owns the reported block — for the block of an `else`, the `if` statement the `else` belongs to — as the formatter formats it in place: each brace on its own line and each statement on its own line between them (FMT-BREAK-002, FMT-BREAK-006).

Why: The formatter owns the layout of statement blocks; delegating to it applies that layout instead of a second one.

Example:

```csharp
class C
{
    void M(bool a)
    {
        if (a) {|RH5403:{|} M(a); }
        else {|RH5403:{|} M(a); M(a); }
    }
}
```

```csharp
class C
{
    void M(bool a)
    {
        if (a)
        {
            M(a);
        }
        else
        {
            M(a);
            M(a);
        }
    }
}
```

Example — no blank line is inserted above a comment that leads the statement (SHARED-FIX-006, *Leading trivia*):

```csharp
class C
{
    void M(int a)
    {
        a = 1;
        // c
        if (a > 0) {|RH5403:{|} a++; }
    }
}
```

```csharp
class C
{
    void M(int a)
    {
        a = 1;
        // c
        if (a > 0)
        {
            a++;
        }
    }
}
```

Formatting the document would also insert a blank line above `// c` (FMT-BLANK-011). Without the comment, no blank line is inserted above the `if` either, where formatting the document would insert one (FMT-BLANK-001).

### RH5403-004 — A block inside a non-verbatim interpolation is not reported before C# 11

The analyzer MUST NOT report a block that stands, at any depth, inside an interpolation of an interpolated string that is not verbatim — one that starts with `$"`, not with `$@"` or `@$"` — when the code is compiled with C# 10 or earlier. This holds also when a verbatim interpolated string lies between the block and that interpolation. A block inside an interpolation of a verbatim interpolated string that no interpolation of a non-verbatim one contains, a block that only contains an interpolated string, and every block when the code is compiled with C# 11 or later MUST be reported as RH5403-001 states.

Why: Before C# 11, an interpolation of a non-verbatim interpolated string cannot contain a line break (CS8967), so the braces and statements of a block inside it cannot start lines of their own, and the change the rule asks for cannot be written there (SHARED-DIAG-011). An interpolation of a verbatim interpolated string accepts line breaks in every language version.

Example:

```csharp
using System;

class C
{
    static int F(Func<int> f) => f();

    string M(bool b) => $"a {F(() => { if (b) { return 1; } return 0; })} b";

    int N(bool b)
    {
        if (b) {|RH5403:{|} return $"{1}".Length; }

        return 0;
    }
}
```

is reported only at `N` when the code is compiled with C# 10 or earlier. When it is compiled with C# 11 or later, the block in `M` is reported as well:

```csharp
using System;

class C
{
    static int F(Func<int> f) => f();

    string M(bool b) => $"a {F(() => { if (b) {|RH5403:{|} return 1; } return 0; })} b";
}
```

In an interpolation of a verbatim interpolated string, the block is reported in every language version:

```csharp
using System;

class C
{
    static int F(Func<int> f) => f();

    string M(bool b) => $@"a {F(() => { if (b) {|RH5403:{|} return 1; } return 0; })} b";
}
```
