# Analyzer — RH5403 Statement must not be on a single line

| | |
|---|---|
| ID prefix | RH5403 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5403StatementMustNotBeOnSingleLineAnalyzer`, `RH5403StatementMustNotBeOnSingleLineCodeFixProvider` |
| Uses | SHARED-BLOCK-001, FMT-BREAK-002, FMT-BREAK-006, FMT-BLANK-001, FMT-STRUCT-001, SHARED-FIX-006 |

RH5403 reports a statement block that holds statements and is written on one line, and offers a code fix that lays out the statement it belongs to the way the formatter does.

## Non-goals

- A block whose opening brace shares the line of its statement while the block spans several lines — RH5402.
- Type bodies — RH5404; the bodies of members, accessors, and lambdas.
- Unbraced bodies — RH5405 and RH5406.

## Requirements

### RH5403-001 — A block with statements on one line is reported

The analyzer MUST report a block that SHARED-BLOCK-001 names when it contains at least one statement and its opening and closing braces are on the same line. An empty block on one line (`{ }`) MUST NOT be reported.

Why: A statement hidden between two braces on one line is hard to read and cannot get a breakpoint of its own. An empty block holds no statement that could be moved to a line of its own.

Example:

```csharp
class C
{
    void M(bool a)
    {
        if (a) {|RH5403:{|} M(a); }
        else {|RH5403:{|} M(a); M(a); }
        while (a) { }
        System.Action f = () => { M(a); };
    }
}
```

### RH5403-002 — The diagnostic is on the opening brace

The analyzer MUST report one diagnostic per block, located on its opening brace.

Why: The block starts at its opening brace, and the brace is the first thing that moves.

Example: see RH5403-001.

### RH5403-003 — The fix lays out the statement

The code fix MUST lay out the reported block as the formatter lays it out in place: each brace on its own line and each statement on its own line between them (FMT-BREAK-002, FMT-BREAK-006). The rest of the statement that owns the block MUST stay as written (SHARED-FIX-006): its header, such as the condition of an `if` or the header of a loop, and, for the block of an `if` or an `else`, the other branches of the `if` statement, also where formatting the document would change them, such as by wrapping an unbraced branch in braces (FMT-STRUCT-001). The leading trivia of that statement — the blank lines, comments, and directives above it — MUST stay as written: the fix MUST NOT insert a blank line above the statement or above a comment that leads it, also where formatting the document would insert one (FMT-BLANK-001).

Why: The formatter owns the layout of statement blocks; delegating to it applies that layout instead of a second one. The diagnostic is about the block, so the statement's header, its other branches, and the blank lines and comments above it are the author's layout, which the formatter and the layout rules correct on their own.

Example:

```csharp
class C
{
    void M(bool a)
    {
        if (a) {|RH5403:{|} M(a); }
        else {|RH5403:{|} M(a); M(a); }
    }
}
```

```csharp
class C
{
    void M(bool a)
    {
        if (a)
        {
            M(a);
        }
        else
        {
            M(a);
            M(a);
        }
    }
}
```

Example — the other branch of the `if` statement stays as written:

```csharp
class C
{
    void M(bool a)
    {
        if (a) M(a);
        else {|RH5403:{|} M(a); M(a); }
    }
}
```

```csharp
class C
{
    void M(bool a)
    {
        if (a) M(a);
        else
        {
            M(a);
            M(a);
        }
    }
}
```

Formatting the document would also wrap `M(a);` behind `if (a)` in braces.

Example — no blank line is inserted above a comment that leads the statement:

```csharp
class C
{
    void M(int a)
    {
        a = 1;
        // c
        if (a > 0) {|RH5403:{|} a++; }
    }
}
```

```csharp
class C
{
    void M(int a)
    {
        a = 1;
        // c
        if (a > 0)
        {
            a++;
        }
    }
}
```

Formatting the document would also insert a blank line above `// c`.
