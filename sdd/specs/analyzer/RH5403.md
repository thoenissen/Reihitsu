# Analyzer — RH5403 Statement must not be on a single line

| | |
|---|---|
| ID prefix | RH5403 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5403StatementMustNotBeOnSingleLineAnalyzer`, `RH5403StatementMustNotBeOnSingleLineCodeFixProvider` |
| Uses | SHARED-BLOCK-001, FMT-BREAK-002, FMT-BREAK-006, SHARED-FIX-006, SHARED-FIX-007 |

RH5403 reports a statement block that holds statements and is written on one line, and offers a code fix that lays out that block the way the formatter does.

## Non-goals

- A block whose opening brace shares the line of its statement while the block spans several lines — RH5402.
- Type bodies — RH5404; the bodies of members, accessors, and lambdas.
- Unbraced bodies — RH5405 and RH5406.

## Requirements

### RH5403-001 — A block with statements on one line is reported

The analyzer MUST report a block that SHARED-BLOCK-001 names when it contains at least one statement and its opening and closing braces are on the same line. An empty block on one line (`{ }`) MUST NOT be reported.

Why: A statement hidden between two braces on one line is hard to read and cannot get a breakpoint of its own. An empty block holds no statement that could be moved to a line of its own.

Example:

```csharp
class C
{
    void M(bool a)
    {
        if (a) {|RH5403:{|} M(a); }
        else {|RH5403:{|} M(a); M(a); }
        while (a) { }
        System.Action f = () => { M(a); };
    }
}
```

### RH5403-002 — The diagnostic is on the opening brace

The analyzer MUST report one diagnostic per block, located on its opening brace.

Why: The block starts at its opening brace, and the brace is the first thing that moves.

Example: see RH5403-001.

### RH5403-003 — The fix lays out the reported block

The code fix MUST put each brace of the reported block on its own line and each statement of the block on its own line between them, laid out as the formatter lays them out (FMT-BREAK-002, FMT-BREAK-006). It MUST NOT change anything outside the reported block and the gap in front of its opening brace (SHARED-FIX-006): not the header of the statement that owns the block, not another block of the same statement, such as the `else` block of an `if` or the `if` block of an `else`, and not the blank lines in front of the statement. A block of an `else if` takes the column the formatter gives it, the column of the `else` (SHARED-FIX-007).

Why: The formatter owns the layout of statement blocks, so the fix applies that layout to the block it reports instead of a second one. The rest of the statement is not what the diagnostic is about; another block of the same statement that is on one line has a diagnostic of its own.

Example:

```csharp
class C
{
    void M(bool a)
    {
        if (a) {|RH5403:{|} M(a); }
        else {|RH5403:{|} M(a); M(a); }
    }
}
```

```csharp
class C
{
    void M(bool a)
    {
        if (a)
        {
            M(a);
        }
        else
        {
            M(a);
            M(a);
        }
    }
}
```

Example — the rest of the statement stays as written:

```csharp
class C
{
    void M(bool a, bool b)
    {
        int  x = 1;
        if (a) {|RH5403:{|} M(a, b); }
        else if (b)
        {
            x  = 2;
        }
        else if (x > 1) {|RH5403:{|} M(a, b); }
    }
}
```

```csharp
class C
{
    void M(bool a, bool b)
    {
        int  x = 1;
        if (a)
        {
            M(a, b);
        }
        else if (b)
        {
            x  = 2;
        }
        else if (x > 1)
        {
            M(a, b);
        }
    }
}
```
