# Analyzer — RH5034 Comments must not be placed between a documentation comment and its declaration

| | |
|---|---|
| ID prefix | RH5034 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH5034CommentsMustNotBePlacedBetweenDocumentationAndDeclarationAnalyzer` |
| Uses | SHARED-COMMENT-001, SHARED-COMMENT-002, SHARED-COMMENT-003 |

RH5034 reports a comment placed between the documentation comment of a declaration and the declaration itself.

## Non-goals

- Whether a declaration has documentation, and where a documentation comment is placed — the documentation rules of the RH8xxx range.
- A comment between the attributes of a declaration and the declaration — RH5033.

## Requirements

### RH5034-001 — A comment after the documentation comment of a declaration is reported

The analyzer MUST report every ordinary comment (SHARED-COMMENT-001, SHARED-COMMENT-002) that stands before the first token of a declaration — its first attribute list, modifier, or keyword — and after a documentation comment in front of that token, as SHARED-COMMENT-003 specifies. A documentation comment counts whether or not the compiler parses documentation comments; when it does not, its text decides, as SHARED-COMMENT-001 specifies. A preprocessor directive between the documentation comment and the comment does not change this. A comment before the documentation comment, a comment in front of a declaration without documentation, and a comment after the declaration's first token MUST NOT be reported.

Why: The documentation comment belongs directly to the declaration it documents. A comment between the two separates them and reads as part of the documentation.

Example:

```csharp
using System;

/// <summary>C</summary>
{|RH5034:/* note */|}
class C
{
    /// <summary>M</summary>
    {|RH5034:// note|}
    void M()
    {
    }

    /// <summary>N</summary>
    {|RH5034:// note|}
    [Obsolete]
    void N()
    {
    }

    /// <summary>O</summary>
#region Members
    {|RH5034:// note|}
    void O()
    {
    }
#endregion
}

enum E
{
    /// <summary>A</summary>
    {|RH5034:// note|}
    A,
}
```

```csharp
class C
{
    // note
    /// <summary>M</summary>
    void M()
    {
    }

    // note
    void N()
    {
    }

    /// <summary>O</summary>
    public
    // note
    void O()
    {
    }
}
```

is not reported.

### RH5034-002 — Only type, delegate, and member declarations are checked

The analyzer MUST check only the declaration of a type, a delegate, a member, or an enum member. It MUST NOT report a comment after a documentation comment in front of a namespace declaration, an accessor, a parameter, a local function, or a statement.

Why: Only these declarations carry documentation of their own. A documentation comment in front of a namespace, an accessor, a parameter, a local function, or a statement documents nothing, so a comment after it separates nothing.

Example:

```csharp
/// <summary>N</summary>
// note
namespace N
{
    class C
    {
        private int _value;

        /// <summary>V</summary>
        public int V
        {
            /// <summary>Gets</summary>
            // note
            get { return _value; }
        }

        void P(
            /// <summary>Item</summary>
            // note
            int item)
        {
        }

        void M()
        {
            /// <summary>L</summary>
            // note
            void L()
            {
            }

            /// <summary>Value</summary>
            // note
            var value = 1;

            L();
            _ = value;
        }
    }
}
```

is not reported.
