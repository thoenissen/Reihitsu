# Analyzer — RH5104 Comments must be on their own line

| | |
|---|---|
| ID prefix | RH5104 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5104CommentsMustBeOnTheirOwnLineAnalyzer`, `RH5104CommentsMustBeOnTheirOwnLineCodeFixProvider` |
| Uses | SHARED-COMMENT-002 |

RH5104 reports a comment that shares a line with code, and offers a code fix that moves the comment onto a line of its own above that line.

## Non-goals

- Where a comment on its own line is placed inside a declaration or a statement — the comment-placement rules (SHARED-COMMENT) and RH5048.
- Whether a comment on its own line is preceded by a blank line — RH5020.
- Code of other rules that the moved comment ends up next to, such as a comment above an `else` or above a closing brace.

## Requirements

### RH5104-001 — A comment that shares a line with code is reported

The analyzer MUST report a `//` comment that does not start with `///`, and a `/* */` comment that does not start with `/**`, when a token precedes it or follows it on one of the lines it spans and the comment is not in the trivia of a token of an interpolated string that spans several lines.

Why: A comment on the line of code competes with the code for the same space, and it is unclear whether it describes the code before it or after it. On its own line above the code, it reads as a description of what follows.

Example:

```csharp
class C
{
    int _a; {|RH5104:// first|}

    void N(int x)
    {
        var y = x {|RH5104:/* why */|} + 1;
        {|RH5104:/* lead */|} M();
        M(); {|RH5104:/* a
        b */|} M();
        var s = $"{x {|RH5104:/* hole */|}}";
    }

    void M()
    {
    }
}
```

### RH5104-002 — Comments on their own line, of directives, and in multi-line interpolations are not reported

The analyzer MUST NOT report a comment that has only whitespace around it on every line it spans, a comment that is part of a preprocessor directive line (SHARED-COMMENT-002), such as the comment behind `#endregion`, and a comment inside an interpolation of an interpolated string that spans several lines.

Why: A comment on its own line already is where this rule wants it. A comment behind a directive belongs to the directive, which cannot share a line with anything else. Inside a multi-line interpolated string, the line holds the string's text, and moving the comment out of the interpolation would move it into the string's lines.

Example:

```csharp
class C
{
    #region A
    int _a;
    #endregion // A

    void N(int x)
    {
        // own line
        M();
        /* own
           lines */
        M();
#if DEBUG // debug
        M();
#endif
        var t = $"""
            {x // value
            }
            """;
    }

    void M()
    {
    }
}
```

is not reported.

### RH5104-003 — The diagnostic is on the comment

The analyzer MUST report one diagnostic per comment, located on the comment.

Why: Each comment is moved on its own, and its location identifies it whatever else shares the line.

Example: see RH5104-001.

### RH5104-004 — The fix moves the comment above its line

When the line on which the comment starts does not start inside a literal or a comment, the code fix MUST remove the comment from its line together with the whitespace that separates it from the code, and insert it, unchanged, on a new line above that line, indented like that line. When the comment spans lines and holds the only line break between the code before and after it, the code after it MUST stay on a line of its own.

Why: Above the code it shares a line with is where a comment describing that code belongs, and the indentation of that line is the indentation of the code it describes. Keeping the line break the comment carried keeps the two statements around it apart.

Example:

```csharp
class C
{
    void N(int x)
    {
        var y = x {|RH5104:/* why */|} + 1;
    }

    void O()
    {
        M(); {|RH5104:/* a
        b */|} M();
    }

    void M()
    {
    }
}
```

```csharp
class C
{
    void N(int x)
    {
        /* why */
        var y = x + 1;
    }

    void O()
    {
        /* a
        b */
        M();
        M();
    }

    void M()
    {
    }
}
```

### RH5104-005 — The moved comment is preceded by a blank line after code

The code fix MUST insert a blank line above the moved comment when the line directly above it holds code. It MUST NOT insert one when that line is blank or starts with a `//` comment, when the comment's line is the first line after an opening brace or after a switch label, or when it follows a preprocessor directive.

Why: A comment on its own line starts a new thought and is separated from the code before it by a blank line (RH5020); a comment directly below another comment continues it, and the first line of a block or a switch section, and the line after a directive, need no separation.

Example:

```csharp
class C
{
    void N(int x)
    {
        M(); {|RH5104:// first|}
        M(); {|RH5104:// second|}
        // note
        M(); {|RH5104:// third|}
        switch (x)
        {
            case 1:
                M(); {|RH5104:// fourth|}
                break;
        }
    }

    void M()
    {
    }
}
```

```csharp
class C
{
    void N(int x)
    {
        // first
        M();

        // second
        M();
        // note
        // third
        M();
        switch (x)
        {
            case 1:
                // fourth
                M();
                break;
        }
    }

    void M()
    {
    }
}
```
