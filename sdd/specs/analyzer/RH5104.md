# Analyzer — RH5104 Comments must be on their own line

| | |
|---|---|
| ID prefix | RH5104 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5104CommentsMustBeOnTheirOwnLineAnalyzer`, `RH5104CommentsMustBeOnTheirOwnLineCodeFixProvider` |
| Uses | — |

RH5104 reports a comment that shares a line with code, and offers a code fix that moves the comment onto a line of its own above that line.

## Non-goals

- Where a comment on its own line is placed inside a declaration or a statement — the comment-placement rules (SHARED-COMMENT) and RH5048.
- Whether a comment on its own line is preceded by a blank line — RH5020.
- Code of other rules that the moved comment ends up next to, such as a comment above an `else` or above a closing brace.

## Requirements

### RH5104-001 — A comment that shares a line with code is reported

The analyzer MUST report a `//` comment or a `/* */` comment that is not a documentation comment when code precedes it or follows it on one of the lines it spans.

Why: A comment on the line of code competes with the code for the same space, and it is unclear whether it describes the code before it or after it. On its own line above the code, it reads as a description of what follows.

Example:

```csharp
class C
{
    int _a; {|RH5104:// first|}

    void N(int x)
    {
        var y = x {|RH5104:/* why */|} + 1;
        {|RH5104:/* lead */|} M();
        M(); {|RH5104:/* a
        b */|} M();
    }

    void M()
    {
    }
}
```

### RH5104-002 — Comments of directives, documentation, and multi-line interpolated strings are not reported

The analyzer MUST NOT report a comment on its own line, a documentation comment (`///` or `/** */`), a comment that is part of a preprocessor directive line, such as the comment behind `#endregion`, and a comment inside an interpolation of an interpolated string that spans several lines.

Why: A comment behind a directive belongs to the directive, which cannot share a line with anything else. A documentation comment belongs to the declaration it documents. Inside a multi-line interpolated string, the line holds the string's text, and moving the comment out of the interpolation would change the string.

Example:

```csharp
class C
{
    #region A
    int _a;
    #endregion // A

    /// <summary>N</summary>
    void N(int x)
    {
        // own line
        M();
#if DEBUG // debug
        M();
#endif
        var t = $"""
            {x // value
            }
            """;
    }

    void M() { } /// tail
}
```

is not reported.

### RH5104-003 — The diagnostic is on the comment

The analyzer MUST report one diagnostic per comment, located on the comment.

Why: Each comment is moved on its own, and its location identifies it whatever else shares the line.

Example: see RH5104-001.

### RH5104-004 — The fix moves the comment above its line

The code fix MUST remove the comment from its line together with the whitespace that separates it from the code, and insert it, unchanged, on a new line above the line on which it starts, indented like that line. When the comment spans lines and holds the only line break between the code before and after it, the code after it MUST stay on a line of its own.

Why: Above the code it shares a line with is where a comment describing that code belongs, and the indentation of that line is the indentation of the code it describes. Keeping the line break the comment carried keeps the two statements around it apart.

Example:

```csharp
class C
{
    void N(int x)
    {
        var y = x {|RH5104:/* why */|} + 1;
    }

    void O()
    {
        M(); {|RH5104:/* a
        b */|} M();
    }

    void M()
    {
    }
}
```

```csharp
class C
{
    void N(int x)
    {
        /* why */
        var y = x + 1;
    }

    void O()
    {
        /* a
        b */
        M();
        M();
    }

    void M()
    {
    }
}
```

### RH5104-005 — The moved comment is preceded by a blank line after code

The code fix MUST insert a blank line above the moved comment when the line directly above it holds code. It MUST NOT insert one when that line is blank or starts with a `//` comment, when the comment's line is the first line after an opening brace, or when it follows a preprocessor directive.

Why: A comment on its own line starts a new thought and is separated from the code before it by a blank line (RH5020); a comment directly below another comment continues it, and the first line of a block or the line after a directive needs no separation.

Example:

```csharp
class C
{
    void N()
    {
        M(); {|RH5104:// first|}
        M(); {|RH5104:// second|}
        // note
        M(); {|RH5104:// third|}
    }

    void M()
    {
    }
}
```

```csharp
class C
{
    void N()
    {
        // first
        M();

        // second
        M();
        // note
        // third
        M();
    }

    void M()
    {
    }
}
```
