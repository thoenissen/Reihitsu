# Analyzer — RH3104 Do not use default value type constructor

| | |
|---|---|
| ID prefix | RH3104 |
| Status | Active |
| Category | Clarity |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH3104DoNotUseDefaultValueTypeConstructorAnalyzer`, `RH3104DoNotUseDefaultValueTypeConstructorCodeFixProvider` |
| Uses | — |

RH3104 reports `new S()` and target-typed `new()` that create a value type with its default value, and offers a code fix that writes `default(S)`.

## Non-goals

- Creations of reference types.
- Which form of `default` the code uses — the fix always writes `default(S)`.

## Requirements

### RH3104-001 — A parameterless creation of a value type is reported

The analyzer MUST report an object creation `new S()` or a target-typed `new()` whose type is a value type — a struct, an enum, a nullable value type, or a predefined value type — when it has no arguments and no initializer, unless RH3104-002 applies.

Why: `new S()` looks like a constructor call, but for a value type without its own parameterless constructor it only produces the default value; `default(S)` says so.

Example:

```csharp
using System;

struct S
{
    public int X;
}

enum E
{
    A
}

class C
{
    void M()
    {
        var a = new {|RH3104:int|}();
        var b = new {|RH3104:Guid|}();
        S c = {|RH3104:new|}();
        var e = new {|RH3104:E|}();
        var f = new {|RH3104:int?|}();
        var g = new {|RH3104:System.DateTime|}();
    }
}
```

### RH3104-002 — A creation that runs code is not reported

The analyzer MUST NOT report a creation with arguments or an initializer, a creation of a struct that declares its own parameterless constructor, or a creation `new T()` of a type parameter.

Why: Each of these can run code that `default` does not: a constructor with arguments, the initializer, the declared parameterless constructor, or — for a type parameter — the parameterless constructor of whichever struct is substituted for it.

Example:

```csharp
using System;

struct S
{
    public S()
    {
        X = 1;
    }

    public int X;
}

struct P
{
    public int X;
}

class C
{
    T M<T>() where T : struct
    {
        var a = new DateTime(1);
        var b = new P { X = 1 };
        var c = new S();
        return new T();
    }
}
```

is not reported.

### RH3104-003 — The diagnostic is on the type or on `new`

The analyzer MUST report one diagnostic per creation: on the type of `new S()`, and on the `new` keyword of a target-typed `new()`.

Why: The type names the value whose default the creation produces; a target-typed creation has no type, and `new` is its first token.

Example: see RH3104-001.

### RH3104-004 — The fix writes `default` with the type

The code fix MUST replace the creation with `default(S)`, where `S` is the created type in its shortest form that binds in place, and keep the trivia in front of and after the creation.

Why: `default(S)` is the value the creation produced, so the program does not change. Naming the type keeps a target-typed creation readable on its own.

Example:

```csharp
using System;

struct S
{
    public int X;
}

class C
{
    void M()
    {
        var a = new {|RH3104:int|}();
        S c = {|RH3104:new|}();
        var g = new {|RH3104:System.DateTime|}();
        var f = new {|RH3104:int?|}();
    }
}
```

```csharp
using System;

struct S
{
    public int X;
}

class C
{
    void M()
    {
        var a = default(int);
        S c = default(S);
        var g = default(DateTime);
        var f = default(int?);
    }
}
```
