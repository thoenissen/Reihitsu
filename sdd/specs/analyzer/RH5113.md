# Analyzer — RH5113 Declaration semicolon must stay on the declaration line

| | |
|---|---|
| ID prefix | RH5113 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5113DeclarationSemicolonMustStayOnDeclarationLineAnalyzer`, `RH5113DeclarationSemicolonMustStayOnDeclarationLineCodeFixProvider` |
| Uses | FMT-BREAK-009, SHARED-JOIN-001 |

RH5113 reports the terminating semicolon of a member declaration that starts a line below the end of the declaration, and offers a code fix that lays the declaration out the way the formatter does.

## Non-goals

- The semicolon of an expression-bodied member, which terminates the expression body.
- The semicolon of a statement, such as a local declaration.

## Requirements

### RH5113-001 — A semicolon below its declaration is reported

The analyzer MUST report the terminating semicolon of a field, an event field, a delegate, and a property with an initializer when the semicolon starts on a later line than the token in front of it ends on, except where SHARED-JOIN-001 keeps the gap from being reported. The semicolon of an expression-bodied property MUST NOT be reported.

Why: A semicolon on a line of its own looks like an empty statement and splits a single declaration over lines for no reason (FMT-BREAK-009). The semicolon of an expression-bodied property ends the expression body, which may wrap onto its own line.

Example:

```csharp
using System;

class C
{
    int _a
        {|RH5113:;|}
    event Action E
        {|RH5113:;|}
    int P { get; set; } = 5
        {|RH5113:;|}
    int Q
        => 5
        ;
}

delegate void D()
    {|RH5113:;|}
```

### RH5113-002 — The diagnostic is on the semicolon

The analyzer MUST report one diagnostic per declaration, located on its terminating semicolon.

Why: The semicolon is the token that has to move.

Example: see RH5113-001.

### RH5113-003 — The fix lays out the declaration

The code fix MUST format the declaration that owns the semicolon as the formatter formats it in place, which moves the semicolon directly behind the end of the declaration (FMT-BREAK-009).

Why: The formatter owns the layout of a declaration; delegating to it applies that layout instead of a second one.

Example:

```csharp
using System;

class C
{
    int _a
        {|RH5113:;|}
    event Action E
        {|RH5113:;|}
    int P { get; set; } = 5
        {|RH5113:;|}
}

delegate void D()
    {|RH5113:;|}
```

```csharp
using System;

class C
{
    int _a;
    event Action E;
    int P { get; set; } = 5;
}

delegate void D();
```
