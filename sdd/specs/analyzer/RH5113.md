# Analyzer — RH5113 Declaration semicolon must stay on the declaration line

| | |
|---|---|
| ID prefix | RH5113 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5113DeclarationSemicolonMustStayOnDeclarationLineAnalyzer`, `RH5113DeclarationSemicolonMustStayOnDeclarationLineCodeFixProvider` |
| Uses | FMT-BREAK-009, SHARED-FIX-006, SHARED-JOIN-001 |

RH5113 reports the terminating semicolon of a member declaration that starts a line below the end of the declaration, and offers a code fix that moves the semicolon behind the declaration the way the formatter does.

## Non-goals

- The semicolon of an expression-bodied member, which terminates the expression body.
- The semicolon of a statement, such as a local declaration.

## Requirements

### RH5113-001 — A semicolon below its declaration is reported

The analyzer MUST report the terminating semicolon of a field, an event field, a delegate, and a property with an initializer when the semicolon starts on a later line than the token in front of it ends on, except where SHARED-JOIN-001 keeps the gap from being reported. The semicolon of an expression-bodied property MUST NOT be reported.

Why: A semicolon on a line of its own looks like an empty statement and splits a single declaration over lines for no reason (FMT-BREAK-009). The semicolon of an expression-bodied property ends the expression body, which may wrap onto its own line.

Example:

```csharp
using System;

class C
{
    int _a
        {|RH5113:;|}
    event Action E
        {|RH5113:;|}
    int P { get; set; } = 5
        {|RH5113:;|}
    int Q
        => 5
        ;
}

delegate void D()
    {|RH5113:;|}
```

### RH5113-002 — The diagnostic is on the semicolon

The analyzer MUST report one diagnostic per declaration, located on its terminating semicolon.

Why: The semicolon is the token that has to move.

Example: see RH5113-001.

### RH5113-003 — The fix lays out the declaration

The code fix MUST move the semicolon directly behind the end of the declaration that owns it, as the formatter moves it (FMT-BREAK-009). The declaration's code in front of the semicolon MUST stay as written (SHARED-FIX-006), also where formatting the document would change it, such as the spacing between the declaration's tokens.

Why: The formatter owns the place of a declaration's semicolon; following it applies that layout instead of a second one. The diagnostic is about the semicolon, so the code of the declaration is the author's layout, which the formatter and the layout rules correct on their own.

Example:

```csharp
using System;

class C
{
    int _a
        {|RH5113:;|}
    event Action E
        {|RH5113:;|}
    int P { get; set; } = 5
        {|RH5113:;|}
}

delegate void D()
    {|RH5113:;|}
```

```csharp
using System;

class C
{
    int _a;
    event Action E;
    int P { get; set; } = 5;
}

delegate void D();
```

Example — the documentation comment and the spacing of the declaration stay as written:

```csharp
class C
{
    /// <summary>A</summary>
    int  _a
        {|RH5113:;|}
}
```

```csharp
class C
{
    /// <summary>A</summary>
    int  _a;
}
```

Formatting the document would also spread the documentation comment over three lines and write `int _a;`.
