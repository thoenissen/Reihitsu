# Analyzer — RH5531 Accessor attribute lists must follow shape rules

| | |
|---|---|
| ID prefix | RH5531 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5531AccessorAttributeListsMustFollowShapeRulesAnalyzer`, `RH5531AccessorAttributeListsMustFollowShapeRulesCodeFixProvider` |
| Uses | SHARED-ATTR-001, SHARED-ATTR-002, SHARED-ATTR-006, SHARED-ATTR-013, SHARED-ATTR-014, SHARED-ATTR-015, SHARED-ATTR-016, SHARED-ATTR-017, SHARED-ATTR-018, SHARED-ATTR-019, SHARED-ATTR-020 |

RH5531 reports an attribute list of a `get`, `set`, `init`, `add`, or `remove` accessor that holds more than one attribute when the accessor list spans several lines, and a list that follows another list of the same accessor and target when the accessors of an auto-property stay on its line. Its code fix splits or merges the lists accordingly. The rule uses `shared/attribute-targets.md`.

## Non-goals

- The `return:` attributes of an accessor — RH5528.
- Attributes of the property, indexer, or event that owns the accessor — RH5516 and RH5520.
- Where an accessor attribute list is placed — RH5530.

## Requirements

### RH5531-001 — Accessor lists of a multi-line accessor list hold one attribute

The analyzer MUST check every attribute list attached to an accessor that resolves to the method target (SHARED-ATTR-001, SHARED-ATTR-002): the lists of a `get`, `set`, `init`, `add`, or `remove` accessor without a specifier, with `type:`, or with `method:`. When the property, indexer, or event that owns the accessor spans more than one line, apart from its own attribute lists, the analyzer MUST report such a list that holds more than one attribute, as SHARED-ATTR-013 specifies.

Why: In a multi-line accessor list every attribute already has room for a line of its own, so one attribute per list costs nothing and lets each be read, commented, or removed on its own.

Example:

```csharp
class C
{
    int P
    {
        {|RH5531:[A, B]|}
        get;
        {|RH5531:[method: A, B]|}
        set;
    }

    int this[int i]
    {
        {|RH5531:[A, B]|}
        get => i;
    }

    event System.Action E
    {
        {|RH5531:[A, B]|}
        add
        {
        }
        {|RH5531:[type: A, B]|}
        remove
        {
        }
    }

    int Q
    {
        [A] [B]
        get;
        set;
    }
}
```

### RH5531-002 — Accessor lists of an inline auto-property are merged

When SHARED-ATTR-006 exempts the accessor's lists from the separate-line placement, the analyzer MUST report a list that follows another list of the same accessor naming the same target, as SHARED-ATTR-015 specifies, and MUST NOT report a list that holds more than one attribute (SHARED-ATTR-014).

Why: The accessor list of an inline auto-property stays on the property's line, so there is no line to gain per attribute; separate lists only repeat the brackets on an already crowded line.

Example:

```csharp
class C
{
    int P { [A] {|RH5531:[B]|} get; set; }

    int Q { [A] {|RH5531:[method: B]|} get; set; }

    [D]
    int R { [A] {|RH5531:[B]|} get; set; } = 1;

    int S { [A, B] get; set; }

    int T { [A] [type: B] get; set; }
}
```

### RH5531-003 — Method attributes of other declarations are not checked

The analyzer MUST NOT report an attribute list that resolves to the method target but is not attached to an accessor.

Why: Methods, operators, local functions, and lambdas have no accessor list around them; RH5514 checks their lists.

Example:

```csharp
class C
{
    [A, B]
    void M()
    {
    }
}
```

is not reported by RH5531; RH5514 reports it.

### RH5531-004 — The diagnostic is on the attribute list

The analyzer MUST report the diagnostic on the attribute list, as SHARED-ATTR-016 specifies.

Why: The list is what has the wrong shape; each list of an accessor is reported on its own.

Example: see RH5531-001 and RH5531-002.

### RH5531-005 — The fix splits or merges the lists

For a list RH5531-001 reports, the code fix MUST replace the list with one list per attribute, each on its own line, as SHARED-ATTR-017 specifies. For a list RH5531-002 reports, it MUST merge every list of that target on the accessor into the first of them, as SHARED-ATTR-018 specifies.

Why: The fix makes only the change the diagnostic asks for, in the direction the accessor list's layout requires.

Example:

```csharp
class C
{
    int P
    {
        {|RH5531:[A, B]|}
        get;
        set;
    }

    int Q { [A] {|RH5531:[B]|} get; set; }
}
```

```csharp
class C
{
    int P
    {
        [A]
        [B]
        get;
        set;
    }

    int Q { [A, B] get; set; }
}
```

### RH5531-006 — The fix is withheld for comments and directives

The code fix MUST NOT be offered when SHARED-ATTR-019 withholds the split or SHARED-ATTR-020 withholds the merge. The diagnostic is still reported.

Why: A comment inside or between the lists belongs to the attribute next to it, and only the author can tell where it goes once the lists are split or merged.

Example:

```csharp
class C
{
    int P
    {
        {|RH5531:[A, /* c */ B]|}
        get;
        set;
    }

    int Q { [A] /* c */ {|RH5531:[B]|} get; set; }
}
```

is reported, and no code fix is offered.
