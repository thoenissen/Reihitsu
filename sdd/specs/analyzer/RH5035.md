# Analyzer — RH5035 Comments must not be placed inside a parameter list

| | |
|---|---|
| ID prefix | RH5035 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH5035CommentsMustNotBePlacedInsideParameterListAnalyzer` |
| Uses | SHARED-COMMENT-001, SHARED-COMMENT-002, SHARED-COMMENT-003, SHARED-COMMENT-004, SHARED-COMMENT-005, SHARED-COMMENT-006, SHARED-COMMENT-008, SHARED-COMMENT-009 |

RH5035 reports a comment placed inside a parameter list, or between a declaration's name and its parameter list.

## Non-goals

- A comment inside a type parameter list — RH5046.
- How a parameter list is laid out — the line-break rules.

## Requirements

### RH5035-001 — A comment inside a parameter list is reported

The analyzer MUST report every ordinary comment (SHARED-COMMENT-001, SHARED-COMMENT-002) inside a parameter list, as SHARED-COMMENT-003, SHARED-COMMENT-004, SHARED-COMMENT-005, SHARED-COMMENT-006, SHARED-COMMENT-008, and SHARED-COMMENT-009 specify for a region. The regions are the parameter list from `(` to `)` of a method, a constructor, a finalizer, an operator, a conversion operator, a delegate, a local function, a lambda, an anonymous method, the primary constructor of a class, struct, or record, and an extension block; the parameter list from `[` to `]` of an indexer; and the parameter list from `<` to `>` of a function pointer type.

Why: A comment inside a parameter list leaves it unclear which parameter it describes, and it splits the list across lines. A parameter is described in the documentation comment of its declaration.

Example:

```csharp
using System;

class C(
    {|RH5035:// the value|}
    int value)
{
    public int Value => value;

    void M(int first {|RH5035:/* first */|}, int second = 1 |
                                                     {|RH5035:// flag|}
                                                     2)
    {
        Func<int, int> function = (
            {|RH5035:// the value|}
            int item) => item;
        _ = function;
    }

    void N(int flags = 1
                       // flag
                       | 2)
    {
    }

    int this[
        {|RH5035:// the index|}
        int index] => index;

    ~C(
        {|RH5035:// none|}
        )
    {
    }
}

unsafe class D
{
    delegate*<{|RH5035:/* value */|} int, void> _callback;
}
```

### RH5035-002 — A comment between a declaration and its parameter list is reported

The analyzer MUST also report a comment directly before the opening token of a parameter list when the token before the comment belongs to the same declaration or lambda, such as a comment between a method's name and `(`, between `this` and the `[` of an indexer, or between `static` and the `(` of a lambda. It MUST NOT report a comment directly before a parameter list that starts its lambda, nor a comment after the closing token of a parameter list.

Why: The name and the parameter list of a declaration form its signature; a comment between them splits it. A lambda that starts with its parameter list has nothing in front of it that the comment could separate it from.

Example:

```csharp
using System;

class C
{
    void M
        {|RH5035:// parameters|}
        (int value)
    {
        Func<int, int> function = static
            {|RH5035:// the value|}
            (item) => item;
        _ = function;
    }

    int this
        {|RH5035:// the index|}
        [int index] => index;
}
```

```csharp
using System;

class C
{
    int Run(params object[] values) => 0;

    void M(int value)
        // body
    {
        Run(
            // the projection
            (int item) => item);
    }
}
```

is not reported.
