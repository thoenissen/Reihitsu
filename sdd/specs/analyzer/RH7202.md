# Analyzer — RH7202 Using alias directives must be placed after other using directives

| | |
|---|---|
| ID prefix | RH7202 |
| Status | Active |
| Category | Organization |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH7202UsingAliasDirectivesMustBePlacedAfterOtherUsingDirectivesAnalyzer`, `RH7202UsingAliasDirectivesMustBePlacedAfterOtherUsingDirectivesCodeFixProvider` |
| Uses | SHARED-USING-001, SHARED-USING-002, SHARED-USING-003, SHARED-USING-009, FMT-USING-001, FMT-USING-002, FMT-USING-003, FMT-USING-005, FMT-USING-006, FMT-USING-007, FMT-USING-008, FMT-USING-009 |

RH7202 reports an alias directive that precedes a regular namespace directive, and offers a code fix that organizes the whole using block.

## Non-goals

- The order of the aliases among each other — RH7204.
- The canonical order and grouping of using directives — SHARED-USING — and how the formatter lays out a reordered block — FMT-USING.

## Requirements

### RH7202-001 — An alias directive before a regular directive is reported

The analyzer MUST report every alias directive that precedes a regular namespace directive in the same block (SHARED-USING-001) and the same section, global or not (SHARED-USING-002), when SHARED-USING-009 allows the block to be reordered.

Why: Aliases are special-case imports that rename a namespace or a type; keeping them after the ordinary imports (SHARED-USING-003) makes the file header read from the general to the specific. Every alias above a regular directive is out of place, so each is reported.

Example:

```csharp
using {|RH7202:A|} = System.Text;
using {|RH7202:B|} = System.IO;
using System;

class C
{
}
```

while an alias of the global section is not compared with a local directive:

```csharp
global using A = System.Text;
using System;

class C
{
}
```

and a block with a preprocessor directive is not reported (SHARED-USING-009):

```csharp
using A = System.Text;
#if DEBUG
using System.Diagnostics;
#endif
using System;

class C
{
}
```

### RH7202-002 — An alias followed only by static or alias directives is not reported

The analyzer MUST NOT report an alias directive that is followed in its section only by `using static` and alias directives.

Why: Whether a `using static` directive belongs after an alias is RH7205's decision, so RH7202 looks only at the regular directives below an alias.

Example:

```csharp
using System;
using A = System.Text;
using static System.Math;

class C
{
}
```

is not reported.

### RH7202-003 — The diagnostic is on the alias name

The analyzer MUST report one diagnostic per reported directive, located on its alias identifier.

Why: The alias is the name the directive introduces and the one a reader looks for.

Example: see RH7202-001.

### RH7202-004 — The fix organizes the whole block

The code fix MUST rewrite the whole using block that contains the reported directive as the formatter's using-directive phase does: into the canonical order (FMT-USING-001), with exactly one blank line between two groups and none inside a group (FMT-USING-002), with one directive per line (FMT-USING-003), and with comments placed as FMT-USING-005, FMT-USING-006, FMT-USING-007, FMT-USING-008, and FMT-USING-009 specify. It MUST NOT change anything outside the block.

Why: A block has one organized form, shared by the formatter and the seven using-ordering rules RH7201–RH7207. Producing it in one step corrects every diagnostic those rules report in the block at once, so their fixes never undo each other. The code after the block is not the finding.

Example:

```csharp
using {|RH7202:A|} = System.Text;
using System;

class C
{
}
```

```csharp
using System;

using A = System.Text;

class C
{
}
```
