# Analyzer — RH5528 Return value attribute lists must use one attribute per list

| | |
|---|---|
| ID prefix | RH5528 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5528ReturnValueAttributeListsMustFollowShapeRulesAnalyzer`, `RH5528ReturnValueAttributeListsMustFollowShapeRulesCodeFixProvider` |
| Uses | SHARED-ATTR-002, SHARED-ATTR-013, SHARED-ATTR-014, SHARED-ATTR-016, SHARED-ATTR-017, SHARED-ATTR-019 |

RH5528 reports a `return:` attribute list that holds more than one attribute, and offers a code fix that gives each attribute a list of its own. The rule uses `shared/attribute-targets.md`.

## Non-goals

- Attribute lists of a method without the `return:` specifier — RH5514.
- Where a return-value attribute list is placed — RH5527.

## Requirements

### RH5528-001 — Return-value attribute lists hold one attribute

The analyzer MUST check every attribute list with the `return:` specifier that is not attached to a parameter or type parameter (SHARED-ATTR-002): on a method, operator, conversion operator, local function, lambda, delegate, or accessor, and MUST report such a list that holds more than one attribute, as SHARED-ATTR-013 and SHARED-ATTR-014 specify.

Why: `[return: A, B]` reads as one annotation with two parts rather than as two independent statements about the result; split, either attribute can be removed without rewriting the other.

Example:

```csharp
class C
{
    {|RH5528:[return: A, B]|}
    int M() => 0;

    int P { [return: A, B] get; set; }

    int Q
    {
        {|RH5528:[return: A, B]|}
        get;
        set;
    }

    void N()
    {
        System.Func<int> f = {|RH5528:[return: A, B]|} () => 0;
    }
}

{|RH5528:[return: A, B]|}
delegate int D();
```

### RH5528-002 — The diagnostic is on the attribute list

The analyzer MUST report the diagnostic on the attribute list, as SHARED-ATTR-016 specifies.

Why: The list is what has the wrong shape; each list of a declaration is reported and fixed on its own.

Example: see RH5528-001.

### RH5528-003 — The fix gives each attribute a list of its own

The code fix MUST replace the list with one list per attribute, each on its own line, as SHARED-ATTR-017 specifies.

Why: The fix makes only the change the diagnostic asks for: the attributes keep their order and their specifier, and each gets a line of its own.

Example:

```csharp
class C
{
    {|RH5528:[return: A, B]|}
    int M() => 0;
}
```

```csharp
class C
{
    [return: A]
    [return: B]
    int M() => 0;
}
```

### RH5528-004 — The fix is withheld for a comment or directive inside the list

The code fix MUST NOT be offered when SHARED-ATTR-019 withholds it. The diagnostic is still reported.

Why: A comment inside the list belongs to the attribute next to it, and only the author can tell which of the new lists it belongs to.

Example:

```csharp
class C
{
    {|RH5528:[return: A, /* c */ B]|}
    int M() => 0;
}
```

is reported, and no code fix is offered.
