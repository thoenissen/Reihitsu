# Analyzer — RH8105 Element return value must be documented

| | |
|---|---|
| ID prefix | RH8105 |
| Status | Active |
| Category | Documentation |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH8105ElementReturnValueMustBeDocumentedAnalyzer` |
| Uses | SHARED-DOC-004, SHARED-DOC-008, SHARED-DOC-009 |

RH8105 reports a documented method, delegate, operator, or conversion operator that returns a value but has no `<returns>` documentation.

## Non-goals

- Whether the declaration has a summary — RH8001 to RH8029 and RH8034.
- Whether the `<returns>` element has text — RH8106; a `<returns>` element on a member that returns `void` — RH8107.
- Properties and indexers, whose value is described by their summary.

## Requirements

### RH8105-001 — A missing return value description is reported

The analyzer MUST report a method, delegate, operator, or conversion operator declaration whose return type is not the `void` keyword when the declaration has a documentation comment, as SHARED-DOC-004 defines it, and its documentation has neither a `<returns>` nor an `<inheritdoc>` element at its top level. Either element MUST count whether it is in the first documentation comment, in a later one, or in the content that an `<include>` element brings in, and a `<returns>` element MUST count whether or not it has text. A `<returns>` element nested inside another element MUST NOT count. Every return type other than `void` MUST count as a value, `Task`, `ValueTask`, a `ref` return, and a type parameter included. A method declaration includes the methods of an interface and of an extension block; local functions, lambdas, and anonymous methods are not checked.

The analyzer MUST NOT report a declaration without a documentation comment, or a declaration that explicitly implements an interface member, which SHARED-DOC-009 exempts. The declaration's accessibility does not matter, and nothing is reported when SHARED-DOC-008 applies.

This requirement covers documentation comments placed as SHARED-DOC-004 covers that are well-formed XML, with the tag names `returns` and `inheritdoc` written in lower case, without a namespace prefix, and in no XML namespace; an included file is covered when it is well-formed XML and writes the tag names the same way. A part of a partial method declared in several parts is not covered.

Why: The return value is what the caller works with, and without a `<returns>` element the tooltip and the generated documentation say nothing about it. A `Task` is a value the caller receives and awaits, so it is described like any other. `<inheritdoc>` takes the description from the member it inherits from. A declaration without any documentation comment is left to the rules that require a summary, and an explicit implementation is described by the interface member it implements.

Example:

```csharp
using System.Threading.Tasks;

/// <summary>
/// Factory
/// </summary>
public delegate {|RH8105:int|} Factory();

/// <summary>
/// Contract
/// </summary>
public interface I
{
    /// <summary>
    /// Gets
    /// </summary>
    /// <returns>Value</returns>
    int Get();
}

/// <summary>
/// Service
/// </summary>
public class C : I
{
    private int _field;

    /// <summary>
    /// Counts
    /// </summary>
    private {|RH8105:int|} Count() => 0;

    /// <summary>
    /// Loads
    /// </summary>
    public async {|RH8105:Task|} LoadAsync() => await Task.CompletedTask;

    /// <summary>
    /// Refers
    /// </summary>
    public {|RH8105:ref int|} Refer() => ref _field;

    /// <summary>
    /// Finds
    /// </summary>
    /// <remarks>
    /// <returns>Nested</returns>
    /// </remarks>
    public {|RH8105:int|} Find() => 0;

    /// <summary>
    /// Measures
    /// </summary>
    /// <returns/>
    public int Measure() => 0;

    /// <summary>
    /// Sizes
    /// </summary>

    /// <returns>Size</returns>
    public int Size() => 0;

    /// <inheritdoc/>
    public int Get() => 0;

    /// <summary>
    /// Gets
    /// </summary>
    int I.Get() => 0;

    public int Undocumented() => 0;

    /// <summary>
    /// Runs
    /// </summary>
    public void Run()
    {
    }

    /// <summary>
    /// Adds
    /// </summary>
    /// <param name="left">Left</param>
    /// <param name="right">Right</param>
    public static {|RH8105:C|} operator +(C left, C right) => left;

    /// <summary>
    /// Converts
    /// </summary>
    /// <param name="value">Value</param>
    public static implicit operator {|RH8105:int|}(C value) => 0;
}
```

Example — with a file `docs.xml` next to the source:

```xml
<doc>
    <members>
        <member name="A">
            <summary>Value</summary>
            <returns>Value</returns>
        </member>
        <member name="B">
            <summary>Value</summary>
        </member>
    </members>
</doc>
```

```csharp
/// <summary>
/// Service
/// </summary>
public class C
{
    /// <include file='docs.xml' path='doc/members/member[@name="A"]/*'/>
    public int A() => 0;

    /// <include file='docs.xml' path='doc/members/member[@name="B"]/*'/>
    public {|RH8105:int|} B() => 0;
}
```

### RH8105-002 — The diagnostic is on the return type

The analyzer MUST report one diagnostic per declaration, located on the return type as written — with `ref` or `ref readonly` when the member returns by reference — and, for a conversion operator, on the type it converts to.

Why: The return type is what the missing description is about, and it stays in place when the member's body or parameters change.

Example: see RH8105-001.
