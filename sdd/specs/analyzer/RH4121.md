# Analyzer — RH4121 Type parameter names

| | |
|---|---|
| ID prefix | RH4121 |
| Status | Active |
| Category | Naming |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH4121TypeParameterNameCasingAnalyzer`, `RH4121TypeParameterNameCasingCodeFixProvider` |
| Uses | SHARED-CASING-001, SHARED-CASING-006, SHARED-CASING-007, SHARED-CASING-009, SHARED-CASING-010 |

RH4121 reports a type parameter whose name is not an uppercase `T`, optionally followed by a PascalCase name or by digits, and offers a code fix that adds or corrects the `T` prefix and renames every reference.

## Non-goals

- Whether a declaration with one type parameter should name it `T` rather than a descriptive name.
- The casing of every other kind of name — the other RH40xx and RH41xx rules.

## Requirements

### RH4121-001 — Type parameters of every generic declaration are checked

The analyzer MUST check every type parameter of a class, struct, interface, record, delegate, method, or local function, and MUST report one diagnostic per declared type parameter whose name is not in the style of RH4121-002, located on its identifier. Each part of a partial type or partial method declares its type parameters, so each part gets its own diagnostic.

Why: A type parameter is used like a type in the declaration's body; wherever it is declared, a reader has to be able to tell it from a real type at the point of use.

Example:

```csharp
public class C<{|RH4121:Key|}>
{
    public void M<{|RH4121:item|}>()
    {
        void Local<{|RH4121:arg|}>()
        {
        }
    }
}

public struct S<{|RH4121:value|}>
{
}

public interface I<{|RH4121:element|}>
{
}

public record R<{|RH4121:entity|}>;

public delegate void D<{|RH4121:result|}>();
```

Example — a partial type, reported on each part:

```csharp
public partial class P<{|RH4121:key|}>
{
}

public partial class P<{|RH4121:key|}>
{
}
```

### RH4121-002 — A type parameter name is `T`, `T` and a PascalCase name, or `T` and digits

A type parameter name MUST be accepted exactly when it is an uppercase `T` alone, an uppercase `T` followed by a name that is in PascalCase as SHARED-CASING-001 defines it, or an uppercase `T` followed by decimal digits only.

Why: The `T` prefix is the .NET convention (`TKey`, `TValue`, `TResult`) and makes a name read as a type parameter, not as a type. Digits after the prefix (`T1`, `T2`) follow the convention of `Func` and `Tuple`.

Example:

```csharp
public class C<T, TKey, TKEY, T1, T23, {|RH4121:Key|}, {|RH4121:tKey|}, {|RH4121:t1|}, {|RH4121:Type|}, {|RH4121:T1Key|}>
{
}
```

### RH4121-003 — The fix adds or corrects the `T` prefix

The code fix MUST rename the type parameter and every reference to it (SHARED-CASING-007) to a name derived from the old name as follows:

- The old name `t` becomes `T`.
- When the old name starts with `t` or `T` followed by an uppercase letter or a decimal digit, that first character is the prefix: it becomes `T`, and the rest of the name is the body.
- Otherwise the whole old name is the body, and `T` is put in front of it.
- The body is kept when it is in PascalCase as SHARED-CASING-001 defines it or consists of decimal digits only; otherwise it is replaced by the PascalCase name that SHARED-CASING-006 derives from it.

The fix is withheld as SHARED-CASING-009 specifies, and its Fix All skips colliding names as SHARED-CASING-010 specifies. This requirement covers an old name that does not start with `t` or `T` followed by `_`, and whose body, when it is replaced, is a name that SHARED-CASING-006 covers.

Why: A leading `t` or `T` before an uppercase letter or a digit is an attempt at the prefix, so only its case is corrected; any other name gets the prefix in front of its words, as in `Type`, which becomes `TType`. The body follows the same derivation as every PascalCase fix.

Example:

```csharp
public class C<{|RH4121:Key|}, {|RH4121:tValue|}, {|RH4121:t1|}, {|RH4121:item_type|}, {|RH4121:Type|}>
{
    public Key M(tValue value, t1 index, item_type item, Type type) => default;
}

public class D<{|RH4121:t|}>
{
}
```

```csharp
public class C<TKey, TValue, T1, TItemType, TType>
{
    public TKey M(TValue value, T1 index, TItemType item, TType type) => default;
}

public class D<T>
{
}
```

### RH4121-004 — The fix is withheld when no usable name can be derived

The code fix MUST NOT be offered when the old name has no letter or digit, such as `_`, or when the body that RH4121-003 derives is neither in PascalCase nor digits only, such as the `1Key` of `T1Key`. The diagnostic is still reported.

Why: Such a body cannot be turned into a valid type parameter name, so no rename would satisfy the rule.

Example:

```csharp
public class C<{|RH4121:_|}, {|RH4121:T1Key|}>
{
}
```

is reported, and no code fix is offered for either type parameter.
