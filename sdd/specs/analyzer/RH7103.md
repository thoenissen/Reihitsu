# Analyzer — RH7103 Static elements must appear before instance elements

| | |
|---|---|
| ID prefix | RH7103 |
| Status | Active |
| Category | Organization |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH7103StaticElementsMustAppearBeforeInstanceElementsAnalyzer`, `RH7103StaticElementsMustAppearBeforeInstanceElementsCodeFixProvider` |
| Uses | SHARED-ORDER-001, SHARED-ORDER-002, SHARED-ORDER-003, SHARED-ORDER-004, SHARED-ORDER-005, SHARED-ORDER-006, SHARED-ORDER-007 |

RH7103 reports a static member that follows an instance member of the same kind and accessibility, and offers a code fix that moves it in front of the first such instance member.

## Non-goals

- The order of `const` fields relative to other fields — RH7102.
- The order of readonly and non-readonly members — RH7109 — and of accessibility levels — RH7110.
- Ordering across the parts of a `partial` type. Each declaration is checked on its own.
- The layout of the fixed type. The fix lays the type out with the formatter (FMT-PIPE); the examples below are already in canonical layout.
- Members without an accessibility modifier. They currently form a group of their own, so `int _a;` is not compared with `private static int _b;` and a static constructor is never compared with an instance constructor that has a modifier; whether that is intended is an open question.
- How much of the type the fix reformats. It currently formats the whole containing type, including structural rewrites of members the diagnostic is not about; whether it should be limited to the moved member is an open question.

## Requirements

### RH7103-001 — A static member after a matching instance member is reported

The analyzer MUST report every static member of a class, struct, interface, record, or record struct declaration that follows, in the same declaration, an instance member of the same group. A group is the combination of member kind (RH7103-002), accessibility (RH7103-003), and containing top-level region (RH7103-004).

Why: Readers expect the static surface of a type — factories, shared state — before the per-instance behavior. Comparing only within one group keeps the rule from fighting the kind and accessibility order other rules impose.

Example:

```csharp
public class C
{
    public void Run()
    {
    }

    public static void {|RH7103:Create|}()
    {
    }
}
```

### RH7103-002 — Only members of the same kind are compared

The analyzer MUST compare a static member only with instance members of the same kind: nested type, delegate, field, constructor, destructor, property, indexer, event, event field, method, operator, or conversion operator. A member is static when it carries the `static` modifier; operators and conversion operators are always static. `const` fields are neither static nor instance members for this rule and are skipped.

Why: The kind order of a type is a separate decision. A static field after an instance method is in the field group, not misplaced inside the method group.

Example:

```csharp
public class C
{
    public void Run()
    {
    }

    public static int Count;

    private static void Helper()
    {
    }

    public static void {|RH7103:Create|}()
    {
    }
}
```

Only `Create` is reported: `Count` is a field and `Helper` is private, so neither matches `Run`.

A nested `static` type and a `static abstract` interface member count as static:

```csharp
public interface I
{
    void Run();

    static abstract void {|RH7103:M|}();
}
```

### RH7103-003 — Only members of the same written accessibility are compared

The analyzer MUST compare a static member only with instance members whose accessibility modifiers form the same group: `public`, `protected internal`, `private protected`, `internal`, `protected`, `private`, or `file`, with `protected internal` and `private protected` each one group regardless of modifier order.

Why: Accessibility order is RH7110's decision, so a private static helper after a public instance method is not an RH7103 violation.

Example:

```csharp
public class C
{
    public void Run()
    {
    }

    private static void Helper()
    {
    }
}
```

is not reported.

### RH7103-004 — Each top-level region is checked on its own

The analyzer MUST compare a static member only with instance members in the same top-level `#region` of the type, or with instance members outside every region when the static member is outside every region too. A member in a nested region belongs to the top-level region around it. Regions of nested types are not considered. This is the region scope of SHARED-ORDER-004.

Why: A type organized as `#region Lifecycle` and `#region Factories` has chosen its order by region; comparing across them would ask for a static factory to leave its region.

Example:

```csharp
public class C
{
    #region Lifecycle

    public void Run()
    {
    }

    #endregion

    #region Factories

    public static C Create()
    {
        return new C();
    }

    #endregion
}
```

is not reported, and neither is the same pair with one of the members outside any region.

```csharp
public class C
{
    #region Members

    public void Run()
    {
    }

    #region Inner

    public static void {|RH7103:Create|}()
    {
    }

    #endregion

    #endregion
}
```

### RH7103-005 — The diagnostic is on the member's name

The analyzer MUST report one diagnostic per misplaced static member, located on its identifier — for a field or event field the first declarator's identifier, for an indexer the `this` keyword, for an operator the operator token, and for a conversion operator the `operator` keyword.

Why: The name is what a reader scans for, and one diagnostic per member keeps Fix All one action per member.

Example:

```csharp
public record struct R(int X)
{
    public int Y => 1;

    public static int {|RH7103:Z|} => 2;
}
```

### RH7103-006 — The fix moves the member in front of the first matching instance member

The code fix MUST move the reported member in front of the first earlier instance member of the same group (RH7103-001), and MUST perform the move as specified in SHARED-ORDER-001 and SHARED-ORDER-002.

Why: The first matching instance member is the earliest position at which the static member satisfies the rule, so one move corrects the diagnostic without moving any other member.

Example:

```csharp
public class C
{
    public void A()
    {
    }

    public void B()
    {
    }

    public static void {|RH7103:Create|}()
    {
    }
}
```

```csharp
public class C
{
    public static void Create()
    {
    }

    public void A()
    {
    }

    public void B()
    {
    }
}
```

### RH7103-007 — The fix is withheld when the move is unsafe

The code fix MUST NOT be offered when the move is refused by SHARED-ORDER-003, SHARED-ORDER-004, SHARED-ORDER-005, or SHARED-ORDER-007. The diagnostic is still reported. A balanced directive pair alone does not withhold it (SHARED-ORDER-006).

Why: These moves would change which code a directive governs or the order in which initializers run. A reported diagnostic without a fix is a supported end state; the user decides where the directive or initializer belongs.

Example:

```csharp
public class C
{
    private int _instance;
    public static int A = 1;
    private static int {|RH7103:_b|} = A;
}
```

is reported, and no code fix is offered: moving `_b` in front of `_instance` would cross the initializer of `A`. `A` itself is not reported, because no public instance member precedes it.

### RH7103-008 — Fix All keeps the written order of the moved members

The code fix MUST provide a batch Fix All. When it corrects several static members of one group, they MUST end up in the order the author wrote them, with every separator in its original position (SHARED-ORDER-002).

Why: Each move goes in front of the first matching instance member, so applying the moves one after another keeps the static members in their written order instead of depending on the order the fixes are applied in.

Example:

```csharp
public class C
{
    public void Run()
    {
    }

    public static void {|RH7103:CreateA|}()
    {
    }

    public static void {|RH7103:CreateB|}()
    {
    }
}
```

```csharp
public class C
{
    public static void CreateA()
    {
    }

    public static void CreateB()
    {
    }

    public void Run()
    {
    }
}
```
