# Analyzer — RH7311 Region descriptions must be unique within a type

| | |
|---|---|
| ID prefix | RH7311 |
| Status | Active |
| Category | Organization |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH7311RegionDescriptionsMustBeUniqueWithinATypeAnalyzer` |
| Uses | SHARED-REGDESC-001 |

RH7311 reports a top-level region of a type whose description repeats the description of an earlier top-level region of the same type declaration. It has no code fix: merging the blocks moves members, and renaming one invents a label.

## Non-goals

- Regions inside element bodies — RH7303.
- Whether the `#endregion` repeats the description — RH7301.

## Requirements

### RH7311-001 — A repeated description is reported

For every class, struct, interface, record, and record struct declaration, the analyzer MUST report each top-level region whose description (SHARED-REGDESC-001) equals, ignoring case, the description of an earlier top-level region of the same declaration. Regions without a description MUST NOT be compared.

Why: Two regions with one label make the editor's outline ambiguous, and they usually mean that members that belong together were split across two blocks. A region without a description has no label to confuse.

Example:

```csharp
class C
{
    #region Methods

    void A()
    {
    }

    #endregion

    {|RH7311:#region  methods|}

    void B()
    {
    }

    #endregion

    {|RH7311:#region Methods|}

    void D()
    {
    }

    #endregion

    #region

    int _a;

    #endregion

    #region

    int _b;

    #endregion
}
```

### RH7311-002 — Only the top-level regions of one declaration are compared

The analyzer MUST NOT report a region whose description repeats that of a region nested in another region, of a region in a nested type, or of a region in another declaration of a `partial` type.

Why: A nested region is a sub-heading inside its outer region, and a nested type or another partial declaration has its own outline; a repeated name there is not ambiguous within one list.

Example:

```csharp
class C
{
    #region Methods

    #region Methods

    void M()
    {
    }

    #endregion

    #endregion

    class D
    {
        #region Methods

        void N()
        {
        }

        #endregion
    }
}

partial class P
{
    #region Methods

    void A()
    {
    }

    #endregion
}

partial class P
{
    #region Methods

    void B()
    {
    }

    #endregion
}
```

is not reported.

### RH7311-003 — The diagnostic is on the later `#region`

The analyzer MUST report one diagnostic per repeating region, located on its `#region` directive from the `#` to the end of its line. The first region with a description stays unreported.

Why: The first occurrence is the canonical block; each later one is the block to merge or rename.

Example: see RH7311-001.
