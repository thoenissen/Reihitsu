# Analyzer — RH7311 Region descriptions must be unique within a type

| | |
|---|---|
| ID prefix | RH7311 |
| Status | Active |
| Category | Organization |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH7311RegionDescriptionsMustBeUniqueWithinATypeAnalyzer` |
| Uses | SHARED-DIAG-008, SHARED-REGDESC-001, SHARED-TYPEREGION-006 |

RH7311 reports a top-level region of a type whose description repeats the description of an earlier top-level region of the same type declaration. It has no code fix: merging the blocks moves members, and renaming one invents a label.

## Non-goals

- Regions inside element bodies — RH7303.
- Whether the `#endregion` repeats the description — RH7301.

## Requirements

### RH7311-001 — A repeated description is reported

For every class, struct, interface, record, record struct, and union declaration, the analyzer MUST report each top-level region (SHARED-TYPEREGION-006) that the analyzed build compiles and whose description (SHARED-REGDESC-001) equals, ignoring case, the description of an earlier top-level region of the same declaration that the analyzed build compiles. The analyzer judges the outline of the analyzed build (SHARED-DIAG-008): a region in the branch of a conditional directive — the code between an `#if`, `#elif`, or `#else` and the directive that ends that branch — that the build compiles MUST be compared like a region outside every branch. A region in a branch that the build excludes MUST NOT be compared with any other region, so two regions in different branches of one conditional directive are never compared with each other (SHARED-TYPEREGION-006). Regions without a description MUST NOT be compared.

Why: Two regions with one label make the editor's outline ambiguous, and they usually mean that members that belong together were split across two blocks. A region without a description has no label to confuse. The outline is the one the analyzed build compiles; another build's outline is judged when that build is analyzed. No build compiles two branches of one conditional directive, so their regions never stand in one outline.

Example:

```csharp
class C
{
    #region Methods

    void A()
    {
    }

    #endregion

    {|RH7311:#region  methods|}

    void B()
    {
    }

    #endregion

    {|RH7311:#region Methods|}

    void D()
    {
    }

    #endregion

    #region

    int _a;

    #endregion

    #region

    int _b;

    #endregion
}
```

Example — the regions of an `#if` and an `#else` branch are not compared with each other, and the region of the branch the build compiles is compared with the region outside every branch. In a build that does not define `DEBUG`,

```csharp
class C
{
#if DEBUG
    #region Fields

    int _a;

    #endregion
#else
    #region Fields

    int _b;

    #endregion
#endif

    {|RH7311:#region Fields|}

    int _c;

    #endregion
}
```

reports the last region, which repeats the description of the region in the `#else` branch.

Example — a conditional directive encloses the whole declaration, which the build compiles, so its regions are compared:

```csharp
#if !NEVER
class C
{
    #region Methods

    void A()
    {
    }

    #endregion

    {|RH7311:#region Methods|}

    void B()
    {
    }

    #endregion
}
#endif
```

Example — a union:

```csharp
union U(int, string)
{
    #region Methods

    int A() => 1;

    #endregion

    {|RH7311:#region Methods|}

    int B() => 2;

    #endregion
}
```

### RH7311-002 — Only the top-level regions of one declaration are compared

The analyzer MUST NOT report a region whose description repeats that of a region that is not a top-level region of the same declaration (SHARED-TYPEREGION-006), such as a nested region, a region of a nested class, struct, interface, record, record struct, union, or enum, or a region of another declaration of a `partial` type.

Why: A nested region is a sub-heading inside its outer region, and a nested type, a nested enum, or another partial declaration has its own outline; a repeated name there is not ambiguous within one list.

Example:

```csharp
partial class P
{
    #region Methods

    void A()
    {
    }

    #endregion
}

partial class P
{
    #region Methods

    void B()
    {
    }

    #endregion
}
```

is not reported. The nested region, the nested type, and the nested enum are shown under SHARED-TYPEREGION-006.

### RH7311-003 — The diagnostic is on the later `#region`

The analyzer MUST report one diagnostic per repeating region, located on its `#region` directive from the `#` to the end of its line. The first region with a description stays unreported.

Why: The first occurrence is the canonical block; each later one is the block to merge or rename.

Example: see RH7311-001.
