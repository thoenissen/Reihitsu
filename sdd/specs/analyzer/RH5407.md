# Analyzer — RH5407 Use braces consistently

| | |
|---|---|
| ID prefix | RH5407 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5407UseBracesConsistentlyAnalyzer`, `RH5407UseBracesConsistentlyCodeFixProvider` |
| Uses | SHARED-BRACE-001, SHARED-BRACE-002 |

RH5407 reports the body without braces of an `if` statement whose other branch has braces, and offers the code fix of SHARED-BRACE-002, which wraps the body in braces.

## Non-goals

- A body without braces in an `if` statement without `else`, or whose branches both lack braces — RH5405 and RH5406.

## Requirements

### RH5407-001 — A branch without braces next to one with braces is reported

The analyzer MUST report an `if` statement with an `else` clause whose body is not an `if` statement when exactly one of its two bodies, as SHARED-BRACE-001 names them, is a block. An `if` statement whose two bodies both are blocks or both are not, and an `if` statement without `else`, MUST NOT be reported. An `else if` is checked as the `if` statement it is, against its own `else`.

Why: Mixing a braced and an unbraced branch in one `if` statement makes it easy to add a statement to the wrong branch, because the indentation of the two branches no longer looks alike.

Example:

```csharp
class C
{
    void M(bool a, bool b)
    {
        if (a)
            {|RH5407:M(a, b);|}
        else
        {
            M(a, b);
        }

        if (a)
        {
            M(a, b);
        }
        else if (b)
            {|RH5407:M(a, b);|}
        else
        {
            M(a, b);
        }

        if (a)
            M(a, b);
        else
            M(a, b);
    }
}
```

### RH5407-002 — The diagnostic is on the body without braces

The analyzer MUST report one diagnostic per `if` statement, located on the whole body that is not a block.

Why: That body is what the fix wraps in braces.

Example: see RH5407-001.
