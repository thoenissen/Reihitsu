# Analyzer — RH6024 Binary operators must be spaced correctly

| | |
|---|---|
| ID prefix | RH6024 |
| Status | Active |
| Category | Spacing |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH6024BinaryOperatorsMustBeSpacedCorrectlyAnalyzer`, `RH6024BinaryOperatorsMustBeSpacedCorrectlyCodeFixProvider` |
| Uses | FMT-SPACE-010, SHARED-OPSPACE-001, SHARED-OPSPACE-002, SHARED-OPSPACE-003, SHARED-OPSPACE-004 |

RH6024 reports a binary operator without exactly one space on each side, as SHARED-OPSPACE-001 to SHARED-OPSPACE-003 specify, and offers a code fix that puts one space there as SHARED-OPSPACE-004 specifies.

In the examples, `→` marks a tab.

## Non-goals

- Assignment operators and the `=` of initializers — RH6023.
- Unary operators — RH6017 to RH6020.
- The conditional operator `?:`, the range operator `..`, the `=>` of a lambda or a switch arm, and pattern combinators and relational patterns such as `and`, `or`, `not`, and `> 0` — no analyzer rule checks their spacing.

## Requirements

### RH6024-001 — Binary operators are checked

The analyzer MUST check, as SHARED-OPSPACE-001 and SHARED-OPSPACE-002 specify, and report as SHARED-OPSPACE-003 specifies, the operator of every binary expression in code: the arithmetic operators `+`, `-`, `*`, `/`, and `%`; the shift operators `<<`, `>>`, and `>>>`; the comparison operators `==`, `!=`, `<`, `<=`, `>`, and `>=`; the logical operators `&&` and `||`; the bitwise operators `&`, `|`, and `^`; the null-coalescing operator `??`; and the type operators `is` and `as` with a type on their right, also inside an interpolation hole.

Why: Operands run together with their operator are hard to read, and a binary operator always separates two operands. The formatter puts one space on both sides of the same operators (FMT-SPACE-010), so formatted code raises no RH6024.

Example:

```csharp
class C
{
    bool M(int a, int b, object o, string s)
    {
        _ = a{|RH6024:+|}b;
        _ = a  {|RH6024:+|}  b;
        _ = a→{|RH6024:*|} b;
        _ = a{|RH6024:==|}b && a{|RH6024:!=|}b;
        _ = a{|RH6024:<|}b || a{|RH6024:>=|}b;
        _ = a{|RH6024:<<|}1;
        _ = a{|RH6024:>>>|}1;
        _ = (o){|RH6024:is|} string;
        _ = o {|RH6024:as|}  string;
        _ = s{|RH6024:??|}"x";
        _ = a{|RH6024:-|} -b;
        _ = $"{a{|RH6024:+|}b}";
        _ = a +
            b;

        return a{|RH6024:>|}b;
    }
}
```

### RH6024-002 — Directive conditions and patterns are not reported

The analyzer MUST NOT report an operator inside the condition of a preprocessor directive, and MUST NOT report `is` when a pattern follows it, such as `is null`, a declaration pattern, or a relational pattern.

Why: A directive condition is not code the rule lays out. `is` with a pattern is a different construct from the binary type test; its spacing is not decided by this rule.

Example:

```csharp
class C
{
    bool M(int a, object o)
    {
#if DEBUG&&TRACE
#endif
        _ = o is  null;
        _ = o  is string s;

        return a is  > 0 and < 5;
    }
}
```

is not reported.

### RH6024-003 — The fix puts one space on both sides

The code fix MUST put one space on both sides of the reported operator as SHARED-OPSPACE-004 specifies.

Why: The fix answers exactly the question the diagnostic asks.

Example:

```csharp
class C
{
    bool M(int a, int b, object o, string s)
    {
        _ = a{|RH6024:+|}b;
        _ = (o){|RH6024:is|} string;
        _ = s{|RH6024:??|}"x";
        _ = a{|RH6024:+|}-b;

        return a  {|RH6024:>|}  b;
    }
}
```

```csharp
class C
{
    bool M(int a, int b, object o, string s)
    {
        _ = a + b;
        _ = (o) is string;
        _ = s ?? "x";
        _ = a + -b;

        return a > b;
    }
}
```
