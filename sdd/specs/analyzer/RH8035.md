# Analyzer — RH8035 Non-private unions must be documented

| | |
|---|---|
| ID prefix | RH8035 |
| Status | Active |
| Category | Documentation |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH8035NonPrivateUnionsMustBeDocumentedAnalyzer` |
| Uses | SHARED-DOC-001, SHARED-DOC-002, SHARED-DOC-004, SHARED-DOC-005, SHARED-DOC-006, SHARED-DOC-007, SHARED-DOC-008, SHARED-DOC-019 |

RH8035 reports a union in the non-private group that has no `<summary>` or `<inheritdoc>` documentation.

## Non-goals

- Unions in the private group — RH8036.
- Structs, classes, and records — RH8001 to RH8010.
- Whether the summary has text — RH8030; the documentation of type parameters — RH8108. A union's case types have no names and are not documented with `<param>` — RH8101 does not check a union.

## Requirements

### RH8035-001 — Undocumented non-private unions are reported

The analyzer MUST report every union declaration, written with the `union` keyword, in the non-private group of SHARED-DOC-002 that is not documented, checked as SHARED-DOC-001 specifies, including generic unions and unions with a body. Whether it is documented MUST be decided as SHARED-DOC-004, SHARED-DOC-005, SHARED-DOC-006, and SHARED-DOC-007 specify, and nothing is reported when SHARED-DOC-008 applies or for a union that SHARED-DOC-019 leaves unjudged — one whose documentation comment holds a `param` or `paramref` element in any letter case, or whose documentation the compiler cannot expand — which is left to be corrected by hand.

Why: A union that other code can use is part of the contract that code builds on: it names the set of types a value can be. Without a summary, the generated documentation and the editor's tooltip show nothing, and readers have to infer what the union stands for from its case types.

Example:

```csharp
public union {|RH8035:Shape|}(int, string);

/// <remarks>
/// No summary
/// </remarks>
internal union {|RH8035:Result|}<T>(T, string);

union {|RH8035:Implicit|}(int, long);

/// <summary>
/// Documented
/// </summary>
public union Documented(int, string)
{
    private union Hidden(int, string);
}

/// <summary>
/// Outer
/// </summary>
public class Outer
{
    protected union {|RH8035:Visible|}(int, string);

    private union Inner(int, string);
}

public struct Point
{
}
```

`Hidden` and `Inner` are in the private group, which RH8036 checks; `Point` is a struct, which RH8003 checks.

### RH8035-002 — The diagnostic is on the union name

The analyzer MUST report one diagnostic per undocumented union declaration, located on its identifier, without its type parameter list and its case types.

Why: The name is what the documentation describes; marking it identifies the declaration without marking its whole body.

Example: see RH8035-001.
