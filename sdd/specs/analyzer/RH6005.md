# Analyzer — RH6005 Operator keyword must be followed by space

| | |
|---|---|
| ID prefix | RH6005 |
| Status | Active |
| Category | Spacing |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH6005OperatorKeywordMustBeFollowedBySpaceAnalyzer`, `RH6005OperatorKeywordMustBeFollowedBySpaceCodeFixProvider` |
| Uses | FMT-SPACE-012 |

RH6005 reports the `operator` keyword of an operator or conversion operator declaration when nothing separates it from what follows, and offers a code fix that inserts a space after it.

## Non-goals

- Spacing after the other statement keywords — RH6001.
- Spacing around the operator symbol and before the parameter list.

## Requirements

### RH6005-001 — An `operator` keyword glued to what follows is reported

The analyzer MUST report the `operator` keyword of an operator declaration or a conversion operator declaration when the keyword's trailing trivia contains neither whitespace nor a line break. A comment alone after the keyword does not separate it.

Why: Without the space, `operator+` reads as a single identifier rather than a keyword followed by a symbol. The formatter writes the same space (FMT-SPACE-012), so formatted code raises no RH6005.

Example:

```csharp
class C
{
    public static C {|RH6005:operator|}+(C a, C b) => a;

    public static C {|RH6005:operator|}/* note */-(C a, C b) => a;

    public static explicit {|RH6005:operator|}/* note */long(C c) => 0;
}
```

### RH6005-002 — A separated keyword and references in documentation are not reported

The analyzer MUST NOT report an `operator` keyword that is followed by exactly one space, and MUST NOT check an operator named in a documentation comment, such as `cref="operator+(C, C)"`.

Why: A reference in documentation names the member and is not a declaration; the spacing of a declaration does not apply to it.

Example:

```csharp
class C
{
    public static C operator +(C a, C b) => a;

    public static implicit operator int(C c) => 0;

    /// <see cref="operator+(C, C)"/>
    public void M()
    {
    }
}
```

is not reported.

### RH6005-003 — The diagnostic is on the keyword

The analyzer MUST report one diagnostic per declaration, located on the `operator` keyword.

Why: The keyword is the token whose spacing is wrong.

Example: see RH6005-001.

### RH6005-004 — The fix inserts a space after the keyword

The code fix MUST insert one space directly after the `operator` keyword, in front of a comment that follows it, and MUST NOT change anything else.

Why: The fix answers exactly what the diagnostic reports; inserting the space next to the keyword never touches the comment.

Example:

```csharp
class C
{
    public static C {|RH6005:operator|}+(C a, C b) => a;

    public static explicit {|RH6005:operator|}/* note */long(C c) => 0;
}
```

```csharp
class C
{
    public static C operator +(C a, C b) => a;

    public static explicit operator /* note */long(C c) => 0;
}
```
