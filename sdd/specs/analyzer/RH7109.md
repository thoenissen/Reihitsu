# Analyzer — RH7109 Readonly elements must appear before non-readonly elements

| | |
|---|---|
| ID prefix | RH7109 |
| Status | Active |
| Category | Organization |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH7109ReadonlyElementsMustAppearBeforeNonReadonlyElementsAnalyzer`, `RH7109ReadonlyElementsMustAppearBeforeNonReadonlyElementsCodeFixProvider` |
| Uses | SHARED-ORDER-001, SHARED-ORDER-002, SHARED-ORDER-003, SHARED-ORDER-004, SHARED-ORDER-005, SHARED-ORDER-006, SHARED-ORDER-007, SHARED-TYPEREGION-006 |

RH7109 reports a `readonly` field that follows a non-readonly field of the same accessibility and the same static or instance context, and offers a code fix that moves it in front of the first such field.

## Non-goals

- The order of constants and fields — RH7102 — and of static and instance fields — RH7103.
- The order of accessibility levels — RH7110.
- Ordering across the parts of a `partial` type and between a type and its nested types. Each type declaration is checked on its own.
- Members other than fields, such as get-only properties.

## Requirements

### RH7109-001 — A readonly field after a field of the same group is reported

The analyzer MUST report every `readonly` field declaration that contains no `#if`, `#elif`, `#else`, or `#endif` directive and follows, in the same class, struct, interface, record, or record struct declaration, a field declaration with neither `readonly` nor `const` of the same group. The analyzer compares the two fields when both lie outside every region, or both lie in the same top-level region (RH7109-003). A group is the combination of:

- the accessibility modifiers: `public`, `protected internal`, `private protected`, `internal`, `protected`, or `private`, with `protected internal` and `private protected` each one group regardless of modifier order; in an interface, a field without accessibility modifier counts as `public`;
- the context: both fields `static`, or both without `static`.

`const` fields take part on neither side.

Why: Fields that are fixed after construction describe what an object is; the mutable ones describe what it does. Listing the readonly fields first shows the fixed part of the state at a glance. Comparing only within one accessibility and one context leaves those orders to RH7110 and RH7103.

Example:

```csharp
class C
{
    private static int _shared;
    private int _count;
    public int Value;
    private readonly int {|RH7109:_id|};
    private static readonly int {|RH7109:_default|};
    public readonly int {|RH7109:Key|};
    private const int Max = 1;
}

interface I
{
    static int Counter;
    public static readonly int {|RH7109:Limit|};
}
```

### RH7109-002 — Fields of another group are not compared

The analyzer MUST NOT report a `readonly` field that follows only fields of other groups or `const` fields.

Why: Each group is ordered on its own; a static readonly field after an instance field is RH7103's concern, not this rule's.

Example:

```csharp
class C
{
    private int _count;
    private static readonly int _default = 1;
    private const int Max = 1;
    public readonly int Key;
}
```

is not reported: `_default` is static and `Key` is public, so neither is in the group of `_count`, and `Max` takes no part.

### RH7109-003 — Fields in one top-level region are compared

The analyzer MUST compare a `readonly` field with the earlier fields of its group that lie in the same top-level region of the type (SHARED-TYPEREGION-006), also when one of them lies in a region nested in it.

Why: A region holds members the author keeps together, and inside it the fields are read in order as in a type without regions.

Example:

```csharp
class C
{
    #region Fields

    private int _count;
    private int _other;
    private readonly int {|RH7109:_id|};

    #endregion
}
```

The diagnostic has no code fix here (RH7109-006): the `#region` line belongs to the leading trivia of `_count`, so it lies in the crossed span without its partner (SHARED-ORDER-004).

### RH7109-004 — The diagnostic is on the first name

The analyzer MUST report one diagnostic per misplaced field declaration, located on the identifier of its first declarator.

Why: The order belongs to the declaration, and the fix moves the whole declaration at once.

Example: see RH7109-001.

### RH7109-005 — The fix moves the field in front of the first field of its group

The code fix MUST move the reported field declaration in front of the first earlier field declaration of the same group (RH7109-001) that has neither `readonly` nor `const`, and MUST perform the move as specified in SHARED-ORDER-001 and SHARED-ORDER-002.

Why: The first such field is the earliest position at which the readonly field satisfies the rule, so one move corrects the diagnostic without moving any other member.

Example:

```csharp
class C
{
    private int _count;
    private readonly int {|RH7109:_id|} = 2;
}
```

```csharp
class C
{
    private readonly int _id = 2;
    private int _count;
}
```

The documentation comment travels with the field, and the blank line stays where it was:

```csharp
class C
{
    private int _count;

    /// <summary>
    /// The identifier
    /// </summary>
    private readonly int {|RH7109:_id|};
}
```

```csharp
class C
{
    /// <summary>
    /// The identifier
    /// </summary>
    private readonly int _id;

    private int _count;
}
```

### RH7109-006 — The fix is withheld when the move is unsafe

The code fix MUST NOT be offered when the move is refused by SHARED-ORDER-003, SHARED-ORDER-004, SHARED-ORDER-005, or SHARED-ORDER-007. When no `#if`, `#elif`, `#else`, or `#endif` directive takes part in the refusal, the diagnostic is still reported. A balanced directive pair alone does not withhold it (SHARED-ORDER-006).

Why: These moves would change which code a directive governs or the order in which initializers run. A reported diagnostic without a fix is a supported end state.

Example:

```csharp
class C
{
    private int _count = 1;
    private readonly int {|RH7109:_id|} = 2;
}
```

is reported, and no code fix is offered: both fields have an instance initializer, so the move would run `_id`'s initializer before `_count`'s.
