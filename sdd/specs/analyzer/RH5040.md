# Analyzer — RH5040 Comments must not be placed around the arrow of an expression-bodied member

| | |
|---|---|
| ID prefix | RH5040 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH5040CommentsMustNotBePlacedAroundExpressionBodyArrowAnalyzer` |
| Uses | SHARED-COMMENT-001, SHARED-COMMENT-002, SHARED-COMMENT-003 |

RH5040 reports a comment placed directly before or directly after the `=>` of an expression-bodied member or accessor.

## Non-goals

- Whether a member should have an expression body — the expression-body rules such as RH3202.
- Comments elsewhere in the expression body — the rules for the construct the comment is in.

## Requirements

### RH5040-001 — A comment around the arrow of an expression-bodied member is reported

The analyzer MUST report every ordinary comment (SHARED-COMMENT-001, SHARED-COMMENT-002) directly before or directly after the `=>` of the expression body of a member — a method, a constructor, a finalizer, an operator, a conversion operator, a property, or an indexer — or of an accessor, as SHARED-COMMENT-003 specifies. A comment before the member, or elsewhere in its expression, MUST NOT be reported.

Why: The arrow joins the member's signature to its body. A comment around it separates the two and leaves it unclear whether it describes the signature or the expression.

Example:

```csharp
class C
{
    private int _value;

    public int Value
        {|RH5040:// computed|}
        => 42;

    public int Other =>
        {|RH5040:// computed|}
        42;

    public int M() => {|RH5040:/* computed */|} 42;

    public int Stored
    {
        get
            {|RH5040:// stored|}
            => _value;
    }

    // computed
    public int Sum => 1
                      // offset
                      + 2;
}
```

The comments `// computed` before `Sum` and `// offset` are not reported.

### RH5040-002 — Other arrows are not checked

The analyzer MUST NOT report a comment around the `=>` of a local function, a lambda, or a switch expression arm.

Why: These arrows belong to a statement or an expression, not to a member signature; the rules for those constructs decide where a comment may go.

Example:

```csharp
using System;

class C
{
    void M(object o)
    {
        int Local() =>
            // computed
            42;

        Func<int> function = () =>
            // computed
            42;

        _ = o switch
        {
            string =>
                // text
                1,
            _ => 2
        };

        _ = Local();
        _ = function;
    }
}
```

is not reported.
