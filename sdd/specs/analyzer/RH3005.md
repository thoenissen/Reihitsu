# Analyzer — RH3005 Use readable conditions

| | |
|---|---|
| ID prefix | RH3005 |
| Status | Active |
| Category | Clarity |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH3005UseReadableConditionsAnalyzer`, `RH3005UseReadableConditionsCodeFixProvider` |
| Uses | SHARED-FIX-003 |

RH3005 reports a comparison that has a constant on the left and a value that is not constant on the right, and offers a code fix that swaps the operands and mirrors the operator.

## Non-goals

- Comparisons by pattern, such as `x is 0` or `x is > 0`.
- Logical negation — RH3001.

## Requirements

### RH3005-001 — A constant on the left of a comparison is reported

The analyzer MUST report a comparison with `==`, `!=`, `<`, `>`, `<=`, or `>=` whose left operand is constant-like and whose right operand is not. An operand is constant-like when it is a literal (`null` included), a `default` expression, an expression with a constant value, a `const` field, or a `static readonly` field.

Why: A condition reads naturally when the value that changes comes first; a constant in front ("Yoda condition") slows the reader down. A `static readonly` field is treated like a constant because it is read like one.

Example:

```csharp
class C
{
    const int Max = 10;
    static readonly int Min = 0;

    void M(int a, string s)
    {
        if (0 {|RH3005:<|} a) { }
        if (Max {|RH3005:==|} a) { }
        if (Min {|RH3005:>=|} a) { }
        if (null {|RH3005:==|} s) { }
        if (default(int) {|RH3005:!=|} a) { }
    }
}
```

### RH3005-002 — Other comparisons are not reported

The analyzer MUST NOT report a comparison whose left operand is not constant-like, or whose operands are both constant-like.

Why: With the changing value on the left, or no changing value at all, there is no order to correct.

Example:

```csharp
class C
{
    const int Max = 10;

    void M(int a, int b)
    {
        if (a < 0) { }
        if (a < b) { }
        if (Max > 0) { }
    }
}
```

is not reported.

### RH3005-003 — The diagnostic is on the operator

The analyzer MUST report one diagnostic per comparison, on its operator token.

Why: The operator stands between the two operands whose order the fix swaps.

Example: see RH3005-001.

### RH3005-004 — The fix swaps the operands and mirrors the operator

For a comparison whose operands are not themselves comparisons, for which RH3005-005 does not withhold the fix, and where the largest expression that contains the comparison — the comparison itself, when it is not part of a larger expression — holds no `<` or `>` operator besides the comparison's own, the code fix MUST write the right operand first and the left operand second, with `<` and `>` exchanged, `<=` and `>=` exchanged, and `==` and `!=` kept, and keep the trivia in front of and after the comparison.

Why: Mirroring the operator keeps the comparison's meaning when its operands change sides.

Example:

```csharp
class C
{
    const int Max = 10;
    static readonly int Min = 0;

    void M(int a, string s)
    {
        if (0 {|RH3005:<|} a) { }
        if (Max {|RH3005:==|} a) { }
        if (Min {|RH3005:>=|} a) { }
        if (null {|RH3005:==|} s) { }
        if (default(int) {|RH3005:!=|} a) { }
    }
}
```

```csharp
class C
{
    const int Max = 10;
    static readonly int Min = 0;

    void M(int a, string s)
    {
        if (a > 0) { }
        if (a == Max) { }
        if (a <= Min) { }
        if (s == null) { }
        if (a != default(int)) { }
    }
}
```

### RH3005-005 — The fix is withheld unless the built-in operator compares both ways

The code fix MUST NOT be offered when either operand is `dynamic`, when the comparison binds to an operator that a type declares itself rather than to a built-in operator, or when the comparison with its operands swapped and the operator mirrored would bind to an operator that a type declares itself. The diagnostic is still reported.

Why: Only a built-in comparison is guaranteed to have a mirrored operator with the same meaning. A user-defined operator may not exist for the swapped operand types, may bind to a different overload, or may not be symmetric; a `dynamic` operand binds only at run time.

Example:

```csharp
class V
{
    public static bool operator ==(int a, V b) => true;
    public static bool operator !=(int a, V b) => false;
    public override bool Equals(object o) => false;
    public override int GetHashCode() => 0;
}

class C
{
    void M(V v, dynamic d)
    {
        if (1 {|RH3005:==|} v) { }
        if (0 {|RH3005:<|} d) { }
    }
}
```

is reported, and no code fix is offered.
Neither is one offered when only the swapped comparison would bind to an operator the type declares:

```csharp
class V
{
    public static implicit operator int(V v) => 0;
    public static bool operator <(V a, int b) => true;
    public static bool operator >(V a, int b) => true;
}

class C
{
    bool M(V v)
    {
        return 1 {|RH3005:<|} v;
    }
}
```

is reported, and no code fix is offered: `1 < v` binds to the built-in comparison of `int`, while `v > 1` would bind to `V`'s operator.

### RH3005-006 — A comment inside the comparison withholds the fix

The code fix MUST NOT be offered when a comment or a preprocessor directive stands inside the comparison, between its first and its last token. The diagnostic is still reported. A comment in front of or after the comparison MUST NOT withhold the fix.

Why: The swapped comparison is rebuilt from the two operands without their trivia; a comment between them would be lost. Trivia around the comparison is kept by RH3005-004.

Example:

```csharp
class C
{
    void M(int a)
    {
        if (0 /* x */ {|RH3005:<|} a) { }
    }
}
```

is reported, and no code fix is offered. A comment in front of the comparison stays where it is:

```csharp
class C
{
    bool M(int a)
    {
        return /* x */ 0 {|RH3005:<|} a;
    }
}
```

```csharp
class C
{
    bool M(int a)
    {
        return /* x */ a > 0;
    }
}
```

### RH3005-007 — A swap that would group the operands differently is withheld

The code fix MUST NOT be offered when an operand of the comparison is itself a comparison written without parentheses and the swapped comparison, written without parentheses, would group its operands differently. The diagnostic is still reported. An operand comparison whose swapped comparison groups its operands the same way, as `true == a < b` written as `a < b == true` does, is not withheld by this requirement.

Why: `1 == 1 == b` groups as `(1 == 1) == b`; written as `b == 1 == 1`, it groups as `(b == 1) == 1`, which compares a `bool` with an `int` and does not compile (SHARED-FIX-003).

Example:

```csharp
class C
{
    void M(bool b)
    {
        if (1 == 1 {|RH3005:==|} b) { }
    }
}
```

is reported, and no code fix is offered.

### RH3005-008 — A swap that would parse as a generic name is withheld

The code fix MUST NOT be offered when the code it writes would parse as a generic name: when a `<` and a later `>`, one of them the mirrored operator the fix writes, would read as a type argument list, as they do when the `>` is followed by `(`. The diagnostic is still reported. Where the code the fix writes parses with the same operators and operands as the code it replaces, this requirement does not withhold the fix.

Why: After an open `<`, a `>` followed by a token such as `(` is read as the end of a type argument list, so the comparisons would become a generic name that does not compile (SHARED-FIX-003).

Example:

```csharp
class C
{
    const int Max = 1;
    int G;
    int B;

    void M(bool x, bool y)
    {
    }

    void Run()
    {
        M(Max {|RH3005:>|} G, B > (7));
    }
}
```

is reported, and no code fix is offered: `M(G < Max, B > (7))` would call a generic method `G<Max, B>`.
