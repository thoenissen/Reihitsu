# Analyzer — RH3005 Use readable conditions

| | |
|---|---|
| ID prefix | RH3005 |
| Status | Active |
| Category | Clarity |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH3005UseReadableConditionsAnalyzer`, `RH3005UseReadableConditionsCodeFixProvider` |
| Uses | — |

RH3005 reports a comparison that has a constant on the left and a value that is not constant on the right, and offers a code fix that swaps the operands and mirrors the operator.

## Non-goals

- Comparisons by pattern, such as `x is 0` or `x is > 0`.
- Logical negation — RH3001.

## Requirements

### RH3005-001 — A constant on the left of a comparison is reported

The analyzer MUST report a comparison with `==`, `!=`, `<`, `>`, `<=`, or `>=` whose left operand is constant-like and whose right operand is not. An operand is constant-like when it is a literal (`null` included), a `default` expression, an expression with a constant value, a `const` field, or a `static readonly` field.

Why: A condition reads naturally when the value that changes comes first; a constant in front ("Yoda condition") slows the reader down. A `static readonly` field is treated like a constant because it is read like one.

Example:

```csharp
class C
{
    const int Max = 10;
    static readonly int Min = 0;

    void M(int a, string s)
    {
        if (0 {|RH3005:<|} a) { }
        if (Max {|RH3005:==|} a) { }
        if (Min {|RH3005:>=|} a) { }
        if (null {|RH3005:==|} s) { }
        if (default(int) {|RH3005:!=|} a) { }
    }
}
```

### RH3005-002 — Other comparisons are not reported

The analyzer MUST NOT report a comparison whose left operand is not constant-like, or whose operands are both constant-like.

Why: With the changing value on the left, or no changing value at all, there is no order to correct.

Example:

```csharp
class C
{
    const int Max = 10;

    void M(int a, int b)
    {
        if (a < 0) { }
        if (a < b) { }
        if (Max > 0) { }
    }
}
```

is not reported.

### RH3005-003 — The diagnostic is on the operator

The analyzer MUST report one diagnostic per comparison, on its operator token.

Why: The operator stands between the two operands whose order the fix swaps.

Example: see RH3005-001.

### RH3005-004 — The fix swaps the operands and mirrors the operator

For a comparison whose operands are not themselves comparisons, the code fix MUST write the right operand first and the left operand second, with `<` and `>` exchanged, `<=` and `>=` exchanged, and `==` and `!=` kept, and keep the trivia in front of and after the comparison.

Why: Mirroring the operator keeps the comparison's meaning when its operands change sides.

Example:

```csharp
class C
{
    const int Max = 10;
    static readonly int Min = 0;

    void M(int a, string s)
    {
        if (0 {|RH3005:<|} a) { }
        if (Max {|RH3005:==|} a) { }
        if (Min {|RH3005:>=|} a) { }
        if (null {|RH3005:==|} s) { }
        if (default(int) {|RH3005:!=|} a) { }
    }
}
```

```csharp
class C
{
    const int Max = 10;
    static readonly int Min = 0;

    void M(int a, string s)
    {
        if (a > 0) { }
        if (a == Max) { }
        if (a <= Min) { }
        if (s == null) { }
        if (a != default(int)) { }
    }
}
```

### RH3005-005 — The fix is withheld unless the built-in operator compares both ways

The code fix MUST NOT be offered when either operand is `dynamic`, or when the comparison binds to an operator that a type declares itself rather than to a built-in operator. The diagnostic is still reported.

Why: Only a built-in comparison is guaranteed to have a mirrored operator with the same meaning. A user-defined operator may not exist for the swapped operand types, may bind to a different overload, or may not be symmetric; a `dynamic` operand binds only at run time.

Example:

```csharp
class V
{
    public static bool operator ==(int a, V b) => true;
    public static bool operator !=(int a, V b) => false;
    public override bool Equals(object o) => false;
    public override int GetHashCode() => 0;
}

class C
{
    void M(V v, dynamic d)
    {
        if (1 {|RH3005:==|} v) { }
        if (0 {|RH3005:<|} d) { }
    }
}
```

is reported, and no code fix is offered.

### RH3005-006 — A comment inside the comparison withholds the fix

The code fix MUST NOT be offered when a comment or a preprocessor directive stands inside the comparison, between its first and its last token. The diagnostic is still reported. A comment in front of or after the comparison MUST NOT withhold the fix.

Why: The swapped comparison is rebuilt from the two operands without their trivia; a comment between them would be lost. Trivia around the comparison is kept by RH3005-004.

Example:

```csharp
class C
{
    void M(int a)
    {
        if (0 /* x */ {|RH3005:<|} a) { }
    }
}
```

is reported, and no code fix is offered. A comment in front of the comparison stays where it is:

```csharp
class C
{
    bool M(int a)
    {
        return /* x */ 0 {|RH3005:<|} a;
    }
}
```

```csharp
class C
{
    bool M(int a)
    {
        return /* x */ a > 0;
    }
}
```
