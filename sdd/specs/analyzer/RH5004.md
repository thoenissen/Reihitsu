# Analyzer — RH5004 do-Statement should be preceded by a blank line

| | |
|---|---|
| ID prefix | RH5004 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5004DoStatementsShouldBePrecededByABlankLineAnalyzer`, `RH5004DoStatementsShouldBePrecededByABlankLineCodeFixProvider` |
| Uses | SHARED-STMT-001, SHARED-STMT-002, SHARED-STMT-003, SHARED-STMT-004 |

RH5004 reports a `do` statement that follows another statement of the same block or switch section without a blank line between them, and offers a code fix that inserts one as SHARED-STMT-004 specifies.

## Non-goals

- Blank lines before other statement kinds — the other rules that use `shared/statement-blank-lines.md`.

## Requirements

### RH5004-001 — A `do` statement that follows a statement needs a blank line

The analyzer MUST report a `do` statement as SHARED-STMT-001, SHARED-STMT-002, and SHARED-STMT-003 specify.

Why: A `do` statement starts a loop whose condition only comes at its end; the blank line marks where the repeated part begins.

Example:

```csharp
class C
{
    void M(int a)
    {
        a++;
        {|RH5004:do|}
        {
            a--;
        }
        while (a > 0);

        do
        {
            a--;
        }
        while (a > 0);
    }
}
```

The second `do` follows a blank line and is not reported.

### RH5004-002 — The diagnostic is on the `do` keyword

The analyzer MUST report the diagnostic on the `do` keyword.

Why: The keyword is where the missing separator becomes visible, and the location stays stable when the loop body changes.

Example: see RH5004-001.
