# Analyzer — RH0001 Configuration file must be valid

| | |
|---|---|
| ID prefix | RH0001 |
| Status | Active |
| Category | Analyzer |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH0001ConfigurationFileMustBeValidAnalyzer`, `ConfigurationManager`, `ConfigurationLoadResult`, `ConfigurationValidationError`, `CopyrightHeaderTemplateResolver` |
| Uses | — |

RH0001 validates the `reihitsu.json` configuration file and reports every problem in it as a diagnostic located in that file. The same loader feeds the rules that read the configuration — RH4009 (`naming`) and RH8402 (`copyright`).

## Non-goals

- How the file reaches the compiler. It must be an `AdditionalFiles` item of the project; the package does not add it.
- What the configured values mean for the rules that read them — RH4009 and RH8402.
- `.editorconfig` settings, which configure severities, not Reihitsu's own settings.

## Requirements

### RH0001-001 — The first `reihitsu.json` among the additional files is the configuration

The analyzer MUST load the first additional file whose file name, without its directory, is `reihitsu.json` compared case-insensitively, wherever the file lies. A file with a similar name (`my-reihitsu.json`, `reihitsu.json.bak`) MUST NOT be loaded. Without such a file, nothing is reported.

Why: The configuration is optional; a project without it uses the defaults. Matching the exact file name keeps backups and other tools' files from being picked up by accident.

### RH0001-002 — Every problem is one diagnostic in the configuration file

The analyzer MUST report each problem it finds as its own diagnostic with the message "The reihitsu.json configuration is invalid: " followed by the problem's description, located in `reihitsu.json` at the property name, value, or section the problem is about. Positions MUST be character positions, so non-ASCII characters before a problem do not shift it. All problems of a well-formed file MUST be reported, not only the first.

Why: The user fixes the file, not the code, so the diagnostic has to point into the file. Reporting everything at once saves a round trip per mistake.

Example — two problems, two diagnostics, one on each property name:

```json
{ "Copyright": {}, "formatting": 1 }
```

reports "Unknown configuration section 'Copyright'." and "Unknown configuration section 'formatting'.". Section names are case-sensitive.

### RH0001-003 — An empty or malformed file is one problem

The analyzer MUST report "The configuration file must not be empty or whitespace-only." at the start of an empty or whitespace-only file, and "The configuration file contains invalid JSON syntax." at the position where parsing failed for a file that is not valid JSON — including comments and trailing commas, which strict JSON does not allow. A file that cannot be parsed MUST NOT be validated further.

Why: Without a parsed document there is nothing to validate; a single diagnostic at the failing position is the most useful hint.

Example:

```json
{ "naming": { "allowedNamespaceDeclarations": [ "A", ] } }
```

reports invalid JSON syntax at the `]` that follows the trailing comma.

### RH0001-004 — The root is an object of known sections

The analyzer MUST report "The configuration root must be a JSON object." when the root value is not an object. Inside the root object, the only sections are `copyright` and `naming`; any other property MUST be reported as "Unknown configuration section '…'.", and a known section whose value is not an object MUST be reported as "The '…' section must be a JSON object.".

Why: An unknown section is almost always a typo or a setting from another tool; silently ignoring it would leave the user believing the setting is in effect.

Example:

```json
{ "copyright": "x" }
```

reports "The 'copyright' section must be a JSON object." on `"x"`.

### RH0001-005 — The `naming` section holds the allowed namespace declarations

In the `naming` section, the analyzer MUST accept only the setting `allowedNamespaceDeclarations`, which MUST be an array whose entries are strings. Another setting MUST be reported as "Unknown configuration setting 'naming.…'.", a non-array value as "The 'naming.allowedNamespaceDeclarations' setting must be a JSON array.", and each non-string entry, `null` included, as "Entries in 'naming.allowedNamespaceDeclarations' must be strings.".

Why: RH4009 compares namespaces against these strings; any other shape has no meaning to it.

Example:

```json
{
  "naming": {
    "allowedNamespaceDeclarations": "MyCompany.Project"
  }
}
```

reports the array requirement;

```json
{
  "naming": {
    "allowedNamespaceDeclarations": [
      "MyCompany.Project"
    ]
  }
}
```

is valid.

### RH0001-006 — The `copyright` section describes a comment header

In the `copyright` section, the analyzer MUST require the setting `copyrightText` as a non-empty string that is a comment header: either every line starts with `//`, or the trimmed text starts with `/*` and ends with `*/`. Every other property of the section is the value of a placeholder and MUST be a string, except `fileName`, which is reserved and MUST be reported when present. Every placeholder `{name}` used in `copyrightText`, other than `{fileName}`, MUST have a setting of that name. The problems are reported as:

- "The 'copyright.copyrightText' setting is required and must not be empty." and "The 'copyright.copyrightText' setting must be a comment header that uses either '//' line comments or '/* */' block comments.", both on the whole section;
- "The 'copyright.…' setting must be a string." on a non-string value;
- "The 'copyright.fileName' setting is reserved and must not be configured." on the property name;
- "The placeholder '…' used in 'copyright.copyrightText' has no matching setting in 'copyright'." on the whole section.

Why: RH8402 compares the start of every file with this header after substituting the placeholders; `{fileName}` is filled in from the file being checked, so a configured value for it would be ignored. A header that is not a comment cannot be the start of a C# file.

Example:

```json
{
  "copyright": {
    "copyrightText": "// Copyright {company}. {fileName}",
    "company": "ACME"
  }
}
```

is valid.

```json
{ "copyright": { "copyrightText": "// {company} {fileName} {year}", "company": "A", "year": 2026 } }
```

reports that `year` must be a string and that the placeholder `year` has no matching setting: a non-string value does not count as a setting.
