# Analyzer — RH8302 Element documentation headers must not be followed by blank line

| | |
|---|---|
| ID prefix | RH8302 |
| Status | Active |
| Category | Documentation |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH8302ElementDocumentationHeadersMustNotBeFollowedByBlankLineAnalyzer`, `RH8302ElementDocumentationHeadersMustNotBeFollowedByBlankLineCodeFixProvider` |
| Uses | SHARED-BLANK-001, SHARED-DOC-004, SHARED-DOC-008 |

RH8302 reports the blank lines between a documentation comment and the line that follows it, and offers a code fix that removes them.

## Non-goals

- The blank line in front of a documentation comment — RH8303.
- Blank lines after ordinary comments, and blank lines elsewhere in the code — the layout rules, such as RH5023.

## Requirements

### RH8302-001 — Blank lines after a documentation comment are reported

The analyzer MUST report the blank lines, as SHARED-BLANK-001 defines them, that directly follow the last line of a `///` documentation comment, and those that directly follow the line on which a `/** */` documentation comment ends when nothing but white space follows its `*/` on that line. What comes after the blank lines does not matter: the documented declaration, an ordinary comment, a preprocessor directive, and another documentation comment are reported alike. Nothing is reported when SHARED-DOC-008 applies.

This requirement covers the documentation comments of a declaration as SHARED-DOC-004 defines them, each starting its own line. A documentation comment that starts behind code on its line, a run of blank lines followed by `#region` or `#endregion`, and a `///` or `/** */` comment that is not a documentation comment of a declaration, such as one inside a method body or one in front of a closing brace, are not covered.

Why: A documentation comment belongs to the code directly below it. A blank line visually detaches it, so the reader can no longer see at a glance which element it describes; between two documentation comments of one declaration, it splits what the compiler joins into one documentation.

Example:

```csharp
class C
{
    /// <summary>
    /// First
    /// </summary>
{|RH8302:
|}    int A;

    /** <summary>Second</summary> */
{|RH8302:
|}    int B;

    /// <summary>
    /// Third
    /// </summary>
{|RH8302:
|}    // Ordinary comment
    int C1;

    /// <remarks>Remarks</remarks>
{|RH8302:
|}    /// <summary>Fourth</summary>
    int D;

    /// <summary>Fifth</summary>
{|RH8302:
|}#if !NEVER
    int E;
#endif
}
```

### RH8302-002 — Other comments and other positions are not reported

The analyzer MUST NOT report a documentation comment that is directly followed by its next line, a blank line after a `/** */` documentation comment whose line continues after the `*/`, a blank line after a comment that starts with four or more slashes, or a blank line after a `///` line inside a string literal, inside a `/* */` comment, or inside code that an `#if` branch excludes.

Why: Without a blank line there is nothing to remove. Behind the `*/`, the line continues with other content, so the blank line below it does not follow the documentation comment. Four slashes start an ordinary comment, and a line inside a literal, a block comment, or excluded code is not a documentation comment.

Example:

```csharp
class C
{
    /// <summary>
    /// First
    /// </summary>
    int A;

    /** <summary>Second</summary> */ // Note

    int B;

    ////

    int C1;

    /*
    /// Not documentation
    */

    int D;
}
```

is not reported.

### RH8302-003 — One diagnostic covers the whole run of blank lines

The analyzer MUST report one diagnostic per run of blank lines, covering every line of the run from its start through its line break, the white space on the lines included.

Why: The run is what the fix removes, so one diagnostic and one fix cover it whatever its length.

Example:

```csharp
class C
{
    /// <summary>
    /// First
    /// </summary>
{|RH8302:

|}    int A;
}
```

### RH8302-004 — The fix removes the blank lines

The code fix MUST remove the reported run of blank lines and change nothing else.

Why: The documentation comment and the code below it are already as the author wrote them; only the separation is wrong.

Example:

```csharp
class C
{
    /// <summary>
    /// First
    /// </summary>
{|RH8302:

|}    int A;

    /** <summary>Second</summary> */
{|RH8302:
|}    int B;
}
```

```csharp
class C
{
    /// <summary>
    /// First
    /// </summary>
    int A;

    /** <summary>Second</summary> */
    int B;
}
```
