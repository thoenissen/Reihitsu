# Analyzer — RH4118 Tuple expression element casing

| | |
|---|---|
| ID prefix | RH4118 |
| Status | Active |
| Category | Naming |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH4118TupleElementCasingAnalyzer` |
| Uses | SHARED-CASING-001 |

RH4118 reports an element name written in a tuple expression that is not in PascalCase.

## Non-goals

- Element names of a tuple type, such as `(int count, int total)` — RH4116.
- Variables declared by a deconstruction — RH4115 and RH4117.

## Requirements

### RH4118-001 — Element names written in a tuple expression are in PascalCase

The analyzer MUST report every element name written as `name:` in a tuple expression that is not in PascalCase as SHARED-CASING-001 defines it, including the names of a tuple expression nested in another one. An element without a written name MUST NOT be reported, including an element whose name the compiler infers from a variable, as in `(count, Total: count)`. The analyzer MUST report one diagnostic per written name, located on the name.

Why: The name written in a tuple expression is the name callers read the value back with — `result.FirstValue` — so it is spelled like the member access it becomes, and like the name a tuple type would declare (RH4116).

Example:

```csharp
class C
{
    void M(int count)
    {
        var a = ({|RH4118:count|}: 1, Total: 2, 3);
        var b = (count, Total: count);
        var c = ({|RH4118:outer|}: ({|RH4118:inner|}: 1, Other: 2), 3);
    }
}
```
