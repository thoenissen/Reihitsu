# Analyzer — RH5516 Property attribute lists must use one attribute per list

| | |
|---|---|
| ID prefix | RH5516 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5516PropertyAttributeListsMustFollowShapeRulesAnalyzer`, `RH5516PropertyAttributeListsMustFollowShapeRulesCodeFixProvider` |
| Uses | SHARED-ATTR-001, SHARED-ATTR-002, SHARED-ATTR-003, SHARED-ATTR-013, SHARED-ATTR-014, SHARED-ATTR-016, SHARED-ATTR-017, SHARED-ATTR-019 |

RH5516 reports an attribute list of a property or indexer that holds more than one attribute, and offers a code fix that gives each attribute a list of its own. The rule uses `shared/attribute-targets.md`.

## Non-goals

- Attributes of a property's accessors — RH5531.
- A `property:` list on a positional record parameter — RH5524.
- Where a property attribute list is placed — RH5515.

## Requirements

### RH5516-001 — Property attribute lists hold one attribute

The analyzer MUST check every attribute list that resolves to the property target (SHARED-ATTR-001, SHARED-ATTR-002, SHARED-ATTR-003): the lists of a property or indexer without a specifier or with `type:`, and every list with the `property:` specifier that is not attached to a parameter or type parameter, and MUST report such a list that holds more than one attribute, as SHARED-ATTR-013 and SHARED-ATTR-014 specify.

Why: Properties attract independent attributes from several directions at once — serialization, validation, data binding — and each on its own line can be changed without rewriting the others.

Example:

```csharp
class C
{
    {|RH5516:[A, B]|}
    int P { get; set; }

    {|RH5516:[A, B]|}
    int this[int i] => i;

    {|RH5516:[property: A, B]|}
    int Q { get; set; }
}

record R([property: A, B] int Id);
```

The `property:` list of the record parameter `Id` is not reported by RH5516.

### RH5516-002 — The diagnostic is on the attribute list

The analyzer MUST report the diagnostic on the attribute list, as SHARED-ATTR-016 specifies.

Why: The list is what has the wrong shape; each list of a declaration is reported and fixed on its own.

Example: see RH5516-001.

### RH5516-003 — The fix gives each attribute a list of its own

The code fix MUST replace the list with one list per attribute, each on its own line, as SHARED-ATTR-017 specifies.

Why: The fix makes only the change the diagnostic asks for: the attributes keep their order and their specifier, and each gets a line of its own.

Example:

```csharp
class C
{
    {|RH5516:[A, B]|}
    int P { get; set; }
}
```

```csharp
class C
{
    [A]
    [B]
    int P { get; set; }
}
```

### RH5516-004 — The fix is withheld for a comment or directive inside the list

The code fix MUST NOT be offered when SHARED-ATTR-019 withholds it. The diagnostic is still reported.

Why: A comment inside the list belongs to the attribute next to it, and only the author can tell which of the new lists it belongs to.

Example:

```csharp
class C
{
    {|RH5516:[A, /* c */ B]|}
    int P { get; set; }
}
```

is reported, and no code fix is offered.
