# Analyzer — RH5527 Return value attributes must be on their own line

| | |
|---|---|
| ID prefix | RH5527 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5527ReturnValueAttributesMustFollowPlacementRulesAnalyzer`, `RH5527ReturnValueAttributesMustFollowPlacementRulesCodeFixProvider` |
| Uses | SHARED-ATTR-002, SHARED-ATTR-004, SHARED-ATTR-005, SHARED-ATTR-006, SHARED-ATTR-007, SHARED-ATTR-008, SHARED-ATTR-009, SHARED-ATTR-011, SHARED-ATTR-012 |

RH5527 reports a `return:` attribute list that shares its line with the token after it, and offers a code fix that moves that token onto the next line. The rule uses `shared/attribute-targets.md`.

## Non-goals

- Attribute lists of a method without the `return:` specifier — RH5513.

## Requirements

### RH5527-001 — Return-value attribute lists are on their own line

The analyzer MUST check every attribute list with the `return:` specifier (SHARED-ATTR-002), on a method, operator, local function, delegate, accessor, or any other declaration, and MUST report such a list whose closing bracket shares its line with the first token after it, as SHARED-ATTR-004, SHARED-ATTR-005, and SHARED-ATTR-006 specify for a list that must be on its own line.

Why: A `return:` attribute is a statement about the value a member hands back, not about the member's name or parameters; on its own line it reads as what it is, made before the signature that produces the value.

Example:

```csharp
class C
{
    {|RH5527:[return: A]|} int M() => 0;

    void N()
    {
        {|RH5527:[return: A]|} int L() => 1;
    }

    [return: A]
    int O() => 0;
}

{|RH5527:[return: A]|} delegate int D();
```

### RH5527-002 — The diagnostic is on the attribute list

The analyzer MUST report the diagnostic on the attribute list, as SHARED-ATTR-007 specifies.

Why: The list is what is misplaced; each list of a declaration is reported and fixed on its own.

Example: see RH5527-001.

### RH5527-003 — The fix moves what follows onto the next line

The code fix MUST put the first token after the list on a new line, as SHARED-ATTR-008 and SHARED-ATTR-009 specify.

Why: The fix makes only the change the diagnostic asks for: the declaration starts on its own line, and the list stays where it is.

Example:

```csharp
class C
{
    {|RH5527:[return: A]|} int M() => 0;
}
```

```csharp
class C
{
    [return: A]
    int M() => 0;
}
```

### RH5527-004 — The fix is withheld for comments, directives, and missing braces

The code fix MUST NOT be offered when SHARED-ATTR-011 or SHARED-ATTR-012 withholds it. The diagnostic is still reported.

Why: A comment inside the list belongs to the attribute next to it, and an unclosed scope leaves no indentation to compute; both are left to the author.

Example:

```csharp
class C
{
    {|RH5527:[return: A /* c */]|} int M() => 0;
}
```

is reported, and no code fix is offered.
