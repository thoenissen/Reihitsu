# Analyzer — RH8101 Element parameters must be documented

| | |
|---|---|
| ID prefix | RH8101 |
| Status | Active |
| Category | Documentation |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH8101ElementParametersMustBeDocumentedAnalyzer` |
| Uses | SHARED-DOC-008, SHARED-DOC-009, SHARED-DOC-011, SHARED-DOC-012 |

RH8101 reports a parameter of a documented method, constructor, delegate, indexer, operator, conversion operator, or primary constructor that has no matching `<param>` documentation.

## Non-goals

- Whether the declaration has a summary — RH8001 to RH8029 and RH8034.
- The parameter of an extension declaration — RH8032; type parameters — RH8108 and RH8033.
- Whether the `<param>` elements follow the parameters, name one, and have text — RH8102, RH8103, and RH8104.

## Requirements

### RH8101-001 — An undocumented parameter is reported

The analyzer MUST report each parameter of a method, constructor, delegate, indexer, operator, or conversion operator declaration, and each parameter of the primary constructor of a class, struct, record, or record struct declaration, that is not documented as SHARED-DOC-012 specifies, unless SHARED-DOC-011 exempts the declaration. A method declaration includes the methods of an interface and of an extension block; local functions, lambdas, and anonymous methods are not checked. The declaration's accessibility does not matter. The analyzer MUST NOT report the parameters of a declaration that explicitly implements an interface member, which SHARED-DOC-009 exempts, and nothing is reported when SHARED-DOC-008 applies.

This requirement covers what SHARED-DOC-011 and SHARED-DOC-012 cover. A part of a partial element declared in several parts, and the `__arglist` of a parameter list, are not covered.

Why: The parameters are part of the declaration's contract, and the `<param>` description is what the editor shows for an argument while the caller writes it. A declaration without any documentation comment is left to the rules that require a summary, so it gets one diagnostic there instead of one on every parameter. An explicit implementation is described by the interface member it implements, parameters included.

Example:

```csharp
/// <summary>
/// Point
/// </summary>
/// <param name="X">X</param>
public record Point(int X, int {|RH8101:Y|});

/// <summary>
/// Handler
/// </summary>
public delegate void Handler(int {|RH8101:value|});

/// <summary>
/// Contract
/// </summary>
public interface I
{
    /// <summary>
    /// Runs
    /// </summary>
    /// <param name="value">Value</param>
    void Run(int value);
}

/// <summary>
/// Service
/// </summary>
public class C : I
{
    /// <summary>
    /// Creates
    /// </summary>
    public C(int {|RH8101:size|})
    {
    }

    /// <summary>
    /// Runs
    /// </summary>
    /// <param name="a">A</param>
    private void M(int a, int {|RH8101:b|})
    {
    }

    public void N(int a)
    {
    }

    /// <inheritdoc/>
    public void O(int a)
    {
    }

    /// <summary>
    /// Runs
    /// </summary>
    void I.Run(int value)
    {
    }

    /// <summary>
    /// Item
    /// </summary>
    public int this[int {|RH8101:index|}] => 0;

    /// <summary>
    /// Adds
    /// </summary>
    /// <param name="left">Left</param>
    /// <returns>Sum</returns>
    public static C operator +(C left, C {|RH8101:right|}) => left;

    /// <summary>
    /// Converts
    /// </summary>
    /// <returns>Value</returns>
    public static implicit operator int(C {|RH8101:value|}) => 0;

    private void P()
    {
        void Local(int value)
        {
        }
    }
}

/// <summary>
/// Extensions
/// </summary>
public static class Extensions
{
    /// <summary>
    /// Text values
    /// </summary>
    /// <param name="value">Value</param>
    extension(string value)
    {
        /// <summary>
        /// Counts
        /// </summary>
        public int Count(char {|RH8101:c|}) => 0;
    }
}
```

### RH8101-002 — The diagnostic is on the parameter name

The analyzer MUST report one diagnostic per undocumented parameter, located on its identifier.

Why: The name is what the `<param>` element has to repeat, so marking it shows what is missing.

Example: see RH8101-001.
