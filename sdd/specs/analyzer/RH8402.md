# Analyzer — RH8402 Files must start with configured copyright header

| | |
|---|---|
| ID prefix | RH8402 |
| Status | Active |
| Category | Documentation |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH8402FileMustStartWithConfiguredXmlStyleCopyrightHeaderAnalyzer`, `RH8402FileMustStartWithConfiguredXmlStyleCopyrightHeaderCodeFixProvider` |
| Uses | RH0001-001, RH0001-006 |

RH8402 reports a file that does not start with the copyright header configured in `reihitsu.json`, and offers a code fix that writes the header at the start of the file.

## Non-goals

- Loading and validating the configuration file, and the problems found in it — RH0001.
- Comments after the header, and the documentation of the declarations in the file.

## Requirements

All examples use this configuration, and the checked file is named `C.cs`:

```json
{
  "copyright": {
    "copyrightText": "// <copyright file=\"{fileName}\" company=\"{company}\">\n// Copyright (c) {company}.\n// </copyright>",
    "company": "Example"
  }
}
```

### RH8402-001 — Nothing is checked without a valid configured header

The analyzer MUST check files only when the configuration that RH0001-001 loads has a `copyright` section whose `copyrightText` is not empty or only white space, and RH0001 finds no problem in the configuration. Without a configuration, without a `copyright` section, or with any problem in the configuration, nothing is reported.

Why: The rule enforces a header that the project chose; without one there is nothing to compare. A configuration with problems is reported by RH0001, and comparing files against a header that may be wrong would only add misleading diagnostics.

Example — without `reihitsu.json`,

```csharp
namespace N;

class C
{
}
```

is not reported.

### RH8402-002 — The expected header is the configured text with its placeholders filled in

The analyzer MUST derive the expected header from `copyrightText` by replacing every placeholder `{name}` that has a setting of that name in the `copyright` section, as RH0001-006 specifies, with the setting's value, and the placeholder `{fileName}` with the name of the checked file, without its directory. Every line break of the header MUST be written as the first line break of the file, or as `\n` when the file has none.

Why: A header that names the file and the company is written once in the configuration and stays correct for every file. Comparing in the file's own line ending keeps a CRLF file from being reported only because the configuration is written with `\n`.

Example:

```csharp
// <copyright file="C.cs" company="Example">
// Copyright (c) Example.
// </copyright>
namespace N;

class C
{
}
```

is not reported.

### RH8402-003 — A file that does not start with the header is reported

The analyzer MUST report a file whose text does not start with the expected header, compared character by character and case-sensitively. Anything in front of the header counts, a blank line or white space included, and so does an empty file.

This requirement covers a syntax tree whose documentation mode is `Parse` or `Diagnose`, and a file in which the expected header is followed by a line break or by the end of the file.

Why: The header states the file's ownership and licence terms in the agreed words. A header with different words, a different company, or another file name states something else, and one that does not start the file is easily missed.

Example:

```csharp
{|RH8402:|}namespace N;

class C
{
}
```

```csharp
{|RH8402:|}// <copyright file="Other.cs" company="Example">
// Copyright (c) Example.
// </copyright>
namespace N;
```

```csharp
{|RH8402:|}
// <copyright file="C.cs" company="Example">
// Copyright (c) Example.
// </copyright>
namespace N;
```

### RH8402-004 — The diagnostic is at the start of the file

The analyzer MUST report one diagnostic per file, as an empty span at the start of the file.

Why: The header belongs at the start, and a missing header has no text to mark.

Example: see RH8402-003.

### RH8402-005 — The fix writes the header at the start of the file

The code fix MUST write the expected header at the start of the file. When text follows the header and does not start with a line break, the fix MUST put a line break, in the line ending of the file's first line, or `\n` when the file has only one line, between the header and that text. Where the header goes depends on what starts the file:

- when the file starts with comments, none of which contains the word `copyright` in any casing, the header is inserted in front of them;
- when the file starts with a comment that contains that word, the header replaces it;
- otherwise the header replaces the white space and line breaks in front of the first token, and is written in front of a preprocessor directive or a documentation comment that starts the file.

This requirement covers a file whose comment that contains the word `copyright` is the only comment in front of the first token and is followed directly by the first token or directive on the next line.

Why: A comment that mentions copyright is the old header, so the configured one takes its place. Any other comment is the author's note and stays below the new header.

Example:

```csharp
{|RH8402:|}namespace N;
```

```csharp
// <copyright file="C.cs" company="Example">
// Copyright (c) Example.
// </copyright>
namespace N;
```

Example — an old header is replaced:

```csharp
{|RH8402:|}// Copyright (c) Old Company.
namespace N;
```

```csharp
// <copyright file="C.cs" company="Example">
// Copyright (c) Example.
// </copyright>
namespace N;
```

Example — another comment is kept below the header:

```csharp
{|RH8402:|}// Orders and invoices
namespace N;
```

```csharp
// <copyright file="C.cs" company="Example">
// Copyright (c) Example.
// </copyright>
// Orders and invoices
namespace N;
```
