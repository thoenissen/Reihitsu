# Analyzer — RH8501 Code analysis suppressions must have a justification

| | |
|---|---|
| ID prefix | RH8501 |
| Status | Active |
| Category | Documentation |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH8501CodeAnalysisSuppressionMustHaveJustificationAnalyzer` |
| Uses | — |

RH8501 reports a `SuppressMessage` attribute that has no `Justification`, or whose `Justification` has no text.

## Non-goals

- Suppressions through `#pragma warning disable`, `.editorconfig`, or a ruleset.

## Requirements

### RH8501-001 — A suppression without a justification is reported

The analyzer MUST report an attribute that binds to `System.Diagnostics.CodeAnalysis.SuppressMessageAttribute` and has no named argument `Justification`, however the attribute is written — as `SuppressMessage` or `SuppressMessageAttribute`, qualified, through a using alias — and whatever it targets, an assembly or a module included. An attribute of the same name that binds to another type MUST NOT be reported.

This requirement covers `SuppressMessageAttribute` only; `UnconditionalSuppressMessageAttribute` is not covered.

Why: A suppression turns a warning off for good. Without a stated reason, the next reader cannot tell whether the warning was examined and dismissed or only silenced, nor whether the reason still holds after the code has changed.

Example:

```csharp
using System.Diagnostics.CodeAnalysis;
using Suppress = System.Diagnostics.CodeAnalysis.SuppressMessageAttribute;

[assembly: {|RH8501:SuppressMessage|}("Design", "CA1000", Scope = "member", Target = "~M:C.M")]

namespace Other
{
    public class SuppressMessageAttribute : System.Attribute
    {
        public SuppressMessageAttribute(string category, string checkId)
        {
        }
    }
}

class C
{
    [{|RH8501:SuppressMessage|}("Design", "CA1000")]
    void M()
    {
    }

    [{|RH8501:System.Diagnostics.CodeAnalysis.SuppressMessageAttribute|}("Design", "CA1000", MessageId = "Id")]
    void N()
    {
    }

    [{|RH8501:Suppress|}("Design", "CA1000")]
    void O()
    {
    }

    [Other.SuppressMessage("Design", "CA1000")]
    void P()
    {
    }
}
```

### RH8501-002 — A justification without text is reported

The analyzer MUST report the attribute when the value of its `Justification` argument is `null`, empty, or only white space. A constant expression that yields text — a literal, a constant, a concatenation, or `nameof` — MUST NOT be reported.

This requirement covers a justification that is not the text `<Pending>`.

Why: An empty justification satisfies the attribute's shape but states no reason, so it hides the missing reason instead of giving one. A constant lets several suppressions share one stated reason.

Example:

```csharp
using System.Diagnostics.CodeAnalysis;

class C
{
    const string Reason = "Validated by the caller.";
    const string Empty = "";

    [{|RH8501:SuppressMessage|}("Design", "CA1000", Justification = "")]
    void M()
    {
    }

    [{|RH8501:SuppressMessage|}("Design", "CA1000", Justification = "   ")]
    void N()
    {
    }

    [{|RH8501:SuppressMessage|}("Design", "CA1000", Justification = null)]
    void O()
    {
    }

    [{|RH8501:SuppressMessage|}("Design", "CA1000", Justification = Empty)]
    void P()
    {
    }

    [SuppressMessage("Design", "CA1000", Justification = Reason)]
    void Q()
    {
    }

    [SuppressMessage("Design", "CA1000", Justification = "Validated " + "by the caller.")]
    void R()
    {
    }
}
```

### RH8501-003 — The diagnostic is on the attribute's name

The analyzer MUST report one diagnostic per attribute, located on the attribute's name as written, including its qualification.

Why: The name identifies the suppression among the attributes of a list; the missing argument has no text to mark.

Example: see RH8501-001.
