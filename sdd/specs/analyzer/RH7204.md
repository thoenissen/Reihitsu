# Analyzer — RH7204 Using alias directives must be ordered alphabetically by alias name

| | |
|---|---|
| ID prefix | RH7204 |
| Status | Active |
| Category | Organization |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH7204UsingAliasDirectivesMustBeOrderedAlphabeticallyByAliasNameAnalyzer`, `RH7204UsingAliasDirectivesMustBeOrderedAlphabeticallyByAliasNameCodeFixProvider` |
| Uses | SHARED-USING-004, SHARED-USING-007, SHARED-USING-009, FMT-USING-001, FMT-USING-002, FMT-USING-003, FMT-USING-005, FMT-USING-006, FMT-USING-007, FMT-USING-008, FMT-USING-009 |

RH7204 reports an alias directive whose alias name sorts before the alias of its group directly above it, and offers a code fix that organizes the whole using block.

## Non-goals

- The position of aliases after the other directives — RH7202 — and the order of the alias groups — RH7207.
- The canonical order and grouping of using directives — SHARED-USING — and how the formatter lays out a reordered block — FMT-USING.

## Requirements

### RH7204-001 — An alias sorted before its neighbor is reported

The analyzer MUST report every alias directive that directly follows an alias directive of the same group (SHARED-USING-004) and whose alias name sorts before that directive's, compared as SHARED-USING-007 specifies, when SHARED-USING-009 allows the block to be reordered. The group of an alias is decided by the root namespace of its target.

Why: When aliases are sorted by the name they introduce, the one a reader needs is easy to find. Grouping them by their target keeps an alias next to the library it points into.

Example:

```csharp
using b = System.Text;
using {|RH7204:A|} = System.IO;

using Beta = Microsoft.CodeAnalysis.SyntaxNode;
using {|RH7204:Alpha|} = Microsoft.CodeAnalysis.SyntaxToken;

class C
{
}
```

and the global section is checked on its own:

```csharp
global using B = System.Text;
global using {|RH7204:A|} = System.IO;

using C2 = System.Text;

class C
{
}
```

and a block with a preprocessor directive is not reported (SHARED-USING-009):

```csharp
using B = System.Text;
#if DEBUG
using System.Diagnostics;
#endif
using A = System.IO;

class C
{
}
```

### RH7204-002 — Aliases of other groups and other kinds are not reported

The analyzer MUST NOT report an alias directive whose neighbor alias belongs to another group, and MUST NOT report a regular or `using static` directive.

Why: The order of the alias groups is RH7207's decision, and the other kinds are ordered by RH7203 and RH7206.

Example:

```csharp
using X = Microsoft.CodeAnalysis.SyntaxNode;
using A = System.IO;

using System.Linq;
using System;

class C
{
}
```

is not reported by RH7204.

### RH7204-003 — The diagnostic is on the alias name

The analyzer MUST report one diagnostic per reported directive, located on its alias identifier.

Why: The alias name is the sort key, and one diagnostic per directive shows each one that is out of order.

Example: see RH7204-001.

### RH7204-004 — The fix organizes the whole block

The code fix MUST rewrite the whole using block that contains the reported directive as the formatter's using-directive phase does: into the canonical order (FMT-USING-001), with exactly one blank line between two groups and none inside a group (FMT-USING-002), with one directive per line (FMT-USING-003), and with comments placed as FMT-USING-005, FMT-USING-006, FMT-USING-007, FMT-USING-008, and FMT-USING-009 specify. It MUST NOT change anything outside the block.

Why: A block has one organized form, shared by the formatter and the seven using-ordering rules RH7201–RH7207. Producing it in one step corrects every diagnostic those rules report in the block at once, so their fixes never undo each other. The code after the block is not the finding.

Example:

```csharp
using b = System.Text;
using {|RH7204:A|} = System.IO;

class C
{
}
```

```csharp
using A = System.IO;
using b = System.Text;

class C
{
}
```
