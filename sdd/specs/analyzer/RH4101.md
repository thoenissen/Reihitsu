# Analyzer — RH4101 Enum member casing

| | |
|---|---|
| ID prefix | RH4101 |
| Status | Active |
| Category | Naming |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH4101EnumMemberCasingAnalyzer`, `RH4101EnumMemberCasingCodeFixProvider` |
| Uses | SHARED-CASING-001, SHARED-CASING-006, SHARED-CASING-007, SHARED-CASING-008, SHARED-CASING-009, SHARED-CASING-010 |

RH4101 reports an enum member whose name is not in PascalCase and offers a code fix that renames the member and every reference to it.

## Non-goals

- The name of the enum itself — RH4004.

## Requirements

### RH4101-001 — Enum member names are in PascalCase

The analyzer MUST report every enum member whose name is not in PascalCase as SHARED-CASING-001 defines it, with one diagnostic per member, located on its identifier.

Why: Enum members are public constants of their type; .NET names them in PascalCase, like other constants.

Example:

```csharp
public enum Status
{
    {|RH4101:active|},
    Valid,
    {|RH4101:in_progress|},
    {|RH4101:_readAccess|}
}
```

### RH4101-002 — The fix renames the enum member to PascalCase

The code fix MUST rename the member and every reference to it (SHARED-CASING-007) to the PascalCase name that SHARED-CASING-006 derives from its old name. It is withheld as SHARED-CASING-008 and SHARED-CASING-009 specify, and its Fix All skips colliding names as SHARED-CASING-010 specifies.

Why: The fix makes exactly the change the diagnostic asks for, and a member is referenced wherever its value is used.

Example:

```csharp
public enum OrderState
{
    {|RH4101:created|},
    {|RH4101:in_progress|},
    {|RH4101:_readAccess|}
}

public class C
{
    public OrderState State = OrderState.created;
}
```

```csharp
public enum OrderState
{
    Created,
    InProgress,
    ReadAccess
}

public class C
{
    public OrderState State = OrderState.Created;
}
```
