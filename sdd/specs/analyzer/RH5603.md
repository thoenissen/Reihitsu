# Analyzer — RH5603 File must not end with a newline

| | |
|---|---|
| ID prefix | RH5603 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5603FileMustNotEndWithANewlineAnalyzer`, `RH5603FileMustNotEndWithANewlineCodeFixProvider` |
| Uses | FMT-CLEAN-005, FMT-CLEAN-006, SHARED-FIX-001 |

RH5603 reports the line breaks at the end of a file, together with the whitespace-only lines between them, and offers a code fix that deletes them so the file ends with its last character.

In the examples, a code block ends where the file ends: an empty last line in a block is a line break at the end of the file, `␍` marks a carriage return, and `·` a space.

## Non-goals

- Blank lines at the start of a file — RH5028.
- Whitespace at the end of the last line that holds code or a comment, and the whitespace of a last line that ends without a line break — RH5602.
- Which line ending the file uses — RH5604.

## Requirements

### RH5603-001 — Line breaks at the end of the file are reported

The analyzer MUST report a file whose text ends with one or more line breaks, whether `\n`, `\r\n`, or a mix, when the last non-whitespace character before them is the last character of a code token — a token outside directives and documentation comments — or of a `//` or `/* */` comment that is not on a directive line. The line breaks at the end of the file are every line break after that character; a line between them that holds whitespace only belongs to them.

Why: Whether a file ends with a line break is invisible in an editor and drifts from file to file; settling it in one direction removes a recurring, content-free diff. The formatter writes the same end of file (FMT-CLEAN-005, FMT-CLEAN-006).

Example:

```csharp
class C
{
}{|RH5603:

|}
```

A comment on the last line counts like code:

```csharp
class C
{
}

// end{|RH5603:
|}
```

Whitespace-only lines between the trailing line breaks belong to them:

```csharp
class C
{
}{|RH5603:
···
|}
```

Whitespace behind the last character on its own line does not; it stays RH5602's:

```csharp
class C
{
}··{|RH5603:
|}
```

### RH5603-002 — A file that ends with its last character is not reported

The analyzer MUST NOT report a file whose last character is the last character of a code token or of a `//` or `/* */` comment that is not on a directive line, and MUST NOT report line breaks inside the file, such as blank lines before its last line.

Why: Only the end of the file is decided by this rule; blank lines elsewhere belong to the blank-line rules.

Example:

```csharp
class C
{
}

// end
```

is not reported.

### RH5603-003 — One diagnostic on the trailing line breaks

The analyzer MUST report one diagnostic per file, located on the whole run of line breaks at its end, from the first line break after the last non-whitespace character to the end of the file, the whitespace-only lines among them included.

Why: The run is removed as one piece; a file has only one end.

Example: see RH5603-001, where the two line breaks after `}` are one diagnostic, and so are the two line breaks after `}` with the line of three spaces between them.

### RH5603-004 — The fix deletes the trailing line breaks

The code fix MUST delete the reported line breaks and the whitespace-only lines among them in one application (SHARED-FIX-001), so the file ends with the line that holds the last non-whitespace character, and MUST NOT change anything else. Whitespace behind that character on its line stays.

Why: The fix answers exactly what the diagnostic reports. Deleting only the last line break would leave a line break and a line of whitespace behind the last character, the same tail in another shape; the formatter removes that tail as a whole (FMT-CLEAN-005), and so does the fix.

Example:

```csharp
class C␍
{␍
}{|RH5603:␍
␍
|}
```

```csharp
class C␍
{␍
}
```

With a whitespace-only line in the tail, and with whitespace behind the last character:

```csharp
class C
{
}{|RH5603:
···
|}
```

```csharp
class C
{
}
```

```csharp
class C
{
}··{|RH5603:
|}
```

```csharp
class C
{
}··
```
