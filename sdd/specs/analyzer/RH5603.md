# Analyzer — RH5603 File must not end with a newline

| | |
|---|---|
| ID prefix | RH5603 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5603FileMustNotEndWithANewlineAnalyzer`, `RH5603FileMustNotEndWithANewlineCodeFixProvider` |
| Uses | FMT-CLEAN-005, FMT-CLEAN-006 |

RH5603 reports the line breaks at the end of a file, and offers a code fix that deletes them so the file ends with its last character.

In the examples, a code block ends where the file ends: an empty last line in a block is a line break at the end of the file, and `␍` marks a carriage return.

## Non-goals

- Blank lines at the start of a file — RH5028.
- Whitespace at the end of the last line — RH5602.
- Which line ending the file uses — RH5604.

## Requirements

### RH5603-001 — Line breaks at the end of the file are reported

The analyzer MUST report a file whose text ends with one or more line breaks, whether `\n`, `\r\n`, or a mix, when the character before them is the last character of a code token — a token outside directives and documentation comments — or of a `//` or `/* */` comment.

Why: Whether a file ends with a line break is invisible in an editor and drifts from file to file; settling it in one direction removes a recurring, content-free diff. The formatter writes the same end of file (FMT-CLEAN-005, FMT-CLEAN-006).

Example:

```csharp
class C
{
}{|RH5603:

|}
```

A comment on the last line counts like code:

```csharp
class C
{
}

// end{|RH5603:
|}
```

### RH5603-002 — A file that ends with its last character is not reported

The analyzer MUST NOT report a file whose last character is the last character of a code token or of a `//` or `/* */` comment, and MUST NOT report line breaks inside the file, such as blank lines before its last line.

Why: Only the end of the file is decided by this rule; blank lines elsewhere belong to the blank-line rules.

Example:

```csharp
class C
{
}

// end
```

is not reported.

### RH5603-003 — One diagnostic on the trailing line breaks

The analyzer MUST report one diagnostic per file, located on the whole run of line breaks at its end.

Why: The run is removed as one piece; a file has only one end.

Example: see RH5603-001, where the two line breaks after `}` are one diagnostic.

### RH5603-004 — The fix deletes the trailing line breaks

The code fix MUST delete the reported line breaks, so the file ends with the character before them, and MUST NOT change anything else.

Why: The fix answers exactly what the diagnostic reports.

Example:

```csharp
class C␍
{␍
}{|RH5603:␍
␍
|}
```

```csharp
class C␍
{␍
}
```
