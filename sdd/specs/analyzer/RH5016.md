# Analyzer — RH5016 unchecked-Statement should be preceded by a blank line

| | |
|---|---|
| ID prefix | RH5016 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5016UncheckedStatementsShouldBePrecededByABlankLineAnalyzer`, `RH5016UncheckedStatementsShouldBePrecededByABlankLineCodeFixProvider` |
| Uses | SHARED-STMT-001, SHARED-STMT-002, SHARED-STMT-003, SHARED-STMT-004 |

RH5016 reports an `unchecked` statement that follows another statement of the same block or switch section without a blank line between them, and offers a code fix that inserts one as SHARED-STMT-004 specifies.

## Non-goals

- Blank lines before other statement kinds — the other rules that use `shared/statement-blank-lines.md`.

## Requirements

### RH5016-001 — An `unchecked` statement that follows a statement needs a blank line

The analyzer MUST report an `unchecked` statement as SHARED-STMT-001, SHARED-STMT-002, and SHARED-STMT-003 specify. It MUST NOT report a `checked` statement or an `unchecked` expression.

Why: An `unchecked` statement opens a block without overflow checking; the blank line marks where that context begins. An `unchecked` expression is part of the statement that contains it.

Example:

```csharp
class C
{
    void M(int a)
    {
        a++;
        {|RH5016:unchecked|}
        {
            a++;
        }

        a++;
        checked
        {
            a--;
        }

        a++;
        a = unchecked(a + 1);
    }
}
```

The `checked` statement belongs to RH5015, and `unchecked(a + 1)` is an expression; RH5016 reports neither.

### RH5016-002 — The diagnostic is on the `unchecked` keyword

The analyzer MUST report the diagnostic on the `unchecked` keyword.

Why: The keyword is where the missing separator becomes visible.

Example: see RH5016-001.
