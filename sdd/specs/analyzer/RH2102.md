# Analyzer — RH2102 Classes should not use parameterized primary constructors

| | |
|---|---|
| ID prefix | RH2102 |
| Status | Active |
| Category | Design |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH2102ClassesShouldNotUseParameterizedPrimaryConstructorsAnalyzer` |
| Uses | — |

RH2102 reports a class declaration whose primary constructor has parameters.

## Non-goals

- Structs — RH2103.
- Records and record structs. Their positional parameter list declares their members.
- A code fix. Moving the parameters into an explicit constructor needs fields or properties whose names and kinds only the author can decide.

## Requirements

### RH2102-001 — A class with primary-constructor parameters is reported

The analyzer MUST report a class declaration whose primary constructor has at least one parameter, whether the class is nested, `partial`, or generic. A class whose primary constructor has no parameters, `class C()`, and a class without a primary constructor MUST NOT be reported. A record MUST NOT be reported.

Why: The parameters of a primary constructor are captured wherever the class body uses them, so the type header hides how the object is initialized and which state it keeps. An explicit constructor shows both. An empty parameter list captures nothing.

Example:

```csharp
class {|RH2102:Service|}(int id)
{
    public int Id => id;
}

class Empty()
{
}

class Plain
{
}

partial class {|RH2102:Part|}(int value)
{
}

record Point(int X);

class Outer
{
    class {|RH2102:Inner|}(int value)
    {
    }
}
```

### RH2102-002 — The diagnostic is on the class name

The analyzer MUST report one diagnostic per reported class declaration, located on its identifier.

Why: The name identifies the type whose header carries the parameters; the parameter list itself may span several lines.

Example: see RH2102-001.
