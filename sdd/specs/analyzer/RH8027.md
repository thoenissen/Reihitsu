# Analyzer — RH8027 Private fields must be documented

| | |
|---|---|
| ID prefix | RH8027 |
| Status | Active |
| Category | Documentation |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH8027PrivateFieldsMustBeDocumentedAnalyzer` |
| Uses | SHARED-DOC-001, SHARED-DOC-002, SHARED-DOC-004, SHARED-DOC-005, SHARED-DOC-006, SHARED-DOC-007, SHARED-DOC-008 |

RH8027 reports a field declaration in the private group that has no `<summary>` or `<inheritdoc>` documentation.

## Non-goals

- Fields in the non-private group — RH8026.
- Field-like events — RH8028 and RH8029.
- Whether the summary has text — RH8030.

## Requirements

### RH8027-001 — Undocumented private fields are reported

The analyzer MUST report every field declaration in the private group of SHARED-DOC-002 that is not documented, checked as SHARED-DOC-001 specifies. A field declaration is a declaration of one or more fields in the body of a class, struct, interface, record, or record struct — constant, static, and read-only fields included; a field-like event and an enum member are not ones. A declaration of several fields is one declaration, documented by the documentation comments before it. Whether it is documented MUST be decided as SHARED-DOC-004, SHARED-DOC-005, SHARED-DOC-006, and SHARED-DOC-007 specify, and nothing is reported when SHARED-DOC-008 applies.

Why: A private field is state that outlives every call, and its type and name rarely say what is stored, when the value is valid, or which code may change it. The summary is the one place where that is recorded. It has a rule of its own, so a project can require documentation for what other code uses without requiring it here.

Example:

```csharp
/// <summary>
/// Counters
/// </summary>
public class Counters
{
    private int {|RH8027:_current|};

    /// <remarks>
    /// No summary
    /// </remarks>
    static readonly int {|RH8027:_maximum|} = 10;

    private const int {|RH8027:Limit|} = 5;

    private int {|RH8027:_first|}, _second;

    /// <summary>
    /// The total count
    /// </summary>
    private int _total;

    private protected int Shared;

    private event System.Action Changed;
}

/// <summary>
/// Point
/// </summary>
public struct Point
{
    int {|RH8027:_x|};
}
```

### RH8027-002 — The diagnostic is on the name of the first field

The analyzer MUST report one diagnostic per undocumented field declaration, located on the identifier of the first field it declares.

Why: The documentation comment covers the whole declaration, so one diagnostic is enough, and the first name identifies the declaration without marking its initializers.

Example: see RH8027-001.
