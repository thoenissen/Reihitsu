# Analyzer — RH2111 Types should not exceed the line limit

| | |
|---|---|
| ID prefix | RH2111 |
| Status | Active |
| Category | Design |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH2111TypesShouldNotExceedTheLineLimitAnalyzer` |
| Uses | RH0001-001, RH0001-007, SHARED-DIAG-004, SHARED-DIAG-007, SHARED-LINES-001, SHARED-LINES-002, SHARED-LINES-003 |

RH2111 reports a type declaration whose body holds more lines of code than its limit allows: 500 lines in production code and 1000 in test code, unless the `design` section of the `reihitsu.json` configuration file sets other limits.

The examples are production code (SHARED-LINES-003) unless they say otherwise.

## Non-goals

- Loading and validating the configuration file and the `design` section — RH0001 (RH0001-007).
- Telling test code from production code — SHARED-LINES-003.
- The size of a method or another member with a body — RH2008.
- Enum declarations, whose body is a list of named values, and delegate declarations, which have no body.
- Extension blocks (`extension(…) { … }`), which are members of their type; their lines count toward the type that holds them.
- The total size of a partial type across its parts (RH2111-004).
- The length of a file, which can hold several types or none.

## Requirements

### RH2111-001 — The limits are `design.maximumTypeLines` and `design.maximumTestTypeLines`

The analyzer MUST take the limit of a type declaration in production code from the setting `design.maximumTypeLines`, with the default 500, and the limit of a type declaration in test code (SHARED-LINES-003) from the setting `design.maximumTestTypeLines`, with the default 1000, of the configuration that RH0001-001 loads, valid as RH0001-007 specifies, and MUST compare each judged type declaration with its limit as SHARED-LINES-002 specifies.

Why: Most types stay far below 500 lines of code, so a longer one stands out; a test class usually holds one test per case of the type it tests, with the inputs written out, and runs longer, so its default is higher. A project that wants other limits sets them; RH0001 validates the settings, and SHARED-LINES-002 states when a default applies and how the count is compared.

Example: see RH2111-002; without a `reihitsu.json`, `C` and `S` there are not reported, since their counts lie below both defaults.

### RH2111-002 — A type is judged by the lines between its braces

The analyzer MUST judge every class, struct, interface, record, record struct, and union declaration that has a brace body, and MUST count the lines of code (SHARED-LINES-001) of the tokens between its opening and its closing brace. The declaration's attributes, modifiers, keyword, name, type parameters, parameter list, base list, constraint clauses, and its braces MUST NOT be counted. Documentation comments, comments, and directives such as `#region` and `#endregion` in the body are trivia and are not counted (SHARED-LINES-001).

Why: The body is what a reader works through to understand what the type does; the header is read at a glance and does not grow with what the type holds. Regions, comments, and documentation organize and explain the members without adding to them, and counting them would make the rule punish a well-documented type. A union is a type declaration like a struct, with members in its body.

Example — with `{ "design": { "maximumTypeLines": 4 } }`; the body of `C` holds six lines of code — the field, the four lines of `Get`, and the line of `Set` — and the body of `S` four:

```csharp
class {|RH2111:C|}
{
    #region Fields

    /// <summary>
    /// Value
    /// </summary>
    private int _value;

    #endregion // Fields

    #region Methods

    public int Get()
    {
        return _value;
    }

    public void Set(int value) => _value = value;

    #endregion // Methods
}

struct S
{
    public int X;
    public int Y;
    public int Z;
    public int W;
}
```

### RH2111-003 — A nested type counts toward the type that holds it

The lines of code of a type declared in the body of another type MUST count toward the body of that type, and the nested type MUST in addition be judged on its own by the lines of its own body.

Why: A reader of the outer type reads the types declared inside it; moving members into a nested type keeps the outer declaration exactly as long as it was. The nested type is still a type of its own, so its own size is judged too.

Example — with `{ "design": { "maximumTypeLines": 3 } }`; the body of `Outer` holds five lines of code — the line of `class Inner`, the two lines of its braces, and its two fields — and the body of `Inner` holds two:

```csharp
class {|RH2111:Outer|}
{
    class Inner
    {
        public int A;
        public int B;
    }
}
```

### RH2111-004 — Each part of a partial type is judged on its own

The analyzer MUST judge each part of a type declared with the `partial` modifier by the lines of its own body, and MUST NOT add the lines of the other parts. Each part over the limit MUST be reported, located on that part. This is a verdict on the members that one part holds, which SHARED-DIAG-004 does not join across parts.

Why: A reader opens one part in one file and reads the members it holds; the parts of a type are usually split so that each stays readable. Summing them would report a part that is short on its own and offer no place to act on, since no single part is too long.

Example — with `{ "design": { "maximumTypeLines": 2 } }`; the first part holds three lines of code, the second two:

```csharp
partial class {|RH2111:C|}
{
    public int A;
    public int B;
    public int C1;
}

partial class C
{
    public int D;
    public int E;
}
```

### RH2111-005 — A type without a brace body is not reported

The analyzer MUST NOT report a type declaration that ends with `;` instead of a brace body, such as `record R(int X);` or `class C;`.

Why: A declaration without a body holds no members to count; its parameter list is part of its header.

Example — with `{ "design": { "maximumTypeLines": 1 } }`:

```csharp
record R(int X, int Y, int Z);
```

is not reported.

### RH2111-006 — One diagnostic per declaration, located on its name

The analyzer MUST report one diagnostic for each judged type declaration whose count exceeds the limit, located on the identifier of the type.

Why: The name is where a reader looks for the type and where a suppression is placed (SHARED-DIAG-007).

Example: see RH2111-002 to RH2111-004.
