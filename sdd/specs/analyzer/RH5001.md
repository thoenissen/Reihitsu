# Analyzer — RH5001 try-Statement should be preceded by a blank line

| | |
|---|---|
| ID prefix | RH5001 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5001TryStatementsShouldBePrecededByABlankLineAnalyzer`, `RH5001TryStatementsShouldBePrecededByABlankLineCodeFixProvider` |
| Uses | SHARED-STMT-001, SHARED-STMT-002, SHARED-STMT-003, SHARED-STMT-004 |

RH5001 reports a `try` statement that follows another statement of the same block or switch section without a blank line between them, and offers a code fix that inserts one as SHARED-STMT-004 specifies.

## Non-goals

- Blank lines before other statement kinds — the other rules that use `shared/statement-blank-lines.md`.

## Requirements

### RH5001-001 — A `try` statement that follows a statement needs a blank line

The analyzer MUST report a `try` statement as SHARED-STMT-001, SHARED-STMT-002, and SHARED-STMT-003 specify.

Why: A `try` statement opens a protected region with its own error handling; the blank line marks where that region begins.

Example:

```csharp
class C
{
    void M(int a)
    {
        a++;
        {|RH5001:try|}
        {
            a--;
        }
        finally
        {
        }
    }

    void N(int a)
    {
        try
        {
        }
        catch
        {
        }
    }
}
```

The `try` in `N` is the first statement of its block and is not reported.

### RH5001-002 — The diagnostic is on the `try` keyword

The analyzer MUST report the diagnostic on the `try` keyword.

Why: The keyword is where the missing separator becomes visible, and the location stays stable when the protected block changes.

Example: see RH5001-001.
