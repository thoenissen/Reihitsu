# Analyzer — RH7206 Using static directives must be ordered alphabetically

| | |
|---|---|
| ID prefix | RH7206 |
| Status | Active |
| Category | Organization |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH7206UsingStaticDirectivesMustBeOrderedAlphabeticallyAnalyzer`, `RH7206UsingStaticDirectivesMustBeOrderedAlphabeticallyCodeFixProvider` |
| Uses | SHARED-USING-004, SHARED-USING-007, SHARED-USING-009, SHARED-USING-011, FMT-USING-001, FMT-USING-002, FMT-USING-003, FMT-USING-005, FMT-USING-006, FMT-USING-007, FMT-USING-008, FMT-USING-009, FMT-USING-010, FMT-USING-011, FMT-USING-012 |

RH7206 reports a `using static` directive whose type name sorts before an earlier static directive of its group, and offers a code fix that organizes the whole using block.

## Non-goals

- The position of static directives between the other kinds — RH7205 — and the order of the static groups — RH7207.
- The canonical order and grouping of using directives — SHARED-USING — and how the formatter lays out a reordered block — FMT-USING.

## Requirements

### RH7206-001 — A static directive sorted before an earlier one of its group is reported

The analyzer MUST report every `using static` directive whose type name sorts before the type name of any earlier `using static` directive of the same group (SHARED-USING-004) in the block, whatever directives of other groups or kinds lie between them, compared as SHARED-USING-007 specifies. The group and the sort key are taken from the type name's value (SHARED-USING-004).

Why: Alphabetical order makes a static import easy to find and keeps it consistent with the rest of the using block.

Example:

```csharp
using static System.Math;
using static {|RH7206:System.Console|};

using static Microsoft.CodeAnalysis.CSharp.SyntaxFacts;
using static {|RH7206:Microsoft.CodeAnalysis.CSharp.SyntaxFactory|};

class C
{
}
```

and a directive is compared with every earlier static directive of its group, whatever lies between them:

```csharp
using static Microsoft.CodeAnalysis.CSharp.SyntaxFacts;
using static Reihitsu.Core.CasingUtilities;
using static {|RH7206:Microsoft.CodeAnalysis.CSharp.SyntaxFactory|};

class C
{
}
```

```csharp
using static System.Math;
using static {|RH7206:System.Console|};
using static {|RH7206:System.Convert|};

class C
{
}
```

and the type name's value decides the group and the order, not its spelling:

```csharp
using static System . Math;
using static {|RH7206:System.Console|};

class C
{
}
```

```csharp
using static @System.Math;
using static {|RH7206:System.Console|};

class C
{
}
```

and a leading `global::` is not part of the sort key, so `global::System.Math` sorts as `System.Math`, after `System.Console`:

```csharp
using static global::System.Math;
using static {|RH7206:System.Console|};

class C
{
}
```

and whitespace inside a type-argument list is not part of the type name, so `Comparer<byte>` sorts before `Comparer< int >`:

```csharp
using static System.Collections.Generic.Comparer< int >;
using static {|RH7206:System.Collections.Generic.Comparer<byte>|};

class C
{
}
```

and a block with a preprocessor directive among its directives is reported as well, without a code fix (SHARED-USING-009); in a build that does not define `DEBUG`:

```csharp
using static System.Math;
#if DEBUG
using System.Diagnostics;
#endif
using static {|RH7206:System.Console|};

class C
{
}
```

### RH7206-002 — Static directives of other groups and other kinds are not reported

The analyzer MUST NOT report a `using static` directive because of a `using static` directive of another group, MUST NOT report one whose type name sorts before the type name of no earlier static directive of its group, and MUST NOT report a regular or alias directive.

Why: The order of the static groups is RH7207's decision, and the other kinds are ordered by RH7203 and RH7204.

Example:

```csharp
using static Microsoft.CodeAnalysis.CSharp.SyntaxFactory;
using static System.Console;

using B = System.Text;
using A = System.IO;

class C
{
}
```

is not reported by RH7206.

### RH7206-003 — The diagnostic is on the type name

The analyzer MUST report one diagnostic per reported directive, located on the type name it imports.

Why: The type name is the sort key, and one diagnostic per directive shows each one that is out of order.

Example: see RH7206-001.

### RH7206-004 — The fix organizes the whole block

The code fix MUST rewrite the whole using block that contains the reported directive as the formatter's using-directive phase does: into the canonical order (FMT-USING-001), with exactly one blank line between two groups and none inside a group other than the one kept above a comment that leads a directive (FMT-USING-002, FMT-USING-010), with one directive per line (FMT-USING-003), and with comments placed as FMT-USING-005, FMT-USING-006, FMT-USING-007, FMT-USING-008, and FMT-USING-009 specify, with the leading trivia of the block's original first directive kept at its top when that trivia holds a preprocessor directive (FMT-USING-012), and at the indentation FMT-USING-011 specifies. It MUST NOT change anything outside the block. No code fix is offered for a diagnostic in a block that SHARED-USING-009 forbids to reorder: a block with a preprocessor directive between two of its directives or between the tokens of one, or with disabled text in front of its first directive. A block whose preprocessor directives all stand in front of its first directive, with no disabled text there, is fixed.

Why: The formatter and the seven using-ordering rules RH7201–RH7207 organize a block the same way; where the organized form leaves a choice to the author, such as the blank line above a comment that leads a directive (SHARED-USING-011), they keep the author's. Producing it in one step corrects every diagnostic those rules report in the block at once, so their fixes never undo each other. The code after the block is not the finding.

Example:

```csharp
using static System.Math;
using static {|RH7206:System.Console|};

class C
{
}
```

```csharp
using static System.Console;
using static System.Math;

class C
{
}
```

and a block with a preprocessor directive in front of its first directive is fixed, with the directive at the top:

```csharp
#nullable enable
using static System.Math;
using static {|RH7206:System.Console|};

class C
{
}
```

```csharp
#nullable enable
using static System.Console;
using static System.Math;

class C
{
}
```
