# Analyzer — RH7206 Using static directives must be ordered alphabetically

| | |
|---|---|
| ID prefix | RH7206 |
| Status | Active |
| Category | Organization |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH7206UsingStaticDirectivesMustBeOrderedAlphabeticallyAnalyzer`, `RH7206UsingStaticDirectivesMustBeOrderedAlphabeticallyCodeFixProvider` |
| Uses | SHARED-USING-004, SHARED-USING-007, SHARED-USING-009, FMT-USING-001, FMT-USING-002, FMT-USING-003, FMT-USING-005, FMT-USING-006, FMT-USING-007, FMT-USING-008, FMT-USING-009 |

RH7206 reports a `using static` directive whose type name sorts before the static directive of its group directly above it, and offers a code fix that organizes the whole using block.

## Non-goals

- The position of static directives between the other kinds — RH7205 — and the order of the static groups — RH7207.
- The canonical order and grouping of using directives — SHARED-USING — and how the formatter lays out a reordered block — FMT-USING.

## Requirements

### RH7206-001 — A static directive sorted before its neighbor is reported

The analyzer MUST report every `using static` directive that directly follows a `using static` directive of the same group (SHARED-USING-004) and whose type name sorts before that directive's, compared as SHARED-USING-007 specifies, when SHARED-USING-009 allows the block to be reordered.

Why: Alphabetical order makes a static import easy to find and keeps it consistent with the rest of the using block.

Example:

```csharp
using static System.Math;
using static {|RH7206:System.Console|};

using static Microsoft.CodeAnalysis.CSharp.SyntaxFacts;
using static {|RH7206:Microsoft.CodeAnalysis.CSharp.SyntaxFactory|};

class C
{
}
```

and a block with a preprocessor directive is not reported (SHARED-USING-009):

```csharp
using static System.Math;
#if DEBUG
using System.Diagnostics;
#endif
using static System.Console;

class C
{
}
```

### RH7206-002 — Static directives of other groups and other kinds are not reported

The analyzer MUST NOT report a `using static` directive because of a `using static` directive of another group, and MUST NOT report a regular or alias directive.

Why: The order of the static groups is RH7207's decision, and the other kinds are ordered by RH7203 and RH7204.

Example:

```csharp
using static Microsoft.CodeAnalysis.CSharp.SyntaxFactory;
using static System.Console;

using B = System.Text;
using A = System.IO;

class C
{
}
```

is not reported by RH7206.

### RH7206-003 — The diagnostic is on the type name

The analyzer MUST report one diagnostic per reported directive, located on the type name it imports.

Why: The type name is the sort key, and one diagnostic per directive shows each one that is out of order.

Example: see RH7206-001.

### RH7206-004 — The fix organizes the whole block

The code fix MUST rewrite the whole using block that contains the reported directive as the formatter's using-directive phase does: into the canonical order (FMT-USING-001), with exactly one blank line between two groups and none inside a group (FMT-USING-002), with one directive per line (FMT-USING-003), and with comments placed as FMT-USING-005, FMT-USING-006, FMT-USING-007, FMT-USING-008, and FMT-USING-009 specify. It MUST NOT change anything outside the block.

Why: A block has one organized form, shared by the formatter and the seven using-ordering rules RH7201–RH7207. Producing it in one step corrects every diagnostic those rules report in the block at once, so their fixes never undo each other. The code after the block is not the finding.

Example:

```csharp
using static System.Math;
using static {|RH7206:System.Console|};

class C
{
}
```

```csharp
using static System.Console;
using static System.Math;

class C
{
}
```
