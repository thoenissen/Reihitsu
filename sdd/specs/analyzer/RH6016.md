# Analyzer — RH6016 Member access symbols must be spaced correctly

| | |
|---|---|
| ID prefix | RH6016 |
| Status | Active |
| Category | Spacing |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH6016MemberAccessSymbolsMustBeSpacedCorrectlyAnalyzer`, `RH6016MemberAccessSymbolsMustBeSpacedCorrectlyCodeFixProvider` |
| Uses | FMT-SPACE-006, FMT-SPACE-013, SHARED-GAP-001 |

RH6016 reports a member-access symbol with whitespace on either side on the same line, and offers a code fix that removes that whitespace.

In the examples, `→` marks a tab.

## Non-goals

- Other symbols between two names, such as the `::` of an alias-qualified name, the `..` of a range, and the `=>` of a lambda.
- Whether a member access of a chain starts its own line — the chain layout rules and the formatter.
- Dots inside documentation comment references, directives, and disabled text, which are not code tokens.

## Requirements

### RH6016-001 — Whitespace next to a member-access symbol on the same line is reported

The analyzer MUST report a member-access symbol — the dot of a member access (also in an extended property pattern), of a qualified name (also in a `using` directive or a namespace name), or of a member binding; the `?` that opens a conditional access (`?.` and `?[`); and the `->` of a pointer member access — when a space or tab is directly in front of it and the token before it ends on the same line, also when a comment sits between that token and the whitespace, or when spaces and tabs directly after it are followed by the next token on the same line.

Why: A member access is one name path; a space on either side of the symbol breaks the visual link between an expression and its member. The formatter removes the same whitespace (FMT-SPACE-006), also between a comment and the symbol (FMT-SPACE-013), so formatted code raises no RH6016.

Example:

```csharp
using System {|RH6016:.|} Text;

namespace N {|RH6016:.|} M;

class C
{
    string _t = "";

    unsafe void M(string s, int[] v, S* p)
    {
        _ = string {|RH6016:.|}Empty;
        _ = string{|RH6016:.|} Empty;
        _ = s→{|RH6016:.|}Length;
        _ = s /* note */ {|RH6016:.|}Length;
        _ = s {|RH6016:?|}.Length;
        _ = s?{|RH6016:.|} Length;
        _ = v {|RH6016:?|}[0];
        _ = p {|RH6016:->|} X;
        _ = global::System {|RH6016:.|} String.Empty;
        _ = $"{s {|RH6016:.|} Length}";
        _ = this is { _t {|RH6016:.|} Length: 1 };
    }
}

struct S
{
    public int X;
}
```

### RH6016-002 — A side across a line break and other `?` symbols are not reported

The analyzer MUST NOT report a member-access symbol that has no space or tab directly next to it on a side whose neighboring token is on the same line — for example when its only whitespace is on a side that wraps to another line, or when a comment ends directly in front of it and nothing follows it but the next token. The `?` of a conditional expression and the `?` of a nullable type MUST NOT be reported.

Why: A symbol at the start or end of a line is a layout choice, such as a wrapped method chain; its indentation is not a gap. When a comment ends directly in front of the symbol, no whitespace touches it. A conditional `?` is an operator between two operands, and a nullable `?` is part of a type name (RH6015).

Example:

```csharp
class C
{
    int M(string s)
    {
        _ = s
            .Length;
        _ = s.
            Length;
        _ = s
            ?.Length;
        _ = s /* note */.Length;
        int? n = null;

        return s == null ? 1 : 2;
    }
}
```

is not reported.

### RH6016-003 — One diagnostic per symbol

The analyzer MUST report one diagnostic per member-access symbol, located on the symbol, whether one side or both sides are spaced.

Why: The symbol is the token whose surroundings are wrong; one diagnostic per symbol keeps one fix per symbol.

Example: see RH6016-001, where the dots in `System . Text` and `N . M` are spaced on both sides and reported once each.

### RH6016-004 — The fix removes the whitespace on each reported side

The code fix MUST remove the whole gap between the symbol and its neighbor on each side that RH6016-001 reports. A side whose neighbor is on another line MUST NOT be changed, including the comment or directive on it.

Why: The fix answers exactly the question the diagnostic asks; a wrapped side belongs to the layout, not to the rule.

Example:

```csharp
using System {|RH6016:.|} Text;

class C
{
    unsafe void M(string s, int[] v, S* p)
    {
        _ = string {|RH6016:.|}Empty;
        _ = s {|RH6016:?|} {|RH6016:.|}Length;
        _ = v {|RH6016:?|}[0];
        _ = p {|RH6016:->|} X;
        _ = s {|RH6016:.|} // note
            Length;
        _ = s
            {|RH6016:.|} Length;
        _ = s {|RH6016:.|}
#if DEBUG
            Length;
#else
            Length;
#endif
    }
}

struct S
{
    public int X;
}
```

```csharp
using System.Text;

class C
{
    unsafe void M(string s, int[] v, S* p)
    {
        _ = string.Empty;
        _ = s?.Length;
        _ = v?[0];
        _ = p->X;
        _ = s. // note
            Length;
        _ = s
            .Length;
        _ = s.
#if DEBUG
            Length;
#else
            Length;
#endif
    }
}

struct S
{
    public int X;
}
```

The fix of the `?` in `s ? .Length` removes the gap before and after it, which also corrects the dot.

### RH6016-005 — A comment in a rewritten gap withholds the fix

The code fix MUST NOT be offered when a gap it rewrites contains a comment, as SHARED-GAP-001 specifies; a comment on a side the fix does not change MUST NOT withhold it.

Why: Removing the whitespace between a comment and the symbol would glue them; the author decides whether the comment stays there.

Example:

```csharp
class C
{
    int M(string s)
    {
        return s /* note */ {|RH6016:.|}Length;
    }
}
```

is reported, and no code fix is offered. In

```csharp
class C
{
    int M(string s)
    {
        return s /* note */{|RH6016:.|} Length;
    }
}
```

only the side after the dot is reported, and the fix produces `return s /* note */.Length;`.
