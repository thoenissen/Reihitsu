# Analyzer — RH5518 Field attribute lists must use one attribute per list

| | |
|---|---|
| ID prefix | RH5518 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5518FieldAttributeListsMustFollowShapeRulesAnalyzer`, `RH5518FieldAttributeListsMustFollowShapeRulesCodeFixProvider` |
| Uses | SHARED-ATTR-001, SHARED-ATTR-002, SHARED-ATTR-003, SHARED-ATTR-013, SHARED-ATTR-014, SHARED-ATTR-016, SHARED-ATTR-017, SHARED-ATTR-019 |

RH5518 reports an attribute list of a field or enum member that holds more than one attribute, and offers a code fix that gives each attribute a list of its own. The rule uses `shared/attribute-targets.md`.

## Non-goals

- Attributes of the enum itself — RH5510.
- A `field:` list on a positional record parameter — RH5524.
- Where a field attribute list is placed — RH5517.

## Requirements

### RH5518-001 — Field attribute lists hold one attribute

The analyzer MUST check every attribute list that resolves to the field target (SHARED-ATTR-001, SHARED-ATTR-002, SHARED-ATTR-003): the lists of a field declaration or an enum member without a specifier or with `type:`, and every list with the `field:` specifier that is not attached to a parameter or type parameter, and MUST report such a list that holds more than one attribute, as SHARED-ATTR-013 and SHARED-ATTR-014 specify.

Why: Fields are read as a block of short declarations, so a merged attribute list is the widest thing on the page; one attribute per line keeps each above the field it applies to.

Example:

```csharp
class C
{
    {|RH5518:[A, B]|}
    int _f;

    {|RH5518:[field: A, B]|}
    int P { get; set; }
}

enum E
{
    {|RH5518:[A, B]|}
    X
}

record R([field: A, B] int Id);
```

The `field:` list of the record parameter `Id` is not reported by RH5518.

### RH5518-002 — The diagnostic is on the attribute list

The analyzer MUST report the diagnostic on the attribute list, as SHARED-ATTR-016 specifies.

Why: The list is what has the wrong shape; each list of a declaration is reported and fixed on its own.

Example: see RH5518-001.

### RH5518-003 — The fix gives each attribute a list of its own

The code fix MUST replace the list with one list per attribute, each on its own line, as SHARED-ATTR-017 specifies.

Why: The fix makes only the change the diagnostic asks for: the attributes keep their order and their specifier, and each gets a line of its own.

Example:

```csharp
class C
{
    {|RH5518:[A, B]|}
    int _f;
}
```

```csharp
class C
{
    [A]
    [B]
    int _f;
}
```

### RH5518-004 — The fix is withheld for a comment or directive inside the list

The code fix MUST NOT be offered when SHARED-ATTR-019 withholds it. The diagnostic is still reported.

Why: A comment inside the list belongs to the attribute next to it, and only the author can tell which of the new lists it belongs to.

Example:

```csharp
class C
{
    {|RH5518:[A, /* c */ B]|}
    int _f;
}
```

is reported, and no code fix is offered.
