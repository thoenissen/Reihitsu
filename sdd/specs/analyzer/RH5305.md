# Analyzer — RH5305 Collection expressions should be formatted correctly

| | |
|---|---|
| ID prefix | RH5305 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5305CollectionExpressionsShouldBeFormattedCorrectlyAnalyzer`, `RH5305CollectionExpressionsShouldBeFormattedCorrectlyCodeFixProvider` |
| Uses | FMT-BREAK-022, FMT-INDENT-025 |

RH5305 reports a collection expression (`[…]`) that spans several lines without its brackets in one column or without each element on a line of its own, and offers a code fix that lays it out the way the formatter does.

## Non-goals

- List patterns — RH5306; collection and array initializers — RH5303.
- The layout of an element after its first token.

## Requirements

### RH5305-001 — Wrapped brackets out of column are reported

The analyzer MUST report a collection expression that spans several lines when its closing bracket does not start at the column of its opening bracket. A collection expression on one line MUST NOT be reported.

Why: Once a collection expression is wrapped, it is a block that hangs from its opening bracket; the closing bracket in the same column shows where the block ends (FMT-INDENT-025). On one line it reads as one value (FMT-BREAK-022).

Example:

```csharp
class C
{
    void M()
    {
        int[] a = [1, 2];
        int[] b = {|RH5305:[
                      1
            ]|};
    }
}
```

### RH5305-002 — Wrapped elements that share a line are reported

The analyzer MUST report a collection expression that spans several lines when one of its elements does not start on a line of its own between the brackets: on the line of the opening bracket, on the line of the closing bracket, or on the line of the element before it. A wrapped collection expression whose brackets are in one column and whose elements each start on their own line between them MUST NOT be reported.

Why: A wrapped collection gets one element per line, as an initializer does, so each element is visible on its own (FMT-BREAK-022).

Example:

```csharp
class C
{
    void M(int[] v)
    {
        int[] a = {|RH5305:[1,
                   2]|};
        int[] b = {|RH5305:[
                      .. v,
                      3 ]|};
        int[] c = [
                      1,
                      2
                  ];
    }
}
```

### RH5305-003 — The diagnostic is on the collection expression

The analyzer MUST report one diagnostic per collection expression, located on the whole collection expression, even when both its brackets and its elements are out of place.

Why: Brackets and elements are laid out together, so the diagnostic covers the construct the fix lays out.

Example: see RH5305-001 and RH5305-002.

### RH5305-004 — The fix lays out the collection expression

The code fix MUST lay out the reported collection expression as the formatter lays it out: every element starts its own line one level deeper than the opening bracket, and the closing bracket starts its own line at the column of the opening bracket (FMT-BREAK-022, FMT-INDENT-025). A comment behind an element stays behind it.

Why: The formatter owns the layout of collection expressions; delegating to it applies that layout instead of a second one.

Example:

```csharp
class C
{
    void M()
    {
        int[] a = {|RH5305:[1, // one
                   2]|};
    }
}
```

```csharp
class C
{
    void M()
    {
        int[] a = [
                      1, // one
                      2
                  ];
    }
}
```
