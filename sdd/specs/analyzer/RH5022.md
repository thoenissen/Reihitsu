# Analyzer — RH5022 Opening brace must not be followed by blank line

| | |
|---|---|
| ID prefix | RH5022 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5022OpeningBraceMustNotBeFollowedByBlankLineAnalyzer`, `RH5022OpeningBraceMustNotBeFollowedByBlankLineCodeFixProvider` |
| Uses | SHARED-WS-001 |

RH5022 reports a blank line directly below a line that ends with an opening brace, and offers a code fix that deletes it as SHARED-WS-001 specifies.

In the examples, a reported blank line is marked from its start to the end of its line break, so the markup encloses the line break itself.

## Non-goals

- A blank line directly above a closing brace that does not follow an opening brace directly — RH5024. In an empty body the same line is directly below `{` and directly above `}`, and both rules report it.
- A region directive directly below an opening brace — RH5031.

## Requirements

### RH5022-001 — A blank line below an opening brace is reported

The analyzer MUST report the blank line directly below a line that ends with an opening brace `{` — whatever the brace opens: a type, a member, a statement body, or an initializer. A line holding nothing but whitespace counts as blank.

Why: The brace already delimits the content below it; a blank line next to it adds height without separating anything.

Example:

```csharp
class C
{
{|RH5022:
|}    int[] _a = new[]
    {
{|RH5022:
|}        1,
    };

    void M()
    {
{|RH5022:
|}        _a[0]++;
    }
}
```

### RH5022-002 — A brace inside a comment, a string, or disabled code is not considered

The analyzer MUST NOT report a blank line below a `{` that is not an opening-brace token: a `{` in the text of a comment, in the content of a string literal, or in code that an `#if` branch excludes.

Why: Such a brace opens nothing; the line below it is part of the comment's text, the string's value, or code the compiler does not see.

Example:

```csharp
class C
{
    string _s = """
        {

        """;

    /* {

    */
#if NEVER
    void M()
    {

    }
#endif
}
```

is not reported.

### RH5022-003 — One diagnostic per brace, on the first blank line

The analyzer MUST report one diagnostic per opening brace, located on the blank line directly below it, from the line's start to the end of its line break.

Why: The diagnostic covers exactly the line the brace touches, which is the line the fix deletes.

Example: see RH5022-001.

### RH5022-004 — The fix deletes the blank line

The code fix MUST delete the reported line as SHARED-WS-001 specifies. It is offered for every reported line.

Why: The reported span holds nothing but whitespace and its line break, so deleting it can never touch a comment, a directive, or a token.

Example:

```csharp
class C
{
{|RH5022:
|}    int[] _a = new[]
    {
{|RH5022:
|}        1,
    };
}
```

```csharp
class C
{
    int[] _a = new[]
    {
        1,
    };
}
```
