# Analyzer — RH8108 Generic type parameters must be documented

| | |
|---|---|
| ID prefix | RH8108 |
| Status | Active |
| Category | Documentation |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH8108GenericTypeParametersMustBeDocumentedAnalyzer` |
| Uses | SHARED-DOC-008, SHARED-DOC-009, SHARED-DOC-011, SHARED-DOC-012 |

RH8108 reports a type parameter of a documented type, delegate, or method that has no matching `<typeparam>` documentation.

## Non-goals

- Whether the declaration has a summary — RH8001 to RH8029.
- The type parameters of an extension declaration — RH8033; parameters — RH8101.
- Whether the `<typeparam>` elements follow the type parameters, name one, and have text — RH8109, RH8110, and RH8111.

## Requirements

### RH8108-001 — An undocumented type parameter is reported

The analyzer MUST report each type parameter of a class, struct, interface, record, record struct, delegate, or method declaration that is not documented as SHARED-DOC-012 specifies, unless SHARED-DOC-011 exempts the declaration. A method declaration includes the methods of an interface and of an extension block; local functions are not checked. The declaration's accessibility does not matter. The analyzer MUST NOT report the type parameters of a method that explicitly implements an interface member, which SHARED-DOC-009 exempts, and nothing is reported when SHARED-DOC-008 applies.

This requirement covers what SHARED-DOC-011 and SHARED-DOC-012 cover. A part of a partial element declared in several parts is not covered.

Why: A type parameter often carries expectations about the types a caller may supply, which its name alone does not state, and the `<typeparam>` description is what the editor shows for it. A declaration without any documentation comment is left to the rules that require a summary, and an explicit implementation is described by the interface member it implements.

Example:

```csharp
/// <summary>
/// Contract
/// </summary>
/// <typeparam name="T">Element</typeparam>
public interface I<T>
{
    /// <summary>
    /// Converts
    /// </summary>
    /// <typeparam name="U">Target</typeparam>
    void Convert<U>();
}

/// <summary>
/// Factory
/// </summary>
public delegate T Factory<{|RH8108:T|}>();

/// <summary>
/// Pair
/// </summary>
/// <typeparam name="TFirst">First</typeparam>
public record Pair<TFirst, {|RH8108:TSecond|}>;

/// <summary>
/// Service
/// </summary>
public class C : I<int>
{
    /// <summary>
    /// Creates
    /// </summary>
    private T Create<{|RH8108:T|}>() => default;

    public void Undocumented<T>()
    {
    }

    /// <inheritdoc/>
    public void Convert<U>()
    {
    }

    /// <summary>
    /// Converts
    /// </summary>
    void I<int>.Convert<U>()
    {
    }

    private void Run()
    {
        void Local<T>()
        {
        }
    }
}
```

### RH8108-002 — The diagnostic is on the type parameter name

The analyzer MUST report one diagnostic per undocumented type parameter, located on its identifier.

Why: The name is what the `<typeparam>` element has to repeat, so marking it shows what is missing.

Example: see RH8108-001.
