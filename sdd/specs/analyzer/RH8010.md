# Analyzer — RH8010 Private record structs must be documented

| | |
|---|---|
| ID prefix | RH8010 |
| Status | Active |
| Category | Documentation |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH8010PrivateRecordStructsMustBeDocumentedAnalyzer` |
| Uses | SHARED-DOC-001, SHARED-DOC-002, SHARED-DOC-004, SHARED-DOC-005, SHARED-DOC-006, SHARED-DOC-007, SHARED-DOC-008 |

RH8010 reports a record struct in the private group that has no `<summary>` or `<inheritdoc>` documentation.

## Non-goals

- Record structs in the non-private group — RH8009.
- Structs declared with `struct` — RH8004; records declared with `record` or `record class` — RH8008.
- Whether the summary has text — RH8030; the documentation of type parameters and positional parameters — RH8108 and RH8101.

## Requirements

### RH8010-001 — Undocumented private record structs are reported

The analyzer MUST report every record struct declaration in the private group of SHARED-DOC-002 that is not documented, checked as SHARED-DOC-001 specifies. A record struct declaration is one written with `record struct`, positional or not, including `readonly` and generic record structs; a `struct` declaration is not one, and neither is a `record` or `record class` declaration. Whether it is documented MUST be decided as SHARED-DOC-004, SHARED-DOC-005, SHARED-DOC-006, and SHARED-DOC-007 specify, and nothing is reported when SHARED-DOC-008 applies.

Why: A private record struct is an implementation detail of its type, but the next maintainer still has to know what it is for. It has a rule of its own, so a project can require documentation for what other code uses without requiring it here.

Example:

```csharp
/// <summary>
/// Outer
/// </summary>
public class Outer
{
    private record struct {|RH8010:Hidden|}(int Value);

    /// <remarks>
    /// No summary
    /// </remarks>
    readonly record struct {|RH8010:Pair|}<T>
    {
    }

    /// <summary>
    /// Documented
    /// </summary>
    private record struct Documented;

    internal record struct Visible;

    private struct Plain
    {
    }

    private record Entity;
}
```

### RH8010-002 — The diagnostic is on the record struct name

The analyzer MUST report one diagnostic per undocumented record struct declaration, located on its identifier, without its type parameter list and its parameter list.

Why: The name is what the documentation describes; marking it identifies the declaration without marking its whole body.

Example: see RH8010-001.
