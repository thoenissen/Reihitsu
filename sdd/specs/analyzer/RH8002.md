# Analyzer — RH8002 Private classes must be documented

| | |
|---|---|
| ID prefix | RH8002 |
| Status | Active |
| Category | Documentation |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH8002PrivateClassesMustBeDocumentedAnalyzer` |
| Uses | SHARED-DOC-001, SHARED-DOC-002, SHARED-DOC-004, SHARED-DOC-005, SHARED-DOC-006, SHARED-DOC-007, SHARED-DOC-008 |

RH8002 reports a class in the private group that has no `<summary>` or `<inheritdoc>` documentation.

## Non-goals

- Classes in the non-private group — RH8001.
- Records declared with `record` or `record class` — RH8008.
- Whether the summary has text — RH8030; the documentation of type parameters and primary constructor parameters — RH8108 and RH8101.

## Requirements

### RH8002-001 — Undocumented private classes are reported

The analyzer MUST report every class declaration in the private group of SHARED-DOC-002 that is not documented, checked as SHARED-DOC-001 specifies. A class declaration is one written with the `class` keyword, including static, abstract, sealed, and generic classes; a `record` or `record class` declaration is not one. Whether it is documented MUST be decided as SHARED-DOC-004, SHARED-DOC-005, SHARED-DOC-006, and SHARED-DOC-007 specify, and nothing is reported when SHARED-DOC-008 applies.

Why: A private class is an implementation detail of its type, but the next maintainer still has to know what it is for. It has a rule of its own, so a project can require documentation for what other code uses without requiring it here.

Example:

```csharp
/// <summary>
/// Outer
/// </summary>
public class Outer
{
    private class {|RH8002:Hidden|}
    {
    }

    /// <remarks>
    /// No summary
    /// </remarks>
    private static class {|RH8002:Helper|}
    {
    }

    class {|RH8002:Cache|}<T>
    {
    }

    /// <summary>
    /// Documented
    /// </summary>
    private class Documented
    {
    }

    internal class Visible
    {
    }

    private record Entity;
}
```

### RH8002-002 — The diagnostic is on the class name

The analyzer MUST report one diagnostic per undocumented class declaration, located on its identifier, without its type parameter list.

Why: The name is what the documentation describes; marking it identifies the declaration without marking its whole body.

Example: see RH8002-001.
