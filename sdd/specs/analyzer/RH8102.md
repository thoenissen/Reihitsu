# Analyzer — RH8102 Element parameter documentation must match element parameters

| | |
|---|---|
| ID prefix | RH8102 |
| Status | Active |
| Category | Documentation |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH8102ElementParameterDocumentationMustMatchElementParametersAnalyzer` |
| Uses | SHARED-DOC-008, SHARED-DOC-015 |

RH8102 reports a `<param>` element whose name does not match the parameter in its position.

## Non-goals

- A parameter without a `<param>` element — RH8101.
- A `<param>` element without a name, and one without text — RH8103 and RH8104.
- `<typeparam>` elements — RH8109.

## Requirements

### RH8102-001 — A `<param>` element that does not follow the parameters is reported

The analyzer MUST report each `<param>` element that does not match the declaration's parameters as SHARED-DOC-015 specifies, in the documentation comment of a method, constructor, delegate, indexer, operator, or conversion operator declaration, or of a class, struct, record, or record struct declaration, whose parameters are the parameters of its primary constructor. A declaration that explicitly implements an interface member MUST be checked as well, and the declaration's accessibility does not matter. Nothing is reported when SHARED-DOC-008 applies.

This requirement covers what SHARED-DOC-015 covers.

Why: A description that names the wrong parameter, or one the signature does not have, makes the reader attach the text to the wrong argument, and one in a different order than the signature has to be matched up by hand. The documentation written on an explicit implementation drifts from its signature like any other.

Example:

```csharp
/// <summary>
/// Point
/// </summary>
/// <param name="X">X</param>
/// {|RH8102:<param name="Z">Z</param>|}
public record Point(int X, int Y);

/// <summary>
/// Contract
/// </summary>
public interface I
{
    /// <summary>
    /// Runs
    /// </summary>
    /// <param name="value">Value</param>
    void Run(int value);
}

/// <summary>
/// Service
/// </summary>
public class C : I
{
    /// <summary>
    /// Runs
    /// </summary>
    /// {|RH8102:<param name="other">Other</param>|}
    void I.Run(int value)
    {
    }

    /// <summary>
    /// Saves
    /// </summary>
    /// {|RH8102:<param name="overwrite">Overwrite</param>|}
    /// {|RH8102:<param name="customer">Customer</param>|}
    public void Save(int customer, bool overwrite)
    {
    }

    /// <summary>
    /// Saves
    /// </summary>
    /// <param name="customer">Customer</param>
    /// <param name="overwrite">Overwrite</param>
    public void Store(int customer, bool overwrite)
    {
    }
}
```

### RH8102-002 — The diagnostic is on the element

The analyzer MUST report one diagnostic per reported `<param>` element, located on the whole element: the empty element, or everything from the start tag through the end tag.

Why: The element is what has to be renamed or moved, and each misplaced element is corrected on its own.

Example: see RH8102-001.
