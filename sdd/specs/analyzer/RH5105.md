# Analyzer — RH5105 Opening parenthesis must be on declaration line

| | |
|---|---|
| ID prefix | RH5105 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5105OpeningParenthesisMustBeOnDeclarationLineAnalyzer`, `RH5105OpeningParenthesisMustBeOnDeclarationLineCodeFixProvider` |
| Uses | FMT-BREAK-011, SHARED-JOIN-001, SHARED-JOIN-002, SHARED-WS-003 |

RH5105 reports the opening parenthesis of a parameter list that starts a line below the token in front of it, and offers a code fix that moves the parenthesis onto that token's line.

## Non-goals

- The first parameter, the commas, and the closing parenthesis of a parameter list — RH5108, RH5107, and RH5106.
- The bracketed parameter list of an indexer, and the parameter of a simple lambda (`x => …`), which has no parentheses.
- Argument lists.

## Requirements

### RH5105-001 — An opening parenthesis below the declaration is reported

The analyzer MUST report the opening parenthesis of the parameter list of a method, a constructor, a finalizer, a local function, an operator, a conversion operator, a delegate, a record, an extension block, an anonymous method, and the primary constructor of a class or a struct, when the parenthesis starts on a later line than the token in front of it ends on, except where SHARED-JOIN-001 keeps the gap from being reported and in a file with a syntax error (SHARED-JOIN-002). The parameter list of a parenthesized lambda MUST NOT be reported.

Why: The parenthesis belongs to the declaration's name; on a line of its own it separates the name from its parameters (FMT-BREAK-011). A parenthesized lambda has no name in front of its parameter list; its opening parenthesis starts the expression and is placed by the code around it.

Example:

```csharp
using System;

class C
    {|RH5105:(|}int a)
{
    void M
        {|RH5105:(|}int b)
    {
        Func<int, int> f = delegate
            {|RH5105:(|}int c) { return c; };
        Func<int, int> g =
            (int c) => c;
    }

    ~C
        {|RH5105:(|})
    {
    }
}

delegate void D
    {|RH5105:(|}int a);

record R
    {|RH5105:(|}int A);

static class E
{
    extension
        {|RH5105:(|}int value)
    {
        public int Twice() => value * 2;
    }
}
```

### RH5105-002 — The diagnostic is on the opening parenthesis

The analyzer MUST report one diagnostic per parameter list, located on its opening parenthesis.

Why: The parenthesis is the token that has to move.

Example: see RH5105-001.

### RH5105-003 — The fix joins the parenthesis to the declaration

The code fix MUST move the opening parenthesis directly behind the token in front of it, as SHARED-WS-003 specifies.

Why: Deleting the line break and the indentation in front of the parenthesis is the whole correction; the rest of the parameter list keeps its layout.

Example:

```csharp
class C
{
    void M
        {|RH5105:(|}int a,
               int b)
    {
    }
}
```

```csharp
class C
{
    void M(int a,
               int b)
    {
    }
}
```
