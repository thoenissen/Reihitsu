# Analyzer — RH8014 Enum members in private enums must be documented

| | |
|---|---|
| ID prefix | RH8014 |
| Status | Active |
| Category | Documentation |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH8014PrivateEnumMembersMustBeDocumentedAnalyzer` |
| Uses | SHARED-DOC-001, SHARED-DOC-002, SHARED-DOC-003, SHARED-DOC-004, SHARED-DOC-005, SHARED-DOC-006, SHARED-DOC-007, SHARED-DOC-008 |

RH8014 reports a member of an enum in the private group that has no `<summary>` or `<inheritdoc>` documentation.

## Non-goals

- Members of enums in the non-private group — RH8013.
- The enum itself — RH8011 and RH8012.
- Whether the summary has text — RH8030.

## Requirements

### RH8014-001 — Undocumented members of private enums are reported

The analyzer MUST report every enum member that belongs to the private group, as SHARED-DOC-003 derives it from its enum with SHARED-DOC-002, and that is not documented, checked as SHARED-DOC-001 specifies: whether the enum itself is documented does not matter. Whether a member is documented MUST be decided as SHARED-DOC-004, SHARED-DOC-005, SHARED-DOC-006, and SHARED-DOC-007 specify, and nothing is reported when SHARED-DOC-008 applies.

Why: A private enum is an implementation detail of its type, but the next maintainer still has to know what each value means. It has a rule of its own, so a project can require documentation for what other code uses without requiring it here.

Example:

```csharp
/// <summary>
/// Outer
/// </summary>
public class Outer
{
    private enum Hidden
    {
        {|RH8014:First|},

        /// <remarks>
        /// No summary
        /// </remarks>
        {|RH8014:Second|} = 2,

        /// <summary>
        /// Third
        /// </summary>
        Third,
    }

    enum Implicit
    {
        {|RH8014:Value|},
    }

    internal enum Visible
    {
        Other,
    }
}
```

### RH8014-002 — The diagnostic is on the member name

The analyzer MUST report one diagnostic per undocumented enum member, located on its identifier, without its value.

Why: Each member needs its own documentation, and the name identifies the member that lacks it.

Example: see RH8014-001.
