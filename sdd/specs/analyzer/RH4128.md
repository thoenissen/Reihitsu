# Analyzer — RH4128 Local constant casing

| | |
|---|---|
| ID prefix | RH4128 |
| Status | Active |
| Category | Naming |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH4128LocalConstantCasingAnalyzer`, `RH4128LocalConstantCasingCodeFixProvider` |
| Uses | SHARED-CASING-002, SHARED-CASING-003, SHARED-CASING-006, SHARED-CASING-007, SHARED-CASING-008, SHARED-CASING-009, SHARED-CASING-010, SHARED-CASING-013 |

RH4128 reports a local constant whose name is not in camelCase and offers a code fix that renames the constant and every reference to it.

## Non-goals

- Constant fields — RH4110.
- Local variables that are not constants — RH4115 and RH4117.
- Local constant names of a single letter — RH4125.

## Requirements

### RH4128-001 — Local constant names are in camelCase

The analyzer MUST report every local constant whose name is not in camelCase as SHARED-CASING-002 defines it. A local constant is a variable of a local declaration statement with the `const` modifier, in a method, a local function, a lambda, an accessor, or the top-level statements of a program. The analyzer MUST report one diagnostic per variable of the declaration, located on its identifier. A local declaration statement without `const` is not checked; RH4115 checks it.

Why: A local constant is a local: it is visible only in its block, so it follows the camelCase style of locals, and at every use it reads as a value of the current block, not as a member of the type. The style does not change when a local variable becomes a constant, or a constant a variable.

Example:

```csharp
using System;

class C
{
    int M()
    {
        const int maxValue = 3, {|RH4128:MaxCount|} = 5;
        const string {|RH4128:default_name|} = "x";
        int Total = maxValue;

        int Local()
        {
            const int {|RH4128:Limit|} = 1;

            return Limit;
        }

        Func<int> f = () =>
        {
            const int {|RH4128:Step|} = 2;

            return Step;
        };

        return Total + MaxCount + default_name.Length + Local() + f();
    }
}
```

`Total` is not reported by RH4128.

### RH4128-002 — A local constant named `_` is not reported

The analyzer MUST NOT report a local constant named `_`. A name that only starts or ends with `_`, such as `_limit`, is reported as RH4128-001 states.

Why: `_` is the conventional name of a value that is not used, and every neighbouring casing rule accepts it: a local variable named `_` (RH4115), a parameter named `_` (RH4105), and a field named `_` (SHARED-CASING-003). The fix could derive no name from it (SHARED-CASING-008).

Example:

```csharp
class C
{
    void M()
    {
        const int _ = 1;
        const int {|RH4128:_limit|} = 2;
    }
}
```

### RH4128-003 — The fix renames the constant to camelCase

The code fix MUST rename the local constant and every reference to it (SHARED-CASING-007) to the camelCase name that SHARED-CASING-006 derives from its old name. It is withheld as SHARED-CASING-008, SHARED-CASING-009, and SHARED-CASING-013 specify, and its Fix All skips colliding names as SHARED-CASING-010 specifies. This requirement covers the renames that SHARED-CASING-007 covers.

Why: The fix makes exactly the change the diagnostic asks for, and a local constant is referenced throughout its block, also in other constant expressions such as another constant's value, a `case` label, or an attribute argument of a local function.

Example:

```csharp
class C
{
    int M(int value)
    {
        const int {|RH4128:MaxValue|} = 3;
        const int {|RH4128:Max_Count|} = MaxValue + 1;

        switch (value)
        {
            case MaxValue:
                return Max_Count;
        }

        return MaxValue;
    }
}
```

```csharp
class C
{
    int M(int value)
    {
        const int maxValue = 3;
        const int maxCount = maxValue + 1;

        switch (value)
        {
            case maxValue:
                return maxCount;
        }

        return maxValue;
    }
}
```
