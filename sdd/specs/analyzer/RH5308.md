# Analyzer — RH5308 Conditional expressions should be formatted correctly

| | |
|---|---|
| ID prefix | RH5308 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5308ConditionalExpressionsShouldBeFormattedCorrectlyAnalyzer`, `RH5308ConditionalExpressionsShouldBeFormattedCorrectlyCodeFixProvider` |
| Uses | FMT-BREAK-018, FMT-INDENT-020, FMT-PIPE-017, FMT-UNSUP-007, FMT-UNSUP-008, SHARED-COMMENT-011, SHARED-FIX-006, SHARED-FIX-010 |

RH5308 reports a conditional expression that spans several lines when its `?` or `:` does not start its own line, or starts it outside its column, and offers a code fix that lays out the conditional the way the formatter does.

## Non-goals

- The layout of a branch after its first token.
- The null-conditional operators `?.` and `?[]`, and the null-coalescing operator `??`.

## Requirements

### RH5308-001 — An operator that does not start its line is reported

The analyzer MUST report a conditional expression that spans several lines when its `?` is on the line its condition ends on, or its `:` is on the line its `true` branch ends on. A conditional expression nested in the `true` or the `false` branch of such a conditional MUST be checked in the same way. A conditional expression on one line that contains no nested conditional expression MUST NOT be reported.

Why: A partly wrapped conditional mixes two shapes and hides a branch at the end of a line; once wrapped, each branch starts its own line behind its operator (FMT-BREAK-018).

Example:

```csharp
class C
{
    int M(bool a)
    {
        var x = a {|RH5308:?|}
                1 :
                2;
        var y = a
                    ? 1 {|RH5308::|} 2;
        var z = a ? 1 : 2;

        return x;
    }
}
```

### RH5308-002 — An operator that starts its line outside its column is reported

The analyzer MUST report a conditional expression that spans several lines when a `?` or `:` that starts a line does not start four columns to the right of the first token of the outermost condition. The `?` and `:` of a conditional nested in the `true` or the `false` branch MUST start one further level (four columns) to the right for each level of nesting. A wrapped conditional whose operators all start their own lines in these columns, each followed by its branch on that line, MUST NOT be reported. A line that starts with a comment is judged as SHARED-COMMENT-011 specifies.

Why: The operators one level deeper than the condition, and one level further for each nested conditional, make the nesting visible as a stair (FMT-INDENT-020).

Example:

```csharp
class C
{
    int M(bool a, bool b)
    {
        var x = a
                {|RH5308:?|} 1
                : 2;
        var y = a
                    ? 1
                    : b
                    {|RH5308:?|} 2
                    : 3;
        var z = a
                    ? 1
                    : b
                        ? 2
                        : 3;

        return x;
    }
}
```

### RH5308-003 — The diagnostic is on the first misplaced operator

The analyzer MUST report one diagnostic per outermost conditional expression — one that is not itself a branch of a conditional expression — located on its first misplaced operator: the `?`, then the `:`, then the operators of a conditional nested in the `true` branch, then those of a conditional nested in the `false` branch.

Why: The fix lays out the whole conditional at once, so one diagnostic per conditional is enough, and two diagnostics for one conditional would offer fixes that overlap.

Example:

```csharp
class C
{
    int M(bool a)
    {
        var x = a {|RH5308:?|}
                1 :
                2;

        return x;
    }
}
```

The `?` and the `:` are both misplaced, and only the `?` is reported.

### RH5308-004 — The fix lays out the conditional expression

The code fix MUST lay out the reported conditional expression as the formatter lays it out: every `?` and `:` starts its own line, followed by its branch, one level deeper than the condition, and one further level for each nested conditional (FMT-BREAK-018, FMT-INDENT-020). The fix MUST change only the conditional expression: its first token keeps its line and its column in the document, and its other lines are laid out from that column (FMT-PIPE-017). The statement, initializer, expression body, or argument that contains the conditional expression MUST stay as written apart from it (SHARED-FIX-006) — the code in front of the conditional expression on its line and the code behind it — also where formatting the document would change it.

Why: The formatter owns the layout of conditional expressions; delegating to it applies that layout instead of a second one. The operators are indented from the condition, the conditional's first token, so laying it out from the column that token has in the document places them as the formatter places them there; the code around the conditional is the author's layout, which the formatter and the layout rules correct on their own.

Example:

```csharp
class C
{
    int M(bool a, bool b)
    {
        var x = a {|RH5308:?|}
                1 :
                b ? 2 : 3;

        return x;
    }
}
```

```csharp
class C
{
    int M(bool a, bool b)
    {
        var x = a
                    ? 1
                    : b
                        ? 2
                        : 3;

        return x;
    }
}
```

Example — the code in front of the conditional stays as written:

```csharp
class C
{
    int M(bool a, int b)
    {
        var  r=a {|RH5308:?|} b+1
            : 2;

        return r;
    }
}
```

```csharp
class C
{
    int M(bool a, int b)
    {
        var  r=a
                   ? b + 1
                   : 2;

        return r;
    }
}
```

The conditional is laid out from the column of `a`, and `b+1` inside it is formatted with it; formatting the document would also write `var r = a` and lay the conditional out from the column `a` gets there.

Example — a conditional in an argument of an `[assembly:]` attribute, which stands in no statement and no member:

```csharp
[assembly: System.CLSCompliant(true {|RH5308:?|}
    true :
    false)]
```

```csharp
[assembly: System.CLSCompliant(true
                                   ? true
                                   : false)]
```

### RH5308-005 — The fix is withheld for a comment or directive behind an operator

The code fix MUST NOT be offered for a conditional expression with a comment, a directive, or disabled text between its `?` and its `true` branch, or between its `:` and its `false` branch, nor for one that holds such a conditional in its condition or a branch: the fix formats the conditional (RH5308-004), the formatter refuses it (FMT-UNSUP-008), and the fix asks it before it is offered (FMT-UNSUP-007, SHARED-FIX-010). The diagnostic is still reported. A comment in front of the `?` or the `:`, such as one on the line above the operator's line, does not withhold the fix, and neither does such a conditional elsewhere in the statement or the member, outside the reported conditional.

Why: The comment keeps the branch off the operator's line, so the layout the rule asks for cannot be written without moving the comment, and where it belongs is the author's decision. The formatter declares the shape unsupported, so the fix needs no guard of its own for it.

Example:

```csharp
class C
{
    int M(bool a)
    {
        var x = a {|RH5308:?|} // c
            1
            : 2;
        var y = a
                    ? 1 {|RH5308::|} // c
                    2;

        return x;
    }
}
```

is reported, and no code fix is offered for either conditional. Written above the operator's line, the comment does not withhold the fix:

```csharp
class C
{
    int M(bool a)
    {
        var x = a
                // c
                {|RH5308:?|} 1
                : 2;

        return x;
    }
}
```

Outside the reported conditional, a conditional with a comment behind its `?` does not withhold the fix either:

```csharp
class C
{
    int M(bool a, bool b)
    {
        var x = (a {|RH5308:?|}
            1 : 2) + (b ? /* c */ 3 : 4);

        return x;
    }
}
```

```csharp
class C
{
    int M(bool a, bool b)
    {
        var x = (a
                     ? 1
                     : 2) + (b ? /* c */ 3 : 4);

        return x;
    }
}
```

### RH5308-006 — The fix is withheld for a conditional outside any statement or member

Status: Retired — the fix formats only the reported conditional (RH5308-004), which needs no statement or member around it, so it is offered for a conditional in an argument of an `[assembly:]` or `[module:]` attribute as well, and lays it out as RH5308-004 states.
