# Analyzer — RH5102 Arguments should either all be on one line or each on its own line

| | |
|---|---|
| ID prefix | RH5102 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5102ArgumentsShouldBeOnSingleOrSeparateLinesAnalyzer`, `RH5102ArgumentsShouldBeOnSingleOrSeparateLinesCodeFixProvider` |
| Uses | FMT-BREAK-012, FMT-BREAK-013 |

RH5102 reports a multi-line argument list in which two arguments start on the same line, and offers a code fix that lays the argument list out the way the formatter does.

## Non-goals

- Whether the first argument starts on the line of the opening parenthesis — RH5101; the column of a wrapped argument — RH5203.
- Parameter lists — RH5109.
- Bracketed argument lists (`m[…]`) and attribute argument lists.
- The position of a comma or of the closing parenthesis in an argument list.

## Requirements

### RH5102-001 — Arguments sharing a line in a multi-line list are reported

The analyzer MUST report a parenthesized argument list with at least two arguments whose opening and closing parentheses are on different lines when two of its arguments start on the same line. An argument list on one line, and a multi-line argument list in which every argument starts its own line, MUST NOT be reported, however many lines an argument spans.

Why: A partly wrapped list hides arguments at the end of a line; a list is either compact or one argument per line (FMT-BREAK-012). An argument that spans lines, such as a lambda with a block body, keeps the list multi-line, so the arguments next to it get their own lines too (FMT-BREAK-013).

Example:

```csharp
using System;

class C
{
    void N()
    {
        M{|RH5102:(1, 2,
          3)|};
        M{|RH5102:(1, () =>
        {
        })|};
        M(1, 2, 3);
        M(1,
          2,
          3);
        M(1,
          () =>
          {
          });
    }

    void M(params object[] values)
    {
    }
}
```

### RH5102-002 — The diagnostic is on the argument list

The analyzer MUST report one diagnostic per argument list, located on the whole argument list from its opening to its closing parenthesis, however many arguments share a line.

Why: The layout of the whole list is wrong, not one argument; one diagnostic per list matches the one fix that lays out the list.

Example:

```csharp
class C
{
    void N()
    {
        M{|RH5102:(1, 2,
          3, 4)|};
    }

    void M(params int[] values)
    {
    }
}
```

### RH5102-003 — The fix lays out the argument list

The code fix MUST format the argument list as the formatter formats it in place (FMT-BREAK-012, FMT-BREAK-013), which puts every argument on its own line, the first one on the line of the opening parenthesis and the others aligned under it.

Why: The formatter owns the layout of a wrapped argument list; delegating to it keeps the fixed code identical to formatted code.

Example:

```csharp
class C
{
    void N()
    {
        M{|RH5102:(1, 2,
          3)|};
    }

    void M(params int[] values)
    {
    }
}
```

```csharp
class C
{
    void N()
    {
        M(1,
          2,
          3);
    }

    void M(params int[] values)
    {
    }
}
```

### RH5102-004 — A comment or directive in the argument list withholds the fix

The code fix MUST NOT be offered when a comment or a preprocessor directive sits in front of the opening parenthesis or anywhere inside the argument list, a documentation comment included. A comment behind the closing parenthesis MUST NOT withhold the fix. The diagnostic is still reported.

Why: Laying out the list would move the comment or the directive. A comment behind the closing parenthesis stays where it is when the list is laid out, so it does not get in the way.

Example:

```csharp
class C
{
    int N()
    {
        M{|RH5102:(1, // first
          2, 3)|};

        return M
            /* note */ {|RH5102:(1, 2,
            3)|};
    }

    int M(params int[] values) => 0;
}
```

is reported, and no code fix is offered. In

```csharp
class C
{
    void N()
    {
        M{|RH5102:(1, 2,
          3)|}; // note
    }

    void M(params int[] values)
    {
    }
}
```

the comment follows the closing parenthesis, and the fix is offered.
