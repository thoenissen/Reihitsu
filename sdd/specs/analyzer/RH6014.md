# Analyzer — RH6014 Closing attribute brackets must be spaced correctly

| | |
|---|---|
| ID prefix | RH6014 |
| Status | Active |
| Category | Spacing |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH6014ClosingAttributeBracketsMustBeSpacedCorrectlyAnalyzer`, `RH6014ClosingAttributeBracketsMustBeSpacedCorrectlyCodeFixProvider` |
| Uses | FMT-SPACE-004, SHARED-WS-001 |

RH6014 reports whitespace in front of the closing bracket of an attribute list on the line of the token before it, and offers a code fix that deletes it as SHARED-WS-001 specifies.

In the examples, `→` marks a tab.

## Non-goals

- Closing square brackets that do not close an attribute list — RH6008.
- The whitespace after the opening bracket of an attribute list — RH6013.
- The whitespace after the closing bracket of an attribute list — the formatter (FMT-SPACE-003); no analyzer rule checks it.
- Whether a closing attribute bracket starts its own line — the attribute layout rules and the formatter.

## Requirements

### RH6014-001 — Whitespace before a closing attribute bracket on the same line is reported

The analyzer MUST report the run of spaces and tabs directly in front of the closing bracket of an attribute list when the bracket is on the line on which the token before it ends and the run directly follows that token. A closing attribute bracket that starts its line, after a line break, MUST NOT be reported, including when a comment, a directive, or disabled text precedes that line.

Why: The bracket belongs to the attributes it closes; a space in front of it makes the attribute read less like one compact annotation. A bracket on its own line is a layout choice, and its indentation is not a gap. The formatter removes the same whitespace (FMT-SPACE-004), so formatted code raises no RH6014.

Example:

```csharp
using System;
using System.Runtime.InteropServices;

[Obsolete{|RH6014: |}]
class C
{
    [Obsolete{|RH6014:→|}]
    [return: MarshalAs(UnmanagedType.I4){|RH6014:  |}]
    int M([In{|RH6014: |}] int a)
    {
        return a;
    }

    [Obsolete
        ]
    void O()
    {
    }

    [Obsolete // note
        ]
    void P()
    {
    }

    [Obsolete
#if DEBUG
#endif
        ]
    void Q()
    {
    }
}
```

### RH6014-002 — One diagnostic per bracket

The analyzer MUST report one diagnostic per closing attribute bracket, located on the whitespace run in front of it.

Why: The run is the text that is wrong and the text the fix deletes.

Example: see RH6014-001.

### RH6014-003 — The fix deletes the whitespace

The code fix MUST delete the reported whitespace as SHARED-WS-001 specifies.

Why: The run is the whole of what the diagnostic names as wrong, and deleting it is the whole correction.

Example:

```csharp
using System;
using System.Runtime.InteropServices;

[Obsolete{|RH6014: |}]
class C
{
    [Obsolete{|RH6014:→|}]
    int M([In{|RH6014: |}] int a)
    {
        return a;
    }
}
```

```csharp
using System;
using System.Runtime.InteropServices;

[Obsolete]
class C
{
    [Obsolete]
    int M([In] int a)
    {
        return a;
    }
}
```
