# Analyzer — RH4117 Deconstruction variable casing

| | |
|---|---|
| ID prefix | RH4117 |
| Status | Active |
| Category | Naming |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH4117DeconstructionVariableCasingAnalyzer`, `RH4117DeconstructionVariableCasingCodeFixProvider` |
| Uses | SHARED-CASING-002, SHARED-CASING-006, SHARED-CASING-007, SHARED-CASING-008, SHARED-CASING-009, SHARED-CASING-010, SHARED-CASING-013 |

RH4117 reports a variable that a deconstruction declares — in a declaration, a `foreach` statement, or a pattern — whose name is not in camelCase, and offers a code fix that renames the variable and every reference to it.

## Non-goals

- Other local variables, including the variable that names a whole pattern and the variables of a property pattern — RH4115; local constants — RH4128.
- Element names of tuple types and tuple expressions — RH4116 and RH4118.
- Deconstruction variable names of a single letter — RH4125 and RH4126.

## Requirements

### RH4117-001 — Variables of a deconstruction declaration are in camelCase

The analyzer MUST report every variable that a deconstruction declaration declares whose name is not in camelCase as SHARED-CASING-002 defines it, whether the deconstruction is the target of a deconstructing assignment or the variable part of a `foreach` statement. These are:

- every variable of a parenthesized variable designation, `var (a, b)`, including the variables of a nested designation, `var (a, (b, c))`;
- every variable declared by a declaration expression, `var a` or `int a`, that is an element of a tuple expression — directly or inside a nested tuple expression — on the left of a deconstructing assignment, `(var a, int b) = p`, or in front of `in` of a `foreach` statement, `foreach ((var k, var v) in list)`.

The analyzer MUST report one diagnostic per variable, located on its identifier. An existing variable that a tuple on the left of a deconstruction assigns, such as `existing` in `(existing, var b) = p`, declares nothing and is not reported. A variable declared by a declaration expression that is not an element of such a tuple, such as `out var Parsed`, is not a deconstruction variable; RH4115 checks it.

Why: A deconstruction variable is a local like any other, so it follows the camelCase style of locals; at every use it reads as a value of the current block. Both spellings declare the variables of one deconstruction, so one rule checks both, and a user who configures deconstruction apart from other locals gets the same result for either spelling.

Example:

```csharp
using System.Collections.Generic;

class C
{
    void M((int, (int, int)) value, (int, int) pair, List<(int, int)> pairs, int existing)
    {
        var (count, ({|RH4117:Total|}, {|RH4117:item_count|})) = value;
        (var {|RH4117:First|}, int second) = pair;
        (int {|RH4117:Third|}, var ({|RH4117:Fourth|}, fifth)) = value;
        (existing, var {|RH4117:Sixth|}) = pair;

        foreach (var ({|RH4117:Key|}, entry) in pairs)
        {
        }

        foreach ((var {|RH4117:Name|}, var size) in pairs)
        {
        }
    }
}
```

### RH4117-002 — The fix renames the variable to camelCase

The code fix MUST rename the variable and every reference to it (SHARED-CASING-007) to the camelCase name that SHARED-CASING-006 derives from its old name. It is withheld as SHARED-CASING-008, SHARED-CASING-009, and SHARED-CASING-013 specify, and its Fix All skips colliding names as SHARED-CASING-010 specifies. This requirement covers the renames that SHARED-CASING-007 covers.

Why: The fix makes exactly the change the diagnostic asks for, and a local is referenced throughout its block.

Example:

```csharp
class C
{
    int M((int, (int, int)) value)
    {
        var ({|RH4117:First|}, ({|RH4117:Second_Value|}, third)) = value;

        return First + Second_Value + third;
    }
}
```

```csharp
class C
{
    int M((int, (int, int)) value)
    {
        var (first, (secondValue, third)) = value;

        return first + secondValue + third;
    }
}
```

Example — the variables of a deconstruction pattern:

```csharp
class C
{
    int M((int, int) pair)
    {
        if (pair is var ({|RH4117:Left|}, {|RH4117:Right|}))
        {
            return Left + Right;
        }

        return pair is (var {|RH4117:Head|}, _) ? Head : 0;
    }
}
```

```csharp
class C
{
    int M((int, int) pair)
    {
        if (pair is var (left, right))
        {
            return left + right;
        }

        return pair is (var head, _) ? head : 0;
    }
}
```

### RH4117-003 — Variables of a deconstruction pattern are in camelCase

The analyzer MUST report every variable that a deconstruction pattern declares whose name is not in camelCase as SHARED-CASING-002 defines it, in an `is` expression, a `switch` statement, and a `switch` expression alike. These are:

- every variable of the parenthesized variable designation of a `var` pattern, `p is var (a, b)` or `case var (a, b)`, including the variables of a nested designation;
- the variable of a `var` pattern or a declaration pattern that is itself a subpattern of a positional pattern, `p is (var a, int b)`, also of a positional pattern nested in another one, `p is (var a, (var b, var c))`.

The analyzer MUST report one diagnostic per variable, located on its identifier. A variable a pattern declares in any other position is not a deconstruction variable, and RH4115 checks it: the variable that names a whole positional or property pattern, such as `Both` in `p is (1, 2) Both`; the variable of a subpattern of a property pattern, such as `Size` in `{ Length: var Size }`, also when that property pattern is itself a subpattern of a positional pattern; the variable of a declaration pattern or `var` pattern that stands inside a pattern combinator or parentheses, such as `Number` in `p is (int Number and > 0, _)`; and a simple pattern variable, such as `Number` in `input is int Number`.

Why: A positional pattern and a `var (…)` pattern deconstruct the value they test as a deconstruction declaration does, and each variable they declare receives one element of it, so the variables are checked by the rule that checks the variables of a deconstruction declaration (RH4117-001). A simple pattern variable receives the whole value tested, not an element of a deconstruction, and stays an ordinary local.

Example:

```csharp
class C
{
    int M((int, int) pair, (object, (int, int)) nested)
    {
        if (pair is var ({|RH4117:First|}, {|RH4117:Second|}))
        {
            return First + Second;
        }

        if (nested is (int {|RH4117:Count|}, (var {|RH4117:Inner|}, var outer)))
        {
            return Count + Inner + outer;
        }

        switch (pair)
        {
            case var ({|RH4117:Left|}, {|RH4117:Right|}):
                return Left + Right;
        }

        return 0;
    }

    int N((int, int) pair) => pair switch
    {
        (var {|RH4117:Head|}, _) => Head,
    };
}
```

Example — pattern variables that are not deconstruction variables:

```csharp
class C
{
    void M(object input, (int, int) pair, (string, int) named)
    {
        if (pair is (1, 2) Both)
        {
        }

        if (named is ({ Length: var Size }, _))
        {
        }

        if (pair is (int Number and > 0, _))
        {
        }

        if (input is int Value)
        {
        }
    }
}
```

is not reported by RH4117; RH4115 reports `Both`, `Size`, `Number`, and `Value`.
