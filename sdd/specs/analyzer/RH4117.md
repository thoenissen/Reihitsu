# Analyzer — RH4117 Deconstruction variable casing

| | |
|---|---|
| ID prefix | RH4117 |
| Status | Active |
| Category | Naming |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH4117DeconstructionVariableCasingAnalyzer`, `RH4117DeconstructionVariableCasingCodeFixProvider` |
| Uses | SHARED-CASING-002, SHARED-CASING-006, SHARED-CASING-007, SHARED-CASING-008, SHARED-CASING-009, SHARED-CASING-010, SHARED-CASING-013, SHARED-CASING-015 |

RH4117 reports a variable that a deconstruction declares — in a declaration, a `foreach` statement, or a pattern — whose name is not in camelCase, and offers a code fix that renames the variable and every reference to it.

## Non-goals

- Other local variables, including the variable that names a whole pattern that is not an element of a positional pattern, the variables of a property pattern, and the variables of the elements of a list pattern — RH4115; local constants — RH4128.
- Element names of tuple types and tuple expressions — RH4116 and RH4118.
- Deconstruction variable names of a single letter — RH4125 and RH4126.

## Requirements

### RH4117-001 — Variables of a deconstruction declaration are in camelCase

The analyzer MUST report every variable that a deconstruction declaration declares whose name is not in camelCase as SHARED-CASING-002 defines it, whether the deconstruction is the target of a deconstructing assignment or the variable part of a `foreach` statement. These are:

- every variable of a parenthesized variable designation, `var (a, b)`, including the variables of a nested designation, `var (a, (b, c))`;
- every variable declared by a declaration expression, `var a` or `int a`, that is an element of a tuple expression — directly or inside a nested tuple expression — on the left of a deconstructing assignment, `(var a, int b) = p`, or in front of `in` of a `foreach` statement, `foreach ((var k, var v) in list)`.

The analyzer MUST report one diagnostic per variable, located on its identifier. An existing variable that a tuple on the left of a deconstruction assigns, such as `existing` in `(existing, var b) = p`, declares nothing and is not reported. A variable declared by a declaration expression that is not an element of such a tuple, such as `out var Parsed`, is not a deconstruction variable; RH4115 checks it.

Why: A deconstruction variable is a local like any other, so it follows the camelCase style of locals; at every use it reads as a value of the current block. Both spellings declare the variables of one deconstruction, so one rule checks both, and a user who configures deconstruction apart from other locals gets the same result for either spelling.

Example:

```csharp
using System.Collections.Generic;

class C
{
    void M((int, (int, int)) value, (int, int) pair, List<(int, int)> pairs, int existing)
    {
        var (count, ({|RH4117:Total|}, {|RH4117:item_count|})) = value;
        (var {|RH4117:First|}, int second) = pair;
        (int {|RH4117:Third|}, var ({|RH4117:Fourth|}, fifth)) = value;
        (existing, var {|RH4117:Sixth|}) = pair;

        foreach (var ({|RH4117:Key|}, entry) in pairs)
        {
        }

        foreach ((var {|RH4117:Name|}, var size) in pairs)
        {
        }
    }
}
```

### RH4117-002 — The fix renames the variable to camelCase

The code fix MUST rename the variable and every reference to it (SHARED-CASING-007) to the camelCase name that SHARED-CASING-006 derives from its old name. It is withheld as SHARED-CASING-008, SHARED-CASING-009, and SHARED-CASING-013 specify, and its Fix All skips colliding names as SHARED-CASING-010 specifies. It keeps the name of an anonymous object member that a renamed reference names, as SHARED-CASING-015 specifies. This requirement covers the renames that SHARED-CASING-007 covers.

Why: The fix makes exactly the change the diagnostic asks for, and a local is referenced throughout its block.

Example:

```csharp
class C
{
    int M((int, (int, int)) value)
    {
        var ({|RH4117:First|}, ({|RH4117:Second_Value|}, third)) = value;

        return First + Second_Value + third;
    }
}
```

```csharp
class C
{
    int M((int, (int, int)) value)
    {
        var (first, (secondValue, third)) = value;

        return first + secondValue + third;
    }
}
```

Example — the variables of a deconstruction pattern:

```csharp
class C
{
    int M((int, int) pair)
    {
        if (pair is var ({|RH4117:Left|}, {|RH4117:Right|}))
        {
            return Left + Right;
        }

        return pair is (var {|RH4117:Head|}, _) ? Head : 0;
    }
}
```

```csharp
class C
{
    int M((int, int) pair)
    {
        if (pair is var (left, right))
        {
            return left + right;
        }

        return pair is (var head, _) ? head : 0;
    }
}
```

### RH4117-003 — Variables of a deconstruction pattern are in camelCase

The analyzer MUST report every variable that a deconstruction pattern declares whose name is not in camelCase as SHARED-CASING-002 defines it, in an `is` expression, a `switch` statement, and a `switch` expression alike. These are:

- every variable of the parenthesized variable designation of a `var` pattern, `p is var (a, b)` or `case var (a, b)`, including the variables of a nested designation;
- every variable that receives a whole element of a positional pattern: the variable that a `var` pattern, a declaration pattern, a property or positional pattern, or a list pattern declares for the value it tests, when that pattern is the pattern of a subpattern of a positional pattern, or stands inside that subpattern's pattern only behind `and` combinators and parentheses. Examples are `a` and `b` in `p is (var a, int b)`, `number` in `p is (int number and > 0, _)`, `text` in `p is (string { Length: > 0 } text, _)`, `any` in `p is ({ } any, _)`, and `items` in `p is ([_, _] items, _)`. This holds also for a positional pattern nested in another positional pattern, `p is (var a, (var b, var c))`, or standing inside a property or list pattern, `p is { Pair: (var a, _) }`.

The analyzer MUST report one diagnostic per variable, located on its identifier. A variable a pattern declares in any other position is not a deconstruction variable, and RH4115 checks it. Examples are the variable that names a whole pattern that is not itself an element of a positional pattern, such as `Both` in `p is (1, 2) Both`; the variable of a subpattern of a property pattern, such as `Size` in `{ Length: var Size }`, also when that property pattern is itself an element of a positional pattern, `p is ({ Length: var Size }, _)`; the variable of an element or of the slice of a list pattern, such as `First` in `p is [var First, ..]`; and a simple pattern variable, such as `Number` in `input is int Number`.

Why: A positional pattern and a `var (…)` pattern deconstruct the value they test as a deconstruction declaration does, and each element of it is tested by one subpattern, so every variable that receives a whole element is checked by the rule that checks the variables of a deconstruction declaration (RH4117-001), however its subpattern is spelled. An `and` combinator and parentheses only add tests to the element; they do not change which value the variable receives. A variable of a property pattern receives a property of the element, the variable of a list pattern's element an element of a list, and a simple pattern variable the whole value tested; none of them is an element of a deconstruction, and each stays an ordinary local.

Example:

```csharp
class C
{
    int M((int, int) pair, (object, (int, int)) nested, (object, object) objects)
    {
        if (pair is var ({|RH4117:First|}, {|RH4117:Second|}))
        {
            return First + Second;
        }

        if (nested is (int {|RH4117:Count|}, (var {|RH4117:Inner|}, var outer)))
        {
            return Count + Inner + outer;
        }

        if (objects is (int {|RH4117:Number|} and > 0, string { Length: > 0 } {|RH4117:Text|}))
        {
            return Number + Text.Length;
        }

        if (objects is ({ } {|RH4117:Any|}, (int {|RH4117:Wrapped|})))
        {
            return Any.GetHashCode() + Wrapped;
        }

        switch (pair)
        {
            case var ({|RH4117:Left|}, {|RH4117:Right|}):
                return Left + Right;
        }

        return 0;
    }

    int N((int, int) pair) => pair switch
    {
        (var {|RH4117:Head|}, _) => Head,
    };
}
```

Example — pattern variables that are not deconstruction variables, next to one that is:

```csharp
class C
{
    void M(object input, (int, int) pair, (string, int) named, int[] values)
    {
        if (pair is (1, 2) Both)
        {
        }

        if (named is ({ Length: var Size }, _))
        {
        }

        if (named is (string { Length: var Chars } {|RH4117:Whole|}, _))
        {
        }

        if (values is [var Head, .. var Rest])
        {
        }

        if (input is int Value)
        {
        }
    }
}
```

RH4117 reports only `Whole`, which receives the first element; RH4115 reports `Both`, `Size`, `Chars`, `Head`, `Rest`, and `Value`.
