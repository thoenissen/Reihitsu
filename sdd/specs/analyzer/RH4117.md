# Analyzer — RH4117 Deconstruction variable casing

| | |
|---|---|
| ID prefix | RH4117 |
| Status | Active |
| Category | Naming |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH4117DeconstructionVariableCasingAnalyzer`, `RH4117DeconstructionVariableCasingCodeFixProvider` |
| Uses | SHARED-CASING-002, SHARED-CASING-006, SHARED-CASING-007, SHARED-CASING-008, SHARED-CASING-009, SHARED-CASING-010 |

RH4117 reports a variable of a `var (…)` deconstruction whose name is not in camelCase and offers a code fix that renames the variable and every reference to it.

## Non-goals

- Other local variables — RH4115.
- Element names of tuple types and tuple expressions — RH4116 and RH4118.
- Deconstruction variable names of a single letter — RH4125 and RH4126.

## Requirements

### RH4117-001 — Variables of a `var (…)` deconstruction are in camelCase

The analyzer MUST report every variable declared by a deconstruction declaration `var (…)` whose name is not in camelCase as SHARED-CASING-002 defines it, whether the declaration is the target of a deconstructing assignment or the variable part of a `foreach` statement, and including the variables of a nested `var (a, (b, c))`. The analyzer MUST report one diagnostic per variable, located on its identifier.

Why: A deconstruction variable is a local like any other, so it follows the camelCase style of locals; at every use it reads as a value of the current block.

Example:

```csharp
using System.Collections.Generic;

class C
{
    void M((int, (int, int)) value, List<(int, int)> pairs)
    {
        var (count, ({|RH4117:Total|}, {|RH4117:item_count|})) = value;

        foreach (var ({|RH4117:Key|}, entry) in pairs)
        {
        }
    }
}
```

### RH4117-002 — The fix renames the variable to camelCase

The code fix MUST rename the variable and every reference to it (SHARED-CASING-007) to the camelCase name that SHARED-CASING-006 derives from its old name. It is withheld as SHARED-CASING-008 and SHARED-CASING-009 specify, and its Fix All skips colliding names as SHARED-CASING-010 specifies. This requirement covers the renames that SHARED-CASING-007 covers.

Why: The fix makes exactly the change the diagnostic asks for, and a local is referenced throughout its block.

Example:

```csharp
class C
{
    int M((int, (int, int)) value)
    {
        var ({|RH4117:First|}, ({|RH4117:Second_Value|}, third)) = value;

        return First + Second_Value + third;
    }
}
```

```csharp
class C
{
    int M((int, (int, int)) value)
    {
        var (first, (secondValue, third)) = value;

        return first + secondValue + third;
    }
}
```
