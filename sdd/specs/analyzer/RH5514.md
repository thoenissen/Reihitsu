# Analyzer — RH5514 Method attribute lists must use one attribute per list

| | |
|---|---|
| ID prefix | RH5514 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5514MethodAttributeListsMustFollowShapeRulesAnalyzer`, `RH5514MethodAttributeListsMustFollowShapeRulesCodeFixProvider` |
| Uses | SHARED-ATTR-001, SHARED-ATTR-002, SHARED-ATTR-013, SHARED-ATTR-016, SHARED-ATTR-017, SHARED-ATTR-019 |

RH5514 reports an attribute list of a method, operator, conversion operator, destructor, local function, or lambda that holds more than one attribute, and offers a code fix that gives each attribute a list of its own. The rule uses `shared/attribute-targets.md`.

## Non-goals

- Attributes of constructors — RH5512.
- The `return:` attributes of a method — RH5528.
- Where a method attribute list is placed — RH5513.

## Requirements

### RH5514-001 — Method attribute lists hold one attribute

The analyzer MUST check every attribute list that resolves to the method target (SHARED-ATTR-001, SHARED-ATTR-002) and is not attached to an accessor: the lists of a method, operator, conversion operator, destructor, local function, or lambda without a specifier or with `type:`, and every list with the `method:` specifier that is not attached to a parameter or type parameter, and MUST report such a list that holds more than one attribute, as SHARED-ATTR-013 specifies.

Why: Methods attract the attributes with the longest argument lists — test cases, route templates, interop declarations — and merged into one list they run off the right margin; one per line leaves room for the arguments and a comment.

Example:

```csharp
class C
{
    {|RH5514:[A, B]|}
    void M()
    {
        {|RH5514:[A, B]|}
        void L()
        {
        }

        System.Action a = {|RH5514:[A, B]|} () => { };
    }

    {|RH5514:[A, B]|}
    public static C operator +(C a, C b) => a;

    {|RH5514:[A, B]|}
    ~C()
    {
    }

    {|RH5514:[method: A, B]|}
    void N()
    {
    }
}
```

### RH5514-002 — Accessor attributes are not checked

The analyzer MUST NOT report an attribute list attached to an accessor, even though it resolves to the method target.

Why: An accessor's lists are shaped by the layout of its property's accessor list, which RH5531 checks.

Example:

```csharp
class C
{
    int P
    {
        [A, B]
        get;
        set;
    }
}
```

is not reported by RH5514; RH5531 reports it.

### RH5514-003 — The diagnostic is on the attribute list

The analyzer MUST report the diagnostic on the attribute list, as SHARED-ATTR-016 specifies.

Why: The list is what has the wrong shape; each list of a declaration is reported and fixed on its own.

Example: see RH5514-001.

### RH5514-004 — The fix gives each attribute a list of its own

The code fix MUST replace the list with one list per attribute, each on its own line, as SHARED-ATTR-017 specifies.

Why: The fix makes only the change the diagnostic asks for: the attributes keep their order and their specifier, and each gets a line of its own.

Example:

```csharp
class C
{
    {|RH5514:[A, B]|}
    void M()
    {
    }
}
```

```csharp
class C
{
    [A]
    [B]
    void M()
    {
    }
}
```

### RH5514-005 — The fix is withheld for a comment or directive inside the list

The code fix MUST NOT be offered when SHARED-ATTR-019 withholds it. The diagnostic is still reported.

Why: A comment inside the list belongs to the attribute next to it, and only the author can tell which of the new lists it belongs to.

Example:

```csharp
class C
{
    {|RH5514:[A, /* c */ B]|}
    void M()
    {
    }
}
```

is reported, and no code fix is offered.
