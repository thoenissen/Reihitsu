# Analyzer — RH0002 Documentation rules are not active for this project

| | |
|---|---|
| ID prefix | RH0002 |
| Status | Active |
| Category | Analyzer |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH0002DocumentationModeMustNotBeNoneAnalyzer` |
| Uses | — |

RH0002 reports every source file that the compiler parses without documentation comments, because the documentation rules (RH8###) cannot check those files.

## Non-goals

- What the documentation rules report once documentation comments are parsed — their own specs.
- Which project setting selects the documentation mode. The rule reads the mode the compiler parses a file with; how a project sets it, for example with `GenerateDocumentationFile`, is a matter of the build.
- A code fix. The correction is a project setting, which a C# code fix cannot edit.

## Requirements

### RH0002-001 — A file parsed without documentation comments is reported

The analyzer MUST report each source file of the compilation whose documentation mode is `None`. A file parsed in the mode `Parse` or `Diagnose` MUST NOT be reported.

Why: In the mode `None`, the compiler treats `///` comments as ordinary comments, so the documentation rules see nothing to check and stay silent. The project then looks clean although its documentation was never checked. The mode is part of each file's parse options, so each file is judged on its own.

Example — with documentation mode `None`:

```csharp
{|RH0002:namespace|} N;

class C
{
}
```

With documentation mode `Parse` or `Diagnose`, the same file is not reported.

### RH0002-002 — The diagnostic is on the first token of the file

The analyzer MUST report one diagnostic per reported file, located on the file's first token. In a file without tokens, such as an empty file or a file that holds only comments, the diagnostic MUST be the empty span at the end of the file.

Why: The problem belongs to the whole file, not to any construct in it. The first token gives the diagnostic a stable place that every file has.

Example — a file whose only content is the line `// Only a comment` followed by a line break is reported with the empty span after that line break, and an empty file with the empty span at its start.

Example — two files of one project with documentation mode `None`:

```csharp
{|RH0002:namespace|} First;
```

```csharp
{|RH0002:namespace|} Second;
```

Each file is reported once.
