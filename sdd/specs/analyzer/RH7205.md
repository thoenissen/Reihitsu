# Analyzer — RH7205 Using static directives must be placed at correct position

| | |
|---|---|
| ID prefix | RH7205 |
| Status | Active |
| Category | Organization |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH7205UsingStaticDirectivesMustBePlacedAtCorrectPositionAnalyzer`, `RH7205UsingStaticDirectivesMustBePlacedAtCorrectPositionCodeFixProvider` |
| Uses | SHARED-USING-001, SHARED-USING-002, SHARED-USING-003, SHARED-USING-009, SHARED-USING-011, FMT-USING-001, FMT-USING-002, FMT-USING-003, FMT-USING-005, FMT-USING-006, FMT-USING-007, FMT-USING-008, FMT-USING-009, FMT-USING-010, FMT-USING-011, FMT-USING-012 |

RH7205 reports a `using static` directive that follows an alias directive or precedes a regular namespace directive, and offers a code fix that organizes the whole using block.

## Non-goals

- The order of the static directives among each other — RH7206.
- The canonical order and grouping of using directives — SHARED-USING — and how the formatter lays out a reordered block — FMT-USING.

## Requirements

### RH7205-001 — A static directive outside its place is reported

The analyzer MUST report every `using static` directive that follows an alias directive or precedes a regular namespace directive in the same block (SHARED-USING-001) and the same section, global or not (SHARED-USING-002). A directive that does both is reported once.

Why: Static imports belong between the regular directives and the aliases (SHARED-USING-003); mixed into either, they are easy to overlook. One diagnostic per directive is enough, however many neighbors it is misplaced against.

Example:

```csharp
using static {|RH7205:System.Math|};
using System;

class C
{
}
```

```csharp
using A = System.Text;
using static {|RH7205:System.Math|};
using System;

class C
{
}
```

while a static directive of the global section is not compared with a local directive:

```csharp
global using static System.Math;
using System;

class C
{
}
```

and a block with a preprocessor directive among its directives is reported as well, without a code fix (SHARED-USING-009); in a build that does not define `DEBUG`:

```csharp
using static {|RH7205:System.Math|};
#if DEBUG
using System.Diagnostics;
#endif
using System;

class C
{
}
```

### RH7205-002 — A static directive between regular and alias directives is not reported

The analyzer MUST NOT report a `using static` directive that no alias directive precedes and no regular namespace directive follows in its section, and MUST NOT report a regular or alias directive.

Why: That is the place SHARED-USING-003 gives it; the order of the static directives among each other is RH7206's decision.

Example:

```csharp
using System;
using static System.Math;
using static System.Console;
using A = System.Text;

class C
{
}
```

is not reported by RH7205.

### RH7205-003 — The diagnostic is on the type name

The analyzer MUST report one diagnostic per reported directive, located on the type name it imports.

Why: The type name is what the reader scans for in a `using static` directive.

Example: see RH7205-001.

### RH7205-004 — The fix organizes the whole block

The code fix MUST rewrite the whole using block that contains the reported directive as the formatter's using-directive phase does: into the canonical order (FMT-USING-001), with exactly one blank line between two groups and none inside a group other than the one kept above a comment that leads a directive (FMT-USING-002, FMT-USING-010), with one directive per line (FMT-USING-003), and with comments placed as FMT-USING-005, FMT-USING-006, FMT-USING-007, FMT-USING-008, and FMT-USING-009 specify, with the leading trivia of the block's original first directive kept at its top when that trivia holds a preprocessor directive (FMT-USING-012), and at the indentation FMT-USING-011 specifies. It MUST NOT change anything outside the block. No code fix is offered for a diagnostic in a block that SHARED-USING-009 forbids to reorder: a block with a preprocessor directive between two of its directives or between the tokens of one, or with disabled text in front of its first directive. A block whose preprocessor directives all stand in front of its first directive, with no disabled text there, is fixed.

Why: The formatter and the seven using-ordering rules RH7201–RH7207 organize a block the same way; where the organized form leaves a choice to the author, such as the blank line above a comment that leads a directive (SHARED-USING-011), they keep the author's. Producing it in one step corrects every diagnostic those rules report in the block at once, so their fixes never undo each other. The code after the block is not the finding.

Example:

```csharp
using A = System.Text;
using static {|RH7205:System.Math|};
using System;

class C
{
}
```

```csharp
using System;

using static System.Math;

using A = System.Text;

class C
{
}
```

and a block with a preprocessor directive in front of its first directive is fixed, with the directive at the top:

```csharp
#nullable enable
using static {|RH7205:System.Math|};
using System;

class C
{
}
```

```csharp
#nullable enable
using System;

using static System.Math;

class C
{
}
```
