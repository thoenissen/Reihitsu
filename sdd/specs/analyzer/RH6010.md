# Analyzer — RH6010 Closing braces must be spaced correctly

| | |
|---|---|
| ID prefix | RH6010 |
| Status | Active |
| Category | Spacing |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH6010ClosingBracesMustBeSpacedCorrectlyAnalyzer`, `RH6010ClosingBracesMustBeSpacedCorrectlyCodeFixProvider` |
| Uses | FMT-SPACE-009 |

RH6010 reports a closing brace outside interpolated strings that directly follows another character on its line, and offers a code fix that inserts a space in front of it.

## Non-goals

- The whitespace after a closing brace — no analyzer rule checks it.
- Opening braces — RH6009.
- Whether a brace starts its own line — the brace layout rules, such as RH5402 and RH5417.

## Requirements

### RH6010-001 — A closing brace glued to the character before it is reported

The analyzer MUST report a closing brace token outside interpolated strings whose preceding character is not whitespace — the last character of a token (the opening brace of an empty pair included) or of a `/* */` comment. A closing brace preceded by whitespace of any width, or that starts its line, MUST NOT be reported.

Why: A closing brace written directly against the preceding token, as in `set;}`, runs the end of the block into the last thing inside it. The formatter writes one space in front of these braces (FMT-SPACE-009), so formatted code raises no RH6010.

Example:

```csharp
class C
{
    int P { get; set;{|RH6010:}|}
    int Q { get; set;  }
    int R { get; set; /* note */{|RH6010:}|}

    void M(int a)
    {
        var x = new int[] { 1{|RH6010:}|};
        var e = new int[] {{|RH6010:}|};
    }
}
```

### RH6010-002 — The braces of an interpolation are not reported

The analyzer MUST NOT report the closing brace of an interpolation in an interpolated string, such as the brace in `$"{a}"`.

Why: An interpolation brace is part of the string's text layout; a space in front of it would become part of the string's value.

Example:

```csharp
class C
{
    string M(int a)
    {
        return $"{a}:value";
    }
}
```

is not reported.

### RH6010-003 — The diagnostic is on the brace

The analyzer MUST report one diagnostic per brace, located on the closing brace token.

Why: The brace is the token whose spacing is wrong.

Example: see RH6010-001.

### RH6010-004 — The fix inserts a space in front of the brace

The code fix MUST insert one space directly in front of the reported brace, after a comment that precedes it, and MUST NOT change anything else.

Why: The fix answers exactly what the diagnostic reports; inserting the space next to the brace never touches the comment.

Example:

```csharp
class C
{
    int P { get; set;{|RH6010:}|}
    int R { get; set; /* note */{|RH6010:}|}

    void M(int a)
    {
        var e = new int[] {{|RH6010:}|};
    }
}
```

```csharp
class C
{
    int P { get; set; }
    int R { get; set; /* note */ }

    void M(int a)
    {
        var e = new int[] { };
    }
}
```
