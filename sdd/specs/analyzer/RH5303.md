# Analyzer — RH5303 Collection initializer should be formatted correctly

| | |
|---|---|
| ID prefix | RH5303 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5303CollectionInitializerShouldBeFormattedCorrectlyAnalyzer`, `RH5303CollectionInitializerShouldBeFormattedCorrectlyCodeFixProvider` |
| Uses | SHARED-INIT-001, SHARED-INIT-002, FMT-BREAK-021, FMT-INDENT-022 |

RH5303 reports the collection initializer of an object creation whose braces are not in the column of `new`, or whose elements are not each on their own line one level deeper, and offers a code fix that lays out the collection initializer the way the formatter does.

## Non-goals

- Object initializers — RH5301; collection initializers assigned to a member inside an object initializer — RH5304.
- Array initializers and collection expressions (`[1, 2]`) — RH5305.
- The layout of an element after its first token, except for a complex element initializer (SHARED-INIT-002).

## Requirements

### RH5303-001 — Braces outside the column of `new` are reported

The analyzer MUST report an object creation with a collection initializer — `new T { … }`, `new T(…) { … }`, or a target-typed `new() { … }` — when its opening or its closing brace does not start at the column of the `new` keyword, the line's anchor decided by SHARED-INIT-001. A brace on the line of `new`, as in an initializer written on one line, therefore is reported.

Why: The initializer completes the expression that creates the collection; braces in the column of `new` keep it with that expression, the way the formatter lays it out (FMT-BREAK-021, FMT-INDENT-022).

Example:

```csharp
using System.Collections.Generic;

class C
{
    void M()
    {
        var a = {|RH5303:new List<int> { 1, 2 }|};
        List<int> b = new()
                      {
                          1
                      };
    }
}
```

### RH5303-002 — Elements outside their own line or column are reported

When both braces start at the column of `new`, the analyzer MUST report each element that does not start on a line of its own between the two braces — an element on the line of the opening brace, on the line of the closing brace, or on the line of the element before it — or whose first token does not start four columns to the right of the `new` keyword, the line's anchor decided by SHARED-INIT-001. When a brace is reported under RH5303-001, the elements of that initializer MUST NOT be reported.

Why: One element per line, one level inside the braces, makes each element visible and gives it its own diff line.

Example:

```csharp
using System.Collections.Generic;

class C
{
    void M()
    {
        var a = new List<int>
                {
                    1, {|RH5303:2|},
                  {|RH5303:3|}
                };
    }
}
```

### RH5303-003 — A misaligned complex element is reported

When an element starts on its own line in its column, the analyzer MUST report it when it is a complex element initializer (`{ 1, 2 }`) that SHARED-INIT-002 treats as misaligned, with the opening brace's expected column four columns to the right of the `new` keyword.

Why: A wrapped complex element is a block of its own, and its parts follow the same layout as the initializer around it.

Example: see SHARED-INIT-002.

### RH5303-004 — Where the diagnostic is

The analyzer MUST report one diagnostic located on the whole object creation expression when a brace of the collection initializer is out of place. Otherwise it MUST report one diagnostic per misplaced element, located on the whole element. For a misaligned complex element, it MUST report one diagnostic, located on the whole complex element when one of its braces is out of place, otherwise on its first misplaced expression.

Why: A misplaced brace concerns the initializer as a whole; a misplaced element or expression concerns only itself, and reporting it there keeps several of them apart.

Example: see RH5303-001, RH5303-002, and SHARED-INIT-002.

### RH5303-005 — The fix lays out the collection initializer

The code fix MUST lay out the reported object creation as the formatter lays it out: the braces start their own lines at the column of `new`, every element starts its own line one level deeper, and a wrapped complex element puts each of its expressions on its own line (FMT-BREAK-021, FMT-INDENT-022).

Why: The formatter owns the layout of collection initializers; delegating to it applies that layout instead of a second one.

Example:

```csharp
using System.Collections.Generic;

class C
{
    void M()
    {
        var a = new Dictionary<int, int>
                {
                    {
                        1, {|RH5303:2|}
                    },
                  {|RH5303:{ 3, 4 }|}
                };
    }
}
```

```csharp
using System.Collections.Generic;

class C
{
    void M()
    {
        var a = new Dictionary<int, int>
                {
                    {
                        1,
                        2
                    },
                    { 3, 4 }
                };
    }
}
```
