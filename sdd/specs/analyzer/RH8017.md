# Analyzer — RH8017 Non-private constructors must be documented

| | |
|---|---|
| ID prefix | RH8017 |
| Status | Active |
| Category | Documentation |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH8017NonPrivateConstructorsMustBeDocumentedAnalyzer` |
| Uses | SHARED-DOC-001, SHARED-DOC-002, SHARED-DOC-004, SHARED-DOC-005, SHARED-DOC-006, SHARED-DOC-007, SHARED-DOC-008 |

RH8017 reports a constructor in the non-private group that has no `<summary>` or `<inheritdoc>` documentation.

## Non-goals

- Constructors in the private group, among them the static constructors of classes, structs, records, and record structs — RH8018.
- Primary constructors, which are documented with their type — RH8001 to RH8004 and RH8007 to RH8010.
- Whether the summary has text — RH8030; the documentation of parameters — RH8101.

## Requirements

### RH8017-001 — Undocumented non-private constructors are reported

The analyzer MUST report every constructor declaration in the non-private group of SHARED-DOC-002 that is not documented, checked as SHARED-DOC-001 specifies. A constructor declaration is a constructor declared in the body of a class, struct, record, or record struct; the parameter list of a primary constructor is not one. Whether it is documented MUST be decided as SHARED-DOC-004, SHARED-DOC-005, SHARED-DOC-006, and SHARED-DOC-007 specify, and nothing is reported when SHARED-DOC-008 applies.

Why: A constructor that other code can use is part of the contract that code builds on. Without a summary, the generated documentation and the editor's tooltip show nothing, and readers have to infer what the constructor is for from its implementation.

Example:

```csharp
/// <summary>
/// Service
/// </summary>
public class Service
{
    public {|RH8017:Service|}()
    {
    }

    /// <remarks>
    /// No summary
    /// </remarks>
    protected internal {|RH8017:Service|}(int value)
    {
    }

    private protected {|RH8017:Service|}(long value)
    {
    }

    /// <summary>
    /// Creates a service
    /// </summary>
    /// <param name="value">Value</param>
    internal Service(short value)
    {
    }

    private Service(byte value)
    {
    }

    static Service()
    {
    }
}

/// <summary>
/// Point
/// </summary>
/// <param name="left">Left</param>
public class Point(int left)
{
}
```

### RH8017-002 — The diagnostic is on the constructor name

The analyzer MUST report one diagnostic per undocumented constructor declaration, located on its identifier.

Why: The name is what the documentation describes; marking it identifies the declaration without marking its whole body.

Example: see RH8017-001.
