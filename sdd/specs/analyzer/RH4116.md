# Analyzer — RH4116 Tuple type element casing

| | |
|---|---|
| ID prefix | RH4116 |
| Status | Active |
| Category | Naming |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH4116TupleElementCasingAnalyzer` |
| Uses | SHARED-CASING-001 |

RH4116 reports an element name of a tuple type that is not in PascalCase.

## Non-goals

- Element names written in a tuple expression, such as `(count: 1, total: 2)` — RH4118.
- Variables declared by a deconstruction — RH4115 and RH4117.

## Requirements

### RH4116-001 — Tuple type element names are in PascalCase

The analyzer MUST report every element name of a tuple type that is not in PascalCase as SHARED-CASING-001 defines it, wherever the tuple type is written: as the type of a field, parameter, local, or return value, as a type argument, or as an element of another tuple type. An element without a name MUST NOT be reported. The analyzer MUST report one diagnostic per element name, located on the name.

This requirement covers a tuple type that is not part of the signature of a member that overrides or implements a member declared in a referenced assembly.

Why: A named tuple element is read like a member: `result.FirstValue` looks exactly like a property access, and that is how callers use it. Naming it in PascalCase also keeps a value spelled the same whether it is returned as a tuple or as a type with properties.

Example:

```csharp
using System.Collections.Generic;

class C
{
    (int {|RH4116:count|}, int Total) _pair;

    List<(string {|RH4116:name|}, int)> _entries;

    (int {|RH4116:first|}, (int {|RH4116:inner|}, int Other) {|RH4116:nested|}) M((int {|RH4116:left|}, int Right) input)
    {
        (int {|RH4116:x|}, int Y) local = (1, 2);

        return default;
    }
}
```
