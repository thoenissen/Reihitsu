# Analyzer — RH8303 Element documentation header must be preceded by blank line

| | |
|---|---|
| ID prefix | RH8303 |
| Status | Active |
| Category | Documentation |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH8303ElementDocumentationHeaderMustBePrecededByBlankLineAnalyzer`, `RH8303ElementDocumentationHeaderMustBePrecededByBlankLineCodeFixProvider` |
| Uses | SHARED-BLANK-001, SHARED-DOC-004, SHARED-DOC-008, SHARED-FIX-008 |

RH8303 reports a documentation comment that starts its line directly below a line that is not blank, and offers a code fix that inserts a blank line above it.

## Non-goals

- The blank line between a documentation comment and the code it documents — RH8302.
- Ordinary comments (`//`, `/* */`) — RH5020.

## Requirements

### RH8303-001 — A documentation comment needs a blank line above it

The analyzer MUST report a `///` or `/** */` documentation comment that starts its line — nothing but white space stands before it on that line — when the line directly above it is not blank, as SHARED-BLANK-001 defines it, unless RH8303-002 or RH8303-003 exempts it. A line that ends with a comment behind code is not blank, and the comment does not exempt the documentation comment below it. Nothing is reported when SHARED-DOC-008 applies.

This requirement covers the documentation comments of a declaration as SHARED-DOC-004 defines them. A documentation comment that starts behind code on its line, and a `///` or `/** */` comment that is not a documentation comment of a declaration — one inside a method body, inside an argument list, in a switch section, or after an attribute list — are not covered.

Why: A documentation comment starts the description of the next element. Without a blank line above it, the element before and the documentation of the next one run together, and the reader cannot see where one member ends and the next begins.

Example:

```csharp
using System;
{|RH8303:///|} <summary>
/// Type
/// </summary>
class C
{
    /// <summary>First</summary>
    int A;
    {|RH8303:///|} <summary>Second</summary>
    int B;
    int D; // Note
    {|RH8303:/**|} <summary>Third</summary> */
    int E;

    enum Kind
    {
        First,
        {|RH8303:///|} <summary>Second</summary>
        Second,
    }
}
```

### RH8303-002 — The first documentation comment of a block is not reported

The analyzer MUST NOT report a documentation comment whose documented token directly follows an opening brace `{` — the first element of a namespace, type, or enum body — even when a comment follows the brace on its line. A documentation comment on the first line of the file MUST NOT be reported either.

Why: The opening brace already marks where the content starts, and the start of a file needs no separator; a blank line there would only pad the block.

Example:

```csharp
/// <summary>Type</summary>
class C
{
    /// <summary>First</summary>
    int A;
}

namespace N
{ // Note
    /** <summary>Type</summary> */
    class D
    {
    }
}
```

is not reported.

### RH8303-003 — A documentation comment that follows a comment or a directive is not reported

The analyzer MUST NOT report a documentation comment when the content directly before it in the trivia of the documented token, apart from white space and line breaks, is a comment — an ordinary comment or another documentation comment — or a preprocessor directive.

Why: A comment directly above a documentation comment forms one block with it, and a blank line between them would split that block. A directive already marks a boundary, and a blank line between it and the documentation would separate the directive from the code it governs.

Example:

```csharp
class C
{
    int A;
    // Ordinary comment
    /// <summary>First</summary>
    int B;
    /* Block comment */
    /// <summary>Second</summary>
    int D;
#region Values
    /// <summary>Third</summary>
    int E;
#endregion
    /** <summary>Fourth</summary> */
    int F;

    /** <summary>Fifth</summary> */
    /// <remarks>Remarks</remarks>
    int G;
}
```

is not reported.

### RH8303-004 — The diagnostic is on the comment's opening

The analyzer MUST report one diagnostic per documentation comment, located on its first three characters: the `///` of its first line or the `/**` of a delimited comment.

Why: The opening marks the line above which the blank line belongs; continuation lines of the same comment are not reported again.

Example: see RH8303-001.

### RH8303-005 — The fix inserts one empty line above the comment

The code fix MUST insert one empty line — a line break in the line ending SHARED-FIX-008 specifies, with no indentation — directly above the line of the reported documentation comment, and change nothing else.

Why: The empty line is exactly the separator the rule asks for; the comment and the code around it stay as written.

Example:

```csharp
class C
{
    int A;
    {|RH8303:///|} <summary>
    /// First
    /// </summary>
    int B;
    int D; // Note
    {|RH8303:/**|} <summary>Second</summary> */
    int E;
}
```

```csharp
class C
{
    int A;

    /// <summary>
    /// First
    /// </summary>
    int B;
    int D; // Note

    /** <summary>Second</summary> */
    int E;
}
```
