# Analyzer — RH2007 Debug.Fail must provide message text

| | |
|---|---|
| ID prefix | RH2007 |
| Status | Active |
| Category | Design |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH2007DebugFailMustProvideMessageTextAnalyzer` |
| Uses | SHARED-DEBUG-001 |

RH2007 reports a call of `System.Diagnostics.Debug.Fail` whose message has no text.

## Non-goals

- `Debug.Assert` — RH2006.
- `Trace.Fail` and failure methods of other types and test frameworks.

## Requirements

### RH2007-001 — A failure without message text is reported

The analyzer MUST report a call of `System.Diagnostics.Debug.Fail`, also when it is called through `using static`, whose `message` argument has no text as SHARED-DEBUG-001 defines it. The `message` argument is the argument named `message`, or else the argument at the position of the `message` parameter.

Why: `Debug.Fail` marks a path that should never be reached. Without a message, whoever hits it has to reconstruct from the surrounding code what the unreachable case was.

Example:

```csharp
using System.Diagnostics;
using static System.Diagnostics.Debug;

class C
{
    void M()
    {
        {|RH2007:Debug.Fail(null)|};
        {|RH2007:Fail("")|};
        {|RH2007:Debug.Fail(detailMessage: "Detail", message: "")|};
        Debug.Fail("Unreachable branch.");
        Fail("Unreachable branch.");
        Debug.Fail(detailMessage: "Detail", message: "Unreachable branch.");
    }
}
```

### RH2007-002 — Only the `message` argument is checked

The analyzer MUST NOT report a call whose `message` argument has text, whatever its detail message is, and MUST report a call whose `message` argument has no text even when its detail message has text.

Why: The message is the line a failure shows first; the detail message only adds to it.

Example:

```csharp
using System.Diagnostics;

class C
{
    void M()
    {
        Debug.Fail("Unreachable branch.", "");
        {|RH2007:Debug.Fail("   ", "Detail")|};
    }
}
```

### RH2007-003 — Only `System.Diagnostics.Debug.Fail` is checked

The analyzer MUST NOT report a call of a method named `Fail` that is not declared on `System.Diagnostics.Debug`, such as `Trace.Fail` or a method of the user's own type.

Why: The rule is about the framework's debug failure; other failure methods have their own conventions for messages.

Example:

```csharp
using System.Diagnostics;

class C
{
    void M()
    {
        Trace.Fail("");
        Check.Fail(null);
    }

    static class Check
    {
        public static void Fail(string message)
        {
        }
    }
}
```

is not reported.

### RH2007-004 — The diagnostic covers the whole call

The analyzer MUST report one diagnostic per reported call, covering the whole invocation expression.

Why: The empty message belongs to the call as a whole, not to one of its arguments alone.

Example: see RH2007-001.
