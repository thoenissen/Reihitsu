# Analyzer — RH4005 Interface name casing

| | |
|---|---|
| ID prefix | RH4005 |
| Status | Active |
| Category | Naming |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH4005InterfaceNameCasingAnalyzer`, `RH4005InterfaceNameCasingCodeFixProvider` |
| Uses | SHARED-CASING-001, SHARED-CASING-006, SHARED-CASING-007, SHARED-CASING-008, SHARED-CASING-009, SHARED-CASING-010 |

RH4005 reports an interface whose name is not an `I` followed by a PascalCase name, and offers a code fix that renames the interface and every reference to it.

## Non-goals

- Class, struct, enum, and delegate names — RH4002, RH4003, RH4004, and RH4006.

## Requirements

### RH4005-001 — Interface names are `I` followed by PascalCase

The analyzer MUST report every interface declaration whose name is not accepted. A name MUST be accepted exactly when it has at least two characters, its first character is `I`, its second character is an uppercase letter, and the whole name is in PascalCase as SHARED-CASING-001 defines it. The diagnostic MUST be located on the interface's identifier.

Why: The `I` prefix tells a reader in every signature and base list that the type is an interface. The uppercase letter after it separates the prefix from a name that merely starts with an I, such as `Index`.

Example:

```csharp
public interface IDocumentReader
{
}

public interface IHTTPClient
{
}

public interface IRepository<T>
{
}

public interface {|RH4005:iDocumentWriter|}
{
}

public interface {|RH4005:DocumentStore|}
{
}

public interface {|RH4005:Index|}
{
}

public interface {|RH4005:IOrder_Line|}
{
}

public interface {|RH4005:I|}
{
}
```

### RH4005-002 — The fix keeps an existing prefix and adds a missing one

The code fix MUST derive the new name as follows. When the old name starts with `i` or `I` that is followed by an uppercase letter, a decimal digit, or `_`, or that is the whole name, that first letter is the prefix: it is dropped, and so are the underscores directly behind it. When the old name starts with any other character than `i` or `I`, or with `i` or `I` followed by a lowercase letter, nothing is dropped. When the rest is already in PascalCase, it is kept as it is written; otherwise it is converted to the PascalCase name that SHARED-CASING-006 derives. `I` is then put in front of it. When nothing is left behind the prefix, no name can be derived, and the fix is withheld. The fix MUST rename the interface and every reference to it (SHARED-CASING-007); it is withheld as SHARED-CASING-008 and SHARED-CASING-009 specify, and its Fix All skips colliding names as SHARED-CASING-010 specifies. This requirement covers the renames that SHARED-CASING-007 covers, of an old name whose rest is already in PascalCase or is a name that SHARED-CASING-006 covers.

Why: A name such as `iDocumentReader` already carries the prefix in the wrong case; only the case is corrected. A name such as `i_document` carries it too, separated by `_`, so the separator is dropped with it rather than the prefix being doubled. A name such as `index` or `Item` starts with a word, not with a prefix, so the prefix is added in front of the whole word. A rest that is already PascalCase, such as `URL`, is a valid type name as it stands, so only the missing prefix is added. A name that is only the prefix, such as `I`, has no name behind it to keep.

Example:

```csharp
public interface {|RH4005:iDocumentReader|}
{
}

public interface {|RH4005:Repository|}<T>
{
}

public interface {|RH4005:index|}
{
}

public interface {|RH4005:Item|}
{
}

public interface {|RH4005:IOrder_Line|}
{
}

public interface {|RH4005:URL|}
{
}

public interface {|RH4005:Document_STORE|}
{
}

public interface {|RH4005:i_document|}
{
}

public interface {|RH4005:I_reader|}
{
}
```

```csharp
public interface IDocumentReader
{
}

public interface IRepository<T>
{
}

public interface IIndex
{
}

public interface IItem
{
}

public interface IOrderLine
{
}

public interface IURL
{
}

public interface IDocumentStore
{
}

public interface IDocument
{
}

public interface IReader
{
}
```

Example — a derived name that this rule still reports:

```csharp
public interface {|RH4005:_|}
{
}

public interface {|RH4005:__|}
{
}

public interface {|RH4005:_2x|}
{
}

public interface {|RH4005:注文|}
{
}
```

is reported, and no code fix is offered for any interface (SHARED-CASING-008): `_` and `__` have no letter or digit, and the derived names of the other two, `I2x` and `I注文`, are still reported by this rule, because the character after the `I` is not an uppercase letter.

Example — a prefix with nothing usable behind it:

```csharp
public interface {|RH4005:I|}
{
}

public interface {|RH4005:i|}
{
}

public interface {|RH4005:I_|}
{
}

public interface {|RH4005:i2Factory|}
{
}
```

is reported, and no code fix is offered for any interface: nothing is left behind the prefix of `I`, `i`, and `I_`, and the derived name of `i2Factory`, `I2Factory`, is still reported by this rule (SHARED-CASING-008).
