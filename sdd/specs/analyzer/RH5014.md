# Analyzer — RH5014 switch-Statement should be preceded by a blank line

| | |
|---|---|
| ID prefix | RH5014 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5014SwitchStatementsShouldBePrecededByABlankLineAnalyzer`, `RH5014SwitchStatementsShouldBePrecededByABlankLineCodeFixProvider` |
| Uses | SHARED-STMT-001, SHARED-STMT-002, SHARED-STMT-003, SHARED-STMT-004 |

RH5014 reports a `switch` statement that follows another statement of the same block or switch section without a blank line between them, and offers a code fix that inserts one as SHARED-STMT-004 specifies.

## Non-goals

- Blank lines before other statement kinds — the other rules that use `shared/statement-blank-lines.md`.

## Requirements

### RH5014-001 — A `switch` statement that follows a statement needs a blank line

The analyzer MUST report a `switch` statement as SHARED-STMT-001, SHARED-STMT-002, and SHARED-STMT-003 specify. It MUST NOT report a `switch` expression.

Why: A `switch` statement starts a multi-way decision; the blank line makes that decision visible. A `switch` expression is part of the statement that contains it.

Example:

```csharp
class C
{
    void M(int a)
    {
        a++;
        {|RH5014:switch|} (a)
        {
            case 1:
                break;
        }

        a++;
        a = a switch
        {
            1 => 2,
            _ => 3
        };
    }
}
```

The `switch` expression assigned to `a` is not a statement and is not reported.

### RH5014-002 — The diagnostic is on the `switch` keyword

The analyzer MUST report the diagnostic on the `switch` keyword.

Why: The keyword is where the missing separator becomes visible, and the location stays stable when the governing expression changes.

Example: see RH5014-001.
