# Analyzer — RH3201 Comments must contain text

| | |
|---|---|
| ID prefix | RH3201 |
| Status | Active |
| Category | Clarity |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH3201CommentsMustContainTextAnalyzer`, `RH3201CommentsMustContainTextCodeFixProvider` |
| Uses | — |

RH3201 reports a `//` or `/* */` comment that contains nothing but whitespace and offers a code fix that removes it.

## Non-goals

- Documentation comments (`///` and `/** */`) without text — the documentation rules (RH8###).
- Comments whose text says nothing useful but is not empty.

## Requirements

### RH3201-001 — An empty comment is reported

The analyzer MUST report a `//` comment whose text after `//` is empty or whitespace, and a `/* */` comment whose text between `/*` and `*/` is empty or consists of whitespace and line breaks only, wherever the comment stands, unless RH3201-002 applies. A comment that has any other character in its text MUST NOT be reported; `////` therefore has the text `//` and is not reported.

Why: An empty comment carries no information. It looks like a leftover or an unfinished thought and distracts from the comments that matter.

Example:

```csharp
class C
{
    {|RH3201://|}
    int _a;
    {|RH3201:/* */|}
    int _b; {|RH3201://|}
    // text
    int _c;
}
```

### RH3201-002 — An empty `//` line inside a block of `//` comments is not reported

The analyzer MUST NOT report an empty `//` comment when the line above it and the line below it each start with a `//` comment that is not a documentation comment. A `///` line does not count as such a line; a `////` line does.

Why: Between two lines of the same `//` comment block, the empty line is a paragraph break of one piece of prose. A documentation comment is a different block.

Example:

```csharp
class C
{
    // First.
    //
    // Second.
    int _a;

    //// First.
    //
    //// Second.
    int _b;
}
```

is not reported. Next to a documentation comment, the empty line is reported:

```csharp
class C
{
    // First.
    {|RH3201://|}
    /// <summary>Second.</summary>
    int _a;
}
```

### RH3201-003 — An unterminated block comment is not reported

The analyzer MUST NOT report a `/*` comment that has no closing `*/`.

Why: An unterminated comment is usually being typed; its text runs to the end of the file and is not empty in any useful sense.

Example:

```csharp
class C
{
}
/*
```

is not reported.

### RH3201-004 — The diagnostic covers the comment

The analyzer MUST report one diagnostic per comment, from its first to its last character.

Why: The comment is what the fix removes.

Example: see RH3201-001.

### RH3201-005 — The fix removes the comment

The code fix MUST remove the reported comment:

- when the comment is the only thing on its line, together with the whole line, its line break included;
- when code precedes the comment on its line, together with the spaces and tabs between that code and the comment.

Why: A line that held only the empty comment would otherwise stay behind as a blank line; after code, the whitespace that separated the comment has nothing left to separate.

Example:

```csharp
class C
{
    {|RH3201://|}
    int _a;
    {|RH3201:/* */|}
    int _b; {|RH3201://|}

    int M(int a, int b) => a + {|RH3201:/* */|} b;
}
```

```csharp
class C
{
    int _a;
    int _b;

    int M(int a, int b) => a + b;
}
```
