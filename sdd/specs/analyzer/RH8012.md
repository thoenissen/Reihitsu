# Analyzer — RH8012 Private enums must be documented

| | |
|---|---|
| ID prefix | RH8012 |
| Status | Active |
| Category | Documentation |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH8012PrivateEnumsMustBeDocumentedAnalyzer` |
| Uses | SHARED-DOC-001, SHARED-DOC-002, SHARED-DOC-004, SHARED-DOC-005, SHARED-DOC-006, SHARED-DOC-007, SHARED-DOC-008 |

RH8012 reports an enum in the private group that has no `<summary>` or `<inheritdoc>` documentation.

## Non-goals

- Enums in the non-private group — RH8011.
- The members of an enum — RH8013 and RH8014.
- Whether the summary has text — RH8030.

## Requirements

### RH8012-001 — Undocumented private enums are reported

The analyzer MUST report every enum declaration in the private group of SHARED-DOC-002 that is not documented, checked as SHARED-DOC-001 specifies. Enums with an underlying type are enum declarations too. Whether it is documented MUST be decided as SHARED-DOC-004, SHARED-DOC-005, SHARED-DOC-006, and SHARED-DOC-007 specify, and nothing is reported when SHARED-DOC-008 applies.

Why: A private enum is an implementation detail of its type, but the next maintainer still has to know what it is for. It has a rule of its own, so a project can require documentation for what other code uses without requiring it here.

Example:

```csharp
/// <summary>
/// Outer
/// </summary>
public class Outer
{
    private enum {|RH8012:Hidden|}
    {
    }

    /// <remarks>
    /// No summary
    /// </remarks>
    enum {|RH8012:State|} : byte
    {
    }

    /// <summary>
    /// Documented
    /// </summary>
    private enum Documented
    {
    }

    internal enum Visible
    {
    }
}
```

### RH8012-002 — The diagnostic is on the enum name

The analyzer MUST report one diagnostic per undocumented enum declaration, located on its identifier, without its underlying type.

Why: The name is what the documentation describes; marking it identifies the declaration without marking its whole body.

Example: see RH8012-001.
