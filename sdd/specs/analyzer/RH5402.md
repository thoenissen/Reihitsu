# Analyzer — RH5402 Braces for multi-line statements must not share line

| | |
|---|---|
| ID prefix | RH5402 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5402BracesForMultiLineStatementsMustNotShareLineAnalyzer`, `RH5402BracesForMultiLineStatementsMustNotShareLineCodeFixProvider` |
| Uses | SHARED-BLOCK-001, SHARED-GAP-001 |

RH5402 reports the opening brace of a multi-line statement block that is on the line of the code in front of it, and offers a code fix that moves the brace to a line of its own.

## Non-goals

- A block whose braces are on one line — RH5403 for a block with statements.
- The braces of types, members, accessors, lambdas, and switch statements.
- Where the closing brace and the code after it, such as `else` or the `while` of a `do` statement, are placed.

## Requirements

### RH5402-001 — An opening brace on the line of its statement is reported

The analyzer MUST report a block that SHARED-BLOCK-001 names when its opening brace is on the line the token in front of it ends on, and its closing brace is on a later line than its opening brace. A block whose opening brace starts a later line than that token, and a block whose closing brace is on the line of its opening brace, MUST NOT be reported.

Why: An opening brace at the end of the statement's line is easy to miss; on its own line it lines up with the closing brace and shows how far the block reaches.

Example:

```csharp
class C
{
    void M(bool a)
    {
        if (a) {|RH5402:{|}
            M(a);
        } else {|RH5402:{|}
            M(a);
        }
        do {|RH5402:{|}
            M(a);
        } while (a);
        if (a)
        {
            M(a);
        }
        if (a) { }
    }
}
```

### RH5402-002 — The diagnostic is on the opening brace

The analyzer MUST report one diagnostic per block, located on its opening brace.

Why: The opening brace is what has to move.

Example: see RH5402-001.

### RH5402-003 — The fix moves the brace to its own line

The code fix MUST replace the gap in front of the opening brace with a line break and the indentation of the line on which the statement or `else` clause that owns the block starts. When a comment or a preprocessor directive sits in that gap, the fix follows SHARED-GAP-001 and is withheld.

Why: The brace starts its own line in the column of the line that introduces the block, so the two braces of the block align with it.

Example:

```csharp
class C
{
    void M(bool a)
    {
        if (a) {|RH5402:{|}
            M(a);
        } else {|RH5402:{|}
            M(a);
        }
        if (a) /* note */ {|RH5402:{|}
            M(a);
        }
    }
}
```

```csharp
class C
{
    void M(bool a)
    {
        if (a)
        {
            M(a);
        } else
        {
            M(a);
        }
        if (a) /* note */ {|RH5402:{|}
            M(a);
        }
    }
}
```

The comment in front of the last brace withholds the fix for that brace, and its diagnostic stays.
