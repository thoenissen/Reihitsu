# Analyzer — RH6023 Assignment operators must be spaced correctly

| | |
|---|---|
| ID prefix | RH6023 |
| Status | Active |
| Category | Spacing |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH6023AssignmentOperatorsMustBeSpacedCorrectlyAnalyzer`, `RH6023AssignmentOperatorsMustBeSpacedCorrectlyCodeFixProvider` |
| Uses | FMT-SPACE-010, SHARED-OPSPACE-001, SHARED-OPSPACE-002, SHARED-OPSPACE-003, SHARED-OPSPACE-004 |

RH6023 reports an assignment operator or an initializer `=` without exactly one space on each side, as SHARED-OPSPACE-001 to SHARED-OPSPACE-003 specify, and offers a code fix that puts one space there as SHARED-OPSPACE-004 specifies.

In the examples, `→` marks a tab.

## Non-goals

- Binary operators, such as `==` and `+` — RH6024.
- The `=>` of a lambda or an expression body, and the colon of a named argument — no analyzer rule checks their spacing.

## Requirements

### RH6023-001 — Assignment and initializer `=` are checked

The analyzer MUST check, as SHARED-OPSPACE-001 and SHARED-OPSPACE-002 specify, and report as SHARED-OPSPACE-003 specifies: the operator of every assignment expression — `=` and the compound assignments `+=`, `-=`, `*=`, `/=`, `%=`, `&=`, `|=`, `^=`, `<<=`, `>>=`, `>>>=`, and `??=`, also inside an object initializer, a `with` expression, or an interpolation hole; the `=` of an initializer of a field, a local variable or constant, a property, a parameter default, or an enum member; and the `=` of a name-equals clause — a `using` alias, a named attribute argument, or an anonymous-object member.

Why: All of these assign a value, and they read alike when the operator is set off by one space on each side. The formatter puts one space on both sides of the same operators (FMT-SPACE-010), so formatted code raises no RH6023.

Example:

```csharp
using X{|RH6023:=|}System.String;

class A : System.Attribute
{
    public int N { get; set; }
}

record R(int V);

enum E
{
    One{|RH6023:=|}1,
}

class C
{
    int _f{|RH6023:=|}1;

    int P { get; }  {|RH6023:=|} 2;

    [A(N{|RH6023:=|}1)]
    void M(int a, int b{|RH6023:=|}2)
    {
        a{|RH6023:=|}1;
        a  {|RH6023:=|} 1;
        a→{|RH6023:=|} 1;
        a{|RH6023:+=|}1;
        a {|RH6023:<<=|}  1;

        object o = null;
        o{|RH6023:??=|}a;

        var n = new { V{|RH6023:=|}a };
        var c = new A { N{|RH6023:=|}1 };
        var r = new R(1) with { V{|RH6023:=|}2 };
        const int K{|RH6023:=|}3;
        var s = $"{a{|RH6023:=|}2}";

        a =
            1;
        var t = "a=1";
    }
}
```

### RH6023-002 — The fix puts one space on both sides

The code fix MUST put one space on both sides of the reported operator as SHARED-OPSPACE-004 specifies.

Why: The fix answers exactly the question the diagnostic asks.

Example:

```csharp
using X{|RH6023:=|}System.String;

class C
{
    int _f{|RH6023:=|}1;

    void M(int a, int b{|RH6023:=|}2)
    {
        a  {|RH6023:=|} 1;
        a{|RH6023:+=|}1;
        a {|RH6023:<<=|}  1;
    }
}
```

```csharp
using X = System.String;

class C
{
    int _f = 1;

    void M(int a, int b = 2)
    {
        a = 1;
        a += 1;
        a <<= 1;
    }
}
```
