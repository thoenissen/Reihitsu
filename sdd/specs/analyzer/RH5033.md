# Analyzer — RH5033 Comments must not be placed between attributes and the declaration

| | |
|---|---|
| ID prefix | RH5033 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | None |
| Code owners | `RH5033CommentsMustNotBePlacedBetweenAttributesAndDeclarationAnalyzer` |
| Uses | SHARED-COMMENT-001, SHARED-COMMENT-002, SHARED-COMMENT-003 |

RH5033 reports a comment placed after an attribute list of a declaration, between it and the next attribute list or the declaration itself.

## Non-goals

- A comment inside an attribute list — RH5044.
- A comment between a documentation comment and its declaration — RH5034.
- Where an attribute list is placed — the attribute placement rules of the RH55xx range.

## Requirements

### RH5033-001 — A comment after an attribute list of a declaration is reported

The analyzer MUST report every ordinary comment (SHARED-COMMENT-001, SHARED-COMMENT-002) directly after the closing bracket of an attribute list that belongs to a declaration — a type, a member, an enum member, an accessor, a parameter, a type parameter, a local function, or a lambda — as SHARED-COMMENT-003 specifies. A comment before the first attribute list or inside an attribute list MUST NOT be reported.

Why: The attributes and the declaration they apply to belong together. A comment between them separates the two and leaves it unclear whether it describes an attribute or the declaration.

Example:

```csharp
using System;
using System.Runtime.CompilerServices;

[Obsolete]
{|RH5033:// note|}
[Serializable]
class C
{
    [Obsolete] {|RH5033:/* note */|}
    void M([CallerMemberName] {|RH5033:/* name */|} string name = "")
    {
    }
}
```

```csharp
using System;

class C
{
    // note
    [Obsolete,
        // compliance
        CLSCompliant(false)]
    void M()
    {
    }
}
```

is not reported.

### RH5033-002 — Assembly and module attributes are not checked

The analyzer MUST NOT report a comment after an attribute list that stands at file level, such as an `assembly:` or `module:` attribute list.

Why: A file-level attribute list applies to the assembly or the module, not to the declaration that happens to follow it, so a comment after it does not separate an attribute from its declaration.

Example:

```csharp
using System;

[assembly: CLSCompliant(false)]

// note
class C
{
}
```

is not reported.
