# Analyzer — RH5026 Chained statement blocks must not be preceded by blank line

| | |
|---|---|
| ID prefix | RH5026 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5026ChainedStatementBlocksMustNotBePrecededByBlankLineAnalyzer`, `RH5026ChainedStatementBlocksMustNotBePrecededByBlankLineCodeFixProvider` |
| Uses | SHARED-BLANK-006, SHARED-FIX-001, SHARED-FIX-004, SHARED-WS-001 |

RH5026 reports a blank line directly above a line that begins with `else`, `catch`, or `finally`, and offers a code fix that deletes it, together with the rest of its run of blank lines, as SHARED-WS-001 specifies for that run.

In the examples, a reported blank line is marked from its start to the end of its line break, so the markup encloses the line break itself.

## Non-goals

- The `while` of a `do` statement — RH5027.
- A blank line directly above `} else` or `} catch`, where the line begins with the closing brace — RH5024.

## Requirements

### RH5026-001 — A blank line above a chained keyword is reported

The analyzer MUST report the blank line directly above a line that begins with an `else`, `catch`, or `finally` keyword — only whitespace stands in front of the keyword on its line — including the `else` of an `else if`. A line holding nothing but whitespace counts as blank.

Why: These keywords continue the statement above them; a blank line makes the continuation look like a new statement.

Example:

```csharp
class C
{
    void M(bool flag)
    {
        if (flag)
        {
        }
{|RH5026:
|}        else if (flag)
        {
        }
{|RH5026:
|}        else
        {
        }

        try
        {
        }
{|RH5026:
|}        catch
        {
        }
{|RH5026:
|}        finally
        {
        }
    }
}
```

### RH5026-002 — Only a keyword that begins its line is considered

The analyzer MUST NOT report a blank line above a line on which the keyword follows other code, such as `} else`, above an identifier that merely begins with one of the keywords, or above a keyword in the text of a comment, a string literal, or code that an `#if` branch excludes.

Why: Only a keyword that starts its line is separated from the statement above it by the blank line; on `} else` the blank line sits above the brace, which RH5024 reports.

Example:

```csharp
class C
{
    void M(bool flag)
    {
        if (flag)
        {
            flag = false;

        } else
        {
        }

        var elseValue = 1;

        /*

        else */
    }
}
```

is not reported.

### RH5026-003 — One diagnostic per keyword, on the line directly above it

The analyzer MUST report one diagnostic per keyword, located on the line directly above it, from the line's start to the end of its line break.

Why: The diagnostic covers exactly the line the keyword touches, which the fix deletes together with the rest of its run.

Example: see RH5026-001.

### RH5026-004 — The fix deletes the run of blank lines

The code fix MUST delete the reported line together with every blank line of the run it belongs to — the blank lines that directly precede it, up to the previous line that is not blank — and MUST NOT change any other text, as SHARED-WS-001 specifies for the span of that run. It is offered for every reported line.

Why: The run holds nothing but whitespace and line breaks, so deleting it can never touch a comment, a directive, or a token. One application removes the whole run (SHARED-FIX-001); deleting only the reported line would leave a blank line that the rule reports again.

Example:

```csharp
class C
{
    void M()
    {
        try
        {
        }
{|RH5026:
|}        catch
        {
        }
{|RH5026:
|}        finally
        {
        }
    }
}
```

```csharp
class C
{
    void M()
    {
        try
        {
        }
        catch
        {
        }
        finally
        {
        }
    }
}
```

Example — a run of two blank lines; RH5023 reports the line directly above the keyword as well:

```csharp
class C
{
    void M(int a)
    {
        if (a > 0)
        {
        }

{|RH5026:
|}        else
        {
        }
    }
}
```

```csharp
class C
{
    void M(int a)
    {
        if (a > 0)
        {
        }
        else
        {
        }
    }
}
```

### RH5026-005 — A blank line below a region directive is not reported

The analyzer MUST NOT report a blank line above a chained keyword when the nearest line above it that is not blank holds an active `#region` or `#endregion` directive. A run of two or more blank lines there is not reported by RH5026 either; RH5023 reports every line after the first.

Why: SHARED-BLANK-006 requires the line below a region directive to be blank — its exemption for `#endregion` applies only in front of `}`, and RH5026 considers only a line that begins with the keyword — and RH5032 inserts that line. Deleting it would undo RH5032's fix, and the two fixes would alternate forever (SHARED-FIX-004).

Example:

```csharp
class C
{
    void M(int a)
    {
        if (a > 0)
        {
        }
        #region R

        else
        {
        }
        #endregion // R
    }
}
```

is not reported by RH5026. A blank line whose nearest line above that is not blank holds code or a comment stays reported as RH5026-001 states.
