# Analyzer — RH5026 Chained statement blocks must not be preceded by blank line

| | |
|---|---|
| ID prefix | RH5026 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5026ChainedStatementBlocksMustNotBePrecededByBlankLineAnalyzer`, `RH5026ChainedStatementBlocksMustNotBePrecededByBlankLineCodeFixProvider` |
| Uses | SHARED-WS-001 |

RH5026 reports a blank line directly above a line that begins with `else`, `catch`, or `finally`, and offers a code fix that deletes it as SHARED-WS-001 specifies.

In the examples, a reported blank line is marked from its start to the end of its line break, so the markup encloses the line break itself.

## Non-goals

- The `while` of a `do` statement — RH5027.
- A blank line directly above `} else` or `} catch`, where the line begins with the closing brace — RH5024.
- The other blank lines of a run above the keyword — RH5023.

## Requirements

### RH5026-001 — A blank line above a chained keyword is reported

The analyzer MUST report the blank line directly above a line that begins with an `else`, `catch`, or `finally` keyword — only whitespace stands in front of the keyword on its line — including the `else` of an `else if`. A line holding nothing but whitespace counts as blank.

Why: These keywords continue the statement above them; a blank line makes the continuation look like a new statement.

Example:

```csharp
class C
{
    void M(bool flag)
    {
        if (flag)
        {
        }
{|RH5026:
|}        else if (flag)
        {
        }
{|RH5026:
|}        else
        {
        }

        try
        {
        }
{|RH5026:
|}        catch
        {
        }
{|RH5026:
|}        finally
        {
        }
    }
}
```

### RH5026-002 — Only a keyword that begins its line is considered

The analyzer MUST NOT report a blank line above a line on which the keyword follows other code, such as `} else`, above an identifier that merely begins with one of the keywords, or above a keyword in the text of a comment, a string literal, or code that an `#if` branch excludes.

Why: Only a keyword that starts its line is separated from the statement above it by the blank line; on `} else` the blank line sits above the brace, which RH5024 reports.

Example:

```csharp
class C
{
    void M(bool flag)
    {
        if (flag)
        {
            flag = false;

        } else
        {
        }

        var elseValue = 1;

        /*

        else */
    }
}
```

is not reported.

### RH5026-003 — One diagnostic per keyword, on the line directly above it

The analyzer MUST report one diagnostic per keyword, located on the line directly above it, from the line's start to the end of its line break.

Why: The diagnostic covers exactly the line the keyword touches; a run of blank lines is RH5023's concern.

Example: see RH5026-001.

### RH5026-004 — The fix deletes the blank line

The code fix MUST delete the reported line as SHARED-WS-001 specifies. It is offered for every reported line.

Why: The reported span holds nothing but whitespace and its line break, so deleting it can never touch a comment, a directive, or a token.

Example:

```csharp
class C
{
    void M()
    {
        try
        {
        }
{|RH5026:
|}        catch
        {
        }
{|RH5026:
|}        finally
        {
        }
    }
}
```

```csharp
class C
{
    void M()
    {
        try
        {
        }
        catch
        {
        }
        finally
        {
        }
    }
}
```
