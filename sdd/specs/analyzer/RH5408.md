# Analyzer — RH5408 Simple auto-properties should be single lined

| | |
|---|---|
| ID prefix | RH5408 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5408SimpleAutoPropertiesShouldBeSingleLinedAnalyzer`, `RH5408SimpleAutoPropertiesShouldBeSingleLinedCodeFixProvider` |
| Uses | FMT-BREAK-024 |

RH5408 reports a simple auto-property that spans several lines, and offers a code fix that puts the declaration on one line the way the formatter does.

## Non-goals

- Indexers, events, and properties whose accessors have a body or an expression body.
- The line of a property-level attribute list.

## Requirements

### RH5408-001 — A simple auto-property on several lines is reported

The analyzer MUST report a property whose accessor list holds only accessors without a body and without an expression body — such as `get;`, `set;`, `init;`, also with an accessor modifier — when the declaration from its first modifier, or its type when it has none, to its end spans several lines. The declaration's end is the closing brace of the accessor list, or the semicolon after its initializer. A simple auto-property on one line MUST NOT be reported.

Why: An auto-property is a single declaration; spreading `get;` and `set;` over several lines adds height without information, and the initializer and the semicolon belong to the same declaration (FMT-BREAK-024).

Example:

```csharp
class C
{
    {|RH5408:int A
    {
        get;
        set;
    }|}

    {|RH5408:int B { get;
        private set; } = 5;|}

    {|RH5408:int D { get; init; }
        = 5;|}

    {|RH5408:int E { get; set; } = 5
        ;|}

    int F { get; set; } = 5;
}
```

### RH5408-002 — A property that is not simple, or that cannot be joined, is not reported

The analyzer MUST NOT report a property when:

- an accessor carries an attribute list of its own;
- the signature, from the first modifier or the type to the token in front of the accessor list, spans several lines; or
- the value of its initializer spans several lines.

Why: An attribute on an accessor makes the accessor list more than a plain list of accessors, and its layout belongs to the attribute rules (RH5530 and RH5531). A wrapped signature or a wrapped value cannot be on one line with the rest of the declaration, so asking for one line would ask for the impossible.

Example:

```csharp
using System;

class C
{
    int A
    {
        [Obsolete] get;
    }

    public
        int B
    {
        get;
    }

    int D { get; set; } = N(1,
                            2);

    static int N(int a, int b) => a;
}
```

is not reported.

### RH5408-003 — A comment or directive that blocks the join is not reported

The analyzer MUST NOT report a property when a comment or a preprocessor directive sits inside its accessor list, between its signature and the accessor list, or inside its initializer, or when one sits in a gap that holds a line break in front of the initializer's `=` or in front of the semicolon. A comment behind the declaration MUST NOT keep it from being reported.

Why: Joining the declaration onto one line would move the comment or the directive into the middle of the line or comment out the code behind it; the author decides where it goes. A comment behind the semicolon stays where it is.

Example:

```csharp
class C
{
    int A
    {
        get; // note
    }

    int B // note
    {
        get;
    }

    int D { get; set; } // note
        = 5;
}
```

is not reported, while

```csharp
class C
{
    {|RH5408:int A
    {
        get;
    }|} // note
}
```

is reported.

### RH5408-004 — The diagnostic covers the declaration without its attributes

The analyzer MUST report one diagnostic per property, located from its first modifier, or its type when it has none, to the end of the declaration. Attribute lists of the property MUST NOT be part of the location.

Why: A property-level attribute keeps its own line, so it is not part of what has to be joined.

Example:

```csharp
using System;

class C
{
    [Obsolete]
    {|RH5408:public int A
    {
        get;
    }|}
}
```

### RH5408-005 — The fix puts the declaration on one line

The code fix MUST format the reported property as the formatter formats it in place: the signature, the accessor list, the initializer, and the semicolon on one line (FMT-BREAK-024). A property-level attribute list stays on its own line above the declaration.

Why: The formatter owns the layout of auto-properties; delegating to it applies that layout instead of a second one.

Example:

```csharp
using System;

class C
{
    [Obsolete]
    {|RH5408:public int A
    {
        get;
    }|}

    {|RH5408:int B { get;
        private set; } = 5;|}

    {|RH5408:int E { get; set; } = 5
        ;|}
}
```

```csharp
using System;

class C
{
    [Obsolete]
    public int A { get; }

    int B { get; private set; } = 5;

    int E { get; set; } = 5;
}
```
