# Analyzer — RH8204 Do not use placeholder elements

| | |
|---|---|
| ID prefix | RH8204 |
| Status | Active |
| Category | Documentation |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH8204DoNotUsePlaceholderElementsAnalyzer`, `RH8204DoNotUsePlaceholderElementsCodeFixProvider` |
| Uses | SHARED-DOC-004, SHARED-DOC-008 |

RH8204 reports a `<placeholder>` element in a documentation comment, and offers a code fix that replaces the element with its content.

## Non-goals

- The content, order, and layout of the remaining documentation — RH8301 to RH8309.

## Requirements

### RH8204-001 — A `<placeholder>` element is reported

The analyzer MUST report every `<placeholder>` element in the documentation comments of a declaration, as SHARED-DOC-004 defines them: at the top level or nested inside another element, inside a `<code>` or an `<example>` element as well, in a later documentation comment as well as in the first, and whatever the declaration. Nothing is reported when SHARED-DOC-008 applies.

This requirement covers documentation comments placed as SHARED-DOC-004 covers, with the tag name `placeholder` written in lower case, without a namespace prefix, and in no XML namespace. A `///` or `/** */` comment that is not a documentation comment of a declaration as SHARED-DOC-004 defines it, such as one inside a method body, after an attribute list, or between modifiers, is not covered.

Why: A placeholder marks documentation that is still to be written. Left in committed code, it makes the documentation look unfinished and shows the reader a stand-in instead of the final text.

Example:

```csharp
/// <summary>
/// Saves the {|RH8204:<placeholder>current customer</placeholder>|}
/// </summary>
public class C
{
    /// <summary>
    /// Runs
    /// </summary>

    /// <remarks>
    /// {|RH8204:<placeholder/>|}
    /// </remarks>
    public void Run()
    {
    }

    /// <summary>
    /// Count
    /// </summary>
    /// <example><code>{|RH8204:<placeholder>Sample</placeholder>|}</code></example>
    private int _count;
}
```

### RH8204-002 — The diagnostic is on the element

The analyzer MUST report one diagnostic per `<placeholder>` element, located on the whole element: the empty element, or everything from the start tag through the end tag. A `<placeholder>` element nested inside another `<placeholder>` element MUST be reported as well.

This requirement covers a `<placeholder>` element that is empty or closed by its own end tag `</placeholder>`.

Why: The element is what the fix replaces, so the squiggle shows the text that will change.

Example:

```csharp
/// <summary>
/// Saves {|RH8204:<placeholder>the {|RH8204:<placeholder>current</placeholder>|} customer</placeholder>|}
/// </summary>
public class C
{
}
```

### RH8204-003 — The fix replaces the element with its content

The code fix MUST replace the reported `<placeholder>` element with its content and keep everything around the element as it is; an empty element (`<placeholder/>`) is removed. When the element's text is not well-formed XML, such as content with an unescaped `&`, the fix MUST remove only the start and end tags.

This requirement covers a `<placeholder>` element without attributes that is empty or closed by its own end tag `</placeholder>`, and whose content is empty or is text with at least one character that is not white space, without character references, entity references, XML elements, and `>` characters; content that spans several lines is covered in a document whose line breaks are `\n`.

Why: The content of a placeholder is the text that was meant to be there; removing only the tags keeps it and finishes the sentence around it.

Example:

```csharp
/// <summary>
/// Saves the {|RH8204:<placeholder>current
/// customer</placeholder>|} now
/// </summary>
public class C
{
    /// <summary>
    /// Runs {|RH8204:<placeholder/>|} quickly
    /// </summary>
    public void Run()
    {
    }

    /// <summary>
    /// Handles {|RH8204:<placeholder>a & b</placeholder>|}
    /// </summary>
    public void Stop()
    {
    }
}
```

```csharp
/// <summary>
/// Saves the current
/// customer now
/// </summary>
public class C
{
    /// <summary>
    /// Runs  quickly
    /// </summary>
    public void Run()
    {
    }

    /// <summary>
    /// Handles a & b
    /// </summary>
    public void Stop()
    {
    }
}
```
