# Analyzer — RH8204 Do not use placeholder elements

| | |
|---|---|
| ID prefix | RH8204 |
| Status | Active |
| Category | Documentation |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH8204DoNotUsePlaceholderElementsAnalyzer`, `RH8204DoNotUsePlaceholderElementsCodeFixProvider` |
| Uses | SHARED-DOC-004, SHARED-DOC-008, SHARED-DOC-017, SHARED-FIX-006, SHARED-FIX-008 |

RH8204 reports a `<placeholder>` element in a documentation comment, and offers a code fix that replaces the element with its content.

## Non-goals

- The content, order, and layout of the remaining documentation — RH8301 to RH8309.

## Requirements

### RH8204-001 — A `<placeholder>` element is reported

The analyzer MUST report every `<placeholder>` element in the documentation comments of a declaration, as SHARED-DOC-004 defines them: at the top level or nested inside another element, inside a `<code>` or an `<example>` element as well, in a later documentation comment as well as in the first, and whatever the declaration. Nothing is reported when SHARED-DOC-008 applies.

This requirement covers documentation comments placed as SHARED-DOC-004 covers, with the tag name `placeholder` written in lower case, without a namespace prefix, and in no XML namespace. A `///` or `/** */` comment that is not a documentation comment of a declaration as SHARED-DOC-004 defines it, such as one inside a method body, after an attribute list, or between modifiers, is not covered.

Why: A placeholder marks documentation that is still to be written. Left in committed code, it makes the documentation look unfinished and shows the reader a stand-in instead of the final text.

Example:

```csharp
/// <summary>
/// Saves the {|RH8204:<placeholder>current customer</placeholder>|}
/// </summary>
public class C
{
    /// <summary>
    /// Runs
    /// </summary>

    /// <remarks>
    /// {|RH8204:<placeholder/>|}
    /// </remarks>
    public void Run()
    {
    }

    /// <summary>
    /// Count
    /// </summary>
    /// <example><code>{|RH8204:<placeholder>Sample</placeholder>|}</code></example>
    private int _count;
}
```

### RH8204-002 — The diagnostic is on the element

The analyzer MUST report one diagnostic per `<placeholder>` element, located on the whole element: the empty element, or everything from the start tag through the end tag. A `<placeholder>` element nested inside another `<placeholder>` element MUST be reported as well. A `<placeholder>` element that has no end tag of its own, as SHARED-DOC-017 defines it, MUST be located from its start tag to where the parser ends it: through the end tag of another name that closes it, or, when it has no end tag at all, to the end of the documentation comment, the line break of its last line included.

This requirement covers a `<placeholder>` element that is empty, closed by its own end tag `</placeholder>`, closed by an end tag of another name, or without an end tag at all.

Why: The element is what the fix replaces, so the squiggle shows the text that will change; where the element has no end tag of its own and no fix is offered, it shows how far the element reaches.

Example:

```csharp
/// <summary>
/// Saves {|RH8204:<placeholder>the {|RH8204:<placeholder>current</placeholder>|} customer</placeholder>|}
/// </summary>
public class C
{
}
```

Example — elements without an end tag of their own:

```csharp
/// <summary>C</summary>
public class C
{
    /// <remarks>Fast</remarks>
    /// <placeholder>Later text
    public void Run()
    {
    }

    /// <remarks><placeholder>Later text</remarks>
    public void Stop()
    {
    }
}
```

The first `<placeholder>` is reported from its start tag through the line break at the end of its line, where the documentation comment ends; the second from its start tag through `</remarks>`.

### RH8204-003 — The fix replaces the element with its content

The code fix MUST replace the reported `<placeholder>` element with its content and keep everything around the element as it is; an empty element (`<placeholder/>`) is removed. The fix MUST remove only the start and end tags and keep the content exactly as it is written, character for character: character and entity references stay references, a `>` stays as written, a nested element keeps its quotes, its attributes, and its empty-element form, content of white space only stays, and the line breaks inside the content keep their line ending. The same holds when the element's text is not well-formed XML, such as content with an unescaped `&`.

This requirement covers a `<placeholder>` element, with or without attributes, that is empty or closed by its own end tag `</placeholder>`, whatever its content: empty, white space only, or text with character references, entity references, `>` characters, XML elements, XML comments, or CDATA sections, on one line or on several lines in a document whose line breaks are `\n` or `\r\n`. Content that holds another `<placeholder>` element is not covered. A `<placeholder>` element that has no end tag of its own gets no code fix (SHARED-DOC-017).

Why: The content of a placeholder is the text that was meant to be there; removing only the tags keeps it and finishes the sentence around it. The content is what the author wrote, not what the diagnostic is about, so the fix does not rewrite its markup or its line endings (SHARED-FIX-006, SHARED-FIX-008).

Example:

```csharp
/// <summary>
/// Saves the {|RH8204:<placeholder>current
/// customer</placeholder>|} now
/// </summary>
public class C
{
    /// <summary>
    /// Runs {|RH8204:<placeholder/>|} quickly
    /// </summary>
    public void Run()
    {
    }

    /// <summary>
    /// Handles {|RH8204:<placeholder>a & b</placeholder>|}
    /// </summary>
    public void Stop()
    {
    }
}
```

```csharp
/// <summary>
/// Saves the current
/// customer now
/// </summary>
public class C
{
    /// <summary>
    /// Runs  quickly
    /// </summary>
    public void Run()
    {
    }

    /// <summary>
    /// Handles a & b
    /// </summary>
    public void Stop()
    {
    }
}
```

Example — content kept as written:

```csharp
/// <summary>
/// Saves the {|RH8204:<placeholder>a &#32; <see cref='C'/> b</placeholder>|}
/// </summary>
public class C
{
    /// <summary>
    /// Runs if {|RH8204:<placeholder>a > b</placeholder>|}
    /// </summary>
    public void Run()
    {
    }

    /// <summary>
    /// Stops the{|RH8204:<placeholder> </placeholder>|}customer
    /// </summary>
    public void Stop()
    {
    }
}
```

```csharp
/// <summary>
/// Saves the a &#32; <see cref='C'/> b
/// </summary>
public class C
{
    /// <summary>
    /// Runs if a > b
    /// </summary>
    public void Run()
    {
    }

    /// <summary>
    /// Stops the customer
    /// </summary>
    public void Stop()
    {
    }
}
```

In a document whose line breaks are `\r\n`, the first example of this requirement keeps the `\r\n` between `current` and `customer`.
