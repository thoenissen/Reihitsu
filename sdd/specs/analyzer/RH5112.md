# Analyzer — RH5112 Wrapped fluent calls should keep the first call on the original line

| | |
|---|---|
| ID prefix | RH5112 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5112WrappedFluentCallsShouldKeepFirstCallOnOriginalLineAnalyzer`, `RH5112WrappedFluentCallsShouldKeepFirstCallOnOriginalLineCodeFixProvider` |
| Uses | SHARED-CHAIN-001, SHARED-CHAIN-003, SHARED-CHAIN-004, SHARED-CHAIN-008, SHARED-CHAIN-009 |

RH5112 reports the first link of a member-access chain when it starts a line below its root, and offers a code fix that lays the chain out the way the formatter does.

## Non-goals

- The links after the first one: whether they start a line and where they are aligned — RH5201.
- A comment between the root and the first link — RH5048.

## Requirements

### RH5112-001 — A first link that starts a line is reported

The analyzer MUST report a chain (SHARED-CHAIN-001) whose first link starts a line, whether the first link is a call, a property read, or a conditional or null-forgiving access, as SHARED-CHAIN-003 requires. A chain whose first link stays on the line the root ends on MUST NOT be reported, also when a later link starts a line, and a link directly behind the closing delimiter of a multi-line raw string literal counts as staying on that line.

Why: The root says what the chain operates on; a first link on a new line separates the receiver from the first thing done to it (SHARED-CHAIN-003).

Example:

```csharp
#nullable enable
using System.Linq;

class C
{
    C? Next { get; set; }
    int[] Items { get; } = [];

    C Self() => this;

    void M(C? c, C d)
    {
        var a = c
            {|RH5112:?|}.Self()
            .Self();
        var b = d
            {|RH5112:.|}Next;
        var e = d.Items
            .Where(x => x > 0);
        var f = """
            x
            """.Trim();
    }
}
```

### RH5112-002 — A comment or directive in front of the first link suppresses the diagnostic

The analyzer MUST NOT report the chain when a comment, a preprocessor directive, or disabled text sits between the root and the first link (SHARED-CHAIN-004).

Why: The first link cannot join the root's line without moving the comment or the directive; RH5048 reports the comment instead, so the author can move it.

Example:

```csharp
using System.Linq;

class C
{
    void M(int[] items)
    {
        var a = items // only positive
            .Where(x => x > 0)
            .ToList();
        var b = items
#if DEBUG
            .Where(x => x > 0)
#endif
            .ToList();
    }
}
```

is not reported.

### RH5112-003 — The diagnostic is on the first link's operator

The analyzer MUST report one diagnostic per chain, located on the first token of its first link's operator: the `.`, the `?` of `?.`, or the `!` of `!.` and `!?.`.

Why: The operator is the token that starts the misplaced line, and its first token is where the line break has to go.

Example: see RH5112-001.

### RH5112-004 — The fix lays out the chain

The code fix MUST lay out the chain as SHARED-CHAIN-008 and SHARED-CHAIN-009 specify, which joins the first link to the root's line and aligns the later wrapped links under it.

Why: Joining only the first link would leave the later links aligned to the column the first link had; the formatted layout of the whole chain clears every chain diagnostic at once.

Example:

```csharp
using System.Linq;

class C
{
    void M(int[] items)
    {
        var a = items
            {|RH5112:.|}Where(x => x > 0)
            .ToList();
    }
}
```

```csharp
using System.Linq;

class C
{
    void M(int[] items)
    {
        var a = items.Where(x => x > 0)
                     .ToList();
    }
}
```
