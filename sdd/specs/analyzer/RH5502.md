# Analyzer — RH5502 Assembly attribute lists must use one attribute per list

| | |
|---|---|
| ID prefix | RH5502 |
| Status | Active |
| Category | Layout |
| Severity | Warning |
| Enabled by default | Yes |
| Code fix | Fix All |
| Code owners | `RH5502AssemblyAttributeListsMustFollowShapeRulesAnalyzer`, `RH5502AssemblyAttributeListsMustFollowShapeRulesCodeFixProvider` |
| Uses | SHARED-ATTR-002, SHARED-ATTR-013, SHARED-ATTR-014, SHARED-ATTR-016, SHARED-ATTR-017, SHARED-ATTR-019 |

RH5502 reports an assembly attribute list that holds more than one attribute, and offers a code fix that gives each attribute a list of its own. The rule uses `shared/attribute-targets.md`.

## Non-goals

- Module attributes — RH5504.
- Where an assembly attribute list is placed — RH5501.

## Requirements

### RH5502-001 — Assembly attribute lists hold one attribute

The analyzer MUST check every attribute list with the `assembly:` specifier that is not attached to a parameter or type parameter (SHARED-ATTR-002), and MUST report such a list that holds more than one attribute, as SHARED-ATTR-013 and SHARED-ATTR-014 specify.

Why: Assembly attributes have nothing to do with one another — one sets a title, another marks the assembly as CLS-compliant; one list per attribute lets a change to one of them change exactly one line.

Example:

```csharp
{|RH5502:[assembly: A, B]|}
[assembly: D]
[assembly: E]
```

### RH5502-002 — The diagnostic is on the attribute list

The analyzer MUST report the diagnostic on the attribute list, as SHARED-ATTR-016 specifies.

Why: The list is what has the wrong shape; each list of a declaration is reported and fixed on its own.

Example: see RH5502-001.

### RH5502-003 — The fix gives each attribute a list of its own

The code fix MUST replace the list with one list per attribute, each on its own line, as SHARED-ATTR-017 specifies.

Why: The fix makes only the change the diagnostic asks for: the attributes keep their order and their specifier, and each gets a line of its own.

Example:

```csharp
{|RH5502:[assembly: A, B]|}
class C
{
}
```

```csharp
[assembly: A]
[assembly: B]
class C
{
}
```

### RH5502-004 — The fix is withheld for a comment or directive inside the list

The code fix MUST NOT be offered when SHARED-ATTR-019 withholds it. The diagnostic is still reported.

Why: A comment inside the list belongs to the attribute next to it, and only the author can tell which of the new lists it belongs to.

Example:

```csharp
{|RH5502:[assembly: A, /* c */ B]|}
class C
{
}
```

is reported, and no code fix is offered.
