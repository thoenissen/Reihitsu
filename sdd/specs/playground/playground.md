# Playground — Formatting in the browser

| | |
|---|---|
| ID prefix | PLAY |
| Status | Active |
| Code owners | `Home`, `MainLayout`, `PlaygroundFormatter`, `PlaygroundFormatResult`, `PlaygroundVersion` |
| Uses | FMT-PIPE-004, FMT-PIPE-005, FMT-PIPE-006, FMT-PIPE-008 |

This spec covers the user-visible behavior of the Reihitsu Playground, a Blazor WebAssembly page that formats pasted C# with the Reihitsu formatter: what it shows, when it formats, and what it does with input it cannot format.

## Non-goals

- The formatting itself — FMT-PIPE and the phase specs.
- Analyzer diagnostics. The Playground runs only the formatter.
- Hosting and deployment (`deploy-pages.yml`), styling, and the framework's loading and error screens.
- Choosing a language version, sharing a link to the input, and download or upload of files — the Playground has none of these.
- Input marked as generated (`// <auto-generated/>`). The formatter leaves it unchanged (FMT-PIPE-006) and the Playground currently shows it unchanged without a message; whether it should say why is an open question.

## Requirements

### PLAY-001 — Formatting runs in the browser

The Playground MUST format the input inside the browser and MUST NOT send the input anywhere. The page MUST say so above the editors: "Paste C# source below and format it with the Reihitsu formatter. Formatting runs entirely in your browser; nothing is uploaded anywhere."

Why: Users paste proprietary code to try the formatter; the promise that it stays local is what makes that acceptable, and it is true because the formatter is compiled to WebAssembly and runs client-side.

### PLAY-002 — Input on the left, read-only output on the right

The page MUST show an editable "Input" text area and a read-only "Formatted output" text area side by side, with a "Format" button below them. Spell checking MUST be off in both.

Why: Before and after next to each other is what a user compares; the output is a result, not a second editor.

### PLAY-003 — The page opens with a formatted example

On load, the input MUST contain the example `public class Sample{public int Add(int a,int b){return a+b;}}` and the output MUST already show it formatted.

Why: A first-time visitor sees what the formatter does without typing anything.

Example — the output on load:

```csharp
public class Sample
{
    public int Add(int a, int b)
    {
        return a + b;
    }
}
```

### PLAY-004 — The output changes only on "Format"

The Playground MUST format the current input and replace the output when the "Format" button is pressed, and MUST NOT format while the user types.

Why: Formatting on every keystroke would rewrite the output for half-typed code that does not parse yet and would flash the syntax error message constantly.

### PLAY-005 — The whole input is formatted as one file

The Playground MUST parse the input as one C# file with Roslyn's default parse options — the default language version, no preprocessor symbols — and format it with `ReihitsuFormatter.FormatSyntaxTree`, so the result equals the formatter's document-level output for that text (FMT-PIPE-008 for the language version). Line breaks in the input decide the line ending of the output (FMT-PIPE-007), and the result is idempotent (FMT-PIPE-004).

Why: The Playground is a window onto the formatter, not a second formatter; it must show what `reihitsu-format` would write for the same file.

### PLAY-006 — Input with syntax errors is shown unchanged with a message

When the input has a syntax error, the Playground MUST show the input unchanged as the output and show the message "The input contains syntax errors and was left unchanged." below the button. The message MUST disappear on the next successful format.

Why: The formatter never formats code it cannot parse (FMT-PIPE-005); without the message the unchanged output would look like the formatter had nothing to do.

Example — input:

```csharp
public class Sample{ int x }
```

The output is the same text, and the message is shown.

### PLAY-007 — The page shows the formatter version

The footer MUST show the informational version of the `Reihitsu.Formatter` assembly the page runs, as `v<version>`, and the header MUST link to the GitHub repository.

Why: A user who reports a formatting result from the Playground needs to say which version produced it.
