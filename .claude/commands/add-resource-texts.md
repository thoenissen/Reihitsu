# Add Resource Texts

Add or update localized resource texts in Reihitsu. Use when introducing new analyzer or code-fix strings in the `.resx`-based resource system.

## Goal

Keep resource texts consistent across:

1. the `.resx` source of truth
2. the handwritten code-fix wrapper class
3. the analyzer/code-fix call sites

Analyzer texts have no per-rule wrapper property: the analyzer base finds them by the rule's ID.

## Resource locations

### Analyzer texts

- `src/Reihitsu.Analyzer/AnalyzerResources.resx` — every analyzer text
- `src/Reihitsu.Analyzer/AnalyzerResources.cs` — the `ResourceManager` only; it holds no property per rule

Every analyzer rule has exactly two resources, named after its diagnostic ID:

- `RH####Title`
- `RH####MessageFormat`

`DiagnosticAnalyzerBase` derives both names from the diagnostic ID the analyzer passes to it and reads them through `AnalyzerResources.ResourceManager` as `LocalizableResourceString`s. An analyzer names no resource itself. The base publishes the two texts as properties of the analyzer (`Title` and `MessageFormat`), so a unit test checks for every analyzer that both texts exist, and analyzer tests take a message from the analyzer's `MessageFormat` property.

### Code-fix texts

- `src/Reihitsu.Analyzer.CodeFixes/CodeFixResources.resx`
- `src/Reihitsu.Analyzer.CodeFixes/CodeFixResources.cs`

Code-fix resources usually contain:

- `RH####Title`

These are consumed through `CodeFixResources.RH####Title`.

## Required workflow

When adding a new resource text:

1. Add the new key to the correct `.resx` file, named after the diagnostic ID.
2. For a code-fix text, add the matching property to `CodeFixResources` and use it from the code fix. For an analyzer text, add nothing else: the analyzer base finds the resource by the ID.
3. Build and run the relevant tests.

## Wrapper rules

The resource classes are **handwritten source files**, not generated artifacts.

- Do **not** create or restore `.Designer.cs` files.
- Do **not** add `<auto-generated>` comments.
- Do **not** reintroduce `ResXFileCodeGenerator`, `LastGenOutput`, `AutoGen`, or related project metadata.
- Keep the resource classes as normal `internal static class` types with a `ResourceManager`.
- `CodeFixResources` keeps one string-returning property per text.
- Do **not** add per-rule properties to `AnalyzerResources`; it would grow by two properties with every rule.

## Naming rules

- Analyzer titles: `RH####Title`
- Analyzer messages: `RH####MessageFormat`
- Code-fix titles: `RH####Title`

Use the same key name in the `.resx` entry, the code-fix wrapper property, and the consuming code. An analyzer resource whose name differs from `<diagnostic ID>Title` or `<diagnostic ID>MessageFormat` is never found.

## Example

If you add a new analyzer rule `RH9999`:

1. Add `RH9999Title` and `RH9999MessageFormat` to `src/Reihitsu.Analyzer/AnalyzerResources.resx`.
2. Pass the analyzer's diagnostic ID to the base; it reads `RH9999Title` and `RH9999MessageFormat` from the resources.
3. In the analyzer's tests, take the expected message from the analyzer's `MessageFormat` property, not from a string literal.

If you add a matching code fix:

1. Add `RH9999Title` to `src/Reihitsu.Analyzer.CodeFixes/CodeFixResources.resx`.
2. Add this property to `src/Reihitsu.Analyzer.CodeFixes/CodeFixResources.cs`:

   ```cs
   internal static string RH9999Title => GetString(nameof(RH9999Title));
   ```

## Validation

```shell
scripts/build.sh
scripts/test.sh --project analyzer
```

If the change touches code fixes or formatter-coupled behavior, also run `scripts/test.sh --project formatter`.

## What to avoid

- Do not edit only `CodeFixResources.resx` and forget the wrapper property.
- Do not add code-fix wrapper properties without adding the matching `.resx` key.
- Do not name an analyzer resource other than `<diagnostic ID>Title` and `<diagnostic ID>MessageFormat`.
- Do not put analyzer texts into `CodeFixResources`.
- Do not put code-fix texts into `AnalyzerResources`.
- Do not fall back to string literals in analyzer or code-fix implementations when a resource should be used.
