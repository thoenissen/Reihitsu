# RH5517 — Field attributes must be on their own line

| Property | Value |
|----------|-------|
| **ID** | RH5517 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

Field attributes must be on their own line.

This rule also reports on enum members, since an enum member declaration resolves to the same attribute target as a
field.

Attribute lists on a parameter or a type parameter are not covered here, even when they name the `field:` target as
on a primary-constructor parameter. RH5523 reports on the parameter lists instead; no placement rule covers type
parameters.

## Why is this a problem?

Fields are usually read as a block of declarations at the top of a type, one type-and-name pair per line. An attribute
written in front of one field breaks that block: the declaration it belongs to starts further right than its
neighbours, and the longer the attribute, the harder the field itself is to find. Keeping the attribute on its own
line leaves the field declarations aligned as a group.

## How to fix it

Move the field declaration onto the line after the attribute list, leaving the attribute alone on its own line. A code
fix is offered and performs that edit for you.

## Examples

### Violation

```cs
internal class Example
{
    [First] private int _value;
}
```

### Correction

```cs
internal class Example
{
    [First]
    private int _value;
}
```
