# RH5531 — Accessor attribute lists must follow shape rules

| Property | Value |
|----------|-------|
| **ID** | RH5531 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

The expected shape of an accessor's attribute lists depends on how the property is written:

- On a property whose body is spread over several lines, each attribute gets a list of its own: `[First]` then
  `[Second]`.
- On a property whose declaration is single line — once any property-level attribute list of its own is set aside —
  all attributes on an accessor share one list: `[First, Second]`.

## Why is this a problem?

The two layouts are the same decision applied to the space available. In a multi-line property body every attribute
already gets a line of its own, so splitting the list costs nothing and lets a reader take the attributes one at a
time, comment on one of them, or remove one without rewriting the line that carries the other. On a single-line
property there is no vertical space to gain: separate lists only repeat the brackets on an already crowded line,
where one merged list says the same thing more briefly.

## How to fix it

On a multi-line property, give each attribute a list of its own: replace `[First, Second]` with `[First]` on one line
and `[Second]` on the next. On a property whose declaration is single line, do the reverse and merge the separate
lists into one — this includes a property that carries its own property-level attribute on the line above, as long as
the rest of the declaration still fits on one line. A code fix is offered for both directions and performs the edit
for you.

If a comment sits inside one of the lists, the diagnostic is still reported but no code fix is offered, because the
rewrite would have to decide which of the resulting lists keeps your comment. Reshape the lists by hand in that case.

## Examples

### Violation

A multi-line property with the two attributes merged into one list:

```cs
internal class Example
{
    internal int Value
    {
        [First, Second]
        get;
        set;
    }
}
```

A single-line property with the two attributes split across separate lists:

```cs
internal class Example
{
    internal int Value { [First][Second] get; set; }
}
```

### Correction

```cs
internal class Example
{
    internal int Value
    {
        [First]
        [Second]
        get;
        set;
    }
}
```

```cs
internal class Example
{
    internal int Value { [First, Second] get; set; }
}
```
