# RH8301 — Documentation lines must begin with single space

| Property     | Value        |
|--------------|--------------|
| **ID**       | RH8301       |
| **Category** | Documentation |
| **Severity** | Warning      |
| **Code Fix** | ✓            |

## Description

Each non-empty `///` documentation comment line must have an ordinary space immediately after the triple-slash marker. Any whitespace after that separator belongs to the documentation content, so indentation for nested lists and examples is allowed. An exterior-only `///` line does not require a trailing space.

## Why is this a problem?

A missing or non-standard separator makes documentation comments visually inconsistent. Treating all leading whitespace as separator spacing is also harmful because it flattens intentionally indented content.

## How to fix it

Add or replace the first character after `///` with an ordinary space. Preserve any whitespace after that separator because it is part of the documentation content. On lines without content, remove excess whitespace after the exterior.

## Examples

### Violation

```cs
internal class TestClass
{
    ///Summary
    ///   - Nested item
    void Method()
    {
    }
}
```

### Correction

```cs
internal class TestClass
{
    /// Summary
    ///   - Nested item
    void Method()
    {
    }
}
```
