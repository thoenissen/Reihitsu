# RH8301 — Documentation lines must begin with single space

| Property | Value |
|----------|-------|
| **ID** | RH8301 |
| **Category** | Documentation |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

On every `///` documentation line that carries text, the first character after the three slashes must be an ordinary space — not a tab, and not the text itself. Everything after that one space counts as documentation content, so further indentation is kept: nested list items and indented examples are not reported. A `///` line without text carries either a single space or nothing after the slashes.

## Why is this a problem?

That first space is what separates the marker from the text. Without it, `///Summary` runs the marker into the sentence and starts one character further left than every other line of the same comment. Fixing only the separator, and treating the rest as content, straightens the left edge of the comment without flattening indentation you put there on purpose.

## How to fix it

Make the character right after `///` an ordinary space — insert one where it is missing, and replace a tab with one. Leave the indentation that follows it alone. On a line with no text, keep at most a single space after the slashes.

## Examples

### Violation

```cs
internal class TestClass
{
    ///Summary
    ///   - Nested item
    void Method()
    {
    }
}
```

### Correction

```cs
internal class TestClass
{
    /// Summary
    ///   - Nested item
    void Method()
    {
    }
}
```
