# RH5115 — Index and null-forgiving operator must stay on the line of their expression

| Property | Value |
|----------|-------|
| **ID** | RH5115 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

An index such as `[0]` or `?[0]`, and a null-forgiving operator `!`, must start on the line of the expression it belongs to. The rule reports one that a line break separates from that expression, wherever it stands.

## Why is this a problem?

An index and a null-forgiving operator belong to the expression in front of them. On a line of their own, `[0]` reads like a collection expression or an attribute list, and `!` like a negation of what follows, so the reader has to look back to see what they apply to.

## How to fix it

Remove the line break in front of the index or the `!`, so that it follows the expression directly. The code fix does this for you; in a wrapped method chain, it also realigns the chain's lines.

## Examples

### Violation

```cs
internal class TestClass
{
    int Method(int[] values)
    {
        return values
            [0];
    }
}
```

### Correction

```cs
internal class TestClass
{
    int Method(int[] values)
    {
        return values[0];
    }
}
```
