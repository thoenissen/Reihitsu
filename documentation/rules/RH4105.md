# RH4105 — Parameter and query range variable names should be in camelCase

| Property | Value |
|----------|-------|
| **ID** | RH4105 |
| **Category** | Naming |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

Checks that parameter names follow camelCase naming conventions. The first word should start with a lowercase letter, and each subsequent word should start with an uppercase letter. Besides methods, this covers constructors, indexers, delegates, local functions, and lambdas, as well as the range variables of query expressions (`from`, `let`, `join`, and `into`), which play the role of lambda parameters.

The discard identifier `_` is exempt. Record primary-constructor parameters are named in PascalCase, because they become public properties, and are handled by RH4120 instead.

## Why is this a problem?

camelCase for parameters is a fundamental C# naming convention. Inconsistent parameter naming reduces readability and makes it harder to distinguish parameters from types and properties. A range variable names the same value that a lambda parameter names in method syntax, so both follow the same style.

## How to fix it

Rename the parameter or range variable to use camelCase.

If the corrected name would collide with a name that already exists, no code fix is offered and the name has to be changed by hand.

## Examples

### Violation

```cs
internal class Example
{
    public void Method(int MyParam)
    {
    }
}
```

### Correction

```cs
internal class Example
{
    public void Method(int myParam)
    {
    }
}
```
