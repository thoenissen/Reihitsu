# RH5501 — Assembly attributes must be on their own line

| Property | Value |
|----------|-------|
| **ID** | RH5501 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

Assembly attributes must be placed on their own line.

## Why is this a problem?

An assembly attribute applies to the whole assembly, not to whatever happens to be written after it. When it shares a
line with the next declaration it reads like a decoration on that declaration, and only the `assembly:` target tells
the reader otherwise. Giving each assembly attribute its own line also keeps the block of them at the top of a file
scannable as a list, and lets a change to one of them touch a single line.

## How to fix it

Move the declaration that follows onto the line after the attribute list, leaving the attribute alone on its own
line. A code fix is offered and performs that edit for you.

If a comment sits inside the attribute list, the diagnostic is still reported but no code fix is offered, because the
rewrite would have to carry your comment along with the attribute. Insert the line break by hand in that case.

## Exceptions

The rule does not report when a comment or a preprocessor directive sits between the closing `]` and the declaration
that follows. Nothing can be moved onto its own line there without disturbing what you wrote in that gap, so the
layout you chose is left exactly as it is.

An attribute list on an accessor of a single-line auto-property or auto-indexer, such as
`public int Value { [assembly: First] get; set; }`, is not reported. The formatter keeps every attribute list of such
an accessor on the property's line, whatever its explicit target, so the compact form is the accepted shape there. The
exemption holds only while no accessor has a body or an expression body and no comment or directive sits inside the
accessor list; the formatter expands the property otherwise, and the rule applies as usual.

## Examples

### Violation

```cs
[assembly: First] internal class Example;
```

### Correction

```cs
[assembly: First]
internal class Example;
```
