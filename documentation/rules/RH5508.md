# RH5508 — Struct attribute lists must use one attribute per list

| Property | Value |
|----------|-------|
| **ID** | RH5508 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

Struct attribute lists must contain exactly one attribute.

## Why is this a problem?

Attributes on a type are rarely related to each other, and `[First, Second]` is the syntax that says they are.
Splitting them gives each attribute its own line, so a reader can take them one at a time, a single attribute can be
commented out or given its own explanatory comment, and an attribute with a long argument list does not have to share
a line with anything else.

## How to fix it

Give each attribute a list of its own: replace `[First, Second]` with `[First]` on one line and `[Second]` on the
next. A code fix is offered and performs the split for you.

If a comment sits inside the list, the diagnostic is still reported but no code fix is offered, because the split
would have to decide which of the two new lists keeps your comment. Separate the attributes by hand in that case.

## Examples

### Violation

```cs
[First, Second]
internal struct Example;
```

### Correction

```cs
[First]
[Second]
internal struct Example;
```
