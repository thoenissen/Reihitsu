# RH5507 — Struct attributes must be on their own line

| Property | Value |
|----------|-------|
| **ID** | RH5507 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

Struct attributes must be on their own line.

This rule also reports on record structs, since a `record struct` declaration resolves to the same attribute target
as a `struct` declaration.

## Why is this a problem?

The declaration line is what a reader scans for when looking for a type: the accessibility, the `struct` keyword and
the name. Attributes written in front of it push all of that to the right by however much attribute text happens to be
present, so no two type declarations begin in the same place. Keeping them apart also separates two kinds of change in
a diff — adding or removing an attribute no longer edits the line that carries the type's signature.

## How to fix it

Move the struct declaration onto the line after the attribute list, leaving the attribute alone on its own line. A
code fix is offered and performs that edit for you.

## Examples

### Violation

```cs
[First] internal struct Example;
```

### Correction

```cs
[First]
internal struct Example;
```
