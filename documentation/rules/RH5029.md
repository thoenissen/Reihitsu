# RH5029 — Local declarations should be preceded by a blank line

| Property | Value |
|----------|-------|
| **ID** | RH5029 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

Where a local variable declaration follows a statement that is not itself a declaration, the two should be separated by a blank line.

## Why is this a problem?

Blank lines help separate actions from a new block of local state. Without that separation, declarations can blend into the preceding logic and make a method harder to scan.

## How to fix it

Insert a blank line above the declaration. The code fix does this for you. When a comment sits directly above the declaration, the blank line is placed above the comment, so the comment stays attached to the code it describes.

## Exceptions

Nothing is reported, and no blank line is needed, when the declaration:

- follows another local declaration, so a run of declarations stays grouped together as one block;
- is the first statement of its block, or the first statement under a `case` or `default` label;
- directly follows a preprocessor directive such as `#if` or `#region`;
- is a top-level statement in a file that has no enclosing type.

## Examples

### Violation

```cs
private void Execute()
{
    DoWork();
    var value = GetValue();
}
```

### Correction

```cs
private void Execute()
{
    DoWork();

    var value = GetValue();
}
```
