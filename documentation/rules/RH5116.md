# RH5116 — Null-forgiving operator must stay on the line of its expression

| Property | Value |
|----------|-------|
| **ID** | RH5116 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

A null-forgiving operator `!` must start on the line of the expression it belongs to. The rule reports one that a line break separates from that expression, wherever it stands. A `!` directly in front of `.` or `?.` is part of a member access and is not reported by this rule.

## Why is this a problem?

A null-forgiving operator belongs to the expression in front of it. At the start of a line, `!` reads like a negation of what follows, so the reader has to look back to see what it applies to.

## How to fix it

Remove the line break in front of the `!`, so that it follows the expression directly. The code fix does this for you; in a wrapped method chain, it also realigns the chain's lines.

## Examples

### Violation

```cs
internal class TestClass
{
    string Method(string value)
    {
        return value
            !;
    }
}
```

### Correction

```cs
internal class TestClass
{
    string Method(string value)
    {
        return value!;
    }
}
```
