# RH5529 — Generic parameter attributes must use merged attribute lists

| Property | Value |
|----------|-------|
| **ID** | RH5529 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

All attributes on one type parameter belong in a single attribute list: `[typevar: First, Second]`, not
`[typevar: First][typevar: Second]`. This is the opposite of the rule for declaration-level attributes, which get one
list each.

## Why is this a problem?

Attributes on a type parameter sit inside the angle brackets of the declaration, on the same line as the type or
method being declared. Splitting them into separate lists therefore buys no vertical space at all — it only repeats
the brackets and, because a type parameter attribute must name its `typevar:` target, repeats that target too. A
single merged list states the target once and keeps the declaration line as short as the attributes allow.

## How to fix it

Move every attribute on the type parameter into the first attribute list, separated by commas, and delete the now
empty lists. A code fix is offered and performs the merge for you.

If a comment sits inside one of the lists, the diagnostic is still reported but no code fix is offered, because the
merge would have to decide where in the combined list your comment belongs. Merge the lists by hand in that case.

## Examples

### Violation

```cs
internal class Example<[typevar: First][typevar: Second] T>
{
}
```

### Correction

```cs
internal class Example<[typevar: First, Second] T>
{
}
```
