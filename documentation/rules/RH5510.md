# RH5510 — Enum attribute lists must use one attribute per list

| Property | Value |
|----------|-------|
| **ID** | RH5510 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

Enum attribute lists must contain exactly one attribute.

## Why is this a problem?

An enum usually carries a small number of independent attributes, and `[Flags]` in particular changes how every member
of the type is meant to be read. Merged into a list with an unrelated attribute it is easy to miss. One attribute per
list puts each on its own line, where it can also be given its own explanatory comment.

## How to fix it

Give each attribute a list of its own: replace `[First, Second]` with `[First]` on one line and `[Second]` on the
next. A code fix is offered and performs the split for you.

If a comment sits inside the list, the diagnostic is still reported but no code fix is offered, because the split
would have to decide which of the two new lists keeps your comment. Separate the attributes by hand in that case.

## Examples

### Violation

```cs
[First, Second]
internal enum Example { A }
```

### Correction

```cs
[First]
[Second]
internal enum Example { A }
```
