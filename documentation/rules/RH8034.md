# RH8034 — Operators must be documented

| Property | Value |
|----------|-------|
| **ID** | RH8034 |
| **Category** | Documentation |
| **Severity** | Warning |
| **Code Fix** | ❌ |

## Description

This rule requires operator overload and conversion operator declarations to have XML documentation. A declaration counts as documented when it has a `<summary>` tag or uses `<inheritdoc/>`. Unlike the paired rules for the other member kinds, this one does not distinguish accessibility, because an operator is always `public`.

## Why is this a problem?

Operators change the meaning of ordinary expression syntax for a type. Without documentation, a reader has no way to know what an expression like `a + b` actually does for that type without inspecting the implementation.

## How to fix it

Add a meaningful XML comment above the declaration. In most cases a short `<summary>` is the best fix; document the parameters and the return value too, since RH8101 and RH8105 validate them once a documentation comment exists.

## Examples

### Violation

```cs
public readonly struct Money
{
    public static Money operator +(Money left, Money right) => new(left.Amount + right.Amount);
}
```

### Correction

```cs
public readonly struct Money
{
    /// <summary>
    /// Adds two amounts
    /// </summary>
    /// <param name="left">Left operand</param>
    /// <param name="right">Right operand</param>
    /// <returns>The sum of the two amounts</returns>
    public static Money operator +(Money left, Money right) => new(left.Amount + right.Amount);
}
```
