# RH5527 — Return value attributes must be on their own line

| Property | Value |
|----------|-------|
| **ID** | RH5527 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

Return value attributes must be on their own line.

## Why is this a problem?

`[return: ...]` annotates the value a method hands back, not the method's name or its parameters, yet written on the
signature line it appears in front of the accessibility modifiers, further from the return type than the modifiers
are. On its own line it reads as what it is: a statement about the result, made before the signature that produces it.

## How to fix it

Move the method declaration onto the line after the attribute list, leaving the attribute alone on its own line. A
code fix is offered and performs that edit for you.

If a comment sits inside the attribute list, the diagnostic is still reported but no code fix is offered, because the
rewrite would have to carry your comment along with the attribute. Insert the line break by hand in that case.

The fix is also withheld — with the diagnostic still reported — while an enclosing type, namespace, or block is
missing its closing brace, since the indentation level cannot be computed from a scope the parser has not closed yet.
This is ordinary mid-edit source, so the fix reappears once the brace is typed.

The moved declaration is indented at the attribute list's canonical nesting depth, not at whatever column the
attribute list itself happens to sit at. If the attribute list is already indented non-canonically, the fix does not
copy that depth onto the declaration.

## Exceptions

The rule does not report when a comment or a preprocessor directive sits between the closing `]` and the method
declaration. Nothing can be moved onto its own line there without disturbing what you wrote in that gap, so the layout
you chose is left exactly as it is.

## Examples

### Violation

```cs
internal class Example
{
    [return: First] internal int Execute()
    {
        return 0;
    }
}
```

### Correction

```cs
internal class Example
{
    [return: First]
    internal int Execute()
    {
        return 0;
    }
}
```
