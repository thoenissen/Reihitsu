# RH5114 — Using directives must be placed on separate lines

| Property | Value |
|----------|-------|
| **ID** | RH5114 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

This rule checks whether a using directive starts on the same line on which the preceding using directive of the same file or namespace ends. It applies to every pair of neighboring using directives, whatever their group, their order, or what separates them on the line — nothing, spaces, tabs, or block comments.

A line break inside a comment between the two directives already places the second one on a later line, so a single-line documentation comment (`///`) or a block comment that spans lines is not reported. `extern alias` directives are not checked.

## Why is this a problem?

Using directives that share a line are easy to overlook, make the list of imported namespaces harder to scan, and turn a change to one directive into a change to its neighbors in reviews and merges.

## How to fix it

Place each using directive on its own line.

The code fix only inserts the line break. It keeps the order of the directives and adds no blank lines, so ordering and grouping are left to the using-directive ordering rules. A comment that trails the first directive stays on its line, and a comment that leads the moved directive moves with it.

## Examples

### Violation

```cs
using System.Collections.Generic; using System.Linq;

internal class TestClass
{
}
```

### Correction

```cs
using System.Collections.Generic;
using System.Linq;

internal class TestClass
{
}
```
