# RH3210 — Get-only indexers should use an expression body

| Property | Value |
|----------|-------|
| **ID** | RH3210 |
| **Category** | Clarity |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

This rule reports an indexer that has only a `get` accessor returning a single value or throwing an exception. Such an indexer should be written as an expression-bodied indexer (`=>`).

The rule reports only when the project's C# language version allows the expression-bodied form (C# 6 or later, and C# 7 or later for a getter that throws).

## Why is this a problem?

An accessor list with a single getter takes several lines and two levels of braces to say what one line says. The expression-bodied form shows at a glance that the indexer is read-only and what it returns, and keeps all get-only indexers in one consistent shape.

## How to fix it

Replace the accessor list with `=>` followed by the value the getter returns. The code fix applies this change automatically.

## Examples

### Violation

```cs
internal class Example
{
    private readonly int[] _values = new int[3];

    public int this[int index]
    {
        get
        {
            return _values[index];
        }
    }
}
```

### Correction

```cs
internal class Example
{
    private readonly int[] _values = new int[3];

    public int this[int index] => _values[index];
}
```
