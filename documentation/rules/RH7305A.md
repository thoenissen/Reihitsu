# RH7305A — Types with multiple member kinds should be organized with regions

| Property | Value |
|----------|-------|
| **ID** | RH7305A |
| **Category** | Organization |
| **Severity** | Warning |
| **Code Fix** | ❌ |
| **Enabled by default** | ❌ |

## Description

This rule requires a type that mixes several kinds of member to put all of those members inside `#region` blocks. It reports such a type when it has no regions at all, or when at least one of its own members sits outside every region.

A type whose members are all of one kind — only methods, or only properties — is never reported, however many of them there are. Only the members the type declares itself are counted, and types nested inside another type are not reported; the enclosing type's regions already group them.

This rule is switched off unless you enable it. See *Alternative rule* below for how it relates to RH7305.

## Why is this a problem?

A type that mixes fields, constructors, properties, and methods is read by jumping between those groups, and without regions there is nothing to jump to: the collapse tree and the navigation drop-down show one flat list. Named regions give that type an outline, and a member left outside them breaks it, because the outline no longer accounts for everything the type declares. A type whose members are all of one kind already reads as one group, so regions would add ceremony without adding orientation — which is why this rule leaves it alone.

## How to fix it

Wrap the members of the type in clearly named type-level regions such as `Fields`, `Properties`, `Constructors`, and `Methods`, grouping each kind of member into its own region, until no member is left outside a region. There is no code fix: which regions a type should have, and which member belongs in which one, is a decision about the type's shape and is made by hand.

## Alternative rule

RH7305A and RH7305 ask for the same thing, but of different types, and they are meant to be used one at a time:

- **RH7305** — active by default. It expects regions in every type that has members, including a type that holds nothing but a handful of methods.
- **RH7305A** — this rule, off unless you turn it on. It expects regions only in types that mix several kinds of member.

If you turned RH7305A on because you want small single-purpose types left alone, suppress RH7305 as well; otherwise RH7305 keeps reporting the very types RH7305A was chosen to exempt.

## Examples

### Violation

```cs
internal sealed class CustomerCache
{
    private readonly Dictionary<int, Customer> _cache;

    public CustomerCache()
    {
        _cache = new Dictionary<int, Customer>();
    }

    public int Count => _cache.Count;

    public Customer GetById(int id)
    {
        return _cache[id];
    }
}
```

### Correction

```cs
internal sealed class CustomerCache
{
    #region Fields

    private readonly Dictionary<int, Customer> _cache;

    #endregion // Fields

    #region Constructors

    public CustomerCache()
    {
        _cache = new Dictionary<int, Customer>();
    }

    #endregion // Constructors

    #region Properties

    public int Count => _cache.Count;

    #endregion // Properties

    #region Methods

    public Customer GetById(int id)
    {
        return _cache[id];
    }

    #endregion // Methods
}
```

### Not a violation (single member kind)

```cs
internal static class StringExtensions
{
    public static string Truncate(this string value, int maxLength)
    {
        return value.Length <= maxLength ? value : value[..maxLength];
    }

    public static bool IsNullOrEmpty(this string value)
    {
        return string.IsNullOrEmpty(value);
    }
}
```
