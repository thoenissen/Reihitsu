# RH0002 — Documentation rules are not active for this project

| Property | Value |
|----------|-------|
| **ID** | RH0002 |
| **Category** | Analyzer |
| **Severity** | Warning |
| **Code Fix** | ❌ |

## Description

The documentation rules (`RH8###`) can only inspect XML documentation comments when the project is compiled with XML documentation enabled. Without it, `///` comments are not parsed and the documentation rules see nothing to check. This rule reports that state once per source file in the project.

## Why is this a problem?

While XML documentation is disabled, every documentation rule stays silent. Missing, malformed, or outdated `///` comments are never reported, so the project looks clean even though it has never been checked.

## How to fix it

Enable XML documentation generation in the project file. This is a project setting, so the correction is made in the `.csproj` file rather than in the source file the diagnostic points at.

If the documentation rules are not wanted for this project, suppress `RH0002` deliberately instead of leaving the warning in the build output.

## Examples

### Violation

```xml
<Project Sdk="Microsoft.NET.Sdk">

  <PropertyGroup>
    <TargetFramework>net10.0</TargetFramework>
  </PropertyGroup>

</Project>
```

### Correction

```xml
<Project Sdk="Microsoft.NET.Sdk">

  <PropertyGroup>
    <TargetFramework>net10.0</TargetFramework>
    <GenerateDocumentationFile>true</GenerateDocumentationFile>
  </PropertyGroup>

</Project>
```
