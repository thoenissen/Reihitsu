# RH3202 — Expression style methods should not be used

| Property | Value |
|----------|-------|
| **ID** | RH3202 |
| **Category** | Clarity |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

This rule disallows expression-bodied methods (methods using `=>`). All methods should use block bodies with explicit `return` statements for consistency and clarity.

## Why is this a problem?

Expression-bodied methods can reduce readability for complex expressions and create inconsistency when some methods use block bodies and others use expression bodies. Requiring block bodies ensures a uniform coding style across the codebase.

## How to fix it

Replace the expression-bodied method with a block body containing a `return` statement (or just the statement for void methods).

## Exceptions

The rule is not reported when a preprocessor directive sits between the arrow and the expression:

```cs
public int GetValue() =>
#pragma warning disable CS0618
    1;
#pragma warning restore CS0618
```

Rewriting that member as a block body would place the directive directly after the generated
`return`, where a directive cannot sit because it must start its own line, so the result would no
longer compile. The same applies to a conditional or region group whose partner directive lies
outside the member. A directive written *after* the expression is unaffected, and such a member is
still reported.

## Examples

### Violation

```cs
public int GetValue() => 42;
```

### Correction

```cs
public int GetValue()
{
    return 42;
}
```
