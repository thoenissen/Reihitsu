# RH5524 — Parameter attributes must use merged attribute lists

| Property | Value |
|----------|-------|
| **ID** | RH5524 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

All attributes on one parameter belong in a single attribute list: `[First, Second]`, not `[First][Second]`. This is
the opposite of the rule for declaration-level attributes, which get one list each.

## Why is this a problem?

Parameter attributes stay on the parameter's line, so splitting them into separate lists does not buy a line per
attribute the way it does on a declaration — it only repeats the brackets. `[First][Second] int value` costs two
extra characters and one more visual break than `[First, Second] int value` for no gain, and in a parameter list of
several such parameters the brackets quickly outnumber the parameters. One list per parameter also means the reader
counts parameters by counting bracket groups.

## How to fix it

Move every attribute on the parameter into the first attribute list, separated by commas, and delete the now empty
lists. A code fix is offered and performs the merge for you.

If a comment sits inside one of the lists, the diagnostic is still reported but no code fix is offered, because the
merge would have to decide where in the combined list your comment belongs. Merge the lists by hand in that case.

## Examples

### Violation

```cs
internal class Example
{
    internal void Execute([First][Second] int value)
    {
    }
}
```

### Correction

```cs
internal class Example
{
    internal void Execute([First, Second] int value)
    {
    }
}
```
