# RH5303 — Collection initializer should be formatted correctly

| Property | Value |
|----------|-------|
| **ID** | RH5303 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

This rule requires collection initializer braces and entries to be formatted under the `new` anchor. Multi-line complex elements, such as dictionary-style `{ key, value }` entries, must add one indentation level for their braces and another for their contained expressions.

## Why is this a problem?

Misaligned collection initializers make it harder to see where the creation expression starts and where each item belongs. Consistent brace placement keeps collection setup readable, especially in longer initializers.

## How to fix it

Move the opening brace onto its own line under `new`, put each entry on its own indented line, and align the closing brace with `new`. For a multi-line `{ key, value }` entry, align its braces as an entry and indent the key and value one additional level. The code fix will reformat the initializer automatically.

## Examples

### Violation

```cs
var values = new List<int>
{
1,
    2
};
```

### Correction

```cs
var values = new List<int>
             {
                 1,
                 2
             };
```

Multi-line dictionary-style elements add another indentation level:

```cs
var values = new Dictionary<Data, Data>()
             {
                 {
                     existingKey,
                     existingValue
                 }
             };
```
