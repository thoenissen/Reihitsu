# RH5521 — Interface attributes must be on their own line

| Property | Value |
|----------|-------|
| **ID** | RH5521 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

Interface attributes must be on their own line.

## Why is this a problem?

The declaration line is what a reader scans for when looking for an interface: the accessibility, the `interface`
keyword and the name. Attributes written in front of it push all of that to the right by however much attribute text
happens to be present, so no two type declarations begin in the same place. Interfaces frequently carry interop or
marker attributes that are long, which makes the effect worse than it is elsewhere.

## How to fix it

Move the interface declaration onto the line after the attribute list, leaving the attribute alone on its own line. A
code fix is offered and performs that edit for you.

If a comment sits inside the attribute list, the diagnostic is still reported but no code fix is offered, because the
rewrite would have to carry your comment along with the attribute. Insert the line break by hand in that case.

## Exceptions

The rule does not report when a comment or a preprocessor directive sits between the closing `]` and the interface
declaration. Nothing can be moved onto its own line there without disturbing what you wrote in that gap, so the layout
you chose is left exactly as it is.

## Examples

### Violation

```cs
[First] internal interface IExample { }
```

### Correction

```cs
[First]
internal interface IExample { }
```
