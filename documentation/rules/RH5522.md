# RH5522 — Interface attribute lists must use one attribute per list

| Property | Value |
|----------|-------|
| **ID** | RH5522 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

Interface attribute lists must contain exactly one attribute.

## Why is this a problem?

Attributes on an interface are rarely related to each other — interop layout, marker attributes and obsolescence
notices are independent decisions — and `[First, Second]` is the syntax that says they are not. Splitting them gives
each attribute its own line, with room for its arguments and for a comment explaining it.

## How to fix it

Give each attribute a list of its own: replace `[First, Second]` with `[First]` on one line and `[Second]` on the
next. A code fix is offered and performs the split for you.

If a comment sits inside the list, the diagnostic is still reported but no code fix is offered, because the split
would have to decide which of the two new lists keeps your comment. Separate the attributes by hand in that case.

## Examples

### Violation

```cs
[First, Second]
internal interface IExample { }
```

### Correction

```cs
[First]
[Second]
internal interface IExample { }
```
