# RH7305 — Types should be organized with regions

| Property | Value |
|----------|-------|
| **ID** | RH7305 |
| **Category** | Organization |
| **Severity** | Warning |
| **Code Fix** | ❌ |

## Description

This rule requires every type that declares at least one member to put all of those members inside `#region` blocks. It reports the type when it has no regions at all, or when at least one of its own members sits outside every region.

Only the members the type declares itself are counted — fields, constructors, finalizers, properties, indexers, events, methods, operators, and nested types and delegates. Types nested inside another type are not reported; the enclosing type's regions already group them.

## Why is this a problem?

Types grow, and a long member list with no headings has to be read from top to bottom before you know what is in it. Named regions turn that list into a table of contents: the collapse tree and the navigation drop-down show `Fields`, `Properties`, `Constructors`, `Methods` at a glance, and a reader looking for one of them can go straight there. A single member left outside the regions breaks that guarantee, because the outline no longer accounts for everything the type declares.

## How to fix it

Wrap the members of the type in clearly named type-level regions such as `Fields`, `Properties`, `Constructors`, and `Methods`, until no member is left outside a region. There is no code fix: which regions a type should have, and which member belongs in which one, is a decision about the type's shape and is made by hand.

## Alternative rule

RH7305 and RH7305A ask for the same thing, but of different types, and only one of them is switched on for you:

- **RH7305** — active by default. It expects regions in every type that has members, including a type that holds nothing but a handful of methods.
- **RH7305A** — off unless you turn it on. It expects regions only in types that mix several kinds of member, and stays silent on a type whose members are all of one kind.

They are alternatives, not a pair: use RH7305 if you want regions everywhere, and switch to RH7305A if you want small single-purpose types left alone. If you enable RH7305A, suppress RH7305 as well, or the same types will be reported twice.

## Examples

### Violation

```cs
internal class DataService
{
    private string _name;

    public string Name { get; set; }

    public DataService()
    {
    }

    public void Save()
    {
    }
}
```

### Correction

```cs
internal class DataService
{
    #region Fields

    private string _name;

    #endregion // Fields

    #region Properties

    public string Name { get; set; }

    #endregion // Properties

    #region Constructors

    public DataService()
    {
    }

    #endregion // Constructors

    #region Methods

    public void Save()
    {
    }

    #endregion // Methods
}
```
