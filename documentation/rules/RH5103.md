# RH5103 — Code must not contain multiple statements on one line

| Property | Value |
|----------|-------|
| **ID** | RH5103 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

This rule checks whether sibling statements in a block or switch section start on the same line.

## Why is this a problem?

Placing multiple statements on one line reduces readability and makes changes harder to review.

## How to fix it

Move each statement to its own line.

No code fix is offered when anything other than plain spacing separates the statements — a comment, a preprocessor directive, or a stray semicolon — or when the reported statement is the first one on the line. Split the line by hand there.

Inside an object initializer or anonymous object, the fix reads the moved statement's column from whichever switch-section label leads the shared physical line. When that label is not itself first on its own line — for example, an entire `switch` statement written on one physical line — no column can be read this way, and the fix leaves the statement at that line's own column instead of aligning it one level below the label. Correct the indentation by hand in that case.

The same applies when the label itself spans multiple physical lines — for example, a `case` pattern with a `when` clause split across lines. If the statement shares a physical line with one of the label's own continuation lines rather than with the label's first line, the fix reads that continuation line's column as if it were the label's, adding one level too many. Correct the indentation by hand in that case too.

## Examples

### Violation

```cs
internal class TestClass
{
    void Method()
    {
        int first = 1; int second = 2;
    }
}
```

### Correction

```cs
internal class TestClass
{
    void Method()
    {
        int first = 1;
        int second = 2;
    }
}
```
