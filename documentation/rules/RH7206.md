# RH7206 — Using static directives must be ordered alphabetically

| Property | Value |
|----------|-------|
| **ID** | RH7206 |
| **Category** | Organization |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

This rule requires `using static` directives within the same global-or-local root-namespace group to be sorted alphabetically by type name. Root-namespace groups themselves are ordered by [RH7207](RH7207.md).

## Why is this a problem?

Alphabetical ordering makes static import blocks easier to scan and keeps them consistent with the rest of the using section.

## How to fix it

Sort `using static` directives alphabetically within each root-namespace group. Keep global and local directives in separate sections.

## Exceptions

No diagnostic is reported for a `using` block that contains a preprocessor directive such as `#if`, `#region` or `#pragma`. Reordering imports across a directive could change which imports the build actually sees, so the whole block is left exactly as written — sort it by hand there.

## Examples

### Violation

```cs
using static System.Math;
using static System.Console;

internal class Example
{
}
```

### Correction

```cs
using static System.Console;
using static System.Math;

internal class Example
{
}
```
