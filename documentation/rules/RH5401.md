# RH5401 — Expression style get-only properties should be single lined

| Property | Value |
|----------|-------|
| **ID** | RH5401 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

This rule checks that expression-bodied get-only properties keep the `=>` arrow and the start of the expression on the property signature line. The expression itself may still wrap onto following lines (for example a switch expression, a wrapped fluent chain, or a multi-line collection expression); only the arrow and the first expression token are required to stay on the signature line.

## Why is this a problem?

Dropping the `=>` or the beginning of the expression onto a separate line defeats the purpose of the concise expression syntax: the reader has to look at the next line to find out whether the property returns a value, and a property written that way no longer lines up with the other one-line properties around it. A long expression that starts on the signature line and then wraps is still easy to scan, because the first line already says what the property computes.

## How to fix it

Move the `=>` arrow and the start of the expression onto the property signature line. Short expressions end up on a single line; longer expressions may continue on following lines.

The code fix is offered when the whole declaration fits on one line. A property whose expression stays spread over several lines even after the arrow is moved up — a multi-line collection expression or a switch expression, for example — is reported without a code fix, so that the expression keeps the shape you gave it. Move the arrow and the first token of the expression onto the signature line by hand.

## Examples

### Violation

```cs
public int Value
    => 42;
```

### Correction

```cs
public int Value => 42;
```
