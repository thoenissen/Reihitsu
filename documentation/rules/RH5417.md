# RH5417 — Function and accessor body braces must not share a line

| Property | Value |
|----------|-------|
| **ID** | RH5417 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

The braces of a function or accessor body must not share a line. This applies to methods, constructors, destructors, operators, conversion operators, accessors, local functions, simple and parenthesized lambda block bodies, and anonymous methods. Both the empty form (`{ }`) and the populated single-line form (`{ return 1; }`) are reported.

## Why is this a problem?

Reihitsu uses Allman-style braces, where the opening and closing brace of a body each sit on their own line. Collapsing a function or accessor body onto a single line breaks that consistency and hides the body's structure.

## How to fix it

Place the opening brace and the closing brace on their own lines. The code fix applies this change automatically to methods, constructors, destructors, operators, conversion operators, and accessors.

The code fix lays the member out through the formatter, so a property or indexer accessor whose body is a single `return e;`, `throw e;`, or — for `set` and `init` — expression statement is rewritten to its expression-bodied form (`get => e;`) instead of being expanded. Any other accessor body is expanded as shown below.

A body that belongs to a local function, a lambda, or an anonymous method is reported without a code fix. Put its braces on their own lines by hand:

```cs
Action work = () => { };
```

```cs
Action work = () =>
{
};
```

Expression-bodied members (`=> ...`), expression-bodied lambdas, auto-property accessor lists (`{ get; set; }`), and control-flow or other non-function blocks are not affected by this rule.

## Examples

### Violation

```cs
public class C
{
    public int GetValue() { return 1; }
}
```

### Correction

```cs
public class C
{
    public int GetValue()
    {
        return 1;
    }
}
```
