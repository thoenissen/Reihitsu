# RH4001 — The name of the type should match the filename

| Property | Value |
|----------|-------|
| **ID** | RH4001 |
| **Category** | Naming |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

Checks that the first type declared in a file has a name that matches the file name segment before the first dot. This means `View.xaml.cs`, `Component.razor.cs`, and split files such as `Type.Part1.cs` are all validated against `View`, `Component`, and `Type`.

## Why is this a problem?

When a type name does not match its file name, developers cannot locate the type by browsing the file system. This breaks common conventions and makes navigation in large codebases significantly harder.

## How to fix it

Rename the file to match the type name before the first dot, or rename the type to match the file name. The code fix renames the file and preserves any suffix after the first dot, so `Bar.xaml.cs` stays a code-behind file.

When the project already contains another file with the target name in the same folder, renaming would overwrite it, so no code fix is offered. Resolve the collision yourself — usually by renaming one of the two types.

## Examples

### Violation

```cs
// File: Foo.cs
public class Bar
{
}
```

### Correction

```cs
// File: Bar.cs (renamed to match the type)
public class Bar
{
}
```

## Exceptions

Only the file name segment before the first dot has to match, so a partial type split across `Component.Part1.cs` and `Component.Part2.cs` is accepted:

```cs
// File: Component.Part1.cs
public partial class Component
{
}
```

A 14-digit timestamp prefix followed by an underscore — the shape Entity Framework Core gives its migration files — is ignored, so only the part after the underscore has to match the type name:

```cs
// File: 20210501083748_InitialCreate.cs
public class InitialCreate : Migration
{
}
```

A generic type is expected in a file whose name carries its type parameters in curly braces, which is the form the code fix produces:

```cs
// File: Cache{TKey,TValue}.cs
public class Cache<TKey, TValue>
{
}
```
