# RH5043 — Comments must not be placed inside a base list

| Property | Value |
|----------|-------|
| **ID** | RH5043 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ❌ |

## Description

This rule reports a comment placed inside the base list of a type, from the colon to the last base type. The rule applies whether or not the comment shares a line with code.

## Why is this a problem?

A comment in this position sits inside a single construct, so it is unclear which part of the code it describes. It also splits the construct across lines and keeps its layout from being kept consistent.

## How to fix it

Move the comment above the type declaration. No code fix is offered, because only you can decide what the comment refers to.

## Exceptions

- A comment directly before a binary operator or before a later call of a method chain is not reported.
- A comment inside a nested block, initializer, switch expression, pattern, or query is not reported, for example above a statement inside a lambda.

## Examples

### Violation

```cs
public class Repository :
    // storage
    Base,
    IRepository
{
}

public class Base
{
}

public interface IRepository
{
}
```

### Correction

```cs
// storage
public class Repository : Base, IRepository
{
}

public class Base
{
}

public interface IRepository
{
}
```
