# RH5516 — Property attribute lists must use one attribute per list

| Property | Value |
|----------|-------|
| **ID** | RH5516 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

Property attribute lists must contain exactly one attribute.

This rule also reports on indexers, since an indexer declaration resolves to the same attribute target as a
property.

Attribute lists on a parameter or a type parameter are not covered here, even when they name the `property:` target
as on a positional record parameter. RH5524 reports on the parameter lists and RH5529 on the type-parameter lists
instead.

## Why is this a problem?

Properties attract independent attributes from several directions at once: serialization, validation, data binding,
designer support. Merged into `[First, Second]` they read as a single decision and every change to one of them
rewrites the line carrying the others. Splitting them gives each its own line, with room for its arguments and for a
comment explaining it.

## How to fix it

Give each attribute a list of its own: replace `[First, Second]` with `[First]` on one line and `[Second]` on the
next. A code fix is offered and performs the split for you.

If a comment sits inside the list, the diagnostic is still reported but no code fix is offered, because the split
would have to decide which of the two new lists keeps your comment. Separate the attributes by hand in that case.

## Exceptions

A list on an accessor of a single-line auto-property or auto-indexer, such as
`public int Value { [property: First, Second] get; set; }`, is not reported. The formatter keeps every attribute list
of such an accessor merged on the property's line, whatever its explicit target, so splitting it would only be undone
again. The exemption holds only while no accessor has a body or an expression body and no comment or directive sits
inside the accessor list; the formatter expands the property otherwise, and the rule applies as usual.

## Examples

### Violation

```cs
internal class Example
{
    [First, Second]
    internal int Value { get; set; }
}
```

### Correction

```cs
internal class Example
{
    [First]
    [Second]
    internal int Value { get; set; }
}
```
