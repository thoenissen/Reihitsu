# RH3208 — Expression style local functions should not be used

| Property | Value |
|----------|-------|
| **ID** | RH3208 |
| **Category** | Clarity |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

This rule disallows expression-bodied local functions (local functions using `=>`). All local functions should use block bodies with explicit `return` statements for consistency and clarity.

## Why is this a problem?

Expression-bodied local functions create inconsistency when some functions use block bodies and others use expression bodies. Requiring block bodies keeps local functions in line with methods and gives every function a uniform shape.

## How to fix it

Replace the expression-bodied local function with a block body containing a `return` statement (or just the statement for `void`, `async Task`, and `async ValueTask` local functions).

## Examples

### Violation

```cs
internal class Calculator
{
    public int Calculate(int value)
    {
        return Double(value);

        int Double(int x) => x * 2;
    }
}
```

### Correction

```cs
internal class Calculator
{
    public int Calculate(int value)
    {
        return Double(value);

        int Double(int x)
        {
            return x * 2;
        }
    }
}
```
