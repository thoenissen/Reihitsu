# RH7105 — Declaration keywords must follow order

| Property | Value |
|----------|-------|
| **ID** | RH7105 |
| **Category** | Organization |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

This rule enforces a consistent order for declaration modifiers such as accessibility, `static`, `sealed`, `override`, and `readonly`. The trailing modifiers follow the order C# itself requires: `ref` comes after every other modifier, and `partial` is last, so a ref struct is declared as `public readonly ref partial struct`.

## Why is this a problem?

When modifiers appear in different orders, declarations become harder to skim and compare. A consistent sequence makes the important parts of a declaration easier to spot.

## How to fix it

Reorder the modifiers into the expected sequence:

`file` / `public` / `private` / `protected` / `internal` → `static` → `abstract` → `virtual` → `sealed` → `override` → `new` → `readonly` → `volatile` → `async` → `extern` → `unsafe` → `required` → `ref` → `partial`

Accessibility keywords come first and keep their own relative order — [RH7106](RH7106.md) governs the compound forms such as `protected internal`. Any modifier not listed above, such as `const` or `fixed`, belongs at the end of the sequence.

## Examples

### Violation

```cs
public class Example
{
    static public int Value { get; set; }
}
```

### Correction

```cs
public class Example
{
    public static int Value { get; set; }
}
```
