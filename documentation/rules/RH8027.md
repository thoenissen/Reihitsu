# RH8027 — Private fields must be documented

| Property | Value |
|----------|-------|
| **ID** | RH8027 |
| **Category** | Documentation |
| **Severity** | Warning |
| **Code Fix** | ❌ |

## Description

This rule requires private field declarations to have XML documentation. A declaration counts as documented when it has a `<summary>` tag or uses `<inheritdoc/>`.

## Why is this a problem?

A private field is state that outlives every call, and its type and name rarely say what is stored, when the value is valid, or which code is allowed to change it. The summary is the one place where that is recorded, and the editor shows it at every use site inside the file.

## How to fix it

Add a meaningful XML comment above the declaration. In most cases a short `<summary>` is the best fix.

## Examples

### Violation

```cs
/// <summary>
/// Stores counters
/// </summary>
internal class CounterStore
{
    private int _currentCount;
}
```

### Correction

```cs
/// <summary>
/// Stores counters
/// </summary>
internal class CounterStore
{
    /// <summary>
    /// Stores the currently processed item count
    /// </summary>
    private int _currentCount;
}
```
