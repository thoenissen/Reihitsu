# RH5010 — break-Statement should be preceded by a blank line

| Property | Value |
|----------|-------|
| **ID** | RH5010 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

A `break` statement that follows another statement in the same block should be separated from it by a blank line. In practice this applies to a `break` inside a loop body that is not the only statement there.

## Why is this a problem?

Separating statements with blank lines improves code readability by visually grouping related logic. A blank line before a `break` statement makes the termination point of a case or loop iteration clearly visible.

## How to fix it

Insert a blank line between the preceding statement and the `break` statement. The code fix does this for you. When a comment sits directly above the statement, the blank line is placed above that comment, so the comment stays attached to the code it describes.

## Exceptions

Nothing is reported, and no blank line is needed, when the `break` statement:

- is the last statement under a `case` or `default` label, where it closes the section instead of interrupting a sequence of statements;
- is the first statement of its block, or the first statement under a `case` or `default` label;
- is the body of a statement that is written without braces — for example the single statement after `while`, `for`, `foreach`, `using`, `lock`, `fixed`, `do`, or `else`;
- directly follows a preprocessor directive such as `#if`, `#endif`, or `#region`;
- is a top-level statement in a file that has no enclosing type.

## Examples

### Violation

```cs
internal class Example
{
    private void Execute()
    {
        while (Condition)
        {
            DoSomething();
            break;
        }
    }
}
```

### Correction

```cs
internal class Example
{
    private void Execute()
    {
        while (Condition)
        {
            DoSomething();

            break;
        }
    }
}
```
