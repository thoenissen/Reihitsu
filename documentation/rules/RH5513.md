# RH5513 — Method attributes must be on their own line

| Property | Value |
|----------|-------|
| **ID** | RH5513 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

Method attributes must be on their own line.

## Why is this a problem?

A reader scanning a type for a method looks down a column of accessibility modifiers, return types and names. An
attribute written in front of the method displaces that whole line to the right by however much attribute text happens
to be present, so methods that carry attributes no longer line up with methods that do not. Separating them also keeps
a change to the signature distinguishable in a diff from a change to the method's attributes.

## How to fix it

Move the method declaration onto the line after the attribute list, leaving the attribute alone on its own line. A
code fix is offered and performs that edit for you.

If a comment sits inside the attribute list, the diagnostic is still reported but no code fix is offered, because the
rewrite would have to carry your comment along with the attribute. Insert the line break by hand in that case.

## Exceptions

The rule does not report when a comment or a preprocessor directive sits between the closing `]` and the method
declaration. Nothing can be moved onto its own line there without disturbing what you wrote in that gap, so the layout
you chose is left exactly as it is.

## Examples

### Violation

```cs
internal class Example
{
    [First] internal void Execute() { }
}
```

### Correction

```cs
internal class Example
{
    [First]
    internal void Execute() { }
}
```
