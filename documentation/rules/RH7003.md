# RH7003 — File-scoped namespaces should be used

| Property | Value |
|----------|-------|
| **ID** | RH7003 |
| **Category** | Organization |
| **Severity** | Warning |
| **Code Fix** | ❌ |

## Description

This rule requires eligible namespace declarations to use the file-scoped form instead of the block-scoped form.

## Why is this a problem?

Block-scoped namespaces add an extra indentation level around the entire file. That makes the file longer and pushes all members further to the right without adding useful structure.

Using the file-scoped form keeps the namespace visible while reducing nesting and making the file easier to scan.

## How to fix it

Replace the block-scoped namespace with a file-scoped namespace and remove the extra indentation from the namespace contents.

## Exceptions

A file-scoped namespace covers the whole file, so the rule only reports a namespace that can actually be converted:

- A file that declares a second namespace, or a type outside the namespace, is not reported. Split it up first — [RH7001](RH7001.md) and [RH7002](RH7002.md) already ask for that.
- A project compiled with a language version below C# 10 is not reported, because file-scoped namespaces do not exist there.

## Examples

### Violation

```cs
namespace Sample.Project
{
    using System;

    internal class Example
    {
    }
}
```

### Correction

```cs
namespace Sample.Project;

using System;

internal class Example
{
}
```
