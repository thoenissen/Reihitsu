# RH7003 — File-scoped namespaces should be used

| Property | Value |
|----------|-------|
| **ID** | RH7003 |
| **Category** | Organization |
| **Severity** | Warning |
| **Code Fix** | ❌ |

## Description

This rule reports a block-scoped namespace that can be written in the file-scoped form instead. A file-scoped namespace covers the whole file, so the rule reports a namespace only when it is the one declaration in its file and declares no namespace inside it, and only in projects that use C# 10 or later, where file-scoped namespaces exist.

A file with several namespaces, or with a type outside the namespace, is not reported. Split it up first, as [RH7001](RH7001.md) and [RH7002](RH7002.md) ask.

## Why is this a problem?

Block-scoped namespaces add an extra indentation level around the entire file. That makes the file longer and pushes all members further to the right without adding useful structure.

Using the file-scoped form keeps the namespace visible while reducing nesting and making the file easier to scan.

## How to fix it

Replace the block-scoped namespace with a file-scoped namespace and remove the extra indentation from the namespace contents.

## Examples

### Violation

```cs
namespace Sample.Project
{
    using System;

    internal class Example
    {
    }
}
```

### Correction

```cs
namespace Sample.Project;

using System;

internal class Example
{
}
```
