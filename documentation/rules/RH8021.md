# RH8021 — Private methods must be documented

| Property | Value |
|----------|-------|
| **ID** | RH8021 |
| **Category** | Documentation |
| **Severity** | Warning |
| **Code Fix** | ❌ |

## Description

This rule requires private method declarations to have XML documentation. A declaration counts as documented when it has a &lt;summary&gt; tag or uses &lt;inheritdoc/&gt;.

## Why is this a problem?

A private method is callable only from inside the type that declares it, so nothing outside that type explains what it is for. The summary is the one place where the reason it exists is recorded, and the editor shows it at every call site — so the next reader of the file, often the author some months later, does not have to reconstruct the intent from the body.

## How to fix it

Add a meaningful XML comment above the declaration. In most cases a short &lt;summary&gt; is the best fix.

## Exceptions

A method that explicitly implements an interface member, such as `void IDisposable.Dispose()`, is not reported even though it carries no accessibility modifier. Its description belongs to the interface member it implements, which is where readers and the editor already look for it.

## Examples

### Violation

```cs
/// <summary>
/// Represents a worker
/// </summary>
internal class Worker
{
    private void Execute()
    {
    }
}
```

### Correction

```cs
/// <summary>
/// Represents a worker
/// </summary>
internal class Worker
{
    /// <summary>
    /// Executes the internal cleanup routine
    /// </summary>
    private void Execute()
    {
    }
}
```
