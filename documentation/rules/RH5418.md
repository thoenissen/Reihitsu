# RH5418 — Empty unions should use semicolon declarations

| Property | Value |
|----------|-------|
| **ID** | RH5418 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

This rule prefers semicolon declarations for empty unions.

A union already lists the types it can hold in its declaration, so a brace body without members adds only noise.

## Why is this a problem?

An empty union expresses its full intent on the declaration line. The empty body adds visual overhead without adding behavior.

Using a semicolon declaration keeps declaration-only unions brief and consistent with the other empty types.

## How to fix it

Replace the empty brace body with a trailing semicolon. The code fix applies this change automatically.

## Examples

### Violation

```cs
internal union Pet(int, string)
{
}
```

### Correction

```cs
internal union Pet(int, string);
```
