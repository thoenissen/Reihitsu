# RH5021 — Local declarations should be followed by a blank line

| Property | Value |
|----------|-------|
| **ID** | RH5021 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

Where a local variable declaration is directly followed by an expression statement such as a method call, the two should be separated by a blank line.

## Why is this a problem?

When local declarations are placed directly next to the expression statements that use or follow them, the code becomes harder to scan. Separating declaration blocks from the next action makes the logical structure of the method easier to follow.

## How to fix it

Insert a blank line between the declaration and the statement that follows it. The code fix does this for you. When a comment sits directly above that statement, the blank line is placed above the comment, so the comment stays attached to the code it describes.

## Exceptions

This rule reports nothing when the statement that follows the declaration:

- is another declaration, so a run of declarations stays grouped together — no blank line is needed;
- is an assignment such as `value = 1;`, which keeps setting up the variables just declared — no blank line is needed;
- directly follows a preprocessor directive such as `#if` or `#region` — no blank line is needed;
- is a top-level statement in a file that has no enclosing type — no blank line is needed;
- is a control-flow statement such as `if`, `foreach`, or `return`. Those still need a blank line, but the rule for that particular statement reports it, not RH5021.

## Examples

### Violation

```cs
private void Execute()
{
    var value = GetValue();
    Consume(value);
}
```

### Correction

```cs
private void Execute()
{
    var value = GetValue();

    Consume(value);
}
```
