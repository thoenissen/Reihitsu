# RH3207 — Expression style finalizers should not be used

| Property | Value |
|----------|-------|
| **ID** | RH3207 |
| **Category** | Clarity |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

This rule disallows expression-bodied finalizers (finalizers using `=>`). All finalizers should use block bodies for consistency and clarity.

## Why is this a problem?

Expression-bodied finalizers create inconsistency when some members use block bodies and others use expression bodies. Requiring block bodies keeps finalizers in line with constructors and gives every member a uniform shape.

## How to fix it

Replace the expression-bodied finalizer with a block body containing the expression as a statement.

## Exceptions

The rule is not reported when a preprocessor directive sits between the arrow and the expression:

```cs
~Resource() =>
#pragma warning disable CS0618
    Release();
#pragma warning restore CS0618
```

The conversion to a block body would have to move that directive into the generated block, which the
formatter refuses to do, so the finalizer keeps its expression body. The same applies to a
conditional group whose partner directive lies outside the finalizer, and to any `#region` or
`#endregion` directive between the arrow and the semicolon. A `#pragma` or a complete `#if` group
written *after* the expression is unaffected, and such a finalizer is still reported.

## Examples

### Violation

```cs
internal class Resource
{
    ~Resource() => Release();

    private void Release()
    {
    }
}
```

### Correction

```cs
internal class Resource
{
    ~Resource()
    {
        Release();
    }

    private void Release()
    {
    }
}
```
