# RH5204 — Indentation must use 4 spaces per scope level

| Property | Value |
|----------|-------|
| **ID** | RH5204 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

This rule requires each scope level to add exactly 4 spaces of indentation.

## Why is this a problem?

Inconsistent indentation makes nested code harder to scan and understand. When members, blocks, regions, or comments drift away from their expected scope level, the visual structure of the file becomes unclear.

## How to fix it

Indent each nested scope by 4 additional spaces. Keep comments and region directives aligned with the code they belong to, or apply the provided code fix to normalize the indentation.

## What the rule deliberately leaves alone

Two constructs are exempt by design, so that `reihitsu-format` and the RH5204 code fix always write the same
text for the same input. Both exemptions are shared with the formatter's indentation phase rather than
re-decided here.

### Region directives inside an excluded branch

`#region` and `#endregion` inside a conditional branch the compiler skipped are left exactly where the author
wrote them:

```cs
public class Example
{
#if false
#region Disabled
#endregion
#endif

    public bool Value => true;
}
```

The code around such a directive is untouched disabled text, so re-indenting the directive on its own would
half-format a region nobody compiles. The formatter declines this for the same reason, and the rule follows it
so the CLI and the IDE fix cannot disagree.

### Statements inside a brace-bodied lambda

Block bodies of lambdas and anonymous methods are not analysed for scope indentation. Their columns are owned
by the formatter's alignment pass, which positions them against the construct they are nested in rather than
against a plain scope depth, so reporting a fixed 4-spaces-per-level expectation there would contradict the
formatter's own output. Running the formatter still normalizes those bodies.

## Examples

### Violation

```cs
public class Example
{
  public bool Foo()
  {
     return false;
  }
}
```

### Correction

```cs
public class Example
{
    public bool Foo()
    {
        return false;
    }
}
```
