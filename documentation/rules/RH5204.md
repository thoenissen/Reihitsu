# RH5204 — Indentation must use 4 spaces per scope level

| Property | Value |
|----------|-------|
| **ID** | RH5204 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

This rule requires each scope level to add exactly 4 spaces of indentation.

## Why is this a problem?

Inconsistent indentation makes nested code harder to scan and understand. When members, blocks, regions, or comments drift away from their expected scope level, the visual structure of the file becomes unclear.

## How to fix it

Indent each nested scope by 4 additional spaces. Keep comments and region directives aligned with the code they belong to, or apply the provided code fix to normalize the indentation.

## Exceptions

The rule does not check the indentation of lines inside the body of a statement lambda or an anonymous method:

```cs
public class Example
{
    public void Method()
    {
        Register(() =>
                 {
                     var value = 1;
                 });
    }
}
```

Where those lines belong depends on how the surrounding expression is laid out, so it is not a fixed four
spaces per scope level in every case. Run `reihitsu-format` to normalize the layout of such a body.

## Conditional-compilation exemption

This rule does not report a `#region` or `#endregion` directive that sits inside a conditional block the
compiler excluded — an `#if false` block, or an `#if SYMBOL` block whose symbol is not defined when the file is
analyzed:

```cs
public class Example
{
#if false
#region Disabled
#endregion // Disabled
#endif

    public bool Value => true;
}
```

The code inside such a block is not compiled and is left exactly as it was written. Moving the directive on its
own would re-indent a single line of an otherwise untouched block, which makes the file look half-formatted
rather than corrected. `reihitsu-format` applies the same exemption, so the command-line formatter and the IDE
code fix always produce the same result.

Only the indentation is exempt. The name of the region and its matching `#endregion` comment are still
normalized, so the two directives above keep their column but not necessarily their exact text.

Directives in a branch that *is* compiled are reported and fixed as usual.

## Examples

### Violation

```cs
public class Example
{
  public bool Foo()
  {
     return false;
  }
}
```

### Correction

```cs
public class Example
{
    public bool Foo()
    {
        return false;
    }
}
```
