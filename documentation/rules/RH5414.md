# RH5414 — Empty interfaces should use semicolon declarations

| Property | Value |
|----------|-------|
| **ID** | RH5414 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

This rule prefers semicolon declarations for empty interfaces.

Brace-based empty interface bodies add noise when the declaration contains no members.

The rule reports only when the project's C# language version allows the semicolon form (C# 12 or later for an empty interface).

## Why is this a problem?

An empty interface already communicates everything through its declaration line. The extra braces do not add information.

Using a semicolon declaration makes empty contracts more concise and keeps declaration-only code easier to read.

## How to fix it

Replace the empty brace body with a trailing semicolon. The code fix applies this change automatically.

A declaration that carries a comment or a `#` directive in the body, after the header, or between the header and the opening brace is still reported, but no code fix is offered for it: dropping the braces would leave that text with nowhere to go, and only you can decide where it belongs. Move the note above the declaration and remove the braces by hand, or keep the declaration as it is.

## Examples

### Violation

```cs
internal interface IExample
{
}
```

### Correction

```cs
internal interface IExample;
```
