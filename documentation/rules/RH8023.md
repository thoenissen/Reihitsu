# RH8023 — Private properties must be documented

| Property | Value |
|----------|-------|
| **ID** | RH8023 |
| **Category** | Documentation |
| **Severity** | Warning |
| **Code Fix** | ❌ |

## Description

This rule requires private property declarations to have XML documentation. A declaration counts as documented when it has a &lt;summary&gt; tag or uses &lt;inheritdoc/&gt;.

## Why is this a problem?

A private property is visible only inside the type that declares it, so nothing outside that type explains what it holds. The summary is the one place where its meaning is recorded — what the value stands for, and when it is valid — and the editor shows it at every use site inside the file.

## How to fix it

Add a meaningful XML comment above the declaration. In most cases a short &lt;summary&gt; is the best fix.

## Exceptions

A property that explicitly implements an interface member, such as `string IEntity.Name { get; }`, is not reported even though it carries no accessibility modifier. Its description belongs to the interface member it implements, which is where readers and the editor already look for it.

## Examples

### Violation

```cs
/// <summary>
/// Stores application settings
/// </summary>
internal class Settings
{
    private string Name { get; }
}
```

### Correction

```cs
/// <summary>
/// Stores application settings
/// </summary>
internal class Settings
{
    /// <summary>
    /// Gets the cached profile name used by the settings loader
    /// </summary>
    private string Name { get; }
}
```
