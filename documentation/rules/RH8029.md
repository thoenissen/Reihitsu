# RH8029 — Private events must be documented

| Property | Value |
|----------|-------|
| **ID** | RH8029 |
| **Category** | Documentation |
| **Severity** | Warning |
| **Code Fix** | ❌ |

## Description

This rule requires private event declarations to have XML documentation. A declaration counts as documented when it has a `<summary>` tag or uses `<inheritdoc/>`.

## Why is this a problem?

An event says nothing about when it is raised, and a private one is raised only from inside the type that declares it, so there is no other place that answers the question. The summary is where the triggering condition is recorded, and the editor shows it wherever the event is subscribed to or raised.

## How to fix it

Add a meaningful XML comment above the declaration. In most cases a short `<summary>` is the best fix.

## Exceptions

An event that explicitly implements an interface member, such as `event System.Action IPublisher.Changed`, is not reported even though it carries no accessibility modifier. Its description belongs to the interface member it implements, which is where readers and the editor already look for it.

## Examples

### Violation

```cs
/// <summary>
/// Publishes notifications
/// </summary>
internal class Publisher
{
    private event System.Action Changed;
}
```

### Correction

```cs
/// <summary>
/// Publishes notifications
/// </summary>
internal class Publisher
{
    /// <summary>
    /// Raised after the internal state changes
    /// </summary>
    private event System.Action Changed;
}
```
