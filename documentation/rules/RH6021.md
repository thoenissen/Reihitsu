# RH6021 — Colons must be spaced correctly

| Property | Value |
|----------|-------|
| **ID** | RH6021 |
| **Category** | Spacing |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

A colon `:` must carry one space in front of it and one space behind it. The rule covers the colon that introduces a base class or interface list (`class TestClass : IDisposable`) and the colon of a constructor initializer (`: base(…)`, `: this(…)`). Colons in other positions — a case label, a conditional expression, a named argument — keep their own spacing and are not reported.

When the colon or one of its neighbours starts a new line, that side is positioned by the surrounding indentation and is left as it is; only the side that shares a line with the colon is checked.

## Why is this a problem?

A colon written tight against the tokens on either side fuses them into one run of characters, so the base type a class derives from, or the constructor it chains to, is harder to pick out of the declaration line.

## How to fix it

Put a single space before and after the colon. The code fix applies this change automatically.

No code fix is offered when a comment sits in the gap the rule flags, because inserting the space there would move or swallow the comment. Add the space by hand in that case.

## Examples

### Violation

```cs
internal class TestClass:System.IDisposable
{
    public void Dispose()
    {
    }
}
```

### Correction

```cs
internal class TestClass : System.IDisposable
{
    public void Dispose()
    {
    }
}
```
