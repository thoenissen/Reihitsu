# RH5004 — do-Statement should be preceded by a blank line

| Property | Value |
|----------|-------|
| **ID** | RH5004 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

A `do` statement that follows another statement in the same block or `switch` section should be separated from it by a blank line.

## Why is this a problem?

Separating statements with blank lines improves code readability by visually grouping related logic. A blank line before a `do` loop clearly marks the start of the loop construct and separates it from preceding code.

## How to fix it

Insert a blank line between the preceding statement and the `do` statement. The code fix does this for you. When a comment sits directly above the statement, the blank line is placed above that comment, so the comment stays attached to the code it describes.

## Exceptions

Nothing is reported, and no blank line is needed, when the `do` statement:

- is the first statement of its block, or the first statement under a `case` or `default` label;
- is the body of a statement that is written without braces — for example the single statement after `while`, `for`, `foreach`, `using`, `lock`, `fixed`, `do`, or `else`;
- directly follows a preprocessor directive such as `#if`, `#endif`, or `#region`;
- is a top-level statement in a file that has no enclosing type.

## Examples

### Violation

```cs
private void Execute()
{
    var value = 0;
    do
    {
        value++;
    }
    while (value < 10);
}
```

### Correction

```cs
private void Execute()
{
    var value = 0;

    do
    {
        value++;
    }
    while (value < 10);
}
```
