# RH8035 — Non-private unions must be documented

| Property | Value |
|----------|-------|
| **ID** | RH8035 |
| **Category** | Documentation |
| **Severity** | Warning |
| **Code Fix** | ❌ |

## Description

This rule requires non-private union declarations to have XML documentation. A declaration counts as documented when it has a `<summary>` tag or uses `<inheritdoc/>`.

## Why is this a problem?

A union that other code can use defines which kinds of values that code has to handle. Without a summary, readers have to infer what the union stands for from its case types instead of reading a clear contract.

## How to fix it

Add a meaningful XML comment above the declaration. In most cases a short `<summary>` is the best fix.

## Examples

### Violation

```cs
public union CustomerKey(int, string);
```

### Correction

```cs
/// <summary>
/// Identifies a customer by account number or by user name
/// </summary>
public union CustomerKey(int, string);
```
