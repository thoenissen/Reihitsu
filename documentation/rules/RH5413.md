# RH5413 — Empty structs should use semicolon declarations

| Property | Value |
|----------|-------|
| **ID** | RH5413 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

This rule prefers semicolon declarations for empty structs.

Brace-based empty struct bodies add noise when the declaration contains no members.

The rule reports only when the project's C# language version allows the semicolon form (C# 12 or later for an empty struct).

## Why is this a problem?

An empty struct body adds visual weight without contributing implementation detail.

Using a semicolon declaration keeps simple marker structs and placeholder value types compact and easier to scan.

## How to fix it

Replace the empty brace body with a trailing semicolon. The code fix applies this change automatically.

A declaration that carries a comment or a `#` directive in the body, after the header, or between the header and the opening brace is still reported, but no code fix is offered for it: dropping the braces would leave that text with nowhere to go, and only you can decide where it belongs. Move the note above the declaration and remove the braces by hand, or keep the declaration as it is.

## Examples

### Violation

```cs
internal struct Example
{
}
```

### Correction

```cs
internal struct Example;
```
