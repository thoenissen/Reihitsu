# RH3206 — Expression style conversion operators should not be used

| Property | Value |
|----------|-------|
| **ID** | RH3206 |
| **Category** | Clarity |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

This rule disallows expression-bodied conversion operators (`implicit` or `explicit` operators using `=>`). All conversion operators should use block bodies with explicit `return` statements for consistency and clarity.

## Why is this a problem?

Expression-bodied conversion operators create inconsistency when some members use block bodies and others use expression bodies. Requiring block bodies keeps conversions in line with methods and operators and gives every member a uniform shape.

## How to fix it

Replace the expression-bodied conversion operator with a block body containing a `return` statement.

## Exceptions

The rule is not reported when a preprocessor directive sits between the arrow and the expression:

```cs
public static implicit operator double(Meters meters) =>
#pragma warning disable CS0618
    meters.Value;
#pragma warning restore CS0618
```

The conversion to a block body would have to move that directive into the generated block, which the
formatter refuses to do, so the conversion operator keeps its expression body. The same applies to a
conditional group whose partner directive lies outside the conversion operator, and to any `#region`
or `#endregion` directive between the arrow and the semicolon. A `#pragma` or a complete `#if` group
written *after* the expression is unaffected, and such a conversion operator is still reported.

## Examples

### Violation

```cs
internal class Meters
{
    public Meters(double value)
    {
        Value = value;
    }

    public double Value { get; }

    public static implicit operator double(Meters meters) => meters.Value;
}
```

### Correction

```cs
internal class Meters
{
    public Meters(double value)
    {
        Value = value;
    }

    public double Value { get; }

    public static implicit operator double(Meters meters)
    {
        return meters.Value;
    }
}
```
