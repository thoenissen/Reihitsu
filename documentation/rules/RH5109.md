# RH5109 — Parameters must be on same line or separate lines

| Property | Value |
|----------|-------|
| **ID** | RH5109 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

In a parameter list, all parameters must either fit on one line or each parameter must be on its own line. Once the list spans multiple lines — including when a single parameter's type wraps across lines — every parameter must start on its own line. Mixing parameters that share a line with parameters on separate lines is not allowed.

A parameter's type that is a wrapped generic argument list with nothing inside it that would refuse a join — no comment, directive, or multi-line argument — is joined onto one line by the formatter itself before this rule has anything to evaluate (see the type-argument and type-parameter list rules in the formatter documentation). A parameter type that still spans multiple lines after formatting is what continues to put the parameter list into its multi-line form.

## Why is this a problem?

Partially split parameter lists are harder to scan because the reader cannot quickly determine how many parameters there are or align them visually.

## How to fix it

Either keep all parameters on one line or put each parameter on its own line. The code fix applies the one-parameter-per-line form.

## Exceptions

When a comment or a preprocessor directive sits between the parentheses, or on its own line between the method name and the opening parenthesis, the diagnostic is still reported, but no code fix is offered. Redistributing the parameters would move that comment or directive somewhere you did not put it, so the list is left for you to split by hand.

## Examples

### Violation

```cs
internal class TestClass
{
    void Method(int first, int second,
                int third)
    {
    }
}
```

### Correction

```cs
internal class TestClass
{
    void Method(int first,
                int second,
                int third)
    {
    }
}
```
