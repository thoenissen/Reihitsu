# RH5105 — Opening parenthesis must be on declaration line

| Property | Value |
|----------|-------|
| **ID** | RH5105 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

The opening parenthesis of a parameter list must appear on the same line as the preceding declaration token. This applies to methods, constructors, destructors, local functions, operators, conversion operators, delegates, records, class and struct primary constructors, interface parameter lists, extension blocks, and anonymous methods.

Parenthesized lambdas are outside this rule because their opening parenthesis is the first token of the expression. Its placement belongs to the surrounding expression or argument-list layout rather than to a preceding declaration token. Simple lambdas have no parameter list and are also outside this rule.

## Why is this a problem?

Moving the opening parenthesis to the next line separates the declaration name from its parameter list, making the declaration harder to read and navigate.

## How to fix it

Move the opening parenthesis immediately after the preceding declaration token on the same line. The code fix applies this change automatically.

## Exceptions

The rule does not report a declaration whose opening parenthesis is separated from the declaration name by a comment or a preprocessor directive. Joining the lines there would change where that comment or directive belongs, so the declaration is left exactly as written.

## Examples

### Violation

```cs
internal class TestClass
{
    void Method
    (int value)
    {
    }
}
```

### Correction

```cs
internal class TestClass
{
    void Method(int value)
    {
    }
}
```
