# RH5404 — Element must not be on a single line

| Property | Value |
|----------|-------|
| **ID** | RH5404 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

A type declaration body must not be written on a single line. The opening brace, the members, and the closing brace must each appear on their own line. This covers classes, structs, interfaces, records, record structs, and enums, and it also reaches extension blocks and — for consumers compiling with a preview language version — union declarations.

A type written without a brace body at all — `internal class Marker;` or `internal readonly record struct Point(int X, int Y);` — is not reported.

## Known limitation

An extension block has no name. The rule reports it on the declaration's identifier, which for an extension block is a missing token, so the resulting diagnostic carries no source location and the code fix cannot be applied to it. A single-line extension block therefore has to be expanded by hand. Correcting that is tracked separately; the diagnostic is left in place rather than dropped, because the shape is one the formatter does reformat.

## Why is this a problem?

A one-line type body hides where the type begins and ends, so the members are hard to pick out and the next person adding one has to reformat the declaration first. Expanded declarations also produce readable diffs: adding a member changes one line instead of rewriting the whole type.

## How to fix it

Expand the declaration so the opening brace, each member, and the closing brace are on their own lines. The code fix applies this change automatically.

A type with a one-line *empty* body is turned into a semicolon declaration instead — `internal class Marker { }` becomes `internal class Marker;` — because an empty brace body would immediately be reported again by the rule for empty types of that kind.

## Examples

### Violation

```cs
internal class TestClass { private int _value; }
```

### Correction

```cs
internal class TestClass
{
    private int _value;
}
```
