# RH2009 — Methods should not exceed the complexity limit

| Property | Value |
|----------|-------|
| **ID** | RH2009 |
| **Category** | Design |
| **Severity** | Warning |
| **Code Fix** | ❌ |

## Description

Reports a method whose body is harder to follow than its limit allows, measured as its cognitive complexity. Constructors, finalizers, operators, local functions, and property, indexer, and event accessors are checked in the same way.

The cognitive complexity adds points for every break in the straight flow of the code:

- `if`, `?:`, `switch` (once for the whole switch), `for`, `foreach`, `while`, `do`, and `catch` each add 1, **plus 1 for every level they are nested in**. The same `if` costs 1 at the top of the method, 2 inside one `if` or loop, and 3 inside two.
- `else if`, `else`, and a `?:` chained in the false branch of another add 1, without the nesting points.
- Each sequence of `&&`, `||`, or `&`, `|`, `^` on `bool` or `bool?` adds 1, and each change from one operator to another adds 1 more; a `!` starts a new sequence. `and` and `or` in an `is` pattern count the same way. Each `goto` adds 1, and a method that calls itself adds 1.
- The code of a lambda counts toward the method that contains it, one level deeper. A local function is checked on its own.

A method is reported only when it nests at least one `if`, `?:`, `switch`, loop, or `catch` inside another; a method whose decisions all stand one after another is never reported, however many it has.

By default, a method may have a cognitive complexity of 15, in production code and in test code. [Cognitive complexity](../cognitive-complexity.md) explains the scoring of every construct, with examples.

## Why is this a problem?

Every branch makes the reader track one more condition, and a branch inside another branch makes them hold both in mind at once. Deeply nested code is where mistakes hide and where tests miss cases. A limit makes that complexity visible in every build instead of leaving it to each reviewer's judgment.

## How to fix it

Reduce the nesting and the number of decisions in the method: return early instead of wrapping the rest of the method in an `if`, combine conditions, and extract a nested block that has a clear purpose into a method with a descriptive name. No code fix is offered, because how to restructure a method is a design decision.

## Configuration

To use another limit, add a `reihitsu.json` file to your project and set the highest cognitive complexity a method may have:

```json
{
  "design": {
    "maximumMethodComplexity": 15
  }
}
```

The setting is optional: when you leave it out, or when RH0001 reports it as invalid, the default applies. A method with exactly that complexity is accepted.

## Examples

### Violation

```cs
// Cognitive complexity 16: foreach 1, if 2, if 3, for 4, if 5, else if 1
public int Score(int[] values)
{
    int total = 0;

    foreach (var value in values)
    {
        if (value > 0)
        {
            if (value % 2 == 0)
            {
                for (int i = 0; i < value; i++)
                {
                    if (i % 3 == 0)
                    {
                        total += i;
                    }
                    else if (i % 5 == 0)
                    {
                        total -= i;
                    }
                }
            }
        }
    }

    return total;
}
```

### Correction

```cs
public int Score(int[] values)
{
    int total = 0;

    foreach (var value in values)
    {
        total += ScoreValue(value);
    }

    return total;
}

private int ScoreValue(int value)
{
    if (value <= 0 || value % 2 != 0)
    {
        return 0;
    }

    int score = 0;

    for (int i = 0; i < value; i++)
    {
        score += AdjustForIndex(i);
    }

    return score;
}

private int AdjustForIndex(int index)
{
    if (index % 3 == 0)
    {
        return index;
    }

    if (index % 5 == 0)
    {
        return -index;
    }

    return 0;
}
```
