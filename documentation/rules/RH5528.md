# RH5528 — Return value attribute lists must use one attribute per list

| Property | Value |
|----------|-------|
| **ID** | RH5528 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

Return value attribute lists must contain exactly one attribute.

## Why is this a problem?

Every return-value attribute has to name the `return:` target, and merging them hides that: `[return: First, Second]`
reads as one annotation with two parts rather than as two independent statements about the result. Splitting the list
restores the reading, and lets either attribute be removed without rewriting the line that carries the other.

## How to fix it

Give each attribute a list of its own: replace `[return: First, Second]` with `[return: First]` on one line and
`[return: Second]` on the next. A code fix is offered and performs the split for you.

If a comment sits inside the list, the diagnostic is still reported but no code fix is offered, because the split
would have to decide which of the two new lists keeps your comment. Separate the attributes by hand in that case.

## Exceptions

A list on an accessor of a single-line auto-property, such as
`public int Value { [return: First, Second] get; set; }`, is not reported. The formatter keeps every attribute list of
such an accessor merged on the property's line, whatever its explicit target, so splitting it would only be undone
again. The exemption holds only while no accessor has a body or an expression body and no comment or directive sits
inside the accessor list; the formatter expands the property otherwise, and the rule applies as usual.

## Examples

### Violation

```cs
internal class Example
{
    [return: First, Second]
    internal int Execute()
    {
        return 0;
    }
}
```

### Correction

```cs
internal class Example
{
    [return: First]
    [return: Second]
    internal int Execute()
    {
        return 0;
    }
}
```
