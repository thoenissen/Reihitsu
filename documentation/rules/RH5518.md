# RH5518 — Field attribute lists must use one attribute per list

| Property | Value |
|----------|-------|
| **ID** | RH5518 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

Field attribute lists must contain exactly one attribute.

This rule also reports on enum members, since an enum member declaration resolves to the same attribute target as a
field.

## Why is this a problem?

Attributes on a field are independent decisions, and `[First, Second]` is the syntax that says they are not. Because
fields are read as a block of short declarations, a merged attribute list is also the widest thing on the page;
splitting it keeps each attribute on a line of its own, above the field it applies to.

## How to fix it

Give each attribute a list of its own: replace `[First, Second]` with `[First]` on one line and `[Second]` on the
next. A code fix is offered and performs the split for you.

If a comment sits inside the list, the diagnostic is still reported but no code fix is offered, because the split
would have to decide which of the two new lists keeps your comment. Separate the attributes by hand in that case.

## Examples

### Violation

```cs
internal class Example
{
    [First, Second]
    private int _value;
}
```

### Correction

```cs
internal class Example
{
    [First]
    [Second]
    private int _value;
}
```
