# RH5523 — Parameter attributes must stay inline

| Property | Value |
|----------|-------|
| **ID** | RH5523 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

An attribute on a parameter stays on the same line as the parameter it applies to. This is the opposite of the rule
for declaration-level attributes, which get a line of their own.

This also covers an attribute list that names another target, such as `[property: JsonPropertyName("id")]` on a
positional record parameter: the list still sits inside the parameter list, so it stays on the parameter's line.

## Why is this a problem?

A parameter list is read as a sequence of parameters, and each parameter is read as one unit: its attributes, its
type and its name. Breaking the line between the attribute and the parameter splits that unit in two, and in a
multi-line parameter list the orphaned attribute then looks like a parameter of its own. Parameter attributes are
also short markers as a rule — `[CallerMemberName]`, `[NotNull]`, `[FromBody]` — so they cost almost nothing on the
parameter's line and cost a whole line each when they are moved off it.

## How to fix it

Join the attribute and the parameter onto one line. A code fix is offered and performs that edit for you.

## Examples

### Violation

```cs
internal class Example
{
    internal void Execute([First]
                          int value)
    {
    }
}
```

### Correction

```cs
internal class Example
{
    internal void Execute([First] int value)
    {
    }
}
```
