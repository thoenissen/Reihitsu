# RH5409 — Final enum members must not have trailing commas

| Property | Value |
|----------|-------|
| **ID** | RH5409 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

This rule forbids a trailing comma after the final member in an enum declaration.

## Why is this a problem?

A trailing comma on the last enum member adds noise without improving readability.

Keeping the final member free of a trailing comma makes the end of the enum clearer and keeps formatting predictable.

## How to fix it

Remove the comma after the final enum member. If the member has an attached comment, keep the comment with the member and remove only the comma.

The code fix and formatter can apply this automatically.

## Conditional-compilation exemption

This rule does not report a trailing comma when a preprocessor conditional directive (`#if`, `#elif`, `#else`,
`#endif`) or disabled text sits between the comma and the closing brace. Removing the comma there is only safe
for the preprocessor symbols in effect when the file was analyzed; under a different symbol configuration, a
member inside the conditional block can become active and follow the "final" member without a separator, which
no longer compiles. The exemption fires on the presence of a conditional boundary alone — it does not evaluate
the condition or reason about which branch is reachable, so it also withholds in cases where the comma happens
to be removable in every configuration.

```cs
internal enum Status
{
    Ready,
#if SYMBOL
    Completed,
#endif
}
```

The comma after `Ready` is not flagged, regardless of whether `SYMBOL` is defined. A `#region`/`#endregion` or
`#pragma` directive in the same position does not trigger the exemption, since neither can introduce a further
enum member.

## Examples

### Violation

```cs
internal enum Status
{
    Ready,
    Completed, // final value
}
```

### Correction

```cs
internal enum Status
{
    Ready,
    Completed // final value
}
```
