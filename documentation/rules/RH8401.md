# RH8401 — Single-line comments must not use documentation style slashes

| Property | Value |
|----------|-------|
| **ID** | RH8401 |
| **Category** | Documentation |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

This rule forbids regular single-line comments that start with `///`.

## Why is this a problem?

Three leading slashes are reserved for XML documentation comments. Using them for ordinary comments makes the code look documented when it is not, and can confuse editors and readers.

## How to fix it

Change ordinary comments to use `//` instead of `///`.

## Examples

### Violation

```cs
/// temporary workaround
DoWork();
```

### Correction

```cs
// temporary workaround
DoWork();
```

## Code fix behavior

Applying the fix once converts every line of the comment, not only the reported one, so a multi-line comment never ends up half `//` and half `///`. Only the leading slashes change: the text after them is kept exactly as it was, and a `///` further along the same line stays part of that text.

One case is left to manual correction. A line whose `///` is preceded by an invisible character that is not ordinary whitespace — a byte-order mark (U+FEFF) or a substitute character (U+001A) — keeps its three slashes after the fix has run. Change that line to `//` yourself, or delete the stray character and apply the fix again.
