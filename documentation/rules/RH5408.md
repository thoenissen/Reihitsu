# RH5408 — Simple auto-properties should be single lined

| Property | Value |
|----------|-------|
| **ID** | RH5408 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

A simple auto-property must be written on a single line. An auto-property is simple when none of its accessors has a body — `{ get; }`, `{ get; set; }`, `{ get; init; }`, and forms with accessor modifiers such as `{ get; private set; }` — and none of them carries its own attribute list.

The whole declaration counts, not just the accessor list: an initializer and the terminating semicolon belong on the same line as the signature. A property-level attribute does not exclude a property; it keeps its own line while the rest of the declaration still collapses.

## Why is this a problem?

A multi-line auto-property adds vertical noise without adding meaning. Simple accessor declarations are easier to scan when the full property stays compact, especially when a type contains many small members.

A declaration like

```cs
[Example]
public int Count
{
    get;
    set;
}
```

is harder to read than the equivalent single-line form because the accessor list carries no implementation logic.

## How to fix it

Put the signature, the accessor list, any initializer, and the terminating semicolon on one line. A property attribute stays on the line above it. The code fix applies this change automatically.

## Exceptions

Nothing is reported when:

- an accessor (`get`, `set`, or `init`) carries its own attribute — [RH5530](RH5530.md) and [RH5531](RH5531.md) decide how such a property is laid out;
- the initializer value spans several lines by itself;
- the signature is already wrapped over more than one line.

## Examples

### Violation

```cs
internal class Example
{
    [Example]
    public int Count
    {
        get;
        set;
    }

    public string Name
    {
        get;
    }
}
```

### Correction

```cs
internal class Example
{
    [Example]
    public int Count { get; set; }

    public string Name { get; }
}
```
