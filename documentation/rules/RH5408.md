# RH5408 — Simple auto-properties should be single lined

| Property | Value |
|----------|-------|
| **ID** | RH5408 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

A simple auto-property must be written on a single line. An auto-property is simple when none of its accessors has a body — `{ get; }`, `{ get; set; }`, `{ get; init; }`, and forms with accessor modifiers such as `{ get; private set; }`.

The whole declaration counts, not just the accessor list: an initializer and the terminating semicolon belong on the same line as the signature. Attributes do not exclude a property; a property-level attribute keeps its own line, and accessor-level attributes move onto the declaration line together with the accessors they belong to.

## Why is this a problem?

A multi-line auto-property adds vertical noise without adding meaning. Simple accessor declarations are easier to scan when the full property stays compact, especially when a type contains many small members.

A declaration like

```cs
[Example]
public int Count
{
    [Example]
    get;
    [Example]
    set;
}
```

is harder to read than the equivalent single-line form because the accessor list carries no implementation logic.

## How to fix it

Put the signature, the accessor list, any initializer, and the terminating semicolon on one line. A property attribute stays on the line above it. The code fix applies this change automatically.

## Exceptions

The rule stays silent whenever putting the declaration on one line would have to move a comment or a `#` directive away from the place you wrote it. That covers:

- a comment or directive inside the accessor list, for example between `get;` and `set;` or above a single accessor;
- a comment or directive between the signature and the opening brace, as in `public int Value // note` with the accessor list on the next line;
- a comment or directive between the accessor list and an initializer that starts on a later line, or between `=` and the initializer value;
- a comment or directive in front of a terminating semicolon that was pushed onto a line of its own — a line comment always has this effect, because it runs to the end of its line;
- an initializer value that spans several lines by itself;
- a signature that is already wrapped over more than one line.

These declarations are left to you. Rewrite them by hand if you want them on one line, or keep the comment where it is and leave them as they are.

A comment that does not stand in the way is not an exception. `public int Value { get; set; } // explanation`, `public int Value { get; set; } /* note */ = 1;`, and `public int Value { get; set; } = 1 /* note */;` are all fine as written, and the multi-line form of any of them is reported and put on one line with the comment kept where it was.

## Examples

### Violation

```cs
[Example]
public int Count
{
    [Example]
    get;
    [Example]
    set;
}

public string Name
{
    get;
}
```

### Correction

```cs
[Example]
public int Count { [Example] get; [Example] set; }

public string Name { get; }
```
