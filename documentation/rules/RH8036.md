# RH8036 — Private unions must be documented

| Property | Value |
|----------|-------|
| **ID** | RH8036 |
| **Category** | Documentation |
| **Severity** | Warning |
| **Code Fix** | ❌ |

## Description

This rule requires private union declarations to have XML documentation. A declaration counts as documented when it has a `<summary>` tag or uses `<inheritdoc/>`.

## Why is this a problem?

A private union is visible only inside the type that declares it, so nothing outside that type explains what it stands for. The summary is the one place where the reason it exists is recorded, and the editor shows it at every use site.

## How to fix it

Add a meaningful XML comment above the declaration. In most cases a short `<summary>` is the best fix.

## Examples

### Violation

```cs
/// <summary>
/// Parses configuration values
/// </summary>
internal class ConfigurationParser
{
    private union Token(int, string);
}
```

### Correction

```cs
/// <summary>
/// Parses configuration values
/// </summary>
internal class ConfigurationParser
{
    /// <summary>
    /// A single value read from the configuration
    /// </summary>
    private union Token(int, string);
}
```
