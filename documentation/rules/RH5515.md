# RH5515 — Property attributes must be on their own line

| Property | Value |
|----------|-------|
| **ID** | RH5515 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

Property attributes must be on their own line.

## Why is this a problem?

A reader scanning a type for a property looks down a column of accessibility modifiers, types and names. An attribute
written in front of the property displaces that whole line to the right, so properties that carry attributes no longer
line up with properties that do not. Properties also tend to attract several attributes — serialization, validation,
data binding — and the line grows unreadable long before the last one is added.

## How to fix it

Move the property declaration onto the line after the attribute list, leaving the attribute alone on its own line. A
code fix is offered and performs that edit for you.

If a comment sits inside the attribute list, the diagnostic is still reported but no code fix is offered, because the
rewrite would have to carry your comment along with the attribute. Insert the line break by hand in that case.

## Exceptions

The rule does not report when a comment or a preprocessor directive sits between the closing `]` and the property
declaration. Nothing can be moved onto its own line there without disturbing what you wrote in that gap, so the layout
you chose is left exactly as it is.

## Examples

### Violation

```cs
internal class Example
{
    [First] internal int Value { get; set; }
}
```

### Correction

```cs
internal class Example
{
    [First]
    internal int Value { get; set; }
}
```
