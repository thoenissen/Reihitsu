# RH5038 — Comments must not be placed inside an argument list

| Property | Value |
|----------|-------|
| **ID** | RH5038 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ❌ |

## Description

This rule reports a comment placed inside the argument list of a method call, an object creation, an element access, or an attribute. The rule applies whether or not the comment shares a line with code.

## Why is this a problem?

A comment in this position sits inside a single construct, so it is unclear which part of the code it describes. It also splits the construct across lines and keeps its layout from being kept consistent.

## How to fix it

Move the comment above the statement that contains the call. No code fix is offered, because only you can decide what the comment refers to.

## Exceptions

- A comment directly before a binary operator or before a later call of a method chain is not reported.
- A comment inside a nested block, initializer, switch expression, pattern, or query is not reported, for example above a statement inside a lambda.

## Examples

### Violation

```cs
using System;

internal class Example
{
    int Method()
    {
        return Math.Max(
            // first value
            1,
            2);
    }
}
```

### Correction

```cs
using System;

internal class Example
{
    int Method()
    {
        // first value is the lower bound
        return Math.Max(1, 2);
    }
}
```
