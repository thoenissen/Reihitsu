# RH3203 — Expression style constructors should not be used

| Property     | Value        |
|--------------|--------------|
| **ID**       | RH3203       |
| **Category** | Clarity |
| **Severity** | Warning      |
| **Code Fix** | ✔️            |

## Description

This rule disallows expression-bodied constructors (constructors using `=>`). All constructors should use block bodies for consistency and clarity.

## Why is this a problem?

Expression-bodied constructors can obscure initialization logic and create inconsistency when some constructors use block bodies and others use expression bodies. Requiring block bodies ensures a uniform coding style and makes constructor logic explicit.

## How to fix it

Replace the expression-bodied constructor with a block body containing the assignment or initialization statements.

## Exceptions

The rule is not reported when a preprocessor directive sits between the arrow and the expression:

```cs
public RH3203() =>
#pragma warning disable CS0618
    _value = 1;
#pragma warning restore CS0618
```

Rewriting that member as a block body would place the directive directly after the generated
expression statement, where a directive cannot sit because it must start its own line, so the result would no
longer compile. The same applies to a conditional or region group whose partner directive lies
outside the rewritten span. A directive that follows the expression is unaffected and is still
reported, because it travels inside the generated statement.

## Examples

### Violation

```cs
public MyClass(int x) => _x = x;
```

### Correction

```cs
public MyClass(int x)
{
    _x = x;
}
```
