# RH5035 — Comments must not be placed inside a parameter list

| Property | Value |
|----------|-------|
| **ID** | RH5035 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ❌ |

## Description

This rule reports a comment placed inside the parameter list of a method, constructor, delegate, indexer, operator, local function, lambda, or primary constructor. This includes a comment between the name and the opening parenthesis. The rule applies whether or not the comment shares a line with code.

## Why is this a problem?

A comment in this position sits inside a single construct, so it is unclear which part of the code it describes. It also splits the construct across lines and keeps its layout from being kept consistent.

## How to fix it

Move the comment above the declaration. Use the documentation comment of the declaration to describe individual parameters. No code fix is offered, because only you can decide what the comment refers to.

## Examples

### Violation

```cs
internal class Example
{
    public void Method(
        // the value
        int value,
        int other)
    {
    }
}
```

### Correction

```cs
internal class Example
{
    // value: the value
    public void Method(int value, int other)
    {
    }
}
```
