# RH8016 — Private delegates must be documented

| Property | Value |
|----------|-------|
| **ID** | RH8016 |
| **Category** | Documentation |
| **Severity** | Warning |
| **Code Fix** | ❌ |

## Description

This rule requires private delegate declarations to have XML documentation. A declaration counts as documented when it has a &lt;summary&gt; tag or uses &lt;inheritdoc/&gt;.

## Why is this a problem?

A private delegate is visible only inside the type that declares it, so nothing outside that type explains what it is for. The summary is the one place where the reason it exists is recorded, and the editor shows it at every use site — so the next reader of the file, often the author some months later, does not have to reconstruct the intent from the code.

## How to fix it

Add a meaningful XML comment above the declaration. In most cases a short &lt;summary&gt; is the best fix.

## Examples

### Violation

```cs
/// <summary>
/// Hosts nested callbacks
/// </summary>
internal class Container
{
    private delegate void WorkerCallback();
}
```

### Correction

```cs
/// <summary>
/// Hosts nested callbacks
/// </summary>
internal class Container
{
    /// <summary>
    /// Handles work completion inside the container
    /// </summary>
    private delegate void WorkerCallback();
}
```
