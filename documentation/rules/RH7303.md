# RH7303 — Do not place regions within elements

| Property | Value |
|----------|-------|
| **ID** | RH7303 |
| **Category** | Organization |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

This rule reports a `#region` or `#endregion` directive that sits inside executable code — a method or constructor body, a property or event accessor, a local function, a lambda, or any statement.

Regions that group the members of a type, a namespace, or a file are the intended use and are not reported.

## Why is this a problem?

A region inside a method body collapses part of an algorithm out of sight. Whoever reads the method next sees a labelled block instead of the statements it hides, and has to expand it before the control flow can be followed at all. A method that needs regions to stay readable is usually a method that should be split into smaller ones.

## How to fix it

Remove the `#region` and `#endregion` directives and leave the code they enclosed where it is. The code fix does this for you. If the block really needed a heading, extract it into its own method with a descriptive name, or replace the region with a short comment.

## Examples

### Violation

```cs
internal class TestClass
{
    void Method()
    {
        #region Helper
        var value = 1;
        #endregion
    }
}
```

### Correction

```cs
internal class TestClass
{
    void Method()
    {
        var value = 1;
    }
}
```
