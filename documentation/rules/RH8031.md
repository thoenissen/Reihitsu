# RH8031 — Extension declarations must have summary text

| Property | Value |
|----------|-------|
| **ID** | RH8031 |
| **Category** | Documentation |
| **Severity** | Warning |
| **Code Fix** | ❌ |

## Description

This rule requires each `extension(...)` or `extension<T>(...)` declaration to include a non-empty `<summary>` tag. A declaration carrying no documentation at all and a declaration whose `<summary>` is empty are both reported. The members written inside the block are covered by the ordinary member documentation rules.

## Why is this a problem?

An `extension` block names the value it extends and nothing else. Without a summary, a reader who wants to know which values the block is meant for, and what it adds to them, has to open the block and work that out from the members inside it.

## How to fix it

Write a `<summary>` on the extension declaration that says what the block adds and which values it applies to.

## Examples

### Violation

```cs
/// <summary>
/// Provides text-related extensions
/// </summary>
public static class Extensions
{
    extension(string value)
    {
    }
}
```

### Correction

```cs
/// <summary>
/// Provides text-related extensions
/// </summary>
public static class Extensions
{
    /// <summary>
    /// Adds parsing helpers to a text value
    /// </summary>
    extension(string value)
    {
    }
}
```
