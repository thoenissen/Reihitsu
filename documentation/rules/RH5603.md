# RH5603 — File must not end with a newline

| Property | Value |
|----------|-------|
| **ID** | RH5603 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

A source file must end immediately after its last source character, with no line break and no blank line after it.

## Why is this a problem?

Whether a file ends with a line break is invisible in an editor, so it drifts from file to file and from contributor
to contributor without anyone deciding it. The drift is not harmless: adding or removing the final line break makes
the last line of the file appear in a diff as a changed line even though its content is untouched, and different
editors and generators disagree about which form they leave behind. Settling the question in one direction removes a
recurring, content-free source of diff noise.

## How to fix it

Delete the line break — and any blank lines — after the last source character. A code fix is offered and performs
that edit for you; `reihitsu-format` applies the same normalization across a whole file.

## Examples

### Violation

The closing brace is followed by a line break, so the file's real last line is an empty one. Nothing in an editor
shows this, but the fenced block below really has that trailing blank line:

```cs
internal class TestClass
{
}

```

### Correction

The file ends with the closing brace itself; there is no blank line after it:

```cs
internal class TestClass
{
}
```
