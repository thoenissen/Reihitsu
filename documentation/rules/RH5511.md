# RH5511 — Constructor attributes must be on their own line

| Property | Value |
|----------|-------|
| **ID** | RH5511 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

Constructor attributes must be on their own line.

## Why is this a problem?

Constructors are found by their name, which is also the type's name, and a reader scanning a type for its constructors
looks down a single column for it. An attribute written in front of the constructor moves that name out of the column,
so a constructor carrying attributes no longer lines up with the one next to it. Separating the two also keeps a
change to the constructor's parameters distinguishable in a diff from a change to its attributes.

## How to fix it

Move the constructor declaration onto the line after the attribute list, leaving the attribute alone on its own line.
A code fix is offered and performs that edit for you.

If a comment sits inside the attribute list, the diagnostic is still reported but no code fix is offered, because the
rewrite would have to carry your comment along with the attribute. Insert the line break by hand in that case.

The same is true when the attribute list's line is itself the continuation of a multi-line comment, or a multi-line
raw or verbatim string literal, that started on an earlier line. That line's leading whitespace is then part of the
comment's or string's own content rather than code indentation, and there is no general way to recover the
declaration's real indentation from it, so the fix is withheld and the diagnostic is left for you to correct by hand.

## Exceptions

The rule does not report when a comment or a preprocessor directive sits between the closing `]` and the constructor
declaration. Nothing can be moved onto its own line there without disturbing what you wrote in that gap, so the layout
you chose is left exactly as it is.

## Examples

### Violation

```cs
internal class Example
{
    [First] internal Example() { }
}
```

### Correction

```cs
internal class Example
{
    [First]
    internal Example() { }
}
```
