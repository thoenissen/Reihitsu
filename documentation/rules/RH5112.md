# RH5112 — Wrapped fluent calls should keep the first call on the original line

| Property | Value |
|----------|-------|
| **ID** | RH5112 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

This rule requires a wrapped chain to keep its first member access on the line its receiver ends on. This covers chains of calls, chains that only read properties (`order.Customer.Address`), and the first `.`, `?.`, `!.`, or `!?.` of a chain, whether or not it is a call. When later members still need to wrap, they may continue on following lines.

When properties are read before the first call (`settings.Items.Where(...)`), the first call may start a new line; only the first property access has to stay on the original line. An index access such as `?[0]` is not a member access and is not reported.

## Why is this a problem?

Breaking before the first fluent call makes the expression harder to scan because the starting point is separated from the object being configured or queried. Keeping the first call on the original line makes the expression easier to follow while still allowing longer call sequences to wrap clearly.

## How to fix it

Move the first wrapped member access back onto the original line. Leave later calls on separate lines when the expression still needs to wrap.

## Examples

### Violation

```cs
var pipeline = new PipelineBuilder()
    .UseLogging()
    .UseValidation()
    .UseExecution();
```

### Correction

```cs
var pipeline = new PipelineBuilder().UseLogging()
                                    .UseValidation()
                                    .UseExecution();
```
