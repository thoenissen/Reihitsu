# RH5107 — Comma must be on same line as previous parameter

| Property | Value |
|----------|-------|
| **ID** | RH5107 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

In a multi-line parameter or argument list, the comma separating elements must appear at the end of the line that contains the preceding element, not at the start of the following line.

## Why is this a problem?

A leading comma on the next line is non-standard in C# and makes it harder to read parameter lists by moving the separator away from the element it follows.

## How to fix it

Move the comma to the end of the preceding line, and align the following element under the first element of the list. The code fix applies this change automatically, except for the case described below.

## Exceptions

The rule does not report a list in which a comment or a preprocessor directive sits between the preceding element and the comma. Pulling the comma up would change where that comment or directive belongs, so the list is left exactly as written.

The rule still reports a diagnostic, but offers no fix, when the comma is the last non-whitespace content on its own line. The misaligned element the diagnostic is about then sits on a further line the fix does not locate, so applying it there would only leave a whitespace-only line behind; that line has to be corrected by hand.

## Examples

### Violation

```cs
internal class TestClass
{
    void Method(int first
               ,int second)
    {
    }
}
```

### Correction

```cs
internal class TestClass
{
    void Method(int first,
                int second)
    {
    }
}
```
