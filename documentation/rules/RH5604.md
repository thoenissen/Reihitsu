# RH5604 — Code must not contain mixed line endings

| Property | Value |
|----------|-------|
| **ID** | RH5604 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

A file must end all of its lines the same way. It must not mix CRLF (carriage return followed by line feed) and LF
(line feed alone). Whichever of the two is already in the majority in the file is the one the rule treats as
intended; every line that ends differently is reported.

## Why is this a problem?

Line endings are invisible, so a file usually acquires a mixed set by accident — a snippet pasted from a different
platform, a generator that hard-codes one style, an editor configured differently from the last person's. The
consequence is not invisible: the next tool that normalizes the file rewrites every odd line, and those lines appear
in the diff as changes even though nothing about their content changed. Some tools also compare files as text and
report two identical files as different.

## How to fix it

Convert the odd lines so the whole file uses one style. A code fix is offered and converts them for you;
`reihitsu-format` normalizes an entire file at once.

To keep the file from drifting back, set the line-ending style in your editor configuration, and — for a repository —
in `.gitattributes`, so a checkout produces the same endings for everyone.

## Examples

### Violation

The first line ends with CRLF and the second with LF. Neither is visible in an editor, so the endings are spelled out
here:

```text
internal class TestClass    <- ends with CRLF
{                           <- ends with LF
}
```

### Correction

Every line ends the same way:

```text
internal class TestClass    <- ends with CRLF
{                           <- ends with CRLF
}
```
