# RH4116 — Named tuple elements should be in PascalCase

| Property | Value |
|----------|-------|
| **ID** | RH4116 |
| **Category** | Naming |
| **Severity** | Warning |
| **Code Fix** | ❌ |

## Description

Checks that the element names in a tuple type follow PascalCase. Each word in the name should start with an uppercase letter, with no underscores or other separators. Tuple types without element names are not reported.

## Why is this a problem?

A named tuple element is read like a member: `result.FirstValue` looks exactly like a property access, and that is how callers use it. Naming the elements like locals makes a return value that is part of the signature read like an implementation detail, and it makes the same value spell differently depending on whether it is returned as a tuple or as a type with properties.

## How to fix it

Rename each element so it starts with an uppercase letter, and update the call sites that read it. Correct the name yourself; no code fix is offered, because renaming a tuple element changes every place the value is unpacked or accessed.

## Examples

### Violation

```cs
internal class Example
{
    public (int firstValue, int secondValue) Load()
    {
        return default;
    }
}
```

### Correction

```cs
internal class Example
{
    public (int FirstValue, int SecondValue) Load()
    {
        return default;
    }
}
```
