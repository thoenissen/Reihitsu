# RH7101 — Do not combine fields

| Property | Value |
|----------|-------|
| **ID** | RH7101 |
| **Category** | Organization |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

This rule checks whether a field declaration declares more than one variable.

## Why is this a problem?

Combining multiple fields into a single declaration makes field declarations harder to scan and harder to extend with individual comments or attributes later.

## How to fix it

Split the combined declaration into one field declaration per variable. The code fix carries the comments written on the declaration and on the individual variables over to the fields it creates.

No code fix is offered when the combined declaration contains a preprocessor directive, or code a directive excludes from the build. Splitting one declaration into several would have to decide which of the new fields the directive belongs to, and any answer changes what the build sees. Split such a declaration by hand and place the directives where you want them.

## Examples

### Violation

```cs
internal class TestClass
{
    private int firstField, secondField;
}
```

### Correction

```cs
internal class TestClass
{
    private int firstField;
    private int secondField;
}
```
