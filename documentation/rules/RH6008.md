# RH6008 — Closing square brackets must be spaced correctly

| Property | Value |
|----------|-------|
| **ID** | RH6008 |
| **Category** | Spacing |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

No same-line space or tab may appear immediately before a closing square bracket `]`. Indentation before a bracket that begins a continuation line is left unchanged. The closing bracket of an attribute is covered separately by [RH6014](RH6014.md).

## Why is this a problem?

A trailing space inside brackets is non-standard and makes indexer and collection expressions harder to scan.

## How to fix it

Remove the space immediately before the closing square bracket. The code fix applies this change
automatically, unless a comment shares the same-line token gap the whitespace run sits in — for example
`values[0 /* keep */ ]`. Deleting the whitespace in that case would glue the comment to the bracket, so the
diagnostic is still reported but no fix is offered.

`reihitsu-format` still removes the space in that case, gluing the comment directly against the bracket
(`values[0 /* keep */]`). The formatter's horizontal-spacing phase decides this purely from the token pair, the
same way it does for every other zero-space rule, and does not special-case an adjacent comment; no manual
action is needed. A comment on a continuation line above the bracket does not reach this rule at all: unlike a
sibling rule such as [RH6012](RH6012.md), this analyzer only compares the immediately preceding token's line to
the bracket's line, so no diagnostic is reported there in the first place.

## Examples

### Violation

```cs
internal class TestClass
{
    void Method()
    {
        int[] values = [0];
        _ = values[0 ];
    }
}
```

### Correction

```cs
internal class TestClass
{
    void Method()
    {
        int[] values = [0];
        _ = values[0];
    }
}
```
