# RH5106 — Closing parenthesis must be on line of last argument

| Property | Value |
|----------|-------|
| **ID** | RH5106 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

The closing parenthesis of a parameter list must appear on the same line as its last parameter, not on a line of its own. This applies everywhere a parameter list is written — methods, constructors, destructors, local functions, operators, conversion operators, delegates, records, primary constructors, extension blocks and anonymous methods — and also to parenthesized lambdas, whose closing parenthesis has a last parameter to sit behind just like any other list.

## Why is this a problem?

A closing parenthesis on its own line adds a visually empty line between the last argument and subsequent code, making parameter lists harder to scan and taking up unnecessary vertical space.

## How to fix it

Move the closing parenthesis to the end of the line that contains the last argument or parameter. The code fix applies this change automatically.

## Exceptions

The rule does not report a list whose closing parenthesis is preceded by a comment or a preprocessor directive. Pulling the parenthesis up would change where that comment or directive belongs, so the list is left exactly as written.

## Examples

### Violation

```cs
internal class TestClass
{
    void Method1(int first, int second
                )
    {
    }

    void Method2(int first,
                 int second
                 )
    {
    }
}
```

### Correction

```cs
internal class TestClass
{
    void Method1(int first, int second)
    {
    }

    void Method2(int first,
                 int second)
    {
    }
}
```
