# RH8025 — Private indexers must be documented

| Property | Value |
|----------|-------|
| **ID** | RH8025 |
| **Category** | Documentation |
| **Severity** | Warning |
| **Code Fix** | ❌ |

## Description

This rule requires private indexer declarations to have XML documentation. A declaration counts as documented when it has a `<summary>` tag or uses `<inheritdoc/>`.

## Why is this a problem?

A private indexer is usable only inside the type that declares it, and its signature says nothing about what the index means or which values are accepted. The summary is the one place where that is recorded, and the editor shows it at every use site inside the file.

## How to fix it

Add a meaningful XML comment above the declaration. In most cases a short `<summary>` is the best fix.

## Exceptions

An indexer that explicitly implements an interface member, such as `int IBuffer.this[int index]`, is not reported even though it carries no accessibility modifier. Its description belongs to the interface member it implements, which is where readers and the editor already look for it.

## Examples

### Violation

```cs
/// <summary>
/// Stores values by position
/// </summary>
internal class Buffer
{
    private int this[int index] => index;
}
```

### Correction

```cs
/// <summary>
/// Stores values by position
/// </summary>
internal class Buffer
{
    /// <summary>
    /// Gets the internally cached value at the specified index
    /// </summary>
    private int this[int index] => index;
}
```
