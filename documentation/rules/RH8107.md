# RH8107 — Void return value must not be documented

| Property | Value |
|----------|-------|
| **ID** | RH8107 |
| **Category** | Documentation |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

This rule forbids `<returns>` tags on methods, delegates, operators, and conversion operators that return `void`.

## Why is this a problem?

A `void` member has no return value to describe. Keeping a `<returns>` tag in the documentation is misleading and suggests behavior that does not exist.

## How to fix it

Remove the `<returns>` tag from the documentation comment.

No code fix is offered when the `<returns>` tag is never closed, or is closed by the end tag of another element or by an end tag spelled differently, such as `<Returns>Nothing</returns>`. Delete the tag and its text yourself there.

## Examples

### Violation

```cs
internal class Customer
{
}

internal class Example
{
    /// <summary>
    /// Saves the customer
    /// </summary>
    /// <returns>Nothing</returns>
    internal void Save(Customer customer)
    {
    }
}
```

### Correction

```cs
internal class Customer
{
}

internal class Example
{
    /// <summary>
    /// Saves the customer
    /// </summary>
    internal void Save(Customer customer)
    {
    }
}
```
