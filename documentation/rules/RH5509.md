# RH5509 — Enum attributes must be on their own line

| Property | Value |
|----------|-------|
| **ID** | RH5509 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

Enum attributes must be on their own line.

## Why is this a problem?

The declaration line is what a reader scans for when looking for an enum: the accessibility, the `enum` keyword and
the name. Attributes written in front of it push all of that to the right by however much attribute text happens to be
present. This matters especially for enums, where `[Flags]` changes how every member of the type is meant to be read
and deserves a line of its own rather than a place at the head of the declaration.

## How to fix it

Move the enum declaration onto the line after the attribute list, leaving the attribute alone on its own line. A code
fix is offered and performs that edit for you.

If a comment sits inside the attribute list, the diagnostic is still reported but no code fix is offered, because the
rewrite would have to carry your comment along with the attribute. Insert the line break by hand in that case.

## Exceptions

The rule does not report when a comment or a preprocessor directive sits between the closing `]` and the enum
declaration. Nothing can be moved onto its own line there without disturbing what you wrote in that gap, so the layout
you chose is left exactly as it is.

## Examples

### Violation

```cs
[First] internal enum Example { A }
```

### Correction

```cs
[First]
internal enum Example { A }
```
