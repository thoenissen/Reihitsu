# RH5602 — Code must not contain trailing whitespace

| Property | Value |
|----------|-------|
| **ID** | RH5602 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

A line must not end with spaces or tabs before the line break. Trailing whitespace inside string, interpolated-string
and raw-string literals is part of the value and is left untouched. Trailing whitespace inside comments (`//`,
`/* */`, `///`, `/** */`) and inside code that a preprocessor directive excludes from the build — for example the body of an `#if false` block — is
exempt for the same reason tabs are exempt there under RH5601: that content may be deliberate, such as aligned
example output, and is never rewritten.

## Why is this a problem?

Trailing whitespace has no effect on what the code does and no appearance in an editor, so it accumulates unnoticed.
It shows up later as changed lines in a diff whose content did not change, and as merge conflicts on lines nobody
meant to touch. Because it is invisible, the only reliable way to keep it out is to have a rule report it.

## How to fix it

Delete the spaces or tabs between the last visible character on the line and the line break. A code fix is offered
and performs that edit for you; `reihitsu-format` removes trailing whitespace across a whole file.

Most editors can show trailing whitespace or strip it on save, which prevents the diagnostic from recurring.

## Examples

### Violation

Two of the lines below end in spaces. They are invisible in an editor, so each one is marked here with `·`:

```cs
internal class TestClass··
{
    void Method()···
    {
    }
}
```

### Correction

No line ends with a space or a tab:

```cs
internal class TestClass
{
    void Method()
    {
    }
}
```
