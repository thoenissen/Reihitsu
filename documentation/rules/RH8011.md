# RH8011 — Non-private enums must be documented

| Property | Value |
|----------|-------|
| **ID** | RH8011 |
| **Category** | Documentation |
| **Severity** | Warning |
| **Code Fix** | ❌ |

## Description

This rule requires non-private enum declarations to have XML documentation. A declaration counts as documented when it has a `<summary>` tag or uses `<inheritdoc/>`.

## Why is this a problem?

Undocumented non-private enum declarations make the code harder to understand because readers have to infer intent from implementation details instead of reading a clear contract.

## How to fix it

Add a meaningful XML comment above the declaration. In most cases a short `<summary>` is the best fix.

## Examples

### Violation

```cs
internal enum OrderState
{
    /// <summary>
    /// The order was created and is waiting for processing
    /// </summary>
    Open
}
```

### Correction

```cs
/// <summary>
/// Represents the processing state of an order
/// </summary>
internal enum OrderState
{
    /// <summary>
    /// The order was created and is waiting for processing
    /// </summary>
    Open
}
```
