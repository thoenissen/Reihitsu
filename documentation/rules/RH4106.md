# RH4106 — Private field names should be in _camelCase

| Property | Value |
|----------|-------|
| **ID** | RH4106 |
| **Category** | Naming |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

Checks that private field names follow _camelCase naming conventions with an underscore prefix. This includes fields whose `private` accessibility is implicit because no accessibility modifier is declared. The first word after the underscore should start with a lowercase letter, and each subsequent word should start with an uppercase letter.

`const` fields are named in PascalCase whatever their accessibility and are handled by RH4110 instead. `private protected` fields are handled by RH4107.

## Why is this a problem?

Inside a method body, `count` could be a local, a parameter, or state that outlives the call. The underscore prefix answers that at the point of use, without scrolling to the declaration, and it keeps a field and a parameter of the same value from colliding on one name.

## How to fix it

Rename the private field to use _camelCase with an underscore prefix, including `private static readonly` fields.

## Examples

### Violation

```cs
private int count;
private static readonly int CacheLimit = 10;
int total;
```

### Correction

```cs
private int _count;
private static readonly int _cacheLimit = 10;
int _total;
```
