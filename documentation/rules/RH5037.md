# RH5037 — Comments must not be placed before a continuation clause

| Property | Value |
|----------|-------|
| **ID** | RH5037 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ❌ |

## Description

This rule reports a comment placed directly before `else`, `catch`, `finally`, or the `while` of a `do` loop. The rule applies whether or not the comment shares a line with code.

## Why is this a problem?

A continuation clause belongs to the statement before it. A comment in front of it separates the clause from that statement and reads as a comment on the previous block.

## How to fix it

Move the comment into the body of the clause, above the statement it describes. No code fix is offered, because only you can decide what the comment refers to.

## Examples

### Violation

```cs
internal class Example
{
    void Method(bool a)
    {
        if (a)
        {
        }
        // otherwise
        else
        {
        }
    }

    void Fallback()
    {
    }
}
```

### Correction

```cs
internal class Example
{
    void Method(bool a)
    {
        if (a)
        {
        }
        else
        {
            // otherwise
            Fallback();
        }
    }

    void Fallback()
    {
    }
}
```
