# RH7204 — Using alias directives must be ordered alphabetically by alias name

| Property | Value |
|----------|-------|
| **ID** | RH7204 |
| **Category** | Organization |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

This rule requires using-alias directives to be sorted alphabetically by alias name within their group. Aliases are grouped by the root namespace of what they point at — the first segment before the first dot, such as `System` or `Microsoft` — so the alias-name ordering is compared only between aliases in the same group. [RH7207](RH7207.md) governs the order of the groups themselves.

## Why is this a problem?

When aliases are unordered, it takes longer to find the one you need. Alphabetical ordering keeps alias blocks predictable.

## How to fix it

Within each alias group, sort the `using Alias = ...;` directives by the alias identifier.

## Exceptions

No diagnostic is reported for a `using` block that contains a preprocessor directive such as `#if`, `#region` or `#pragma`. Reordering imports across a directive could change which imports the build actually sees, so the whole block is left exactly as written — sort it by hand there.

## Examples

### Violation

```cs
using StringList = System.Collections.Generic.List<string>;
using IntList = System.Collections.Generic.List<int>;
```

### Correction

```cs
using IntList = System.Collections.Generic.List<int>;
using StringList = System.Collections.Generic.List<string>;
```
