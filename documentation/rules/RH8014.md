# RH8014 — Enum members in private enums must be documented

| Property | Value |
|----------|-------|
| **ID** | RH8014 |
| **Category** | Documentation |
| **Severity** | Warning |
| **Code Fix** | ❌ |

## Description

This rule requires enum members in private enums to have XML documentation. A member counts as documented when it has a `<summary>` tag or uses `<inheritdoc/>`.

## Why is this a problem?

A private enum is visible only inside the type that declares it, so nothing outside that type explains what its values stand for. The name of a value rarely carries the condition it represents, and the summary is the one place where that condition is recorded for the next reader of the file.

## How to fix it

Add a meaningful XML comment above each enum member in the private enum. In most cases a short `<summary>` is the best fix.

## Examples

### Violation

```cs
/// <summary>
/// Hosts nested states
/// </summary>
internal class Container
{
    /// <summary>
    /// Represents the processing state of an order
    /// </summary>
    private enum OrderState
    {
        Open,
    }
}
```

### Correction

```cs
/// <summary>
/// Hosts nested states
/// </summary>
internal class Container
{
    /// <summary>
    /// Represents the processing state of an order
    /// </summary>
    private enum OrderState
    {
        /// <summary>
        /// The order was created and is waiting for processing
        /// </summary>
        Open,
    }
}
```
