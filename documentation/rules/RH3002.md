# RH3002 — Statement must not use unnecessary parentheses

| Property | Value |
|----------|-------|
| **ID** | RH3002 |
| **Category** | Clarity |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

This rule removes parentheses that do not change meaning and only make a statement harder to read.

## Why is this a problem?

Unnecessary parentheses create visual clutter. They can make simple expressions look more complex than they really are and reduce readability.

## How to fix it

Remove the parentheses when they do not affect the behavior of the expression.

A comment written before or after the parenthesized expression is kept where it is, so the code fix is still offered.

When a comment or a preprocessor directive is written *between* the parentheses, no code fix is offered, because removing the parentheses would also remove what you wrote inside them. The diagnostic is still reported for that shape; remove the parentheses by hand and decide where the comment or directive belongs afterwards.

## Examples

### Violation

```cs
internal class Example
{
    public int GetValue(int value)
    {
        return (value);
    }
}
```

### Correction

```cs
internal class Example
{
    public int GetValue(int value)
    {
        return value;
    }
}
```
