# RH5048 — Comments must not be placed before the first call of a wrapped chain

| Property | Value |
|----------|-------|
| **ID** | RH5048 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ❌ |

## Description

This rule reports a comment placed before the first call of a method chain that is wrapped onto a new line. The rule applies whether or not the comment shares a line with code.

## Why is this a problem?

The first call of a chain belongs on the line of the expression it is called on. A comment in front of it keeps the call apart from its receiver.

## How to fix it

Move the comment above the statement. A comment before a later call of the chain is not reported. No code fix is offered, because only you can decide what the comment refers to.

## Examples

### Violation

```cs
using System.Linq;

internal class Example
{
    object Method(int[] items)
    {
        return items
            // only positive
            .Where(x => x > 0)
            .Select(x => x)
            .ToList();
    }
}
```

### Correction

```cs
using System.Linq;

internal class Example
{
    object Method(int[] items)
    {
        // only positive
        return items.Where(x => x > 0)
                    .Select(x => x)
                    .ToList();
    }
}
```
