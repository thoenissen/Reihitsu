# RH5039 — Comments must not be placed inside a statement header

| Property | Value |
|----------|-------|
| **ID** | RH5039 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ❌ |

## Description

This rule reports a comment placed inside the header of an `if`, `while`, `for`, `foreach`, `using`, `lock`, or `fixed` statement, from the keyword to the closing parenthesis. The rule applies whether or not the comment shares a line with code.

## Why is this a problem?

A comment in this position sits inside a single construct, so it is unclear which part of the code it describes. It also splits the construct across lines and keeps its layout from being kept consistent.

## How to fix it

Move the comment above the statement. No code fix is offered, because only you can decide what the comment refers to.

## Exceptions

- A comment directly before a binary operator or before a later call of a method chain is not reported.
- A comment inside a nested block, initializer, switch expression, pattern, or query is not reported, for example above a statement inside a lambda.

## Examples

### Violation

```cs
internal class Example
{
    void Method(int n)
    {
        for (
            // start
            var i = 0; i < n; i++)
        {
        }
    }
}
```

### Correction

```cs
internal class Example
{
    void Method(int n)
    {
        // start
        for (var i = 0; i < n; i++)
        {
        }
    }
}
```
