# RH3001 — Not operator should not be used

| Property | Value |
|----------|-------|
| **ID** | RH3001 |
| **Category** | Clarity |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

The logical negation operator `!` should not be used for boolean negation. This rule enforces using `== false` instead of the `!` operator to improve readability.

## Why is this a problem?

The `!` operator is easy to overlook, especially in complex conditional expressions with multiple operands. Using `== false` makes the negation explicit and immediately visible, reducing the risk of misreading the intent of the code.

## How to fix it

Replace `!condition` with `condition == false`.

No code fix is offered when a preprocessor directive, code that such a directive excludes from the build, or code the compiler cannot parse sits between `!` and the value it negates. Rewrite the expression by hand there.

## Exclusions

Only operands of type `bool` are reported. Operands of type `bool?` are skipped because `!x` propagates `null` while `x == false` does not, and operands with a user-defined `operator !` are skipped because the rewrite is not equivalent (and `== false` may not compile).

## Examples

### Violation

```cs
internal class Example
{
    void Run(bool isValid)
    {
        if (!isValid)
        {
        }
    }
}
```

### Correction

```cs
internal class Example
{
    void Run(bool isValid)
    {
        if (isValid == false)
        {
        }
    }
}
```
