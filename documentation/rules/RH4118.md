# RH4118 — Named tuple argument names should be in PascalCase

| Property | Value |
|----------|-------|
| **ID** | RH4118 |
| **Category** | Naming |
| **Severity** | Warning |
| **Code Fix** | ❌ |

## Description

Checks that the names you attach to the elements of a tuple expression follow PascalCase. Each word in the name should start with an uppercase letter, with no underscores or other separators. Tuple expressions without element names are not reported.

This is the expression counterpart of RH4116, which covers the element names written in a tuple *type*.

## Why is this a problem?

The name written in the tuple expression is the name callers use to read the value back — `result.FirstValue`. That reads like a member access, and it is the same name a tuple type would declare. Naming it like a local makes the value spell one way where it is created and another way where it is consumed.

## How to fix it

Rename each element so it starts with an uppercase letter, and update the places that read it. Correct the name yourself; no code fix is offered, because renaming an element changes every place the value is unpacked or accessed.

## Examples

### Violation

```cs
public (int FirstValue, int SecondValue) Load()
{
    return (firstValue: 1, secondValue: 2);
}
```

### Correction

```cs
public (int FirstValue, int SecondValue) Load()
{
    return (FirstValue: 1, SecondValue: 2);
}
```
