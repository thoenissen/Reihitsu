# RH5416 — Empty record structs should use semicolon declarations

| Property | Value |
|----------|-------|
| **ID** | RH5416 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

This rule prefers semicolon declarations for empty record structs.

Brace-based empty record struct bodies add noise when the declaration contains no members.

The rule reports only when the project's C# language version allows the semicolon form (C# 10 or later for an empty record struct).

## Why is this a problem?

An empty record struct already expresses its full intent on the declaration line. The empty body adds visual overhead without adding behavior.

Using a semicolon declaration keeps declaration-only record structs brief and consistent with the preferred formatting style.

## How to fix it

Replace the empty brace body with a trailing semicolon. The code fix applies this change automatically.

A declaration that carries a comment or a `#` directive in the body, after the header, or between the header and the opening brace is still reported, but no code fix is offered for it: dropping the braces would leave that text with nowhere to go, and only you can decide where it belongs. Move the note above the declaration and remove the braces by hand, or keep the declaration as it is.

## Examples

### Violation

```cs
internal record struct Example
{
}
```

### Correction

```cs
internal record struct Example;
```
