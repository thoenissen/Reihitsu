# RH2102 — Classes should not use parameterized primary constructors

| Property | Value |
|----------|-------|
| **ID** | RH2102 |
| **Category** | Design |
| **Severity** | Warning |
| **Code Fix** | ❌ |

## Description

Disallows primary constructors with parameters on class declarations. A parameterless primary constructor, `class Service()`, is not reported.

Records are not reported by this rule. A positional record's parameter list is how the record declares its members, so it is not the pattern this rule is about.

## Why is this a problem?

Parameterized primary constructors on classes can hide initialization flow in the type header and make construction patterns less consistent across a codebase. Using explicit constructors keeps initialization logic easier to read and maintain.

## How to fix it

Remove constructor parameters from the class declaration and move them to an explicit constructor in the class body.

## Examples

### Violation

```cs
namespace Example;

internal class Service(int timeout)
{
}
```

### Correction

```cs
namespace Example;

internal class Service
{
    internal Service(int timeout)
    {
    }
}
```
