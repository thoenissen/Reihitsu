# RH5045 — Comments must not be placed inside a conditional expression

| Property | Value |
|----------|-------|
| **ID** | RH5045 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ❌ |

## Description

This rule reports a comment placed directly before or directly after the `?` or the `:` of a conditional expression. The rule applies whether or not the comment shares a line with code.

## Why is this a problem?

A conditional expression reads as one unit. A comment next to one of its operators splits it across lines and makes it unclear which branch it describes.

## How to fix it

Move the comment above the statement that contains the conditional expression. No code fix is offered, because only you can decide what the comment refers to.

## Examples

### Violation

```cs
internal class Example
{
    string Method(bool isValid)
    {
        return isValid
            // valid case
            ? "ok"
            // fallback
            : "error";
    }
}
```

### Correction

```cs
internal class Example
{
    string Method(bool isValid)
    {
        // valid gives "ok", otherwise "error"
        return isValid ? "ok" : "error";
    }
}
```
