# RH6020 — Dereference and access-of symbols must be spaced correctly

| Property | Value |
|----------|-------|
| **ID** | RH6020 |
| **Category** | Spacing |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

The address-of `&` and dereference `*` pointer operators must not be followed by a space.

## Why is this a problem?

A space after a pointer operator visually separates it from the operand, making unsafe pointer expressions harder to read.

## How to fix it

Remove the space immediately after the `&` or `*` operator. The code fix applies this change automatically.

## Exceptions

The rule does not report when the space is the only thing keeping two symbols apart. In `& &value`, closing the gap would produce `&&value` — the logical-and operator — so that space is left in place.

## Examples

### Violation

```cs
internal class TestClass
{
    unsafe void Method()
    {
        int value = 0;
        int* pointer = & value;
    }
}
```

### Correction

```cs
internal class TestClass
{
    unsafe void Method()
    {
        int value = 0;
        int* pointer = &value;
    }
}
```
