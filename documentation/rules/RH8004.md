# RH8004 — Private structs must be documented

| Property | Value |
|----------|-------|
| **ID** | RH8004 |
| **Category** | Documentation |
| **Severity** | Warning |
| **Code Fix** | ❌ |

## Description

This rule requires private struct declarations to have XML documentation. A declaration counts as documented when it has a `<summary>` tag or uses `<inheritdoc/>`.

## Why is this a problem?

A private struct is visible only inside the type that declares it, so nothing outside that type explains what it is for. The summary is the one place where the reason it exists is recorded, and the editor shows it at every use site — so the next reader of the file, often the author some months later, does not have to reconstruct the intent from the code.

## How to fix it

Add a meaningful XML comment above the declaration. In most cases a short `<summary>` is the best fix.

## Examples

### Violation

```cs
/// <summary>
/// Hosts nested values
/// </summary>
internal class Container
{
    private struct Token
    {
    }
}
```

### Correction

```cs
/// <summary>
/// Hosts nested values
/// </summary>
internal class Container
{
    /// <summary>
    /// Stores the lookup token used by the container
    /// </summary>
    private struct Token
    {
    }
}
```
