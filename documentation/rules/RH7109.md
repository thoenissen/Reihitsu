# RH7109 — Readonly elements must appear before non-readonly elements

| Property | Value |
|----------|-------|
| **ID** | RH7109 |
| **Category** | Organization |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

This rule requires `readonly` fields to appear before mutable fields in the same group.

## Why is this a problem?

Placing immutable fields first makes it easier to see which parts of an object's state are fixed after construction. That improves readability when scanning a type.

## How to fix it

Move `readonly` fields above the matching non-readonly fields.

The code fix takes the comments and documentation written above the field with it. Preprocessor directives cannot always travel safely, so no code fix is offered in these two cases:

- An `#if` or `#region` pair with one end inside the moved field and the other outside it, or with one end among the fields it moves past and the other outside them. The move would carry one half of the pair away and leave the other behind, so the file would end up with unmatched directives (CS1027/CS1028) or with a field that silently changed region.
- A `#pragma warning`, `#nullable` or `#line` directive on the moved field or on the fields it moves past. These apply from where they stand onwards, so moving code across them changes which code they cover.

Reorder those fields by hand.

Directives whose meaning the move cannot change do not withhold the fix: a pair written entirely inside the moved field, entirely inside one of the fields it moves past, or opened above the whole range — around the entire type, for example. Note that a `#region` written directly above the first field of the range counts as belonging to that field.

## Examples

### Violation

```cs
public class Example
{
    private int _value;
    private readonly int _maxValue;
}
```

### Correction

```cs
public class Example
{
    private readonly int _maxValue;
    private int _value;
}
```
