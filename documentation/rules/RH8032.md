# RH8032 — Extension declaration parameters must be documented

| Property | Value |
|----------|-------|
| **ID** | RH8032 |
| **Category** | Documentation |
| **Severity** | Warning |
| **Code Fix** | ❌ |

## Description

This rule requires each parameter declared on an `extension(...)` or `extension<T>(...)` declaration to have matching `<param>` documentation. A parameter counts as documented when a `<param>` tag carries its exact name.

## Why is this a problem?

The parameter on an extension declaration is the value that every member inside the block extends, so it is the first thing a caller needs to understand. Its name and type alone do not say which values are meant to be passed, and readers of the block have nothing else to consult.

## How to fix it

Add a `<param>` tag for each parameter of the extension declaration and spell the name exactly as it appears in the declaration — a `<param>` whose name does not match is the same to this rule as a missing one.

## Exceptions

An extension declaration with no documentation at all is not reported here. RH8031 asks for the summary first, and the parameters come into scope for this rule once documentation exists.

A declaration documented with `<inheritdoc/>` is not reported either, because its parameter descriptions are taken from the member it inherits from.

## Examples

### Violation

```cs
/// <summary>
/// Provides text-related extensions
/// </summary>
public static class Extensions
{
    /// <summary>
    /// Adds parsing helpers to a text value
    /// </summary>
    extension(string value)
    {
    }
}
```

### Correction

```cs
/// <summary>
/// Provides text-related extensions
/// </summary>
public static class Extensions
{
    /// <summary>
    /// Adds parsing helpers to a text value
    /// </summary>
    /// <param name="value">Text the helpers are applied to</param>
    extension(string value)
    {
    }
}
```
