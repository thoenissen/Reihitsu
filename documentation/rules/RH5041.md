# RH5041 — Comments must not be placed inside a declarator list

| Property | Value |
|----------|-------|
| **ID** | RH5041 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ❌ |

## Description

This rule reports a comment placed next to the comma between two declarators of a field, event, or local declaration, or directly before the terminating semicolon. The rule applies whether or not the comment shares a line with code.

## Why is this a problem?

A declaration with several declarators reads as one unit. A comment inside it describes only part of the declaration and splits it across lines.

## How to fix it

Move the comment above the declaration, or declare each variable separately. No code fix is offered, because only you can decide what the comment refers to.

## Examples

### Violation

```cs
internal class Example
{
    private int _first,
        // second
        _second;
}
```

### Correction

```cs
internal class Example
{
    // first and second
    private int _first, _second;
}
```
