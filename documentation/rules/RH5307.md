# RH5307 — Indexer bracketed arguments should be single lined

| Property | Value |
|----------|-------|
| **ID** | RH5307 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

This rule requires indexer argument lists (`target[...]`) to stay on a single line.

## Why is this a problem?

Multiline indexer argument lists reduce readability and make simple element access harder to parse while scanning expressions.

## How to fix it

Collapse indexer arguments so that `[` and `]` and all arguments are on the same line. The code fix applies this change automatically.

## Exceptions

The rule does not report an indexer argument list that contains a comment or a preprocessor directive between the brackets. Collapsing the list onto one line would change where that comment or directive belongs, so the access is left exactly as written.

A comment after the closing bracket, such as `values[0] /* note */ + 2`, is not affected: a list written like that is still reported and collapsed, and the comment stays where you put it.

## Examples

### Violation

```cs
var value = matrix[
    1,
    2];
```

### Correction

```cs
var value = matrix[1, 2];
```
