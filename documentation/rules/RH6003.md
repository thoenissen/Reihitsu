# RH6003 — Semicolons must be spaced correctly

| Property | Value |
|----------|-------|
| **ID** | RH6003 |
| **Category** | Spacing |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

A semicolon must not be preceded by horizontal whitespace on the same line. Indentation before a semicolon on a continuation line is left unchanged.

## Why is this a problem?

A space before a semicolon is non-standard and creates visual noise that draws attention away from the statement content.

## How to fix it

Remove any same-line space or tab immediately before the semicolon. The code fix applies this change
automatically, unless a comment or preprocessor directive shares the token gap the whitespace run sits in —
for example a block comment on the line above a continuation-line semicolon. Deleting the whitespace in that
case would glue the comment to the semicolon or drop the directive, so the diagnostic is still reported but no
fix is offered.

- When the shared content is a same-line comment (`value /* keep */ ;`), `reihitsu-format` still removes the
  space, gluing the comment directly against the semicolon (`value /* keep */;`). The formatter's
  horizontal-spacing phase decides this purely from the token pair, the same way it does for every other
  zero-space rule, and does not special-case an adjacent comment. No manual action is needed.
- When the shared content sits on a continuation line (a comment above the semicolon, or a directive),
  `reihitsu-format` leaves the gap untouched. Remove the space by hand.

## Examples

### Violation

```cs
internal class TestClass
{
    void Method()
    {
        var value = 0 ;
    }
}
```

### Correction

```cs
internal class TestClass
{
    void Method()
    {
        var value = 0;
    }
}
```
