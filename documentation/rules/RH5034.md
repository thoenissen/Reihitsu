# RH5034 — Comments must not be placed between a documentation comment and its declaration

| Property | Value |
|----------|-------|
| **ID** | RH5034 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ❌ |

## Description

This rule reports a comment placed between the documentation comment of a declaration and the declaration itself. The rule applies whether or not the comment shares a line with code.

## Why is this a problem?

The documentation comment belongs directly to the declaration it documents. A comment between them separates the two and reads as part of the documentation.

## How to fix it

Move the comment above the documentation comment. No code fix is offered, because only you can decide what the comment refers to.

## Examples

### Violation

```cs
internal class Example
{
    /// <summary>Does work</summary>
    // TODO: rename
    public void DoWork()
    {
    }
}
```

### Correction

```cs
internal class Example
{
    // TODO: rename
    /// <summary>Does work</summary>
    public void DoWork()
    {
    }
}
```
