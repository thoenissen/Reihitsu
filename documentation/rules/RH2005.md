# RH2005 — Fields must be private

| Property | Value |
|----------|-------|
| **ID** | RH2005 |
| **Category** | Design |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

Public fields in classes and record classes should be private. Public fields in structs and record structs, and non-public fields, are outside this rule's scope.

`public const` and `public static readonly` fields are exempt. They cannot be reassigned after initialization, so exposing them does not hand callers a writable slot on the type.

## Why is this a problem?

Public fields on reference types weaken encapsulation and make it harder to evolve an API without breaking consumers.

## How to fix it

Change the field declaration to `private`. The code fix does exactly that; it leaves the name alone, so rename the field afterwards to the `_camelCase` form expected for private fields ([RH4106](RH4106.md)).

When the value really is part of the type's public surface, replace the field with a property instead, so validation, change notification, or a later reimplementation can be added without breaking callers.

## Examples

### Violation

```cs
internal class TestClass
{
    public int Value;
}
```

### Correction

```cs
internal class TestClass
{
    private int _value;
}
```

When the value is meant to be read from outside the class, use a property:

```cs
internal class TestClass
{
    public int Value { get; set; }
}
```
