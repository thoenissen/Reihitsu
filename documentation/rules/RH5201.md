# RH5201 — Member-access chains should be aligned

| Property | Value |
|----------|-------|
| **ID** | RH5201 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

This rule checks the layout of a member-access chain that spans multiple lines:

- Every member access after the first call starts its own line, including a property read such as `.Name` in `.First().Name`.
- Every line that starts with an access operator (`.`, `?.`, `!.`, or `!?.`) is aligned with the first call. When no call comes before the first wrapped line, it is aligned with the last member access in front of that line, such as `.Count` in `order.Items.Count` followed by `.ToString()` on the next line.
- An access operator is kept together. `?` or `!` in front of a `.` belongs to the operator and is aligned in place of the `.`, so a line break between them is reported.

Argument lists, index accesses such as `[0]` or `?[0]`, and a `!` that is not followed by `.` belong to the member in front of them. They are not aligned on their own and are not reported.

## Why is this a problem?

Misaligned member-access chains make it difficult to follow the sequence of operations, especially when chains are long. Consistent dot alignment provides a clear visual guide through the chain of member accesses.

## How to fix it

Start each member access after the first call on its own line, and align the leading `.`, `?.`, `!.`, or `!?.` of each continuation line with the first call, or with the last member access in front of the first wrapped line when no call comes before it. The code fix lays out the whole chain.

## Examples

### Violation

```cs
var result = list.Where(x => x > 0)
.Select(x => x * 2)
.ToList();
```

### Correction

```cs
var result = list.Where(x => x > 0)
                 .Select(x => x * 2)
                 .ToList();
```
