# RH5046 — Comments must not be placed inside a type parameter, type argument or tuple list

| Property | Value |
|----------|-------|
| **ID** | RH5046 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ❌ |

## Description

This rule reports a comment placed inside a type parameter list, a type argument list, or a tuple type. The rule applies whether or not the comment shares a line with code.

## Why is this a problem?

A comment in this position sits inside a single construct, so it is unclear which part of the code it describes. It also splits the construct across lines and keeps its layout from being kept consistent.

## How to fix it

Move the comment above the declaration or statement. No code fix is offered, because only you can decide what the comment refers to.

## Examples

### Violation

```cs
using System.Collections.Generic;

internal class Example
{
    object Method()
    {
        return new Dictionary<
            // key
            string,
            int>();
    }
}
```

### Correction

```cs
using System.Collections.Generic;

internal class Example
{
    object Method()
    {
        // string key, int value
        return new Dictionary<string, int>();
    }
}
```
