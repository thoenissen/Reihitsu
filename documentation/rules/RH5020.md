# RH5020 — Comments should be preceded by a blank line

| Property | Value |
|----------|-------|
| **ID** | RH5020 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

This rule checks that ordinary comments written on their own line (`//` line comments and `/* ... */` block comments) are preceded by a blank line.

## Why is this a problem?

Comments that are not separated from the preceding code by a blank line can appear cluttered and are easy to overlook. A blank line before a comment improves readability by visually associating the comment with the code that follows it rather than the code above.

## How to fix it

Insert a blank line above the comment. The code fix does this for you.

## Exceptions

Nothing is reported, and no blank line is needed, when the comment:

- is an XML documentation comment (`///` or `/** ... */`);
- follows code on the same line, such as a trailing `// explanation`;
- is the first line of the file, the first thing inside a block, or the first thing under a `case` or `default` label;
- directly follows another comment, so that several comment lines stay together as one paragraph;
- directly follows a preprocessor directive such as `#if` or `#region`.

## Examples

### Violation

```cs
var x = Calculate();
/* Process the result */
Process(x);
```

### Correction

```cs
var x = Calculate();

/* Process the result */
Process(x);
```
