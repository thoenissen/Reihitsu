# RH5020 — Comments should be preceded by a blank line

| Property | Value |
|----------|-------|
| **ID** | RH5020 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

This rule checks that ordinary own-line comments (`//`, `////`, and `/* ... */`) are preceded by a blank line. Inline block comments, XML documentation comments, comments in the first position of a file, block, or switch section, and comments adjacent to directives or another comment remain exempt.

## Why is this a problem?

Comments that are not separated from the preceding code by a blank line can appear cluttered and are easy to overlook. A blank line before a comment improves readability by visually associating the comment with the code that follows it rather than the code above.

## How to fix it

Add a blank line before the ordinary comment.

## Examples

### Violation

```cs
var x = Calculate();
/* Process the result */
Process(x);
```

### Correction

```cs
var x = Calculate();

/* Process the result */
Process(x);
```
