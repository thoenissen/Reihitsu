# RH8303 — Element documentation header must be preceded by blank line

| Property | Value |
|----------|-------|
| **ID** | RH8303 |
| **Category** | Documentation |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

A `///` or `/** ... */` documentation block that immediately follows another member must be preceded by a blank line.

## Why is this a problem?

Without a blank line before the documentation block, successive members and their documentation run together visually, making it harder to distinguish where one member ends and the next begins.

## How to fix it

Insert a blank line before the documentation block. The code fix applies this change automatically.

## Exemptions

Three positions are deliberately not reported, because a blank line there would separate lines that belong together:

- Documentation that opens a block, where the line above it is the opening brace of the type, namespace, or member list.
- Documentation that directly follows an ordinary comment (`//`, `////`, or a `/* */` block comment). The comment and the documentation read as one block, and pushing them apart would break it up.
- Documentation that directly follows a preprocessor directive line such as `#if`, `#endif`, or `#region`, which already marks the boundary a blank line would mark.

Text inside a string that merely looks like a comment or a directive does not create an exemption; documentation after such a line is still reported.

## Examples

### Violation

```cs
internal class TestClass
{
    void First()
    {
    }
    /// <summary>
    /// Summary.
    /// </summary>
    void Second()
    {
    }
}
```

### Correction

```cs
internal class TestClass
{
    void First()
    {
    }

    /// <summary>
    /// Summary.
    /// </summary>
    void Second()
    {
    }
}
```
