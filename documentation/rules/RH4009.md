# RH4009 — The given namespace is not allowed

| Property | Value |
|----------|-------|
| **ID** | RH4009 |
| **Category** | Naming |
| **Severity** | Warning |
| **Code Fix** | ❌ |

## Description

Checks every namespace declaration against the list of namespaces you allow in the `reihitsu.json` configuration file. The list is an allow-list: any namespace that is not on it is reported. The comparison uses the full declared namespace and is exact — a child namespace such as `MyCompany.Project.Data` is not covered by an entry for `MyCompany.Project`.

The rule is inactive until you configure it. Without a `reihitsu.json`, or with an empty list, nothing is reported.

## Why is this a problem?

A project that pins its namespaces keeps its layout predictable: consumers know where a type lives, and code cannot quietly drift into a namespace that belongs to another layer or another team. An unexpected namespace usually means a file was added in the wrong place or copied from elsewhere, and it stays invisible until someone tries to reference the type.

## How to fix it

Move the declaration to one of the allowed namespaces, or — if the new namespace is legitimate — add it to the allow-list in `reihitsu.json`. Correct the namespace yourself; no code fix is offered, because the right answer depends on where the file belongs in your project.

## Configuration

Add a `reihitsu.json` file to your project and list every namespace the project may declare:

```json
{
  "naming": {
    "allowedNamespaceDeclarations": [
      "MyCompany.Project",
      "MyCompany.Project.Data"
    ]
  }
}
```

## Examples

### Violation

```cs
// Only "MyCompany.Project" is listed in reihitsu.json
namespace MyCompany.Internal
{
}
```

### Correction

```cs
namespace MyCompany.Project
{
}
```
