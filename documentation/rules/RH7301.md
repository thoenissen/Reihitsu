# RH7301 — #region and #endregion descriptions should match

| Property | Value |
|----------|-------|
| **ID** | RH7301 |
| **Category** | Organization |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

This rule checks that the description on a `#region` directive is repeated on the `#endregion` directive that closes it. The comparison is forgiving about presentation: surrounding spaces and the optional `//` marker in front of the `#endregion` text are ignored, so `#endregion Methods` and `#endregion // Methods` both close a `#region Methods`.

## Why is this a problem?

When `#region` and `#endregion` descriptions do not match, it becomes unclear which region is being closed. This can lead to confusion when navigating large files, especially when regions are nested or span many lines.

## How to fix it

Change the `#endregion` description so that it repeats the description of the `#region` it closes. The code fix does this for you and writes the pair in the `#endregion // Description` form.

No code fix is offered when the `#region` itself carries no description and only the `#endregion` does. There is nothing to copy in that case, so decide yourself whether the region deserves the name on the `#endregion` — then add it to the `#region` — or whether the stray text should simply go.

## Examples

### Violation

```cs
internal class Example
{
    #region Methods

    public void DoWork()
    {
    }

    #endregion // Fields
}
```

### Correction

```cs
internal class Example
{
    #region Methods

    public void DoWork()
    {
    }

    #endregion // Methods
}
```
