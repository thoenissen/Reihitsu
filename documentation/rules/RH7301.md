# RH7301 — #region and #endregion descriptions should match

| Property     | Value        |
|--------------|--------------|
| **ID**       | RH7301       |
| **Category** | Organization |
| **Severity** | Warning      |
| **Code Fix** | ✓            |

## Description

This rule checks that the normalized description text on a `#region` directive matches the normalized description text on its corresponding `#endregion` directive. Surrounding whitespace, the separator after `#region`, and the optional `//` marker after `#endregion` do not affect equality. Mismatched descriptions can confuse developers about which region they are closing.

## Why is this a problem?

When `#region` and `#endregion` descriptions do not match, it becomes unclear which region is being closed. This can lead to confusion when navigating large files, especially when regions are nested or span many lines.

## How to fix it

Update the `#endregion` description to match the normalized `#region` description. When the start description is nonempty, the code fix automatically writes the canonical `#endregion // Description` form. When the start description is empty but the end description is not, correct the pair manually because the analyzer cannot infer an intended name.

## Examples

### Violation

```cs
#region Methods

public void DoWork()
{
}

#endregion // Fields
```

### Correction

```cs
#region Methods

public void DoWork()
{
}

#endregion // Methods
```
