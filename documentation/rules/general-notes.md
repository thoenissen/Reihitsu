# General notes

These notes apply to every Reihitsu rule. The individual rule pages only describe what is specific to that rule.

## Comments, preprocessor directives, and excluded code

A rule never rewrites your code in a way that would move, drop, or reorder a comment, a preprocessor directive (`#if`, `#pragma`, `#region`, …), or code that `#if` excludes from the build. Where one of these sits inside the code a rule would have to change, one of two things happens:

- The diagnostic is not reported, and the code is left exactly as written.
- The diagnostic is reported, but no code fix is offered. Correct the code by hand and decide yourself where the comment or directive should go.

For example, the arguments below should each be on their own line. The call is reported, but no code fix is offered, because a comment sits inside the argument list:

```cs
Process(first, // the primary input
        second, third);
```

## Code excluded by `#if`

Only the code that is active for the current build configuration is analyzed. Code inside an `#if` branch whose condition is false is not checked, because it is not part of the compilation. It is checked when you build the configuration that includes it.

## Generated code

Generated code is not analyzed. This covers files with names such as `*.g.cs` or `*.Designer.cs`, files that start with an `<auto-generated>` comment, and code marked with `[GeneratedCode]`.

## A diagnostic without a code fix

Some violations can only be corrected by hand. A diagnostic that is reported without a code fix is intended behavior, not an error in the rule. The rule page names the cases that are always left to you.

## Turning a rule off

Every rule can be configured like any other .NET analyzer diagnostic:

- for a whole project or folder in `.editorconfig`, for example `dotnet_diagnostic.RH3202.severity = none`;
- for a few lines with `#pragma warning disable RH3202` and `#pragma warning restore RH3202`;
- for a single member with `[SuppressMessage("Reihitsu", "RH3202")]`.

Some rules are off by default; their rule page says so in the **Enabled by default** row. Enable them through `.editorconfig` in the same way, for example `dotnet_diagnostic.RH7305A.severity = warning`.
