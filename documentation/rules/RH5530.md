# RH5530 — Accessor attributes must follow placement rules

| Property | Value |
|----------|-------|
| **ID** | RH5530 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

On a property, indexer, or event whose body is spread over several lines, an attribute on a `get`, `set`, `init`,
`add`, or `remove` accessor goes on its own line, above the accessor keyword.

## Why is this a problem?

In a multi-line property body the accessor keywords are the structure: a reader looks down the left edge for `get`
and `set` to find out what the property allows. An attribute written in front of one of them displaces that keyword,
so the two accessors of the same property no longer begin in the same column and the one carrying metadata is the
harder of the two to spot — which is the opposite of what an attribute is for.

## How to fix it

Move the accessor keyword onto the line after its attribute list, leaving the attribute alone on its own line. A code
fix is offered and performs that edit for you.

## Exceptions

- An accessor attribute on a one-line auto-property or auto-indexer, such as `internal int Value { [First] get; set; }`,
  is not reported. Breaking the attribute out would turn a one-line property into a five-line one for the sake of a
  single marker. A property-level attribute on its own line above the declaration does not change this.

## Examples

### Violation

```cs
internal class Example
{
    internal int Value
    {
        [First] get;
        set;
    }
}
```

### Correction

```cs
internal class Example
{
    internal int Value
    {
        [First]
        get;
        set;
    }
}
```
