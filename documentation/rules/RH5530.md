# RH5530 — Accessor attributes must follow placement rules

| Property | Value |
|----------|-------|
| **ID** | RH5530 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

On a property whose body is spread over several lines, an attribute on a `get`, `set` or `init` accessor goes on its
own line, above the accessor keyword. On a property whose declaration is single line — once any property-level
attribute list of its own is set aside — the accessor attribute stays where it is and the rule does not report.

## Why is this a problem?

In a multi-line property body the accessor keywords are the structure: a reader looks down the left edge for `get`
and `set` to find out what the property allows. An attribute written in front of one of them displaces that keyword,
so the two accessors of the same property no longer begin in the same column and the one carrying metadata is the
harder of the two to spot — which is the opposite of what an attribute is for.

## How to fix it

Move the accessor keyword onto the line after its attribute list, leaving the attribute alone on its own line. A code
fix is offered and performs that edit for you.

If a comment sits inside the attribute list, the diagnostic is still reported but no code fix is offered, because the
rewrite would have to carry your comment along with the attribute. Insert the line break by hand in that case.

## Exceptions

A property whose declaration is single line, such as `internal int Value { [First] get; set; }`, is never reported.
Breaking the attribute out would turn a one-line property into a five-line one for the sake of a single marker, so
the compact form is the accepted shape there. A property-level attribute on its own line above the declaration does
not change this: `[Example]` followed by `internal int Value { [First] get; set; }` is single line by this rule's own
criterion and stays exempt the same way.

The rule also does not report when a comment or a preprocessor directive sits between the closing `]` and the
accessor keyword. Nothing can be moved onto its own line there without disturbing what you wrote in that gap, so the
layout you chose is left exactly as it is.

## Examples

### Violation

```cs
internal class Example
{
    internal int Value
    {
        [First] get;
        set;
    }
}
```

### Correction

```cs
internal class Example
{
    internal int Value
    {
        [First]
        get;
        set;
    }
}
```
