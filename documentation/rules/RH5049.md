# RH5049 — Comments must not be placed after a binary operator

| Property | Value |
|----------|-------|
| **ID** | RH5049 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ❌ |

## Description

This rule reports a comment placed directly after a binary operator, between the operator and its right operand. The rule applies whether or not the comment shares a line with code.

## Why is this a problem?

A wrapped binary expression breaks before the operator, so the operator starts the line it belongs to. A comment after the operator separates the operator from its right operand.

## How to fix it

Move the comment before the operator. No code fix is offered, because only you can decide what the comment refers to.

## Examples

### Violation

```cs
internal class Example
{
    bool Method(bool a, bool b)
    {
        return a &&
            // why b
            b;
    }
}
```

### Correction

```cs
internal class Example
{
    bool Method(bool a, bool b)
    {
        return a

               // why b
               && b;
    }
}
```
