# RH5044 — Comments must not be placed inside an attribute list

| Property | Value |
|----------|-------|
| **ID** | RH5044 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ❌ |

## Description

This rule reports a comment placed inside an attribute list, between its brackets. The rule applies whether or not the comment shares a line with code.

## Why is this a problem?

A comment in this position sits inside a single construct, so it is unclear which part of the code it describes. It also splits the construct across lines and keeps its layout from being kept consistent.

## How to fix it

Move the comment above the attribute list. No code fix is offered, because only you can decide what the comment refers to.

## Exceptions

- A comment directly before a binary operator or before a later call of a method chain is not reported.

## Examples

### Violation

```cs
using System;

[
    // serialization
    Serializable,
    Obsolete]
public class Data
{
}
```

### Correction

```cs
using System;

// serialization
[Serializable, Obsolete]
public class Data
{
}
```
