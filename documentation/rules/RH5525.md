# RH5525 — Delegate attributes must be on their own line

| Property | Value |
|----------|-------|
| **ID** | RH5525 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

Delegate attributes must be on their own line.

## Why is this a problem?

A delegate declaration is already a complete signature on one line — return type, name and parameter list. Attributes
written in front of it compete with all three for the same line, and the signature is exactly the part a reader came
to that line to read. Moving the attribute up leaves the signature by itself.

## How to fix it

Move the delegate declaration onto the line after the attribute list, leaving the attribute alone on its own line. A
code fix is offered and performs that edit for you.

If a comment sits inside the attribute list, the diagnostic is still reported but no code fix is offered, because the
rewrite would have to carry your comment along with the attribute. Insert the line break by hand in that case.

## Exceptions

The rule does not report when a comment or a preprocessor directive sits between the closing `]` and the delegate
declaration. Nothing can be moved onto its own line there without disturbing what you wrote in that gap, so the layout
you chose is left exactly as it is.

## Examples

### Violation

```cs
[First] internal delegate void ExampleDelegate();
```

### Correction

```cs
[First]
internal delegate void ExampleDelegate();
```
