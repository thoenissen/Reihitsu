# RH5101 — The first argument should be on the same line as the opening parenthesis

| Property | Value |
|----------|-------|
| **ID** | RH5101 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

This rule checks that the first argument of a method or constructor call is on the same line as the opening parenthesis. When arguments are placed on the next line after the opening parenthesis, it makes alignment inconsistent and wastes vertical space.

## Why is this a problem?

Placing the first argument on a new line after the opening parenthesis creates unnecessary vertical distance between the method name and its first argument, reducing readability.

## How to fix it

Move the first argument to the same line as the opening parenthesis. The code fix removes the line break between the opening parenthesis and the first argument.

## Exceptions

The rule does not report a call whose opening parenthesis is followed by a comment or a preprocessor directive before the first argument. Joining the lines there would change where that comment or directive belongs, so the call is left exactly as written.

When a comment sits on its own line between the method name and the opening parenthesis, the diagnostic is still reported, but no code fix is offered. Move the first argument up by hand and decide yourself where the comment should end up.

## Examples

### Violation

```cs
a.Call(
    "test1",
    "test2");
```

### Correction

```cs
a.Call("test1",
       "test2");
```
