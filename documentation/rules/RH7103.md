# RH7103 — Static elements must appear before instance elements

| Property | Value |
|----------|-------|
| **ID** | RH7103 |
| **Category** | Organization |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

This rule requires static members to appear before instance members of the same kind and accessibility.

## Why is this a problem?

Placing static and instance members in a predictable order makes the public shape of a type easier to understand. Readers can quickly see the static API before they move on to instance behavior.

## How to fix it

Move static members above the matching instance members in the same group.

The code fix takes the comments and documentation written above the member with it. Preprocessor directives cannot always travel safely, so no code fix is offered in these two cases:

- An `#if` or `#region` pair with one end inside the moved member and the other outside it, or with one end among the members it moves past and the other outside them. The move would carry one half of the pair away and leave the other behind, so the file would end up with unmatched directives (CS1027/CS1028) or with a member that silently changed region.
- A `#pragma warning`, `#nullable` or `#line` directive on the moved member or on the members it moves past. These apply from where they stand onwards, so moving code across them changes which code they cover.

Reorder those members by hand.

Directives whose meaning the move cannot change do not withhold the fix: a pair written entirely inside the moved member, entirely inside one of the members it moves past, or opened above the whole range — around the entire type, for example. Note that a `#region` written directly above the first member of the range counts as belonging to that member.

## Region scope

When a type uses top-level `#region` blocks, the ordering is evaluated within each region independently. Static members in one region are not compared against instance members in a different region, so per-region groupings such as `#region Lifecycle` and `#region Factories` can coexist without conflicting with this rule. A type without regions continues to be evaluated as a single body.

## Examples

### Violation

```cs
public class Example
{
    public void Run()
    {
    }

    public static void Create()
    {
    }
}
```

### Correction

```cs
public class Example
{
    public static void Create()
    {
    }

    public void Run()
    {
    }
}
```
