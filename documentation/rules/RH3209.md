# RH3209 — Get-only properties should use an expression body

| Property | Value |
|----------|-------|
| **ID** | RH3209 |
| **Category** | Clarity |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

This rule reports a property that has only a `get` accessor returning a single value or throwing an exception. Such a property should be written as an expression-bodied property (`=>`).

The rule reports only when the project's C# language version allows the expression-bodied form (C# 6 or later, and C# 7 or later for a getter that throws).

## Why is this a problem?

An accessor list with a single getter takes several lines and two levels of braces to say what one line says. The expression-bodied form shows at a glance that the property is read-only and what it computes, and keeps all get-only properties in one consistent shape.

## How to fix it

Replace the accessor list with `=>` followed by the value the getter returns. The code fix applies this change automatically.

## Examples

### Violation

```cs
internal class Example
{
    private int _value;

    public int Value
    {
        get
        {
            return _value;
        }
    }
}
```

### Correction

```cs
internal class Example
{
    private int _value;

    public int Value => _value;
}
```
