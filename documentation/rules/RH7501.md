# RH7501 — Break statements should not be inside explicit switch case blocks

| Property | Value |
|----------|-------|
| **ID** | RH7501 |
| **Category** | Organization |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

When a `switch` case section uses an explicit `{ … }` block to scope its local variables, the `break` that ends the section should appear after the closing brace, not as the last statement inside the block.

The rule reports only that closing `break`: the one that is the last statement of the block, where the block is in turn the last thing in the case section. A `break` in the middle of a block, or a block followed by further statements, is left alone.

## Why is this a problem?

The braces and the `break` do two different jobs. The braces limit how far the case section's local variables reach; the `break` ends the case section itself. Writing the `break` inside the braces makes it look like one more statement of the scoped block, and a reader has to look at the closing brace to see that the case actually ends there. With the `break` below the brace, the shape of the section says what it does: this much is scoped, and then the case is over.

## How to fix it

Keep the block if you need it for scoping, and move the final `break` below its closing brace, still inside the same case section. The code fix does this for you and indents the moved `break` to line up with the brace.

## Examples

### Violation

```cs
switch (value)
{
    case 1:
        {
            var result = GetValue();
            break;
        }
}
```

### Correction

```cs
switch (value)
{
    case 1:
        {
            var result = GetValue();
        }
        break;
}
```
