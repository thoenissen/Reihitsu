# RH5419 — Expression style get-only indexers should be single lined

| Property | Value |
|----------|-------|
| **ID** | RH5419 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

This rule checks that expression-bodied indexers keep the `=>` arrow and the start of the expression on the line that ends the indexer signature, the line of the closing `]` of the parameter list. The parameter list may span several lines, and the expression itself may continue on following lines; only the arrow and the first expression token are required to stay on the line of the `]`.

## Why is this a problem?

Dropping the `=>` or the beginning of the expression onto a separate line defeats the purpose of the concise expression syntax: the reader has to look at the next line to find out what the indexer returns, and an indexer written that way no longer lines up with the other one-line members around it. An expression that starts on the signature line and then wraps is still easy to scan, because the first line already says what the indexer computes.

## How to fix it

Move the `=>` arrow and the start of the expression onto the line of the closing `]`. The code fix does this for you.

## Examples

### Violation

```cs
public int this[int index]
    => index * 2;
```

### Correction

```cs
public int this[int index] => index * 2;
```
