# RH5419 — Expression style get-only indexers should be single lined

| Property | Value |
|----------|-------|
| **ID** | RH5419 |
| **Category** | Layout |
| **Severity** | Warning |
| **Code Fix** | ✓ |

## Description

This rule checks that an expression-bodied indexer is written on one line: its parameter list from the opening `[` to the closing `]`, the `=>` arrow, and the start of the expression. The expression itself may continue on following lines; only the parameter list, the arrow, and the first expression token are required to stay on one line.

## Why is this a problem?

Spreading the parameter list over several lines, or dropping the `=>` or the beginning of the expression onto a separate line, defeats the purpose of the concise expression syntax: the reader has to look at several lines to find out what the indexer takes and returns, and an indexer written that way no longer lines up with the other one-line members around it. An expression that starts on the signature line and then wraps is still easy to scan, because the first line already says what the indexer computes.

## How to fix it

Put the parameter list on one line, and move the `=>` arrow and the start of the expression onto the line of the closing `]`. The code fix does this for you.

## Examples

### Violation

```cs
public int this[int index]
    => index * 2;
```

### Correction

```cs
public int this[int index] => index * 2;
```
