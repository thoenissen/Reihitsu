# GitHub PR Preflight

Run a read-only quality gate on GitHub Pull Request **#$ARGUMENTS** before external review or re-review.

This is the **final** gate, not a discovery loop: the implementation or repair cycle is finished, the parent's local self-review and admission artifact are complete, and current `origin/main` is already merged into the branch. `gh-implement` and `gh-apply-review` may spend at most two official attempts on it — one, plus one retry after a single consolidated repair cycle.

It is also risk-triggered rather than mandatory. An audit is **required** when the diff changes a predicate, guard, or the condition or span under which a diagnostic is reported; which tokens or trivia a formatter rewrite writes; a code-fix registration or its applicability; a diagnostic ID, severity, or message; public API; a dependency; a repository script, build property, ruleset, or CI workflow; or adds a rule. It is **not required** when the diff only edits comments, XML documentation, Markdown, skill and command files, or issue and PR templates — including inside `.cs` — or only adds tests for behavior that is already correct. Prove the comment-only case with `scripts/verify-text-only.ps1 -NoInstall -Base <base-sha> -Head <head-sha>` and record its `TEXT-ONLY PROOF: PASS …` line instead of spending an attempt; a line-based `grep` is not acceptable evidence, and a rename is never a carve-out. When a diff fits neither list, ask the user rather than defaulting either way. A skipped audit never skips the full validation.

`$ARGUMENTS` is optional. When it is empty, reuse the PR created or updated in the current author task, or the single PR associated with the current branch. Ask only when no PR can be identified.

Invoke the `gh-preflight` skill and follow it exactly:

1. Confirm GitHub identity and read the PR metadata, diff, changed files, commits, and linked issue through authenticated `gh` — or consume the parent's immutable evidence bundle when one was handed over. The bundle carries facts only, never the author's conclusions; a bundle that disagrees with the checkout is `BLOCKED — state mismatch`. Do not fetch prior review comments merely to copy another review.
2. Require the local checkout to match the PR head and all intended scoped changes to be committed and pushed. Report a blocking state mismatch instead of switching or repairing branches.
3. Read `.codex/skills/gh-review/SKILL.md` and apply its complete 19-item checklist, adversarial corpus, test expectations, counterpart tracing, defect-class closure, severity model, and static-first verification.
4. Build the required three-axis audit. For every changed predicate, guard, or policy, name its exact inspected span, the existing counterpart predicate for the same decision, and whether their boundaries agree. Enumerate every policy owner by `rg`; multiple owners are a finding unless the diff justifies them. For every new or materially changed test, name its invariant, the observation that would falsify it, and why the assertion/helper is strong enough. Missing rows or weaker assertions block `PASS` even when tests are green.
5. Post nothing to GitHub and do not edit files, commit, push, change branches, or change PR state.
6. Return one of four results. `PASS` only when no confirmed finding remains and the three-axis audit is complete. `PASS — non-blocking cleanup` when every remaining confirmed finding is confined to comments or documentation and cannot affect compiled behavior, diagnostics, public API documentation, generated artifacts, or required rule metadata — list them with that justification so the parent fixes the text without spending another attempt. `BLOCKED — findings` otherwise, and `BLOCKED — state mismatch` when the tree cannot be reviewed reliably. Render an explicit N/A reason for an axis with no applicable row. Hints are non-blocking, but every confirmed unrelated pre-existing concern must appear there with its defect mechanism and `new mechanism` relation so the author workflow can preserve it against its scope ledger. Report every blocking finding in this one pass with its scope relation because the parent gets a single consolidated repair cycle and one retry, and remember that `Required change` is a suggestion the parent must re-derive, not a specification.
7. On a retry, work repair-delta-aware: the parent supplies the previous report, the previously audited SHA, the repaired SHA, and the repair diff. Verify every previous finding, the whole repair delta, the guards and predicates it moved, the counterparts those reach, and the new boundary tests, reusing evidence only where it is byte-identical to attempt 1. If the repair expanded into an unrelated production surface, changed the accepted contract, or materially enlarged the file set, incremental mode is invalid: audit in full and say scope grew.
8. When a targeted test is needed to settle a concrete suspicion, confirm the preinstalled SDK with `scripts/prepare.ps1 -NoInstall` and use `scripts/test.ps1 -NoInstall -Project <name> -Filter <expression>`; never install an SDK, modify `PATH`, or run the full suite.

A non-empty argument from which no valid PR number or URL can be extracted is an error. Ask rather than guess.
