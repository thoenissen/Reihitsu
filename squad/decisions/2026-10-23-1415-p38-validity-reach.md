# What makes a form "not valid C# at that position" under P38 (#1415)

| | |
|---|---|
| Date | 2026-10-23 |
| Escalation | 1 |
| Run | issue #1415 |

## Question

SHARED-DIAG-011 (P38) as drafted counted only the grammar and the language version as making the form a rule asks for invalid at a position. Example: `struct S {}` with the statement `new S();` — RH3104 asks for `default(S);`, which parses but fails with CS0201. Options: (a) grammar and language version only, so `new S();` stays reported and only its fix is withheld; (b) any compile error the position itself causes also counts, so `new S();` is not reported, and RH3003-002 and RH2004-003 become instances of SHARED-DIAG-011.

## Answer

(b): where the change a rule asks for cannot be written at that position, the construct is not reported. This is the principle, and it is general: it applies to every rule.

## Reason

none given beyond the principle itself.
